## 3. 设计

### 3.1 依赖方向与边界

- 保持既有依赖方向。contracts 被 web 与 api 共同依赖；平台图片地址的判定只有 contracts 这一个来源。
- SDK 内部 API 只经编辑器适配层使用，新增使用须登记到 ADR-010。修改 SDK 行为只走既有的 pnpm 补丁，并更新补丁登记、摘要，核对 ES 与 CJS 产物一致。补丁的解包编辑目录放在主目录 `.codex/handoffs/m5-p7-20261105/`，不放进本 worktree 的扫描树。
- 唯一获批的跨模块语义调整是 S5 的保存授权（D-01，api 的 documents × assets）。其余修复都在单一模块内完成。如果实施中发现确实需要新的跨模块接线、架构回归或正文格式变化，先提交当前工作，停下来请示。

### 3.2 资源地址与引用（S2、S4、S5）

- **S2，I-04**：`extractAssetIds` 的包裹符剥离改为下标循环线性实现，去掉 `^…+|…+$` 这种可回溯正则；语义保持“去掉词首的 `([{<`、词尾的 `)]}>`”。

  | 验证 | 内容 |
  |---|---|
  | 差分 | 在字母表 {包裹符、字母、`/api/assets/` 片段、合法 UUID} 上，用旧正则作对照，穷举短串 |
  | 对抗长度 | `')'.repeat(1e6)+'x'`、`'/api/assets/'+')'.repeat(1e6)+'x'`：结果正确，并在宽松时限内完成 |
  | 集成 | 保存此类内容正常返回 |

  同时检查 contracts 和 api 提取路径里同类的“`+` 后接 `$`”正则。
- **S4，I-03（D-02）**：在平台命令策略层，把 `IMAGE()` 首参字符串字面量中的本站绝对地址 `${origin}/api/assets/<uuid>` 改写为 `/api/assets/<uuid>`。这与浮动图片已有的同源绝对地址归一保持一致。
  - 只改写精确匹配的字面量，公式的其余部分逐字节保留。
  - 外站地址与非规范写法不变，仍由现有策略拒绝或留作外链。
  - 服务端仍只认相对地址。
  - v0.1 没有真实数据，不做存量迁移。
  - 撤销与重做沿用改写后的值。复制粘贴与公式输入走同一策略，不另开入口。
- **S5，I-02（D-01）**：服务端按版本持久化每次保存从正文提取到的完整 assetId 集合，包含未被授权的 ID。保存时的处理规则如下：
  - 只对“当前正文集合 − 被替换版本集合”中的新 ID，按保存人当时的权限授权并登记引用；
  - 上一版已存在但未登记的 ID，任何人后续保存都不升级；
  - 删除后再次引入的 ID，按再次引入者当时的权限处理。

  副本、恢复、CSV 新建和离线草稿重放的比较基准，统一取服务端被替换的当前版本，不取客户端的基准版本。

  迁移只新增服务端表或列，不触及正文。缺少集合记录的旧版本如何回退，在 Step plan 中定案，必须写明理由。`asset-save.test.ts:175` 按新语义调整预期。另补两类集成用例（双人场景、经历史的场景），以及“乙打开含甲预埋地址的文档不能静默共享”的 E2E。

### 3.3 图片写入策略与实例生命周期（S3、S11）

- **S3，I-01 与 M-10**：来源清洗不再对整次写入共用 10 万节点预算。新的计数口径如下：

  - 只沿可能携带 `source`/`base64Cache` 的路径遍历；

  超限时给出准确原因，改走操作状态通道，不再借用图片显示失败通道，`imageProblem` 不变。回归使用真实 SDK 夹具，覆盖报告列出的五类大范围命令及其撤销。

### 3.5 CSV 与数组公式（S7、S8）

- **S7，I-06（D-03）**：适配层从 `p.body` 生成导出文本，规则如下：
  - 去除 CUSTOM_BLOCK 等文档流结构标记；
  - 段落分隔统一为 LF；
  - `hasContent` 使用同一份文本；
  - 纯图片格导出空串，且不扩大导出矩形；图文混排格只保留文字。

  同一 Step 内的其他修复与验证：
  - **M-13**：为导出方向提供独立的问题码与文案，不回显正文。
  - **M-14**：`hasPendingWork` 增加“未结束”条件；结果未知时作废，提示“可能已创建，请返回空间核对”；首次失败且结果已知时把 creation 置为 none。
  - **Q-12**：补导入控制字符的测试，发现问题再定过滤规则。
- **S8，I-07（D-04）**：
  1. 先补一条 Chromium 复现用例：保存，常规重开，读取溢出区的显示与 CSV。修复前应失败。
  2. 再在打开时对数组公式锚点做一次定向重算。如何识别锚点，依据实际 SDK 计算链在 Step plan 中定案。约束是只读正文、不改格式，阅读态、编辑态以及 Worker 与主线程两种计算模式都要成立。
  3. CSV 兜底：无法证明数组结果完整时拒绝导出，并说明原因。

  如果识别锚点做不到“可靠且不改格式”，提交当前工作，带测量与方案停下来请示，不擅自改为持久化溢出范围。

  - 恢复水位仍由人工声明；

## 7. 风险与未决问题

- **S8 锚点识别**：可能无法在不改格式的前提下做到可靠，这时按 §3.5 停下来请示。
- **S5 旧版本回退**：缺少集合记录的旧版本如何回退，在 plan 中定案。语义变化会影响副本、恢复和草稿重放，需逐条补测。
- **补丁重生成**（S6，以及 S11 若涉及补丁）：可能引入产物差异，按补丁摘要和 ES/CJS 双产物核对。
- **CI 节奏**：每轮约 2 小时，最慢的是 WebKit 分片，并且需要需求方手动触发。已定位的问题，修复后以新 SHA 接续；未知的资源、身份或权限异常一律停止，不自动重跑失败的 SHA。计划在独立审查之后跑一轮分支 CI；只有修复才追加轮次。
- **本机浏览器风险**：WindowServer 首次崩溃无法预防，所以只做少量短时 Chromium 用例；桌面会话保护判异常时停止，不换资源类型绕过。
- **Q-03 测量规模**：会占用磁盘，按有界规模执行，结束后清理隔离库。
