# P4-S6 容器测试资源归属

2026-10-30。适用范围：现有容器 E2E 入口与测试资源运行器的交界，不改业务功能、案例范围或预算。

## 背景与授权

full18/container07 已实际通过；同 `c4b564f5` 的 CI `40994784729` 正在运行。收尾时发现旧 `removeStaleRuns()` 按名字中的 PID 是否存活删除共享 Docker 上的项目、镜像和临时目录；`exercise()` 还在启动前无条件删除同 PID 项目。外层 publication 锁只保护当前资源 Store，不能给全局 Docker 删除提供归属证明。目前没有实际误删证据，也不撤销已观测的门禁结果；这个机制缺口须修复后才能关闭 P4。

用户此前明确要求实际实现资源预登记、并发隔离、异常恢复及保护其他任务，并再次授权自主推进。以下是执行者在该范围内的局部实现决定，不冒称用户另行批准了本文的具体接口。原始调查位于 `.codex/handoffs/m5-p4-20261022/s6/hosted-vm-policy/final-ci-40947141649-investigation/docker-ownership-original-finding.md`。

## 方案取舍

- 只删除旧扫描器：能避免已识别的误删入口，但不能证明本轮失败清理或崩溃后资源状态，未满足既定需求。
- 本轮 UUID + 创建前持久台账 + 精确归属清理：采用。复用已有运行 UUID、锁、进程控制和报告策略，缺证时保留并阻止本 Store 的同类重试。
- 全局 Docker 回收服务：需额外跨 worktree 仲裁及恢复协议，不属于本次必要修复；不实现无证据的历史接管。

## 必须成立的行为

1. 名称使用运行器已登记的 `NERVE_TEST_RUN_ID` UUID，不再由 PID 命名；PID 仅供现有进程退出控制使用。旧 PID 项目、任意未登记资源及其他运行不得被自动删除。停止全局名称/PID 清扫，取消启动前强制 `down`。当前命名空间已有对象或查询异常时，拒绝启动，不接管。
2. 父运行器在启动 container 子命令前，将独立、无密钥的 Docker 意向台账写入本轮持久 run 目录；通过 `NERVE_TEST_RUN_DIR` 给子命令定位。子命令先验证 UUID、父台账与路径，原子登记 Docker daemon ID、源工作目录、精确项目/标签/临时环境路径及专属标签，再执行 build/up。临时环境继续属于本轮 scratch 与短 TMPDIR。台账不得包含密码、master key 或完整 Config.Env。
3. 台账版本为 1，绑定 `runId/repo/scratch`；初始 `state=unclaimed`，资源创建前为 `reserved`，有未确认退出的生产者或清理问题时保持待处理，实际证实资源不存在后才为 `closed`。具体 Docker 字段由专门模块管理；父进程只接受有界、普通文件且身份相符的台账。文件缺失、链接、损坏或身份不符不得当作清理完成。旧历史 run 未登记新协议，不伪造补签。
4. Compose 的服务、网络、卷以及本轮构建标签/单次镜像测量容器带运行归属标签；手工部署的默认使用保持兼容，但没有本轮标签不能被测试清理接管。登记的是创建意向，不要求尚未创建的容器 ID；创建后记录实际身份，合法的应用重建更新观测，不以最初容器 ID 锁死重启用例。
5. 长命令启动前登记生产者待退出，启动后及时登记实际进程组；只有确认整个组退出才撤销待退出状态。若现有等待上限后仍存活，返回失败并保留资源，不进入破坏性清理。原信号转发及等待预算保持。同步查询失败也不能伪装成“对象不存在”。
6. 本轮正常成功、失败及可捕获中断都先收集必要报告，再在相同 daemon、完整本轮标签/命名空间、生产者已退出的前提下删除本轮资源；各清理步骤独立报告失败，实际重新查询容器、网络、卷和镜像标签确认消失。只去掉本轮镜像标签，不清构建缓存/基础镜像，不重启 Docker。未知资源或活动引用存在时保留并失败，不用 `--force` 消除外部使用者。
7. SIGKILL/崩溃留下未闭合台账时，父运行器/下一次 sweep 必须保留台账及所需环境、标记 `cleanup-pending`，阻止本 Store 的同类新环境；不能因本地进程消失就删除 Docker 或抹掉证明。无副作用的 `unclaimed` 可按原本地清理处理。恢复自动化只处理已经可证闭合的台账；未闭合 Docker 由后续有明确证据的调查处理，不跨 Store 全局扫除。
8. 用户批准的方案 B 保持原边界：不得伪造宿主销毁完成；普通本机严格策略不放宽。本次 Docker 清理错误不能变成产品通过。完整原环境不上传；沿用普通报告 14 天/5 GiB、既有失败资料和便携诊断限额；台账/回执保持小型（单文件最多 64 KiB），先登记后启动。

## 验证与交付

先以 KiB 级临时文件、命令记录型 Docker 替身及自建小进程验证实际策略：旧 PID/其他工作副本/活动任务不删；UUID 隔离；先登记再创建；成功与失败清理；清理重复执行；查询异常/标签不符/daemon 更换/未退出生产者拒绝删除；中断后不丢台账且阻止继续堆积。Docker 替身只替代外部系统边界，不用源码字符串断言代替执行行为。

之后保持原检查配置和案例目录，串行完成当前源码的完整门禁、容器门禁及正常合并推送后的同 SHA CI；旧 full18/container07/r09 工具和原始证据不改写、不充当新源码验收。独立审查和实际资源复核均通过后才关闭 P4/DEF-061、进入 P5。

## 实施裁定（2026-10-30）

- 临时 env 由父运行器在 Docker 闭合及原根/别名/句柄核验后清理；子 CLI 不再重复删除。
- 原 60 秒主密钥探针到期即失败并停止第二项，先按原 10 秒+2 秒组等待收尾；正常路径仍跑两个探针。
- pending 时仅发布固定白名单 JSON 的 diagnostic-only 包，沿原 scope_move 原子搬迁与发布锁；不复制 env/tmp 或 Config.Env，不更改产品失败、Docker pending 或方案 B 的原处置边界。
- 严格策略下旧已启动未闭合的环境保留待核；旧合法 hosted 委托记录不因新协议补签或改写。只有新协议 run 必须在 hosted 快路径继续校验 Docker 台账。

- 独审 I1/I2 修补：每层重复键在身份/状态判断前拒绝；有效台账原字节与派生摘要同次读取、白名单验证后封存到既有报告叶。闭合和待处理记录都保留必要观测；未知字段不导出原文，不改变 pending 状态或既有上限。
