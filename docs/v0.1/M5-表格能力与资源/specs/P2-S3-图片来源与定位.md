# P2-S3 图片来源与定位：规格

> 状态：待实施，已根据实际反例和独立设计审查修订｜日期：2026-10-19｜基线：`c6779bc2`｜上层：[P2 设计](../02-P2-图片入口与可靠渲染.md) §3.5。沿已批准的自主推进执行。

## 1. 目标与边界

IMAGE 首参必须能证明来自公式中的平台地址字符串字面量；把同一个地址写在单元格、拼接或函数计算后传入均拒绝。图片命令及片段在进入模型之前归一合法地址、拒绝非法地址。保存和另存副本被图片规则拒绝时给出有界的位置，帮助找到问题，不回显图片地址、正文、文件名或凭据。

S2 的图片身份、字节读取、解码与缓存机制保持。S3 不开放图片菜单、上传、粘贴或拖放，不替代 S4 三项真实原生补证；不处理链接的 DEF-052 部分，不改 sheet@1、保存协议、引用授权、数据库或 SDK 版本。正式输入仍由现有入口守卫阻止。

## 2. 当前代码事实

- RestrictedImageFunction.calculate 只收到已求值的 BaseValueObject，合法地址的拼接结果会通过。仅检查字符串值无法落实来源要求。
- 固定 engine-formula 1.0.1 已提供 BaseFunction.needsAstChildren/calculateAst。FunctionNode 的同步/异步执行都先按子节点数量检查参数个数，再传入 AST 和 getVariant；后者保持现有引用转数组及日期语义。
- 字面量由 ValueNode 表示，字符串 token 保留引号与双引号转义；ValueNodeFactory 是公开导出，节点类型约定必须集中在 internal-api 并用实际解析器证明，不另写公式解析器。
- 实际解析器反例已证明：定义名称在 AST 生成前被展开，`IMAGE(sourceName)` 与字面量产生相同 ValueNode，根节点的 definedNames 也可能为空；透明括号同样消失。原始日志在本地 `s3/ast-v4.log`。单靠 AST 节点种类不足以证明来源。
- BeforeCommandExecute 的参数对象进入实际命令及撤销；入口守卫必须保持创建工作簿之前的第一个订阅者。现有链接改写只看 set-range-values 的相关富文本，不遍历整个工作簿。
- set-sheet-image 先从 drawings 生成 JSON1 redo/undo，再执行 set-drawing-apply；其 op 同时写两个 drawing 服务。op 中删除的旧值不是新输入，不能扫描所有字符串而把合法删除或修复拦下。
- 后端已经在受限子进程中检查快照和资源 data 内的 source。当前只回 rule，embeddedJson 丢失资源索引；增加位置须沿原扫描和 IPC 返回，不在 HTTP 主进程重新解析快照。

## 3. IMAGE 的结构证明

固定 engine-formula 补丁在最初的词法树中、定义名称展开前证明每个 IMAGE 的首参仅含字符串字面量及透明分组括号。名称展开的真实拼接同时传递原已证明调用的精确输出位置；嵌套定义名称产生的文本不继承证明，禁止按 IMAGE 的遍历序号配对。重分词后仅在准确对应位置附加运行期标记，parser 将标记传到函数 AST；不保存标记到工作簿，不改变其他函数的计算。

包装执行器声明 needsAstChildren，直接 calculate 的无来源调用默认返回 #VALUE!。calculateAst 同时核对函数的展开前证明、首参为直接字符串值节点、没有子表达式且 token 带引号。透明括号允许；引用、区域、数组、拼接、计算函数、名称和 lambda 参数均不能当成字面量。空格按 SDK token 语义处理，双引号转义按 SDK 语义解码，再与求值得到的字符串核对。合法首参的其余参数可以继续使用名称或计算表达式。

解码后的地址复用 contracts 的平台判定：规范相对地址或当前同源绝对地址可用；其他源、编码绕写、查询/片段、多余路径等拒绝。检查通过才将原首参和其余参数交给原 IMAGE 执行器，原参数个数、缺省值、模式、尺寸、错误传播与结果对象保持。首参拒绝不能调用原执行器或图片 IO。若固定 SDK 对 null/引用的实际协议与类型声明有差别，先记录反例，集中适配，不能用不安全强转代替证明。

主线程及 Worker 继续共用安装函数，Ready 注册、AST 缓存失效和下一宏任务复核均保持。增加的 SDK 符号/节点约定只经 internal-api 的 Worker 安全出口；不用 UI 包。扩展 S2 的 engine-formula 固定补丁，更新清单、锁文件和独立冷安装证明；其他 S2 修复保持。

## 4. 命令和片段边界

新增 SDK 无关的图片片段清洗器，仅处理明确传入的图片相关子树。规范 source 与 base64Cache 只能保留相对平台地址；同源绝对地址归一，其他地址拒绝整次图片写入。source 与其缓存字段同时提供时保持一致，不把临时地址或占位写入。普通文字、单元格值和合法链接不改写。

清洗采用先验证、后提交的方式，失败不能留下部分改写。对象遍历有深度/元素上限、循环与异常对象处理；拒绝时只发通用图片错误，不报告输入内容。普通大表写值只逐格检查是否有 p 或对象样式等图片载体，不递归 v/f 或整份工作簿。

接线分两层：

1. 高层图片插入/更新和已知片段入口，在生成 undo/redo 前清洗 drawings、doc、相关 cellValue/p/样式子树。命令清单由固定 SDK 导出定义或集中协议提供；普通未知命令不做宽泛的全参数扫描。编辑栏带图的粘贴及工作表背景仍按既定不支持范围拒绝。
2. set-drawing-apply 在写入前用真实 JSON1 协议计算候选 drawing 状态，并检查新增或改变的图片字段必须已规范。不能把 op 的 r 旧值当新输入。此层拒绝而不重写已有 undo/redo，避免逆操作与模型不一致。非法/看不懂的相关操作安全取消，真实其他异常仍按项目通道报告。

预演在 apply 前只允许已证明不原地改对象的 JSON1 基础操作及 text-unicode/number 子类型；拒绝 SDK 中会原地改正文的 text-x 和未知子类型。后续拒绝时两个服务、历史原件与版本必须均不变。普通合法操作保持精确 undo/redo；在 Undo/RedoCommand 的任何 mutation 执行前预检整个相关记录，不能让 preUndos 先发生。

非法旧值的清理不得伪装成普通可撤销修改。普通命令若会把旧非法来源写入逆操作，拒绝并给出通用说明；清理能力必须通过显式确认的独立事务执行，确认文案须说明“此操作无法撤销，并清除当前文档此前的撤销历史”。完整预检通过且清理成功后，才对该 workbook 调用 clearUndoRedo；取消、失败、读取及普通非法输入均不能清史。S3 不开放此清理入口；后续正式入口须复用这一明确的确认边界。不得实现会卡住栈顶的坏 undo，也不得静默重写逆操作或清空历史。

prospective JSON1 与服务读取在 internal-api 封装，图片策略不深引 SDK。必须证明预演不改两个实际 drawing 服务、撤销记录或版本序号；只在 drawing mutation 上预演，不为每个键入捕获/扫描工作簿。若该办法无法满足固定 SDK 的无副作用约束，先以实际反例修正方案，不提交未经证明的模拟。

策略在入口守卫之后、工作簿创建之前安装，阅读/编辑都安装，销毁退订。只读防火墙、链接改写和公式的正常写回顺序保持。测试探针可以驱动实际底层命令，但不能另造正常生产缺失的策略。

## 5. 有界图片错误位置

contracts 为 SNAPSHOT_INVALID 增加可选 imageLocations，只有 image-source 使用。最多 5 项；每项采用有限种类和结构字段：cell（sheetId、零基 row/column）、drawing（sheetId、drawingId，可选可信锚点）、sheet（sheetId）、resource（resourceIndex）、workbook。标识最多 128 字符且仅接受结构标识写法；行列及索引为有上限的非负整数。无法证明结构归属时降为 resource/workbook，不猜坐标、不复制任意路径键。

响应继续宽松：旧服务端没有位置、未知规则、非法位置或未来种类均回退原通用文案；不让位置解析失败遮住原错误。资源名、sheet 名、source、单元格内容和文件名不由服务端返回。位置不进入日志；原日志仍只含规则、文档 id、字节数等事实。

检查子进程在已有图片扫描中携带有限路径上下文。解析资源 data 时保留资源索引，继续累加原深度/元素预算，不重复解析来找位置；找到最多 5 项后即可按 image-source 拒绝。覆盖单元格 p.drawings、SHEET_DRAWING_PLUGIN 的 drawing、嵌套填充/其他 source、工作表背景与无法识别的结构。任何 source 原有判定不放宽。

SnapshotInspection → ProcessPool → InspectionOutcome → snapshotInvalid/requirePassingSnapshot 只传小位置对象；保存及另存副本共用。未通过检查的快照、修订、引用均不写入。

前端通过编辑器适配层只读的工作表名称查询，把可信 sheetId 和坐标描述为“工作表「名称」的 B3”等；无可用实例或无法识别工作表时使用明确的通用位置，不能展示任意服务端字段。查询不 capture、不改选区、不写模型；销毁/重建期间可返回 undefined。普通保存与另存副本复用同一个格式化器，最多显示 5 项。链接错误继续沿原文案。

## 6. 验证与完成定义

- 单元先 RED 后 GREEN：真实 AST 的合法字面量、大小写/_xlfn、空格/引号、引用/区域/数组/拼接/函数/名称/括号、参数数目和原模式/尺寸对照；直接 calculate 无来源不能放行。
- 图片片段的归一/拒绝/不部分写入、有界遍历、普通大表不递归值；真实命令栈的源更新、内部片段、rich text、填充、旧非法值清理的显式确认/历史屏障、undo/redo、只读和生命周期；TextX 与复合撤销的后续拒绝不留下部分修改。
- contracts、实际检查子进程和 API 集成：位置准确/有限、不回显内容、不落日志，旧/未知响应回退；保存及副本拒绝不写库。
- Chromium/Chrome/WebKit、主线程及 Worker：同一个合法资源作为直接字面量可读，拼接/引用等返回 #VALUE! 且零资源请求；非法命令不进模型/撤销，合法绝对地址规范保存/重开；实际图片保存错误位置可见，改正后可保存。
- 改动范围回归、类型、lint、构建、Worker/首屏预算、独立复核后一次 S3 中文代码提交。正式入口、原生补证、完整 verify/容器/CI 仍在 S4–S6。

自审：来源证明、写入边界与最终保存检查职责不同；后端不依赖 SDK，shared/contracts 不引用编辑器；正文保存和身份策略没有新增旁路。全部范围已由 P2 设计批准，无新增用户决策。
