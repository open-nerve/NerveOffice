# P3-S4 数据验证面板连续编辑

> 状态：Task 1 经独立审查修正，待 S4 最终检查；基线 `a0a9344d`。属于 S4 Task 1 的局部缺陷修复，不新增产品范围。

## 实际问题与边界

正式宿主的 Chromium 反例已证实：范围、设置、选项共用一个 1 秒的 trailing debounce，后一次调用覆盖前一种命令；设置后立即切换列表类型，会从旧模型读取规则，覆盖刚输入的设置；确认关闭详情后，模型仍需等旧计时器。原件见主项目 `.codex/handoffs/m5-p3-20261020/s4/panel-red01/02`。

`panel-red01` 两种顺序均在约 60 ms 内完成真实点击，服务器只保留后者。`panel-red02` 的列表切换与立即关闭同样到达内容断言；范围用例暂只作观察，先校准 RangeSelector 的真实文本输入，不能把输入夹具未送达算产品证据。

平台现有 panel-debounce-watch 等到输入落入 SDK 模型后再捕获；它能处理尚未提交的输入，无法恢复已被 SDK 丢弃的命令。继续使用这个单一保存路径及原有 1,000 ms/20 ms 等待边界。批注 300 ms 的既有路径在本 Task 保留，后续备注矩阵检查。

## 选择的修复

在固定 `@univerjs/sheets-data-validation-ui@1.0.1` 的详情组件内，把“仅最后一个调用”改为按实际输入顺序排列的待办。仅相邻同种操作合并，同一窗口内不同种操作全部执行；设置只保留用户实际改过的字段，执行时与当时模型的完整设置合并。不能把范围操作前后的设置合成一次，否则会破坏 SDK 公式位移的顺序。范围、设置、选项仍执行 SDK 原有命令，保留校验、权限和撤销历史。

执行器只服务于这三个已核实为同步 handler 的命令，使用现成 `syncExecuteCommand`，使 flush 返回时模型和撤销记录都已更新。执行失败不冒称成功；真实异常保持可观察。没有新公开 API、保存接口或数据结构。

命令返回 false 或抛出时，保留失败项及其后续输入供明确重试，后续项不得越过失败项执行；异常不吞掉。撤销监听只处理当前工作簿的撤销，不取消另一个内部文本编辑器或工作簿触发的历史操作。

边界：

- 类型切换前先 flush，再按当前模型构造兼容列表规则；不能读取未提交的旧状态。
- 有效的“确认”先 flush 后关闭；删除先提交当前输入再删除，使撤销删除能恢复用户最后看到的规则。
- 侧边栏关闭状态发布时就提交，不能等隐藏后的异步卸载；详情卸载仍提交属于原 Workbook/Worksheet 的待办并清除计时器。原对象已退役则取消，不按同 id 寻找新对象。
- 实际规则删除及撤销/重做前取消尚未提交的输入，避免旧计时器覆盖历史操作；撤销后立即按模型刷新本地控件及范围编辑器正文，不留延迟确认窗口。规则变更监听与命令监听随组件释放。
- 控件显示和排队使用同一次最新规则状态，避免范围失焦与另一控件的事件挤在同一次渲染时互相覆盖。

只拆成三个独立计时器仍缺少明确关闭与类型切换顺序；完全取消防抖则改变连续键入的撤销粒度。相邻同种操作才合并，使跨范围命令前后用户编辑的语义和历史顺序一致。因此保留一个 1 秒窗口，积累不同命令，并在明确边界同步提交。

## 范围输入的追加发现

`panel-range-diagnostic03` 的真实键盘逐字输入 `C3:C4` 被控件改为 `C\r\nC4\nC\nC`，范围命令收到 NaN 行号并删除了规则。整段 input 事件和每键 20 ms 的对照正确，原始失败保留；不以放慢操作替代修复。`sheets-formula-ui` 的 `useRangesHighlight` 先由一个 effect 解析最新文本、更新 sequenceNodes，另一个 effect 却可用上一轮 sequenceNodes 重写当前正文。修复让高亮以执行时的当前文本及其解析结果为一对，禁止旧语法树回写新输入；ES/CJS 同步，真实快速输入作反例与变异。

数据验证面板同时用 SDK 自有 `isValidRange` 检查解析结果，无效范围保留原规则并显示原有范围错误。整行/整列仍沿 SDK 的 rangeType 语义，不用“所有坐标必须有限”误拒绝合法整列范围。该检查补上错误文本到规则矩阵之间的边界，不改变保存协议。
