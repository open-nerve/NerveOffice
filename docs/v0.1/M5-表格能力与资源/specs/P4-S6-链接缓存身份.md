## 方案比较与选择

| 方案 | 实际责任及副作用 | 结论 |
| --- | --- | --- |
| 在 DocEventManager 的正文 change$/dirty 上清空全部 hover | 生产者能释放旧值，但该服务是通用 Docs 事件源；dirty 还包括 resize/scale/布局，订阅者包含指针形态与其他交互。简单清空会让仍有效的悬停失效，扩大到 docs-ui 和所有范围类型；已经排队的消费仍需检查。 | 不选。保留现有几何失效与发布机制，不把本问题扩成事件框架。 |
| 在当前单元格链接消费者核对事件和当前 Docs，拒绝过期范围 | 两个实际 controller 已同时持有 IUniverInstanceService 和 editorUnitId。可在延后回调真正消费时查当前正文，范围明确且不依赖猜测源事件时序。 | **选择此方案。** 只改现有 sheets-hyper-link-ui 包的私有共享判断与两个 controller。 |
| 在 UI/cancel 时把旧 ID 换为当前第一个链接，或 skip(1)/延长等待 | 更换 ID 可能操作错误链接；跳第一项破坏已通过的有效重放；等待不能证明身份。 | 拒绝。命令、选区、原时限和按钮动作不改。 |

## 具体合同

在本包 ES/CJS 内增加一个**不导出**的局部 helper，逻辑名定为：

`resolveCurrentEditingHyperLink(instanceService, editorUnitId, candidateRange, segmentId?) -> ICustomRange | null`

它只读当前模型，不发命令、不修改 range 或任何状态。输入来自已通过既有 normal editor、可见、owner 和权限判断的 controller：

1. 只接受 `editorUnitId === DOCS_NORMAL_EDITOR_UNIT_ID_KEY`；事件 segment 只能是 `undefined` 或空字符串，对应 normal editor body。null、非 body/未知 segment 返回 null，**不回退正文**；即使 SDK 的 getSelfOrHeaderFooterModel 自身把 null 当作 body，本入口也不放宽。本次不扩展 rich 命令的 header/footer/notes 支持，也不改变独立 Docs 的功能。
2. 用 `instanceService.getUnit(editorUnitId, UniverInstanceType.UNIVER_DOC)` 取得真实当前模型，再用 `getSelfOrHeaderFooterModel(segmentId)` 取得该 body；文档/body 缺失返回 null，不读取 B3 或 state.documentModel 兜底。
3. 按候选的同一个 rangeId 找当前范围，且两者都是 HYPERLINK、startIndex/endIndex 相同。ID 不存在或区间已迁移时返回 null；不使用数组第一项，不猜测新 ID，不以 visible 或同一 cell owner 代替身份。
4. 核对菜单实际消费的元数据：`properties.url` 以及有效 tooltip（`tooltip ?? _xlsxHyperlinkTooltip`）与当前范围相同。这里不做新的 URL 规范化或权限放宽。旧元数据返回 null，等后续正常事件。
5. 合格时返回**当前模型中的那一个同 ID 对象**。不要求对象引用相同，因此正文语义相同的复制/重建不会被误拒；不因它是第一条重放而丢弃。

两个 controller 均在以下两处使用同一 helper：

- 收到合法编辑 state/visible 通知、完成原跨 owner 退役后，若现有同 owner `currentPopup.type === editing` 已不满足当前 body 的身份/语义，立即 `hideCurrentPopup(editing, true)`。相同正文的重复通知保留原菜单。这里不新调用 endEditing，不改变表单 keepVisible；原异 owner/退出路径继续处理表单。
- 桌面 debounce 回调及移动 click 回调真正消费时再次解析**事件**。非法的 HYPERLINK 事件强制关闭 editing 菜单并停止，不发任何命令。合法事件到达时也先校验已经展示的 editing 菜单，过期则强制关闭，再把 helper 返回的当前范围交给既有 showPopup。这避免服务的相同 ID 去重留下旧 URL/tooltip/区间。未命中链接的原 hide 行为、画布 rect/skeleton 条件、权限与 viewing 路径保持。

已经展示的 editing 菜单来自这条 body-only 入口；检查它时 segment 使用 body，不新增 popup 字段。强制关闭仅针对 editing 菜单，避免鼠标停在旧菜单里令 canDispose=false 阻止失效；不误关新 viewing 菜单或普通链接表单。

本修复的承诺是每次编辑状态通知或正文链接事件消费时成立的身份约束。它不新增全局正文变化订阅或每个按钮的事务协议；已经显示后、没有任何状态/范围事件的新变化仍属于既有生命周期。若验证揭示此独立可达问题，先保留新证据再明确范围，不能暗自扩成通用事件层。
