# P4-S5 资源回收与备份水位

2026-10-23；基线 S4 `12b76056`。按已批准 M5 总设计 §6.5、P4 §3.5 与项目 JIT 授权自审后实施；同一 P4 分支，不开放生产库回收测试。

## 1. 目标、事实与选择

没有任何当前文档、历史、删除/升级检查点引用的 assetId，在完整宽限后才能删除；物理对象必须另外没有 assetId 或上传占用，备份水位也允许，才回收其字节。权限上的不可读不等于可以回收；回收站、归档、其他空间与副本均按真实关系保留。

现有上传先在配额事务中 reserve，再退出事务 publish 文件，最后 finalize；claim 与 object 都按 hash 唯一。旧文件固定为 `objects/<前两位>/<hash>`，只用这个路径删除会与重新上传同 hash 冲突。文件 IO 不能放在长数据库事务中，进程内互斥和可过期租约都不能证明暂停很久的旧进程已停止。

三种选择：继续复用 hash 路径会留下旧删除误伤新文件的边界；仅增加数据库代次能隔离新对象，但不能阻止旧发布在删除确认后重新产生孤儿文件；采用**不可复用的代次路径、持久删除回执与永久空标记**，同时解决两者。代价是每个已退休代次留一条小记录和一个零字节私有文件，回收的是图片正文占用，不承诺 inode 数归零。

业务接口与图片 URL 不变，不增加依赖。Assets 拥有对象、配额、文件、候选与删除任务；Documents 提供全部保留引用的有限集合判定；Jobs 组合公开接口。Assets 不导入 Documents，也不读取其表。

## 2. 对象代次和旧文件兼容

- `asset_objects` 与 `asset_object_claims` 增加可空 `generation: uuid` 和 `unreferenced_at: timestamptz`。空 generation 只表示既有旧路径；迁移不改文件、不回填虚假的代次。正式 reserve 对新的 hash claim 分配新 UUID。部署必须先停旧应用实例，再迁移并启用新版本；旧程序不能读取新代次路径，不支持这次变更的新旧服务混跑。
- 代次路径为 `objects/<前两位>/<hash>.<generation>`；旧路径仍可读。路径只能由摘要和规范小写 UUID 生成，不能来自用户路径。数据库约束同时校验两种路径，metadata 返回的 storageKey 仅供服务端读取。
- reserve 返回 `AssetObjectReservation { sha256, generation, storageKey }`；publish 必须使用该路径；finalize 必须提交同一个回执。匹配的是整个代次，不能只匹配 hash。reserve 重用现有对象/claim 时清空其孤儿候选时刻。
- 正常同 hash 上传仍复用同一个存活代次。旧代次进入删除任务后，新上传分配新代次并重新收费；旧回执即使字节完全相同也不能借新 claim 转正。
- 已发布但未转正、reserve/发布/提交结果未知、记录配额不足留下的 claim 都保留收费并可接续；只有完整 GC 协议可以释放。

## 3. 不可再发布的文件退休

`StorageAdapter.retire(key, expected)` 只消费服务端删除回执的规范路径、hash 和字节范围，不扫描任意目录。不在数据库事务中执行。

1. 沿现有规则复核私有根、命名空间与 shard，拒绝符号链接、非普通文件、错误权限或所有者。不存在的 shard 可以按 0700 创建并同步。
2. 以已有任务临时文件占用保护一个新 0600 零字节文件，sync 后原子 rename 覆盖该退休路径，再 sync shard。
3. 清理自己的临时文件。原路径留下零字节标记，任何迟到 publish 的 hard link 都遇到 EEXIST；完整性检查会拒绝它，不允许覆盖标记。

不存在的对象也建立标记，防止未开始的旧发布；已有空标记可幂等重做。publish 先成功或 retire 先成功，都不能使旧 finalize 再成功。中断在 rename 前、后、目录同步前或数据库确认前，只会使持久任务待接续，不能提前释放配额。新代次路径始终不同，旧任务重放不会触碰它。沿 ADR-021 的边界，不声称抵御能够改写服务私有目录的本机管理员。

标记及完成回执在本阶段不自动清除；不能用运维脚本随手删除，否则失去防止迟到发布的证明。

## 4. 引用候选与锁协议

`assets.unreferenced_at` 初始为空。不能拿上传时间替代失去最后引用的时间，也不能只定期观察引用是否存在：两轮扫描之间短暂建立、又移除的引用，同样必须重新计算宽限。

新增 `asset_reference_activity(asset_id, transaction_id)`，联合主键，asset 外键 CASCADE。当前关系、检查点关系在实际 INSERT 或 asset_id UPDATE 后，由数据库触发器为本事务记一次活动；同事务同资源多次写入去重。使用数据库事务号，禁止客户端传入。这里采用追加记录，避免多文档检查点按不同资源顺序更新同一候选行产生新的反向锁；不把原共享资源锁升级为排他锁。

扫描一页先锁 quota，按 assetId 有序取得 assets `FOR UPDATE SKIP LOCKED`，然后只读查询 Documents 的保留集合。此时 FK 的 KEY SHARE 和既有资源 SHARE 都与回收互斥；回收不取空间/文档锁。保留关系与活动查询完成后再取新的数据库时刻；移除引用不必锁资产，不能把候选起点回溯到查询期间仍有引用的时刻：

- 任一当前或检查点关系存在（包括尚未物理过期清掉的检查点），或仍在上传者 24 小时窗口内：候选为空。
- 无引用且有新活动，或尚未成为候选：将候选设为这次查询完成后的时刻。
- 无引用、没有新活动且已有候选：维持原时刻；只有宽限和水位同时成立才删除 assetId 并减少记录配额。
- 本页活动在同一事务内消费；清除失败整体回滚。数据库旧 RR 快照也必须经实际写/锁冲突失败，不能吞掉新活动而保留旧候选。

Documents 的保留查询只回传本页 id，不返回正文，也不以现在的用户权限过滤。资产行 FK RESTRICT 仍作为最终兜底；任何未登记的新增引用都不能变成悬空关系。

## 5. 物理对象、孤儿与持久任务

assetId 与物理对象分两层计时。最后一个 assetId 删除后，对象才从本次扫描开始新的孤儿宽限；失败 claim 从首次扫描成为孤儿候选时开始，reserve 使候选失效。这样最多增加一轮完整宽限的占用，换取清晰且独立的备份保护，不按原上传日期倒推。

在 quota 行锁下检查 hash 的 object/claim；同一 hash 仍不能两者共存。object 有任一 assetId 时清空孤儿候选；无引用且候选成熟、备份条件满足时，在同一短事务内：

1. 插入 `asset_object_deletions`：id、hash、generation、storageKey、bytes、unreferencedAt、createdAt、completedAt（空表示待执行）。storageKey 唯一，身份与字节元数据不改写。
2. 删除原 object 或 claim；不释放字节。
3. 同事务记有界聚合审计。此后新的 reserve 只会得到新代次。

持久任务经再次核对配置、水位、任务身份及无存活同路径后才执行文件退休。文件退休已确认后，另开短事务按 quota → task 顺序锁定；仅 pending→completed 的首次确认减少 usedBytes。未知提交先重读任务；失败保留任务和收费，不盲目补偿。

I23 调整为：`usedBytes = objects.bytes + claims.bytes + pendingDeletion.bytes`。记录配额仍严格等于 assets 数量。新不变量检查存活路径与退休路径不能重合、已完成任务不重复收费、引用活动有合法资产、候选/任务时刻有限且状态一致。旧回执可重复执行，不能删除新代次或重复释放额度。

## 6. 配置与可信范围

| 配置 | 默认和范围 |
|---|---|
| NERVE_ASSET_GC_ENABLED | true；开启定期候选整理，不代表已允许物理删除 |
| NERVE_ASSET_GC_INTERVAL_MS | 3600000；1000–86400000 |
| NERVE_ASSET_GC_BATCH | 100；1–1000 |
| NERVE_ASSET_GC_GRACE_DAYS | 30；1–3650 |
| NERVE_BACKUP_RETENTION_DAYS | 无默认，运维显式声明；1–3650 |
| NERVE_ASSET_GC_RECOVERY_BEFORE | 无默认；规范 UTC 时间，表示所有仍可能恢复的备份/日志起点都不早于此时刻 |

宽限小于已声明的备份保留期、非法数字或时间写法，配置解析拒绝。缺少保留期/水位、未来水位或水位晚于“数据库当前时刻减备份保留期”时，GC 返回明确暂停原因，只整理候选/消费引用活动，不删除资产、不排新退休任务、不执行已有物理任务。

允许删除还要求 `unreferencedAt + grace <= now` 且 `unreferencedAt < recoveryBefore`；水位相等仍保留。每批锁后与物理 IO 前重新判定。运行中修改备份策略需要暂停所有实例 GC、核对后更新配置并重启，不能让新旧实例使用矛盾的恢复承诺。

“可信”指部署管理员已经核对所有保留备份及 WAL 的最早可恢复起点，再提供该声明；日期校验不能自动证明外部备份内容。没有证据就不配置水位，不用当前时间伪造。M7 尚未提供备份目录的自动证明，因此默认安全停用物理回收；本 Step 不冒充已完成备份恢复演练，也不允许在线恢复数据库时留下旧应用进程运行。

## 7. 调度、审计与边界

AssetGcJob 使用现有调度器和跨实例独占执行；各扫描页、排队与完成确认是独立短事务，文件 IO 在事务外。按 assetId/hash/id 稳定游标分页，固定本轮上界，允许锁竞争跳过并于下一轮重查。退出完成当前安全单元后停止；失败本轮停止，下轮从持久状态接续。无无限内存列表。

默认每小时整理活动，缺备份条件时也有界消费活动；明确关闭整个 GC 后活动可能累计，部署文档说明。日志和审计只记录数量、有限阶段/原因，不输出图片、绝对路径、正文或无限 id 数组。现有 staging 临时文件回收保留其独立占用协议。

## 8. 必验反例与自审

- 同 hash 双上传去重；旧文件升级后读回；新代次 reserve→publish→finalize 对应；错误代次、已退休回执及未知提交拒绝错误转正。
- 当前/归档/回收站/副本/用户历史/before_delete/before_upgrade 逐项保留；权限不可读不放宽；过期未清的关系保守保留。
- 新引用与 GC 两个先后、旧 RR、两轮之间短暂引用、清除/到期/复制/删除/升级检查点与资源锁交错；无新增反向锁与悬空引用。
- 宽限和水位精确相等/差一毫秒、缺失/未来/超出保留声明、配置收紧；暂停不影响正式保存、读取和历史。
- claim、同 hash 多 assetId、孤儿对象；配额边界；排队/文件退休/完成确认故障和未知提交；旧删除重放与新代次上传并发。
- 真实文件的旧发布延迟、标记重做、并发退休、symlink/FIFO/权限/坏键拒绝；真实子进程 SIGKILL、进程恢复与私有生产卷。

自审：实现范围属于已批准 P4，采用既有模块方向和短事务规则；所有危险删除有持久身份与备份条件；旧材料不迁写；质量与最终阶段门禁不延期。物理回收默认暂停是明确的安全行为，不是将失败测试归为环境缺口。
