# P2-S2 图片实例与可靠渲染：规格

> 状态：已自审，待实施｜日期：2026-10-19｜基线：`73436bb8`｜上层：[P2 设计](../02-P2-图片入口与可靠渲染.md) §3.3–3.4。沿用户批准的自主推进执行，不重复请求 Step 审批。

## 1. 结果与边界

图片必须经过当前页面身份的真实请求才能显示；可见的浮图、单元格图片以及 IMAGE 结果都在实例范围内清理。过期任务不能复活旧像素或写入新实例。坏图不停止表格后续绘制，自动行高不把图片在重开后拉长，Ready 前销毁不留下 drawing 的未处理拒绝。

不改变 `sheet@1`、快照/撤销/发件箱的格式、后端资源协议、权限规则或正文保存。文件输入和三项原生补证在 S4；正式入口在 S5，仍然关闭。IMAGE 的字面量规则和非法来源写入拦截在 S3；本 Step 的读取入口已独立拒绝非平台地址。

## 2. 固定发布包上的调用事实

使用安装的 `@univerjs/*@1.0.1`，不是只读参考的 1.0.0。以下行为须由回归固定：

| 位置（lib/es/index.js，补丁前） | 当前行为 | 本 Step 责任 |
|---|---|---|
| drawing 的 ImageIoService / URLImageService | UUID 和 URL 分路；默认 URL 下载器失败退回原地址 | 在 drawing 插件 override 中替换两个完整服务；禁止默认回退 |
| drawing-ui 的 DrawingRenderService.renderImages（约 828） | 先查元素缓存，URL 异步读取失败仍回原地址；异步后未核对场景/图元是否退役 | 保留规范模型 source，只使用鉴权后地址；核对旧场景/来源 |
| drawing-ui 两处 image update（约 3032、4470） | 移动/缩放等更新直接 changeSource(source) | 更新同样经图片服务，不能因变换退回原 URL |
| core 的 ImageCacheMap（约 26838） | 单元格富文本有自己的元素缓存；URL 失败回退；先设 src 再挂 onload | 缓存元素纳入实例清理；先挂回调，不回退原地址 |
| sheets-drawing-ui 文件插入（约 620–735） | saveImage 后直接 getImageSize(base64Cache)，浮图和单元格路径各一份 | 量尺寸也经 URL 服务；保留规范 base64Cache，不把 blob 写入模型 |
| engine-render 的 Image.changeSource / _drawNative | 修改可能共享的原元素；坏图直接 drawImage | 变更 source 不改其他图元共用的元素；坏/未完成图片跳过绘制 |
| sheets-drawing 的自动行高刷新、drawing 的 refreshTransform | Position 保留尺寸但旧锚点被保存；后者不传递两个锚点字段 | 按保留的 transform 重算锚点并传递；保留原局部派生更新语义 |
| sheets-drawing-ui 的 touchSheetsDrawingFloatingHostCapabilityWhenReady | Ready 等待未处理 LifecycleUnreachableError | 仅把销毁导致的不可达视为取消，保留其他错误报告 |

仅替换 IO 服务无法覆盖表中的直连和缓存；全局改 Image/canvas 原型会影响其他组件且掩盖错误。选择实例服务加固定依赖最小修复，不重写编辑器，也不升级 SDK。

## 3. 解码与图片资源所有权

### 3.1 浏览器解码

`editor/images/decode-image.ts` 接收 S1 的 `AssetBytes` 与 `AbortSignal`，创建 Blob 和对象 URL，用独立 HTMLImageElement 解码。限制沿用 5 MiB、单边 8192、总像素 16,000,000；浏览器解码另限 10,000 ms，HTTP/正文仍是既有 30,000 ms。解码失败、超限、取消或超时都撤销对象 URL、清空临时元素；成功交出 `{ url, image, dispose }`，所有权转移给调用者。dispose 可重复、同步清理。取消原因为调用方原对象；迟到 decode 不能恢复已清掉的资源。

解码超时不能强杀浏览器内部解码器；取消 src 并撤销对象 URL，使迟到完成不可见。真实浏览器像素用 E2E 证明，jsdom 的 decode 替身只证明时序和资源归属。

### 3.2 每实例资源表

`editor/images/image-resources.ts` 无 SDK 依赖。地址只接受规范相对地址及本站同源规范绝对地址；归一后只向 S1 传相对地址。其他输入在任何网络调用前拒绝。

接口为 `createImageResources(options): ImageResources`：

- options：`origin`、受控本地 `placeholder` URL、`read(source, signal): Promise<AssetBytes>`、`decode(bytes, signal): Promise<DecodedImage>`、`changed(): void`、`failed(error): void`。
- `load(source): Promise<string>`：同代同源合并在途读取，成功返回解码后的 blob URL；普通读取/解码失败报告一次并返回本地占位。取消/退役必须拒绝，不冒充占位成功。
- `cached(source): HTMLImageElement | undefined`：只有本代解码成功的元素可复用；不因相同 src 推断重新鉴权。
- `track(source, image): void`：登记 SDK 创建/保留的元素，使其只显示当前该来源已确认的地址或占位；同一元素换来源时先从旧来源解绑，避免旧刷新改动新图。
- `refresh(): void`：同步使旧代失效、取消在途、把所有已登记元素改为占位并撤销旧 URL；随后重新读取已使用的来源。重读成功后更新仍属于该来源的元素，并通知画面重绘。
- `suspend(): void`：同样同步清理，但不重新请求；暂停期间 load/download 拒绝。`refresh` 可在同用户身份确认后恢复；实例 `dispose` 后不能恢复。
- `download(source): Promise<Blob>`：每次经新的真实读取与解码验证，返回原始成功字节；不使用旧显示缓存、不下载占位、不自动重试。自己的临时解码资源在返回前释放。
- `dispose(): void`：永久退役、清理全部资源与订阅，幂等。不得等主线程公式退出才清图片。

表中记录来源和元素，不保留多份原始字节。旧代承诺即使底层忽略 AbortSignal，也必须及时拒绝；迟到返回的 DecodedImage 必须 dispose。内部自动刷新承诺有明确拒绝处理，不制造 unhandledrejection。失败报告不包含原地址、文件名、字节或会话令牌。

普通失败本代内不自动循环重读；用户明确重试、权限重核、联网恢复或实例重建才创建新代。多个图元共用一个资源时，改一张图的来源不能改变其他图。

## 4. SDK IO 与固定修复

`editor/images` 负责实现，SDK 标识/类型经 `internal-api` 主线程出口集中登记。drawing 插件配置的 override 同时提供 IImageIoService、IURLImageService；核心 override 不替代插件的注册顺序。

saveImage 先检查当前实例/上传许可与文件大小、类型和后缀，再读取文件并通过 uploadAsset 上传。不接收远程地址。上传跨过身份代次或实例退役后返回 null，不能进入后续插入。每次成功生成独立 drawing ID，即使同一个 assetId 也不同；source 和 base64Cache 均为响应的相对 URL，类型 URL。SDK wait count 只表示上传进度，不能承担图片重绘通知；所有完成/失败都正确归零。下载器注册不允许替换平台授权流程。

浮图、单元格富文本、IMAGE、插入量尺寸、移动/缩放及复制下载都须经这两个服务。SDK 内的异步取消不回退原地址；晚到渲染须核对场景仍存在、图元仍是当前来源。已解码元素被多个图元使用时，Image.changeSource 创建新元素而非改共享元素；新元素重新登记给资源表。资源清理/恢复调用窄渲染适配，标记当前场景重新绘制，不写命令/模型或修改 dirty seq。

依赖修复使用 pnpm patchedDependencies，记录确切包版本、原件摘要、补丁摘要、运行的发布入口、失败复现、回归及移除条件。当前应用和测试使用 ES 发布入口；必须核对 Worker、浏览器、构建实际选路，不能仅改只读 refer 或依赖安装目录。若 CJS 被运行，同步修复该入口并回归。每个修复先用未修复包得到行为 RED，再应用补丁。SDK 1.0.1 与 sheet@1 保持。

自动行高：Position 的 transform 尺寸不变，以新行列几何重算 sheetTransform 和 axisAlignSheetTransform，refreshTransform 仅在提供时传递字段。Both 的随单元格缩放语义、显式行高、撤销重做保持；检查切表、重开及第二次保存。

破图：仅图片自身的绘制边界判断 complete 与自然尺寸；不吞非图片错误，不覆盖 canvas 全局方法。Ready：只处理已知 LifecycleUnreachableError；其他错误仍报告。engine-formula 的潜在相同写法不按本 Step 已证实 drawing 路径宣称关闭。

## 5. 页面身份与权限接线

增加 SDK 无关的 `EditorImageAccess`：`current(): SessionResponse | undefined` 与 `subscribe(listener): () => void`。通知代表当前图片身份/权限需要清除或复核；页面提供原响应对象，不能复制丢失会话关联。不存在许可时暂停资源；有效许可下刷新。实例以创建时用户为所有者，永不接纳其他用户。

页面持有一个窄图片许可控制器，初次会话成功时激活；会话明确退出、换人、文档不可读和页面卸载立即暂停。本人重新登录（令牌变化或从暂停恢复）重新激活；同用户同令牌的重复会话确认只更新原响应对象，不反复重读，避免图片 401 → 会话确认 → 图片 401 循环。

权限详情复核完成（包括权限未改变但资源引用的权限可能变化）、真正从离线恢复和既有状态检查发现文档权限变化时通知刷新；网络请求失败事件本身不触发新读取。未确认会话/离线失败不冒充已授权，也不改既有正文保存策略。实例重建自然产生空资源表，旧实例同步清图后继续原公式退出流程。

接线不依赖测试构建开关。测试探针只能驱动/观察正式适配 API 和受控图片样本，不能在探针中实现另一条图片路径。适配失败要有本地占位与可见的图片状态；详细输入错误文案归 S4，状态不回显内容。

## 6. 验收

1. 单元：取消前后、忽略取消的晚结果、超时/破图/超限、同源规范化、同代去重、跨代不复用、换来源解绑、下载失败不冒充成功，全部先 RED 后 GREEN。
2. SDK：真实插件配置得到平台服务；source/base64Cache 恒为规范地址，ID 不复用；保存与撤销 JSON 无 blob/data URL；两个 IO 路径和所有直连点有行为证据。
3. 浏览器：Chromium、Chrome、WebKit 经实际 SDK 验证浮图/单元格/IMAGE、移动/缩放、重开；观察实际 no-store 请求、401/404/500/503 与像素清除；慢读取/上传在撤权/换人/销毁后不复活。每个失败后跟普通编辑、绘制、捕获哨兵。
4. UR-006/009/031 drawing 的反例均先复现，修复后通过；尺寸和锚点跨两次保存稳定，未处理拒绝为零，非相关异常仍可见。
5. 图片定向回归、现有 editor/page/session/profile/只读回归、类型、lint、构建与包入口/补丁完整性检查通过；独立 Phase 审查、完整门禁/容器/CI 仍在 S6。

自审：范围、责任、异步所有权、身份闭环及补丁移除条件均有归属；三项原生证据未提前确认，正式入口未开放。这里是实施规格，表中缺陷的已有复现见 UR-006/009/031，新增调用路径还需本 Step 回归证明。
