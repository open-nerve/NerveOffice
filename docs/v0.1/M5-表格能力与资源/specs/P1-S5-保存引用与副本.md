# M5-P1-S5 保存引用与副本规格

> 状态：已自审，按已批准总设计自主实施｜日期：2026-10-18｜基线：`329a6472c0ee68c47346b05f6580b3d8b3e3515b`

## 1. 范围与现状

S3 上传创建独立 assetId，S4 读取已使用当前引用表。S5 把该表接入正式保存、普通复制、上传本机内容另存为副本的事务，不开放图片前端入口、不增加历史引用或 GC。沿用单一 P1 分支，主目录保持 main。

现有保存顺序是重放预检、客户端格式检查、子进程快照检查、请求账本锁、目标文档锁、重放/身份/权限/租约/修订/结构相关校验，最后写新修订或 unchanged 回执。普通复制在源/目标空间与源文档的一致性锁下直接复制 gzip；本机副本先检查上传快照，再锁源文档、决定原空间或个人空间的位置。不能绕开这些规则。

## 2. 提取与大小边界

在现有快照子进程完成 JSON、结构、资源 data、图片与链接规则之后，从解析后所有字符串值中收集规范相对图片地址。包含普通字符串、数组、富文本、资源 data 解析值、公式中的地址字面量；不看对象键、不执行公式、不读取外部地址、不递归解析任意字符串。顶层资源 entry 的序列化 data 不再按原始文本扫描，使用已经通过深度/元素预算检查的解析结果，避免转义或重复键产生假引用。

地址为小写 `/api/assets/<uuid>`。整串或在文字/引号边界中的独立地址可识别；相邻 URI 字符不得把外部域名、查询、片段、编码、附加路径、较长 ID 截成一个有效地址。所有标识去重、按码元顺序排序；返回 `PassedSnapshot.assetIds`，没有时为空数组。非法 source 仍先被原有 image-source 规则拒绝，提取不能改变校验顺序或放宽范围。

5 MiB、嵌套/元素、子进程堆/超时/队列预算保持。结果只包含 ID，不回传正文或图片。来源查询每个输入 ID 至多一个候选；SQL 的 ID 集合使用既有数组参数，不能展开为超过 PostgreSQL 65535 参数的 VALUES/IN。用接近 5 MiB、超过 65535 个不同地址的真实样本验证提取、IPC 与批量查询，不新增静默截断或任意引用数量限制。

## 3. 可建立的当前引用

一次实际写入只对已存在的 assetId 建立以下任一来源的引用：

1. 目标文档在锁下已经持有该当前引用，并且操作者能够编辑该文档。
2. 操作者为该 assetId 的上传者，按本事务数据库时刻仍在严格 24 小时窗口内。
3. 已锁定的其他有效当前来源，按现有空间/单独分享策略确认操作者可读。

系统管理员没有额外内容权利。未知或无权的 ID 不建立引用，合法快照仍按既有保存结果提交；不回传“哪些资源存在”的明细、不把本机保存永久卡在权限错误。当前引用集合只含本次真正落盘内容提取出的合格 ID；移除图片地址时删除相应当前关系，正式对象保留。

来源预选到取锁之间，分享、成员、位置、状态或引用可能变化；所有授权必须在锁下复核。失效来源不产生引用，持有后序锁后不临时发现并补锁新来源。候选集合未包含的新增来源不在这一事务中尝试；后续实际写入可按最新事实重新选择。

### unchanged 与重放

**内容哈希相同的保存严格保持已有当前引用**：它不替换原 gzip、不产生新修订，只写既有 unchanged 回执和允许的公式状态变化。不得从本次没有存下的字节增减引用；例如被内容规范化排除的视图字段可能带不同字符串，不能把未落盘地址变成新的共享资格。此分支也不把原来无权的地址自动升级为独立引用；后续真正修改并写入内容时重新判定。

重放只返回原回执/修订结果，保持当前引用，不把旧请求恢复成当前内容，不增加对象、不重新授予权限。并发相同 requestId 的事务内重放同样遵守；重放本身仍按既有文档可见性和请求摘要检查。

## 4. 事务与锁顺序

`Documents → Assets` 使用公开元数据/持锁服务，Assets 不导入 Documents；空间行通过 SpacesService。Workspace 不增加 SQL。权限条件复用现有 accessible 和 DocumentAccessPolicy，不另建图片专用角色规则。

涉及多个既有文档时，锁顺序统一为：请求账本 advisory lock → 创建位置所需的空间树锁 → 全部候选空间行按 id → 全部既有文档行按 id → 资源 asset 行按 id → 正文/引用写入。没有树改动的保存不取树锁；新插入且尚未对外可见的副本文档属于本事务私有行，不是额外的既有来源锁。资源对象元数据在 P1 只追加，引用不读取或修改对象行，不引入配额锁。

- 在空间或文档行加锁前固定候选文档/空间集合；候选查询不加锁、每个 ID 至多一个可见来源，集合大小受请求限制。
- 保存对目标及候选来源一次按 id 取 FOR UPDATE，避免先共享锁再升级目标造成两个交叉保存互等。只读来源用较强锁的代价是并发写入串行，保留确定顺序；普通复制/本机副本不改任何既有文档，可按 id 取 FOR SHARE。
- 空间行批量按 id 取 FOR SHARE，挡住成员/全员可见/归档变化；文档行挡住正文/当前引用、分享、移动与删除变化。锁下来源的实际空间若不在已持空间集合中，就不作为来源，不能临时补锁。
- 锁下重新读当前关系和政策结果；只在已经锁住的来源文档集合内找合格引用。不存在、回收站、失去访问或关系已删除的来源被排除。
- 资源记录通过公开服务批量按 id 取共享锁，读取上传者和数据库窗口；在引用写入之前完成，不在持资源锁后再取空间或既有文档锁。
- 没有图片标识的保存保留原目标锁路径，实际新内容写入时把当前关系清空。所有错误仍回滚整份事务；保留保存的 70 秒事务总上界与租约规则。

## 5. 两种副本

普通复制：锁下确认能读源文档且能在目标空间创建后，复制源的当前授权关系与原 gzip。源文档授权让操作者能够读取其全部当前关系；复制不额外挖掘正文中原来无权或仅存在于历史中的地址。副本保持 unitId 和 gzip 完整字节、不继承分享，之后源撤权或删除不取消副本独立关系。

上传本机内容另存为副本：保留现有“仍能读原文档”的前提、位置选择、客户端格式和 unitId 校验。只针对上传快照提取的 ID 按本次操作者窗口与锁下可读来源建关系；原文档是可能的来源，但不能无条件整份继承，也不能把草稿里猜到的其他资源变成可读。上传字节与新关系同事务提交，重放无额外写入。

## 6. 验证要求

- 子进程：外层、资源 data、Unicode/JSON 转义、重复键、数组/键名、公式字面量、多地址、排重排序、非规范地址；真实 IPC 大集合。
- 实际保存：三类合法来源、未知/无权、精确窗口边界、删除地址、同 hash 不同上传者；正文与关系原子回滚；规范化相同但原始字节不同的 unchanged、前置和锁内重放。
- 副本：普通复制 gzip/unitId 不变、只复制已有关系；本机副本按上传内容授权；源撤权/删除后的副本独立读取；幂等不重复。
- 确定交错：撤销分享/移出成员/归档/移动/删除或移除源引用发生在预选与锁之间；已经持锁时撤权等待；两个互相引用对方的保存、保存与复制、移动/分享写入不形成逆序等待。
- 相关单元、真实 PG、三浏览器的公开 HTTP 保存/复制读取链路、类型/lint/build通过，留原始报告。P2 原生三项与 SDK 旧图清理边界保持，不在本 Step 冒称完成。

## 7. 自审决定

- unchanged 保留引用与“未写入新正文”的既有承诺一致，避免加列或在持锁事务里再次解析几 MiB 正文；并非延期正常写入的引用更新。
- 批量锁与公开服务是已批准多来源设计的实现细化，没有新增反向依赖或第二套权限政策。
- 当前引用表由 S4 建立，S5 不修改已提交迁移；历史、回收策略及前端入口仍留各自 Phase。
