# P3-S4 公式规则提交与计算完成

日期：2026-10-21。范围沿 P3 §3.5 的数据验证与条件格式验收；本地 SDK 边界修复，不改变产品范围、保存协议或公式计算架构。

## 已确认事实

`s4/task3-ui04` 四类数据验证和六类条件格式通过，自定义验证与条件格式错误修正失败。`task3-diagnostic01` 固定了原因：

- 写入 C3=4 后，自定义规则 `=C3>5` 返回 false，`RegisterOtherFormulaService` 先唤醒 Promise 再同步发送 formulaResult$；规则服务把结果通知发送为普通 dirtyRanges，S3 的模型因此取消正在等这个结果的校验。拒绝输入拦截器收到异常而非 INVALID，没有执行原有回滚。合法值也会出现同样的取消。
- 同格已有计算时，另一个 `validatorCell` 直接收到 VALIDATING，而非等待最终结论。这不能作为拒绝输入的判定结果。
- 条件格式的实际编辑器正文已经是 `=A2>4\r\n`，焦点也正确，但旧“公式错误”状态仍阻止确认。公式编辑器的初始 500 ms 验证抑制让快速修正未及时刷新错误状态；提交使用旧消息作为否决条件。

## 数据验证

缓存脏区增加可选的“公式结果”原因，仅两个实际公式结果消费者设置它。真实改值、规则变化、删表、实例退役仍立即取消任务，保持 S3 语义。

模型对公式结果刷新保留原任务和等待者，标记计算结果需要重新读取。已有计算完成时，若期间收到新公式结果，就从当前公式缓存重新求值；过期结果不能发布状态。重算不启动第二个并行任务，也不把取消变成 VALID。

同格同一次计算的所有显式等待者共用最终成功或失败；渲染层的同步查询仍返回 VALIDATING。任务结算、取消或异常时清空等待者；实际错误继续可观察，失败清掉自己的缓存以允许重试。

实际 SDK 单测使用真实注册服务、结果 Mutation、公式规则服务、模型与公开校验服务，只控制 Worker 结果到达。覆盖自定义与普通公式、合法/非法、并发等待、旧结果过期、改值/改规则/关闭与真实异常。既有生命周期 39 项继续验证。

## 条件格式

最终“确认”以当前公式的实际有效性为准，使用现有同一套等号、非空与括号判定；展示用旧错误消息不再成为独立否决条件。非法输入仍拒绝，正确修正后清掉错误并提交；不通过等待 500 ms 或放慢输入规避。

用正式宿主的快速“错误 → 修正 → 确认”作为反例；保留空条件和错误公式拒绝，以及创建、修改、撤销重做、实际画布和重开验证。ES/CJS 同步、元数据与上游草稿登记。最终三浏览器、公开 running 和 Step 审查均未完成前不认定验收通过。
