# P4-S6 Linux 进程身份观察补正

## 背景与事实边界

最终 main `3dc2cde0` 的 CI `41220859473` 五项成功，WebKit 在 307 条通过日志后因监督器 `parse-process / UNKNOWN` 停止；原始 stat 字段未保留，完整产品报告缺失，本轮不能验收。后续 `quiescent=true` 只证明恢复收尾。原故障 PID 是否属于本轮仍未知。

Linux `do_task_stat` 在无法取得正在退出的任务的 sighand 锁时，存在输出 `ppid=0, pgrp=-1, session=-1, num_threads=0` 的合法路径。state 在取得锁之前读取，不能要求此时一定是 Z/X。现有正数 group 校验会拒绝此形态。这是独立可证明的兼容缺口，**不是原 CI 已证明的根因**。两次本机隔离 Linux 观察分别读取 36,207 和 1,480,938 次，均未捕获真实负 PGID；不继续扩大随机采样。

依据：[Linux v6.8 stat 生成](https://github.com/torvalds/linux/blob/v6.8/fs/proc/array.c#L442)、[sighand 锁](https://github.com/torvalds/linux/blob/v6.8/kernel/signal.c#L1308)、[退出释放](https://github.com/torvalds/linux/blob/v6.8/kernel/exit.c#L139)。证据在主目录 `.codex/handoffs/m5-p4-20261022/s6/ci/41220859473/` 及 `s6/hosted-vm-policy/final-ci-40947141649-investigation/r10-webkit-ci-failure01/`。两轮临时容器、文件、进程和短路径均已实际闭合；共享 PostgreSQL 未改。

## 行为合同

1. 可授权的进程身份继续使用正 PID、非负 UID、正 PGID 和十进制字符串启动 tick；禁止为负 PGID 构造 Identity、扩展组归属或发信号。
2. 完整 stat 先校验结构、已知状态、字段与身份，再考虑特殊形态。固定支持的 Linux 状态为 `R S D T t X Z P I`；原任意大写正则不是未知状态白名单。读取范围绑定请求 PID；不匹配、损坏、未知状态均失败。有效 group=0 继续作为不可授权的内核任务过滤，但坏数据不得借 group=0 绕过格式校验。
3. 仅当完整记录满足上述合法退出哨兵组合时，reader 才有界重新观察；哨兵本身不能解释为不存在。识别第一个完整哨兵时启动单次 25 ms 单调消歧窗口；首次观察计入总数，最多再观察两次。后续观察前后核对同一截止时间，重复哨兵不能重启窗口，也不重新起算原运行/收尾预算。同步系统调用不能硬打断；后续合法身份或消失在截止时或之后返回，仍拒绝本次消歧。首次正常身份、既有 UID/内核任务过滤或真实消失保持原语义，不给正常路径新增 25 ms 时延失败条件。不得改变产品测试 retry。
4. 后续确实返回 ENOENT/ESRCH，才能按消失处理；后续得到完整正身份，重新走原身份与归属判断，启动 tick 变化不能继承旧任务授权。UID 过滤仍按同一 FD 的实际 UID 判断，别的用户不能被旧记录授权。持续哨兵、非精确负值、未知/坏字段、请求 PID 与内容不符、非消失类 I/O 错误及消歧超时仍抛错。期间不得更新或遗忘 known、累计空扫描、授权归档或删除。
5. reader 的 stat UID 与内容从同一次打开的 `/proc/<pid>/stat` 文件描述符获得，关闭路径必须完整；可接受记录最多 4,096 字节，可额外读 1 字节检测超限，单次 I/O 总上限 4,097 字节。超限摘要只描述实际有界读取的字节，并明确 overflow，不能冒称完整文件摘要。不读取 environ/argv 来补造缺失身份。comm 可以含空格、括号、换行或非 UTF-8 字节，不因命令名改变合法数字身份的解释；只解析前后明确的 ASCII 身份字段。
6. 失败诊断只保留固定原因枚举、请求 PID、经验证的数字/状态字段或 `invalid`、字段数/字节数/结构结果和原字节 SHA-256；不得回显 comm、argv、environ、路径、原始 stat 或异常正文。每份错误中的诊断最多 2 KiB；最多保存本次 3 次观察，已有各阶段错误槽合计不超过 16 KiB。持久化和静态快照都验证相同 schema，不能在中转时丢失新增诊断。
7. 覆盖启动登记、leader、scanOwned、signal、settle 的全部调用关系；未知观察必须阻断，不允许只修改 parser 而放过退出/归属判断。

## 范围与验收

只调整 CI 进程观察、诊断及对应测试；产品、SDK、业务数据库、工作流矩阵、原案例/跳过/断言、并发和 90 分钟运行/15 分钟收尾预算保持。本机严格清理和托管方案 B 的边界保持，不把托管销毁写成实测删除。

先用真实 reader 控制流和底层 I/O 替身取得行为 RED，明确标注为模拟；再验证精确哨兵→消失/合法身份、持续哨兵、PID 复用、坏字段、未知状态、读取错误、25 ms 消歧边界和诊断脱敏。首次正常读取即使模拟调度延迟超过 25 ms 仍按原语义返回；首次哨兵之后才开始计时，后续合法身份/消失超时仍拒绝，总观察不超过三次。保留原解析器和真实 Linux 进程合同的断言，并实际在隔离 Linux 运行原进程合同及新增相关路径。只读源码、受管资源、串行执行，结束立即核真实清理。

独立代码审查与局部验证通过后，仍按原 P4 收尾门禁推进新的实际受测源码、正常中文提交、`--no-ff` 合并、正常推送和同 SHA CI。旧本机 full19/container08、旧 CI、原 r10 工具与接受回执保持原样。后续绿色结果也不能倒推旧 CI 原因。P4/DEF-061 实际关闭前不进入 P5。
