# P3-S2 正式链接入口

状态：完成，见[复核报告](../reviews/P3-S2-正式链接入口复核.md)。日期：2026-10-21；代码基线 `061653925015d2e1cecc3ac197da6ee5f3832017`。上层依据：[P3 §3.3](../03-P3-表格能力与链接.md)、M5 总设计 US-M5-08、计划书 §11.3。

## 1. 用户行为

编辑者可以通过工具栏、右键和 Ctrl/Cmd+K 添加链接，在原浮层中修改或取消；普通单元格和正在编辑的富文本都适用。显示文字保持用户输入，地址由既有 `canonicalLink` 规范化；明确输入不合法时保留原内容，表单给固定错误，直接命令被取消并给固定提示。删除链接只去掉链接，保留文字。

明确输入沿用现有契约：完整 http/https/mailto、以 `/` 开头的本站路径和 `#` 锚点；不替用户猜测缺少协议的主机或邮箱。自动识别、纯文本/HTML/内部片段粘贴和 HYPERLINK 沿既有清洗语义保留文字，不能因开放链接入口破坏普通复制粘贴。地址的 2,048 字符上限、主机/凭据/控制字符规则不变。

工作表、区域和定义名称仍由 SDK 的原界面构造内部锚点、由原 resolver 定位。外部或本站路径只在明确点击时打开新页，并使用 `noopener,noreferrer`；非法地址和内部锚点不交给外部打开回调，不发生预取或验证地址的网络请求。查看者可以点击合法链接及内部导航，不能增加、修改或取消链接。

## 2. 固定发布包事实

本节依据已安装的 `@univerjs/sheets-hyper-link{,-ui}@1.0.1`，不按只读参考目录的旧行号推断：

- `sheets-hyper-link-ui/lib/es/index.js` 的桌面/移动表单均调用 `isLegalLink` 和 `serializeUrl`；前者委托 SDK `Tools.isLegalUrl`，后者可能补 `http://` 或 `mailto://`。命令拦截发生得更晚。
- `IUrlHandler` 现只有 `navigateToOtherWebsite`。resolver 在调用它之前检查 `isSafeUrl`，但实际发布包的该函数只核对相对解析后的协议，也接受 `//`、凭据和控制字符；不能代替平台规则。
- 纯文本粘贴 controller 也使用 `isLegalLink`，用于清理旧链接模型；需要同一判定。
- 四个写命令分别是 `sheets.command.add-hyper-link`、`add-rich-hyper-link`、`update-hyper-link`、`update-rich-hyper-link`。两种添加的地址在 `params.link.payload`；两种更新在 `params.payload.payload`。内部区域更新也会使用 rich update，必须保持合法锚点可用。
- parser 将 `#` 开头的地址分为工作表、区域、定义名称或无效引用；其他地址为 URL。不替换其内部导航语义。
- 原 Ctrl/Cmd+K 谓词排除正在编辑的单元格；富文本操作必须补充本实例的非折叠选区绑定。正常编辑器的隐藏输入在 `editorDOM` 外，输入归属应由该实例 `DocSelectionRenderService.isFocusing` 和真实 activeElement 判断。
- 真实表单 autofocus 使隐藏输入 blur，Docs `_setEditing(false)` 在文本/矩形数组引用未变时发送选区通知；原桌面/移动 hyperlink controller 将它误当换选区而立即关闭表单。真实选择替换、清空会产生新数组，需要与只改变焦点的通知区分。

## 3. 接口与实现边界

### SDK 的窄接点

通过 `pnpm patch` 为 `IUrlHandler` 增加可选 `normalizeUrl?: (url: string) => string | null`：返回规范地址或明确拒绝。配置存在时，桌面/移动表单的判定与序列化、纯文本粘贴判定调用它；没有配置时保留 SDK 原行为。

resolver 先取得配置并规范化，拒绝即返回；随后统一保留原 `isSafeUrl` 检查，再将规范值交给平台 navigation handler 或默认 `window.open`。现有平台合法协议/本站路径均满足该检查，无需绕开 SDK 原保护；无配置调用方保持原行为。同步修改发布 ES、CJS 与类型声明，不改只读参考源码，不直接修改 node_modules。

同一补丁在桌面/移动 popup controller 的选区订阅去重：只有 unit/subUnit、segment/page、文本与矩形数组引用都相同时才忽略通知；选择替换、清空、上下文变化仍关闭。订阅继续由原 controller 管理销毁，不改 Docs 全局事件、不延时重开。实际 controller 单元测试覆盖两种实现；真实浏览器证明桌面表单和富文本保存。移动实现的单元对照不代表移动端 UI 验收。

### 平台适配

- `profile/link-input-policy.ts` 提供 `normalizeLinkInput(value: unknown): string | null`、`linkUiConfig` 及 `installLinkInputPolicy(univerAPI): IDisposable`。配置回调只调用现有 contracts；导航再校验一次，内部锚点不走外部打开。
- `internal-api/link-input.ts` 集中封装实际四命令标识；固定提示使用公开 `Facade.showMessage`，不取内部消息服务；从 `internal-api/ui.ts` 导出，登记 SDK 符号、来源、替换条件和回归。不把 UI 服务带进公式 Worker 的出口。
- 执行前只检查上述四命令的实际地址字段，拒绝发生在 SDK 改显示内容、创建撤销记录或写模型前。合法输入只替换 payload 地址，原目标、显示文字、tooltip、范围不变；参数不明或不能安全修改时取消。
- 保留最先安装的入口守卫。增加“链接适配已就绪”的条件，只有策略安装成功且当前实例可编辑才放行原七个入口；销毁时保持首个监听顺序。只读防火墙继续独立处理权限，不凭地址合法放行写入。
- 将两种链接插入菜单从全局隐藏移为只读隐藏。普通复制、图片输入和未支持的图片/保护入口不变。
- `internal-api/link-shortcut.ts` 在 Ready 后给本实例注册原工具栏命令，要求 edit、策略就绪、正常单元格编辑器、非公式栏、非组字、该文档非折叠选区及实际输入归属；销毁时移除。原 SDK 绑定不变，不接管全局键盘事件。测试探针仅动态加载公开 Docs Facade，读取活动文档用于非法命令反例。

## 4. 验证与完成条件

1. 先保留 RED，再实现：非法明确输入不写入、原 SDK 的相对路径表单误拒/改写、resolver 缺少规范化及仅协议检查的反例、未就绪守卫与只读反例。
2. 单元覆盖三类协议、本站路径/内部锚点、规范化、不合法值、四种实际参数、已取消事件、未知命令、只读与销毁；变异至少覆盖绕过命令判定、漏接表单和导航规范化。
3. 三浏览器真实 UI 覆盖添加、修改、取消、富文本、非法输入保留、撤销重做、保存重开；富文本包括中间子串，核对前后文字及包含式 startIndex/endIndex。服务器地址必须通过 `checkCellLinks`。内部表/区域/定义名称导航有独立可观察结果。
4. 页面、Worker 和新页的请求观察证明没有隐式外站请求；明确点击只产生预期的规范化导航，邮件不触发真实邮件客户端。使用自制内容和保留域名，不访问外站验证地址。
5. 现有 links、read-only、图片相关入口和 S1 保存位置回归；生产公开流程在自动保存照常运行时成立。
6. lint、类型、构建、补丁登记/固定版本/产物门禁通过，独立审查落档，正常中文提交 S2。整个 US-M5-08 和 DEF-019/052 仍待 Phase 的完整验收后关闭。
