## 3. 设计

### 3.1 模块边界

contracts 负责地址规则及有限的错误位置契约；documents 的快照检查负责在实际工作簿路径上取位置，继续在现有隔离子进程中运行；页面只用当前实例查得的工作表名称呈现位置。`editor/` 负责 SDK 命令、表单与导航适配，内部 API 只经既有出口登记。没有新的资源服务、保存接口或数据库迁移。

### 3.2 链接规则与可定位拒绝

保留既有 `link-structure`、`link-address`、`link-range-id` 的检查顺序、拒绝行为和默认提示，为这些规则增加可选 `linkLocations`：

- 最多 5 个去重位置，只允许 `cell`（sheetId、row、column）、`sheet`（sheetId）、`workbook`。
- 身份仍限定为 1–128 个字母数字、下划线或连字符，排除原型特殊键；坐标为 0–2,147,483,647 的整数。不能可靠识别坐标时降为工作表或工作簿，不能将任意字符串当位置输出。
- 只从实际 `sheets → cellData → row → cell.p` 路径产生位置，遍历不局限于 `sheetOrder`，保留数组容器和隐藏工作表的原校验语义。首个失败规则保持；收集同一规则的位置，达到上限即停止。
- 沿既有检查结果、IPC、保存和另存副本错误链传递；不回显 URL、链接显示文本、富文本或任意路径。图片字段与既有调用兼容；其他规则丢弃不适用的位置字段。
- 页面查当前实例名称，最多展示 120 字符；未知名称和失效实例回退为“某个工作表”，不显示原始服务端 id。位置异常或新旧客户端互通时保留原通用拒绝说明。

### 3.3 链接入口与导航

选择保留 SDK 已有链接交互、补充窄配置适配，再在平台命令边界校验。它保留内部表/区域/定义名称导航、已有键盘交互及撤销栈；在固定包上增加最小、可移除的校验/规范化接点，使表单、粘贴和导航都能调用同一平台规则。实际接点与 ES/CJS/声明文件范围在 S2 spec 中按当前发布包确定。

比较过的另两条路线：仅拦最终单元格写入会让表单提前误拒或改写地址，且不能覆盖富文本编辑中的命令；重写整套链接面板需要重新实现工作表/区域选择、焦点和撤销语义。前者覆盖不全，后者扩大维护面，因此采用上述窄适配。

命令守卫覆盖普通与富文本添加/更新的实际参数形状、删除/取消及快捷键、菜单、直接命令与 HTML/内部片段；用户显式输入的非法链接保留原内容并给出固定错误。自动识别/粘贴仍保留合法文字和既有清洗语义，不使普通表格复制失效。只读防火墙保持独立，不把“规范化成功”当编辑许可。

外部导航只在用户明确点击时发生，先规范化，再通过 `noopener,noreferrer` 打开；不预取、探测或访问外站验证地址。内部锚点按 SDK 表/区域语义定位，不能误变为外部请求。仅有 CSP 没报错不足以证明无外部请求，测试记录页面、Worker 与新页请求。URL 样本使用自制内容和保留域名。

### 3.4 生命周期

DEF-056 在固定 1.0.1 上先建立确定反例：暂停实际空闲回调，创建含非当前工作表规则的实例，再销毁实例或工作簿，最后释放回调。修复应使任务归属明确、销毁时取消，并在异步续体恢复时核对原工作簿身份，防止同 id 新实例被旧任务修改；正常校验和真实计算错误仍必须可观察。

保持适配层替换优先；插件没有稳定替换点时，用登记的最小依赖补丁处理实际服务，不复制整个插件，不用全局异常监听吞掉错误。覆盖初始 Rendered、后续脏区、打开自检失败、阅读/编辑切换及旧任务后创建的新实例。

DEF-057 继续区分 drawing 已修复与 formula 未证实。S3 复核当前默认 Worker/主线程注册路径及构造失败；只对实际可达的问题作修复和关闭结论，直接调用内部服务的反例不得冒充产品复现。

### 3.5 表格能力矩阵

| 能力组 | 必须经过的用户入口与数据事实 |
|---|---|
| 工作表、单元格 | 新增/重命名/复制/移动/隐藏/显示/删除表；键入、编辑栏、清空、复制/剪切/粘贴、填充；至少两张表互相对照 |
| 行列与样式 | 行列插入/删除、宽高、隐藏/显示；粗斜体、字号/颜色/对齐/换行、合并/取消、数字格式；核对值与样式，自动行高图片回归保持 |
| 冻结、筛选、排序 | 设置/取消冻结、筛选条件与清除、升降序；核对实际顺序、条件和视图语义，包含切表与重开 |
| 数据验证、条件格式 | M0 已承诺样本：列表/复选框/整数/日期/自定义公式；数值比较/数据条/色阶/公式/文本/重复值；新增、修改、删除及有效/无效输入 |
| 备注与查找替换 | 新增/修改/删除/显示备注；查找不改正文，单项与全部替换、撤销、保存重开 |
| 公式与跨表 | M0 样本的聚合、文本拼接、跨表、定义名称；依赖修改、结构操作后引用变化；收齐、待更新、重开和 Worker 退路 |
| 链接 | 网页、邮件、相对地址、表/区域/定义名称导航；添加/修改/取消、纯文本/HTML/内部片段、HYPERLINK；拒绝及定位 |

每个可写能力记录 UI 入口、可观察变化、撤销重做、云端保存、重新打开和查看者对照；保存重开后必要时再保存，检查无无故变化。用纯 Facade 注入只用于准备样本或负面绕行验证，不替代 UI 入口。只改视图的操作不强求正文改变；SDK 不支持独立撤销的视图操作按实际语义明确记录，不能虚构撤销成功。

### 3.6 保存、恢复与公式组合

沿 M3/M4 的单一路径验证，不加第二条保存通道。普通编辑、保存中继续修改、离线写入、明确恢复、真实公式 Worker 故障后的同会话主线程重建，都检查样本的值、公式、资源和版本语义。公式未收齐时保留既有 3 秒上限和“待更新”事实，不能把旧缓存当最终结果。

优先扩展现有 `formula-fallback`、恢复与只读故事中的输入和断言，避免为每个单元格启动一次浏览器或重复制完整崩溃矩阵；实际覆盖和新增样本写入能力报告。

## 7. 风险与处理

链接表单的预处理可能先于命令守卫改变语义，S2 必须从用户输入一路核对最终快照和点击结果。异步生命周期修复要兼顾已经开始执行的 Promise，取消空闲句柄本身不等于消除迟到写入。能力矩阵以真实入口和既有 M0 样本收口，不以测试标题或插件数量估算覆盖。

P2 最后 WebKit CI 的 E2E 步骤约 68 分 45 秒，现有 75 分钟预算余量有限；本 Phase 复用现有上下文/准备流程并查看实际耗时，不先提高预算或删除故事。开发机证据占用较多；测试前检查空间，必要时只无损归档已关闭阶段的自有原件并保留摘要，不能删除失败证据腾出空间。
