# M5-P2 图片入口与可靠渲染：架构设计与实施规划

> 状态：进行中（设计已自审）｜日期：2026-10-19｜基于代码版本：`1f7f7d61edb72081755cb96dd0db6a3df26fdb0c`

## 1. 目标与范围

按已批准 M5 总设计 §5，让编辑者真正完成图片插入、粘贴、拖放、复制、保存与重开；读取失败和权限变化不破坏表格或继续显示旧实例的图片。覆盖 US-M5-05、06、07、09 的当前副本部分及 14 的图片部分。故事完整完成后才激活；历史副本仍由 P4 验收。

P1 已完成同 SHA 六项 CI、原生 x64、独立原件复核及正常清理，见 [P1 最终复核](reviews/P1-S6-最终CI与关闭复核.md)。本 Phase 只用 `codex/m5-p2-images` 与 `.codex/worktress/codex/m5-p2-images`，主目录保持 main。沿用用户批准的自主推进和 Phase 自审规则。

真实 Finder 拖放、真实 Excel 来源、授权 Chrome 右键粘贴仍是**开放正式入口、验收、合并前**的必要条件，详见[原生待验交接](handoffs/P1-S1-原生图片待验项.md)。允许先实现与诊断关闭入口背后的底座，不把合成输入当作补证。M4 DEF-073/UR-035 与完整验收/tag 保持独立。

不增加远程抓图、离线上传、任意附件、工作表背景图、文字文档入口、历史/GC、SDK 升级或新图像解码依赖。

## 2. 当前代码事实

- P1 的 `POST /api/assets` 接收原始字节、媒体类型及 `X-Asset-Extension`；成功只返回规范资源 URL 与服务端确认的尺寸。读取必须检查 `X-Asset-Status`：HTTP 200 可能是 404/500/503 占位；401 仍走原认证错误。
- `shared/api/client.ts` 已统一 CSRF、会话来源、30 秒全请求时限及取消；图片复用它，不自建第二套认证或重试。
- `editor/sheet-editor.ts` 在工作簿创建前安装身份、资源和命令守卫，权限/公式模式切换通过销毁重建完成；这些顺序与只读防火墙不变。
- 固定 SDK 1.0.1 的绘图 URL 路径使用 `IURLImageService`，UUID 路径才使用 `IImageIoService.getImage`；只替换后者覆盖不全。默认 URL 下载器遇错会退回原地址，不能用注册回调代替失败关闭的完整适配。
- `getImageSourceCache` 的 HTMLImageElement 与浏览器 available-images 可保留旧解码内容；重复相同 src 和服务端 no-store 都不能证明重新鉴权。
- `RestrictedImageFunction` 仍只看求值后字符串，字面量与拼接的区别交 S3。S2 已以八份固定补丁完成 IO 绕行点与可靠渲染修复，DEF-025/UR-006、DEF-002/UR-009 和 DEF-057/UR-031 的已证实 drawing 路径有原版反例及三浏览器回归；最终 DEF 状态在 S6 汇总，不宣称完整 Phase 验收已完成。

## 3. 设计

### 3.1 边界与依赖

`shared/assets` 只处理平台字节请求、响应及错误，不依赖 SDK。`editor/images` 负责图片实例资源、SDK IO、入口焦点与输入处理；内部 SDK 符号/原型约定只经 `editor/internal-api` 出口并登记。`features/sheet-editor` 仍负责页面身份、编辑权、联网状态、保存与用户提示，经适配层的窄接口提供事实，不向 shared 或后端传播 SDK 对象。

不改后端上传、授权或引用事务。DEF-052 若需增加错误位置，只为现有快照检查结果添加有界位置数据，沿原检查子进程/错误契约传回；不回显正文、URL、文件名或图片字节。

### 3.2 上传与有界读取

客户端上传在读取文件前核对 1–5 MiB、PNG/JPEG/WebP/GIF 及扩展名匹配；字节请求再次校验大小，文件内容真实性仍由 P1 完整解码负责。只发送后缀，不发送原文件名。上传返回的 ID、相对 URL、类型、字节和尺寸用既有契约校验，失败不自动重试并制造重复资源。

读取仅接受规范 `/api/assets/{uuid}`；同源绝对地址在进入请求层前按共享判定规范化，其他地址不发请求。经统一请求层显式 `cache: no-store`、`redirect: error`，保持 Cookie 与原请求会话归属。状态头必须明确为 200 才能得到真实图片字节；404/500/503 形成独立读取错误，保留 Retry-After，取消未使用的占位正文。缺头/错类型/空响应/过大响应均是格式错误，不把它们当图片下载成功。

成功正文在原 30 秒请求作用域内流式读取，累计最多 5 MiB；超额立即取消，响应头不能绕过实际字节预算。图片解码在后续实例服务内完成；请求层不把“HTTP 成功”当作像素可用。实际上传及读取采用同一时限、取消和会话错误机制。

### 3.3 SDK 读取、缓存与生命周期

同时提供 `IImageIoService` 和 `IURLImageService` 的平台实现。快照仅保留相对 URL；实例内用本次鉴权取得的字节产生临时 blob URL/已解码元素，临时地址不得写入模型、撤销栈或本机草稿。`saveImage` 的 drawing ID 每次独立生成，按计划书保留规范 source/base64Cache 语义；用于量尺寸的真实路径必须覆盖，不因临时资源替换改变保存格式。

资源以编辑器实例与身份代次为所有者：同一代内可合并在途读取，不能跨账号或实例复用。权限重核、会话结束、离线转在线重核和销毁都使旧代失效，取消在途任务、撤销 blob URL、清掉旧元素和画面；迟到读取/上传不能插入新实例。图片加载失败返回平台本地占位并保留可见错误，不能走 SDK 默认的原 URL 回退；下载和复制必须明确失败，不把占位当原图。

同页权限变化沿既有页面事实触发主动重读，重建从空缓存开始。服务端不能收回已经交给客户端的字节；验收看实际新请求、状态变化及旧画面清理，不宣称防止用户先前保存的副本。

### 3.4 可靠渲染与最小依赖修复

先在固定 1.0.1 发布包复现并锁定失败，再在适配层或可追踪依赖补丁中修复：破损/未完成图片不得进入 drawImage；自动行高后的起止锚点与尺寸一致；Ready 前销毁的 drawing 回调不留下未处理拒绝。不得全局吞掉异常或改画布全局方法。

若必须修改依赖，使用 pnpm 的固定补丁，保存版本、原文件摘要、变更点、移除条件和回归。`refer/univer` 不改动；不为修复升级 SDK。现有插件/快照结构和 `sheet@1` 保持；若实测修复必须改变数据结构，按 §8.7 另作格式评审，不能靠设计自审绕过。

### 3.5 IMAGE 与内容边界

在公式仍有结构信息的边界验证首参必须是合法平台地址的字符串字面量，主线程与 Worker 共用同一规则；引用、区域、数组、拼接、计算函数及编码绕写均返回 `#VALUE!`、零图片请求。保留原函数参数数量、模式/尺寸语义与 Ready 安装握手，不用正则或求值后的字符串替代语法来源检查。

图片相关命令与粘贴片段在写入前规范化/拒绝非平台 source，包括嵌套资源、单元格富文本、填充图和内部片段；不在普通大表写值命令上全量递归。保留表格数据、合法文字和链接既有规范；编辑栏/单元格文本编辑的图片在上传前拒绝，避免新增孤儿资源。保存拒绝能定位到工作表/单元格/图片或资源项，位置数量/长度有界。

### 3.6 系统输入与正式入口

沿已确认路线使用现有插入与浮图/单元格图片功能，格式清单对齐四格式。选文件、系统按键粘贴、浏览器/SDK 右键粘贴、HTML/内部片段、Finder 拖放分别取证；文件加表格 HTML 时优先保留真正表格，不能把 Excel 内容误当单张图片吞掉。

复制根据真实图片选择与焦点决定是否接管，保留用户激活并阻止 SDK 之后清空；不采用 350 ms 延迟补写，不把首图探针直接迁入产品。复制到另一文档及外部受控接收方须检查实际像素；权限拒绝、读取失败、取消和重新尝试都有可见结果。拖放在同步事件阶段阻止意外导航，只处理目标编辑器内的合法文件；不支持项给出错误而不污染正文。

原生取证仅用本任务自制样本，不读取任意用户剪贴板。真实 Safari 要求屏幕解锁、开始前空闲 120 秒；工具/应用权限在实际需要时遵从既有授权。Excel 环境未准备好时保留缺口，继续不依赖它的任务；正式入口保持关闭。
