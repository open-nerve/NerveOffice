## 2. 现状与基线

- `apps/api/src/modules/documents/` 统一持有内容与权限。`DocumentAccessPolicy` 是有效权限入口，空间事实经 `SpacesService` 获取，不能跨模块拼接授权 SQL。
- `DocumentContentService` 保存使用请求账本、锁下会话/租约/权限复核、正文与修订事务；`SnapshotInspector` 在子进程完整检查快照，但结果尚未携带 assetId 集合。
- `DocumentCopyService` 在空间树、空间行和源文档锁下直接复制 gzip，保持 unitId；`DocumentConflictCopyService` 接收经过检查的本机草稿并新建独立副本。两者尚无资源引用。
- 资源地址的规范判断已有 `packages/contracts/src/documents/asset-address.ts`，只允许规范的同源 `/api/assets/{uuid}`；现有图片入口仍受守卫。
- 当前生产 SDK 为统一精确版本 1.0.1。M0 验证工程的 package.json 仍为 1.0.0，不能把重跑它当作当前版本的前置结论。S1 使用本 Phase 锁文件解析出的 1.0.1，M0 只作历史参考。
- 主目录保持 main；唯一开发线为 `codex/m5-p1-assets`，路径 `.codex/worktress/codex/m5-p1-assets/`。依赖按既有锁文件离线安装，基线相关 4 个文件、92 项单元测试通过；完整基线为 M4 刚完成的同树全量门禁与 CI，保留各自原回执。

## 3. 设计

### 3.1 模块划分与依赖方向

| 单元 | 职责 | 依赖与公开边界 |
|---|---|---|
| `assets` 模块 | 不可变物理文件、上传处理、assetId 与内容对象元数据、组织配额 | 依赖 config/database/auth 的公开能力；不导入 documents。公开上传结果、资源元数据、已授权对象读取与事务锁接口 |
| `documents` 内的资源引用服务 | 当前正文引用、授权来源、复制引用与保存事务协调 | 复用 DocumentAccessPolicy；经 assets 公开接口查询/锁定元数据，不调用其仓储 |
| `workspace` 的资源接口编排 | `/api/assets` 上传与 `/api/assets/:id` 读取的会话、输入、权限与输出组合 | 组合 assets 与 documents 的公开服务；不绕过两域直接访问表 |
| `contracts` | 上传响应、状态与资源标识、纯地址提取规则 | 无 SDK、Node 或数据库依赖 |
| 编辑器适配层 | P2 才正式接入平台图片 IO 与用户入口 | P1 仅测试探针使用 SDK；不将探针导入生产 |

`Documents → Assets` 为单向依赖；读取由 Workspace 先取得 metadata，再调用文档域授权，再读取文件。这样不会形成 `Assets → Documents → Assets`。资产保留与可读取是两回事；未来历史/运维引用不能自动给当前查看者读权限。

### 3.2 接口契约

- 上传沿用 Cookie 会话、CSRF、Origin 和限流。使用有上限的二进制请求，不接收客户端路径；响应包含独立 `assetId`、规范 `url`、媒体类型、宽高和字节数。单次上传最多 5 MiB，成功不依赖随后保存文档。每次上传新 assetId，字节相同只去重物理对象。
- 处理必须完整解码、重新编码并移除元数据；PNG/JPEG/WebP/GIF 均以真实样本验证。S2已完成有界实验并以[ADR-021](../../adr/ADR-021-图片处理与资源边界.md)固定Sharp0.35.5/libvips8.18.7、5MiB、16M/32M像素、100帧、1536MiB地址空间及队列/时限/配额；S3按正式测试实现，不能凭文件头或版本号判定支持。
- 无会话读取返回既有 401。已登录的不存在与无权使用同一逻辑 404，输出同一平台占位图，HTTP 200、`X-Asset-Status: 404`、`Cache-Control: no-store`。真实读取失败使用相应逻辑故障状态的占位图；所有响应有 nosniff 与 same-origin CORP。下载调用方必须检查状态头。
- 成功读取同样要重新鉴权，使用 `private, no-store`，P1 不引入跨用户共享缓存或能绕过撤权的签名地址。请求范围/缓存协商不新增旁路。
- S4 实测边界：同页已经解码的 `img` 可能复用 HTML available-images，即使响应为 `no-store`；重设相同 `src` 不等于重新请求。P1 保证实际 HTTP 读取每次鉴权，浏览器主动 `fetch(no-store)` 后解码本次字节。P2 开放入口前必须验证 SDK 的权限变化、退出/重建时主动复核及旧画面清理，不能以重新显示旧图冒充重新鉴权；服务端无法收回客户端已接收的字节。证据与标准依据见 S4 复核记录。
- SDK 的 `change$`、drawingId、错误映射、输入格式等正式适配属于 P2；S1 的诊断 IO 只用于观察 SDK，不能成为生产上传实现。

### 3.3 数据模型与文件一致性

- `asset_objects`：处理后 SHA-256 唯一、存储相对键、媒体类型、尺寸、字节数、创建时间。对象只追加、不原位修改。
- `assets`：独立 UUID、上传者、对象标识、创建时间。不得因物理去重合并上传者与 assetId。
- `document_asset_links`：文档与 assetId 联合唯一，当前内容引用。引用随内容事务增减；文档删除的最终清理按既有生命周期执行。P4 再增加历史/运维引用。
- 上传先写任务专用临时文件，完成处理、大小/哈希核对和原子发布，再提交数据库元数据；数据库提交成功后对应文件必须完整可读。失败遗留的完整对象暂留，不在 P1 启动删除任务。
- 同 hash 上传串行确认对象与配额；崩溃、重复上传、元数据提交失败分别故障注入。不得把数据库事务回滚描述成文件回滚。
- S2配额定稿为默认10GiB物理字节、100,000条asset记录。完整发布但数据库尚未转正的对象要保留持久预留占用，不能让失败遗留绕过字节配额；S3细化预留、发布与转正事务。P1不因此提前启动正式对象GC。
- StorageAdapter 只接收服务生成的对象键，文件根目录来自校验后的配置，拒绝链接/路径越界；容器私有卷与启动可写性检查在 S6 落实。

### 3.4 保存、引用与锁顺序

快照在现有子进程完成解析、资源 data 解析和全量检查后提取所有字符串中的规范 assetId，包括公式内字面量；去重排序，只回传标识，不回传正文。正文是否含非法图片地址仍由现有规则决定，不能因提取器遗漏放行。

保存只建立三类获授权引用：目标文档原来已引用、本人 24 小时内上传、本人能读其他有效当前引用。无权地址不获得引用，但合法快照照常保存，避免本机保存永久重试；引用为空不等于资源不存在。

所有涉及多文档的引用授权，在取得写锁之前先确定候选来源及其空间；按既有全局顺序取得请求账本、目标树锁（需要创建时）、空间行按 id、文档行按 id、资源对象/asset 行按 id，再在锁下复核权限与位置，最后更新正文及引用。来源移动或撤权导致不再满足授权时不建立该来源的引用，不在持有后序锁时临时补取前序锁。S5 用确定交错验证保存、复制、撤权与移动，不能依赖死锁重试掩盖顺序错误。

普通复制在既有一致性锁下复制当前已授权引用与原 gzip；本机草稿副本按操作者与草稿中提取的标识判断授权，不能直接继承已撤权源文档的一切图片。幂等重放既不新增对象，也不重复引用；正文相同的保存仍须按实际契约明确引用状态，测试覆盖该分支。

### 3.5 前置真实交互的证据边界

S1 在 `spikes/m5-assets/` 建独立、只监听 loopback 的诊断页面，直接使用锁定的 1.0.1 包。它不挂载生产账户、文档、数据库或目录，不启用正式资源路由。所有图片和表格样本由本任务生成；先复制测试样本，再记录其剪贴板，避免读取用户原有剪贴板。

真实 Chrome 与 Safari 分别记录原生 paste/drop 的 `isTrusted`、MIME 类型、文件信息、HTML 形态、SDK 结果、默认导航行为、权限提示和 CSP/读取记录。合成校准单独标记，不能替代原生事件。观察默认行为和受控诊断接线分别记结果；诊断接线只回答 P2 是否能成立，不冒称产品已实现。

真实 Safari 开始前核对屏幕解锁和至少 120 秒空闲；测试期用户活动使该轮作废。电脑 UI 通过当前会话电脑操作工具执行；不启用远程自动化或改变安全设置。需要权限或外部应用时按实际现状处理，不把缺失的 Excel/系统动作写成通过。文字文档专属来源留给 M6，表格部分的未验证项保持明确状态。

### 3.6 错误、安全与可观测性

拒绝类型、体积、像素/帧预算、超时、繁忙、配额和存储故障均有稳定错误码；日志只记录任务/资源标识、阶段、尺寸和耗时，不记录原文件名、正文、EXIF 或字节。解码在受限子进程，进程异常后可回收队列槽位，下一份正常图片仍可处理。处理库、原生依赖与镜像运行条件通过现有许可、依赖和产物门禁。

## 7. 风险处理

真实浏览器的剪贴板权限或 Excel 不可用会留下明确前置缺口；不通过合成事件盖过。处理库的原生依赖与预算由 S2 实测后锁定。多来源权限可能放大锁集合，S5 先构造确定交错和有界查询，再接保存；任何新增授权旁路或依赖环都要先修正设计。物理 GC 留给有完整历史保留契约的 P4，P1 只追加对象。
