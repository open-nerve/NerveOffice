## 与设计的偏差

- **S5 → S14**：另存为副本以草稿所基于的修订为基准（契约新增可选 `baseRevision`）。这超出了设计 §3.2 的“副本取源文档当前版本”，属于须先请示的跨模块接线，当时没有请示；S14 停点经需求方追认。同时把每版修订记的内容由“完整集合”改为“存在但未登记的标识”，修好了副本丢图（审查 B1）与修订行膨胀（B3）。已写入设计 §3.2 与 ADR-023 附录。
- **S8**：D-04 (c) 的 CSV 兜底由既有的 `formula-pending` 门禁承担，没有另加按函数名或引用猜测的启发式（会误拒普通公式）。理由见 P7-S8 计划 §3 与 ADR-010。
- **S11**：M-12 的拦截点放在 sheets-ui 的 `_pasteFiles`（补丁），不在平台入口：平台入口挡不住多压的撤销记录。M-16 只留普通样式规则，比 D-08i 写的“剥离 `@import` 与外部 `url()`”更严：`@font-face`、`@media` 等规则一并不留。已写入 ADR-010。
- **S13 → S14**：D-10 原定“启用前先在 Linux 上兼容运行”，S13 误写为“首轮分支 CI 即兼容运行”。S14 停点改为 Python 回归只进本机完整门禁、CI 照旧只跑覆盖率（DEF-080）。Q-10 的采样写成 CI 注解，不写进运行台账（台账写入会破坏 `service_proof` 的内存与磁盘一致性），并设了总时限。
- **S9**：Q-03 实测在常见规模内，极端规模外推超过 5 秒锁等待；登记 DEF-079，S14 停点确认留到 M7。
