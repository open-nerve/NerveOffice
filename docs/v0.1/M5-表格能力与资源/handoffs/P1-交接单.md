## 与设计的偏差

- 经用户明确批准，原来先于资源后端的三项真实入口补证，调整为 P2 正式入口开放、验收及合并前的强制条件。审批与范围见 [原生图片待验交接](P1-S1-原生图片待验项.md)，没有降低最终验收。
- 图片的 no-store 响应不能撤回已被浏览器解码/显示的旧图。P1 证明每次实际 GET 的服务端授权；P2 另须用正式 SDK 验证权限/退出/重建时主动复核与旧图清理，不能将重复设置相同 src 当成已重读。
- 初次镜像冷缓存下载触发时限，已保留失败并补材料路径诊断；本机用逐件重新验证的既有原件补充构建缓存，再执行完整收集和离线校验。没有更换来源/摘要、增加时限或忽略缺件。原生 x64 CI 的冷缓存下载仍待实际结果。

## 下一个 Phase 须知

- 在上述 P1 关闭回执实际成立后，从 main 建 P2 的唯一分支/worktree；不留下额外修复分支。原生 x64 不能由 ARM64 或仿真替代。
- 图片服务为已认证的原始字节上传、规范资源 URL 与状态头读取；不要传原文件名、外部 URL 或任意路径给处理器。5 MiB、像素/帧/时间、执行和排队预算见 ADR-021；缺乏可证明引用的 URL 不自动取得权限。
- 保存的 unchanged/重放分支不改 gzip 或关系。源文档候选必须在锁前固定，沿现有空间/文档/资源顺序复核；不得在复制或 SDK 上传回调里另做无锁补关系。
- 图片根必须显式配置。测试 Compose 为 node 用户独占 `/var/lib/nerve-office/assets`，应用默认 4 GiB；数据库、图片卷与本机密钥主密钥分别保管并配套恢复，不能只恢复数据库。
- 完整源码/许可在镜像 `/app/licenses/native-images`，与 Web 根分开；保留离线复核及共享库替换机制。材料缺失、摘要或版本不符必须拒绝构建/验收。
