# M5-P1-S3 私有存储与上传实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不开放前端图片入口的前提下，提供有界四格式上传、私有不可变文件、独立 assetId 与故障后仍成立的组织配额。

**Architecture:** Workspace 只编排会话后的 HTTP 入口；Assets 持有处理、文件与元数据。先持久预留物理配额，再原子发布文件，最后在短事务中转正对象并创建 assetId；子进程结束并回收后才释放处理名额。

**Tech Stack:** Node 24.21.0、pnpm 12.6.0、NestJS、PostgreSQL/Drizzle、Sharp 0.35.5 / libvips 8.18.7。

**Spec:** [Phase 设计](../01-P1-图片资源底座.md) §3.1–3.3、§3.6、S3；[ADR-021](../../../adr/ADR-021-图片处理与资源边界.md) 全文。S2 的实验报告是取值证据，不能直接搬探针实现。

## Global Constraints

- 主目录保持 main；沿用 `codex/m5-p1-assets` 及本 worktree，Phase 内不建新分支。中文提交，正常 hooks。
- 输入/输出各最多 5 MiB；单边 8192，单帧 16,000,000 / 总画布 32,000,000 像素，100 帧。PNG/JPEG/WebP/GIF 完整解码、重编码、移除元数据；APNG 明确拒绝。
- 图片进程每次新建，只同时执行 1 份、等待最多 4 份，每账户执行与等待合计最多 2 份；等待 10 秒、启动加执行 5 秒；回收进程后放名额。
- 子进程 jitless、老生代 128 MiB、半区 16 MiB；Linux prlimit 地址空间 1536 MiB，缺失/不可用拒绝启用。只传 ADR 的三个原生库环境变量，不能继承秘密。
- 配额默认 10 GiB / 100,000 条；字节允许 5 MiB–1 TiB，条数允许 1–1,000,000。对象相同只计一次字节，每次上传独立 assetId 计一次条数。
- Assets 不导入 Documents；不做正式对象 GC。P2 三项原生补证仍是硬门槛。DEF-073 与 M4 正式验收继续单列。
- 正式测试只用 `127.0.0.1:53522` 隔离库和任务自有临时目录；不读取开发库或用户图片。全量、容器和压力运行串行，原件先归档。

## Review Focus

1. 发布后数据库失败/提交结果未知：文件仍有持久字节预留，重复请求不能绕过配额（Task 6）。
2. 同 hash 并发与已有文件损坏：不覆盖、不重复计字节、不合并 assetId；检查内容而非只看名称（Task 2、6）。
3. 客户端慢传、断开或服务关闭：在读大请求体之前准入；等待可取消，子进程真正退出后再放行下一份（Task 5、6）。
4. 格式看似完整但像素不完整、重复动画帧/0 毫秒：完整解码与原始容器语义都须成立，不以浏览器容错代替验证（Task 4）。
5. 原生依赖升级/换平台：例外限包名和版本，许可全文与原始声明可追溯；缺材料不能放行发布（Task 3，正式镜像分发 S6）。

## 落地决定与文件责任

### HTTP 与内部契约

`POST /api/assets` 使用原始二进制、`Content-Type: image/png|image/jpeg|image/webp|image/gif`、`X-Asset-Extension: png|jpg|jpeg|webp|gif`。只接收后缀，不接收原文件名；后缀可按 ASCII 大小写规范化，不接受路径或完整文件名。HTTP 媒体类型/编码不支持用 415，后缀缺少/不合法用 400，三者伪装或不一致用 422 `type`。会话、CSRF、Origin 先于读取正文和图片准入。

响应为 `{ assetId, url, mimeType, width, height, bytes }`，其中 url 必须是该 assetId 的规范相对地址。错误规则为 `type/corrupt/dimensions/pixels/frames/animation/output/too-complex`；未知详情按既有宽松响应规则退回通用说明。内部 `ProcessedImage` 为 `{ data: Uint8Array, sha256, mimeType, width, height, frames, bytes }`，父进程重新校验结构、尺寸和 hash。

`NERVE_ASSET_ROOT` 为私有目录绝对路径。Task 1 只登记/校验配置；Task 6 接入路由时把它设为服务端必填，命令行迁移不要求它。测试用独立目录，部署在 S6 挂载 `/data/assets`；此处不使用仓库目录或前端目录作默认存储。

### 配额与文件事务

新增 assets 域的四张表：`asset_quota` 单行记 `used_bytes/used_assets`，`asset_object_claims` 以 sha256 为键记待转正字节预留，`asset_objects` 记完整已发布对象及媒体信息，`assets` 记 UUID、上传者、对象 hash 与创建时间。

1. 短事务锁配额行；已存在对象/预留则核对字节，同 hash 不重复收费。新 hash 在字节与条数预检后插入 claim、增加 used_bytes，提交成功才允许文件发布。
2. 任务自有临时文件（0600、独占创建、不可跟随链接）完整写入并 fsync；用原子 hard link 发布到 `objects/<hash前两位>/<hash>`，不覆盖。已存在时打开无链接普通文件，核对大小与 hash；随后同步目录。
3. 第二短事务先锁配额行，核对对象/claim；创建 object 并删除 claim（字节计数不变），核对条数后插入独立 assets、增加 used_assets，一次提交。文件在此之前已完整可读。
4. 任一步失败只清理本任务临时文件，已发布文件与 claim 不撤销。未知提交结果保守保留；同 hash 后续请求可重复发布并转正，避免崩溃预留成为不可恢复状态。没有 P1 自动 GC。

已提交状态保持 `used_bytes = SUM(objects.bytes) + SUM(claims.bytes)`、`used_assets = COUNT(assets)`；一个 hash 不同时出现在 object 和 claim。序列化在配额行，事务外没有持锁的文件 IO。上传路径不取文档/空间锁；S5 只通过 assets 公开事务接口接引用，不反向取得配额锁。
