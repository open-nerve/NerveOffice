# P7-S5 引用只授权新出现的图片（M5R-I-02，D-01）

> 状态：实施中｜日期：2026-11-05｜依据：审查报告 §3 M5R-I-02、§9 D-01；P7 设计 §3.2

## 1. 语义

每次写入正文时，服务端保存这一版从正文提取到的**完整** assetId 集合，含未被授权的 ID。授权规则如下：

| 类别 | 定义 | 是否登记引用 |
|---|---|---|
| 沿用 ID | 本次 ∩ 基准版本 | 当且仅当它当前已登记在基准文档上 |
| 新出现 ID | 本次 − 基准版本 | 按写入者当时的权限，沿用原有规则：可读文档的当前引用、可查看的历史、本人 24 小时内的上传、目标文档自身的既有引用 |

对沿用 ID 的处理不看写入者是谁，也不看他现在能读什么。上一版已存在但未登记的 ID，任何人后续保存都不升级；只有删除后重新引入，才按引入者当时的权限授权。

各写入路径的“基准版本”：

| 路径 | 基准 |
|---|---|
| 保存（changed 分支） | 被替换的当前版本，即锁下的 `document.revision` |
| 另存为副本（冲突副本、本机副本） | 草稿所基于的源文档版本。页面在查询参数里新增可选 `baseRevision`，取自 `PreparedDraft.baseRevision`。缺省（旧页面）或该修订记录已不存在时，退回源文档当前版本 |
| 普通复制 | 只复制当前关系（不变）；新文档这一版的集合等于源当前版本的集合 |
| 历史恢复 | 关系取自检查点（不变）；集合取历史校验时检查子进程给出的 `assetIds` |
| 新建 | 模板没有图片，集合为空 |

unchanged 保存与重放不写新版本，也不改关系（不变）。

保存原本就不会出现“同一版本内先删后加”，因为比较的是两版的集合。复制粘贴同一 ID、改变图片位置，都不改变集合，也就不升级。

## 2. 数据模型与迁移

- `document_revisions` 新增 `asset_ids uuid[]`，可为空。每一行修订对应一版正文，这一列与 `content_hash`、`client_build` 同属“这一版的信封”。
  - 新写入的修订总是非空、去重、按码元排序。
  - 迁移前已有的修订为空，表示“未知”。迁移不回填：SQL 解不开 gzip 正文，而 v0.1 上线前没有真实数据。
- 加 CHECK：`asset_ids IS NULL OR array_ndims(asset_ids) = 1`，空数组允许。
- 迁移用 `pnpm db:generate --name m5_revision_asset_ids` 生成，人工审阅后入库。检查点表不加列：恢复时重新检查正文，就能得到集合。

## 3. 基准集合的取得（锁下）

`DocumentRevisionsRepository.assetIdsOf(documentId, revision)` 读单行。基准集合按顺序回退：

1. 首选修订（保存为当前修订；副本为页面给出的 `baseRevision`，须属于源文档）的 `asset_ids` 非空，就用它。
2. 否则，源文档当前修订的 `asset_ids` 非空，就用它。
3. 否则（存量），在主进程、文档行的锁下解析当前正文，取完整集合：`legacy-asset-ids.ts`，沿 `legacy-resources.ts` 的理由与边界，每份文档至多一次。
4. 解析不了时，以当前已登记的关系作基准，记一条警告。这等于对这一次保存沿用旧语义；此类存量内容本来就打不开。

## 4. 授权接口

`DocumentAssetReferences.authorize(held, transaction, base)` 新增参数 `base: { documentId, ids }`。

- **沿用 ID**：须同时满足两点才放行：
  - 基准文档在本次允许的文档中，即保存时为可编辑的目标文档本身，副本时为已持锁、可读的源文档；
  - 该 ID 当前登记在基准文档上。
- **新出现 ID**：沿用原规则。
- **未给出 base**：只供内部旧调用方使用，本 Step 后不再有此类调用方，类型上改为必填。

`prepare`/`hold` 不变：候选来源仍按全部 ID 预选，多取的锁无害，锁序保持。

## 5. 契约与页面

- `conflictCopyQuerySchema` 增加可选 `baseRevision`（正整数）。
- 给出时计入 `conflictCopyPayloadDigest`；不给时摘要与旧请求逐字节相同，旧请求的重放不受影响。
- 页面 `saveConflictCopy` 带上它，`lost-copy.ts` 从 `PreparedDraft.baseRevision` 取值，与请求一起冻结，重试时不变。
