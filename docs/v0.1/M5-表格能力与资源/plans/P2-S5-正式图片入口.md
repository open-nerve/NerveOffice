## 当前代码与方案

`sheet-editor.ts` 目前只在 e2e 模式且 `imageInput=enabled` 时创建桥接/输入任务；`testing/image-input-control.ts` 同时承担生命周期和测试面板。把实例生命周期移入生产 `images/editor-image-input.ts`，测试模块只接收已有输入对象并添加可选面板/记录器，避免重复安装。就绪前已有交互屏障、入口第一监听者、只读防火墙与内容来源守卫顺序保持；销毁开始就取消输入，再等待公式停止和释放编辑器。

保留 SDK 既有“插入 → 图片 → 浮动/单元格图片”菜单，不新增产品工具栏。普通图片插入命令不是 MultiCommand；在集中 SDK 桥接内以同 ID 的实例命令替换两项，使用平台 chooseFiles/insertFiles 和既有任务，不落回默认 SDK 文件选择、异步上传。复制/剪切/右键继续现有 MultiCommand。所有入口在开始时捕获当前焦点/选区/权限，在异步后复核；拒绝、取消、失败均不借命令返回 false 调用旧实现。

菜单只开放两项插入及父项（仅编辑态）；背景、内部文档图片和链接继续关闭。原“保存单元格图片”未有平台下载适配，保持隐藏，不把显示占位作为原图下载。低层浮图提交和两项平台接管命令仅在正式输入成功安装后放行；退役时恢复关闭，不改变内容守卫。

## 执行中追加的必要修正

- 正式四格式故事发现新浮图重开会由 SDK 补写五个 transform 默认值，导致无改动保存也新增修订。保留实际差异和单元反例，创建时写全默认值；没有放宽保存相等判断。
- 独立审查发现图片在线许可在分类前误拦普通表格离线复制/剪切/粘贴。普通剪贴板目标与严格图片目标分离，确认图片后追加限制；普通目标仍固定权限、身份、书/表/选区，表格预览零图片读取/上传。
- 四格式验证改为每张检查服务端模型类型/锚点/来源及目标区域截图；只让 GIF 读取失败的反例保留另外三图，证明不会以首图代替其余格式通过。菜单预检查失败保留“插入图片”提示。
- 新增定位截图后，测试中 N15 连点间隔 148 ms，被 SDK 识别为双击编辑，撤销没有送到表格命令。原 trace/失败保留；撤销前改选 M15，明确建立画布焦点，不修改产品或放宽断言。
- 扩大回归发现普通只读剪切/表格预览粘贴提前被图片预检查拒绝，丢失原 SDK 权限提示。新增实际 SDK 反例，剪切先分类再绑定严格目标；已分类表格事件同步委托固定范围与空 files，由 SDK 自己检查权限。原只读浏览器预期和异步目标检查均保留，不以调整旧测试消除失败。
