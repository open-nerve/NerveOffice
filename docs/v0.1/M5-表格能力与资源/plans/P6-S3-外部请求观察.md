# P6-S3 外部请求观察实施计划

> 执行：superpowers:executing-plans；当前 Agent 顺序实施，同一 P6 分支。依据 [P6 设计](../06-P6-M5收尾.md) S3、[总设计](../00-M5-总设计.md) US-M5-14/A19。

**目标：** 图片与链接从首次导航到保存重开的请求由同一观察器覆盖页面、Worker 和新页；补外部/data IMAGE 反例，保留既有地址、正文与保存断言。

**设计与取舍：** 抽出 `links.spec.ts` 已有的 context request 收集，并由局部自动夹具复用到图片来源、平台图片输入及编辑器内部粘贴故事；CSP 无策略对照沿已有两个 localhost 服务校准这个观察器。单纯给旧用例加编号无法补图片观察范围；另造整套编辑器故事会重复原图片/链接断言，均不采用。不修改生产代码、CSP、SDK 或浏览器配置。此为执行者在既定 Phase 范围内的实现选择。

**当前边界：** S4 决定前不启动真实浏览器或容器；本 Step 可完成辅助逻辑单元、E2E 编写、实际 `--list` 和静态检查。浏览器校准与完整故事未实际运行前，US-M5-14 仍 planned，不能签署已覆盖通过。

## Task 1：复用观察器并核对生命周期

**文件：** 新 `tests/e2e/support/external-requests.ts`、`external-requests.test.ts`、`implicit-request-fixture.ts`；修改 `specs/editor/links.spec.ts` 的局部收集接线。

**接口：** `watchExternalRequests(context: Pick<BrowserContext, 'on' | 'off'>, baseURL: string): { list(): readonly string[], stop(): void }`。只观察 HTTP(S) 异源请求；不路由、不拦截、不因看不到 frame 而丢 Worker。返回列表是副本；stop 只撤自己监听，可重复调用。

- [x] 以事件源核对同源与不同协议/主机/端口、非 HTTP(S)、重复请求、独立监听及停止后的列表；先失败再实现。
- [x] 从已有链接用例抽取同一语义，自动夹具在首次导航前安装，结束时停止、留附件并断言外站数组为空。旧链接断言保持。

## 审查重点与后续

自动夹具只用于没有明确外站点击的故事；正式链接点击仍由原 `link-input.spec.ts` 分开断言唯一请求、opener 与 referrer，不能放宽无隐式请求夹具。data 图片本身不走 HTTP(S)，因此以有效样本的错误结果而非请求数组证明拒绝。校准的 Worker 必须真执行，不能用 Node 人工发事件冒充浏览器证据。S4 通过后先校准再执行相关真实故事，失败原件保留，不增加 skip 或降低原预算。

自审：本计划补 US-M5-14 的已定位缺口，不改变 US-M5-06 原生环境欠账；资源授权/复制/历史/GC 已有组合按 S1 矩阵进入集中复验，本次没有发现需要另写生产代码的缺口。
