# P3-S1 链接拒绝位置：实施计划

> 执行方式：主 Agent 按 `superpowers:executing-plans` 逐任务实施；项目约定的独立审查在 Step/Phase 收口时进行。｜状态：进行中｜日期：2026-10-20

**目标**：真实保存和另存副本被链接规则拒绝时，指出有限、可信的工作表/单元格位置，保留原内容和错误语义。

**架构**：contracts 定义可选位置；documents 的原链接扫描一次完成检查与定位，检查子进程沿现有 IPC 传回；页面经当前实例名称呈现。复用原共享地址规则，不开放 SDK 链接入口，不新建保存通道。

**技术栈**：TypeScript、Zod、NestJS、React、Vitest、Playwright；固定 Node 24.21.0、pnpm 12.6.0、Univer 1.0.1。

**设计依据**：[P3 设计 §3.2](../03-P3-表格能力与链接.md)；DEF-052。

## 全局约束

- `linkLocations` 最多 5 个，允许 cell/sheet/workbook；身份 1–128 字符，坐标 0–2,147,483,647；沿用图片位置的有限身份规则。
- 保持 `link-structure` / `link-address` / `link-range-id` 的首个失败，收集同一规则的位置；有效快照的接受、哈希与正文完全不变。
- 正文、URL、显示文本和任意路径不进错误详情/日志；页头不显示原始 sheetId，当前实例名称最多 120 字符。
- 图片位置、旧响应、未知规则保持兼容；所有工作在唯一 P3 worktree，正常中文提交，不改 main。
- 修复先证实失败，再实现、复验和有效变异；重型检查串行，不提高预算/重试或减少浏览器。

## 审查重点与所属任务

1. 隐藏工作表、未列入 sheetOrder 的表、数组行列不能漏检（Task 2）。
2. 畸形键、特殊原型名、超长身份或坐标不能成为任意正文回显（Task 1/2）。
3. 同格多条链接与多个不同失败规则不改变原首个错误、位置不重复（Task 2）。
4. 缺失/畸形位置和旧服务端、未知规则仍显示原固定说明（Task 1/3）。
5. 检查通过不等于实际写入；保存/另存失败须保留正文、修订与本页修改，修正后可以再保存（Task 2/3）。
