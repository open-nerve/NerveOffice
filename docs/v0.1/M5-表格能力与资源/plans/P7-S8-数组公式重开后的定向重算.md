# P7-S8 数组公式重开后的定向重算（M5R-I-07，D-04）

> 状态：实施中｜日期：2026-11-05｜依据：审查报告 M5R-I-07、§9 D-04；P7 设计 §3.5

## 1. 复现（修复前）

E2E `csv-formulas.spec.ts` 新增“数组公式收齐保存后常规重开”。在 Chromium 上运行：

| 模式 | 结果 | 说明 |
|---|---|---|
| Worker | 失败 | 阅读态导出只剩锚点 `1`，溢出的 `2`、`3` 与第二行 `4,5,6` 全部缺失 |
| 主线程 | 通过 | 测试先让 Worker 启动失败；回退到主线程时本身会强制全量重算（`formula-fallback.ts`） |

结论与审查推导一致：SDK 默认 WHEN_EMPTY 只计算“有公式但没有缓存值”的格。锚点保存了缓存值，溢出结果只在 FormulaDataModel 里，正文不记录，SDK 也从不写回 `ref`。

## 2. 方案（D-04 (a)：打开时定向重算数组锚点，不改正文格式）

**识别**：不靠公式文本猜测。编辑器捕获正文时，向 SDK 的 FormulaDataModel 查询当前确有多格溢出的数组公式锚点（`getArrayFormulaRange` 中范围大于 1×1 的项），这是会话里实际计算出的事实。

**做法**：捕获时只去掉这些锚点的缓存值 `v`/`t`，其他字段原样保留，包括 `f`、`si`、样式、`p` 与 `custom`。

正文格式与档案版本都不变。“有公式、没有缓存值”是正文原本就合法的形态：新输入还没算完的公式，以及“公式待更新”的文档，都是这样。

**重开**：阅读、编辑、Worker 与主线程都走 SDK 现有的 WHEN_EMPTY 初次计算，恰好只重算这些锚点，溢出结果随之恢复。其余公式仍沿用缓存值，不扩大打开时的计算量。

**范围**：`capture()` 统一改为这一形态，保存、自动保存、本机草稿、另存为副本以及其后的检查点和历史都基于它。测试构建探针的 `snapshot()` 原本注明“与捕获相同”，同步改用同一函数。

## 3. D-04 (c) 的落地

修复后，“数组结果不完整”只会表现为“锚点还没有算出来”。这时公式未收齐，CSV 的既有拒绝 `formula-pending` 会说明原因，所以兜底由现有门禁承担，不另加启发式。

另外考虑过按函数名或区域引用猜测“可能是数组”，但这会让 `SUM(A1:A3)` 这类普通公式的导出被误拒，因此不采用。

剩余缺口：P7 之前保存、且之后从未在会话中重新计算过的正文。v0.1 上线前没有真实数据，这类正文只在开发库和测试样本里，交接时写明。处理办法是一次强制重算（“公式待更新”）后再保存。

## 4. 测试

| 层级 | 用例 |
|---|---|
| 单元（真实 SDK 缓存 mutation） | 多格数组锚点的捕获不含 `v`/`t`，`f` 等保留 |
| 单元 | 1×1 数组与普通公式保留缓存值 |
| 单元 | 其他工作簿或工作表的数组数据不影响当前捕获 |
| 单元 | 捕获不改变模型本身 |
| E2E（Chromium） | 复现用例在 Worker 与主线程两种模式都转绿 |
| E2E | 既有 `csv-formulas` 的强制重算用例保持通过 |
| 回归 | 依赖捕获字节的既有单测与只读样本用例 |
