## Task 1 局部修正：焦点与原生选区一致

diagnostic06 已证实实际故障：重命名表后进入首个单元格，activeElement 已为 normal editor，但 DOM Selection 仍在旧改名控件的父节点；首次“青”只有 beforeinput（未取消）而无 input，后续“山”正常。SDK focus() 仅调用 HTMLElement.focus；元素已聚焦时浏览器不再重建选区。临时日志影响时序，不能当通过证据。

按既有适配层策略，在 @univerjs/docs-ui 1.0.1 的实际 focus 边界局部修复：完成 focus 后，仅当该元素仍实际聚焦、未处于 IME 组合、且原生选区缺失或端点不在此输入区内时，使用该元素所属 document 重建输入接收位置。保留已有内部选区、IME、焦点回调选择其他控件等边界，不改 SDK 逻辑选区、公式/保存协议；不在测试中操作 DOM 选区代替产品修复。ES/CJS 对称、固定版本 patch 与摘要登记。

在实际 SDK focus 方法上建立 DOM 状态反例与负向对照；原浏览器故事移除所有诊断后原速复验，并复跑既有输入焦点、IME、自检、恢复相关故事。此为已授权的局部问题修复，不改变模块协作或范围，不新增审批点。

## Task 3 追加修正：延后全选不能覆盖已经开始的表名输入

final01 为 218/219 通过，Chrome 后段改名失败。等待改名框实际聚焦的 final02 仍有 Chromium 两轮失败，因此该就绪条件不构成修复。原失败轨迹显示回车前文字就未改变；输入后单次取证的 diagnostic06 又复现输入“源数据”后只剩“据”，以及完整输入后仍被重新全选的对照。逐事件监听的 diagnostic01–04 改变了时序，不作验收；原生小页面 80 次对照正常，不能简单归为浏览器故障。

固定 sheets-ui 的 keepTextSelected 在 setTimeout 中无条件全选。若原生焦点已先就绪，用户先输入一部分，迟到的全选会使后续字符覆盖这部分；结束改名后到来的任务还可能重置其他控件的选区。建立发布包 ES/CJS 实际函数的确定定时任务反例，不复制实现、不引出新的生产接口。函数未公开导出，测试仅加载发布包原文并提取唯一对应声明，在真实 DOM/Selection 与可控计时器上执行；真实入口仍由浏览器完整链验证。

修正保持原异步全选语义，但任务须仍属于存活且可编辑、正文未改变、没有发生后续用户输入/光标操作或失焦的原控件。以临时原生事件监听记录后续交互，回调运行时先清理监听，再判断是否仍可全选；使用控件所属 document。已经开始的键入、同值输入、IME、用户光标选择、结束/销毁都不再被旧任务覆盖；未交互时仍正常全选。固定版本窄补丁、ES/CJS 对称、摘要及 UR-040/ADR 登记。
