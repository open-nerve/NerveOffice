# M5-P1-S4 鉴权读取与占位实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 登录者按当前有效权限读取图片，上传者窗口严格限制为 24 小时；无权与不存在不可区分，服务器能回答的读取故障输出可解码占位图。

**Architecture:** Workspace 在一个既有 readSnapshot 中取得 Assets 元数据、文档域的当前引用授权；授权结果确定后退出只读事务，再读私有文件。Assets 不导入 Documents，文档授权经 DocumentAccessPolicy 的既有入口和可见范围，不另拼空间权限。S4 建当前引用表用于授权，S5 才接保存、复制和引用增减。

**Tech Stack:** Node 24.21.0、NestJS、PostgreSQL/Drizzle、既有 TransactionRunner、StorageAdapter 与浏览器测试设施。

**Spec:** [Phase 设计](../01-P1-图片资源底座.md) §3.1–3.4、S4；[M5 总设计](../00-M5-总设计.md) §6.2–6.3；ADR-014/018/021。基线 `b4bacc78d31a09b2fdedd5138a6a2fb7e3a55dd7`（S3 已完成）。

## Global Constraints

- 主目录保持 main，沿用唯一 P1 分支/worktree；中文提交、正常 hooks，不单独合并 Step。
- 不开放正式前端图片入口、不写保存引用、不做历史或 GC；P2 三项真实交互硬条件、M4 DEF-073 继续保持。
- Assets 不依赖 Documents；Workspace 不查表；权限仍从 DocumentAccessPolicy 取。文档域不跨模块查询 assets 表。
- 测试只用 127.0.0.1:53522 隔离库、自有图片与私有临时目录；浏览器运行与其他全量/压力串行。
- 无会话和事务开场发现的会话失效保持原 401。已登录的无权与不存在同一 PNG、同一头部、HTTP 200 / X-Asset-Status: 404 / no-store。
- 成功每次重新鉴权，private, no-store；不产生 ETag/Last-Modified/304，不支持 Range/签名 URL 绕过授权；所有图片保持 nosniff 与 same-origin CORP。
- “每次”指实际 HTTP 读取。S4 实测同页 img 的 available-images 会复用已解码内容，no-store 不能收回已有画面；首次直接 img 解码与主动 fetch(no-store) 重读分开验证。SDK 权限变化/退出/重建时主动复核及旧画面清理，列为 P2 开放入口前的条件，不以协议测试替代产品验证。
- 故障输出逻辑 500/503 占位，内容不带路径、hash、SQL、原异常；记录有限分类。网络断流/离线和客户端坏解码的 UI 兜底属于 P2，不以服务器占位冒充覆盖。

## 落地决定与接口

### 1. 元数据与当前引用

Assets 增公开 `AssetReadService.metadata(assetId, transaction): Promise<AssetMetadata | undefined>` 与 `readAuthorized(metadata): Promise<AssetImage>`。内部元数据包含上传者、创建时间、数据库计算的 `withinUploadWindow`、对象摘要/媒体信息；`AssetImage` 只含字节与 MIME。年龄按当前只读事务的数据库时刻判断，`created_at > now() - interval '24 hours'`；到边界即过期，不使用应用时钟。

新增 `document_asset_links(document_id, asset_id)` 联合主键，文档 FK cascade、asset FK restrict，按 asset_id 反查索引。属于 documents 域。S4 为读取授权提前建表；测试可布置真实关系，产品写入在 S5 完成，不在这里引入半套保存规则。

### 2. 授权与查询边界

`DocumentAssetAccessService.canRead(actor, assetId, transaction): Promise<boolean>`：先通过 policy.visibleSpaces 得到当前内容可见空间；DocumentsRepository 复用其已有 accessible(scope)，增加 linked asset EXISTS 条件并 limit 1，拿到一份可见的当前有效引用来源。随后仍经 policy.accessOf 复核；空来源用既有 MISSING_DOCUMENT 执行同样的权限查询。资源元数据不存在时也调用此链，不按是否存在跳过。

这种查法不把引用此图的全部文档装进内存，也不逐条查询无权文档；授权范围复用文档现有空间/单独分享规则。系统管理员身份本身不授予内容读取；归档空间仍可读；回收站文档不提供当前引用授权。用实际 SQL 语句序列比较已知无权与未知 ID，不能只比较 JSON/PNG。

Workspace 的 `AssetReadingService.read(actor, assetId)` 进入 readSnapshot（由既有开场回调复核会话）；总是取元数据和当前引用判定。只有元数据存在且满足“本人窗口内上传或可读当前引用”时输出授权元数据，然后在事务之外调用文件读取。现有只读快照线性化语义保持：撤权之前已开始的快照可以完成，撤权提交之后开始的读取必须拒绝。

### 3. HTTP 与占位

`GET /api/assets/:assetId`，HEAD 走同一认证/授权。规范 UUID 之外的目标按未知资源处理；不将查询参数转成授权凭据。成功带 X-Asset-Status: 200 和原 MIME/完整长度；占位使用自有固定 PNG、逻辑状态头 404/500/503。所有失败占位字节相同，不暴露资源是否存在或失败路径。媒体输出由 interceptor 写头并使用 StreamableFile，避免 Express 的条件响应自动转为 304。

数据库繁忙通过公开 `databaseBusyReasonOf` 映射逻辑 503；文件缺失、内容校验失败与未知内部错误映射逻辑 500。AppError 的会话错误继续抛出给既有全局过滤器；不把 401 转成“图片不存在”。只在守卫通过后的资源读取路径处理占位，认证管线自身故障保持原全局响应。

5. 新表只表达当前引用，保留或未来历史引用不能意外提供当前内容读取权限。
