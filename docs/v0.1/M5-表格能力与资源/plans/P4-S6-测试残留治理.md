# P4-S6 测试残留治理实施计划

> 按用户 2026-10-26 的明确要求立即实施；在唯一 P4 worktree inline 执行（superpowers:executing-plans），不恢复重型验收，不新开分支。用户已授权清理确认无用的测试环境，未知内容保留。

**目标**：实际回收历史测试残留，并让正式测试命令自动登记、结束回收及下次启动清扫，保护源码、Git、其他任务和业务数据。

**架构**：标准库 Python 外层运行器建立独占运行目录和文件锁，管理它亲自创建的 scratch；Playwright 报告和 OPFS 实证移出可丢弃资料，失败原始资料单独限额保存。已有测试断言、浏览器范围和预算保持。存量清理采用独立精确清单，不把旧 handoffs 当成管理器拥有的临时根。

**技术**：Python 3 标准库（macOS/Linux），现有 Node/Playwright；不添加运行时依赖。Python 只用于开发测试入口。

**规格**：本轮用户指示；成功/失败/中断/强制终止、并发隔离、及时登记、有限保留、禁止重建大型环境，以及分支和中文提交要求。

## 决策与边界

- 沿已有 P4 分支；已有 4548 路径及未提交内容已记录并备份，不混入本次提交。
- 管理根 `.test-resources`；每次 UUID 目录、创建前登记、每轮持锁。相同 worktree 的固定报告发布口互斥；不同 worktree 独立。
- 成功：保留 JSON/HTML/trace/截图、OPFS manifest/files/cleanup 和清理回执；普通浏览器缓存/完整资料释放。
- 失败/中断：同样保留核心诊断，完整浏览器资料最多每轮 256 MiB；全管理根最多 2 GiB、最长 7 天。超过时记录省略原因，保留核心报告。完整 VM 不作为默认失败证据。
- 完整报告在管理根最多 14 天或 5 GiB；正式交付需长期保留的报告由 handoff 入口选择转移并登记，禁止完整运行环境无限归档。
- 捕获 INT/TERM 后转交本轮子进程并等待；未确认写入者结束不删。强制中断后下次启动仅处理锁可取得、原进程组不存在且没有打开句柄的本轮资源。
- 路径白名单、禁止符号链接根/越界、未知清单不认领；数据库沿现有主机标识/PID/活动连接守卫，业务数据库不动。
- VM 手动入口要求资格磁盘位于本轮登记的 scratch；制作模板/克隆和整个多次重启实验在同一管理运行内完成，禁止自动认领外部已有 VM。

## Review Focus

1. 锁、PID 重用、尚存子进程或无法读取进程状态时不得清理。
2. 根路径/父目录符号链接、任意清单路径及重复执行不能越界。
3. 先写归属再启动资源，关机来不及完成时仍可定位；失败不能把成功状态写回。
4. 保留 OPFS 实证与原始失败报告，不把原清单改写成从未存在的大文件。
5. 失败保留上限要实际执行；仅证明自己的资源退役，未知 VM/数据库/profile 不动。
