# P2-S2 图片实例与可靠渲染：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 每个编辑器的图片都通过真实鉴权加载，在身份/权限变化和销毁时清理旧图，修复固定 SDK 的已知图片渲染、锚点和 Ready 取消问题。

**Architecture:** S1 管字节请求；images 管浏览器解码、实例所有权和 SDK IO；internal-api 集中 SDK 接口及渲染操作；页面只提供身份/权限事实。固定依赖修复覆盖 SDK 自带的直连路径，不写临时地址进模型。

**Tech Stack:** TypeScript、现有 Fetch/Blob/Image、RxJS、Vitest、Playwright、pnpm 固定补丁；Univer 全部保持 1.0.1。

**Spec:** `docs/v0.1/M5-表格能力与资源/specs/P2-S2-图片实例与可靠渲染.md`。

## Global Constraints

- 只在 `codex/m5-p2-images` worktree 实施；main 不动、不新增分支；完成 S2 后一次中文提交，正常 hooks。设计先落档。
- 图片最多 5 MiB、单边 8192、像素 16,000,000；请求 30,000 ms、浏览器解码另限 10,000 ms。
- 只有规范平台相对地址进入网络层；原会话响应对象原样传递，不能跨用户/实例/代次复用。
- 取消及时拒绝、临时资源幂等释放；普通显示失败可占位，下载/复制失败不可交出占位。
- 正式入口关闭；三项原生证据仍在 S4，全面 Phase 门禁在 S6；重型验证串行。

## Review Focus

- 底层 read/decode 忽略取消并晚成功：旧调用仍及时拒绝，晚解码对象被释放。（Task1、Task4）
- 两张图共用元素，其中一张换源：另一张的像素不变，刷新旧源不改新图。（Task1、Task2、Task4）
- 相同 source 移动/缩放或自动行高后：不绕过 IO、不写 blob、重开二次保存尺寸不变。（Task2–4）
- 图片持续 401 而 session 仍报告本人：不形成自触发重读循环；其他用户不能接管本实例。（Task4）
- Ready 前销毁及主线程公式正在退出：图片当场清掉，不等退出时限；真实非取消错误仍报告。（Task2–4）

**Interfaces:**
- Consumes Task2 EditorImageAccess 与 CreateSheetEditorOptions.imageAccess。
