# M5-P1-S1 真实图片路径前置复核：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 用当前 1.0.1 和真实 Chrome/Safari 获取 DEF-004 的表格部分前置证据，再决定资源后端与 P2 入口的具体接线。

**Architecture:** 新建只监听 127.0.0.1 的诊断页面，直接解析工作区已有的精确依赖；诊断图片 IO 与文件接收只保存本次测试样本，独立于生产应用、账户和数据库。结构化记录保留真实事件、原生动作、SDK 结果和权限；自动校准单列。

**Tech Stack:** 既有 Node 24.21.0、Vite 8.3.0、Univer 1.0.1、Playwright 1.63.0；真实 Chrome/Safari 通过电脑操作工具输入；没有新产品依赖。

**Spec:** `../01-P1-图片资源底座.md` §3.5、M5 总设计 §2.2/6.4、DEF-004 与 M0-P4 报告。需求边界已清楚，不另写重复 spec。

## 全局约束

- 固定 P1 worktree 与 main 基线；主目录不切分支。仅此 Phase 一个分支，中文提交、正常 hooks。
- 生产 SDK 的包必须全为 1.0.1；M0 1.0.0 的报告只作历史参考，不修改参考源码或生产注册表来运行探针。
- PNG/JPEG/WebP/GIF 样本只由本任务生成；观察前先复制已知样本，不读取用户原剪贴板；不访问真实账户或文档。
- 原生 UI、合成 paste、协议拖放三种方法分别登记；`isTrusted` 不能单独证明系统操作来源，必须与本轮 UI 动作回执对应。
- Safari 开始前屏幕解锁且空闲至少 120 秒；用户活动作废本轮；不开远程自动化或关闭安全保护。
- 原件写到主目录 `.codex/handoffs/m5-p1-20261018/s1/`，失败也保留。生产资源实现必须等前置裁决成立。
- 按用户自主推进授权以内联执行，不逐 Task 请求确认；Phase 收尾一次独立审查。此为诊断 Step，不为文档变更编写无效测试。

## 审查重点

1. 把 synthetic/协议事件冒充真实剪贴板或 Finder 文件拖放；记录器和汇总必须拒绝此类资格。
2. 图片文件与 HTML 同时存在时只记录其中一种，误判丢图根因；记录 MIME、文件摘要和受控 HTML 结构。
3. SDK 复制后的延迟清空覆盖早期观察；后续粘贴到接收区与另一页的结果才是复制证据。
4. 未阻止的真实 drop 导航丢失页面内日志；事件立即回传，动作前后同时记录浏览器标签/URL。
5. 未登录、权限提示、CSP 或解码失败被写成“路径有效”；报告必须保留身份、模式、错误、网络事实与实际 drawing 数。

## Task 1：独立探针与记录器校准

**Files:** 新增 `spikes/m5-assets/{README.md,index.html,vite.config.ts,server.ts,record.test.ts}`、`spikes/m5-assets/src/{main.ts,record.ts,probe.css}`；样本放同目录 `fixtures/`。外部构建/记录根固定到本 Phase handoff。总设计、Phase 文档、故事 planned 登记与本 Task 一起提交。

**Interfaces:**
- 页面记录 `ProbeRecord`：schemaVersion=1、runId、caseId、SDK=1.0.1、browser userAgent、mode(default/diagnostic)、method(native-ui/synthetic/protocol)、事件序号/时间、类型、isTrusted、defaultPrevented、clipboard/dataTransfer 类型、文件 type/size/sha256、drawingCount、错误与页面身份。
- `nativeEvidenceOf(records, actionReceipt)` 返回 `{eligible: boolean, reasons: readonly string[]}`；仅受控样本且事件可信、方法为 native-ui、动作回执身份相符、页面版本匹配时允许作为真实证据。它不根据“没有错误”推断成功。
- loopback 服务 `POST /records` 接收有界 JSON，逐条追加原件；`GET /records` 只供本机读回。诊断上传走独立 `/probe-images`，只用临时测试文件，不提供生产 `/api/assets`。
