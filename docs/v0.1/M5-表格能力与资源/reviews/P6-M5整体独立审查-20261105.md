### 1.2 结论

- **Critical 0 / Important 7 / Minor 22**，另有 14 项待验证疑点（原 15 项中 Q-01 经第二轮核实升级为 I-07）；风格或无具体影响的建议单列于附录 B，不计入数量。第二轮核实没有撤销任何问题，修订明细见 §3.0。

- **触发条件**：规则需要条件值（数值、整数、日期、文本长度、自定义公式等）。用户把条件清空或停在非法中间值（输入组件每次按键都入队），随后修改范围或其他不同种类的设置，再把条件改成合法值。此时队列为 [非法设置, 范围/选项, 合法设置]。
- **预期**：最终合法的输入可以提交；失败要指出具体字段且不丢修改；关闭面板不能静默丢弃。
- **实际**
  1. flush 执行到队首的非法设置时命令返回 false，整队停住。之后的合法设置只能与队尾合并，覆盖不了队首。
  2. “确认”时草稿是合法的，但 flush 失败，只打开错误开关。错误内容取自合法草稿，所以界面没有任何提示，面板也不关闭。
  3. “删除规则”“切换类型”同样被拦。
  4. 关闭侧栏或组件卸载时再次失败，随后清空全部待办：范围、选项和改正后的条件全部丢失。
  5. 平台的未提交输入观察在约 1 秒后就认为面板输入已落模型，自动保存随即把不含这些修改的模型报为“已保存”。
- **设计意图与缺陷边界**：失败项阻塞后续项是有意设计，用于保证提交顺序；`apps/web/src/editor/internal-api/data-validation-panel.test.tsx:375-385、411-421` 证明一次性失败可经再次“确认”按原顺序重试成功。缺陷在于：被后续合法输入覆盖的非法设置项既不剔除也不合并，阻塞永远无法解除；确认时没有可见错误；关闭或卸载时待办被清空。
- **影响**：数据验证规则的修改静默丢失，并被报告为已保存（US-M5-04“逐项覆盖界面、撤销与重开”的可靠性缺口）。表格单元格数据本身不受影响。
- **测试为何未覆盖**：`apps/web/src/editor/internal-api/data-validation-panel.test.tsx:375-385、411-451` 只用 `mockReturnValueOnce(false)` 模拟一次性失败；E2E 用 `fill` 一次性填值，不产生非法中间态，也没有“非法→其他种类→改正”的序列。
- **修复方向**：入队时剔除被同字段后续值覆盖的早期设置项（不改变跨种类命令的顺序）；提交失败按失败项给出字段错误；关闭或卸载时提交失败不清空，并通知平台的未提交输入状态。
- **回归验证**：沿用 `data-validation-panel.test.tsx` 的 `setup('number', true)`，依次执行：
  1. 把公式改为 `''`；
  2. 改范围为 `C3:C4`，或执行 `h.option()`；
  3. 把公式改为 `'5'`，点“确认”。

  断言规则中有 `formula1: '5'` 和新的范围/选项，且面板已关闭。变体：直接卸载组件，断言修改不丢失或有明确提示。E2E 用逐键输入复现中间态。

#### M5R-I-07 动态数组公式在常规重开后不再计算，溢出结果在显示与 CSV 导出中静默缺失

- **严重度** Important｜**置信度** 中高（SDK 判定逻辑、持久化与恢复路径均在实际副本中核对；jsdom 夹具完不成公式轮次，未能实测；浏览器复现未运行）｜**归属** 编辑器公式加载（M3/M4 计算模式）× P5 CSV 导出｜**分类** 继承问题被 M5 放大（第二轮由疑点 Q-01 升级）
- **位置**
  - `apps/web/src/editor/profile/sheet-profile.ts:166-171`：只有 `recalculate === true` 时使用 FORCED，否则沿 SDK 默认 WHEN_EMPTY；与 BASE 相同
  - 何时强制重算：`apps/web/src/features/sheet-editor/edit-mode.ts:1569、1642`，仅“公式待更新”的文档进入编辑时；`formula-fallback.ts:22、31` 与 `formula-recovery.ts:189`，公式 Worker 故障回退时。阅读态与普通进入编辑都只按 WHEN_EMPTY 做初次计算，不强制重算（公式引擎在两种访问下都运行，`sheet-profile.ts:100-107` 只按 Worker/主线程区分）
  - `apps/web/node_modules/@univerjs/sheets-formula/lib/es/index.js:615-633`：初次计算在 WHEN_EMPTY 下只提交 `getFormulaDirtyRanges()`，且 `forceCalculation: false`
  - `apps/web/node_modules/@univerjs/engine-formula/lib/es/index.js:4832-4870`：脏区只含“有公式且没有缓存值”或含 `IMAGE` 的格，带缓存值的数组锚点不在其中
  - 同文件 `:4888-4918`：加载时数组数据只从单元格 `ref` 恢复；engine-formula、sheets-formula、sheets 中都没有计算后写回 `ref` 的代码（core `:27247` 只在复制单元格时原样带过已有 `ref`）
  - 平台自身记录：`docs/adr/ADR-010-编辑器适配层与内部API登记.md:254`（“固定 SDK 的数组公式只把锚点写入原 cellData，溢出结果由 SetArrayFormulaDataMutation 写到 FormulaDataModel”）；`apps/web/src/editor/csv/sheet-csv.test.ts:300-316` 断言 `save().cellData` 只有锚点
- **触发条件**：文档含动态数组公式（如 `=SEQUENCE(2,3)`），收齐后正常保存（`formulasPending` 为 false），之后任何人正常打开（阅读）或进入编辑。
- **预期**：重开后显示与保存前一致的溢出结果；CSV 导出“按当前文档/表实际存在的结果格补齐”（P5 §3.2），不静默缺失。
- **实际（代码推导）**：锚点保留缓存值，溢出格既不在 `cellData` 中，也不会因 WHEN_EMPTY 而重算。重开后只显示锚点值，溢出区域为空。`csvArrayCells` 枚举不到缓存，CSV 只导出锚点，而 `formulasSettled()` 为真，导出前检查识别不出。只有编辑公式的前驱、或文档被标记为“公式待更新”时才会恢复。
- **取证情况**：主审在已排除的取证目录中用现有真实 SDK 夹具做了 jsdom 尝试（§7 序号 4–7）。“锚点带缓存值”一组在 12 秒内显示为 `[['1','',''],['','','']]`，CSV 为 `[['1']]`；但对照组（锚点无缓存值）同样始终未完成计算，说明该夹具在 jsdom 中跑不完公式轮次，**这次尝试不能作为证据**。结论依据的是上面的源码判定链。
- **影响**：动态数组的结果在重开后对所有读者“消失”，阅读、编辑与导出都受影响（数据本身可经重算恢复，公式文本不丢）。CSV 导出静默输出不完整数据，违背 US-M5-12 的承诺。
- **测试为何未覆盖**：唯一的数组 CSV 用例 `tests/e2e/specs/editor/csv-formulas.spec.ts:22-43` 先把 `formulas_pending` 置为 true 强制重算，保存后没有常规重开；单测用 `SetArrayFormulaDataMutation` 手工注入缓存。P3 能力矩阵的 M0 公式样本不含动态数组。
- **修复方向（需跨模块决策）**
  - (a) 文档含数组公式时，打开即对这些锚点做一次定向重算：例如把数组锚点加入初次脏区，或在适配层登记一次 onlyLocal 重算。代价是打开时的计算开销。
  - (b) 持久化溢出范围，例如写入 `ref`，使 SDK 加载时可恢复。会改变正文内容，需评审格式与旧客户端兼容（计划书 §8.7）。
  - (c) 过渡措施：CSV 在无法证明数组结果存在时拒绝导出并说明原因。
- **回归验证**：先在浏览器补一条“保存→常规重开→读取 B1:C2 显示与 CSV”的复现用例（预期修复前失败）；修复后阅读、编辑、Worker 与主线程两种模式都断言溢出完整；保留现有强制重算用例。

- 上传入口：先经会话、CSRF、Origin 守卫，取得准入名额后才读正文；按头部与分块判定 5 MiB；拒绝后在有界时间与字节内丢弃。媒体类型、后缀、魔数三方一致。
- 图片处理：完整解码后从像素重新编码，并再解码核对；子进程受地址空间、堆、jitless 与最小环境限制，超时 SIGKILL，close 后才释放名额。IPC 严格校验，父进程复核字节数与 SHA-256。
- 配额与文件一致性：配额单行 `FOR UPDATE` 串行；新对象先建持久 claim 收费，转正时复查。文件先 fsync、再 link、再 fsync 目录，然后才转正；EEXIST 只校验、不覆盖；O_NOFOLLOW、0600/0700、属主与 realpath 检查。
- 读取：无会话返回 401；未知、无权、非规范 id 返回同一占位，查询序列相同，也不碰文件；响应头齐全；没有 ETag、Range 或 304 旁路。
- 引用与锁：引用在锁下复核；锁序为账本→树→空间→文档→资源，未发现逆序。unchanged 与重放不改关系；正文、修订与关系同事务提交。普通复制与本机草稿副本的授权边界与设计一致。

**P2 图片**
- `IMAGE()` 来源：在名称展开前做词法证明，再三重核对。引用、区域、数组、拼接、名称、LET/LAMBDA、INDIRECT、空白、大小写、全角、编码绕写都返回 `#VALUE!`；主线程与 Worker 共用安装函数与 origin。
- 读写客户端：读取 no-store、`redirect: error`，状态头必须为 200，流式 5 MiB 上限，不自动重试；上传只发后缀，响应自洽校验。
- 实例与渲染补丁：代次隔离、迟到结果释放；对象 URL、计时器与监听都会释放。坏图与未完成图不进 drawImage；Position 自动行高重算锚点；Ready 只静默 LifecycleUnreachableError。
- 输入入口：paste/drop 在同步阶段阻止默认行为；表格 HTML 优先；文字编辑与编辑栏不上传。

**P3 表格与链接**
- 链接写命令与菜单：只在编辑实例开放，只读时被守卫取消。地址在写模型前规范化；拒绝协议相对地址、`javascript:`/`data:`、凭据与控制字符。导航使用 `noopener,noreferrer`，内部锚点不外发。
- 弹层强制关闭前都检查类型。
- 服务端链接位置：上限 5 个，标识走白名单，遍历覆盖隐藏表与不在 sheetOrder 中的表，不回显内容。
- 补丁一致性：7 个双格式补丁的 ES/CJS 规范化比对一致，登记 JSON 的摘要吻合。

**P4 历史与回收**
- 检查点：行级触发器拒绝任何 UPDATE。小时桶与检查点同事务；只在 changed 分支采样，unchanged 与重放不采样；时刻在锁后取数据库时钟。保留期由 CHECK 固定为 168/720 小时，到期后读取与授权立即失效。
- 权限：列表、详情、正文与恢复每次都在快照或锁下重判；不可见与不存在统一回答。运维检查点不进入普通读权。
- 恢复副本：锁序与身份复核正确；只复制检查点内已授权的图片关系。
- 升级屏障：独占/共享 advisory 锁加行锁，旧 RR 快照的冲突转为繁忙。
- GC：只在配额→资源一侧取锁；引用活动记录让宽限重新计时；两层候选；代次路径与永久标记；确认时才释放字节；备份声明缺失时只整理候选。

**P5 CSV**
- 解码：fatal UTF-8，只剥离单个 BOM。
- 状态机：CRLF/LF/CR 分隔，引号内换行与双写转义正确，语法错误明确拒绝，末尾单换行不多出一行，预算按 UTF-16 单位逐步检查，按批让出并检查取消。
- 导入类型：只有短十进制且最短表示一致才转数字，日期、指数、前导零、`+1`、`-0` 保持文本。
- 导出注入保护：危险首字符含全角与 TAB/CR/LF，前导空白后仍判定。
- 插表与新建：插表基于最新快照计量，单条撤销，失败零写入。新建先预检再 POST，requestId 账本语义正确，挂载后核对模板才导入。

**前端历史预览与会话协调**
- 预览：独立入口受 lint 边界与预算门禁约束；只建 read 实例，不发租约、保存或草稿请求；换人或未登录即终态清除；晚到实例按代次销毁。
- 恢复账本：键与服务端摘要一致；未知结果沿用 requestId。
- 清除入口：只对空间管理员显示；结果未知时禁止复用同一确认。
- CSRF 停写协调：同代次结果剥离许可并重试；不同代次退休旧记录；换人或换 CSRF 时退休；被停用账户不能被同 CSRF 的成功确认重新激活。

**P6 与跨模块**
- CSP：M5 没有放宽；预览与 CSV 新建页走同一托管链并 no-store。
- 测试构建隔离：测试模块只在 `MODE==='e2e'` 分支动态导入，lint/artifacts/budgets 门禁兜底。
- 报告与 CI：`webServer.env` 的全量展开已移除，上传前双重检查；CI 不持久凭据，Action 按 SHA 锁定，各 job 检出同一 SHA。
- Git 隔离：TS 与 Python 两版都清除 `--local-env-vars` 及 `GIT_CONFIG_KEY/VALUE_n`，并核对根目录。
- 部署：`NERVE_ASSET_ROOT` 必填并与 Web 根互不包含；宽限、备份期与连接池的交叉校验与 README 一致。

**测试资源工具**
- 删除点：全部删除点都限于本轮登记根，删前核对锁、台账、marker、进程组与 lsof；不跟随内部链接；短根与别名做 dev/inode 等身份核验。
- 托管策略：在 macOS 上设置托管策略直接报错；Linux 需要全套 CI 身份，且托管路径只导出不删除，伪造身份只会多保留、不会多删。
- lsof 与报告安全：lsof 输出做全量结构校验，NOFD、错误、超时都按不完整处理；report_safety 对重复键、路径穿越、超限等失败关闭并保留原件。

## 附录 B：非缺陷改进建议（不计入问题数）

1. 检查点图片关系表 `document_checkpoint_assets` 没有数据库层的不可变保护，0038 还为它定义了 UPDATE 活动触发器。可禁止 UPDATE 以及检查点创建事务外的增删（P4）。
2. `captureHourly` 在 `#insert` 返回空时报“源不完整”（`document-checkpoints.repository.ts:31-32`），实际含义应是桶与检查点不一致（当前不可达）。可校正文案（P4）。
3. 新建文档首小时的历史只是初始模板，第一个小时内的实际内容无法经历史恢复。属已批准设计，建议在产品说明中写明（P4）。
4. 上传正文在唯一执行槽内读取，慢速客户端可占槽约 60–90 秒；记录配额是组织级、没有每用户限额；finalize 代次不符时抛出的 `ASSET_BUSY` 未带 Retry-After；含图片的 unchanged 与重放保存仍以 FOR UPDATE 锁住全部候选来源（P1）。
5. engine-formula 补丁在 `getFormulaDirtyRanges` 中对每个有缓存的公式重新分词，可先用 `/IMAGE/i` 文本预筛。上传与读取共用 30 秒总时限，慢上行网络必然超时。每次 refreshDetail 成功都全量重下图片（P2）。
6. 表名按 120 个 UTF-16 码元截断，可能截断代理对。`mailto:` 用 `window.open` 会在部分浏览器留下空白页。可加门禁检查运行图中没有 `@univerjs/*/lib/cjs`（多个补丁只改 ES）（P3/P2）。
7. 从 CSV 新建的文档第一张是空白表；负数货币/会计格式会被加 TAB；`setTimeout(0)` 嵌套会被钳到 4 ms；空表导出 1×1 的 `""` 与注释意图不一致（P5）。
8. 恢复面板默认目标可改为源文档所在空间；目标空间权限被拒时同时刷新候选；编辑页的损坏提示可直接提示“可从历史恢复为副本”（前端）。
9. csp.spec 的安全头检查可补 CSV 新建页与历史预览路径；生产镜像下增加不依赖探针的外部请求冒烟；统一下发 `X-DNS-Prefetch-Control: off`（P6）。
10. 测试资源工具的其他建议：
    - `contained()` 直接拒绝 `..`；`remove()` 比较 st_dev。
    - 诊断导出按 `.log/.json` 后缀会带出 Chromium LevelDB 的数据文件。
    - `report_safety._html` 在出现 `playwrightReportBase64` 时应要求恰好一个 payload。
    - 托管 cleanup-receipt 的文案（`run.py:141`）与 `host-disposal-pending` 的实际处置不符。
    - sweep 的托管分支在复核失败时没有保留原产品状态。
