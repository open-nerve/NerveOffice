## 镜像及预算的两个具体修正

新镜像目前**保留，未实际删除**。Docker 的 `RepoTags` 返回与本轮 digest 完全相同的字符串，初版运行器把“任何 tag”当额外共享引用，保守登记为 `shared`。下一版只把与已登记 digest 相同的别名视为本轮引用；真正其他 tag/digest 或其他容器引用仍不得删除。结果字段也应区分“保留/删除”，避免 `cacheReleased` 被误读成实测释放。

此外，本机 containerd image store 的 inspect `Size` 为 936,679,979 字节，但 image ls 显示占用 3.48 GB。不能把压缩内容大小当成镜像总体积。下一版对这个固定镜像在整轮保持 5 GiB 保守预留，并核对显示容量的上界，不在拉取后降低到压缩值。按 5 GiB 预留加本轮其余环境计算仍远低于 16 GiB 停止阈值，但原计量局限必须保留，不能宣称原采样准确计入全部镜像占用。

## 建议的下一段工作

1. 先经用户确认，受控重启一次 Docker Desktop，以释放仍持有本轮文件的虚拟机进程。当前同时运行的三个服务是 `opennerve-superbase-postgrest`、`agentforge-postgres`、`agentforge-redis`，均为 `unless-stopped`；后两项当前 healthy。它们会短暂中断，因此本次不能自行重启。
2. 重启前核对 daemon、全部六个容器的完整 ID/镜像/重启策略/运行和健康状态，以及旧虚拟机 PID/启动身份；任一状态变化即停止，额外发现停止但配置为 `always` 的容器也拒绝重启。重启后确认旧虚拟机退出、相同 daemon 和三个原服务恢复；原来 healthy 的 PostgreSQL、Redis 必须重新 healthy，必要时只启动已登记的原容器。最后核对全部容器集合与运行集合，另外三个停止的容器必须保持停止。不改 Docker 资源设置，不删除卷、镜像或其他项目。已准备只执行此维护步骤的脚本 `s4/restart-docker-reviewed01.py`；默认只读预检已通过，尚未使用执行参数。
3. 完整句柄检查恢复后，稳定导出并核对本轮未启动浏览器的原始台账/日志/源码与 SDK 证明，再显式解除 evidence hold，使用既有清理入口释放 scratch；无法证明时继续保留，不能补签为浏览器测试通过。
4. 在现有 P6 分支把 Linux 工作文件移到**本轮登记的 Docker 内部卷**：源码与工具链通过有界传输进入，依赖、浏览器资料及临时数据库文件留在 Linux 文件系统内，避免把数万个文件经宿主共享目录打开。使用容器内部的 init 负责回收子进程，替代 Docker 注入的 bind mount init。它是基于本轮映射证据的调整方向，是否解决仍须实际核验。
5. 扩展现有归属与证据传输回归，保持“生产者与 guest 已退出 → 导出有界证据 → 实际闭合本轮容器/卷”的顺序。先做小型完整格式/归属预检，修正上述镜像别名与计量，再继续同一 1+13 校准；任何新失败立即停止。

不修改 `lsof` 对未知映射、NOFD、格式损坏或真实引用的拒绝规则；不排除整个 PID，不换 GitHub VM 豁免，不启用 amd64 模拟，不恢复 Mac 浏览器、完整 Gate 或整套长测。版本、产品断言、超时、重试和最终验收要求保持。
