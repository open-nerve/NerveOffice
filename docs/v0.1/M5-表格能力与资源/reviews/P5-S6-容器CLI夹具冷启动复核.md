## 调查与局部修改

在受管小样例中给真实 CLI 的 `spawnSync` 加只记录命令类别、PID、时长和退出码的观测，不记录参数、环境或输出。原 build/env 两个故事分别串行调用模拟 Docker 50/45 次，等待约 1,809/1,387 ms，占真实 CLI 时长的约 89%/90%；多数调用只返回空列表。完整 coverage 下的精确调度延迟未逐次记录，不能把单次本机通过当作负载根因已被完全证明。

仅换用 Python 解释器的对照没有明显改善，已撤回。最终只把 `container ls`、`network ls`、`volume ls` 这三类固定空列表交给短 shell 子进程；其他分支仍 `exec` 原 Node 逻辑，保留真实 CLI、台账读取、构建前生产者 PID/标签/0600 校验及所有镜像操作。未减少真实 CLI 发出的调用，未替换清理实现。

所有调用先写入参数数量与 NUL 分隔的完整 argv，读取时核对数量与末尾分隔符；保留空字符串、换行及引号，不用 shell 文本拼接解释参数。`exec` 保持已登记生产者 PID。旧 PID/其他 UUID 和临时数据保留、只删本轮镜像、禁止全局 down、台账闭合等原断言保持，原 5 秒、CLI 15 秒、重试/跳过及并发配置均未改变。
