## 根因边界

唯一对应错误分支位于 `tools/test-resources/lifecycle.py` 的 `open_paths`：全局 lsof 命令和记录结构已通过检查，随后逐条 `Path.resolve()` 解析绝对路径，遇到 `OSError/RuntimeError/ValueError` 就统一停止。错误正文里的路径是本轮被检查根，**不是解析失败的候选路径**。日志没有异常类或 errno，不能断言实际为权限不足或特定宿主目录。sudo lsof 与普通 Python 的路径可见性不同是可能机制，循环链接也会触发相同分支。

方案 B 已明确允许固定托管 VM 在只读导出时记录语义未知并保留原环境；当前代码把后续别名解析未知仍当全局失败，遗漏了这一路径。原 `any(resolve(candidate) for candidate in {name, plain})` 还有集合顺序问题：一项失败可能提前阻断另一项的正向引用识别。

## 本次修复范围

- 仅已验证创建时 hosted 身份的非破坏导出允许记录外部路径解析未知；本机、未知宿主、旧台账和删除路径继续严格拒绝。
- 原文及去附注路径独立检查，词法命中、可解析别名及可解析前缀指向本轮根时，正向引用优先阻止导出。一个未知不能跳过同条其他候选或后续记录。
- 根身份和根自身解析、活动生产者、查询失败、记录结构损坏仍拒绝；不扩大 sudo 权限，不新增 PID 或协议豁免。
- 异常诊断仅保存有界类型、errno、PID/FD/type、候选字节数和摘要，不输出外部原路径或异常正文。原环境不移动、不删除，`absenceProven=false`、`rawDeletionAuthorized=false`。
