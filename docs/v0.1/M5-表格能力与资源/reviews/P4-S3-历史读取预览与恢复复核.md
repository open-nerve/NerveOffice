# P4-S3 历史读取、预览与恢复复核

2026-10-22；基线 S2 `974eef0e`；实现者自审。Step 实现与验证完成，Phase 独立审查仍在 S6。

## 实现与边界

- 历史列表、详情、原 gzip 正文只向当前有历史资格的编辑者开放；每次读取使用一个数据库快照和数据库时刻，分页固定 30 条。运维检查点不进入用户列表，也不授予图片读取权限。
- 历史图片从当前仍合法、未过期的小时历史取得资格。源移动、归档、撤权及历史失效后重新判定；保留关系与授权分开。
- 恢复在正文加载前限制全局 2、单账户 1 个任务；校验 gzip、格式信封、摘要、unitId 和 SDK 快照。写事务锁下复核当前资格、检查点身份与期限，再原样生成新平台文档、修订 1、图片关系和初始历史，审计同步提交。
- 原文档、租约、写入代次和原本机草稿不写。结果未知时沿同一 requestId 重试；先查已完成结果，再处理可能已失去访问资格的旧源。失败事务不能留下半份副本。
- 历史列表使用平台路由；预览使用独立 HTML 入口，只经公开 `createSheetEditor(access='read')` 创建实例。预览不启动草稿维护、outbox 或编辑会话；加载、可见性、会话消息及 30 秒可见周期复核资格，失败隐藏并销毁旧画布。晚回包不能重新挂载。
- 自检判定当前正文损坏时仍可进入历史；恢复使用旧历史原字节。未知格式禁用恢复；没有有效历史时明确说明，不能假造可恢复材料。

## 构建口径裁决

原有 180 KiB 平台、2350 KiB 编辑器和 800 KiB 公式 Worker 体积上限不变。新增独立预览后，平台合理共享分组由 2 个首屏文件变成 3 个，因此文件数上限调整为 3；不让预览引入平台草稿运行时来强合并分块。预览首屏仍为 2350 KiB，完整可达 JS 另限 3300 KiB；旧 SDK 约 1 MiB 的按需语言包原先也在编辑器闭包内，不应误用首屏上限衡量全部依赖。

`s3-history-ui-artifacts02` 实测：平台 179.8 KiB / 3 文件；编辑器 2141.6 KiB；预览首屏 2032.7 KiB、全部可达 JS 3059.6 KiB；公式 Worker 679.1 KiB。产物扫描和两类预算通过。保留自动分块，未采用实验性内联选项。证据与代价详见 [S3 规则 §8](../specs/P4-S3-历史读取预览与恢复.md)。
