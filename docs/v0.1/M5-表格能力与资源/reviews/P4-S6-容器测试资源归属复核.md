## 变更与原因

旧入口仅按 PID 名称清扫共享 Docker 的项目、镜像及临时目录，并在启动前强制 down；父运行器看不到 Docker 是否仍在运行。替身下真实 CLI 的 RED 确认会向未登记的其他 PID 项目发删除命令。本次移除这两处入口，以父运行器 UUID、创建前持久台账、源码根哈希标签与实际 daemon/对象核验代替；没有历史误删实证，不把这一机制风险写成已发生的数据损失。

新增 `container-e2e-resources.ts` 与父侧 `container_resources.py`。Node 在创建前登记意向、spawn 后登记真实进程组，只有全组和输出退出才释放生产者状态；父侧只接受精确未使用的 unclaimed 或实际查明不存在后的 closed。清理前及逐项操作前核对当前 daemon/标签，合法应用重建按最新 ID 处理，容器自动删除以成功列表核实；不 force、不清共享缓存/基础镜像、不重启 Docker。env 保持 0600，由父侧按原根/别名/句柄规则处理。

主密钥探针仍用原 60 秒和两个正常检查；超时即失败并停止后项，先按原 10 秒+2 秒组等待收尾，再允许本轮清理。异常 env 写入同样进入现有收尾。查询异常、身份变化、活动生产者或 Docker 删除失败时保留 pending 并禁止同类环境继续堆积。

正常报告携带同一次严格验证的完整无秘密台账原字节及其小型摘要。子 CLI 被强杀后，符合原退出/导出/发布锁条件时，只沿原 scope_move 原子搬迁链发布固定 JSON 的 diagnostic-only 包（有效台账附完整原件，损坏或未知字段输入不附原文），不导出 env/tmp/完整 Config.Env，不取得产品或 hosted 完成资格。严格策略的旧已启动未闭合样本保留待核；旧合法方案 B 历史委托记录字节不变、不补签。新协议在 hosted 完成验收和 sweep 快路径仍须核台账。
