# P4-S2 正式写入与删除前检查点复核

2026-10-22；基线 S1 `698c799c`；实现者自审，Phase 独立审查在 S6。

## 实现与接线清单

| 入口 | 捕获位置与边界 |
|---|---|
| DocumentCreationService.create | 新建私有行的正文、修订完成后；初始正文计入当小时，重放提前返回 |
| DocumentContentService.save | changed 分支当前正文/修订/合法图片关系完成后；unchanged 与两处重放均在之前返回，原保存事务总上界不变 |
| DocumentCopyService.copy | 新副本的当前原 gzip、合法图片关系、修订完成后；只建自己的初始历史 |
| DocumentConflictCopyService.copy | 新副本上传的正文、获权关系与修订完成后；不采到源的服务端旧正文 |
| TrashService.deleteDocument | 原空间/文档锁内，创建删除单元后、状态/代次/租约改变前；eventId 是删除单元 id |
| TrashService.deleteFolder | 已按 id 锁住全部活动文档后，目录/文档状态改变前；内部批量入口固定一次数据库时间，逐条等待，全部成功才继续 |

删除审计既有 trashEntryId 与检查点 eventId 对应；恢复后再次删除是新事件。永久删除只删除当前文档及独立小时占位，不删除未到期的检查点。图片保存的陌生/未知地址可以原样存正文，但不因历史生成获得引用。

## 自审结论与接续

没有 HTTP 契约或权限变化；新增持久化仍在 Documents 内，无跨模块反向依赖。采样异常不吞掉、不按环境缺口处理，真实库已证明业务/正文/引用/历史/占位/审计一起回滚。普通删除与批量删除沿既有锁，不增添倒序锁。

S3 尚未实现历史列表、读取、预览、恢复和历史图片授权；当前查看者不会因新保留关系而获得旧图读取权。S4 尚未开放清除/到期任务/升级前入口，S5 仍未启用物理 GC。容量测量、三浏览器、容器、独立阶段审查与最终 CI 留在相应后续步骤，不把 Step 结果当 Phase 完成交付。
