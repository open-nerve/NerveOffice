## 实现优点与关键判断

上传的资源预算位于真正耗资源的入口。准入先于正文读取，队列请求不会先积累整份图片；子进程时间预算包括启动，结果协议和成品摘要在父进程复核，结束等待 close 后才释放生命周期。Linux 通过实际 prlimit 启动并检查限制，没有只检查命令存在。见 [准入](../../../../apps/api/src/modules/assets/image-admission.ts#L25)、[上传](../../../../apps/api/src/modules/assets/asset-upload.service.ts#L48)、[子进程](../../../../apps/api/src/modules/assets/image-runner.ts#L120)。

处理器并非凭文件头或 metadata() 放行。容器解析后还完整解码成像素，再重新编码、重新完整解码并核对输出。GIF/WebP 的重复帧、原始时长与循环信息有专门处理和测试。未看到路径/URL/SVG 进入原生加载器的产品入口。见 [正式编解码](../../../../apps/api/src/modules/assets/image-codec.ts#L75)。

文件与数据库的故障状态可解释。先提交字节 claim，再写入同步后的私有对象，最后确认对象及独立 assetId；失败不会凭假定“文件不存在”释放额度。已有同摘要文件也重新检查大小/哈希/文件类型，不直接接受文件名。暂存清理依赖数据库会话锁，真实 SIGKILL 与连接丢失的测试覆盖了活跃暂存不被普通第二实例误删、失败后可恢复等情形。见 [文件发布](../../../../apps/api/src/modules/assets/file-storage.ts#L82)、[持久预留](../../../../apps/api/src/modules/assets/assets.repository.ts#L53)。

授权职责没有从文档域倒灌到存储层。读取通过一张只读一致性快照组合上传窗口与当前可读来源，随后才执行文件 IO；缓存/条件请求不能绕过本次授权。新增引用则先固定候选并锁定相关空间和文档，在锁下重新判断，再锁资源；当前正文与关系同事务落库。目标已有合法关系可保留，不会因原上传窗口过期而损坏正常编辑。见 [读取授权](../../../../apps/api/src/modules/workspace/asset-reading.service.ts#L31)、[引用锁与授权](../../../../apps/api/src/modules/documents/document-asset-references.ts#L77)、[保存事务](../../../../apps/api/src/modules/documents/document-content.service.ts#L182)。对照原有批量移动/删除和撤权时，文档锁也分别按 id 排序，未发现可成立的新增锁环。见 [文件夹内文档锁](../../../../apps/api/src/modules/documents/documents.repository.ts#L367)、[撤权锁](../../../../apps/api/src/modules/documents/edit-leases.repository.ts#L489)。

部署校验检查实际运行依赖，而不仅是构建工作区或 package.json。最终镜像有独立离线校验器、完整源码/许可材料和非 Web 目录；构建阶段与 prod-deps 阶段分别加载 Sharp。材料清单检查大小和摘要，分发目录拒绝额外文件、缺件和符号链接；真实部署还核对卷的挂载对象及其他服务无共享。见 [Docker 构建/最终校验](../../../../deploy/Dockerfile#L38)、[运行版本](../../../../tools/src/deploy/native-image-runtime.ts#L7)、[离线材料复核](../../../../tools/src/deploy/native-image-bundle.ts#L1)。
