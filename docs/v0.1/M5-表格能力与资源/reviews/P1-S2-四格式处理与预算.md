## 2. 样本与断言

正常样本涵盖RGBA/文本PNG、调色板、1×1最小图、带EXIF方向/受控GPS/ICC的JPEG、渐进JPEG、静态WebP、多帧GIF/WebP、重复WebP帧、0/10ms短时长、透明画布、无循环GIF、GIF交错与LZW字典增长。受控边界包含16M像素PNG/渐进JPEG/WebP、32M总画布的GIF/WebP。

拒绝样本涵盖四格式截断、PNG错误CRC/缺IEND、JPEG缺EOI及保留EOI的损坏数据、WebP正确容器但缺压缩像素、RIFF长度错误、GIF缺结尾/短像素流/缺LZW结束码、APNG、HTML/SVG伪装、声明类型不符、零尺寸、超边长、超单帧/总像素、超100帧、输入与输出超过5MiB。

成功断言包含实际宽高、方向、帧数/时延/循环、透明度、逐帧取样、适用样本的完整RGBA摘要、隐私元数据为空、输出大小与SHA-256。拒绝断言包含明确原因且没有成功文件。原生异常或超时不能被汇总成成功。

审核器另有8项测试：摘要/体积/路径逃逸/重复ID/缺预期/空矩阵/缺样本等反例。曾先以空实现得到8项RED，补校验后8项GREEN；Task2的语义试验同样保留最初失败。并未用导入错误或删除断言充当测试过程。

## 3. 查明的问题及处理

| 原始事实 | 根因与处理 | 保留证据 |
|---|---|---|
| 缺IEND、GIF结尾与短LZW数据可被库接受 | 原生loader有容错；补容器/CRC/LZW完整性，随后仍完整解码 | mac-01/02、library-tolerance.json |
| APNG变成单帧 | 不支持的动画变体静默降级；按明确规则拒绝 | mac-01及最终apng用例 |
| GIF循环2变成库metadata的3 | 文件重复次数与库总播放次数口径不同；用原文件字段核对 | mac-01/02、独立解码 |
| GIF颜色128被量化为129 | 候选effort3的量化变化；effort7保持当前受控样本像素 | mac-03、gif-palette-comparison.json |
| 50帧WebP变39帧；无损模式仍把重复4帧变3帧 | 动画优化器合帧；用原生库逐帧无损编码，按公开ANMF格式保留帧序 | linux-04、webp-comparison-01.json、mac-05 |
| 0/10ms动画时长被改为100ms | 解码metadata使用播放端最小时长；从文件取原值并在输出保留 | mac-05；最终zero-delay两例 |
| 透明动画的Pillow预期是黑背景，libvips是透明背景 | 生成器优化掉子帧alpha后未设置画布alpha标志，解码器解释不同；新样本显式标记RGBA，不改旧证据 | transparent-flag-comparison.json、mac-05-source |
| 16M WebP在1GiB地址空间下输出复查失败 | 同样输入和处理流程，在1536MiB成功；采用后者，仍有OS硬界限 | linux-04、webp-comparison-01.json |
| 完整32M动画触发临时文件写入，遇只读根失败 | 默认100MiB后可能转临时磁盘；256m阈值配有界像素/地址空间，仍在只读容器通过 | linux-05/06/07 |
| Linux首轮图片处理结束但汇总失败 | 运行用户不能读复制进去的600权限锁文件；只修候选镜像内文件权限并前置读取，旧轮仍失败 | linux-01日志/inspect；后续新轮 |

格式规则依据[GIF89a](https://www.w3.org/Graphics/GIF/spec-gif89a.txt)、[PNG规范](https://www.w3.org/TR/png/)和[WebP容器规范](https://developers.google.com/speed/webp/docs/riff_container)。磁盘阈值参考[libvips说明](https://www.libvips.org/API/8.17/func.get_disc_threshold.html)并在实际8.18.7验证。以上均是本项目诊断结论，未对上游提交issue或消息。

## 4. 资源实测与取值

最终Linux矩阵：512MiB容器内存（swap同值）、1CPU、64个PID、无网络、只读根、无core、drop全部capability、no-new-privileges；每图新Node进程，jitless、heap128MiB、semi16MiB、单libvips线程、关闭缓存、`prlimit --as=1536MiB`，5秒父进程期限。

`linux-07`：最大图片墙钟1,549.62ms；最大子进程maxRSS447,272KiB（约436.8MiB）；整容器cgroup峰值434,933,760字节（约414.8MiB），OOM/oom_kill均为0。共享页、计费与采样范围使RSS与cgroup不等值，不能相互替代。一次短矩阵不是长期性能承诺，5秒仍是最终拒绝边界。

输入/输出5MiB、单边8192、单帧16M、总画布32M、100帧沿用实测候选并定稿。生产调度固定一份执行、四份等待、每账户合计两份，排队10秒；这些生产准入与取消逻辑尚待S3测试，并非探针已经证明。

1536MiB是进程虚拟地址空间硬上限；512MiB是实验容器硬上限，后者不自动成为生产子进程上限。结合既有快照池默认预算，应用容器建议至少4GiB。macOS无同等硬地址空间保证，正式Linux启动不能因`prlimit`不可用而降级。

组织配额同时限定物理对象与asset行：默认10GiB / 100,000条。字节上限可设5MiB–1TiB，条数1–1,000,000；超额拒绝新增而不删旧数据。已发布但尚未完成数据库提交的对象要由持久预留计费，避免异常遗留绕过配额。具体契约和错误码见ADR；S3负责事务、存储故障与并发证明。
