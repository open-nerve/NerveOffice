# P6-S4 浏览器长测恢复建议

2026-11-02。当前只完成非浏览器准备，**尚未恢复真实浏览器、Docker、VM 或完整门禁**。本文件是待用户选择的执行方案，不是新环境已可用的证明，也不改变已有验收标准。

## 当前证据与具体困难

P5 full05 的 WindowServer 图形缓冲分配失败，发生在长时间浏览器测试期间；升级系统后同栈复发。已安装的会话保护能在桌面身份变化后停掉本轮，不能防止第一次崩溃。现有普通权限观测没有可靠的逐客户端 IOSurface 剩余量，磁盘空余、物理内存和 load 也不能替代该指标。原件及分析见 [P5 调查](P5-S6-WindowServer会话中断调查.md)与[图形路径复核](P5-S6-桌面会话保护与图形路径复核.md)。

本轮只读快照 `.codex/handoffs/m5-p6-20261102/s4/host-readonly01.json` 表明：内核仍从 10 月 25 日启动，WindowServer/loginwindow 仍为本日 06:58:19 那一轮；磁盘约 94.54 GiB 可用，系统 memory free percentage 91%、swap 0。Docker daemon 当前未运行。这些只是环境事实，不能证明图形泄漏已解除；本轮没有启动 Docker，也没有创建或删除数据库。

本机为 arm64；实际安装 Playwright 1.63.0 的 `bin/reinstall_chrome_stable_linux.sh` 明确在 aarch64 退出并报告不支持。因此首段只以原生 Linux arm64 的随附 Chromium 校准，不把它写成 Chrome/Edge 可用，不直接启用 amd64 模拟。完整 Linux 浏览器矩阵需要另有原生 x64 执行证据，最终 CI 条件保持。

S2 的生命周期修复已过 11,959 项全单元；S3 请求观察的辅助单元与静态准备可继续，但浏览器校准和图片/链接故事必须实际执行才能关闭。P5→P6 的节奏批准只改变集中验收时机，没有解除本次事故的长测暂停。

## 推荐：先建立隔离的 Linux 浏览器执行路径

让长时间 Playwright 浏览器进程和画面采集运行在 Docker 的 Linux 环境内，避免这一工作负载继续直接使用本机 WindowServer。复用既有 Docker Desktop，不再复制整台 macOS VM 或几十 GB 磁盘。Linux 运行仍消耗本机 CPU、内存与磁盘，不能宣称整个宿主风险为零。

拟批准的第一段工作有明确边界：

1. 恢复 Docker 服务后，只读核对已有容器/镜像、daemon 与容量；不重启或清扫其他项目。旧专用数据库不据名称认领，身份无法对应则保留，不向未知数据库执行测试。
2. 在当前 P6 分支准备独立 Linux arm64 测试运行器，固定当前锁文件、Node 24.21.0/pnpm 12.6.0、Playwright 1.63.0 及其随附 Chromium，使用 Ubuntu 24.04、本轮源码副本与独立数据库。源码/实际 SDK 字节证明要重新生成，不套用 P5 旧工作区的固定脚本。若这些依赖无法按原约束安装，停止并说明，不能改版本或转模拟架构凑结果。
3. 接入现有测试资源生命周期：创建前登记本轮 UUID、daemon/容器/卷/网络/目录身份；复用已有的归属与闭合校验，只删除自己创建的资源。本机仍按严格清理，不使用 GitHub VM 的 `host-disposal-pending` 豁免。镜像缓存与本轮环境分别登记，不删除共享镜像或全局 builder cache。
4. 先用 KiB 级模拟核对正常、失败、中断、重复清理、活动资源隔离；再只运行 Chromium 的 S3 localhost 请求观察校准一条。校准通过后，同一项目选择 `image-input`、`image-policy`、`links`、`paste-images` 四文件并用 `--grep=US-M5-14` 执行其余 13 条，合计 14 条，结束即复核证据。S2 selftest 的真实恢复验证在下一份清单列明，不把它隐含扩成整套 29 场景。重型负载串行、一个项目和一个 worker；原断言、超时、重试及 trace/截图配置不变。
5. 每轮核对空间、进程/句柄、容器闭合及报告；产品失败、清理失败或会话异常立即停止，不自动重试。本机继续保留至少 12 GiB 空间；为新增隔离环境另设 16 GiB 停止阈值并计量，达到阈值作中断而非验收通过，允许采样与退出等待期间超调。成功释放临时环境；失败只保留原规则允许的有界报告和诊断，不保存完整 VM/数据库副本。

**这一段不自动恢复本机浏览器或数千条完整长测。** 先提交可复核的 Linux 运行器与小范围真实结果，再依据实际证明确定集中验收的执行清单。原默认完整 Gate、生产容器、Chromium/Chrome/WebKit 与最终同 SHA CI（含 Edge）仍全部欠账；新的运行器不能把这些记作通过。

Linux WebKit 也不等于 macOS Safari。Mac 原生待验事项继续按既有登记保留；若最终需要把原本机全量验证改为“Linux 全量 + Mac 定向兼容验证”，须明确列出平台差异与所需裁决，不能在此悄悄替换。当前批准仅用于建立隔离路径与小规模校准，原完整验收要求保持。

## 另一个可行选择：本机先做有界小范围复验

沿原本机配置，恢复专用测试数据库，先以一个 worker、单个 Chromium 项目执行 S3 localhost 对照，再执行图片来源故事；每条原 timeout 与 trace 都保持，失败即停。通过后先审阅宿主与清理证据，再决定 Chrome/WebKit 和 selftest 的范围。这个选择准备更少，但仍直接使用当前桌面图形会话，无法保证不再次触发首次崩溃，也不能据一轮短测通过就自动批准长测。

不建议现在继续消耗用户桌面来取得更多同类型崩溃样本。推荐先做上述 Linux 隔离路径；如果环境准备出现实际依赖或成本明显超出这份范围，再给出具体断点，不能不断下载镜像或复制环境试错。

## 决策依据

项目 `CLAUDE.md`“推进节奏与决策边界”要求跨模块协同调整和意料之外高风险发现先提交、再等用户决策；事故调查已经将恢复真实浏览器排除在上一轮授权之外。隔离运行器牵涉测试入口与资源归属，继续本机复验又会恢复已暂停的风险动作，因此在 S3 静态准备和本方案保存后交用户选择。无需用户提供密码或手动执行脚本。
