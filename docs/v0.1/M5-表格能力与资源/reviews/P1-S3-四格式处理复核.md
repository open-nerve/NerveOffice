# P1-S3 正式四格式处理复核

> 2026-10-18；S3 Task 4 实现者自审与独立解码核对。不是 Phase 独立代码审查，也不代表上传接口、生产调度或 P1 已验收。

## 实现与检查范围

正式代码位于 `apps/api/src/modules/assets/`，未从 `spikes` 搬运处理实现。复用 S2 自有样本的固定字节与独立 Pillow 预期，清单记录来源、摘要和生成版本。主要路径：

- 文件头、MIME、后缀一致；所有容器读取先核对长度。PNG 检查块顺序、CRC、IEND，拒绝 APNG；JPEG 检查标记、扫描边界和 EOI，再完整解码；WebP 检查 RIFF/帧/画布及声明一致。
- GIF 检查块、帧范围、调色板索引；LZW 仅计算字典词长、首索引和最大索引，核对精确像素数量、完整结束码和字典增长。帧合成仍由原生库完成。需要用户输入或字形渲染的扩展明确拒绝，不能静默丢掉渲染语义。
- Sharp 只开放 PNG/JPEG/WebP/GIF Buffer loader。完整解码为 RGBA，应用方向、转为 sRGB，再从新像素重新编码；输出完整解码核对尺寸、帧数、原始动画时间/循环和元数据。PNG/WebP 还核对完整 RGBA 字节相同。
- 动画 WebP 逐帧无损编码后封装完整画布，保留重复帧和原始 24-bit 毫秒值。GIF 写回原始 GCE 时间及文件中的额外重复次数；“无循环扩展”、无限循环和最大重复次数分别核对。
- 输入拒绝与内部编码/复核失败分开；不通过原生错误字串推断 OOM。输出超限返回 `output`；超过内部有界输入接口的字节调用直接拒绝，由 HTTP 入口映射 413。

只有 `image-codec.ts` 导入 Sharp，尚无生产调用入口。构建产物不包含测试图片或测试辅助。后续 Task 5 负责加载它的一次性进程及硬限制，Task 6 才启用上传。

规范依据：[PNG](https://www.w3.org/TR/png-3/)、[GIF89a](https://www.w3.org/Graphics/GIF/spec-gif89a.txt)、[WebP RIFF/ANMF](https://developers.google.com/speed/webp/docs/riff_container)、[Sharp loader 控制](https://sharp.pixelplumbing.com/api-utility/)。具体 API 同时核对已安装 0.35.5 的类型与源码。

本机 assets 定向测试 **97 项通过**：原有协议/存储 41 项，处理器 37 项，容器与语义边界 19 项。四种正常样本在任一字节截断、尾随字节/第二份文件、PNG 重复头/错误顺序、GIF 100/101 帧和最大时长/循环、WebP 最大原始时长等均有回归。api 类型、lint 和正式构建通过。

同一实现的全仓单元回归 `pnpm test`：497 个文件、**10,029 项通过**（65.81 秒），原始日志 `task4-unit-all-01.log`。未把尚未执行的集成、端到端或完整门禁计入。

Linux ARM64 使用正式 `nest build`/contracts 构建输出，原生依赖与 S2 固定版本一致；没有调用 S2 处理器。44 个固定样本逐个新进程：`--jitless`、老生代 128 MiB、半区 16 MiB、`prlimit --as=1610612736:1610612736`。每例读取 `/proc/self/limits` 确认硬限制；父进程从启动到退出限时 5 秒。环境只传 ADR 三项原生变量。容器 512 MiB、1 CPU、无网络、只读根、去除 capabilities。

## 发现与处置

1. 首次 RED 为新模块缺失。初轮正式预期误把 CRC 正确但宽度为零的样本映射为 `corrupt`；查生成器及固定字节后，将正式预期细化为 `dimensions`，保留 S2 原 `invalid` 字段和原件。
2. 补充测试发现 Node 的 ASCII 解码忽略高位。文件仍会在原生解码时被拒绝，但不满足严格文件头分类；改为按 Latin-1 的原字节值比较，两个 RED 案例转绿。
3. Linux 第一轮运行器直接加载 TypeScript，在 `--jitless` 下因 Node 类型剥离所需 WebAssembly 不可用而于加载阶段退出；没有开始图片处理。第二轮改用项目正式编译产物，不减少任何限制。首轮失败原件仍保留。
4. lint 的通用 `.raw` 禁令针对 SQL；仅在四处 Sharp RGBA 调用旁加明确局部说明，不修改全局 SQL 规则。
