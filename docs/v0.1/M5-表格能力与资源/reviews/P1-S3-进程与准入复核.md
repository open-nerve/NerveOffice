# P1-S3 进程与准入复核

> 2026-10-18；S3 Task 5 实现者自审与受限 Linux 实测。不是 Phase 独立代码审查，也不代表上传接口或 P1 已验收。

## 实现边界

`ImageAdmission` 在执行回调、读取正文之前取得名额：同时执行 1 份、等待 4 份，每账户合计最多 2 份；FIFO 等待最多 10 秒。等待取消立即腾出位置，运行中的位置要等整条回调结束才释放，不能在子进程仍运行时提前放行。关闭拒绝新增与等待；上传服务负责把关闭信号传到在途正文和 runner。

`ImageRunner` 每份任务新建一个进程，不复用；启动、加载原生库、处理共享 5 秒 deadline。只有进程关闭且 stdio 回收后才交付结果或错误。启动探针执行同一个正式编译 JS 入口，确认 Linux 地址空间软/硬限制都是 1536 MiB；prlimit 缺失、失败或没有实际设限均拒绝初始化。jitless、堆 128 MiB、半区 16 MiB、三个原生环境变量沿用 ADR-021。

采用独立 runner：现有 SnapshotInspector 的共享池具有进程复用及不同的启动/任务时限和释放时机，直接扩展会增加两套生命周期的耦合。本次不修改共享池，保留其回归。只有一次性子进程入口导入 codec；父进程重新校验协议、字节、摘要和尺寸预算。stderr 有界保留用于识别明确的 V8 堆失败，随后丢弃，不进入客户端、普通日志或 Error cause。普通退出、SIGKILL 和包含内存字样的普通错误不能推断为 OOM。

父进程退出后，子进程通过 IPC disconnect 自行退出。结果、取消和超时路径都等待回收；单次启动失败后不会降级到无约束进程。HTTP 接入仍在 Task 6，当前没有正式上传入口。

## 验证证据

本机新增准入 7 项、真实子进程 20 项；与已有 assets、共享池及快照进程回归合计 **8 个文件、187 项通过**（6.91 秒）。包含新 PID、环境隔离、总时限、挂起/退出/断连/坏协议/堆失败后恢复、取消、关闭、杀父进程后无孤儿。API 类型、assets lint 和正式构建通过。

macOS 会给 `env: {}` 的裸 Node 子进程注入 `__CF_USER_TEXT_ENCODING`；独立空环境对照已确认。测试仅容许该系统字段的限定形式，仍严格核对三个主动传入字段，秘密和 `NODE_OPTIONS` 不得继承。Linux 环境不放宽。

Linux ARM64 运行正式构建的 runner 与 codec，容器为 512 MiB / 1 CPU、无网络、只读根、去除 capabilities，逐任务检查回收及下一次处理恢复：

故障包含真实 V8 堆耗尽与受限子进程尝试 2 GiB 原生分配；后者验证地址空间限制确实拒绝分配，不以普通原生错误文本推断正式 codec 的失败原因。本轮未采集独立 child RSS，也不是原生 x64 性能验收。512 MiB 是实验容器边界，不能代替生产 1536 MiB 地址空间预算或整服务内存预算。

## 首轮未完成及修正

首轮 Linux 驱动的矩阵和前 11 个故障场景通过，但最终主动断开真实 child 的测试等待未结束，进程以 13 退出；这一轮没有被记为整体通过。独立诊断确认 child 收到 disconnect、以 0 退出且 PID 已不存在，驱动主动调用 `disconnect()` 后没有收到自己等待的 `close`。Node 24.21.0 的主动断开路径关闭 IPC 并发 disconnect，与读端 EOF 的 close 计数路径不同。

直接断连驱动改为等待 `exit`，同时核对退出码为 0 和 PID 消失；该驱动的 stdio 均为 ignore。正式 runner 不主动调用 disconnect，仍等待完整 `close`，没有降低回收标准。新增子进程主动断连单元回归后重跑完整矩阵，得到上表结果。首轮失败和两种 stdio 的诊断原件保留于 `runner-linux-01/`、`runner-disconnect-debug-01.log`。

Task 6 的持久配额、崩溃残留临时文件收尾、原始请求体和服务关闭集成继续实施；生产镜像源码分发、x64 实测及 Phase 独立审查/完整门禁在 S6 保持未完成。P2 三项原生补证、DEF-004 与 M4 的 DEF-073 状态不变。
