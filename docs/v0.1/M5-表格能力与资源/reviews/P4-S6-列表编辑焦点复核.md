## 问题与修改

旧 CI `40994784729` 的列表非法输入故事首次失败、重试通过，仍按 flaky 保留。真实组件链与本机被动观察证实：编辑联动显示的列表搜索框同时经 React autoFocus 和零延时 timer 自动取焦，与单元格编辑器竞争。旧包单次原 Chromium 故事执行完全部业务断言后，被新增的焦点断言挡住；red 窗在 8/17 ms、cyan 窗在 8 ms 收到搜索取焦。这证明焦点竞争，不能冒称重演了远端 CI 的完整字符分流时序。

`sheets-data-validation-ui` 在 LIST/MULTIPLE_LIST 传入 `autoFocusSearch: param.trigger !== 'editor-bridge'`；`sheets-ui` 沿 ListDropDown 传到 SelectList，缺省 true。React 与 timer 使用同一策略，隐藏搜索、策略切换或卸载会取消本实例 timer。用户主动打开列表、主动进入搜索、过滤、单选/多选与关闭语义保持。没有修改 EditorContainer、全局焦点、校验、命令或保存算法。

两包仍为 1.0.1，通过原 pnpm patch/patch-commit/install 交付 ES/CJS 与 sheets-ui 可选属性声明。旧数据验证面板 27 个 hunk、表名选择 2 个 hunk 的正文全部保留；锁文件只替换两个 patch 摘要，workspace 映射不变。具体摘要与升级移除条件见两份补丁登记和 ADR-010。
