# P3-S6 链接旧弹层覆盖正文调查

2026-10-22。**产品缺陷已在自制样本复现，待用户确认局部修复方向。P3 不关闭，P4 不开始。** 调查未修改产品、SDK 补丁或正式测试；主目录 main/远端为 `974f7f278c2d01c578d78d433b7ca3f84288c479`，唯一 P3 分支的产品输入为 `49f77af17a7ed43c139b20d68a2ca4014fd39dd0`。

## 已确认的事实

第二轮 [CI 39692841654](https://github.com/open-nerve/NerveOffice/actions/runs/39692841654) 的 verify、container、Chromium、Chrome、Edge 成功；WebKit 失败。首次在更新链接时走 `update-hyper-link`，既有重试在取消时走 `cancel-hyper-link`，而故事要求活动 Docs 的 rich 命令。两次均已越过全选、K 和 add-rich；不能把整个故事称为修复完成。

运行随后达到 GitHub 步骤 75 分钟限时。浏览器尚未退出，持久资料仍在改写，tar 报 `file changed as we read it`，上传报 ENOENT。已收集六份日志、验摘要的五个可用报告；WebKit 的 JSON/HTML/trace 没有上传成功，证据缺口明确保留。上一轮完整 WebKit 约 69 分钟，整体时间预算和停止顺序也需要修正。

本机使用原正式宿主、真实后端、独占测试库和持久 WebKit，以复制的故事加公开 Facade 只读观察，进行了三组对照。没有修改命令参数、强行设定 popup 类型或直接调用替代命令；样本全部为本任务创建。

| 对照 | 结果 | 可以证明的范围 |
|---|---|---|
| 原完整故事加只读记录，重复 3 次、无重试 | 3/3 首次通过 | 实际 add/update/cancel rich 路径、非法命令负例、历史及重开在这三次成立；不证明 Linux 稳定 |
| 先悬停显示普通菜单，再双击进入正文编辑，立即用原更新表单 | 失败，实际普通 update | 已进入 Docs 的情况下仍可点击旧 viewing 菜单，重现 CI 同类路由失败 |
| 中间子串有链接，进入编辑后在链接外新增前文，再点击残留菜单取消链接 | 失败，新增文字被覆盖 | 是活动正文的真实变化，不只是命令名称不符合测试预期 |

第三组先用真实富文本表单给“前文富文本资料后文”的中间五字加链接，保存后核对范围为 2..6。随后通过键盘在最前面输入“新增”；点击取消之前，正文确为“新增前文富文本资料后文”，链接范围已正确移动到 4..8。

| 页面时间 | 实际状态 |
|---|---|
| 6287 ms | `isCellEditing() === true`；活动 Docs 正文包含“新增”；鼠标位置命中 Docs 画布 |
| 6355 ms | 残留菜单派发普通 `sheets.command.cancel-hyper-link`；此时活动正文仍包含“新增” |
| 6376 ms | 仍在编辑；正文变回“前文富文本资料后文”，链接范围清空；保护“新增”文字的断言失败 |

普通命令读取工作表已提交的内容并写回单元格，随后刷新活动 Docs；rich 命令应当修改正在编辑的 Docs 模型。当前安装包根据弹层的 `type` 选分支；进入编辑时没有立即撤掉 viewing 弹层，工作表和 Docs 的 hover 又分别延迟 200 ms，因而出现可达的旧菜单窗口。

**证据限制：**正文覆盖已在 macOS WebKit 证明；Linux CI 只保留了命令路由失败日志，还未完成同一最小场景复现。第三组在内存正文断言处失败，后续保存、重开、撤销尚未执行，不能声称已证明云端永久丢失或不可恢复。没有使用用户真实文档。

独立审查者随后逐项复核三组原件、观察代码与实际安装的 SDK，增量结论为 **Critical 1 / Important 0 / Minor 0**。审查确认覆盖结果由后置正文和真实失败断言证明，不能只依据 BeforeCommandExecute 事件推断命令成功；同时要求修复守卫覆盖延迟 hover 的显示和隐藏两种副作用。本次审查确认缺陷与方案边界，尚不构成修复验收。

## 建议修复及验收

建议保持 P3 既定链接能力，在同一分支修复固定 SDK 的弹层生命周期：

1. 从工作表进入正文编辑时，立即撤销旧 viewing 弹层，保证过期按钮不能继续操作已提交模型。
2. 工作表的延迟 hover 回调在执行时重新检查编辑状态；已进入 Docs 时不能重新显示 viewing 弹层，也不能错误关闭新 editing 弹层。退出编辑、取消、销毁与正常普通链接菜单仍按真实上下文工作。
3. 保留普通和 rich 的精确命令断言。补真实 controller 的状态/延迟/销毁回归，以及“预先出现旧菜单”“链接外有未提交前后文”的 UI 对照；覆盖更新、取消、撤销/重做、保存与重开。不得靠等待旧菜单自然消失、接受任意命令或删除断言放行。
4. 同时处理独立的 CI 整体限时：由 Playwright 先结束并生成报告，外层另留关闭、归档与上传余量；真实中断对照必须验证进程退出和归档稳定。单例标准、重试和浏览器范围不变。
5. 局部红绿对照、独立复核及最终输入完整门禁通过后，再正常提交、no-ff/main、同 SHA 六项 CI、冻结清理。当前 full04/container02 保留为历史结果，不替代修改后的复验。

拟改动限定在现有 SDK 补丁/登记、相关测试和 CI 时间预算，没有数据库、快照格式或保存协议调整。暂不开放下一 Phase，也不将此产品缺陷登记为环境延期。

项目 [CLAUDE.md](../../../../CLAUDE.md) 对“意料之外的高风险发现”要求“先提交当前工作，再用大白话汇总问题和建议方案，等用户决策”。本次已证明未提交文字被覆盖，故先提交此证据与方案，确认后再改产品。
