# P2-S2 图片实例与可靠渲染复核

> 日期：2026-10-19｜状态：S2 实现、独立代码审查、三浏览器与最终冷安装复验通过；正式入口和完整 Phase 验收仍按后续 Step 执行。

## 实现与边界

每个编辑器实例持有自己的图片读取、解码、临时 URL 和 SDK 元素登记。固定页面所有者及原会话对象贯穿请求；普通失败本代只报告一次并显示本地占位，下载失败仍拒绝。刷新、暂停、销毁先清旧元素和 URL；取消及时结束等待，底层晚完成也回收，不等待主线程公式退出。

实际 SDK 两个图片服务均由平台实现，覆盖浮图、单元格富文本、IMAGE、插入量尺寸、已有图元更新及下载。模型、撤销和保存只保留规范资源地址。八份 1.0.1 的 pnpm 补丁由锁文件固定，修改点、摘要和移除条件见 [ADR-022](../../../adr/ADR-022-图片实例与SDK修复.md)及 `patches/univer-images.json`；只读参考源码与 `node_modules` 未手工改写。

发布包的修复包括坏图绘制边界、Position 自动行高锚点、Ready 取消、共享图片元素换源，以及 IMAGE 的鉴权量尺寸、重开补算和失败恢复。普通画布异常及非取消错误继续报告。页面权限只驱动图片许可与重读，没有增加正文保存通道。

## 独立审查与修正

独立同模型审查者只读核对了设计基线 `f002708c` 之后的全部生产改动、测试、八份补丁及实际安装的 ES 调用点，未运行测试或改文件。两项 Important、后续浏览器发现及账户分块最终差异均已逐项复核；没有剩余 Critical/Important/Minor 可行动问题。

1. **旧权限响应重新授权。** 详情和阅读状态的旧成功原先会越过另一来源的新 404；资源若仍由别的可读文档授权，就可能重新显示旧图。双向 deferred 反例先失败；修复在请求开始记录共享许可代次，拒绝过时成功。额外反例确保实际拒绝不被并发成功掩盖。证据：`task4-permissions-race-red-01/02.log`、`task4-unit-06.log`。
2. **IMAGE 恢复沿用占位几何。** 真实竖图首次失败后恢复为横向 `76×52`，重新打开为 `52×76`；仅验证图片出现不足以验收。控制器改为采用当前有效原件尺寸，无原件时由受管元素等待有效解码。服务返回后撤回、新缓存恰在测量后到达也有反例。证据：`browser-18/`、`task4-formula-geometry-red-01/02.log`；最终 `browser-24/` 三引擎通过。
3. **迟到的 401 会话通知阻断明确重试。** `browser-22/` 为 53 通过/1 WebKit 失败：session-stopped 晚于本人复核，清掉图片身份，详情成功随后只清提示而不发请求。明确重试现在先经既有会话复核恢复缺失身份，再查权限；本人、断网、换人及合并复核先成功后失败共四个时序先 RED 后 GREEN。错误提示仅在实际图片许可激活后清除；stopped 本身不触发复核，持续 401 不循环。`browser-23/24/` 通过。

单元最终运行还暴露既有交接测试在真实 gzip/摘要完成前就检查 handOver。两处等待改为原业务状态成立后的 vi.waitFor，产品逻辑、时限和断言未放宽；3,565 项最终全绿。

## 首页预算收尾

最终生产门禁发现首页 184,360 字节，超过原 184,320 字节预算 40 字节。与 P1 冻结模块清单比较，没有新增首屏模块；唯一源码变化是 S1 请求层必要的 cache/redirect 选项。保留请求约束和原预算，将邀请、重置、改密三个独立账户页沿现有模式改为路由按需加载，路径判定迁到 shared，公开页补中性加载提示和既有分块错误恢复。

三条行为反例先 RED 后 GREEN；真实分块延迟期间保留 hash、零令牌核对，加载完成才由原页面接管；实际下载失败保持 hash、给出重试按钮、不核对令牌。60 项三引擎账户流程通过。失败故事未点击重试，不扩大为“已证明失败分块在 WebKit 重载后一定可恢复”；沿用的整页重载与既有浏览器缓存边界保持。最终首页 **178.7/180 KiB**；编辑器、公式 Worker、草稿 Worker 原预算均通过。

同时记录两项实际 SDK 行为：`FOverGridImage` 是快照，移动/缩放后须重新获取；其 `setSource` 会先改持有模型，不能用于平台正式换源。当前换源验证经过 `sheet.command.set-sheet-image` 和独立 payload，S4/S5 沿此封装，不声称修好了该 Facade。
