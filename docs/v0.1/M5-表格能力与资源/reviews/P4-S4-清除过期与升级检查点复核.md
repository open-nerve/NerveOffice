# P4-S4 清除、过期与升级检查点复核

2026-10-22 开始，2026-10-23 完成验证；基线 S3 `a115822e`；实现者自审。Step 验证通过，Phase 独立审查仍在 S6。

## 实现与边界

- 管理员清除只删除本源 hourly 历史；资格与所在空间在锁下重查，审计同事务，当前正文、租约、小时占位、保存回执、运维检查点和副本保留。列表的 canClearHistory 来自同一权限快照。
- 复用懒加载确认窗。未知清除结果禁用本次确认的重试；核对成功刷新的列表并重新确认后才能再次删除。服务器成功而刷新失败时仍准确提示已清除数量，不把旧缓存当作未成功。
- history-purge 使用现有调度器、数据库时钟和事务级独占锁；7/30 天精确到期、分批 SKIP LOCKED、退出接续、审计失败整批回滚。仍有对应历史的旧桶保留，图片文件与配额不在本任务中删除。
- 升级命令由独立 DocumentsOperationsModule 和 app 上下文组合，无 HTTP、Jobs、图片/快照子进程；模块边界仅放行该运维组合。prepare 先排空在途源写，原子建立完整清单与持久冻结。
- 四类源表在数据库 statement BEFORE 触发器统一守卫；零行语句和 TRUNCATE 也不能绕过。try 共享 advisory lock 避免拿业务锁反向等全局锁；屏障 FOR SHARE 阻止旧 RR 快照绕过，序列化失败转为确定回滚的 55P03。仅 writeEpoch、位置/权限状态更新仍可用。
- resume 只在短批内复制 S1 原 gzip/信封/图片关系；检查点和回执一起提交。ready 仍冻结；release 要重新证明本批、本源、原修订及未过期。先锁 CP 再写回执，与到期清扫 FK SET NULL 同序；完成审计等待后再按新时刻核对，防止期间到期却仍提交解冻。
- SIGTERM/SIGINT 完成当前短批后退出非零，强制结束回滚当前批；已完成短批可由新进程接续。结果未知先 status，不能盲目再 prepare；旧 release/abort 不会解除新批次冻结。abort 不声称完整，已生成运维检查点仍保留三十天。
- 新增 0031–0034 向前迁移，旧迁移不改。sourceCount、完成状态和有限失败原因有数据库约束；I26–I28 扫描清单计数、回执归属和冻结状态，每条有真实阳性对照。
