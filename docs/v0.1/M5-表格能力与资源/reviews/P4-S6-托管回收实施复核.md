## 背景与边界

CI 40600596503 的六个 job 都在产品测试开始前被全宿主 lsof 的不可解析记录阻止。用户已批准方案 B：本机继续严格回收；固定一次性 GitHub VM 可以在身份、生产者退出、已知引用、报告稳定性及预算核验后，把原环境交给平台生命周期处置。旧失败记录、full12/container02 与冻结 v2 证明保持原状，不为新代码签发最终通过。

实现沿用唯一 P4 worktree，主目录保持 main。没有修改产品功能、测试范围、断言、重试次数、浏览器支持或本机删除授权。

## 复核范围

- `hosted.py` 核对固定托管上下文、创建前归属及同 job 预算；`lifecycle.py`、`run.py` 将产品结果与 `host-disposal-pending` 分开，原 scratch 不移动、不精简、不删除。
- `stable_reports.py` 只复制必要报告、有效 OPFS 及有界诊断，重算字节和摘要；导出失败保留原环境。现有发布入口只发布新建的便携副本。
- `check_ci_resources.py` 持锁核验唯一预检与主测试；覆盖率进入 integration 的本轮报告目录。CI 上传携带两轮实际清单，失败报告仍保留失败的产品结论。
- `pack_ci_profiles.py` 在本轮 reports 下登记运输目录，使用固定 tar/zstd 管线，只接受与原清单一致的成员、类型、大小和摘要。未知或仍被使用的目录不删除；失败仅移除确认归属的 partial。
- AGENTS、测试资源规范及 ADR-024 明确本机与托管平台的不同处置责任，平台销毁没有被描述为已独立观测的删除结果。
