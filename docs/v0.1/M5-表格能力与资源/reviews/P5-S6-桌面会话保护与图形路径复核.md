## 保护实际接入

正式资源入口 `tools/test-resources/run.py` 和外部 P5 `s6/gate_helpers.py` 复用只读 `SessionGuard`。macOS 浏览器相关入口固定绑定 console 用户、系统 WindowServer 和当前用户 loginwindow 的身份；正常前置、登记后尚未释放命令的屏障、运行中及结束时分别核对。身份改变或读取失败时记录中断，只沿本轮仍存活首进程的进程组处理退出，不能自动采纳新桌面为基线。

内层保留原命令退出码和实际清理结果；即使命令处理退出信号后返回 0，也不能把本轮记为通过。外层会话失效记录 `needs-attention`，阻止直接再次创建完整门禁；首进程已退出时不凭组号发送信号。非 macOS 与非浏览器类型记 `not-applicable`，原 CI 浏览器范围与产品断言不变。具体采样、查询上限和清理语义见[资源规范](../../../testing/test-resource-lifecycle.md)。

保护不提供图形资源的预警阈值，也不保证监测器在强制会话结束后仍能运行。它解决的是“已发生异常仍继续跑、或把同时返回 0 的命令算通过”的错误；首次 IOSurface 分配失败的根因仍须定位。

## 只读图形路径发现

核对实际安装的 Playwright **1.63.0** 源码：项目 `trace: 'retain-on-failure'` 在每条测试中录制，成功后才丢弃；默认 trace 的 `screenshots=true` 会转为 screencast，WebKit 路径使用 `Screencast.startScreencast`、停止和逐帧 ACK 协议。因此“只保留失败报告”不等于“成功测试没有画面采集”。这与官方 trace 模式说明一致：[Playwright recording options](https://github.com/microsoft/playwright/blob/main/docs/src/test-use-options-js.md)。

实际源码的文件摘要、行号与完整配置关系保存为 `readonly-code-path01.json`。该事实提供了有价值的对照方向，但当前只追到 Playwright 的录制协议，**没有追到导致 WindowServer 中止的原生调用客户端**；也没有证明资源跨测试泄漏，不能宣称关闭 trace 就能解决。原 trace、截图与验收断言均未修改。

本机普通权限可以取得进程身份和 IOSurfaceRoot 客户端登记；本次没有取得可校准的 IOSurface 分配余量或逐进程分配计数。`vmmap -summary 29055` 返回 255，明确拒绝读取 WindowServer 的内存映射；未尝试 sudo、改变权限或终止其他应用。客户端登记数量不是图形缓冲数量，当前健康快照更不能解释 06:58 的历史泄漏。
