# P2-S5 正式图片入口复核

> 状态：2026-10-20，S5 实现、缺陷修复及最终串行检查通过；独立第八轮复核确认本 Step 剩余 Critical 0 / Important 0 / Minor 0，提交后接续 S6。P2 完整门禁、生产容器、合并与 CI 尚未验收。

## 已实现的产品路径

普通表格页面在工作簿 Ready 后安装生产图片输入组合；现有“插入 → 图片 → 浮动图片 / 单元格图片”菜单直接进入平台文件选择和上传任务，不依赖测试 URL 或控制面板。两个 SDK 普通命令由实例桥接接管，取消、拒绝和失败不回落旧上传实现；显式文件参数只接受真实 File。菜单与低层入口仅在输入安装成功后放行，退役时先关闭并取消任务，再等待公式退出。

测试模块只添加可选的面板与记录器，复用同一输入对象。背景图、文字文档插图、旧图片下载和超链接继续保持既定关闭状态；本 Step 不修改 SDK 版本、图片协议、快照格式或数据库。

## 发现与修正

1. 正式浮图保存重开时，SDK 会补入 angle/skewX/skewY/flipX/flipY 五个默认值，导致无改动的再次保存产生修订。实际 API 快照差异保存在 `float-reopen-diff.json`；创建浮图时写全这些默认值，真实命令反例先失败后通过，保存相等断言保持。
2. 独立审查 I1 发现普通表格离线复制、剪切及表格粘贴在分类前被图片联网条件拒绝。现在普通剪贴板目标保留 SDK 权限、身份通知、焦点、书/表/选区约束；确认图片后才不可逆升级为严格图片条件。文件选择、拖放及纯图片粘贴始终严格；无图片复制/剪切继续原 SDK，表格预览不读取也不上传。身份或选区失效的目标不能恢复。
3. 独立审查 I2 指出整幅画布出现红蓝像素不足以证明四张图片均正确显示。正式故事现逐张检查保存模型的类型、锚点、目标格、来源和原件格式，并在各自位置截图核对样本颜色与方向。反例仅让 GIF 读取失败，其他三张通过同一判据、GIF 不通过，解除故障后实际重试恢复。
4. Minor M1 的正式菜单拒绝原先显示“粘贴未完成”，现在保留实际“插入图片”操作语义；右键粘贴仍显示粘贴反馈。
5. 扩大回归与独立复核新增 Important I3：普通只读剪切、带预览表格粘贴被图片预检查提前拒绝，原 SDK 的权限提示消失。剪切先按 copy 目标分类，无图片回原 SDK；真图片重新捕获 cut 目标和对应图片绑定。同步表格事件使用窄委托，当场固定本实例/书表/最后范围并去掉 files，再启动原命令的同步权限检查；异步 pasteTable 的目标检查保持。原只读测试未改预期，实际 SDK 单元同时检查提示、零正文写入及严格图片剪切。

这些修正经独立同模型审查，完整意见保存在主目录证据根 `s5/independent-review.md`。审查者只读源码与原件，没有代替主 Agent 运行测试；第七轮已据最终 339 项原件关闭 I1/I3，I2 和操作标签 M1 也已关闭。Phase 上传拒绝提示问题另留 S6。
