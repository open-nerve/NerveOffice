2026-10-23；基线 S4 `12b76056`；实现者自审。Tasks 1–5 已实现并通过 Step 验证，随本次 S5 提交落档；不代表整个 P4 已验收，独立阶段审查仍在 S6。

## 实现与裁决

- 正式 reserve/publish/finalize 使用同一摘要、代次与私有键回执。旧固定 hash 文件继续可读，不搬移或回填；新上传不复用已退休代次。metadata 的 storageKey 只在服务端使用，HTTP 图片 URL 和响应不改。
- 原子空文件标记在文件与目录同步后保持永久占位。仅有新路径不足以阻止旧暂停上传重新制造已清账孤儿，因而回执与标记都保留。代价是每代次一个小记录和 inode，不提供手工清理或过期删除旁路。
- assetId 与对象/claim 独立计完整宽限；引用活动按每资源每事务追加，不把旧共享资源锁升级成排他锁。当前/全部历史关系和上传窗口保留，短暂新增又移除的引用也重新计时。候选起点取自引用与活动核对后的数据库实时钟。
- Assets 持有候选、回执、配额、文件；Documents 只查询本页的全部保留关系；Jobs 组合调度。GC 特权接口仅供 Jobs 与集成测试入口，原模块限制没有放宽到 HTTP 或业务入口。
- 六项配置集中在 jobs.assetGc。缺备份声明、未来/太新水位只整理候选；资源记录删除、排队和已有文件待办均暂停。日期校验不能证明外部备份，运维声明及 M7 恢复演练边界保留。
- quota → 资源/对象/任务的短事务中持久排队，但不释放字节；事务外精确路径退休后，首次完成才释放并审计。未知结果先重读，真实 SQL 或文件故障保持可接续收费。I23 纳入 pending 任务，I29–I31 核对引用活动/候选、存活路径和对象状态。
- 整轮会话锁、固定上界、有界页和退出信号复用既有调度器。GC 单独需要池 2，和回收站同时启用需要池 3；已按同一实际应用池持锁验证。失败日志只含有限阶段/分类，不带原始文件路径或错误参数。
- 0035–0037 都是向前迁移；规范路径、有限时刻、身份不变及完成单向更新有 SQL 约束，手写触发器纳入完整 schema parity。首次上线须停旧实例，数据库与资源卷配套备份/恢复，见 [ADR-023](../../../adr/ADR-023-资源回收与备份水位.md) 和 [部署说明](../../../../deploy/README.md)。
