# M5-P1-S4 鉴权读取与占位复核

> 状态：本 Step 已完成实现与自验；P1 独立审查仍在 S6。日期：2026-10-18。

## 1. 结果与边界

真实上传的 PNG/JPEG/WebP/GIF 已能通过会话保护的 GET/HEAD 读取。上传者的独立 assetId 在严格 24 小时内可读；之后必须存在本人可读的有效当前文档引用。没有内容权限的系统管理员不会自动获得图片权限，物理去重也不合并两个上传者的权利。

元数据、当前引用与有效权限在同一 REPEATABLE READ READ ONLY 快照内查询；查询结束归还连接后才读文件。图片仍由 Assets 管理，文档授权仍经 DocumentAccessPolicy，Workspace 只编排公开服务。当前引用表已由 0028 创建，正式保存和复制写入留在 S5；浏览器前置关系是隔离测试数据，不能冒称产品已接线。

没有会话返回既有 401。身份在守卫之后、快照之前失效时仍返回 SESSION_EXPIRED；系统角色变化导致的开场 403 也保持。已登录无权与未知资源均为 HTTP 200、X-Asset-Status: 404、同一固定 PNG、no-store。成功为 private, no-store；实际 HTTP 请求每次重新鉴权，不产生 ETag、Last-Modified、304、206 或签名地址旁路。

存储缺失、完整性失败和未知内部错误输出逻辑 500 占位；数据库繁忙输出逻辑 503，占位字节相同、Retry-After 为 5 秒。日志只记有限 code/stage/reason，不带原异常、路径、对象摘要或 SQL。无权路径不会调用文件读取。

## 3. 权限交错与查询范围

- 快照已经开始后取消分享、移出团队、跨空间移动或删除文档：在途请求按原快照完成；变更提交后的新请求返回占位。元数据、文档位置与权限不会来自两个时刻。
- 守卫之后、快照之前退出登录或取消系统角色：开场核对拒绝，不转成图片占位或延用守卫的旧事实。
- 暂停在文件读取前时，用真实 pg_stat_activity 确认应用没有未结束的数据库事务；随后撤权，新请求拒绝，原快照的授权结果仍可完成读取。
- 同一图片有多个当前来源时，一个来源失效不影响另一个合法来源；最后一个失效才拒绝。
- 图片接入既有路由清单。外人、系统管理员和只有别处文档授权的人，对已知隐藏与未知资源的非易变响应头、完整 PNG 字节、SQL 文本序列相同；没有给图片增加覆盖豁免。
- 候选来源复用 accessible 的有效文档、空间与单独分享条件，并 limit 1；没有把全部引用读入内存逐个授权。缺失来源仍执行 MISSING_DOCUMENT 的权限查询，资源元数据不存在也不提前跳过文档链。

## 4. 浏览器已解码图片的边界与 P2 条件

`browsers-01` 初版把“新建 img 并重设相同 src”当作重新请求。Chromium 第一次成功读取后，第二次没有 GET，等待 90 秒失败。保存源码、trace 与服务日志后终止该轮：1 失败、1 中断、4 未运行，不能记为通过。

这与 [HTML 的 available-images 规则](https://html.spec.whatwg.org/multipage/images.html#the-list-of-available-images) 一致：同页已解码图片可在不重新下载的情况下复用，包括 HTTP 不允许缓存的图片。服务器的 no-store 与每次 HTTP 鉴权不能收回已经交给客户端的字节，也不能强制一次 DOM 重绘发请求。

因此保留“首次直接 img 解码”，将“主动重读”明确为真实 fetch(no-store) 后解码本次响应，不添加随机 URL、权限豁免或服务器缓存。`browsers-02` 的撤权链路三浏览器已通过；Chromium/Chrome 的 img→fetch 同 URL 场景中，自动化 Response.body 返回空值，而页面已能解码。改为直接取页面实际收到的 blob 字节核对，最终 `browsers-03` 三浏览器全部通过。断言仍包含完整字节、尺寸、安全头和新的请求标识。

**P2 开放正式入口、验收和合并前必须完成 SDK 接线验证**：权限变化、退出、编辑器重建时主动复核资源并处理旧图；未发新请求或只重设相同 src 不能记为权限已复核。这里不规定未验证的 SDK 私有 API，也不声称已经解决编辑器中的旧画面清理。该条件是既有撤权目标的实现边界；Finder 拖放、Excel 来源、Chrome 授权右键粘贴三项原生缺口继续保持。
