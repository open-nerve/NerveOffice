# M5-P1-S6 冷缓存来源修复

日期：2026-10-19。当前状态：首次 main 发布的容器 CI 失败已定位，修复的针对性材料验证通过；独立审查已通过，完整生产容器复验与下一次同 SHA 六项 CI 仍待完成，P1 未关闭。

## 实际失败与原因

首次 `--no-ff` 合并为 `1b89dcfbbff9b765ecbb218b1fb2144b85724110`，正常 pre-push fast 214.76 秒通过并已推送。[CI 39156360790](https://github.com/open-nerve/NerveOffice/actions/runs/39156360790) 的生产容器在构建阶段下载 `native/tiff` 时收到 HTTP 406，应用和容器 E2E 尚未运行。构建及时拒绝不完整材料，不能把它计为成功或归入 M4 DEF-073。该轮其余 job 保持运行，最终日志/报告另行收集，不取消或重试来改写首次结果。

同样版本的 Node 在本机按默认请求及明确标识 NerveOffice 的 User-Agent 对照：libtiff 两次都返回 200 且原摘要相同；fontconfig 两次均为 406、空正文。证据表明 GitLab 来源的实时可用性因端点/运行环境而不同，修改 User-Agent 没有解决已复现的问题；没有证据进一步断言具体上游拦截规则。本机此前完整容器使用已逐件校验的缓存，不能替代首次无缓存下载路径。

## 修复边界

沿用已有 `vendoredPath` 机制，把两份已经在 S2 取得、审阅并包含于成功完整分发中的原始归档存入 `inputs/native/`。仅新增这两个清单字段与归档，仓库补件从 13 份变为 15 份，新增 3,283,541 B；398 份来源及其 201,994,917 B 总量保持。原 URL、版本、字节数、SHA-256、归档成员和既有许可正文均不变。

| 来源 | 固定原件 |
|---|---|
| libtiff 4.7.2 | 2,616,788 B；`62b15f44c10106065211efa22a2dc77937bd97ee1f6e3afd2c9659010de112eb` |
| fontconfig 2.18.3 | 666,753 B；`9ae01e1d53acdef56010c5451cd34aa41d325b2faccd8606448d8fa01b2496b3` |

两份文件分别与 S2 原件、原 manifest 和 `native-bundle-01` 的分发原件逐字节核对一致。没有更换下载源、重写摘要或引入新的二进制版本；下载器、应用运行代码、数据库、浏览器代码、测试与门禁配置均未修改。构建仍校验仓库副本，并在缺件/坏大小/坏摘要时失败。

- 使用正式 `bundleNativeImages`：缓存仅缺这两份，其他来源按既有摘要提供；网络替身固定返回 406。修复前确实在 `native/tiff` 失败；修复后没有任何网络调用，完整收集及离线核对通过，398 份来源、402 份分发文件（加回执为 403）。这是隔离失败来源的回归，不是对所有其他 URL 的冷网络验收。
- 部署单元回归 9 文件、105 项通过；实际 licenses 门禁及来源 JSON lint 通过。原件位于主目录 `.codex/handoffs/m5-p1-20261018/s6/task5-materials-*`。
