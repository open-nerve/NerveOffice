## 1. 目标与范围

**目标**：让表格在既有保存、权限与离线恢复机制之上，具备计划书 §4.2 承诺的完整内容能力；图片、复制、历史恢复和 CSV 都有用户能实际走通的入口与可靠的数据边界。对应计划书 §13.2 的 M5。

**范围内**：

1. 表格目标能力逐项走界面、撤销重做、保存重开与阅读模式验证，包括结构、格式、公式、筛选排序、冻结、数据验证、条件格式、查找替换、超链接、备注、浮动图片和单元格图片。
2. 图片资源服务：PNG/JPEG/WebP/GIF、单张不超过 5 MiB、完整解码与重新编码、像素和帧数预算、私有文件存储、鉴权读取、引用关系、容量约束及延迟回收。
3. 图片插入、粘贴、拖放和复制；清理外链与内联图片，限制 `IMAGE()`；修复已知的图片锚点与加载失败渲染问题。
4. 表格超链接共用平台地址判定；被拒绝的链接和图片能指出可定位的位置。
5. 小时级历史版本、只读预览、恢复为副本；删除前与升级前的恢复检查点；历史清除、审计及过期清理。
6. 按工作表导出 CSV，从 CSV 新建表格或导入为新工作表；处理容量、字符编码、公式注入与失败时的原数据保留。
7. 图片在文档复制、本机草稿另存为副本、历史恢复之后仍然可读，原文档删除不会破坏已有副本。

**范围外**：文字文档产品入口（M6）；任意附件、远程抓图、离线插入图片或离线 CSV 导入；xlsx/docx 转换；Pro 功能、线程评论、客户端保护功能；逐操作历史、差异比较、就地回滚；为追逐版本而升级 SDK 或浏览器。M7 仍负责上线总验收、完整备份恢复演练及独立安全审查。

### 2.1 上层约束和现有代码事实

- 计划书 §4.1、§4.2、§7、§8.2–§8.7、§11.2–§11.4、§12、§13；工程规范与完成定义；架构总览及现有授权、内容保存、编辑器适配、定时任务、离线草稿 ADR。

- 当前协调发布的 Univer 包锁定 `1.0.1`。`sheet@1` 已注册多数目标插件，但图片和链接入口仍受守卫。插件已注册不等于该功能已验收。
- `document_contents` 只保存当前压缩快照；`document_revisions` 只保存修订、请求和哈希等元数据。历史版本必须新增可读回的正文，不能用现有修订列表冒充历史。

- 快照中的图片地址和链接已有共享校验，尚无正式图片资源后端。受限 `IMAGE()` 的执行器仅看求值后的参数，不能据此证明字符串来自字面量还是拼接；开放图片前必须补上可验证的来源约束。
- 本机草稿保留 14 天、保存请求记录至少保留 15 天、用户历史保留 7 天是三个不同规则，不合并清理任务或保留期。

### 2.3 开发顺序选择

推荐先补资源底座，再开放图片和剩余表格能力，随后做历史与完整回收，最后做 CSV 与整体验收。这样图片使用、权限与保存从第一次开放起就相互闭合，历史又能保护图片免于被错误回收。

另外两种顺序的代价是：先开放全部界面会留下图片不能可靠保存和复制的中间状态；先统一升级 SDK 会扩大回归与格式迁移范围，且并不保证已登记缺陷消失。本 M 保持现有版本，必要修复集中在适配层或可追踪的最小依赖补丁；是否升级按证据另行评审。

## 6. 架构影响

### 6.1 模块边界

新增资源存储能力，负责 assetId、不可变文件、上传处理、物理存储与清理执行。文档域继续负责文档访问、当前内容、历史内容、引用的业务授权与事务协调；Workspace 继续组合跨模块用户流程，Jobs 只调度公开服务，不直接访问别的模块的仓库。

避免 `Documents → Assets → Documents` 的循环：存储层不导入文档域，读取接口通过文档域的公开授权查询获得判定，再调用存储服务。文档引用和历史引用由文档域管理；存储回收接收经事务确认的可删对象。P1 具体设计须写清授权查询、统一锁顺序与引用增减的事务边界，不把图片读取变成绕开统一权限的第二套规则。

历史服务留在文档域，独立于当前内容服务组织代码；保存和检查点共享明确的事务接口。前端新增平台功能流程，所有 Univer API、内部接口和补丁仍集中在编辑器适配层，不能把 SDK 对象扩散进列表、历史 API 或资源存储模块。

### 6.2 图片写入与失败处理

上传时先检查会话、CSRF、流量与请求大小，再做类型、完整解码、重编码和输出大小验证。客户端检查用于提示，服务端才是边界。四种格式都必须有实际样本；GIF 的多帧重编码及显示行为按锁定 SDK 的能力验证并明确说明，不额外承诺动画编辑或帧级操控。

图片处理使用有内存、耗时、并发和输出限制的隔离执行单元，失败只影响本次上传。P1 根据四格式支持、动画、原生依赖许可、部署镜像及预算实测选择处理库，精确锁定版本；不在本总设计凭印象承诺某个库。像素和 GIF 帧数限制由 P1 实测定值，连同组织级配额一起形成对用户可解释的配置。

文件只追加，使用服务端生成的标识与私有路径；每次上传是独立 assetId，处理后字节按 SHA-256 去重。文件落盘和数据库不能假装在同一个事务里：先保证完整文件可读，再提交元数据；中断遗留物由带宽限期的任务回收。提交成功不能指向半个文件。

读取以会话和引用权限为准，无会话按既有契约返回 401。已登录后，无权与不存在使用同一个 404 业务状态，再按计划书 §8.5 的图片占位约定返回 `200 + X-Asset-Status + no-store`；读取故障同样明确映射，不从响应差异泄露资源是否存在。下载或 `fetch` 路径必须检查状态头。P1 固定各状态的映射测试，避免把“无权为 404”的逻辑状态与占位图的 HTTP 响应混为一谈；401 引起的破损图片由客户端兜底保证继续绘制。

服务端占位只处理服务器能回答的错误。网络失败、断流、坏解码和离线时，客户端仍要防止破损图片打断整表绘制；禁止用吞掉所有异常的方式掩盖渲染停止。

### 6.3 引用、授权、复制与本机草稿

快照检查从解析后的所有字符串中提取资源地址，包括 `IMAGE()` 的字面量；资源 `data` 也按已定义的解析规则处理，不扫描原始 JSON 文本。地址规范仍是 `/api/assets/{uuid}`，不得携带查询、片段或外部来源。

保存正文与引用更新在同一事务中完成，沿用请求去重、租约、代次、基准修订和锁下权限检查。合法来源为当前文档已有引用、24 小时内本人上传、或本人有权读取的其他引用。无权的地址不获得引用，但不因此把整份本地优先保存永久卡住；正文仍按现有规则保存，图片按读取权限显示占位。重放不得重复建立对象或引用。

当前内容、用户历史、运维检查点分别保存引用。**保留引用不等于向所有当前读者授权**：只存在于历史中的图片，要有对应历史的访问资格才参与读取授权，不能让查看者凭 assetId 读到已删除的敏感历史。运维检查点也不自动给普通成员提供访问权。

复制当前文档时，在已有一致性锁下复制获授权的引用和原 gzip，不更换 SDK `unitId`，不复制源文档单独授权。历史恢复和本机草稿另存为副本复用目标创建、请求重放和资源授权原则。旧文档随后撤权或删除不影响已合法创建副本的独立权限。

M4 已明确离线不能新插入图片。现有图片离线时不保证未缓存的字节可读，但表格和本机草稿须继续工作；不得为图片额外复制一份未加密本机正文。上传成功但正文尚未同步的窗口遵守 24 小时上传者权利与回收宽限，断网超过窗口后应准确提示图片状态，不声称本机草稿一定保存了图像文件。

### 6.4 编辑器入口和依赖修复

插入、文件选择、系统粘贴、HTML/内部片段、拖放、公式及链接命令分别有入口证据。图片处理只遍历相关命令，避免对大表格每次普通写值做全量递归。异步上传失败或编辑权在上传期间失效时，不得晚到后写进已销毁或已只读的实例。

`IMAGE()` 在主线程和公式 Worker 都保持 restricted 策略，非法输入返回 `#VALUE!` 且无请求。对“字符串字面量”要求必须在还能区分公式结构的边界验证；只看求值结果或只用正则搜地址都不够。P2 以字面量、引用、区域、数组、拼接和编码边界的对照用例确定适配方式，服务器的资源授权仍独立生效。

已有插件开启更多入口不自动升级档案编号；真正改变注册插件、数据结构或影响数据的配置时，按计划书 §8.7 评审格式版本、旧客户端隔离和迁移前检查点。补丁采用可追踪的最小修改、锁定版本和失败特征回归；官方修复的移除条件写入上游登记。不得修改 `refer/univer` 代替正式补丁。

### 6.5 历史与检查点

历史保存不可变的压缩正文、格式信封、内容哈希、保存人/时间和授权后的资源引用。以服务端 UTC 自然小时分桶，该小时第一次成功提交的有变化内容生成一份用户历史，后续不覆盖这份正文；新建的初始正文计入当小时。没有内容变化、同请求重放、同小时重复保存都不额外制造历史。P4 落实并发保存的唯一约束并用可控时钟验证；界面显示用户本地时间，采样不受设备时间影响。

删除前与升级前检查点单独标记类型与 30 天保留期；用户历史为 7 天。历史预览是独立只读实例，不申请编辑权、不写本机发件箱，也不修改当前正文。恢复为副本使用新平台文档身份，原文档与其他人的编辑会话继续有效。

历史授权随当前权限重新检查；列表、正文、图片及恢复 API 都要检查，不能只隐藏按钮。清除用户历史需要空间管理员权限和审计，不顺带清除当前正文、运维检查点、保存幂等回执或本机草稿。打开自检失败时为有资格的人提供历史恢复路径；没有可用历史时如实说明，不能虚构可恢复版本。

GC 先按所有有效引用判定 assetId，再判定物理文件是否仍被其他 assetId 引用；删除与新引用并发必须互斥并可恢复。宽限期至少覆盖部署的备份保留期，配置不满足时拒绝危险回收。历史未实现前不启动一个只看当前正文的物理删除任务。

### 6.6 CSV

CSV 在客户端完成，不新增转换服务。导出每次选择一个工作表，采用 UTF-8 BOM；内容是表格数据，不包含图片、样式或插件资源。公式导出其可见结果，并在字符串单元格边界处理公式注入字符；数字与日期的表达约定在 P5 用样本固定，不能因统一加前缀而损坏正常数值。

导入从明确的 UTF-8 文件开始，解析时有体积、字段、行列和单元格总量上限；将可能被解释为公式的内容当作文本，不能自动执行。先完成解析和容量校验，再通过单一受控动作加入新工作表或创建新文档；取消、解析失败和容量超限都保留现状。成功后沿用修改检测、公式计算和本地优先保存，而不是另做一条直接覆盖正文的上传接口。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| M4 依赖缺陷再次出现，导致无关工作反复返工 | 完整保留 DEF-073 的证据与重开条件；照常运行矩阵，逐次判断是否同一问题；不无限重复压力循环，也不扩大豁免 |
| 资源权限与历史引用让已删除内容重新可见 | 区分保留与可读资格，历史引用按历史权限授权；多账号、降级和撤权并发测试 |
| 删除文件与数据库事务脱节 | 不可变文件、先完整落盘、元数据事务、延迟且可恢复的 GC；故障注入覆盖每个提交边界 |
| 图片处理拖垮进程或撑满磁盘 | 请求/输出限制、像素与帧预算、隔离和并发上限、配额；容器中测实际内存与失败恢复 |
| 新图片能力破坏保存管道、只读或重建 | 入口守卫与已授权会话结合；回归上传中撤权、切换、销毁、保存中继续输入及本机恢复 |
| 真实剪贴板、拖放在 Safari 不同于合成测试 | P2 前置复核，一次预约完成可合并的真实操作；始终记录浏览器版本、权限、是否真实事件与结果，不以 Playwright WebKit 代替 Safari |
| 历史保留放大数据库、WAL 与资源成本 | 按三份容量样本测小时采样、去重和保留期容量；不复用修订回执清理，不提前承诺无限历史 |
| CSV 类型或公式处理改变数据 | 明确文字/数值/公式的边界，真实常用表格软件导出样本与平台往返测试；不宣称复杂 Office 格式兼容 |
