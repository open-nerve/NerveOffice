## 下一个 Phase 须知

P6 是 M0 的最后一个 Phase，下面的"须知"交给 M0 结束评审与 M1 起的正式实现。

**验证工程的新能力**

- 页面参数：`outbox=main|worker`、`user=<id>`、`durability=strict`、`mutlog=1|enrich`。
- 验证服务：
  - 文档存储的修订号：`GET` 返回 `X-Revision`，`PUT ?base=N` 为条件写入（不等返回 409）；
  - `GET /api/keys/:user` 下发密钥，`POST /api/keys/:user/revoke` 吊销。
- `window.__m0.outbox`：
  - 查询：`state()`、`lock()`、`generation()`、`recovery()`、`autosave()`、`reloads()`、`inspect(docId?)`；
  - 操作：`capture(...)`、`restore()`、`discard()`、`steal()`。
- `window.__m0.mutlog`：`logger()`、`read(logId, afterSeq)`、`replay(logId, afterSeq)`、`clear(logId)`。
- `e2e/p6-helpers.ts`：
  - `openWithOutbox`、`outboxInfo`、`waitSavedLocal`、`edit`、`contains`；
  - `launchPersistent`：持久化的浏览器上下文；
  - `killProfile`：整棵进程树，WebKit 另加 XPC 服务。
- `scripts/v16-node-load.ts`：纯 Node 加载样本并保存；`scripts/p6-summary.ts`：汇总表格。

**已知的坑**

- **配额覆盖的时机**：CDP 的 `Storage.overrideQuotaForOrigin` 必须在本站第一次写入 IndexedDB 之前设置。发件箱一装上就会写持有者记录，所以要先在同源的空白页上设置。
- **WebKit 的进程结构**：网络、渲染、GPU 进程是 launchd 拉起的 XPC 服务。只有一个 WebKit 实例在跑时，才能按启动时刻把它们一并杀掉；与别的 WebKit 用例并行时不要跑杀进程的用例。
- **页面崩溃**：CDP 的 `Page.crash` 不会返回响应，不要 await 它。
- **组件导入**：Node 原生执行 TypeScript 要求导入带扩展名；验证工程里被 Node 脚本用到的模块要写 `.ts` 扩展名。
- **样本基线**：比较重放或保存结果时，基线要用"已加载实例 `save()` 的输出"，不要直接用手写样本：加载时会随机生成 `sectionId` 等缺省的 id。
- **测量写入的用例要确认每次都有真实的内容变化**：发件箱对内容相同的捕获去重跳过。`edit` 辅助原来用最后一列第一行计数，P3 大样本那一格是表头，从第二次修改起写的都是同样的内容，端到端少算了压缩、加密与写入（收尾时发现并修正）。端到端用例现在断言每次捕获的 `skipped` 为 false。
