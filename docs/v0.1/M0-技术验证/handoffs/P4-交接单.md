## 下一个 Phase 须知

**验证工程的新能力**

- 页面参数：
  - `img=platform`：平台图片服务、粘贴钩子与命令守卫；
  - `imagefn=off|restricted`：`IMAGE()` 的处理；
  - `nosession=1`：页面响应不下发会话 Cookie。
- 验证服务：
  - `POST /api/assets`（原始字节）、`GET /api/assets/{id}`（会话 Cookie）；
  - `/__assets` 查看上传、读取与引用关系，`DELETE` 清空记录；`POST /__assets/fail?status=&count=` 注入上传失败；
  - 保存文档时 `?validate=1` 做图片地址校验；
  - 第 4 个端口（`SERVERS.fallback`）读取失败时返回占位图。
- `server/snapshot-images.ts`：快照中的图片地址提取与分类，服务端与用例共用。
- `e2e/p4-helpers.ts`：
  - `syntheticPaste`：合成粘贴，三个浏览器都可用；
  - `insertViaFileChooser`：执行打开文件选择框的命令并选中文件；
  - `snapshotImages`、`addedImages`：快照中的图片；
  - `watchExternalRequests`：外部请求计数，要在关掉 CSP 的服务上用；
  - `cspViolations`。
- `window.__m0.images`：`events` 为平台图片服务与钩子的操作记录，`io()` 取出图片服务；`editor.imageFunctionInstalled()`。
- `node scripts/p4-summary.ts`：汇总成报告中的表格。

**已知的坑**

- 严格 CSP 下，页面里不能用 `new Function`（`eval` 类）。P3 的 `runFacade` 只能在关掉 CSP 的服务上用。
- 被 CSP 拦截的请求在发出前就被取消：`page.route` 看不到它们，要统计"是否发出请求"必须关掉 CSP。
- `route.fetch()` 取回的响应，其 `Set-Cookie` 会被存进浏览器上下文，不能用它来模拟"没有 Cookie"。
- 验证服务的资源与文档都在各自进程的内存里，4 个端口互不相通。
- 表格插入浮动图片后，图片处于选中状态；要复制图片，先点一下图片（否则复制的是单元格）。
- 并行跑多套用例时不要重新构建共用的 `dist`：用 `npx vite build --outDir dist-xxx` 加 `M0_DIST=dist-xxx`。
