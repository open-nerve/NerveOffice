## 下一个 Phase 须知

**验证工程的新能力**

- `window.__m0.editor.detector`：变更检测原型。`state(since)` 返回检测到的修改、非本地 mutation、`syncOnly` mutation、本地 mutation 统计；`lastActivityAt()` 是报告 §3.4 的"活动"时间。排除名单来自档案的 `changeDetectionExclude`。
- `e2e/p3-helpers.ts`：`ensureGenerated`（按需生成大样本并写入存储）、`waitQuiet`（按报告 §3.4 的时机等待）、`contentDiff`（按报告 §1 的口径比较内容）、`runFacade`。
- `src/harness/content-compare.ts`：内容比较与内容哈希。
- 阅读模式：页面参数 `mode=read&ro=facade|points|firewall|combined`；`window.__m0.enterReadMode(ro, { clearUndo })` 原地进入，`readMode.exit()` 原地退出；`window.__m0.remount({ mode, doc, ro })` 销毁重建。
- `window.__m0.perf`（计时与阻塞测量）、`window.__m0.auditMenus()`（菜单审计）、`editor.undoStatus()`、`editor.setCurrentUser()`。
- 页面参数 `calc=forced`（打开时强制重算）、`split=0`（关掉大表拆分）。
- 构建器：表格 `big-1m`、`big-5m`、`perf-50k`、`formula-scenarios`；文字文档 `doc-20k`、`doc-1m`（`src/experiments/p3-samples/`）。
- `node scripts/p3-summary.ts [v06 … v10]`：把结果汇总成报告中的表格。

**已知的坑**

- 性能测量（V08、V10）必须单独运行，与其他用例并行会拉高数字。
- 判断"内容是否变化"要用 `content-compare.ts` 的口径：资源排序、空值等价、视图状态字段（表格 `zoomRatio`、`scrollTop`、`scrollLeft`，文字文档 `settings.zoomRatio`）。
- 打开含易变函数的文档，`save()` 的结果就与原快照不同（公式结果以 `onlyLocal` 写回），这不是用户修改。
- `onCalculationResultApplied` 在没有计算时也要约 500 ms 才返回；Worker 模式下它可能早于其他工作表的结果返回。
- WebKit 的 `performance.now()` 精度是 1 ms，不支持 Long Tasks；JS 堆只有 Chromium 内核能用 CDP 读。
- `FWorksheetPermission.setReadOnly()` 要求先 `protect()`，会写入保护类资源；不要在阅读模式里用它。
- 不要调用 `setCurrentUser` 设置真实用户：本地授权服务会因此禁止编辑。

**交给后续 Phase 的事项**

- P4：
  - 图片的插入入口（工具栏、右键、粘贴）在阅读模式下已随工具栏与右键菜单一起关掉；编辑模式下的入口清单与 CSP 由 P4 核对；
  - 菜单隐藏的机制（全局 `menu` 配置，按菜单项 id）可以直接用于 P4 需要隐藏的入口。
- P5：
  - 文字文档的变更检测、阅读模式（本地权限点 + 防火墙）与捕获成本已验证；文字文档的排版 Worker 回归、能力矩阵与不支持功能的菜单隐藏仍在 P5；
  - 文字文档的缩放写进 `settings.zoomRatio`，属于视图状态。
- P6：
  - 从修改停止到压缩与哈希完成约 1.57 秒（1 MiB 表格），§12.2 的 2 秒预算只剩约 0.4 秒给本机写入与加密；
  - 5 MiB 的压缩在主线程上有一个 60–95 ms 的任务，考虑在 Worker 里压缩与加密；
  - 实测压缩率：表格约 25%，文字文档约 45%。
- M1（编辑器适配层）：
  - 集中封装并登记报告 §7 的内部 API；
  - 决定"替换 `IAuthzIoService`（全部允许）"还是"不设置当前用户"；
  - 把排除名单与动作矩阵纳入回归。
- M4（本地优先管道）：
  - 变更检测规则（报告 §2.1）、捕获时机（报告 §3.4）、大表操作关掉拆分；
  - 启用公式 Worker（报告 §6.3），并向上游报告"Worker 模式下等待接口提前返回"；
  - 可选优化：只在有计算进行时等待，省下约 0.5 秒。
- M0 结束（00 号计划书 r3）：报告 §9 的全部条目；插件档案定稿时确认公式 Worker 与界面配置。
- 上游报告候选：Worker 模式下公式会话提前完成；删除工作表按行数判断"大表"；`clear-drawing-transformer` 的类型声明。
