## 下一个 Phase 须知

**验证工程的新能力**

- `window.__m0.editor.detector`：变更检测原型（公开的 `CommandExecuted` 事件）。`state(since)` 返回检测到的修改、非本地 mutation、`syncOnly` mutation、本地 mutation 统计；`formulaProgress()` 返回最近一轮公式计算的进度，以及是否有排队的下一轮（`queued`）。排除名单来自档案的 `changeDetectionExclude`。
- `window.__m0.waitForCapture()`（`src/harness/capture-timing.ts`）：报告 §3.4 的捕获时机；`e2e/p3-helpers.ts` 的 `waitQuiet` 调用它。
- `e2e/p3-helpers.ts`：`ensureGenerated`（按需生成大样本并写入存储）、`waitQuiet`、`contentDiff`（按报告 §1 的口径比较内容）、`runFacade`。
- `src/harness/content-compare.ts`：内容比较与内容哈希；页面里通过 `window.__m0.content` 调用。
- 阅读模式：页面参数 `mode=read&ro=facade|points|firewall|combined`；`window.__m0.enterReadMode(ro, { clearUndo, ui })` 原地进入（`ui: true` 同时在运行时切换界面），`readMode.exit()` 原地退出；`window.__m0.remount({ mode, doc, ro })` 销毁重建。
- `window.__m0.perf`（计时与阻塞测量：`probeEventLoopLag`、`probeFrameGap`、`observeLongTasks`、`measureCapture`）、`window.__m0.auditMenus()`（菜单审计）、`editor.undoStatus()`、`editor.setCurrentUser()`。
- 页面参数 `calc=forced`（打开时强制重算）、`split=0`（关掉大表拆分；验证工程默认保留 SDK 的拆分，便于对比）、`interval=N`（公式引擎的让出间隔）。
- 构建器：表格 `big-1m`、`big-5m`、`perf-50k`、`formula-scenarios`；文字文档 `doc-20k`、`doc-1m`（`src/experiments/p3-samples/`）。
- `node scripts/p3-summary.ts [v06 … v10]`：把结果汇总成报告中的表格。

**已知的坑**

- 性能测量（V08、V10）必须单独运行，与其他用例并行会拉高数字。
- 测主线程阻塞时，被测工作常常在一个长任务的末尾完成，`await` 之后的代码仍在这个任务里：停止采集前要把"上一次采样到现在"也算进去（事件循环探针、帧间隔探针），Long Tasks 要先让出一个宏任务与一帧再收集，并按时间窗口过滤。`src/harness/perf.ts` 已这样处理。
- 主线程模式下调小让出间隔后，Chromium 内核里的 `setTimeout` 探针会比帧间隔长很多（两段计算之间先轮到渲染与 `MessageChannel` 任务）；用户看到的冻结以帧间隔为准。
- 判断"内容是否变化"要用 `content-compare.ts` 的口径：资源排序、空值等价、视图状态字段（表格 `zoomRatio`、`scrollTop`、`scrollLeft`，文字文档 `settings.zoomRatio`）。
- 打开含易变函数的文档，`save()` 的结果就与原快照不同（公式结果以 `onlyLocal` 写回），这不是用户修改。
- `onCalculationResultApplied` 在没有计算时也要约 500 ms 才返回；Worker 模式下它可能早于其他工作表的结果返回；它只等调用时正在进行的一轮，不等因之前的修改而排队的下一轮（SDK 不把新修改并进正在进行的一轮）。修改没有牵动公式时，SDK 只发完成通知、不发结果 mutation（捕获时机据此视为收齐）。
- 经单元格编辑器编辑后，单元格可能存成富文本（`p`），`getValue()` 为空，要用 `getDisplayValue()` 或快照判断。
- WebKit 的 `performance.now()` 精度是 1 ms，不支持 Long Tasks；无头 WebKit 不能读剪贴板；JS 堆只有 Chromium 内核能用 CDP 读（Worker 的堆要附加到 Worker 目标）。
- `FWorksheetPermission.setReadOnly()` 要求先 `protect()`，会写入保护类资源、禁止复制；不要在阅读模式里用它。
- 不要调用 `setCurrentUser` 设置真实用户：本地授权服务会因此禁止编辑。
- 平台默认启用公式 Worker：表格相关的验证要带 `worker=1`（或两种模式都跑）；验证工程的页面默认仍是主线程模式，便于对比。
- mutation 防火墙必须只拦本文档：单元格编辑器的同步是作用于其他单元的非本地 mutation。
