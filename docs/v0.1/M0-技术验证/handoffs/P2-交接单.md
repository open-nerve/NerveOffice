## 下一个 Phase 须知

**验证工程的新能力**

- 文档存储：`GET/PUT /api/docs/:id`、`POST /api/docs/:id/copy?to=`；页面参数 `doc=<id>` 从存储加载，`window.__m0.persist(id)` 写回。
- 插件组：`without=<组>` 去掉可单独去掉的组；`window.__m0.editor.lateRegister(组)` 在文档创建后补注册。
- `window.__m0.editor.resourceHooks()`：运行时注册的资源 hook。
- `src/harness/resource-guard.ts`：资源比较与两种防护规则（服务端检查、打开自检）。
- 样本：`fixtures/sheet/*`、`fixtures/doc/*`（由 `src/experiments/v03-samples/` 生成，重新生成用 `M0_BUILD_SAMPLES=1`）。后续 Phase 做"打开即有修改"、只读、性能、图片等实验时，请复用这些样本。

**已知的坑**

- 比较快照要以 JSON 文本为准（`JSON.stringify(save())`），不要直接比较 `page.evaluate` 返回的对象。
- 资源数据的 `""` 与 `{}`、按工作表分组的空数组，在内容上等价；判断"有没有变化"时要先归一化。
- 手写快照第一次打开时会被补齐默认字段、随机生成缺少的 id；做判定时请用 SDK 生成的样本。
- 保护类资源：`sheet-protection` 样本打开后会显示保护阴影与锁图标。

**交给后续 Phase 的事项**

- P3：
  - `setReadOnly` 是否写入保护类资源（插件档案 v1 §3）；
  - 打开自检那一次捕获的耗时；
  - 变更检测是否会被"空值等价"的归一化误判为有修改。
- P4：
  - 相对地址的图片可以正常加载与保存，`/api/assets/{id}` 方案可行，需在 CSP 与鉴权下复验；
  - 需要检查的图片地址位置：表格资源、单元格富文本、文字文档正文与资源；
  - 工作表背景图片（`FWorksheet.setBackgroundImage`）也是一条图片路径。
- M3：报告 §3.3 的防护规则；链接协议检查覆盖文字文档正文与资源两处。
- M4：本机发件箱以 `documentId` 为键。
- M5：DEF-002。
