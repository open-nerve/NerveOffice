## 下一个 Phase 须知

**验证工程的新能力**

- 文档存储：`GET/PUT /api/docs/:id`、`POST /api/docs/:id/copy?to=`；页面参数 `doc=<id>` 从存储加载，`window.__m0.persist(id)` 写回。
- 插件组：`without=<组>` 去掉可单独去掉的组；`window.__m0.editor.lateRegister(组)` 在文档创建后补注册。
- `window.__m0.editor.resourceHooks()`：运行时注册的资源 hook。
- `src/harness/resource-guard.ts`：资源比较与防护规则（服务端检查、打开自检）；`src/harness/guarded-resource-manager.ts`：资源加载错误捕获（`guard=1`）；`window.__m0.resourceLoadFailures` 读取捕获结果。
- `window.__m0.editor.semantics()`：运行时模型的语义摘要；`declaredResources()`：档案声明的资源名；`currentUserId()`：SDK 眼中的当前用户。
- 预期语义：`e2e/samples-expected.ts`；差异基线：`e2e/v03-baselines.ts`（支持 `*` 通配）。
- 样本：`fixtures/sheet/*`、`fixtures/doc/*`（由 `src/experiments/v03-samples/` 生成）。重新生成用 `M0_BUILD_SAMPLES=1`，只核对用 `M0_BUILD_SAMPLES=check`；重新生成后必须再 `vite build`。后续 Phase 做"打开即有修改"、只读、性能、图片等实验时，请复用这些样本。

**已知的坑**

- 比较快照要以 JSON 文本为准（`JSON.stringify(save())`），不要直接比较 `page.evaluate` 返回的对象。
- 资源数据的 `""` 与 `{}`、按工作表分组的空数组，在内容上等价；判断"有没有变化"时要先归一化。
- 手写快照第一次打开时会被补齐默认字段、随机生成缺少的 id；做判定时请用 SDK 生成的样本。
- 保护类资源：`sheet-protection` 样本打开后会显示保护阴影与锁图标；表格页的当前用户是本地授权服务设的 `Owner_…`，文字文档页是匿名用户。
- `sheet-drawing` 样本一打开，`save()` 的结果就与样本不同（DEF-002 的派生尺寸）；用快照比较判断"有没有修改"会误报。
- Facade 的读取方法可能改动模型（例如 `getDataValidations()` 会给每个工作表建空数组）：要比较快照时，先保存再读语义。

**交给后续 Phase 的事项**

- P3：
  - `setReadOnly` 是否写入保护类资源（插件档案 v1 §3）；设置真实用户身份后，本地授权服务对普通编辑有没有影响；
  - 打开自检那一次捕获的耗时，以及资源加载错误捕获的开销；
  - 变更检测是否会被"空值等价"的归一化误判为有修改；计算快照哈希前要按资源名排序；
  - 三个浏览器上的公式 Worker 模式回归（P2 只在 Chromium 上核对了等价）；
  - 工作表背景图片的入口（"视图 → 显示"）是隐藏，还是纳入并补样本。
- P4：
  - 相对地址的图片可以正常加载与保存，`/api/assets/{id}` 方案可行，需在 CSP 与鉴权下复验；
  - 需要检查的图片与链接地址位置，以报告 §2.3 第 6 条的表格为准：表格的图片资源、单元格富文本（图片与超链接）、工作表背景图片（`FWorksheet.setBackgroundImage`）；文字文档的顶层 `drawings`、图片与超链接资源、正文，以及页眉页脚、备注、脚注尾注；
  - 相对地址要按平台的源解析，与 SDK 的 `isSafeUrl` 一致。
- P5：
  - 目录插件会往正文写 FIELD、BOOKMARK、HYPERLINK 类型的区间（`packages/docs-toc/src/commands/table-of-contents.command.ts`），纳入目录就要补样本、纳入地址检查；
  - 三个浏览器上的排版 Worker 回归；
  - `DOC_WORD_STYLES_PLUGIN`、`DOC_NOTE_PLUGIN` 按"必须为空"处置。
- P6 / M4：
  - 本机发件箱的键、Web Locks 的锁名用 `documentId`；
  - "退出清空本机数据"要覆盖 IndexedDB `UniverLocalStorage`、localStorage 中以 `UniverLocalStorage/` 开头的键、`univer-mobile-recent-formula-functions`。
- M3：
  - 报告 §3.3 的防护规则（服务端结构检查、打开自检三部分与失败处置）；
  - 统一的地址提取器；
  - 文字文档超链接资源与正文一致。
- M5：DEF-002。
