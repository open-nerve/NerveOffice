# 插件档案 v1（草案）

> 状态：草案（P2）｜适用 SDK：`@univerjs/*` 1.0.0，`@univerjs/icons` 1.43.0｜代码：`spikes/m0/src/profiles/`（仅供参考，M1 按正式流程重写）

插件档案是某种文档类型固定使用的插件列表、配置与适用的 SDK 版本（00 号计划书 §8.2）。本文件随 M0 各 Phase 逐步补全，M0 结束时定稿：

| 内容 | 由谁确定 | 状态 |
|---|---|---|
| 插件列表与注册顺序、资源名称白名单 | P2 | 本文件 |
| 界面配置（隐藏菜单、只读加固） | P3 | 待补充 |
| 图片读写服务的替换、CSP 定稿 | P4 | 待补充 |
| 文字文档的最终范围（公式引擎、目录、排版 Worker 是否保留） | P5 | 待补充 |

## 1. 表格 `sheet@1`

插件按组注册，组内与组间的顺序都按官方 preset。"可单独去掉"表示其他组不依赖它；V04 用它复现插件缺失。

| 组 | 插件（注册顺序） | 写入快照的资源 | 可单独去掉 |
|---|---|---|---|
| core | Docs、RenderEngine、UI、DocsUI、（Worker 模式另加 RPCMainThread）、FormulaEngine、Sheets、SheetsUI | `SHEET_AuthzIoMockService_PLUGIN`、`SHEET_DEFINED_NAME_PLUGIN`、`SHEET_RANGE_THEME_MODEL_PLUGIN`、`SHEET_RANGE_PROTECTION_PLUGIN`、`SHEET_WORKSHEET_PROTECTION_PLUGIN`、`SHEET_WORKSHEET_PROTECTION_POINT_PLUGIN` | 否 |
| numfmt | SheetsNumfmt、SheetsNumfmtUI | — | 否 |
| formula | SheetsFormula、SheetsFormulaUI | — | 否 |
| drawing | Drawing、DocsDrawing、DrawingUI、SheetsDrawing、SheetsDrawingUI | `SHEET_DRAWING_PLUGIN`（浮动图片）。单元格图片存在单元格的富文本里 | 是 |
| cf | SheetsConditionalFormatting(UI) | `SHEET_CONDITIONAL_FORMATTING_PLUGIN` | 是 |
| filter | SheetsFilter(UI) | `SHEET_FILTER_PLUGIN` | 是 |
| hyperlink | SheetsHyperLink(UI) | —（链接存在单元格富文本的 `customRanges` 里） | 是 |
| dv | DataValidation、SheetsDataValidation(UI) | `SHEET_DATA_VALIDATION_PLUGIN` | 是 |
| find-replace | FindReplace、SheetsFindReplace | — | 是 |
| note | SheetsNote(UI) | `SHEET_NOTE_PLUGIN` | 是 |
| sort | SheetsSort(UI) | — | 是 |

**影响数据的配置**

- `UniverSheetsPlugin`：`onlyRegisterFormulaRelatedMutations: false`。
- 公式 Worker 模式（是否采用由 P3 的性能数据决定）：主线程的 `FormulaEngine`、`Sheets`、`SheetsFormula` 都设 `notExecuteFormula: true`，并注册 `RPCMainThread`。Worker 内注册 Sheets（`onlyRegisterFormulaRelatedMutations: true`）、FormulaEngine、RPCWorkerThread、RemoteSheetsFormula、SheetsFilter。
- 其余插件使用默认配置。

**不注册**：`@univerjs/network`（除它自身外没有任何包使用 `IHTTPService`）；表格的 table、线程评论、十字高亮、水印、action-recorder、slides、Vue/Web Component 适配器；不注册任何 `ITelemetryService` 实现。

## 3. 资源名称白名单

以运行时注册、适用于本文档类型的资源 hook 为准（`e2e/results/v03/roundtrip/*.json` 的 `resourceHooks`）：三个浏览器一致，与各组声明的资源名自动核对一致（V03 的断言），与源码检索交叉核对一致。

| 资源 | 文档类型 | 状态 | 服务端处置 |
|---|---|---|---|
| `SHEET_CONDITIONAL_FORMATTING_PLUGIN`、`SHEET_DATA_VALIDATION_PLUGIN`、`SHEET_DEFINED_NAME_PLUGIN`、`SHEET_DRAWING_PLUGIN`、`SHEET_FILTER_PLUGIN`、`SHEET_NOTE_PLUGIN` | 表格 | 已验证（有样本） | 允许；做结构校验 |
| `SHEET_RANGE_PROTECTION_PLUGIN`、`SHEET_WORKSHEET_PROTECTION_PLUGIN`、`SHEET_WORKSHEET_PROTECTION_POINT_PLUGIN`、`SHEET_AuthzIoMockService_PLUGIN` | 表格 | 保护类 | 必须为空 |
| `SHEET_RANGE_THEME_MODEL_PLUGIN` | 表格 | 无法通过界面产生（界面在未注册的 sheets-table 插件里） | 必须为空 |
| `DOC_DRAWING_PLUGIN` | 文字文档 | 已验证 | 允许；做结构校验 |
| `DOC_HYPER_LINK_PLUGIN` | 文字文档 | 已验证 | 允许；必须与正文 `customRanges` 推导出的内容一致（加载时它会覆盖正文中的地址） |
| `DOC_OBJECT_PERMISSION_PLUGIN` | 文字文档 | 权限规则 | 必须为空 |
| `DOC_WORD_STYLES_PLUGIN`、`DOC_NOTE_PLUGIN` | 文字文档 | 只来自 Word 导入（本期不支持） | 必须为空 |

**结构要求**：资源名唯一（SDK 加载同名资源时只取第一条，重复条目可以让伪造数据生效）；`data` 必须是字符串。

**为什么保护类资源必须为空**：界面隐藏保护入口后，保护类资源只可能来自伪造或外部导入的快照。
- 本地模拟的授权服务在当前用户为空时，会把它设为 `Owner_<随机串>`，并按 id 前缀判断角色。所以表格页上人人都是"所有者"，受保护区域照样能编辑（V03 实测）。
- 但它会让界面显示保护阴影与锁图标，而解除入口已经隐藏。
- 平台以后如果设置真实用户身份，伪造的保护规则还可能变成"锁死编辑"（P2 报告 §2.5）。

P3 需要核实：阅读模式用到的 `setReadOnly` 会不会写入这些资源。

## 4. 档案变更规则

- 档案标识写进平台信封（00 号计划书 §8.1）。增删插件、改变影响数据的配置、升级 SDK，都视为数据格式变更，按 00 号计划书 §8.7 执行：先用 `fixtures/` 中的全部样本做保存重开回归（`e2e/v03-roundtrip.spec.ts`），再发布。回归会断言以下几项，任何一项不符都会失败：
  - 实际差异与基线（`e2e/v03-baselines.ts`）一致；
  - 语义与预期（`e2e/samples-expected.ts`）一致；
  - 档案声明的资源名与运行时 hook 一致。
- 白名单随档案版本维护：新增插件时，同步补充它的资源名、样本与回归用例。
