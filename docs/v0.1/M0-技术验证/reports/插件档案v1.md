## 1. 表格 `sheet@1`

插件按组注册，组内与组间的顺序都按官方 preset。"可单独去掉"表示其他组不依赖它；V04 用它复现插件缺失。

| 组 | 插件（注册顺序） | 写入快照的资源 | 可单独去掉 |
|---|---|---|---|
| core | Docs、RenderEngine、UI、DocsUI、（Worker 模式另加 RPCMainThread）、FormulaEngine、Sheets、SheetsUI | `SHEET_AuthzIoMockService_PLUGIN`、`SHEET_DEFINED_NAME_PLUGIN`、`SHEET_RANGE_THEME_MODEL_PLUGIN`、`SHEET_RANGE_PROTECTION_PLUGIN`、`SHEET_WORKSHEET_PROTECTION_PLUGIN`、`SHEET_WORKSHEET_PROTECTION_POINT_PLUGIN` | 否 |
| numfmt | SheetsNumfmt、SheetsNumfmtUI | — | 否 |
| formula | SheetsFormula、SheetsFormulaUI | — | 否 |
| drawing | Drawing、DocsDrawing、DrawingUI、SheetsDrawing、SheetsDrawingUI | `SHEET_DRAWING_PLUGIN`（浮动图片）。单元格图片存在单元格的富文本里 | 是 |
| cf | SheetsConditionalFormatting(UI) | `SHEET_CONDITIONAL_FORMATTING_PLUGIN` | 是 |
| filter | SheetsFilter(UI) | `SHEET_FILTER_PLUGIN` | 是 |
| hyperlink | SheetsHyperLink(UI) | —（链接存在单元格富文本的 `customRanges` 里） | 是 |
| dv | DataValidation、SheetsDataValidation(UI) | `SHEET_DATA_VALIDATION_PLUGIN` | 是 |
| find-replace | FindReplace、SheetsFindReplace | — | 是 |
| note | SheetsNote(UI) | `SHEET_NOTE_PLUGIN` | 是 |
| sort | SheetsSort(UI) | — | 是 |

**影响数据的配置**

- `UniverSheetsPlugin`：`onlyRegisterFormulaRelatedMutations: false`；`largeSheetOperation.largeSheetCellCountThreshold: Number.MAX_SAFE_INTEGER`（P3：关掉大表操作的拆分，复制大表同步执行，立即捕获也完整；删除大表不再清空撤销栈。P3 报告 §2.2）。
- **公式 Worker 模式（默认启用，P3 报告 §6.3）**：主线程的 `FormulaEngine`、`Sheets`、`SheetsFormula` 都设 `notExecuteFormula: true`，并注册 `RPCMainThread`。Worker 内注册 Sheets（`onlyRegisterFormulaRelatedMutations: true`）、FormulaEngine、RPCWorkerThread、RemoteSheetsFormula、SheetsFilter。
  - 理由：主线程模式下，一次牵动约 320 个公式的修改会冻结界面 0.66–0.83 秒，强制全量重算 0.71–0.89 秒（公式引擎默认每 500 个公式才让出一次主线程）；Worker 模式下计算期间帧间隔 p95 ≤ 34 ms，代价是多约 8–9 MiB 内存（性能样本，约 1 MiB）。
  - 前提：捕获时机按 P3 报告 §3.4（逐表收齐；计算进行中又有修改时等排队的下一轮）。
  - 退路：Worker 创建失败时，销毁实例并以主线程模式重建（Worker 模式下主线程的公式插件注册时就设了 `notExecuteFormula`，不能原地切换），`UniverFormulaEnginePlugin` 配置 `intervalCount: 20`（该样本的冻结降到 67–88 ms）。判定与重建流程由 M4 设计。
  - 待评估（M4）：Worker 内的让出间隔（默认 500 时 stop 基本不生效，计算进行中再改一处，最新结果约晚一倍）。
- 其余插件使用默认配置。

**不注册**：`@univerjs/network`（除它自身外没有任何包使用 `IHTTPService`）；表格的 table、线程评论、十字高亮、水印、action-recorder、slides、Vue/Web Component 适配器；不注册任何 `ITelemetryService` 实现。

## 2. 文字文档 `doc@1`

| 组 | 插件（注册顺序） | 写入快照的资源 | 可单独去掉 |
|---|---|---|---|
| core | Docs、RenderEngine、UI、DocsUI（配置 `toc: true`：只读的大纲侧栏） | `DOC_WORD_STYLES_PLUGIN`、`DOC_NOTE_PLUGIN`（导入 Word 时的元数据透传，平时为空）、`DOC_OBJECT_PERMISSION_PLUGIN` | 否 |
| layout-worker | DocsLayoutWorker（**暂不启用**：Worker 模式下，在表格单元格里键入后立即按 Tab，Tab 会丢失，后面的字写进同一格；修复前不启用，DEF-007 在 M6 重新评估。P5 报告 §5.3 第 4 条） | — | 是 |
| drawing | Drawing、DrawingUI、DocsDrawing、DocsDrawingUI | `DOC_DRAWING_PLUGIN`（图片同时存在正文的 `drawings` 里） | 是 |
| hyperlink | DocsHyperLink(UI) | `DOC_HYPER_LINK_PLUGIN`（链接同时存在正文的 `customRanges` 里；加载时以资源中的地址为准） | 是 |
| find-replace | FindReplace、DocsFindReplace | — | 是 |

**不注册**（P5）：
- 公式引擎：文字文档启用的插件都不依赖它，官方 preset 只是顺带注册；去掉后首屏 JS 从 5.13 MiB 降到 3.75 MiB（未压缩，−27%），gzip 后从 1.23 MiB 降到 0.99 MiB（−19%）（P5 报告 §5.3 第 5 条）。
- 目录块（DocsToc、DocsTocUI）：它在正文里写入 FIELD、HYPERLINK、PAGEREF 区间，页码在无分页版式下没有意义；"目录"由大纲侧栏提供（P5 报告 §5.3 第 3 条）。

**版式**：固定为 MODERN（无分页）。
- 加载时规范：版式改为 MODERN，去掉页眉页脚数据与表格之外多余的分节符（验证工程只实现了版式一项，其余由 M1 适配层补齐）；
- 服务端保存校验：只接受 MODERN；不接受页眉页脚；表格之外只允许文末一个分节符（表格的每个单元格里各有一个分节符，是正常结构）。
- 正常流程里，这些数据只可能来自缺陷，或者绕过客户端的请求。加载时的规范保证历史数据打开后仍能保存，保存时的拒绝不会挡住正常用户（P5 报告 §5.1）。

## 3. 资源名称白名单

以运行时注册、适用于本文档类型的资源 hook 为准（`e2e/results/v03/roundtrip/*.json` 的 `resourceHooks`）：三个浏览器一致，与各组声明的资源名自动核对一致（V03 的断言），与源码检索交叉核对一致。

| 资源 | 文档类型 | 状态 | 服务端处置 |
|---|---|---|---|
| `SHEET_CONDITIONAL_FORMATTING_PLUGIN`、`SHEET_DATA_VALIDATION_PLUGIN`、`SHEET_DEFINED_NAME_PLUGIN`、`SHEET_DRAWING_PLUGIN`、`SHEET_FILTER_PLUGIN`、`SHEET_NOTE_PLUGIN` | 表格 | 已验证（有样本） | 允许；做结构校验 |
| `SHEET_RANGE_PROTECTION_PLUGIN`、`SHEET_WORKSHEET_PROTECTION_PLUGIN`、`SHEET_WORKSHEET_PROTECTION_POINT_PLUGIN`、`SHEET_AuthzIoMockService_PLUGIN` | 表格 | 保护类 | 必须为空 |
| `SHEET_RANGE_THEME_MODEL_PLUGIN` | 表格 | 无法通过界面产生（界面在未注册的 sheets-table 插件里） | 必须为空 |
| `DOC_DRAWING_PLUGIN` | 文字文档 | 已验证 | 允许；做结构校验 |
| `DOC_HYPER_LINK_PLUGIN` | 文字文档 | 已验证 | 允许；必须与正文 `customRanges` 推导出的内容一致（加载时它会覆盖正文中的地址） |
| `DOC_OBJECT_PERMISSION_PLUGIN` | 文字文档 | 权限规则 | 必须为空 |
| `DOC_WORD_STYLES_PLUGIN`、`DOC_NOTE_PLUGIN` | 文字文档 | 只来自 Word 导入（本期不支持） | 必须为空 |

**结构要求**：资源名唯一（SDK 加载同名资源时只取第一条，重复条目可以让伪造数据生效）；`data` 必须是字符串。

**为什么保护类资源必须为空**：界面隐藏保护入口后，保护类资源只可能来自伪造或外部导入的快照。
- 本地模拟的授权服务在当前用户为空时，会把它设为 `Owner_<随机串>`，并按 id 前缀判断角色。所以表格页上人人都是"所有者"，受保护区域照样能编辑（V03 实测）。
- 但它会让界面显示保护阴影与锁图标，而解除入口已经隐藏。
- 平台以后如果设置真实用户身份，伪造的保护规则还可能变成"锁死编辑"（P2 报告 §2.5）。

P3 核实：表格的 `setReadOnly()` 要求先 `protect()`，会写入 `SHEET_WORKSHEET_PROTECTION_PLUGIN` 与 `SHEET_AuthzIoMockService_PLUGIN`，所以阅读模式不用它（§5.2）；文字文档的 `setReadOnly()` 在平台配置下不写资源。另外，设置真实用户身份后，本地授权服务连没有保护的单元格也不允许编辑（P3 报告 §5.3），平台不把真实用户交给它。

## 4. 档案变更规则

- 档案标识写进平台信封（00 号计划书 §8.1）。增删插件、改变影响数据的配置、升级 SDK，都视为数据格式变更，按 00 号计划书 §8.7 执行：先用 `fixtures/` 中的全部样本做保存重开回归（`e2e/v03-roundtrip.spec.ts`），再发布。回归会断言以下几项，任何一项不符都会失败：
  - 实际差异与基线（`e2e/v03-baselines.ts`）一致；
  - 语义与预期（`e2e/samples-expected.ts`）一致；
  - 档案声明的资源名与运行时 hook 一致。
- 白名单随档案版本维护：新增插件时，同步补充它的资源名、样本与回归用例。

### 5.2 阅读模式

- **界面**（进入阅读模式时二选一）：
  - 销毁重建：`UniverUIPlugin` 的 `toolbar: false`、`contextMenu: false`；表格另设 `UniverSheetsUIPlugin` 的 `footer.menus: false`（底栏的网格线开关会写进快照）与 `footer.addSheetButtonConfig.show: false`；再隐藏工作表标签菜单里的 `sheet.command.remove-sheet-confirm`、`sheet.command.copy-sheet`、`sheet.operation.rename-sheet`、`sheet.command.set-tab-color`、`sheet.command.set-worksheet-hidden`。
  - 原地切换：`univerAPI.setUIVisible(BuiltInUIPart.TOOLBAR, false)` 隐藏工具栏，`IContextMenuService.disable()` 停用右键菜单，`IMenuManagerService.updateMenuConfig` 隐藏上面 5 项与 `sheet.command.toggle-gridlines`；新增工作表按钮在工作簿不可编辑时自动变为禁用。退出时逐项恢复。
- **拦截**（编辑器适配层实现，代码：`spikes/m0/src/harness/read-mode.ts` 的 `combined`）：
  - 权限点：表格 `FWorkbook.setEditable(false)`，并用 `IPermissionService` 把工作表的权限点设为 false，**保留"查看"（`WorksheetViewPermission`）与"复制"（`WorksheetCopyPermission`）**，不创建保护规则；文字文档用公开的 `FDocument.getPermission().setReadOnly()`（平台不配置 `objectPermissionTypes`，它只设本地权限点，不写资源）；
  - mutation 防火墙：`BeforeCommandExecute` 取消作用于本文档（参数里的 `unitId` 等于本文档，或没有 `unitId`）的非本地 mutation。**不能拦其他单元的 mutation**：单元格编辑器（内部文档单元）的内容同步也是非本地 mutation，拦住它会让之后的编辑写错内容；
  - `BeforeUndo`、`BeforeRedo` 取消撤销重做；`IUndoRedoService.clearUndoRedo` 清空撤销栈。
- 不使用 `FWorksheetPermission.setReadOnly()`（要求先 `protect()`，会写入保护类资源，还会禁止复制）。

### 5.3 变更检测排除名单

| 文档类型 | 排除的 mutation | 原因 |
|---|---|---|
| 表格 | `sheet.operation.clear-drawing-transformer` | 类型声明为 `MUTATION`，实际只清除界面上的图片变换框 |
| 文字文档 | `doc.operation.clear-drawing-transformer` | 同上 |

- 这两个命令没有出现在打开文档的数据里。表格的这一条单独出现时，正好是 DEF-002 的刷新路径改了图片的派生尺寸（`sheet-drawing-transform-affected.controller.ts:330-337`）；排除它意味着这类变化只随下一次修改保存，与 DEF-002 的处理一致。
- 规则的其余部分（只看 `MUTATION`、排除 `onlyLocal` 等选项、排除其他单元）与捕获时机见 P3 报告 §2.1、§3.4。**不排除**自动行高。
- 排除 `onlyLocal` 的前提：以 `onlyLocal` 修改持久化内容的路径（备注、超链接的位置联动，公式文本的引用更新等）都紧随一次被检测到的修改，由同一次捕获带上。
- 排除名单随 SDK 版本维护，由 `e2e/v06-open-quiet.spec.ts`、`e2e/v06-actions.spec.ts` 回归。

## 6. 图片与外部请求（P4）

代码：`spikes/m0/src/profiles/image-service.ts`、`src/harness/platform-image-io.ts`、`image-guards.ts`、`image-function-policy.ts`。方案与依据见 P4 报告 §1.2。

### 6.1 图片服务

- **表格与文字文档**：`UniverDrawingPlugin` 配置 `override: [[IImageIoService, { useClass: 平台图片服务 }]]`。
- 平台图片服务的约定：
  - `saveImage` 上传后返回 `URL` 类型的同源相对地址 `/api/assets/{assetId}`；
  - `base64Cache` 用同一个地址；
  - `imageId` 每次随机生成；
  - 失败按 `ImageUploadStatusType` 拒绝；
  - `change$` 在上传开始时发出正数、结束时回到 0；
  - 加载失败的元素从缓存中删除。
- **格式对齐**：启动时把 `DRAWING_IMAGE_ALLOW_IMAGE_LIST`（`@univerjs/drawing`）与 `imageMimeTypeSet`（`@univerjs/ui`）改为 PNG、JPEG、GIF、WebP。
- **编辑器适配层另外安装**（不是插件配置，但属于档案的一部分）。"图片地址"指任何深度上名为 `source` 的字段，一律默认拒绝：
  - 文字文档剪贴板钩子：
    - `onBeforePasteImage` 上传，适配层要断言自己是第一个注册它的钩子；
    - `onBeforePaste` 处理整个粘贴内容（包括内部片段）：规范本站地址；`drawings` 里的非平台地址替换成占位图；文字填充图片整项去掉；其他位置去掉持有 `source` 的一项；
  - 命令守卫：参数里有非平台 `source` 的命令一律取消；
  - 表格复制补救：复制 `URL` 类型的浮动图片时，在 SDK 写空文本之后，把同源图片转成 PNG 写入剪贴板（`ISheetClipboardService.addClipboardHook`）。

### 6.2 `IMAGE()`

- 采用 `restricted`：只接受平台资源地址，其余返回 `#VALUE!`，不发请求；
- 在主线程与公式 Worker 里各装一次，都在生命周期 Ready 之后。

### 6.3 CSP（定稿建议；P5 在文字文档的字体、排版 Worker、中文输入与粘贴场景下复核，结论不变）

```
default-src 'self'; img-src 'self' data: blob:; connect-src 'self'; font-src 'self'; style-src 'self' 'unsafe-inline'; script-src 'self'; worker-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
```

- `img-src data:`：表格界面的图标；
- `img-src blob:`：文字文档粘贴图片时量尺寸；
- `style-src 'unsafe-inline'`：界面与剪贴板的内联样式；
- 策略必须随所有响应下发，包括 Worker 脚本。

## 7. 文字文档的平台策略（P5）

代码：`spikes/m0/src/harness/doc-policy.ts`；依据见 P5 报告 §1.2、§7。编辑器适配层在文字文档上安装（不是插件配置，但属于档案的一部分）：

- **`/` 键**：SDK 在任何位置吞掉 `/`。平台在捕获阶段处理两条路径：keydown，以及 `insertText` 的 beforeinput（不经过 `/` 键的输入，例如系统文字替换）。只在表格之外的空段落里交给 SDK 弹出 `/` 菜单，其他位置由平台插入 `/`，沿用左侧文字的样式与链接；文档不可编辑时不介入。
- **输入法事件归一**：`compositionend` 的数据与最后一次 `compositionupdate` 不同时（WebKit 的提交顺序，SDK 在这种顺序下撤销记录出错）：
  - 先补发一次携带最终文字的 `compositionupdate`；
  - `compositionend` 延后一个宏任务派发；
  - 延后期间来了 keydown、beforeinput、input、compositionstart、focusout、mousedown 或 paste，先同步派发 `compositionend`，否则这些输入会被 SDK 当成组合中的输入丢掉。
- **命令守卫**（取消的命令不执行，也不进撤销栈）：
  - 不支持的功能：取消 15 个命令，涵盖切换版式、页面设置、分节与分节符、分栏符、页眉页脚、形状（清单见 `UNSUPPORTED_DOC_COMMANDS`）；
  - 链接：添加与修改链接时，地址按白名单规范化（见下），不合法就取消，写法不规范就改成规范写法再执行；
  - 单元格里的图片：插入图片、移动内联图片、拖动浮动图片的目标位置在表格单元格里时取消；锚点在单元格里的图片不能改为内联。
- **链接地址白名单与规范写法**（`normalizeLinkUrl`，命令守卫、粘贴清洗与服务端保存校验共用同一规则）：
  - 含控制字符（制表符、换行等）的一律拒绝；
  - `http`、`https`、`mailto` 保存 URL 解析后的 `href`（引号、尖括号、空格被百分号编码）；
  - 本站相对地址按站点源解析，结果必须仍在本站，保存解析后的路径；
  - `#` 锚点不能含空白、引号与尖括号；
  - 服务端要求保存的地址等于它的规范写法。
- **粘贴清洗**（与 §6.1 的图片钩子并存，按注册顺序执行，覆盖内部片段）：
  - 链接地址按白名单规范化，不合法的去掉；纯文本粘贴时，SDK 把整段文字当成链接地址，链接文字本身合法时改用链接文字；
  - 去掉表格之外的分节符；
  - 粘贴目标在表格单元格里时，去掉图片。
- **捕获时机**（补充 P3 报告 §3.4）：
  - 组合输入进行中不捕获；防抖从"最后一次修改"与"最后一次组合结束"中较晚的一个算起；
  - 组合持续超过 3 秒就照常捕获（与 00 号计划书 §7.2"持续编辑时最长每 3 秒捕获一次"一致）；
  - 隐藏输入元素失焦时，复位组合状态。
