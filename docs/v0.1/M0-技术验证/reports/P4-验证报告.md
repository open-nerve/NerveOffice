# P4 验证报告：资源与外部请求

> 日期：2026-09-25｜所属：M0-P4｜Univer 版本：1.0.0｜验证工程：`spikes/m0/`

## 摘要

| 编号 | 验证项 | 结论 | 一句话 |
|---|---|---|---|
| V11 | 替换图片服务，以及同源读取 | **通过** | 按 §1.2 的方案（替换图片服务 + 文字文档剪贴板钩子 + 命令守卫 + 服务端保存校验 + 隐藏形状入口），22 条路径在三个浏览器中的结果：<br>• 新增的图片全部是同源地址 `/api/assets/{id}`；<br>• 或者被替换成平台占位图、被命令守卫取消、被 SDK 丢弃。<br>读取走会话 Cookie，`crossOrigin="anonymous"` 的请求也带上了它；"能读引用它的文档，或者是 24 小时内的上传者"的授权、复制文档只加引用、服务端拒绝非平台地址的快照，都按设计工作。<br>对照：SDK 默认的图片服务把图片存成 data URL，文字文档粘贴时还会原样写进外链、`file:`、`blob:` 地址 |
| V12 | 外链图片、`IMAGE()` 与 CSP | **通过** | • 严格 CSP 下，所有外链图片的加载都被拦截并上报。<br>• 平台方案下，粘贴外链图片、`IMAGE()` 都不再发出任何外部请求：`IMAGE()` 只接受平台地址，主线程与 Worker 都生效。<br>• 功能降级可以接受：只有"复制浮动图片到外部应用"不再可用；"保存单元格图片"反而由不可用变为可用。<br>• CSP 定稿：`img-src data: blob:` 与 `style-src 'unsafe-inline'` 必要；`font-src data:`、`worker-src blob:` 在 P1–P4 的全部场景中都没有用到，建议去掉，由 P5 复核 |

**另有三条影响设计的发现**：

- **读取失败时 SDK 会抛出未捕获的异常**：图片读取返回 401 或 403 时，表格渲染会对破损的图片调用 `drawImage`，抛出 `InvalidStateError`。三个浏览器都出现过，时有时无。服务端改为返回平台占位图（200，状态放在响应头里）后，三个浏览器都不再出现（§2.3 第 3 条）。
- **表格粘贴"浏览器复制图片"会丢失图片**：浏览器"复制图片"时，剪贴板里同时有图片文件和一段只有外链 `<img>` 的 HTML。表格按 HTML 粘贴，丢掉了图片，两种图片服务都一样（§2.3 第 4 条）。
- **拖放图片文件没有处理**：SDK 阻止了 `dragover` 的默认行为，却没有阻止 `drop` 的，也不插入图片。真实拖入文件时，浏览器可能直接打开这个文件，离开编辑页（§3.3 第 4 条）。

**环境**：与 P3 相同：
- macOS 26.5.1、Apple M4 Pro；
- Playwright 1.63.0（无头），自带的 Chromium 153、本机 Google Chrome 153、Playwright 自带的 WebKit 26.6。

表格都带 `worker=1`（P3 起默认启用公式 Worker）。

**验证范围**：
- 粘贴用合成的 `paste` 事件：把文件和 HTML 放进 `DataTransfer`，派发到编辑器获得焦点的输入元素，与快捷键粘贴走同一条路径（`DocSelectionRenderService.onPaste$`）。三个浏览器都可用。
- 内部复制粘贴用真实的快捷键。
- 插入图片的文件选择框用 Playwright 的 `filechooser` 事件。触发它的命令与工具栏按钮相同。
- 真实剪贴板、真实文件拖放与真实 Safari 的复核，登记为 DEF-004。

## 1. 验证工程与方案

### 1.1 验证工程

| 位置 | 内容 |
|---|---|
| `server/assets.ts` | 资源的最小实现：<br>• 按文件头识别 PNG、JPEG、WebP、GIF，读出宽高；单张不超过 5 MiB，像素上限取 4,000 万作验证值；<br>• 每次上传生成独立的 assetId，文件按 SHA-256 去重；<br>• 读取要求会话 Cookie；授权条件是能读引用它的文档，或者是 24 小时内的上传者；<br>• 平台内置一张占位图；<br>• `--asset-fallback` 模式下，读取失败时返回占位图 |
| `server/snapshot-images.ts` | 快照中的图片地址：<br>• 结构化提取：任何同时带 `source` 与 `imageSourceType`（或 `sourceType`）的对象，资源数据先解析再遍历；<br>• 通用扫描：找出所有带 `data:`、`http(s):`、`blob:`、`file:` 的字符串，用来发现结构化提取漏掉的位置；<br>• 分类；引用关系按 `/api/assets/{uuid}` 模式从快照文本扫描得出 |
| `server/serve.ts` | 页面响应下发会话 Cookie（`HttpOnly`、`SameSite=Strict`）；保存文档时更新引用关系；`validate=1` 时拒绝含非平台图片地址的快照；复制文档只复制引用关系 |
| `src/harness/platform-image-io.ts` | 平台图片服务（`IImageIoService` 的实现） |
| `src/harness/image-guards.ts` | 文字文档剪贴板钩子、命令守卫 |
| `src/harness/image-function-policy.ts` | `IMAGE()` 的 `off` 与 `restricted`，主线程与公式 Worker 共用。Worker 的策略经 Worker 的 `name` 传入 |
| `e2e/v11-*.spec.ts`、`e2e/v12-*.spec.ts`、`e2e/p4-helpers.ts` | 用例与测试辅助；汇总脚本 `scripts/p4-summary.ts` |

页面参数：`img=default|platform`（缺省 `default`，保持 SDK 行为，P1–P3 的用例不受影响）、`imagefn=default|off|restricted`。

### 1.2 平台方案（建议写入 00 号计划书 §8.5、§11.3，由 M5 实现）

1. **替换图片服务**：
   - `UniverDrawingPlugin` 配置 `override: [[IImageIoService, { useClass: 平台图片服务 }]]`（`packages/drawing/src/plugin.ts:60-69`）。表格与文字文档都要注册；官方 preset 不开放 `override`，档案本来就逐个注册插件。
   - 平台图片服务的约定（SDK 的调用方有硬性要求）：
     - `saveImage` 先在客户端检查类型与大小，再上传，返回 `URL` 类型的同源相对地址；
     - `base64Cache` 用同一个同源地址（插入流程用它量尺寸，必须能加载）；
     - `imageId` 每次随机生成，不用 assetId：它直接当作 drawingId，而服务端按内容去重，同一张图可能被插入多次；
     - 失败时以 `Error(ImageUploadStatusType.X)` 拒绝，SDK 才会显示本地化提示：413 映射为"大小超过限制"，415 为"类型错误"，其他为"无效图片"；
     - `change$` 在上传开始时发出正数、结束时回到 0；
     - 加载失败的元素从缓存中删除（SDK 的渲染服务会一直复用缓存中的元素）。
2. **文字文档剪贴板钩子**（`IDocClipboardService.addClipboardHook`，内部 API），表格的单元格编辑器与编辑栏也用它：
   - `onBeforePasteImage`：粘贴的图片文件、HTML 里的 `data:` 图片改为上传。默认实现把它们读成 data URL，不经过图片服务。
   - `onBeforePaste`：插入前检查 `documentData.drawings`。本站的绝对地址规范回相对地址：粘贴的图片要经过 HTML 转换，相对地址会变成绝对地址，§2.3 第 2 条。外链、`file:`、`blob:`、`data:` 等非平台地址，替换成平台内置的占位图；不删除图片对象，避免破坏正文里的占位字符。
3. **命令守卫**（`BeforeCommandExecute`，公开 API，纵深防御）：命令参数里带非平台地址的图片时取消。它覆盖平台代码的误用与未知路径，例如 Facade 的字符串参数接口。
4. **服务端保存校验**：快照中的图片地址只接受平台资源地址，存储前把本站的绝对地址改写为相对地址。结构化提取之外，再用通用扫描兜底。
5. **隐藏入口**：
   - 文字文档的形状：`doc.command.menu-insert-shape`、`doc.command.menu-insert-shape.below`（00 号计划书 §4.3 已要求隐藏；否则按钮会被命令守卫取消，点了没有反应）；
   - 表格的工作表背景图：P3 已隐藏。
6. **读取**：
   - `/api/assets/{id}` 用会话 Cookie 鉴权；
   - 读取失败时返回平台占位图（200，状态放在 `X-Asset-Status` 头里），而不是 4xx（§2.3 第 3 条）；
   - 响应带 `X-Content-Type-Options: nosniff`，只接受四种位图，不接受 SVG。
7. **`IMAGE()`**：采用 `restricted`：参数是平台资源地址时交给原执行器，否则返回 `#VALUE!`。在主线程与公式 Worker 里各装一次（§3.2）。

## 2. V11 替换图片服务，以及同源读取

### 2.1 结论：通过

- **路径矩阵**：22 条路径 × 两种图片服务 × 三个浏览器（132 个用例）全部完成。
  - 平台方案下，没有任何路径在快照里留下非平台地址；
  - 默认实现下，有 15 条路径写入 data URL、外链、`file:` 或 `blob:` 地址（§2.2）。
- **同源读取**：
  - 重开文档时，所有读取都带会话 Cookie 并成功。浮动图片以 `crossOrigin="anonymous"`（`Sec-Fetch-Mode: cors`）读取，单元格图片以普通方式（`no-cors`）读取，两者都带上了 Cookie；

- **复制文档**：只增加引用关系（文件数不变）；原文档删除后，副本里的图片仍能读。
- **失败与限制**：
  - 服务端 503、客户端超过 5 MiB、SVG、伪装成 PNG 的 HTML，都不插入图片，并给出 SDK 的本地化提示（"无效图片""图片大小超过限制""图片类型错误"）；

### 2.3 发现

1. **需要处理的路径只有文字文档的粘贴与 Facade 的字符串接口**：
   - 所有经过 `saveImage` 的入口（工具栏、表格粘贴图片文件），替换图片服务就够了；
   - 文字文档的粘贴（文件、`data:`、外链）不经过图片服务，必须用剪贴板钩子；
   - Facade 的字符串接口原样写入，由命令守卫与服务端校验兜底。平台不向用户开放 Facade 与脚本，这些接口只有平台代码能调用。
2. **相对地址在粘贴中会变成绝对地址**：
   - 文字文档粘贴图片文件时，钩子返回的相对地址要先拼进 HTML，再由 HTML 转换读回。转换读的是 `element.src`，得到的是解析后的绝对地址（`packages/docs-ui/src/services/clipboard/html-to-udm/converter.ts:178-208`）；
   - 钩子在 `onBeforePaste` 里把本站的绝对地址规范回相对地址（D3、D4、D6 都触发了）；
   - 内部复制粘贴（D7、S8）复用原地址，没有这个问题。
3. **读取失败时 SDK 会抛出未捕获的异常**：
   - **现象**：图片读取返回 401、403，或被 CSP 拦截时，表格渲染可能对破损的图片调用 `drawImage`，抛出 `InvalidStateError`；文字文档在外链被 CSP 拦截时也会抛出（D5）。三个浏览器都出现过，时有时无；SDK 默认的图片服务同样会出现，与平台图片服务无关。
   - **缓解**：服务端对读取失败返回平台占位图（200，真实状态放在 `X-Asset-Status` 头里），实测三个浏览器都不再出现，图片位置显示占位图。
   - **代价**：客户端无法从 `<img>` 得知真实状态；会话过期等情况由平台的其他请求发现。
   - 建议向上游报告。
4. **表格粘贴"浏览器复制图片"会丢失图片**（S5c）：
   - 浏览器"复制图片"时，剪贴板里同时有 `image/png` 和一段只有外链 `<img>` 的 HTML；
   - 表格只在 HTML 中含 `data:` 图片时才改走图片文件的粘贴（`packages/sheets-ui/src/services/clipboard/utils.ts:120-131`），其他情况按 HTML 粘贴，而 HTML 转换会丢掉 `<img>`；
   - 结果是什么也没粘贴进来，两种图片服务都一样；
   - 这不是安全问题，是可用性缺口。M5 可以在表格的粘贴钩子里判断"HTML 只有图片、同时有图片文件"，改为粘贴文件。
5. **编辑栏里粘贴图片会留下孤儿文件**（S7）：钩子先上传再插入，编辑栏不接受图片，SDK 报错，上传的文件没有被引用。孤儿由资源回收处理（00 号计划书 §8.5 的宽限期）。也可以在钩子里判断目标编辑器，编辑栏与单元格编辑器不上传。
6. **引用关系扫描**：
   - 按 `/api/assets/{uuid}` 模式扫描快照文本，能找到三类位置的全部平台地址：浮动图片（资源数据是 JSON 文本，其中的地址没有被转义）、单元格图片、文字文档的正文与资源。不需要理解 Univer 的内部结构（00 号计划书 §8.5）；
   - 通用扫描在平台方案的快照里没有发现结构化提取之外的图片地址。

### 2.4 对设计的影响

- **00 号计划书 §8.5**：

## 3. V12 外链图片、`IMAGE()` 与 CSP

### 3.1 结论：通过

- **外链图片**：
  - 默认实现下，文字文档粘贴外链图片、Facade 传入外链时，关掉 CSP 会实际发出外部请求（每条路径 1 次）；严格 CSP 下都被拦截并上报（强制违规 1 次）。
  - 平台方案下，粘贴外链图片与 `FDocument.insertImage(外链)` 都不再发出任何外部请求。
- **`IMAGE()`**：三种处理 × 两种模式 × 三个浏览器（36 组）：
  - `default` 对外链照常加载：关掉 CSP 时发出请求，严格 CSP 下被拦截、显示 `#VALUE!`；
  - `restricted` 只显示平台地址的图片，外链与 data URL 都显示 `#VALUE!`，没有外部请求、没有 CSP 违规；
  - `off` 全部显示 `#NAME?`；
  - 快照里只有公式字符串。
- **功能降级**：
  - 换成同源地址后，只有"复制浮动图片到外部应用"不可用（剪贴板为空），内部复制粘贴仍可用；
  - "保存单元格图片"在默认实现下被 `connect-src 'self'` 拦截（`fetch(data:)`），平台方案下可以正常下载；
  - 双击预览、移动图片不受影响。
- **CSP**：
  - 严格策略下，平台方案的所有代表性路径没有强制违规；
  - 探测策略显示：`img-src data:`（表格界面的图标，加载时 84 次）、`img-src blob:`（文字文档粘贴图片时量尺寸）、`style-src 'unsafe-inline'` 必要；
  - `font-src data:`、`worker-src blob:` 从未触发。

### 3.2 证据

- 命令：`npx playwright test e2e/v12-external.spec.ts e2e/v12-degradation.spec.ts`（8 + 3 个用例 × 3 个浏览器，全部通过）
- 结果：`e2e/results/v12/image-formula/`、`external-images/`、`degradation/`、`csp/`；汇总：`node scripts/p4-summary.ts formula external degradation csp`
- 外部请求在关掉 CSP 的服务上计数：`page.route` 拦截所有非本站请求。被 CSP 拦截的请求在发出前就被取消，请求记录里看不到。

**`IMAGE()`**（三个浏览器、主线程与 Worker 相同）：

| 处理 | 外链 | 平台地址 | data URL | 外部请求（关掉 CSP） | 严格 CSP 下的强制违规 |
|---|---|---|---|---|---|
| `default` | `#VALUE!`（加载失败） | 图片 | 图片 | 1 | 1 |
| `restricted` | `#VALUE!` | 图片 | `#VALUE!` | 0 | 0 |
| `off` | `#NAME?` | `#NAME?` | `#NAME?` | 0 | 0 |

- `restricted` 的实现：启动时从 `IFunctionService` 取出原有的 `IMAGE` 执行器，注册一个同名的包装：参数是平台地址时交给原执行器，否则返回 `#VALUE!`（`src/harness/image-function-policy.ts`）。
- 内置函数在公式引擎插件 `onReady` 时注册（`packages/engine-formula/src/controllers/formula.controller.ts:135-147`），所以包装要在生命周期到达 Ready 之后安装。主线程与 Worker 都报告安装成功。

**外链图片的外部请求**（关掉 CSP，三个浏览器相同）：

| 路径 | 默认实现 | 平台方案 |
|---|---|---|
| 文字文档粘贴外链图片 | 1 | **0**（钩子在插入前替换） |
| `FDocument.insertImage(外链)` | 1 | **0**（命令守卫取消，给了宽高就不量尺寸） |
| `FWorksheet.insertImage(外链)` | 1 | **1**（量尺寸发生在命令之前，命令守卫来不及介入；严格 CSP 下被拦截） |

**功能降级**（严格 CSP）：

| 功能 | 默认实现 | 平台方案 |
|---|---|---|
| 复制浮动图片到系统剪贴板（Chromium 内核） | `image/png` | **剪贴板为空**（SDK 对 `URL` 类型只写空文本，`packages/sheets-drawing-ui/src/controllers/sheet-drawing-copy-paste.controller.ts:148-153`） |
| 保存单元格图片（单张直接下载） | **失败**：`fetch(data:)` 被 `connect-src 'self'` 拦截 | 下载成功（同源 `fetch`） |
| 双击预览 | 加载 | 加载 |
| 移动图片（`setPositionAsync`） | 正常 | 正常，没有错误 |
| 拖放图片文件（合成事件） | SDK 阻止了 `dragover`，没有阻止 `drop`，不插入 | 同左 |

- 默认实现"移动图片"一栏记录到的 2 个页面错误，来自之前那一步"保存单元格图片"失败的控制台输出，与移动无关。
- 无头 WebKit 不能读剪贴板，第一行只在 Chromium 内核上测。

**CSP：平台方案下的违规**（强制策略 / 探测策略；探测策略去掉 `data:`、`blob:`、`'unsafe-inline'`，只报告）：

| 步骤 | 强制策略 | 探测策略 |
|---|---|---|
| 表格：加载 `sheet-all` | 0 | `img-src data:` × 84、`style-src-elem` 内联 × 4 |
| 表格：插入、内部复制粘贴、单元格图片、粘贴文件、`IMAGE()` | 0 | `style-src-attr` 内联 × 2（Chromium 内核；WebKit 0） |
| 文字文档：加载 `doc-all` | 0 | `style-src-elem` 内联 × 4 |
| 文字文档：插入、粘贴文件、粘贴外链 HTML、全选复制粘贴 | 0 | `img-src blob:` × 1、`style-src-attr` 内联 × 32、`style-src-elem` 内联 × 1（WebKit 只有 `blob:` × 1） |

### 3.3 发现

1. **`IMAGE()` 选 `restricted`**：
   - 它保留了用平台图片做单元格插图的能力，外链与 data URL 一律 `#VALUE!`，不发请求；
   - 包装依赖 `IFunctionService`（内部 API，§4 登记），要在主线程与 Worker 里各装一次；
   - `off` 更简单，但会让已有的 `IMAGE()` 全部变成 `#NAME?`。
2. **CSP 的 `img-src blob:` 必要**：文字文档粘贴图片文件时，SDK 用 `URL.createObjectURL(file)` 量尺寸（`packages/docs-ui/src/services/clipboard/clipboard.service.ts:1121-1132`）。这是 P1 留下的问题的答案。
3. **Facade 的"先量尺寸再插入"会在命令之前发出请求**：
   - `FWorksheet.insertImage(url)`、`FRange.insertCellImageAsync(url)` 在执行命令之前就用 `new Image()` 加载地址量尺寸，命令守卫来不及介入；
   - 严格 CSP 下这个加载被拦截，插入中止并抛出错误；
   - 平台代码不应以外链调用它们。
4. **拖放**：
   - SDK 阻止了 `dragover` 的默认行为，却没有阻止 `drop` 的，也不处理文件（`packages/engine-render/src/engine.ts:889-891、951-960`）；
   - 真实拖入文件时，浏览器的默认行为是打开这个文件，可能离开编辑页。合成事件不会触发这个默认行为，本 Phase 无法自动验证，登记为 DEF-004；
   - 建议宿主在编辑器容器上拦截 `drop`：阻止默认行为，把图片文件交给平台图片服务插入。
5. **"复制浮动图片到外部应用"不可用**：SDK 对 `URL` 类型的图片只往系统剪贴板写空文本。可以接受：内部复制粘贴不受影响。需要时，可以由平台的表格剪贴板钩子读取同源图片再写入剪贴板（M5 评估）。

### 3.4 对设计的影响

- **00 号计划书 §11.3**：
  - 写明"粘贴清洗"的做法（§1.2 第 2 条）；
  - "限制 `IMAGE()`"采用 `restricted`；
  - CSP 定稿见下一条。
- **CSP 定稿**（相对 00 号计划书 §11.3 的起点策略）：

  ```
  default-src 'self'; img-src 'self' data: blob:; connect-src 'self'; font-src 'self'; style-src 'self' 'unsafe-inline'; script-src 'self'; worker-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
  ```

  - 去掉 `font-src data:` 与 `worker-src blob:`：P1–P4 的全部场景都没有用到；
  - 文字文档的字体与排版 Worker 由 P5 复核；
  - 策略必须随所有响应下发，包括 Worker 脚本（P1）。
- **插件档案 v1**：补充 `IMAGE()` 的处理（§6）。
- **M5**：
  - 宿主拦截 `drop` 并插入图片；
  - 评估"复制浮动图片到外部应用"的补救。

## 4. 内部 API 登记

本 Phase 的方案用到下列内部 API，M1 的编辑器适配层必须集中封装并登记（00 号计划书 §10.1）：

| 用途 | 内部 API 或约定 | 说明 |
|---|---|---|
| 替换图片服务 | `IImageIoService`（`@univerjs/core` 导出）、`UniverDrawingPlugin` 配置的 `override` | 插件配置是公开的；服务接口与它的约定（`base64Cache`、`imageId`、错误码、`change$`）没有文档保证 |
| 文字文档剪贴板钩子 | `IDocClipboardService.addClipboardHook`（`@univerjs/docs-ui` 导出）的 `onBeforePasteImage`、`onBeforePaste` | 只有第一个注册 `onBeforePasteImage` 的钩子生效 |
| `IMAGE()` 的限制 | `IFunctionService.getExecutor` / `registerExecutors` / `unregisterExecutors` / `deleteFormulaAstCacheKey`、`IDescriptionService.unregisterDescriptions`（`@univerjs/engine-formula` 导出）、`BaseFunction` | 要在生命周期 Ready 之后安装，主线程与 Worker 各一次 |
| 命令守卫 | —（Facade 的 `BeforeCommandExecute` 事件，公开 API） | 按参数里带 `source` 与 `imageSourceType` 的对象判断 |
| 验证用 | `window.__m0.images.io()`（取出图片服务） | 只用于验证 |
