## 摘要

| 编号 | 验证项 | 结论 | 一句话 |
|---|---|---|---|
| V11 | 替换图片服务，以及同源读取 | **通过** | 按 §1.2 的方案，27 条路径 × 两种图片服务 × 三个浏览器的结果是：平台方案下，快照里新增的图片全部是同源地址 `/api/assets/{id}`（含平台占位图），或者按预期被丢弃、去掉、取消，张数也都符合预期。<br>方案的组成：<br>• 替换图片服务；<br>• 对粘贴内容与命令参数"默认拒绝"：任何位置的 `source` 字段不是平台地址就处理掉；<br>• 服务端保存校验；<br>• 保存时只为有权读取的图片建立引用；<br>• 隐藏形状入口；<br>• 对齐图片格式；<br>• 表格复制补救。<br>其他结果：<br>• 读取走会话 Cookie，`crossOrigin="anonymous"` 的请求也带上了它；<br>• 引用授权、复制文档只加引用、服务端拒绝一切非平台地址（含构造的快照），都按设计工作。<br>对照：SDK 默认的图片服务把图片存成 data URL，文字文档粘贴时还会原样写进外链、`file:`、`blob:` 地址 |
| V12 | 外链图片、`IMAGE()` 与 CSP | **通过** | • 严格 CSP 下，所有外链图片的加载都被拦截并上报。<br>• 平台方案下，粘贴外链图片（含"内部片段"里的文字填充图片与数组地址）、`FDocument.insertImage(外链)` 都不再发出外部请求。<br>• `IMAGE()` 只接受平台地址。<br>• 功能降级可以接受：复制浮动图片（包括跨文档）由平台的复制补救恢复，"保存单元格图片"由不可用变为可用。<br>• CSP 定稿：`img-src data: blob:` 与 `style-src 'unsafe-inline'` 必要；`font-src data:`、`worker-src blob:` 建议去掉，由 P5 复核 |

**另有几条影响设计的发现**：

- **文字文档粘贴"内部片段"会绕过 HTML 转换**：HTML 里的 `<!--univer-doc-fragment:…-->` 注释会被 SDK 直接采用，任何网页都能在复制时放进剪贴板。片段里的文字填充图片、数组形式的地址、没有类型字段的图片，只做"看 `drawings` 里的字符串地址"的检查拦不住。平台的钩子、命令守卫与服务端校验都必须对任何位置的 `source` 字段默认拒绝（§2.3 第 1 条；审查 R1）。
- **引用关系必须经过授权**：只要把别人的地址写进自己的文档并保存，就能获得读取权。所以保存时，只为保存者有权读取的图片建立引用（§2.3 第 2 条；审查 R2）。
- **读取失败时 SDK 会抛出未捕获的异常**：图片读取返回 401 或 404 时，表格渲染可能对破损的图片调用 `drawImage`，抛出 `InvalidStateError`。服务端改为返回平台占位图后，三个浏览器都不再出现；但截断的图片、网络失败仍会触发，根因在 SDK（§2.3 第 3 条）。
- **SDK 的几处可用性缺口**（与平台方案无关）：
  - 表格粘贴"浏览器复制图片"会丢图；
  - 编辑栏里粘贴图片无效；
  - 拖放图片文件没有处理，浏览器可能直接打开文件。

**环境**：与 P3 相同：
- macOS 26.5.1、Apple M4 Pro；
- Playwright 1.63.0（无头），自带的 Chromium 153、本机 Google Chrome 153、Playwright 自带的 WebKit 26.6。

表格都带 `worker=1`（P3 起默认启用公式 Worker）。

**验证范围**：
- 粘贴用合成的 `paste` 事件：把文件与 HTML 放进 `DataTransfer`，派发到编辑器获得焦点的输入元素，与快捷键粘贴走同一条路径（`DocSelectionRenderService.onPaste$`），三个浏览器都可用。
- 内部复制粘贴用真实的快捷键。
- 插入图片的文件选择框用 Playwright 的 `filechooser` 事件，触发它的命令与工具栏按钮相同。
- 跨文档复制只在 Chromium 内核上测（无头 WebKit 不能读写剪贴板）。
- 真实剪贴板、真实文件拖放、右键菜单粘贴与真实 Safari 的复核，登记为 DEF-004。

## 1. 验证工程与方案

### 1.1 验证工程

| 位置 | 内容 |
|---|---|
| `server/assets.ts` | 资源的最小实现：<br>• 按文件头识别 PNG、JPEG、WebP、GIF，读出宽高；单张不超过 5 MiB，像素上限取 4,000 万作验证值；<br>• 每次上传生成独立的 assetId，文件按 SHA-256 去重；<br>• 读取要求会话 Cookie；授权条件是能读引用它的文档，或者是 24 小时内的上传者；无权与不存在都返回 404；<br>• 保存时只为保存者有权读取的图片建立引用；<br>• 平台内置一张占位图；`--asset-fallback` 模式下，读取失败时返回占位图 |
| `server/snapshot-images.ts` | 快照中的图片地址：<br>• 任何深度上名为 `source` 的字段都算图片地址（默认拒绝），资源数据先解析再遍历；<br>• 通用扫描报告不在 `source` 字段里、带协议头的字符串（超链接、正文里的网址）；<br>• 引用关系从解析后的全部字符串值中提取（含 `IMAGE()` 公式里的地址）；<br>• 本站的 origin 取自服务配置 |
| `server/serve.ts` | • 页面响应下发会话 Cookie（`HttpOnly`、`SameSite=Strict`）；<br>• 保存文档时，`validate=1` 拒绝含非平台图片地址的快照，引用关系按授权更新（结果写在 `X-Asset-Links` 头里）；<br>• 复制文档只复制引用关系 |
| `src/harness/platform-image-io.ts` | 平台图片服务（`IImageIoService` 的实现） |
| `src/harness/image-guards.ts` | 文字文档剪贴板钩子、命令守卫（都默认拒绝） |

| `src/harness/image-function-policy.ts` | `IMAGE()` 的 `off` 与 `restricted`，主线程与公式 Worker 共用。Worker 的策略经 Worker 的 `name` 传入 |
| `src/profiles/image-service.ts` | 替换图片服务的插件配置；图片格式对齐 |
| `e2e/v11-*.spec.ts`、`e2e/v12-*.spec.ts`、`e2e/p4-helpers.ts` | 用例与测试辅助；汇总脚本 `scripts/p4-summary.ts` |

页面参数：
- `img=default|platform`：缺省 `default`，保持 SDK 行为，P1–P3 的用例不受影响；
- `imagefn=default|off|restricted`；
- `nosession=1`：页面响应不下发 Cookie。

### 1.2 平台方案（建议写入 00 号计划书 §8.5、§11.3，由 M5 实现）

**"图片地址"的判定**：任何深度上名为 `source` 的字段都是图片地址，值必须是平台资源地址 `/api/assets/{uuid}`（不带查询参数与片段）的字符串，其余一律视为违规：外链、`data:`、`blob:`、`file:`、协议相对地址、非字符串等。

Univer 1.0.0 快照里的 `source` 字段都是图片：浮动图片与单元格图片、工作表背景、文字文档的页面背景、列表符号图片、文字填充图片。其中一些渲染时根本不看类型字段（`packages/drawing-ui/src/services/drawing-render.service.ts:169-170`，`packages/engine-render/src/components/docs/extensions/font-and-base-line.ts:284-289、328-360`）。P2 的全部样本里也没有非图片的 `source` 字段。

1. **替换图片服务**：
   - `UniverDrawingPlugin` 配置 `override: [[IImageIoService, { useClass: 平台图片服务 }]]`（`packages/drawing/src/plugin.ts:60-69`）。表格与文字文档都要注册；官方 preset 不开放 `override`，档案本来就逐个注册插件。
   - 平台图片服务的约定（SDK 的调用方有硬性要求）：
     - `saveImage` 先在客户端检查类型与大小，再上传，返回 `URL` 类型的同源相对地址；
     - `base64Cache` 用同一个同源地址（插入流程用它量尺寸，必须能加载）；
     - `imageId` 每次随机生成，不用 assetId（它直接当作 drawingId，而同一张图可能被插入多次）；
     - 失败时以 `Error(ImageUploadStatusType.X)` 拒绝，SDK 才会显示本地化提示：413 映射为"大小超过限制"，415 为"类型错误"，其他为"无效图片"；
     - `change$` 在上传开始时发出正数、结束时回到 0；
     - 加载失败的元素从缓存中删除。
   - **格式对齐**：把 SDK 导出的 `DRAWING_IMAGE_ALLOW_IMAGE_LIST`（决定文件选择框的 `accept`）与 `imageMimeTypeSet`（决定粘贴时挑哪些图片）改为 PNG、JPEG、GIF、WebP。默认的清单没有 WebP、多了 BMP，文字文档粘贴时还会丢掉 GIF（§2.3 第 7 条）。
2. **文字文档剪贴板钩子**（`IDocClipboardService.addClipboardHook`，内部 API），表格的单元格编辑器与编辑栏也用它：
   - `onBeforePasteImage`：粘贴的图片文件、HTML 里的 `data:` 图片改为上传。默认实现把它们读成 data URL，不经过图片服务。
   - `onBeforePaste`：对整个粘贴内容默认拒绝，包括不经过 HTML 转换的"内部片段"：
     - 本站的绝对地址规范回相对地址；
     - `drawings` 里的非平台地址替换成平台内置的占位图，不删除图片对象，避免破坏正文里的占位字符；
     - 文字填充图片整项去掉（`ts.textFill`）；
     - 其他位置（列表符号图片、页面背景等）去掉持有 `source` 的那一项。
3. **命令守卫**（`BeforeCommandExecute`，公开 API）：
   - 命令参数里有非平台地址的 `source` 时取消。
   - 它只看 `COMMAND`，命令内部执行的 mutation 看不到，所以它兜住的是平台代码的误用（例如 Facade 的字符串接口），不是所有路径。
   - 它对每个命令同步遍历参数：20 万单元格的写值约 74 ms（审查者在 Node 下测得）。生产上只检查与图片有关的命令。
4. **服务端保存校验**：
   - 快照中任何位置的 `source` 字段（含资源 JSON 内部）都必须是平台地址，否则拒绝；存储前把本站的绝对地址改写为相对地址；
   - 本站的 origin 取自配置，不取自请求头；
   - 这是最终防线：`img-src` 必须保留 `data:`，CSP 拦不住 data 图片。
5. **引用关系与读取授权**（00 号计划书 §8.5）：
   - 引用关系从快照解析后的字符串值中提取：不在原始 JSON 文本上扫描，否则 `/` 转义会让扫描漏掉；`IMAGE()` 公式里的地址也算。
   - **保存时只为保存者有权读取的图片建立引用**：这份文档原来就引用它、保存者是 24 小时内的上传者，或者保存者能读引用它的其他文档。无权的地址不建立引用，保存照常成功（拒绝保存会让本地优先管道反复重试）。
   - 读取：会话 Cookie 鉴权；无权与不存在都返回 404，不让人借此探测 assetId 是否存在。
6. **隐藏入口**：
   - 文字文档的形状：`doc.command.menu-insert-shape`、`doc.command.menu-insert-shape.below`（00 号计划书 §4.3 已要求隐藏；否则按钮会被命令守卫取消，点了没有反应）；
   - 表格的工作表背景图：P3 已隐藏；
   - 文字文档的页面背景只在非网页式版式下绘制（`packages/engine-render/src/components/docs/doc-background.ts:101-104`），00 号计划书 §4.3 固定网页式版式；服务端校验照样拒绝它。
7. **读取失败**：服务端返回平台占位图（200，真实状态放在 `X-Asset-Status` 头里，`no-store`），而不是 4xx（§2.3 第 3 条）。响应带 `X-Content-Type-Options: nosniff`、`Cross-Origin-Resource-Policy: same-origin`；只接受四种位图，不接受 SVG。
8. **表格复制补救**（`ISheetClipboardService.addClipboardHook` 的 `onBeforeCopyFocusedObject`，内部 API）：
   - SDK 复制 `URL` 类型的浮动图片时，200 ms 后往系统剪贴板写空文本；
   - 平台在它之后，把同源图片转成 PNG 写入剪贴板。这样跨文档粘贴与粘贴到外部应用都能拿到图片（§3.3 第 5 条）。
9. **`IMAGE()`**：采用 `restricted`：参数是平台资源地址时交给原执行器，否则返回 `#VALUE!`。在主线程与公式 Worker 里各装一次（§3.2）。

## 2. V11 替换图片服务，以及同源读取

### 2.1 结论：通过

- **路径矩阵**：27 条路径 × 两种图片服务 × 三个浏览器（162 个用例）全部完成。
  - 平台方案下，没有任何路径在快照里留下非平台地址，新增图片的张数都符合预期；
  - 默认实现下，有 19 条路径写入 data URL、外链、`file:`、`blob:` 或非字符串地址（§2.2）。
- **同源读取**：
  - 重开文档时，所有读取都带会话 Cookie 并成功：浮动图片以 `crossOrigin="anonymous"`（`Sec-Fetch-Mode: cors`）读取，单元格图片以普通方式（`no-cors`）读取，两者都带上了 Cookie；
  - 另一个会话经由文档引用可以读；只上传、没有随快照保存的图片，另一个会话读到 404，上传者本人可以读；
  - 没有会话时读取返回 401。
- **引用授权**：
  - B 保存一份在文字里写了 A 未保存图片地址的快照：不建立引用，B 仍然读不到；
  - A 把它保存进自己的文档之后，B 的引用才能建立；
  - `/` 转义成 `/` 的地址照样建立引用。
- **复制文档**：只增加引用关系（文件数不变）；原文档删除后，副本里的图片仍能读。
- **失败与限制**：
  - 服务端 503、客户端超过 5 MiB、SVG、伪装成 PNG 的 HTML，都不插入图片，并给出 SDK 的本地化提示；
  - 伪装的文件由服务端按文件头拒绝（415）。
- **格式**：平台方案下，插入图片的文件选择框提供 PNG、JPEG、GIF、WebP；表格粘贴 WebP、文字文档粘贴 GIF 都能插入。默认实现下，两者都插不进去。
- **保存校验**：
  - 平台方案的快照通过（204），默认实现的快照被拒绝（422）；
  - 构造的快照（文字填充图片、列表符号图片、页面背景、没有类型字段、数组地址、资源数据里的图片、协议相对地址、大写的 `DATA:`）全部被拒绝。

### 2.3 发现

1. **文字文档的"内部片段"会绕过 HTML 转换**（审查 R1）：
   - **可达性**：HTML 里的 `<!--univer-doc-fragment:…-->` 注释，或 `application/x-doc-fragment+json`，会被 SDK 当作内部片段直接使用（`packages/docs-ui/src/services/clipboard/clipboard.service.ts:1026`、`internal-fragment.ts:237-253`）。任何网页都能在复制时把它放进剪贴板。
   - **危害**：片段里的文字填充图片、数组形式的地址、没有类型字段的图片，渲染时照样加载（D8a–D8c）。
   - **结论**：平台的检查必须对任何位置的 `source` 字段默认拒绝，不能只看 `drawings` 里带类型字段的字符串。修正后，D8 各情形在三个浏览器下都没有留下非平台地址，关掉 CSP 时也没有外部请求。
2. **引用关系必须经过授权**（审查 R2）：
   - **问题**：如果按快照全文扫描建立引用，而授权规则是"能读引用它的文档即可读"，任何人把别人的地址写进自己文档的文字里并保存，就能永久获得读取权。
   - **修正**：保存时只为保存者有权读取的图片建立引用，即 00 号计划书 §8.5 的"保存校验"。验证服务已实现并测试。
   - **来源**：`IMAGE()` 的平台地址、粘贴的内部片段里其他部署的地址，都会走到这一处。
3. **读取失败时 SDK 会抛出未捕获的异常**：
   - **根因**：`packages/engine-render/src/shape/image.ts` 在图片加载失败之后、`onerror` 换成内置 SVG（155-162 行）之前，`_drawNative`（510、533 行）不检查破损状态就调用 `drawImage`。
   - **现象**：图片读取返回 401、404，或被 CSP 拦截时，表格渲染可能抛出 `InvalidStateError`；文字文档在外链被 CSP 拦截时也会（D5）。三个浏览器都出现过，时有时无，SDK 默认的图片服务同样会出现。
   - **缓解**：服务端对读取失败返回平台占位图。实测三个浏览器都不再出现：返回错误状态码时 9 次里 5 次出现（审查前的一轮为 6 次），返回占位图时 9 次里 0 次。
   - **局限**：它只能缓解服务端能应答的失败。截断或损坏的图片（服务端只查文件头，能上传）、网络失败、离线编辑照样会触发（审查者在截断图片上复现了同样的频率）。客户端兜底可以评估 `IURLImageService.registerURLImageDownloader`（`packages/drawing/src/services/url-image.service.ts:23-40`），但移动、缩放时的 `changeSource` 不经过它；也可以列为补丁候选。
   - **代价**：
     - 客户端无法从 `<img>` 得知真实状态；
     - 走 `fetch` 的路径（"保存单元格图片"）会静默拿到占位图，需要检查 `X-Asset-Status`；
     - 占位图响应必须 `no-store`，否则会以真实图片的地址被缓存。
   - 向上游报告。
4. **相对地址在粘贴中会变成绝对地址**：
   - 文字文档粘贴图片文件时，钩子返回的相对地址要先拼进 HTML，再由 HTML 转换读回。转换读的是 `element.src`，得到的是解析后的绝对地址（`packages/docs-ui/src/services/clipboard/html-to-udm/converter.ts:178-208`）；
   - 钩子在 `onBeforePaste` 里把本站的绝对地址规范回相对地址（D3、D4、D6 都触发了）。
5. **表格粘贴"浏览器复制图片"会丢失图片**（S5c）：
   - 浏览器"复制图片"时，剪贴板里同时有 `image/png` 和一段只有外链 `<img>` 的 HTML。表格只在 HTML 中含 `data:` 图片时才改走图片文件的粘贴（`packages/sheets-ui/src/services/clipboard/utils.ts:120-131`），其他情况按 HTML 粘贴，而 HTML 转换会丢掉 `<img>`；
   - 两种图片服务都一样；
   - 文字文档同样的情形（D6）会同时插入一张上传的图片和一张占位图；
   - 可用性缺口，由 M5 在粘贴钩子里判断"HTML 只有图片、同时有图片文件"，改为粘贴文件。
6. **粘贴时上传失败的提示**：
   - 文字文档粘贴图片时上传失败，钩子返回 null，SDK 不给提示；HTML 里的 `data:` 图片上传失败时，会显示"外部图片未导入"的占位图，提示内容不对；
   - 编辑栏里粘贴图片会先上传、再被编辑栏拒绝，留下孤儿文件（S7），由资源回收处理，也可以在钩子里判断目标编辑器；
   - M5 在钩子里给出提示，区分"上传失败"与"外部图片"。
7. **SDK 默认接受的格式与平台不一致**：
   - 插入图片的文件选择框按 `DRAWING_IMAGE_ALLOW_IMAGE_LIST` 生成 `accept`，默认是 `.png,.jpeg,.jpg,.gif,.bmp`：没有 WebP，却提供平台会拒绝的 BMP；
   - 粘贴按 `imageMimeTypeSet` 挑选图片，默认没有 GIF；
   - 两者都是 SDK 导出的可变模块状态，平台在启动时改成 PNG、JPEG、GIF、WebP 即可，实测生效。这是内部 API，已登记（§4）。
8. **上传只查文件头**：截断的文件、0×0 的图片都能上传；4,000 万像素的图片解码约占 160 MB 内存。M5 上传时应完整解码并重新编码（顺带去掉 EXIF 里的 GPS 等信息），设最小尺寸，按内存预算定像素上限，限制 GIF 帧数。
9. **引用关系扫描不需要理解 Univer 的内部结构**：从解析后的全部字符串值中按 `/api/assets/{uuid}` 模式提取，三类位置（浮动图片、单元格图片、文字文档的正文与资源）的平台地址都能找到（00 号计划书 §8.5）。

## 3. V12 外链图片、`IMAGE()` 与 CSP

### 3.1 结论：通过

- **外链图片**：
  - 默认实现下，文字文档粘贴外链图片（含内部片段）、Facade 传入外链时，关掉 CSP 会实际发出外部请求；严格 CSP 下都被拦截并上报。
  - 平台方案下，粘贴外链图片、粘贴内部片段、`FDocument.insertImage(外链)` 都不再发出任何外部请求。
- **`IMAGE()`**：三种处理 × 两种模式 × 三个浏览器（36 组）：
  - `default` 对外链照常加载：关掉 CSP 时发出请求，严格 CSP 下被拦截、显示 `#VALUE!`；
  - `restricted` 只显示平台地址的图片，外链与 data URL 都显示 `#VALUE!`，没有外部请求、没有 CSP 违规；
  - `off` 全部显示 `#NAME?`；
  - 快照里只有公式字符串。
- **功能降级**：
  - 复制浮动图片：平台方案下，SDK 对 `URL` 类型的图片只写空文本；加上平台的复制补救后，系统剪贴板里有 `image/png`，另一个文档粘贴得到一张重新上传的平台图片；
  - "保存单元格图片"在默认实现下被 `connect-src 'self'` 拦截（`fetch(data:)`），平台方案下可以正常下载；
  - 双击预览、移动图片不受影响；
  - 打印：开源版没有打印入口，只提供拦截点，不在本期范围（00 号计划书 §4.2）。
- **CSP**：
  - 严格策略下，平台方案的所有代表性路径没有强制违规；
  - 探测策略显示 `img-src data:`、`img-src blob:`、`style-src 'unsafe-inline'` 必要；
  - `font-src data:`、`worker-src blob:` 从未触发。

### 3.2 证据

- 命令：`npx playwright test e2e/v12-external.spec.ts e2e/v12-degradation.spec.ts`（8 + 5 个用例 × 3 个浏览器，全部通过；跨文档复制在 WebKit 上按设计跳过）
- 结果：`e2e/results/v12/image-formula/`、`external-images/`、`degradation/`、`cross-copy/`、`csp/`；汇总：`node scripts/p4-summary.ts formula external degradation crosscopy csp`
- 外部请求在关掉 CSP 的服务上计数：`page.route` 拦截所有非本站请求。被 CSP 拦截的请求在发出前就被取消，请求记录里看不到。

**`IMAGE()`**（三个浏览器、主线程与 Worker 相同）：

| 处理 | 外链 | 平台地址 | data URL | 外部请求（关掉 CSP） | 严格 CSP 下的强制违规 |
|---|---|---|---|---|---|
| `default` | `#VALUE!`（加载失败） | 图片 | 图片 | 1 | 1 |

**CSP：平台方案下的违规**（强制策略 / 探测策略；探测策略去掉 `data:`、`blob:`、`'unsafe-inline'`，只报告）：

| 步骤 | 强制策略 | 探测策略 |
|---|---|---|
| 表格：加载 `sheet-all` | 0 | `img-src data:` × 84、`style-src-elem` 内联 × 4 |
| 表格：插入、内部复制粘贴、单元格图片、粘贴文件、`IMAGE()` | 0 | `style-src-attr` 内联（Chromium 内核；WebKit 0） |
| 文字文档：加载 `doc-all` | 0 | `style-src-elem` 内联 × 4 |

### 3.3 发现

1. **`IMAGE()` 选 `restricted`**：
   - 它保留了用平台图片做单元格插图的能力，外链与 data URL 一律 `#VALUE!`，不发请求；
   - 包装依赖 `IFunctionService`（内部 API，§4 登记），要在主线程与 Worker 里各装一次；
   - `off` 更简单，但会让已有的 `IMAGE()` 全部变成 `#NAME?`。
2. **CSP 各项的理由**：
   - `img-src data:`：表格界面的图标，以及 SDK 自带的破损图片 SVG。保留它意味着 data 图片只能靠服务端校验与粘贴清洗来拦；
   - `img-src blob:`：文字文档粘贴图片文件时，SDK 用 `URL.createObjectURL(file)` 量尺寸（`packages/docs-ui/src/services/clipboard/clipboard.service.ts:1121-1132`）。这个 `Image` 没有 `onerror`，去掉 `blob:` 会让粘贴一直挂起，所以是硬性要求。这是 P1 留下的问题的答案；
   - 去掉 `font-src data:`：动态上，P1–P4 的全部场景都没有触发；静态上，构建产物的 CSS 里没有 `@font-face`；
   - 去掉 `worker-src blob:`：Worker 都用 `new Worker(new URL(…))` 从同源地址创建。M1 注明生产构建不得把 Worker 内联成 blob。
3. **Facade 的"先量尺寸再插入"会在命令之前发出请求**：
   - `FWorksheet.insertImage(url)`、`FRange.insertCellImageAsync(url)` 在执行命令之前就用 `new Image()` 加载地址量尺寸，命令守卫来不及介入；
   - 严格 CSP 下这个加载被拦截，插入中止并抛出错误；
   - 平台代码不应以外链调用它们。
4. **拖放**：
   - SDK 阻止了 `dragover` 的默认行为，却没有阻止 `drop` 的，也不处理文件（`packages/engine-render/src/engine.ts:889-891、951-960`）；
   - 真实拖入文件时，浏览器的默认行为是打开这个文件，可能离开编辑页。合成事件不会触发这个默认行为，本 Phase 无法自动验证，登记为 DEF-004；
   - 建议宿主在编辑器容器上拦截 `drop`：阻止默认行为，把图片文件交给平台图片服务插入。
5. **复制浮动图片**（审查 R4）：
   - SDK 对 `URL` 类型的图片，在复制 200 ms 后往系统剪贴板写空文本（`packages/sheets-drawing-ui/src/controllers/sheet-drawing-copy-paste.controller.ts:145-152`）。同一页面里的粘贴依赖内存中的复制信息，所以另一个标签页的文档、外部应用都拿不到图片；
   - 平台的复制补救在它之后写入 PNG，实测恢复了跨文档复制与复制到外部应用；
   - 补救依赖计时（晚于 SDK 的 200 ms）与剪贴板权限，真实 Safari 的剪贴板授权更严，列入 DEF-004。

### 3.4 对设计的影响

- **00 号计划书 §11.3**：
  - 写明"粘贴清洗"的做法（§1.2 第 2 条）；
  - "限制 `IMAGE()`"采用 `restricted`；
  - CSP 定稿见下一条。
- **CSP 定稿**（相对 00 号计划书 §11.3 的起点策略）：

  ```
  default-src 'self'; img-src 'self' data: blob:; connect-src 'self'; font-src 'self'; style-src 'self' 'unsafe-inline'; script-src 'self'; worker-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
  ```

  - 去掉 `font-src data:` 与 `worker-src blob:`；
  - 文字文档的字体与排版 Worker 由 P5 复核；
  - 策略必须随所有响应下发，包括 Worker 脚本（P1）。
- **插件档案 v1**：补充 `IMAGE()` 的处理与 CSP（§6）。
- **M1**：Worker 回报 `IMAGE()` 限制的安装结果；生产构建不把 Worker 内联成 blob。
- **M5**：
  - 宿主拦截 `drop` 并插入图片；
  - 表格复制补救的实现。

## 4. 内部 API 登记

本 Phase 的方案用到下列内部 API，M1 的编辑器适配层必须集中封装并登记（00 号计划书 §10.1）：

| 用途 | 内部 API 或约定 | 说明 |
|---|---|---|
| 替换图片服务 | `IImageIoService`（`@univerjs/core` 导出）、`UniverDrawingPlugin` 配置的 `override` | 插件配置是公开的；服务接口与它的约定（`base64Cache`、`imageId`、错误码、`change$`）没有文档保证 |
| 图片格式对齐 | `DRAWING_IMAGE_ALLOW_IMAGE_LIST`（`@univerjs/drawing` 导出的可变数组）、`imageMimeTypeSet`（`@univerjs/ui` 导出的可变集合） | 模块级状态，对页面里的所有实例生效 |
| 文字文档剪贴板钩子 | `IDocClipboardService.addClipboardHook`（`@univerjs/docs-ui` 导出）的 `onBeforePasteImage`、`onBeforePaste` | 只有第一个注册 `onBeforePasteImage` 的钩子生效，适配层启动时要断言自己是第一个 |
| 表格复制补救 | `ISheetClipboardService.addClipboardHook`（`@univerjs/sheets-ui` 导出）的 `onBeforeCopyFocusedObject`、`IDrawingManagerService.getFocusDrawings`（`@univerjs/drawing` 导出） | 依赖 SDK 在 200 ms 后写剪贴板的时序 |
| `IMAGE()` 的限制 | `IFunctionService.getExecutor` / `registerExecutors` / `unregisterExecutors` / `deleteFormulaAstCacheKey`、`IDescriptionService.unregisterDescriptions`（`@univerjs/engine-formula` 导出）、`BaseFunction` | 要在生命周期 Ready 之后安装，主线程与 Worker 各一次 |
| 命令守卫 | —（Facade 的 `BeforeCommandExecute` 事件，公开 API） | 按参数里的 `source` 字段判断 |
| 验证用 | `window.__m0.images.io()`（取出图片服务） | 只用于验证 |
