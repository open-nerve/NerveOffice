# M0-P5 文字文档与中文：架构设计与实施规划

> 状态：进行中｜日期：2026-09-25｜基于代码版本：`f063a15`（main，P4 已合并）

## 1. 目标与范围

对应 M0 总设计 §5 的 P5 一行，覆盖验证项 V13（00 号计划书 §4.3、§13.4 第 13 条），结论决定 M6 的范围：

- **能力矩阵**：§4.3 列出的每一项能力，都给出"可用""有条件可用（写明条件）"或"不稳定（隐藏）"的结论：
  - 正文与标题样式（标题、副标题、H1–H5）；
  - 字符格式（粗体、斜体、下划线、删除线、上下标、字体、字号、文字颜色、高亮）；
  - 段落对齐；
  - 有序、无序、复选列表；
  - 基础表格（不支持嵌套表格，单元格里不能插入图片）；
  - 图片（内联与浮动环绕）；
  - 超链接、`/` 快捷插入（只包含已启用的能力）、查找替换。
- **中文输入法**：拼音、五笔；覆盖 macOS。Windows 输入法登记为 M6 开始前的补充验证项（M0 总设计 §2）。
- **复制粘贴**：来源包括 Word、网页和本平台。
- **版式**：固定使用无分页的网页式版式；隐藏页面模式切换、页眉页脚、分节符与分栏符、形状、内嵌公式、目录（目录是候选项，本 Phase 给出是否纳入的建议）。
- **`doc@1` 档案的范围**（P1、P2 交接）：
  - 公式引擎是否必需；
  - 是否启用排版 Worker（含三个浏览器上的回归）；
  - 目录是否纳入。
- **文字文档的性能**（P3 交接）：00 号计划书 §12.1 的文字样本（约 2 万汉字，含标题、列表、基础表格与图片）的首屏、键入与输入法响应、内存。
- **CSP 复核**（P4 交接）：在文字文档的字体与排版 Worker 场景下，确认 `font-src data:`、`worker-src blob:` 可以去掉。

不在本 Phase：

- 生产适配层本身（M1）与文字文档模块的产品化（M6）。本 Phase 只在验证工程里做最小的缓解，用来证明结论中的"条件"可行；
- 真实的 Word、WPS 应用与真实剪贴板的逐项复核：本 Phase 用合成粘贴与构造的剪贴板样本，真实来源的复核登记为延期项（与 DEF-004 同类）；
- 表格部分的能力矩阵：证据分散在 P2–P4，在 M0 结束评审前汇总进 `reports/能力矩阵.md`。

## 2. 现状

- **验证工程**（P1–P4 交付）：
  - 文字文档档案 `doc@1-draft`（`spikes/m0/src/profiles/doc.ts`）：core（含公式引擎）、layout-worker、drawing、hyperlink、find-replace、toc 六组；
  - 样本 `fixtures/doc/*`（`documentFlavor: 2`，即 MODERN），P3 的 `doc-20k`、`doc-1m` 构建器（没有表格与图片）；
  - 变更检测、捕获时机、阅读模式、内容比较（P3）；
  - 平台图片服务、粘贴钩子、命令守卫（P4，`img=platform`）；
  - 合成粘贴、文件选择框、CSP 违规收集（`e2e/p4-helpers.ts`）；菜单审计（`window.__m0.auditMenus`）。
- **前序交接**：
  - P1：文字文档能否去掉公式引擎；是否启用排版 Worker；目录是否纳入；
  - P2：目录插件会往正文写 FIELD、BOOKMARK、HYPERLINK 区间，纳入就要补样本与地址检查；三个浏览器上的排版 Worker 回归；
  - P3：能力矩阵、不支持功能的菜单隐藏、中文输入的响应；
  - P4：CSP 的 `font-src`、`worker-src` 复核；其余不支持功能的入口；文字文档中图片的粘贴与"表格中的图片"限制。
- **与本 Phase 相关的源码事实**（v1.0.0，本 Phase 核对，下文 `packages/` 省略；标"实测"的已用临时探针在三个浏览器上确认）：
  - **菜单与入口**：
    - 菜单配置按菜单项 id 全局生效，一个 `{ hidden: true }` 同时隐藏工具栏、右键菜单、段落菜单、`/` 菜单与功能搜索里的同一项（`ui/src/services/menu/menu-manager.service.ts:375`；功能搜索不列出已隐藏的项，实测）。
    - 隐藏菜单不会停用命令与快捷键；要拦截，只能在 `beforeCommandExecuted` 里抛错取消（`core/src/services/command/command.service.ts:440、466`）。
    - 运行时注册的菜单项已用菜单审计导出（约 150 项，含工具栏、右键菜单与段落菜单）；其中页眉页脚、分隔符在 MODERN 版式下自动隐藏，"页面设置"可见。
  - **`/` 快捷插入**：
    - 1.0 没有单独的 quick-insert 插件，它是 docs-ui 的段落菜单服务（`docs-ui/src/services/doc-paragraph-menu.service.ts`），总是注册，没有开关；
    - 光标折叠时键入 `/`（keydown 或 input 两条路径都会检查），不论位置，都会阻止默认行为并弹出段落菜单（422-466 行）。**实测：三个浏览器都无法在正文里键入 `/`；菜单弹出后抢走焦点，其后键入的字全部丢失**（`a/b c` 只剩 `a`）；
    - 菜单项就是段落菜单的"插入"组：H1–H5、三种列表、分割线、表格、图片、形状（已隐藏）、粘贴。
  - **中文输入**：
    - 隐藏的输入元素是 `contenteditable` 的 `div#__editor_<unitId>`，按光标左上角 `position: fixed` 定位；输入法候选框锚定在这个元素里的 DOM 光标上（`docs-ui/src/services/selection/doc-selection-render.service.ts:969-1043、1282-1311`）。
    - 每次 `compositionupdate` 都把中间文字（拼音）写进模型，mutation 带 `noHistory: true`；`compositionend` 时合成一条撤销记录（`docs-ui/src/controllers/render-controllers/doc-ime-input.controller.ts:96-207`、`commands/commands/ime-input.command.ts`、`services/doc-ime-state-change-interceptor.service.ts`）。实测：CDP 输入法模拟（Chromium 内核）与合成事件（三个浏览器）都能驱动这条路径，Univer 只读 `CompositionEvent.data`。
    - **事件顺序**：Chrome 在提交前发一次携带最终文字的 `compositionupdate`，`compositionend` 的数据与之相同。WebKit 提交时先发 `deleteCompositionText`、`insertFromComposition` 两个 `input`，再发 `compositionend`，没有携带最终文字的 `compositionupdate`，于是走"数据不同"的分支（WebKit `Source/WebCore/editing/Editor.cpp` 的 `Editor::setComposition(const String&, SetCompositionMode)` 确认分支）。**实测（合成事件，三个浏览器同样）：文字正确，但撤销按拼音的长度删除，多删了后面的字；重做插回拼音**（`M0 文字…` 输入"你好"后撤销得到 `M0档样本`，重做得到 `M0ni hao档样本`）。真实 Safari 是否走这条分支，要用真实输入法确认。
    - 中间文字会被变更检测看到：停在候选框上超过去抖时间，捕获的快照里就是拼音；Chrome 的提交路径在 `compositionend` 时不产生 mutation，捕获要由 `compositionend` 触发。
  - **粘贴**：
    - 来源优先级：内部 JSON 类型 → HTML 里的 `<!--univer-doc-fragment:…-->` → 纯文本 → `data-copy-id` 缓存 → HTML 转换（`docs-ui/src/services/clipboard/clipboard.service.ts:1025-1057`）。
    - HTML 转换按 Lark → Univer → Word 的顺序匹配插件（`/word|mso|wps|kingsoft/i` 也会匹配网页里常见的 `word-spacing`）；没有 Google Docs 插件。
    - 已知的转换偏差（源码梳理，待实测）：`<em>` 转成粗体；Google Docs 的 `<b id="docs-internal-guid">` 让全文变粗；`text-decoration` 可能丢失；`10.5pt` 截成 10；`<br>` 丢失；`<h6>` 变成正文；Word 的中文编号（`一、`、`（一）`）留在文字里；`line-height` 的 pt、px 被当作倍数。
    - 超链接：HTML 路径只保留 `http`、`https`、`mailto`（`isSafeUrl`）；内部片段不经过检查。
    - 往表格单元格里粘贴含表格的内容，命令静默失败（`docs-ui/src/commands/commands/clipboard.inner.command.ts:71-77、160-170`）；粘贴图片到单元格没有限制。
  - **超链接**：
    - 编辑框用 `isLegalUrl` 校验：`javascript:alert(1)` 被拒，但 `javascript://…` 能通过并原样保存（`core/src/common/url.ts:326`）。源码梳理时以为 `data://…` 也能通过，实测在编辑框里被拒（C7b，审查 S2 更正）；
    - 打开链接前再用 `isSafeUrl` 检查，用 `window.open(url, '_blank', 'noopener noreferrer')`（`docs-hyper-link-ui/src/commands/operations/popup.operation.ts:143-146`）；
    - 复制时 `href` 不转义（`docs-ui/src/services/clipboard/udm-to-html/convertor.ts:214`）。
  - **表格**：
    - 嵌套表格在工具栏、命令、粘贴三处都被拦住；没有合并单元格的命令；
    - 单元格里插入图片只在工具栏按钮上禁用，段落菜单、`/` 菜单、粘贴、Facade、拖动内联图片都没有检查。唯一的插入命令是 `doc.command.insert-doc-image`（`docs-drawing/src/commands/commands/insert-doc-drawing.command.ts:47`）。
  - **版式**：
    - 没有 `documentFlavor` 的快照按 MODERN 处理；MODERN 下一页到底，页眉页脚不渲染也不能编辑，分节符与分栏符被拒绝；
    - 切换模式的按钮在 1.0 被注释掉了，但 `doc.command.switch-mode` 仍然注册；"页面设置"会通过 `docs.command.page-setup` 改写 `documentFlavor`。
  - **目录**：
    - `docs-toc`、`docs-toc-ui` 在正文里插入目录块（FIELD 区间，`fieldType: 'TOC'`）；
    - docs-ui 另有一个只读的大纲侧栏（配置 `toc: true`，`docs-ui/src/views/DocSideMenu.tsx`），按标题导航，不写任何内容。
  - **内嵌公式**：开源版没有这项功能（只有枚举值与 Pro 的字符串）。
  - **公式引擎**：文字文档启用的插件都不依赖 `@univerjs/engine-formula`，官方 preset 只是顺带注册。
  - **其他**：工具栏里"重置高亮"调用的是设置命令，写入主题色（疑似缺陷，待实测）；图片环绕面板遇到导入的 polygon、through、tight 类型会抛错。

### 3.2 实验方案

每项都在严格 CSP 下、三个浏览器上进行。"平台配置"指 `img=platform&docpolicy=platform`；对照组为 SDK 默认。

**V13-1 能力矩阵**：每项能力走用户的入口（工具栏、快捷键、右键或段落菜单、`/` 菜单），然后检查：
- 快照里的结构符合预期（按 §2 的数据位置）；
- 撤销回到原状，重做恢复；
- 保存 → 重开 → 再保存，两次快照一致（P2 的口径）；
- 没有页面错误与 CSP 强制违规；
- 截图留证。

| 编号 | 能力 | 入口与要点 |
|---|---|---|
| C1 | 标题样式 | 工具栏下拉（正文、标题、副标题、H1–H5）；快捷键 Cmd+Alt+0–5；Markdown 式 `# ` |
| C2 | 字符格式 | Cmd+B / I / U、Cmd+Shift+X、上下标按钮；字体、字号、文字颜色、高亮下拉；重置颜色与高亮 |
| C3 | 段落对齐 | 工具栏下拉；Cmd+Shift+L / E / R / J |
| C4 | 列表 | 三种列表按钮；Tab 与 Shift+Tab 调整层级；空项回车退出；点击复选框切换；`1. `、`* ` |
| C5 | 基础表格 | 工具栏对话框与 `/` 菜单插入；单元格中键入与 Tab 移动；右键增删行列、删除表格；嵌套表格的三条路径；单元格里插入图片（对照与平台） |

**V13-2 中文输入**：

- **驱动**：
  - Chromium、Chrome：CDP 的 `Input.imeSetComposition` 与 `Input.insertText`，事件由浏览器的输入法通道产生；
  - 三个浏览器：合成事件，分别按 Chrome 与 WebKit 的事件顺序（WebKit 顺序依据源码梳理，真实 Safari 由人工核对确认，见下）。
- **输入序列**：
  - 拼音：逐字母更新（组合文字里带空格或分隔符），空格提交候选；整句输入分段提交；
  - 五笔：编码更新（`wq`、`wqvb`），四码自动提交；
  - 标点：中文标点直接提交；中英混排；
  - 取消（`compositionend` 数据为空）、组合中退格。
- **位置**：段落开头、中间、末尾；标题；列表项；表格单元格；粗体与链接文字里（样式继承）；替换选中的文字。
- **检查**：
  - 最终正文；
  - 一次组合一条撤销记录，撤销恰好回到输入前，重做恢复；
  - 没有多出的段落（Safari 提交后的回车 keydown）；
  - 提交后光标位置；
  - 隐藏输入元素（候选框的锚点）与画布光标的距离；
  - 捕获时机：组合进行中是否被捕获，提交后的捕获是否包含最终文字；组合进行中执行一次 `save()` 是否打断输入。
- **响应**：每次组合更新到两次 `requestAnimationFrame` 之后的耗时，小文档与 `doc-20k-full`，主线程与排版 Worker。
- **真实输入法（人工，macOS）**：用 `imelog=1` 页面，在 Chrome 与 Safari 中用系统拼音（及五笔，如已安装）按清单输入并撤销；记录的事件序列交回验证服务，再用合成驱动回放。清单与操作说明写进报告附录。

**V13-3 复制粘贴**：

- **来源**：§3.1 的剪贴板样本；本平台的复制（同一文档、另一个标签页、表格到文字文档、文字文档到表格；Chromium 内核用真实剪贴板）。
- **目标**：空段落、段落中间、标题、列表项、表格单元格。
- **检查**：
  - 结构摘要：标题、列表、表格、链接、文字样式、图片的处理；
  - 链接只保留安全地址；脚本与事件属性不执行；
  - 没有页面错误；保存重开一致；
  - 已知偏差逐条记录（见 §2）；
  - "仅保留文本"粘贴（Cmd+Shift+V）与粘贴选项。

**V13-4 版式与入口**：

- 加载 TRADITIONAL 与 UNSPECIFIED 的快照：平台配置下规范为 MODERN；
- 切换版式、页面设置、页眉页脚、分隔符、形状的命令被守卫取消；带分节符的内部片段粘贴后的结果；
- 菜单审计：每个菜单项都有"保留"或"隐藏"的结论；断言隐藏的项在工具栏、右键菜单、段落菜单、`/` 菜单、功能搜索中都不出现；
- 目录：比较大纲侧栏（只读导航）与目录块（写入正文），给出建议。

**V13-5 档案范围与性能**：

- **公式引擎**：`without=formula` 下，文字文档样本的保存重开（V03 的文字文档部分）与能力矩阵的子集照常；记录首屏包体积的差异。
- **排版 Worker**：`worker=1` 下，V03 文字文档部分、V06 文字文档动作、能力矩阵子集在三个浏览器上回归；性能对比。
- **性能**（`doc-20k-full`）：首屏（`Rendered`、`Steady`）、键入响应、输入法响应、内存；主线程与排版 Worker 各测一次。
- **CSP**：P5 各场景下探测策略的违规汇总，确认 `font-src data:`、`worker-src blob:` 没有被触发。

### 3.3 关键设计

**缓解只证明可行，不决定产品实现**：§3.1 的平台策略都是验证用的最小实现，目的是证明结论里的"条件"可以做到。生产实现由 M1 的编辑器适配层统一设计；依赖的内部 API（隐藏输入元素、段落菜单的行为、命令 id）在报告中登记。

**`/` 键**：SDK 在 keydown 与 input 两条路径上都会弹出菜单，并在 input 路径上阻止插入，所以只拦 keydown 不够。平台在捕获阶段拦下 keydown：
- 光标在空段落里：放行，由 SDK 弹出菜单；
- 其他位置：阻止默认行为与传播，由平台执行插入文字的命令。

插入的 `/` 是否继承所在位置的样式（粗体、链接），由 C8 检查。

**输入法事件归一**：
- 只在"`compositionend` 的数据与最后一次 `compositionupdate` 不同"时介入：先派发一次携带最终文字的 `compositionupdate`，等一个宏任务，再派发 `compositionend`。原来的 `compositionend` 在捕获阶段拦下；
- 这样两种浏览器都走 SDK 的"数据相同"分支。

**捕获时机**：
- 组合输入进行中，检测到的修改不触发捕获；
- `compositionend` 之后按正常的去抖触发一次捕获（Chrome 路径在提交时没有 mutation，所以不能只等 mutation）。

**表格单元格里的图片**：
- 00 号计划书 §4.3 写明"单元格里不能插入图片"。平台以命令守卫与粘贴清洗落实这条限制；
- 同时记录单元格图片在 SDK 中的实际表现（渲染、保存重开），供以后放宽限制时参考。

**目录**：两种形态分别评估：
- 大纲侧栏不写内容，风险最低；
- 目录块要承担 FIELD 区间的格式、更新与地址检查。

**实施中的调整**

- `/` 键：表格单元格里 SDK 吞掉 `/` 但不弹出菜单，平台改为只在表格之外的空段落里放行，其余位置都由平台插入。
- 输入法的合成驱动每次派发之后清空一次微任务队列：浏览器派发原生事件时，每个监听器之后都会清空微任务队列，脚本里的 `dispatchEvent` 不会，同步派发会误报错乱。最初改为让出一个宏任务，审查（G5）指出这样会掩盖事件归一的延后派发窗口，改为只清空微任务。
- 纯文本粘贴时 SDK 生成的链接地址是整段文字：粘贴清洗改为"链接文字本身合法时改用它，否则去掉"。
- 目录块插件改为页面参数 `tocblock=1` 时才注册（doc@1 不纳入），大纲侧栏用 `outline=1` 打开。
- 公式引擎的包体积不用 `doc.html` 的产物比较（验证工程的共用代码也引用了公式引擎），改为按 doc@1 的插件清单生成两个最小入口分别构建（`scripts/p5-doc-bundle.ts`）。
- V10 的堆与统计工具抽到 `e2e/perf-helpers.ts`，供 V13 的性能用例复用。
- 档案变体（排版 Worker、去掉公式引擎）用环境变量 `M0_P5_QUERY` 让同一套用例带上页面参数回归，结果放在带后缀的目录（`*-worker/`、`*-without-formula/`）。
- 运行环境：最终一轮进行中，本机断电重启后一直没有登录桌面会话，WebKit 无法启动，Google Chrome 间歇崩溃；这两个浏览器的最终一轮在桌面会话恢复后补跑。
- 按审查意见的调整（`reviews/P5-审查报告.md`）：
  - `/` 键另外处理数据为 `/` 的 `insertText` beforeinput（G1），文档不可编辑时不介入（S5）；
  - 输入法事件归一在延后派发期间，遇到输入先同步派发 `compositionend`（G5）；
  - 捕获时机的组合输入感知加 3 秒上限与失焦复位（G4）；
  - 链接地址判定之后一律保存规范写法，新增命令路径的用例 C7c（G3）；
  - 命令守卫覆盖拖动浮动图片进单元格与改为内联（R3），C5b 增加真实鼠标拖动的步骤，SDK 默认下做保存重开；
  - 隐藏清单补上形状的子项（G6）与浮动图片的组合、层级、对齐（G9），段落把手与粘贴选项新增用例 L5b；
  - 性能用例增加"画出来"的口径（R1）；
  - 排版 Worker 因 Tab 缺陷暂不启用（R2）。§3.2 要求的 `worker=1` 下 V06 文字文档动作回归，改为 DEF-007 重新评估时的前提；`worker=1` 只重跑能力矩阵，用来记录缺陷；
  - `doc@1` 的最终组合（去掉公式引擎、主线程排版、大纲侧栏）用 `M0_P5_QUERY='without=formula&outline=1'` 整体重跑能力矩阵、输入法与粘贴（G8）。
