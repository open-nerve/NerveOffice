# M0-P4 资源与外部请求：架构设计与实施规划

> 状态：进行中｜日期：2026-09-25｜基于代码版本：`ba474e2`（main，P3 已合并）

## 1. 目标与范围

对应 M0 总设计 §5 的 P4 一行，覆盖验证项 V11、V12：

- **V11 替换图片服务，以及同源读取**（00 号计划书 §8.5、§11.4）：
  - 用 `UniverDrawingPlugin` 的 `override` 替换 `IImageIoService`，插入与粘贴图片时先上传到平台，快照里只保存同源地址 `/api/assets/{assetId}`；
  - 逐条核对图片进入文档的全部路径：每条路径都得到同源地址，或者有明确的处理方式（上传、替换、拦截、隐藏入口）；
  - 同源读取走 Cookie 鉴权，渲染图片的各条加载路径（含 `crossOrigin="anonymous"`）都能读到；
  - 引用关系由服务端扫描快照得出，读取授权按"能读引用它的文档，或者是 24 小时内的上传者"；
  - 服务端校验快照中的图片地址。
- **V12 外链图片、`IMAGE()` 与 CSP**（00 号计划书 §11.3）：
  - 外链图片（文字文档粘贴 HTML、Facade 接口）与 `IMAGE()` 公式在严格 CSP 下被拦截，违规能被上报；
  - 粘贴清洗与 `IMAGE()` 限制的做法，以及功能降级是否可以接受；
  - CSP 策略的定稿建议：P1 留下的 `img-src blob:`、`font-src data:`、`worker-src blob:` 是否必要。

不在本 Phase：
- 平台的资源服务本身（数据库表、回收、配额、备份）在 M5 实现；本 Phase 只在验证服务里做最小实现，用来验证机制；
- 文字文档的能力范围（P5）。本 Phase 只核对文字文档里与图片有关的路径；是否保留某个入口（例如形状），由 P5 的能力矩阵决定；
- 本机存储与离线（P6）。离线时"插入图片"禁用，由 M4 实现；本 Phase 只验证上传失败时的行为。

## 2. 现状

- **验证工程**（P1–P3 交付）：

  - 图片样本 `public/fixtures-assets/`（两张 PNG）。
- **P3 交接给本 Phase 的事项**：

- **P1 交给本 Phase 的事项**：
  - 图片下载的两条 `fetch` 路径（`downloadImage`、图片转 Blob）的触发路径；
  - `img-src blob:`、`worker-src blob:`、`font-src data:` 是否必要。
- **与本 Phase 相关的源码事实**（v1.0.0，本 Phase 核对，下文 `packages/` 省略）：

  - **`saveImage` 的约定**：

    - 失败时要以 `Error(ImageUploadStatusType.X)` 拒绝，才有本地化提示；
    - `change$` 在启动时就被订阅（`sheets-drawing-ui/src/menu/drawing-popup-menu.controller.ts:82-99`）。
  - **经过 `saveImage` 的入口**：
    - 表格：浮动图片（工具栏、粘贴图片文件、`InsertFloatImageCommand{files}`）、单元格图片（工具栏、`FRange.insertCellImageAsync(File)`）、工作表背景图（入口已隐藏）；
    - 文字文档：工具栏与右键的插入图片。
  - **不经过它的入口**：
    - 文字文档粘贴图片文件，默认 `fileToBase64`（`docs-ui/src/services/clipboard/clipboard.service.ts:1099-1173`），只能靠剪贴板钩子 `onBeforePasteImage` 改为上传；
    - 文字文档粘贴 HTML 中的 `data:` 图片：有 `onBeforePasteImage` 钩子时会上传后替换（1059-1097），没有就原样保留；
    - 文字文档粘贴 HTML 中的外链、`file:`、`blob:` 图片：原样作为 `URL` 类型写进快照（`docs-ui/src/services/clipboard/html-to-udm/converter.ts:178-208`）；
    - 文字文档的形状：SVG 的 data URL（`docs-drawing-ui/src/commands/commands/insert-shape.command.ts`）。00 号计划书 §4.3 已要求隐藏形状入口；
    - 单元格编辑器与编辑栏里粘贴：走文字文档的剪贴板，钩子同样生效（`sheets-drawing-ui/src/controllers/sheet-cell-image-copy-paste.controller.ts:73-121`）；
    - Facade 的字符串参数接口（`FWorksheet.insertImage(url)`、`FRange.insertCellImageAsync(url)`、`FDocument.insertImage` 等）：原样写入。平台不向用户开放 Facade 与脚本，这些只能由平台代码调用。
  - **剪贴板钩子**（`docs-ui/src/services/clipboard/clipboard.service.ts:193-206`）：
    - `onBeforePasteImage(file)` 返回 `{ source, imageSourceType }`，只有第一个注册了它的钩子生效；
    - `onBeforePaste(body, { documentData })` 在插入之前可以改写 `documentData.drawings`，与插入时用的是同一个对象（744-751、814-819）。
  - **表格粘贴**：
    - 剪贴板里有图片文件时插入浮动图片（经过 `saveImage`，`sheet-drawing-copy-paste.controller.ts:208-230`）；
    - HTML 中的 `<img>` 被丢弃，不发请求（`sheets-ui/src/services/clipboard/html-to-usm/`）；
    - 只认 `data:image/...;base64` 的 `<img>`（`clipboard/utils.ts:120-131`）。
  - **渲染**：全部用 `HTMLImageElement`，不用 `fetch` 或 XHR。
    - 浮动图片设 `crossOrigin="anonymous"`（`engine-render/src/shape/image.ts:148-149`），文档页面背景也设（`doc-background.ts:416-417`）；
    - 单元格图片、`IMAGE()`、量尺寸都不设；
    - 加载失败时，浮动图片换成占位图，并且失败的元素一直留在缓存里（`drawing-ui/src/services/drawing-render.service.ts:189-191`）；
    - 移动、缩放图片时直接用原始地址重设 `src`，不经过 `IURLImageService`（`drawing-ui/src/controllers/image-update.controller.ts:259-261`）。
  - **`fetch` 路径**：
    - "保存单元格图片"（右键菜单、`FRange.saveCellImagesAsync`）会重新请求图片：`URL` 类型走 `downloadImage`，`BASE64` 类型走 `fetch(dataURL)`（`sheets-drawing-ui/src/services/batch-save-images.service.ts:226-239、639-673`）。后者受 `connect-src` 约束。
  - **文字文档粘贴图片文件时量尺寸**：用 `URL.createObjectURL(file)`（`clipboard.service.ts:1121-1132`），这需要 `img-src blob:`；这里的 `Image` 没有 `onerror`，解码失败时可能一直不结束。
  - **`IMAGE()`**：
    - 实现在 `engine-formula/src/functions/lookup/image/index.ts`，不校验协议与域名，只返回带 `imageInfo` 的空字符串；
    - 主线程的 `ImageFormulaCellInterceptorController` 用 `new Image()` 量尺寸、渲染（`sheets-formula/src/controllers/image-formula-cell-interceptor.controller.ts:102-229`），失败时显示 `#VALUE!`；
    - 快照里只有公式字符串；
    - 没有开关或域名白名单。可以用 `IFunctionService.unregisterExecutors` 反注册，或者同名覆盖（`engine-formula/src/services/function.service.ts:74-98`）；
    - Worker 模式下计算在 Worker 里，两边都要处理。
  - **拖放**：SDK 不处理拖入的文件，`drop` 事件没有 `preventDefault`（`engine-render/src/engine.ts:889-891、951-960`），浏览器可能直接打开被拖入的图片。

### 3.1 验证工程的增量

### 3.2 实验方案

**V11-1 路径矩阵**：每条路径在 `img=default` 与 `img=platform` 两种配置下各跑一遍，严格 CSP，三个浏览器；表格带 `worker=1`。每条路径记录：
- 快照中新增图片的地址分类（由 §3.1 的提取得到）；
- 上传次数；
- 图片是否加载成功：从图片服务的缓存取元素，看是否 `complete` 且有尺寸；
- 对 `/api/assets` 的读取是否都带了 Cookie；
- CSP 违规、页面错误、是否检测到修改。

- 对照：`img=default` 时哪些路径写入 `BASE64`、外链或其他；`img=platform` 时每条路径的结果与处理方式。
- 形状（D2）：先核对它在文字文档工具栏里是否可见；可见就测，结论交给 P5 的能力矩阵（00 号计划书 §4.3 要求隐藏）。
- 拖放：把图片文件拖到画布上，记录页面是否跳转，以及宿主拦截 `drop` 之后的行为。

**V11-2 同源读取与授权**：
1. 同一会话：插入后重开文档，全部图片加载成功；读取请求都带 Cookie（包括 `crossOrigin="anonymous"` 的浮动图片）。
2. 另一个会话（新的浏览器上下文）：
   - 打开已保存的文档，被引用的图片能读（经由文档引用授权）；
   - 直接读取一个只上传、还没随快照保存的 assetId，返回 403。
3. 没有会话 Cookie：读取返回 401；编辑器里的图片显示占位图，不产生页面错误。
4. 复制文档（P2 的 `/api/docs/{id}/copy`）：副本里的图片能读，引用关系增加，文件不复制。
5. 上传失败（服务端返回 413、415、503）：出现错误提示，不插入图片，不产生残留。
6. 大小与类型：超过 5 MiB、SVG、伪造扩展名的文件被拒绝，客户端与服务端各查一次。

**V12 外部请求**：
1. 外链图片：
   - 文字文档粘贴外链 `<img>`：`img=default` 时，快照里留下外链，严格 CSP 下加载被拦截并上报；`img=platform` 时被替换成占位图，没有外部请求。
   - Facade 接口传入外链：命令守卫取消。
   - 两种情况都记录实际发出的外部请求：关掉 CSP、用 `page.route` 拦截计数，因为被 CSP 拦截的请求在发出前就被取消，请求记录里看不到。
2. `IMAGE()`：外链、平台地址、`data:` 三种参数 × 三种处理（`default`、`off`、`restricted`）× 主线程与 Worker × 三个浏览器。记录：
   - 单元格显示的值（`#VALUE!`、`#NAME?` 或图片）；
   - 外部请求与 CSP 违规；
   - 快照内容。
3. **功能降级清单**：换成同源地址之后，下面几项是否可用，给出结论：
   - 复制浮动图片到外部应用；
   - "保存单元格图片"；
   - 双击预览；
   - 移动或缩放图片后的重新加载；
   - 打印时的图片（开源版只提供打印拦截点，只核对拦截点下的渲染）。
4. **CSP 定稿**：在 §3.2 的全部路径下，收集探测策略（去掉 `data:`、`blob:`、`'unsafe-inline'` 的只报告策略）的违规，判断每项放宽是否必要：
   - `img-src data:`：P1 已确认表格界面需要；
   - `img-src blob:`：文字文档粘贴图片时量尺寸需要；
   - `font-src data:`；
   - `worker-src blob:`。

### 3.3 关键设计

**同源地址的形式**：
- 快照里保存相对地址 `/api/assets/{assetId}`，不写死域名，便于迁移与复制。
- 文字文档复制粘贴时，HTML 转换会把相对地址变成绝对地址（`element.src` 读到的是解析后的地址）。这条由 D7 实测；需要的话，在 `onBeforePaste` 里把本站的绝对地址规范回相对地址。

**`base64Cache`**：
- 用同源地址本身：多一次读取，但同时验证了读取可用，也不需要 `blob:`。
- 另一个候选是 `URL.createObjectURL(file)`，需要 `img-src blob:`，并且要记得释放。只在第一种不行时才评估它。

**外链图片的处理**：
- 00 号计划书 §4.1 写明"不做远程抓图"，浏览器也无法跨域读取外链（`connect-src 'self'`）。
- 所以粘贴时把外链图片替换成平台内置的占位图（同源，写明"外部图片未导入"），并提示用户下载后上传；不删除图片对象，避免破坏正文里的占位字符。

**`IMAGE()` 的限制**：
- `restricted`：启动时从 `IFunctionService` 取出原有的 `IMAGE` 执行器，注册一个同名的包装：参数是平台地址时交给原执行器，否则返回 `#VALUE!`，不产生任何请求。这样保留 SDK 对尺寸等参数的处理。
- `off`：反注册 `IMAGE`，并从函数说明里去掉。
- 两者都要在主线程与 Worker 里各做一次。

**命令守卫**：
- 作为纵深防御：插入、设置图片的命令携带非平台地址时，取消并记录，覆盖平台代码的误用与未知路径。
- 最终的防线是服务端的保存校验。
