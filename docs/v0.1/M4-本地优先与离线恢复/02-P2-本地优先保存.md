# M4-P2 本地优先保存：架构设计与实施规划

> 状态：S1–S3 完成，S4 任务 1 完成，进入持久来源接线｜日期：2026-10-10｜设计基于代码版本：`8db89a6e`（P1 合并），实施已同步 main `a8d2e0d6`｜依据：已批准的 M4 总设计 §5、§6.2、§6.3、§6.5、§6.7

## 1. 目标与范围

修改先写进本机发件箱，再按原来的节奏同步到服务器。断网期间继续捕获、加密与落盘，只有云端同步等待网络。页头分别说明本机和云端的事实；本机存储不可用、密钥暂时取不到或部署关闭草稿时，保留内存保存与离开提示。

负责 US-M4-01、02、10 的换钥部分、11、15 的部署开关部分，处理 DEF-041、DEF-071 与 DEF-012 的端到端测量。先拆编辑会话和副本流程，重构完成时原 M3 E2E 不改；此后再接功能。

P3 负责重新打开时的恢复、真冲突的完整判定、本人接管接续与自动恢复；P4 负责本机草稿页、撤权和退出的全局清理；P5 负责公式 Worker 退路。P2 不提前宣称这些链路已完成。关闭本机草稿时已有记录继续保留，读回能力沿用 P1，用户操作的恢复入口由 P3/P4 交付。

## 2. 现状与交接约束

- `edit-mode.ts` 为 2,321 行，持有租约、本机锁、保存协调、自动保存和副本流程，跨流程的代次作废已由大量 M3 用例守住。
- `autosave.ts` 为 861 行：同步捕获后把 JSON 留在 `latest`，之后算摘要；`save-coordinator.ts` 为 747 行，还在重试请求中保存 JSON；`lost-copy.ts` 又持有失去编辑权时的快照。
- 上传现在在主线程重新编码、压缩；`SaveRequest.localSeq` 用编辑器 `changeSeq`，重建后会归零。P2 必须分开编辑器修改序号与持久草稿序号。
- P1 的 `DraftWriter` 已具备登记、高水位、加密写入、Worker 返回 gzip、标记在途、确认删除/改基准、换钥与恢复。三个浏览器都采用 Worker；主线程退路不写 OPFS，但登记前默认恢复镜像。
- P1 的同源短期互斥覆盖整个持久化操作，不可绕过。Web Locks 不可用时走内存保存；旧页面不能触碰更新格式的镜像。
- 心跳已经解析 `localKeyVersion`，尚未消费。服务端编辑状态和被占用的错误已有 `sameSession`，客户端 `leaseHolderOf` 会丢掉它。
- 请求层有调用方的 `AbortSignal`，没有统一的应用时限；响应头到达不代表正文已经读完。网络状态主要取自 `navigator.onLine`。
- 本轮基线：编辑模式、自动保存、保存协调、副本四个单元测试文件共 661 项通过。P1 的本机完整门禁已通过，合并提交的 CI 另见 P1 审查报告，最终 main `a8d2e0d6` 的六项 CI 已全部通过，P1 关闭。

## 3. 设计

### 3.1 模块划分与依赖方向

| 模块 | 职责与边界 |
|---|---|
| `edit-mode.ts` | 保留阅读/进入/编辑/离开/失去编辑权的页面转移、编辑器槽位与跨流程作废；委托会话和副本单元，不管理快照正文的多份缓存 |
| `editing-session.ts`（新增） | 当前编辑会话的资源与操作：租约、本机锁、保存协调和调度的建立/停止/释放；后续接写入者登记。显式区分停捕获、停上传、结束租约、放开本机资源 |
| `lost-copy-flow.ts`（新增） | 失效捕获与副本结果归类，委托既有 `lost-copy.ts` 保持幂等重试；页面负责重载、放弃、可见状态和迟到结果作废 |
| `working-draft.ts`（新增） | 本页当前内容的唯一保存来源。对外只给捕获引用、读取上传字节、标记在途与确认；持久模式委托 `DraftWriter`，内存模式保留唯一一份工作内容 |
| `autosave.ts` | 沿用 M3 捕获与上传节奏。持有最新捕获的序号、大小、公式标记与完成状态，不再长期持有 JSON |
| `save-coordinator.ts` | 云端保存状态、请求幂等、冲突与未知结果。保留当前在途/待原样重试的 gzip，不再独立压缩、留 JSON 副本 |
| `snapshot-capture.ts` | 同一个同步段中读取修改序号、捕获、序列化、分配草稿序号并编码一次；输入提交与公式等待的规则不变 |
| `outbox/outbox-worker-client.ts`、`shared/outbox/*` | P1 的既有持久化契约；编辑器的产品状态不下沉到 Worker，Worker 不引入请求层、zod 或 DOM |
| `connection-state.ts`（新增） | 浏览器事件与实际请求结果共同形成联网状态，供自动保存、编辑权与需联网的操作共用 |
| `shared/api/` | 请求的时限、调用方取消、正文读取和错误归类；功能模块不直接调 fetch |
| config / auth / contracts | 部署开关与会话响应的加法；不加数据库表，不改变保存和租约的服务端协议 |

模块位于 `apps/web/src/features/sheet-editor/`，表中另标位置的除外。单元测试用假的编辑器、可控时钟与可暂停的存储，真实 IDB/OPFS 和 Worker 仍用浏览器测试。

### 3.2 内容与序号契约

1. **`editorSeq`**：本次编辑器实例的修改计数，只用于“当前输入是否被捕获/云端确认”。编辑器重建后归零。
2. **`draftSeq`**：登记返回的 `lastDraftSeq` 上单调分配，分配发生在同步捕获段；失败也不回收序号。持久草稿、在途元数据、上传 `localSeq` 和确认删除都用它。
3. **捕获引用**只保存元数据：两个序号、捕获顺序、UTF-8 字节数、公式标记、摘要与本机写入结果。异步完成只能更新对应的一次捕获，不把较早的完成冒充成“当前修改已保存”。
4. **上传准备**从唯一来源读取一份已经完成本机写入尝试的内容，并把序号、基准修订号、格式和 gzip 固定成一个请求。随后捕获的新内容不得改变该请求。
5. **内存退路**仍用同一上层契约。只保留一份最新工作内容，另允许一份在途/结果未知请求的 gzip；内存序号在本页单调，重新载入不会承诺恢复。此前已有的持久记录不因退化被覆盖或删除。
6. **去重**在 Worker 中按原文 SHA-256 和公式标记判定。显式保存照旧不去重。`unchanged` 不表示最新编辑器计数已被云端确认，必须与对应的内容、公式标记和云端确认元数据一起判断。

主线程在捕获后立即把编码后的字节转移给 Worker；不再为摘要、gzip、副本分别编码。持久模式的待上传内容留在发件箱，按需读取 Worker 给出的 gzip；读取和记录的元数据一致，不使用另一次捕获的字节。切换到副本流程时转交同一个来源；为只读重建而临时解压得到的 JSON 在重建完成后释放。

### 3.3 进入编辑与写入者

顺序：服务端批准 → 本机编辑权锁 → 准备工作草稿与本机密钥 → 登记写入者 → 创建编辑器及保存状态机/调度 → 撤掉交互屏障。打开自检失败仍绝不开始保存。

- Writer 身份为 `{ writeEpoch, writerId }`，`writerId` 每次新登记重新生成；租约令牌只在内存。
- `superseded` / `not-writer` 必须向服务端核对；当前代次仍属于本页才 `force`，否则停止写入并交回既有失效流程。不能只比较本机的数值大小来抢回。
- 本机锁被抢时同步停下向 Worker 发起新写入、确认删除和重封；已在途的操作由 P1 栅栏裁决。核对仍是当前者才恢复；网络无法核对期间保留工作内容，不声称已持久化。
- P2 遇已有的别页草稿或更新格式记录时保留它，不自动 `adoptSeq`。完整恢复决策属于 P3；在此之前新编辑可用内存来源，页头说明已有未处理草稿，不能静默替换。
- 释放编辑资源时放开 Worker 的镜像句柄。已经结束的会话的迟到响应不得重新登记、恢复调度或删除新会话的草稿。

### 3.4 捕获、上传与确认

```text
捕获 + 两个序号 + 一次编码
  → Worker 哈希 / gzip / 加密 / strict 写入 / OPFS 镜像
  → 记录本机结果
  → 原 M3 节奏触发上传，固定这一份 gzip 与请求标识
  → markInFlight 完成后发送
  → 云端确认 → confirm(draftSeq, revision)
```

- 网络与会话是否可写只影响上传；已经获准编辑的本页离线后继续本机捕获。捕获时机、公式上限、组合输入、提交哪一次单元格编辑、后台立即捕获均保持 M3 规则。
- 写满/无密钥/存储不可用不阻止上传：使用这次压缩好的字节并如实进入内存退路。写满时每次新的捕获再尝试一次，不为同一份内容开启高频重试。
- 持久模式在上传之前先等待 `markInFlight`；失败不能假装留下了重放信息。属于存储问题时保留内存请求并标记本机保障降级；属于被栅栏拒绝时先核对编辑权。
- 上传期间的新捕获带上仍未确认的 `InFlightSave`。成功回执只确认对应的 `draftSeq`，更新基准；新记录保留并按新基准重封。内容相同的回执同样确认。
- 超时/断线/无法解析响应视为结果未知，保存相同的请求标识、字节和元数据。新内容不套用旧请求标识。旧请求的迟到结果只对原请求生效。
- 版本冲突、失去编辑权、容量超限、客户端过旧时保留内容来源。离开提示继续依据未获云端确认的内容和未提交输入，已写本机也不能省略提示。

### 3.5 密钥与宿主退路

- 阅读时不取密钥，进入编辑时使用 P1 `createLocalKeyKeeper`。密钥只保留不可导出的 `CryptoKey`；原始字节清零，不进日志、事件或页面测试状态。
- 心跳版本交给 keeper。取用在途时出现更新版本也必须记住，旧响应不能重新激活过时密钥。先停用旧密钥，再 `setKey`，对 `notResealed` 的当前工作内容不去重地重写。
- 密钥取不到时上传照旧、页头说明未保存在本机；退避沿用 keeper，会话类失败只在连续第一次确认后立即重试。退出/换人停写并丢掉密钥。
- 发件箱 Worker 创建/握手失败才回退到 P1 的进程内管道；不注入空恢复。回退时没有 OPFS 冗余，状态如实说明。运行中的 Worker 崩溃使在途操作结束，重新准备宿主并核对写入者；无法可靠接续时保留内存内容。
- Web Locks 不可用不能运行持久管道，直接用内存来源。新版镜像受保护，不以“修复存储”为由清除。

### 3.6 请求时限与联网状态（DEF-041）

- 通用请求默认 30 秒；快照保存/副本为 60 秒（给上传、检查队列与检查本身留余量）；租约申请、核对、续租/续上为 10 秒。本机取钥同为 10 秒。已有退出编辑释放的 5 秒等待上限保留。
- 时限覆盖从发出到正文读取/解析结束；HTTP 头到达不能取消计时。调用方主动取消与超时分别归类，组合 signal 不泄漏监听器和定时器。
- 超时主动取消 fetch，同时让调用方有界结束；晚到的响应不更新 UI。网络放弃不代表服务端回滚，沿用保存 requestId 与申请编辑权的未知结果记号。
- `navigator.onLine === false` 立即表示离线；为 true 仅表示可以尝试。网络错误/超时进入连接异常，实际请求成功或联网事件触发受控复核；按既有退避避免请求风暴。
- 页头说明“网络没有回应，正在重试”。没有本机成功证据时不能配上“修改已保存在本机”。离线超过编辑权 90 秒有效期，说明恢复后若有人保存，修改会另存为副本；联网先续租/续上，再同步。
- 分享、移动、改名、复制、删除、请求编辑等依赖服务端的操作在离线时不可用并说明原因。已在编辑的本页继续输入与捕获，阅读页不能离线进入编辑。

### 3.7 被本人接管的位置（DEF-071）

保留 `LeaseHolder.sameSession`。得到本人接管时读取服务端编辑状态：持有者是本人且 `sameSession` 为 true 就是这个浏览器的登录，false 就是另一处；强制接管和他人持有者不误用此字段。读取不到、持有者已消失或结果不属于本次失效时，才用现有本机锁证据与有界等待。

读取同样有时限，失败不阻止先停写、保留内容与转只读。新结果只影响当前这次失效的说明，不让已经完成的流程倒退。S1 纯重构不改变这条原则，S2 单独实现并验证。

### 3.8 部署开关与状态

- 新增 `NERVE_LOCAL_DRAFTS_ENABLED`，默认 `true`，只接受 `true`/`false`；非法值启动失败。`AppConfig.clients.localDraftsEnabled` 经会话响应 `features.localDraftsEnabled` 给页面，登录、当前会话、修改密码和换登录的响应共用实现。
- 关闭后不新建/写入草稿，不为新写入请求密钥，不申请持久保存。已有草稿保留，处理入口在 P3/P4 接入。配置不会自动删除用户内容。
- 页头保留云端保存状态，另有本机事实：尚未捕获、写入中、已保存在本机、镜像降级、空间不足、存储不可用、密钥不可用、部署关闭。当前修改晚于最后落盘的一次时不能显示全部已保存在本机。
- 默认文案沿用总设计：“已保存在本机（等待同步）”“已离线，修改已保存在本机”“本机存储空间不足”“本部署关闭了本机草稿（浏览器崩溃会丢掉没保存的修改）”。镜像降级和进程内退路需明确本机保障的限制。
- 首次进入允许持久保存的编辑会话申请 `navigator.storage.persist()`；拒绝不阻止编辑。状态详情的数据与 P1 `storage-status.ts` 共用，P4 再集中展示。

### 3.9 安全、产物与可观测性

无服务端数据迁移，接口只做加法。保存和租约的认证、权限及请求幂等协议不变。遥测只记录状态、耗时和大小，不记录内容、密钥、令牌或用户草稿的明文。

发件箱 Worker 登记 15 KiB gzip 预算（P1 最终 13.27 KiB）；生产与测试构建都检查闭包，Worker 不包含 zod/请求层/DOM。平台入口仍为 180 KiB、最多两个首屏文件，不为编辑器保存功能增加平台首屏加载。遵循现有模块边界和公开入口，不引入新的依赖。
