# M4-P5 公式 Worker 的退路：架构设计与实施规划

> 状态：进行中，S1–S5 已完成｜日期：2026-10-16｜基于代码版本：`c6c0d5ac`（P4 最终合并，CI `38897083387` 六项及原件验收通过）

## 1. 目标与范围

落实 M4 总设计 §6.8、US-M4-13 与计划书 §10.2：公式 Worker 创建、加载、启动握手失败或运行中报错时，保留内容，以同一档案的主线程变体重建，强制重算后继续阅读与编辑。保存结果符合 A18，页头说明大表可能卡顿，诊断只上报有限枚举。

本 Phase 不升级 SDK、不修改快照格式、不重新申请编辑权、不增加第二份草稿来源。DEF-072 的 Worker 空闲延迟和让出间隔纳入实测；不提前做 P6 的断电验证与全阶段验收。所有工作在唯一分支 `codex/m4-p5-formula-fallback`，主目录始终为 `main`。

## 2. 现状与依据

- `editor/sheet-editor.ts` 的 `createFormulaHost` 创建同源模块 Worker；`worker-image-policy.ts` 以 IMAGE 安装回报证明启动，挂载共用 20 秒就绪期限。就绪后撤掉所有 Worker 监听，后续故障没有独立信号。构造器抛错尚未归入 Worker 原因。
- `profile/sheet-profile.ts` 已有主线程变体：不注册 RPC、三处 `notExecuteFormula: false`、`intervalCount: 20`、档案标识相同；目前只能从测试构建的查询参数选择。
- `formula-round-stop.ts` 与槽位异步销毁已规避 UR-032：主线程算到一半时先停止、等结束再销毁，保留 30 秒异常上限及报告。不能移除或缩短这条规避。
- `features/sheet-editor/editor-slot.ts` 是具体实例与容器的唯一持有者，按 ticket 串行替换。`editing-session.ts` 持有租约、锁、工作草稿、保存协调器和自动保存；这些对象直接订阅创建时的编辑器，不能靠销毁会话来换实例。
- `snapshot-capture.ts` 区分未提交单元格、面板防抖、公式收齐。输入法组合期间不能销毁；`interaction-barrier.ts` 会拦住 compositionend，所以等待组字结束必须早于挂完整屏障。
- 打开自检失败的实例绝不进入保存；上报现有 `open-check-failures` 接口有严格结构、可读权限、去重及账户限量。Worker 退化是可恢复诊断，不得伪装成资源损坏而禁止正常编辑。
- P4 的每实例内存偏好覆盖在主线程变体仍须安装。根 main `c6c0d5ac` 的本机门禁为 14,025 单元/集成、2,042 浏览器通过及 16 个既有跳过；容器 268 通过。CI 为 2,723 浏览器通过、20 个既有平台跳过，六项全绿；完整回执在 `.codex/handoffs/m4-p4-20261014/p4-completion-receipt.json`（外部忽略目录）。

## 3. 设计

### 3.1 模块划分与取舍

采用“适配层报告事实，页面协调重建，保存会话保持身份”的分工：

| 模块 | 职责 |
|---|---|
| `editor/formula-worker-failure.ts` 与 `image-function/worker-image-policy.ts` | 有限故障枚举、启动期限、完整 Worker 生命周期监听；不读快照、不请求接口、不操作保存会话 |
| `editor/sheet-editor.ts` | 显式选择执行模式；暴露当前模式、首个故障与订阅；具体实例的创建、捕获、销毁仍由适配层完成 |
| `features/sheet-editor/editor-slot.ts` | 维持同容器一个实例；把主线程选项传给工厂；取消与旧创建结果的回收沿用 ticket |
| `features/sheet-editor/saving-editor.ts`（新增） | 编辑会话内稳定的捕获/订阅入口；换实例时延续修改序号，间隙只读已固定的完整快照；不持有 SDK、不管理租约 |
| `features/sheet-editor/formula-fallback.ts`（新增） | 本页模式偏好与创建失败后的单次重试，不持有具体实例或保存资源 |
| `features/sheet-editor/formula-recovery.ts`（新增） | 单飞恢复流程、等待输入、取消与结果；依赖注入，具体页面状态和权限仍由 edit-mode 决定 |
| `editing-session.ts`、`edit-mode.ts`、`editor-page.ts` | 保留原协调器、草稿及租约；在合法状态执行恢复，挂屏障，处理失权/换人/退出优先级，接纳新实例 |
| 现有诊断契约、服务及页头 | 可恢复的 Worker 故障报告、提示、失败时可操作的说明；不把普通退化报告成未处理页面错误 |

未选择：①修改已注册插件原地切换（SDK 不支持）；②完整重建编辑会话（会丢失在途请求、保存序号与草稿身份）；③适配层内部悄悄重建（页面无法可靠协调未提交输入、失权和打开自检）。不把新状态继续堆进 `edit-mode.ts`，新恢复编排和稳定保存入口分别独立测试。

### 3.2 故障与适配层契约

Worker 故障枚举为 `create`、`error-before-ready`、`messageerror-before-ready`、`ready-timeout`、`image-policy`、`error-after-ready`、`messageerror-after-ready`。浏览器的 error 无法可靠细分网络加载失败和脚本执行失败，名称不声称能区分。这里“ready”指 Worker 已回报 IMAGE 限制安装成功，不等同主线程渲染完成。

`FormulaWorkerError extends SheetEditorLoadError` 带只读 `failure`；启动错误保留既有 `worker-failed` / `image-policy-failed` 分类。Worker 握手仍为 20 秒；已收到成功回报却渲染超时是普通 `ready-timeout`，不能冒充 Worker 故障。主线程 IMAGE 失败、快照无效、插件注册失败、测试模块加载失败均不触发 Worker 退路。

`CreateSheetEditorOptions.formulaMode?: 'worker' | 'main-thread'` 是生产参数，不是生产 URL 开关；显式参数优先于测试构建选择。返回值增加 `formulaMode`、`workerFailure()`、`onWorkerFailure(listener)`。订阅不隐式回放，调用方订阅后读取 getter，补齐创建与接线之间的窗口。首个故障锁存，重复事件不重复通知；销毁移除监听和计时器，旧事件不复活恢复。回报成功后继续监听 error/messageerror；坏回报不能把已失败的 Worker 重新标成成功。

`formulasSettled()` 在 Worker 失效后为 false，相关订阅会收到进度变化。只处理本适配层持有的 Worker 的故障事件，不加全局页面错误过滤。加载与导航取消继续服从页面的离开处理。

### 3.3 保存身份与重建快照

稳定保存入口只活在同一编辑会话内，协调器、自动保存、本机草稿始终引用它。具体编辑器替换时：退订旧实例；逻辑修改序号不倒退；新的实例以当前逻辑序号为基准，后续模型修改再递增。主线程全量重算的 onlyLocal 写回仍不计作用户修改。

恢复前先让当前输入落入模型，捕获正文、视图与逻辑序号，交给原 `WorkingDraft`，明确 `formulasPending: true`。恢复不会清除尚未 ACK 的捕获、换 requestId 或修改在途请求字节。冻结前先等完已经发起的输入准备，不等 HTTP；提交当前输入和面板准备的每个 await 后均复核恢复资格。冻结后，排队保存只能读固定快照；新实例通过打开自检后才切换到它。未覆盖输入的旧草稿不能冒充最终捕获。

自动保存需显式接纳这份恢复捕获（包括修改序号未变但公式结果作废的情况），并在强制重算收齐后补存无标记版本。原在途 ACK 只确认它自己的序号，不得把恢复快照提前标为已保存。不用伪造用户编辑来强迫自动保存。

### 3.4 关键流程与优先级

1. **启动失败**：页面选定本页主线程偏好，等失败实例完全销毁，以原快照、原 access 和视图重建一次，强制全量重算。重建也失败时沿用可见的加载失败；不回到 Worker 无限循环。
2. **阅读中失败**：固定当前内容与视图，屏障覆盖重建；沿用相同 read 权限，主线程重算，绝不申请编辑权或保存。后续进入编辑也用本页已选定的主线程模式。
3. **编辑中失败**：标记公式不可用。若正在组字，显示等待完成输入，先不装会截断 compositionend 的完整屏障；组字结束后离开该事件栈再进入准备。随后挡住新输入，提交当前单元格并等待面板防抖，固定完整快照及草稿，再经槽位销毁和主线程重建。
4. **提交或捕获失败**：保留旧实例，不销毁未落盘输入，提示完成输入/重试；恢复入口不能把失败写成成功。已经固定快照后重建失败，保留快照和原保存状态，停止编辑器输入，提供重试/既有副本或重载路径；任何放弃内容仍沿用已有确认。
5. **重建完成**：打开自检通过、页面 generation 与账户/租约仍有效才接纳。保存入口绑定新实例后才撤屏障。若自检失败，保留重建前完整快照，绝不捕获或上传新实例的不完整模型。
6. **并发事件**：失权、会话结束、权限撤销和卸载优先；恢复任务可取消，迟到结果交给槽位销毁，不能恢复编辑或重启保存。失权捕获可读取已冻结的完整快照。故障在进入/退出/刷新期间发生时，由正在进行的同一替换流采用主线程偏好，不启动第二条替换。用户新发的保存/退出/交出在恢复期间按页面状态阻止或排队，不直接调用已销毁的实例。

### 3.5 诊断、界面与兼容

沿用现有诊断接收通道，新增“公式 Worker 故障”的可恢复报告变体；与资源缺失报告分开判定，不给故障捏造资源名。严格 schema 只收上述种类、既有文档修订/access/构建元数据，不收快照、公式、Worker URL、message、stack。服务端沿用可读权限、CSRF、账户限量和去重；无数据库迁移，旧报告仍按原结构接收。实际契约在 S4 按现有服务细化。

页头常驻状态区说明正在恢复/等待输入/恢复失败；成功后说明“公式已改用当前页面计算，大表格可能暂时卡顿”。不称为已保存，不覆盖离线、本机已存或服务端已存的既有事实。按钮和快捷键使用相同恢复状态。生产没有故障注入或模式查询参数。

### 3.6 让出间隔与 DEF-072

在 S5 独立测量 Worker `intervalCount` 为 20、50、100 时计算耗时与 stop 延迟；主线程现有 20 先保持。记录原始样本、环境、比较依据，结论写入 ADR-010。对 DEF-072，先在 Playwright WebKit 按原 `measure:probe -g 冷热` 跑 off/on 对照，测试候选 100 ms 空计时器；只有证明有效才在真实 Safari 复核并决定采用。若无效，继续定位，不把“加了计时器”当作解决。测量不与门禁或其他性能工作并行。

## 7. 风险与自审

2026-10-16 自审：识别并纳入设计的关键风险是保存入口旧引用、组合输入被屏障截断、公式失效但修改序号未变导致不补存、恢复期间原 ACK 误覆盖、迟到实例恢复已撤销编辑权。分别由 S2/S3 的状态与交错测试覆盖。总设计内既定的跨层接线按其已批准边界实施；不增加新的数据格式、权限或持久化机制。

运行中单纯 `Worker.terminate()` 不会自动产生错误通知，故障测试须使 Worker 本身执行抛错或派发真实错误路径，不能把“已终止”直接等同浏览器已报告。浏览器不提供的崩溃分类不在日志里猜测。实现如发现保留输入或权限所需契约与现有协议冲突，先保存证据再按 CLAUDE.md 的意外高风险规则处理。
