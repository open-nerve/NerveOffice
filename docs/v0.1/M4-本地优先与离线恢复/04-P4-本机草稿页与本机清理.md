# M4-P4 本机草稿页与本机清理：架构设计与实施规划

> 状态：设计自审通过，待逐 Step 实施｜日期：2026-10-14｜基于 main：d9fa57f1｜唯一分支：codex/m4-p4-drafts-cleanup

## 1. 目标与范围

落实 M4 总设计 §5 的 P4：让本人在一处找到这台设备上尚未同步的修改，并能恢复、另存为副本或放弃；退出登录、账户停用、文档不可读及保留期到期时，完整且如实地处理本机数据。

覆盖 US-M4-07、08、09、10 的全站发现与清理部分，以及 US-M4-12；承接 US-M4-15 的关闭新写后处理既有草稿。上线门槛对应 A06、A14，并保持 P3 的 A05/A07/A16 与明确恢复边界。

范围包括本机草稿页、空间列表/与我共享/搜索标记、文档事实的批量只读接口、会话失效原因、用户级清理协调、14 天保留期、Univer 存储的内存实现及旧记号清理。没有离线冷启动、自动原页身份继承、跨设备草稿同步、批量恢复/批量副本或新的编辑器能力。P5 的公式 Worker 退路、P6 的真实 Safari 暂停及虚拟机断电仍留在原 Phase。

## 3. 设计

### 3.1 模块与依赖方向

选择“共享无界面能力 + 独立草稿页 + 编辑器负责编辑重建”：

| 模块 | 职责与边界 |
|---|---|
| contracts/auth、contracts/documents | 会话失效原因及批量文档事实的运行时契约、数量上限；不依赖浏览器或 Node |
| api/auth | 按请求真正持有的登录判断失效原因；统一守卫、快照与写事务的说法，保留换令牌时不清除新 Cookie 的规则 |
| api/documents | 在一个只读快照内批量读取标题、权限、修订/来源与编辑占用；无权与不存在同样回答，不读取快照正文 |
| web/shared/outbox | 原件观察、镜像比对、条件清理、用户清理栅栏和存储状态；保持 SDK 无关 |
| web/shared/local-drafts | 从 P3 提取无界面的恢复判定及副本协调、目录管理与清理生命周期；不引用 app、功能组件或 editor |
| web/features/local-drafts | 按需加载的本机草稿页、逐条操作与状态展示；依赖共享能力及公开 API |
| web/features/documents、search、shared-documents | 通过轻量共享索引显示本人未同步标记；不为标记取钥或访问新的服务端接口 |
| web/app 与 sheet-editor 组装层 | 注入当前会话、页面存活性、宿主和导航；接入启动清理、退出及失效处理 |
| web/editor | 用现有 SDK 依赖注入点替换本机存储服务，SDK 类型与实现留在适配层 |

直接让平台引用 sheet-editor 会破坏入口隔离；在草稿页重写恢复判定会使权限、原样重放及条件删除逐渐分叉。这两种做法均不采用。提取时保留 P3 的行为与测试，编辑器仍负责申请编辑权、文档锁、公式重算和 SDK 重建；共享层不取得这些权限。

### 3.2 批量文档事实

新增 GET /api/documents/draft-facts，查询参数 ids 为逗号分隔 UUID，输入最多 100 个（包括重复项），去重后按首次出现的顺序返回。空、非法 UUID、重复参数或超过上限都按 REQUEST_INVALID 拒绝；前端对更长列表按批串行查询。静态路由登记在 :id 路由之前。

每个请求 id 必须有且只有一项结果：

- accessible：id、title、type、canEdit、revision、revisionSource、occupied。occupied 是当前有效租约或有效预留的布尔事实，不返回租约令牌、实例或持有者身份。
- unavailable：只有 id 与该状态；无权、不存在、已删除和当前不能读取均同形，不泄露标题、位置、权限或修订。

只在同一只读快照中读取文档、批量权限、修订来源与有效编辑占用；同一连接逐条 await。查询使用有界 id 数组参数，保留权限单一入口和请求开始后的身份复核。查询不是授权凭据：恢复、副本和清理操作开始时重新核对所需事实。离线、超时、401、5xx 或结果格式错误都不能当成 unavailable。

### 3.3 会话失效与账户清理边界

在 SESSION_EXPIRED 的 details 增加经契约校验的 reason。对真正识别出的会话，同时带该会话所属 userId，供页面绑定清理对象；随机/格式错误/已无法识别的令牌不带可推测的账户事实。reason 区分 account_disabled、password_reset、password_changed、replaced、logout、expired。登录失败继续保持原来的统一响应，不暴露停用。

守卫、只读快照的身份复核和写事务 requireActive 复用同一分类方法，查询必须使用所在事务；数据库错误仍是原来的失败，不能归成 expired 或 account_disabled。被 replaced 撤销的旧响应继续不清除浏览器可能已经收到的新 Cookie。

页面处理规则：

| 事实 | 行为 |
|---|---|
| 本人明确退出 | 先展示未同步列表与去草稿页的入口；确认后停写、丢弃密钥、清理本人本机数据，再结束登录；分别记录本机清理和服务端退出的结果 |
| 已识别登录的 account_disabled | 停写、丢弃密钥并清理对应用户；说明账户已停用 |
| password_reset/password_changed/expired/replaced、未绑定本机明确退出操作的 logout，或未知的认证失败 | 停止当前会话写入并提示重新确认/登录；保留草稿，不当作停用；同源明确退出由已建立的本机清理资格协调 |
| 网络或会话查询结果未知 | 保留草稿，显示原因与重试；不执行撤权清理 |
| 清理期间同一人重新登录或换人 | 旧清理资格立即失效，迟到回包与 pending 重试不能清理新会话的数据 |

用户级协调必须覆盖所有新写入宿主与清理入口。它在共享存储中记录用户清理状态与代次，写入/登记使用绑定到其认证来源的代次；清理在同源互斥内核对该资格、停用旧写入者、清镜像与库。新会话激活和旧清理共用顺序约束，不能靠“发了广播”或“刚查过会话”推定没有竞争。广播只加速其他页停写/重新核对；漏收、冻结后恢复、晚到登记同样由存储栅栏拒绝。

新增栅栏只存必要的非秘密元数据，不持久化 Cookie、CSRF 原值、密钥或正文，不替代服务端授权。S2 在细化规格中固定代次获取、失效、激活与 pending 清理的完整交错；这些交错的确定性反例通过后才接入退出界面。

退出有两个独立结果：会话已结束不代表本机已清空。本机清理 pending/失败仍须结束服务端会话并明确保留“本机数据尚未清理完成”的说明及重试；后续只在该用户仍未重新登录且清理资格仍有效时重试。服务端退出结果未知时保持停写和原操作资格，按现有请求/会话确认规则核对，不能显示已经退出；同用户新登录、换人或新激活代次都使旧操作结束，重新退出须重新展示当前草稿并确认。

### 3.4 本机目录、恢复与逐条操作

先对当前用户逐份 reconcileAll，再列主库和未能完成比对的镜像事实，不能把镜像读取失败当作“没有草稿”。每份检查串行进行，任何时候只借用当前记录的解密数据，不把全部正文放进 React 状态或查询缓存。页面留标题、时间、状态与操作结果；标题来自有权限的服务器响应，无法确认时显示“无法确认文档”及本机时间，不猜测标题。

状态由共享 P3 判定产生：可以恢复、他页占用、有冲突、只能另存为副本、需要联网/重试、需要更新页面，以及已清理的不可读/过期/吊销/损坏说明。已知存在但读盘/取钥失败保持待处理；较新密钥版本先取新钥再试，较新格式保留。解密认证失败或原文档确定不可读才按既定规则条件清理，界面保留具体结果说明。

- **恢复**：草稿页的“打开文档恢复”进入对应文档页，仍由 P3 提示中的明确点击授权恢复/接手；导航参数不授予编辑资格、不继承身份，也不自动申请租约。最终正文、重算与唯一修订沿现有恢复链路验证。
- **另存为副本**：在草稿页经共享副本协调提交原记录的内容，保留同一 requestId 的未知结果处理、目标位置与标题规则。操作开始绑定认证原件，副本确认后只条件清理该原件；不得用副本修订确认原文档。正文仍受当前格式、权限和服务端上限核对。
- **放弃**：二次确认绑定当时观察到的完整记录及写入者，点击后不重新观察一份新记录并把旧确认套上去。changed 时保留新记录、说明变化并要求重新决定。
- **并发变化**：单条操作中按钮保留且防重入；其他页更新后刷新目录。列表上的旧事实不能让操作越过当前权限和原件核对。条件清理的镜像 pending 如实展示并保留墓碑，不报告全部已删。

账户菜单始终保留入口，关闭本机草稿部署同样可以处理既有记录。无草稿时有明确空状态。存储状态分别显示持久保存授权、已用空间和配额；不支持或读取失败时说明“无法取得”，不用零冒充事实。沿用既有申请持久保存的入口，不声称授权等于永久不丢。

### 3.5 启动、保留期与旧数据

任意平台入口及编辑器启动均接入共享维护协调，按实际会话确定本人的提示范围。清理超过 14 天的记录时不论属于谁，仍沿 IDB/OPFS 合一规则；只向当前用户说明其被清理的文档，能重新确认读取权限才显示标题。新格式、未来时间、无法判断到期或读取失败的记录保持保守处理。维护失败不阻塞普通阅读，也不虚报清理成功。

退出/停用需要清理发件箱记录、写入者和提示、OPFS 镜像、本人的 pending-save，以及遗留 reload/edit-request 记号。墓碑和必要的停止写入凭据属于清理协调状态，镜像 pending 未完成前保留，完成后的回收仍不能让旧操作重新取得资格。

pending-save 键改为 userId/documentId 共同限定，所有调用点从已确认会话取得 userId。旧未分用户的键不迁移成任何人的授权或草稿，只作无内容旧记号清理。edit-request 继续留在当前 Document 内存；不为满足旧总设计的措辞重新持久化已经退役的意图。

Univer 的 ILocalStorageService 换成每个编辑器实例的内存实现，销毁时释放。按锁定版本的真实 API 实现并登记；数字格式习惯和最近使用项不再跨页面保存。清理旧 UniverLocalStorage IndexedDB、UniverLocalStorage/ 前缀键及 univer-mobile-recent-formula-functions，不能遍历删除站点的其他库/键。数据库 blocked/失败必须可见且可重试，不能误报完成。

### 3.6 模型演进、失败与体积

服务端复用现有会话撤销原因、文档、修订、租约表，不新增服务端表；如需补充读取方法，仍由所属模块仓储负责。客户端用户清理栅栏用明确的新 object store 作加法升级，旧草稿密文、AAD、OPFS 槽位格式及序号语义不变。旧连接 versionchange 必须关闭；升级 blocked 时显示本机存储不可用/等待其他页关闭，不绕过栅栏写入。

错误按原契约分类，不把超时、认证未知、较新格式或暂时镜像占用归为不存在/撤权/损坏。清理和写入保持短期同源锁与 strict 事务；网络确认不放进 IDB 活事务。异步回调带当前认证来源与操作代次，退出/换人后不再采纳旧结果。

不增加依赖，原 CSP、覆盖率、构建和体积门槛保持。平台只首屏加载轻量入口与索引契约，完整目录/解密/清理模块按需加载；共享提取不得增加首屏文件数。Worker 接入栅栏时做增量构建核对，超限先拆清职责与消除重复，不悄悄上调预算。

界面沿用现有组件、简体中文 messages、页面标题、StatusRegion、ConfirmDialog、RetryButton 和焦点恢复约定。进行中的按钮不卸载，行移除后焦点回到稳定元素，长列表状态区不把焦点推出视口。日志只记录分类及请求标识，不记录正文、密钥或认证材料。
