## 关键发现与处理

| 根因 | 修复后的行为与反例 |
|---|---|
| 恢复初值被当作已保存；内存恢复暂停后无法继续 | 显式 initialUnsaved，editorSeq=0 仍调度上传；固定内存来源可暂停/继续。打开自检和最多 10 秒公式收齐在采用之前，失败保留原件 |
| 租约 source 缺失、旧请求成功后使用旧快照、迟到结果越过生命周期 | 真实 acquire 封装透传 source，区分 undefined 与 null；原请求无租约重放，只有明确 EDIT_LEASE_LOST 才判未接受。确认后取最新云端；会话、租约、本机锁、来源代次作废时取消安装与清理 |
| 旧观察/旧回执删除新记录；未知副本被重新创建 | 清理闭包绑定原宿主、钥匙、观察和存在事实代次；不重新观察后套旧回执。副本流程按原件摘要关联，未知结果保持同一 requestId/gzip；成功链接与清理结果独立保留 |
| blocked 或暂停后的旧宿主持有镜像句柄；空阅读多留 Worker | blocked 先 retire 原宿主，再建立阅读候选。暂停先同步停写，由唯一来源保留正文后关闭绑定的旧宿主；保留失败留下读回退路。无候选/待清理时释放 Reader，提示确认按原 at 重开并条件清除 |
| 新恢复保护阻断合法存储退路，或中途已见原件却被误当空白 | 从未见原件且浏览器明确 denied/unsupported 时，普通入口可固定内存编辑云端内容。镜像忙、配额、一般失败、blocked/newer-version 不授予此许可。未知副本仍阻止新编辑；不得从固定内存自动重新登记 |
| 存在事实在部分读取、换钥、重登或事务重试中丢失 | Store 收到非空 raw 即记录事实，跨连接重试保留；镜像第一槽已读而第二槽失败仍携带事实。Writer、协议、Reader 二读及有效 prepare 轮次贯穿 recordKnown，包括 superseded→核对→force。取消仍优先，失败不附旧凭证；从未读到原件的错误不虚构存在事实 |
| 404 页面不再是无副作用的存储探针入口 | 存储探针改开不带 documentId 的 editor.html，HTTP 密钥探针自行取 session/CSRF。空库断言未删；真实文档地址上的早期 404 仍验证清理提示、原件删除和 HTTP 404 |
