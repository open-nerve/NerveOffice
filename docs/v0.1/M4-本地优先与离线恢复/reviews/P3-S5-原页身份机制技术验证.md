## 官方语义与源码边界

Navigation key 对应历史项位置，同源替换允许复用；id 描述具体条目，两者不是公开的标签页编号。[HTML NavigationHistoryEntry](https://html.spec.whatwg.org/multipage/nav-history-apis.html#the-navigationhistoryentry-interface)

固定 WebKit 源码 `22a2306fb72994403a9910071fff0284a132292b` 的 FrameState/HistoryItem 会复制 navigation key；新建 NavigationHistoryEntry 时 id 随对象生成，复制既有 Entry 才沿用 id。跨进程 FrameState 转换传 classic state/key，未传 Navigation API state。因此 id/Navigation state 普通刷新保留，仍可能在崩溃时丢失。**这是上游源码推论，不能写成本机实测结论。**[Entry 构造](https://github.com/WebKit/WebKit/blob/22a2306fb72994403a9910071fff0284a132292b/Source/WebCore/page/NavigationHistoryEntry.cpp)、[跨进程转换](https://github.com/WebKit/WebKit/blob/22a2306fb72994403a9910071fff0284a132292b/Source/WebKit/WebProcess/WebCoreSupport/SessionStateConversion.cpp)

Service Worker 的 clientId 是请求发起方，resultingClientId 是新客户端；二者不能替代被导航掉的原页。规范中的 replacesClientId 更接近前驱关系，但固定 WebKit IDL 未提供它，未验证前不引入生产 Service Worker。[SW 规范](https://w3c.github.io/ServiceWorker/#fetch-event-clientid)、[WebKit IDL](https://github.com/WebKit/WebKit/blob/22a2306fb72994403a9910071fff0284a132292b/Source/WebCore/workers/service/FetchEvent.idl)

## 候选边界与下一步
