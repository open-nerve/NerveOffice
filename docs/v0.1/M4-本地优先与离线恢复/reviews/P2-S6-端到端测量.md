# P2-S6 本地优先端到端测量

> 2026-10-11；生产逻辑 `cc25266a`；三浏览器 18 组 × 20 次，360 次真实落盘验证。正式运行 18/18 通过，8.2 分钟，零重试/跳过。本报告只证明下面列出的环境与样本，不替代整 Phase 功能门禁。

## 结论与边界

全部组的完整样本 p95 为 **1,036.7–1,155.4 ms**，360 次中的最大值 **1,184 ms**，均小于 2 秒。满足公式完成 ≤900 ms 条件的 347 次另算统计，各组 p95 同样通过；其余 13 次完整保留，并未从“全部样本”中删除。约 1 MiB 的同步捕获 p95 为 **9.8–24 ms**，低于 100 ms 目标。

这是实际编辑器 → 生产自动捕获 → WorkingDraft → 发件箱 Worker → IndexedDB → 本机保存指示的链路。每轮都在计时结束后独立读密文、解密，核对新的 draftSeq、修改值、公式缓存与捕获序号；不是只看 UI 文案。离线组核对期间没有 HTTP 保存，在线组最后等待自然上传并核对服务器上的最终正文。

未运行真实 Safari；Playwright WebKit 不等同于真实 Safari。DEF-012 的本地优先管道部分在本环境完成，真实 Safari 的端到端复核仍保留给 M4-P6 的真实浏览器验证。P1 的真实 Safari 存储基线不因此变成 P2 端到端证据。部署环境、100 ms RTT/20 Mbps 的云端保存性能属于 M7 范围。

## 环境与方法

- Apple M4 Pro，12 核，48 GiB，macOS 内核 Darwin 27.0.0 arm64，Node 24.21.0、pnpm 12.6.0。
- Chromium UA 154.0.0.0；Chrome UA 153.0.8010.12；Playwright WebKit UA Version/26.6、AppleWebKit/605.1.15。完整 UA、时间与机器信息写在各原始 JSON。
- 北京时间 2026-10-11 01:54:14 至 02:02:25；持久资料目录每组独立，真实时钟，单 worker，浏览器串行，无重试。没有并行运行本项目的构建或其他测试。
- **不是完全空闲机器**：各组前后的一分钟系统负载为 6.63–13.27；系统及远程桌面等后台活动仍存在，未结束用户程序。保留每组的 loadavg。结果是在这份实测负载下通过，不能表述成无背景负载的基准；没有因慢样本而重跑挑数。
- 样本模板字节：1m 1,018,497；5m 5,086,987；perf-50k 1,286,300（约 5 万格、1,000 个公式）。前三者都使用既有真实样本生成器，实际捕获字节见逐轮 rawBytes；公式组逐次修改依赖单元格并核对结果缓存。
- 起点在浏览器内同步修改命令开始之前，包含命令成本，保守于“修改停止”；终点是本轮对应的 saved DOM 更新，必须先经过非 saved 状态，防止把上一轮的完成当本轮。两端都用同页 performance.now；没有主动 flush、快进时钟或调整捕获/上传节奏。
- “首轮”指全新持久上下文打开编辑器后的第一次修改；不声称包含启动浏览器或打开编辑器的时间。首轮纳入全部分布，没有暖机剔除。
- 分位数采用最近秩。公式完成时间由同页逐帧被动观察，包含到观察帧的等待；不是公式 Worker 的纯 CPU 时间。无公式的 bulk 样本该项按 0 记录。

## 校准、检查与独立审查

两轮校准时 18 组均完成实际落盘校验，14 组通过；4 组 Chromium/Chrome 公式时间全部超过 900 ms，失败点是测量器额外要求“至少一轮满足公式条件”，端到端本身约 1 秒。该非空要求不是既定性能目标：修订为条件内样本为空时，仍要求**全部**样本 p95 ≤2 秒，报告明确无条件内样本；没有修改生产节奏、性能阈值或删除慢轮。本次正式 20 轮各组都有条件内样本，不使用这个后备分支。

测量代码通过相关 lint、全工作区类型检查；复用已有统计单元测试。独立只读审查 C0/I0/M0：确认排除旧 saved、真实持久上下文和逐轮内容核对、原始结果先于性能断言写出、最近秩统计与条件外样本保留。全量代码门禁另见 `P2-审查报告.md`。
