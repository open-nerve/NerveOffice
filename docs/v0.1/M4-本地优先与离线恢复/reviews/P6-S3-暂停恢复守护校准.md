# P6-S3 暂停恢复守护校准

日期：2026-10-17。结论：原生保障子计划通过。本报告仅记录自有空进程校准，没有暂停真实 Safari；完整 S3 实机验收及 DEF-069 结论另见 `P6-S3-真实Safari暂停与请求恢复.md`，不能用本子计划替代它。

## 1. 实现与边界

`profile-pause-native.swift` 只接受完整、新鲜的 Apple WebContent 身份。Swift 在桌面解锁、连续空闲 120 秒、唯一当前 UID 控制台会话和内核出生身份检查后发送一次 STOP；确认 SSTOP 后使用连续单调时钟、非阻塞管道、直接 IOKit 和内核查询监测。暂停上限 180 秒，还受控制端原有绝对截止时间限制。生产入口没有空进程或测试模式参数。

所有中止路径共用恢复：只向本次成功 STOP、出生身份/UID/父进程/路径未变且仍停止的目标发一次 CONT，确认离开 SSTOP。独立 JSONL 文件在恢复尝试后才写入并 fsync；磁盘等待不延长暂停。stdout 关闭/拥塞不阻塞恢复，Node 不会用 kill 清理守护者。Node 的正常结束仍须有完整终态和退出码 0；提前恢复不等于实验正常完成。

守护者自身遭 SIGKILL/OOM、宿主断电或内核无法调度不在保障内。人工 STOP 没有执行 WebKit 自主暂停协议，不据此推断 Safari 自然后台行为。

## 2. 原件与结果

原件位于主库 `.codex/handoffs/m4-p6-20261017/`。最终批次 `s3-native-calibration-final/` 固定四份 Swift、协议/适配/归属/驱动源文件和两个二进制摘要，结束后逐一核对未改变。之前的缺文件 RED、16 项与 17 项递进批次均保留。

| 校准 | 结果 |
|---|---|
| 正常请求、期限、EOF、无效命令、超长输入、stdout 关闭 | 实际 STOP → 独立 ps 为 T → CONT → ps 为 S；只有主动请求是正常完成 |
| SIGTERM、SIGINT、SIGHUP | 守护者接收实际信号，恢复自有目标后落盘 |
| 活动、锁屏、桌面读取失败、墙钟倒退 | 确定性监测夹具触发同一原生恢复循环；不是实际锁屏实验 |
| 自有目标被 SIGKILL、被外部 SIGCONT | 没有多发 CONT，也不宣称自己恢复成功 |
| 初始已停 | 守护者 STOP/CONT 都为 0；目标仍为 T，最后由独立 owner cleanup 恢复并回收 |
| 正式入口收到校准目标 | `initial-refused`、STOP/CONT 都为 0；空进程仍运行 |
| 自有 Node 控制进程遭 SIGKILL | 脱离 Node 的守护者恢复，原件完整；owner cleanup 未补发 CONT |

共 18 项通过，另有正式入口未收到目标即 EOF 的零信号检查。每项均回收本次创建的空进程。最后一项中控制 PID 2696、守护 PID 2697、目标 PID 2698（出生身份见原件）；控制端死亡后 2 ms 发出 CONT，外部 ps 从 T 观察到 S，最终回收。该时延仅是本轮观察，不承诺固定恢复时延。
