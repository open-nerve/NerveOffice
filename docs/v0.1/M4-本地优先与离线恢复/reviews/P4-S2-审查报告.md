## 1. 范围与结论

提取 P3 的无界面恢复、副本、内容来源和 Worker 宿主；新增 IDB v2 会话状态、真实请求前票据、固定宿主许可和用户清理许可。旧写入不能穿越清理，新登录先发生时旧清理不能触碰新原件。没有新增服务端认证机制、依赖、退出确认界面或自动删除触发。

已修复自审发现的会话缓存对象复用问题；未发现阻断 S3 的剩余问题。本次是 Step 自审与累计验收，不代替 S6 的独立整分支审查、默认完整门禁、生产容器及同 SHA CI。

## 2. 已核对的边界

- 网络和来源摘要计算不持同源锁或 IDB 事务。五类会话入口先取得票据；只有模块加载失败才直接执行原请求，不能捕获网络失败后重发登录。来源只保存用途隔离的摘要，不落盘 Cookie、CSRF 原值、密钥或正文。
- 查询只观察代次，变更先退役旧许可；未决窗口到期或时钟回拨只取消资格。清理后的旧来源、旧 GET/登录回包与更早代次不能借当前资格激活。损坏或未知格式会话行报错保留，不当作空库重写。
- DraftStore 在异步前固定绑定副本，关闭再打开也不能换绑。16 个用户入口在各自事务内读取 sessions 并核对；原 writeEpoch、writerId、序号、完整原件和活宿主观察继续生效。
- Writer 的完整缓存、主库和镜像操作先持同源锁核对资格；缓存命中不绕过核对。预检返回后再次检查销毁状态；仅释放旧镜像句柄不要求活跃许可。Worker v2 严格解析许可且不可达页面、批量维护、React、Zod 或 SDK。
- 恢复读者创建时固定许可和文档键；编辑准备开始时捕获许可，临时读回沿用该次准备的许可。会话失效保留原件；压缩前已失效的捕获可从同一份内存内容进入既有上传流程。
- 用户清理整轮持同源锁；墓碑和主库删除又各在 strict 事务核对 clearing。镜像忙保留 pending，只有最终状态提交成功才 cleared；用户目录仍忙时 pending 数组可为空，完成与否只看 kind。保留期不回收会话代次。
- 真实交错覆盖新登录先到、清理先到、旧 pending 重试、迟到 force 登记、未登记的新文档及同用户新原件；其他用户原始字节不变。草稿页只能使用 RecoveryReader.remove 的完整观察，不能使用历史 seq-only abandon 入口。
- 平台通过动态导入加载共享恢复与会话实现；模块规则正反例及实际产物图继续限制 Worker 和首屏。原预算没有扩大。

## 3. 审查发现与修复

### 3.1 会话缓存丢失或借用许可

许可关联原 SessionResponse 对象。TanStack Query 的结构复用会生成另一对象，或者在字段相同时沿用旧对象：前者丢失新许可，后者可借用旧许可。新增真实 QueryClient 测试覆盖 set/fetch 两种路径，以及新 CSRF、相同字段的新代次、相同字段但无许可三种响应，六项先 RED。

会话查询选项和生产 QueryClient 对该查询键关闭结构复用，覆盖查询尚未挂载时登录/接受邀请直接写缓存的路径；其他查询仍复用。相关 29 文件/518 项通过，实际登录/改密与关闭本机保存的 Chromium/Chrome 各 26 项、WebKit 相应矩阵通过。

### 3.2 原有夹具与新异步边界

首轮全单元为 8,858 PASS/4 FAIL，并有 10 个环境销毁后的动态导入错误。旧测试在真实请求开始前更换 handler，或在动态导入完成前断言/恢复 mocks；改为等待对应请求及 vi.dynamicImportSettled，132 项定向和最终全单元通过。

浏览器旧断言更新为真实新边界：事务包含 sessions；失败可能早于登记发生在 bind-session；“已读到镜像后数据库失败”的注入放到 drafts 事务；删库后的恢复由新真实 HTTP 响应取得新许可；CDP 配额夹具仍先验证空库、再绑定。关闭新写后的两个绑定事件属于恢复检查，取钥次数、写入者/草稿缺失和云端内容断言均保留。没有删除失败案例、扩大超时或放松数据完整性断言。

### 3.3 清理守卫变异

限定移除 DraftMaintenanceStore 的事务内清理资格检查，旧清理对新会话记录执行墓碑/删除；虽然最终 finish 返回 invalidated，新草稿及写入者已经成为 null。测试按原始记录和镜像核对，确定捕获该失败。随后按原文件 SHA 恢复，10 项清理/镜像/跨宿主浏览器及 932 项受影响单元通过；变异 RED 与恢复 GREEN 原件分别保留。
