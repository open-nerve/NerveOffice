# P1 合并后 CI：探针校准的说明与结论一致

> 日期：2026-10-10｜基线：main `e8970e91`｜修复分支：`codex/m4-p1-ci-fix`。仅修正 CI 校准的结果投影，不修改生产代码或独立实测的门槛。

## 故障与既定规则

首次合并 `8db89a6e` 的 [CI 38021340220](https://github.com/open-nerve/NerveOffice/actions/runs/38021340220) 最终有三项失败：容器和 Chromium 的关页竞态见 [前一份修复](P1-CI-关页竞态修复.md)；Edge 的 `capture-1m` 首轮失败、重试通过。基础门禁、Chrome、WebKit 三项通过。

Edge 的一次校准采样得到异步段主线程最长阻塞 13.3 ms。真实实测函数 `probeVerdicts` 按 10 ms 门槛判为 `fail`，这一判定正确。CI 的投影函数把此类非语义项转成 `status: complete`，表示数据齐全，却仍保留原来 `fail` 的说明行；与预期的空说明比较时失败。

这与已经批准和落档的规则不符：P1 设计 §3.6、原 `selftest.spec.ts` 文件头和判定函数注释均明确，CI 的少次小样本只校准探针本身与数据完整性；时间门槛在真实 Safari 与本机持久上下文的独立实测中判定。《工程规范与完成定义》§8.1 同样要求性能测试单独运行，不进默认套件。

## 修复与边界

把原校准投影提到 `support/probe-calibration.ts`，以便直接覆盖原 bug。原有项目清单和语义项集合不变，结果的说明行改为依据投影后的状态决定：

- 数据齐全的计时、持久保存及配额项目，校准结论为 `complete`；原始计时和判定仍保留在报告中。
- 回滚、IndexedDB 基本行为、密钥交给 Worker、Web Locks 四类语义项失败时仍是 `fail`，保留原因。
- 数据缺失仍是 `missing`；没有对应判定也不能通过。

`probe-verdicts.ts`、10 ms / 100 ms 等实测门槛、样本次数、默认套件和 CI 的 flaky 判定均未修改。独立实测仍按原规则运行。
