## 任务 2：持久来源准备、密钥与写入资格

进入编辑按服务端批准、本机锁、来源 ready、编辑器创建的顺序执行。准备句柄同步可停写/销毁；打开自检失败、准备时退出或换人，不建立保存调度。EditorPage 使用 SessionResponse.features 的真实开关，阅读不取钥，关闭与能力缺失走内存。旧草稿、新版或损坏内容留在原处，不自动 adopt。

保存协调等待 onDraftResult 的异步核对。fenced 时仍可内存捕获，但上传等服务端裁决；未知结果保持暂停，后续有效心跳或重新确认会话可恢复。页面会话恢复不能绕过未完成核对。关闭本地草稿后可恢复云端上传，但不能再取钥、建宿主或持久写入。同一 editorSeq 因换钥/恢复产生更新引用时，autosave 跟上新引用，避免不断重试已被替代的引用。

## 任务 3：失效副本接收原内容来源

失效捕获只返回 DraftCaptureRef；副本接收同一个 WorkingDraft，在原 HTTP 和一次未知结果核对结束后，先停止原协调器、释放 pin，再接受唯一来源。原会话不再销毁转交的来源。只读重建的 JSON 仅在 helper 调用中存在；副本只持固定上传与请求元数据。unknown 原样重试，确定拒绝后才能换标识；副本成功不把新文档 revision 确认到原草稿。清理 start/page/session 剩余 compress/digest 注入，编解码统一归来源。

捕获失败保留原编辑器用于人工复制；重建失败仍可另存，副本成功后重载失败保留链接。重载成功、放弃后不可重建、读不到和卸载都释放副本来源。副本准备失败且来源仍保留失败快照时，显式重试从同一来源临时读回并重新捕获，不另留长期 JSON。
