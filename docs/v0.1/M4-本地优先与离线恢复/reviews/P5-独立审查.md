### I1 / Important / P2：恢复宏任务前未复核下一轮组字

位置为审查 HEAD 的 `apps/web/src/features/sheet-editor/formula-recovery.ts:136–139`、`:246–251`；冻结检查位于 `saving-editor.ts:115`，既有单轮组字测试位于 `formula-recovery.test.ts:74`。

Worker 在组字 A 期间失败，A 的结束事件取消组字订阅并排入恢复任务。若用户在任务开始前进入组字 B，`run()` 只复核恢复资格，直接挂上完整屏障，没有重新读取 `composing()`。窗口捕获屏障会阻断 B 的后续组合事件，包括不可取消的 `compositionend`；恢复还可能在组字中提交单元格，随后冻结被拒绝，形成自动恢复失败、组字状态残留。没有证明真实 SDK 下发生不可逆正文丢失，因此不列 Critical。

审查者用生产 `createFormulaRecovery`、`createSavingEditor`、`watchComposition`、`blockInteractions` 和 JSDOM 只读复现：

1. 单元格编辑中，派发 `compositionstart(A)`，触发 Worker 故障，进入 `waiting-input`。
2. 派发 `compositionend(A)`，暂不执行它排入的 0 ms 恢复任务；派发 `compositionstart(B)`。
3. 执行任务，保持 `settleInputPreparations()` 的 promise 待定；派发 `compositionend(B)`，再结束准备 promise。
4. 得到 `waiting-input/blocksInput=false/composing=true` → `preparing/blocksInput=true/composing=true`；B 结束事件未到达目标，提交发生时仍在组字，随后 `SavingEditorInputError`，最终 `failed/capture/composing=true`。

建议在实际恢复任务执行、挂屏障和提交输入前重新检查组字；若又开始组字，继续等待并恢复监听，每次排队后都复核。补控制器时序和实际 DOM 屏障回归，验证 B 的结束事件正常到达、最终内容进入快照，原保存资源身份不变。
