## 核对结果

- 保留旧 OpenCheckReport 的字段，新增独立 FormulaWorkerReport 和共同 union。七种 failure 有唯一事实来源；严格 schema 拒绝额外内容和未知枚举。页面构建器逐字段挑选，传入额外 message/snapshot/stack/URL 不会带到请求。编辑器分块不新增 Zod schema 求值。
- 服务端两种报告共用原端点、可读权限、后台请求属性、同一个去重/账户配额 gate。新的签名与旧资源签名隔离；先校验权限再计数。日志白名单、当前修订/档案补全、无数据库写入/审计、CSRF 和完整权限矩阵均由真实 API/数据库验证。
- 每个创建入口传入它实际使用的内容修订、access 与起因，避免刷新中旧 shown 的误报。运行期单独使用 formula-recovery；先锁定本页首报再发请求，网络失败不会重复上报或妨碍恢复。主线程重试也失败时仍能报告 Worker 首因；换人、卸载、隐藏后的迟到创建不报告。
- 运行期重建后的资源自检继续走原上报和接纳规则；它与 Worker 可恢复故障是两项独立事实，不给 Worker 错误伪造资源名，不接纳不完整模型。
- 页头映射全部恢复状态；主线程成功只说明大表可能卡顿，不承诺已保存/落盘。重试可离线执行；本人会话、确认状态、当前模式与保存终态决定资格。公式、云端、本机三条读屏事实互不遮蔽，例行保存不重复播旧提示。
- 保存/退出/进入/刷新/请求/交接和强制接管按钮与 S3 动作保护一致，取消请求仍可用。已打开的强制接管与放弃本机修改确认框会重新读当前恢复状态；本机恢复/丢弃入口在重建期间暂停。重试按钮消失后的焦点由既有救援机制处理，已有登录与失权出口保持可用。
