## 任务 3：宿主与写入资格准备

宿主独立于资格：初始 Worker 创建/握手失败才转进程内 P1 管道，保留默认恢复；两种放置的请求均有 15 秒等待上限。会话对象同步返回、ready 等初次准备，关闭能力/缺少 Web Locks 与加密能力时无取钥、persist、登记或存储副作用。首次符合资格申请一次 persist，不等用户决策才能编辑。

准备的六处等待都核对当前会话、准备代次与密钥身份；每次新登记用新 writerId，superseded 只在 confirm=current 后 force 一次。任何已有记录均保留，结果只带摘要、不缓存 gzip。暂停同步停止新持久写入、标记、确认、换钥；运行中栅栏拒绝也停下该代，旧拒绝不影响新宿主。暂停可只读，调用方在 resume 关闭旧宿主前读回需要的内容。

独立审查发现 1 Important：进程内 IDB 打开晚于超时/dispose，P1 writer 原有幂等 dispose 不会再次关闭晚到的连接。修复在实际管道操作的 finally 收尾，文档操作仍在原 P1 锁内，直接读提示的路径也覆盖；不改变 DraftStore.close 可重开契约。另在接缝审查中补齐运行中栅栏停写及 existing 正文只保留摘要的边界。

## 任务 4：唯一工作草稿来源

内存与持久实现共用内容所有权内核。capture 同步分配 draftSeq、编码一次并交回身份引用；普通队列只有执行中与最新待处理两项，另允许一份固定上传（含准备中）。ready 与订阅只带元数据；持久写成后按原 writer 与真实 contentSeq 读回，unchanged 不冒充分配的新序号。内存退路保留原捕获的内容，不能拿后来的编辑替换转移失败的旧请求。

暂停、换钥、重建先把当前内容留在同一个来源里，再关闭旧宿主。宿主失效时临时只读恢复不登记、不 force、不启用写入；仅原宿主暂缺密钥时使用 refreshKey，保留其重封缓存。返回的 WriterProblem 仅是元数据，不把失败结果中的 gzip 塞进页面状态。markInFlight/confirm 的结果供 S4 处理，view.local 表达最后内容写入事实。

独立审查闭合四处重要交错：

1. **写入中暂停**：已经开始的写入完成前不能宣布保留结束；保留意图必须接住写成后返回的 gzip，再允许关闭旧宿主。
2. **unchanged 时暂停**：P1 不返回 gzip，此时读库也可能已不可用。用该捕获仍拥有的临时文本建立内存内容，实际 contentSeq 仍是旧序号；正常捕获的一次编码不变。
3. **明确拒绝后释放**：有效 release 清当前请求，要求下一次真实写入清旧标记。以代次隔开较早写入的完成；清理写满不会错误恢复去重，旧上传或字段副本不能释放新上传。
4. **删除后丢确认回包**：已知云端成功时，当前 contentSeq 相同就接回固定 gzip，不依赖本机确认回包成功；failed/reject 如实交回，较新正文不被旧确认覆盖。

引用身份、排队修改、读取取消、订阅重入、销毁后晚到摘要等亦有确定交错测试。审查者使用真实 P1 writer 的隔离探针独立复验上述交错，最后确认无遗留问题；其执行证据不混算为主线程门禁数量。

## S4 接线约束

- capture 之后调度只保留引用与元数据，editorSeq 只负责页面修改确认，上传 localSeq 使用 PreparedDraft.contentSeq。
- 保存先 prepare、等 markInFlight 结束再发送；本机修改失败由返回值表达，不能用之前的 persisted 推断请求重放信息已落盘。
- 结果未知继续保留原 pin、请求标识、格式、基准、公式标记与 gzip；明确结束才 release。旧流程允许未知请求后继续发送不同内容，S4 必须在滚动计划中明确其与单 pin 上界的协调，保留 M3 的未知结果和终态核对业务断言。
- 云端确认与本机确认分开处理；旧确认不得清掉新内容，删除回包丢失仍有当前正文。释放后的旧标记清理可能延至下一次真实写入，不能宣称立即落盘。
- 暂停/换钥/恢复通过持久来源的生命周期接口；宿主只读恢复不代表重新取得编辑权。prepare 必须在新捕获覆盖目标前同步固定，副本流程接收同一个来源。
- 初次准备放在服务端与本机编辑权之后、创建可交互编辑器之前；初次 existing 不自动 adopt 或删除，恢复入口留 P3/P4。
