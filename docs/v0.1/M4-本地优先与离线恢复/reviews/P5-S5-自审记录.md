## 测量方法与前提

公式间隔测量在独立 measure 配置串行运行，不与门禁并行。每个候选记录构建来源及产物散列；只临时改 Worker 的配置，测后恢复。参数环境变量仅声明预期值，真实计算进度的相邻计数必须证明配置生效。

每轮为全量重算、收到第一条实际计算进度后发 stop、再强制重算，逐轮核对停止状态、被停轮无结果、最终公式与定义一致。stop 时长从页面发命令到实际结束通知，包含消息传递和 SDK 让出；不承诺单个长公式、依赖构建或任意时点的最大停止时长。

最初 811 公式样本在默认 500 间隔下不足以稳定容纳消息往返：发 stop 后实际返回 SUCCESS。三浏览器校准均拒收这些样本；改用现有自动保存停止回归的 `AUTOSAVE_STOP_SAMPLE`（1,020 个重型公式）后才开始正式对照。另以实际 500 的构建声明预期 20，校准准确失败，避免“标签变了、产物没变”的假测量。

四个候选、三个浏览器、每组 10 轮，共 120 轮通过；每轮均核对实际间隔、停止和重算正确性。下表单位为毫秒，三元组依次为 Chromium / Chrome / WebKit；最大值仅为这 10 轮观察值，不是任意公式的上界。

| Worker 间隔 | 全量计算中位数 | stop 中位数 | stop 最大值 |
|---|---|---|---|
| 500（原默认） | 3813.4 / 3778.8 / 1686.5 | 1814.9 / 1803.4 / 1.5 | 1823.0 / 1826.8 / 799.0 |
| 20 | 3979.8 / 3835.7 / 1700.0 | 0.3 / 0.4 / 6.5 | 13.3 / 14.6 / 12.0 |
| 50 | 3807.7 / 3823.4 / 1681.5 | 83.4 / 82.7 / 41.0 | 95.3 / 84.5 / 42.0 |
| 100 | 3794.7 / 3806.8 / 1696.5 | 360.7 / 361.9 / 159.0 | 369.0 / 379.7 / 163.0 |

采用决定：选择 20。相对原默认，整轮中位数增加约 0.8%–4.4%，本样本停止响应显著改善；50/100 的耗时接近原默认，但停止响应较慢。主线程原有 20 保持。原始配置已由测量脚本还原、散列及还原构建均通过；配置回归先在原代码失败（只差 `intervalCount: 20`），采用后 25 项通过；测量入口的默认预期同步改为 20。

DEF-072 对照固定原间隔 500，只改变 100 ms 空计时器，避免同时改变两个变量。WebKit 原配置 12 次打开中 10 次首次增量比随后中位数多出原有 500 ms 停顿阈值 以上（中位差 996 ms），开启空计时器后为 0/12（中位差 -10 ms，沿用最近秩统计）；全部 cold/warm 缓存前提通过。候选已还原。真实 Safari 因本机屏幕锁定暂未运行，尚未采用空计时器，也不关闭 DEF-072。
