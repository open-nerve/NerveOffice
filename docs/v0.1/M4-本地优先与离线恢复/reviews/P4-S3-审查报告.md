# P4-S3 本机草稿页审查报告

> 日期：2026-10-14｜审查：实现者按规格和计划逐项自审｜基线：4ea34f0c｜状态：Step 验收通过

## 1. 范围与结论边界

S3 提供本机草稿页、逐条明确恢复/副本/放弃、存储状态，以及空间、与我共享、搜索三处标记。目录复用 S2 的固定会话许可、共享 DocumentRecovery、完整原件条件清理与同请求副本协调。只保留当前一份操作的正文，不把目录中的正文放进 React 或查询缓存。

本报告是 Step 自审。退出/停用自动清理与启动维护属于 S4，SDK 和旧记号属于 S5；整 Phase 独立审查、默认完整门禁、生产容器及同 SHA CI 属于 S6。本 Step 的无头 WebKit 不代表真实 Safari 验收。

## 2. 逐项核对

- 批量事实按最多 100 个唯一 ID 串行读取；空列表不请求，合法但少/多 ID 的响应拒绝。不可读项在发现前再核对，网络未知不变成撤权。
- 目录先比对镜像再列本人主库，保留镜像独有、读取失败与提示记录。元数据 HTTP 前后核对固定许可；换人或失效后销毁目录，清空旧标题、副本入口和恢复资源。
- 放弃确认固定完整密文及写入者的观察，不重新读取新原件套用旧确认；同序号不同正文保留。未知副本重试沿用同 requestId 和 gzip，其他行不能抢占正文；成功旧按钮不能再复制新记录。
- 条件清理分别表达 changed、主库完成但镜像未完成、未知与完全完成；不以旧 seq-only abandon 作为新页面入口。较新格式保留，无法取钥不冒充损坏。
- 普通文档链接不授予恢复或租约。浏览器证实列表与目录未申请编辑；到编辑器明确点击之后才保存，内容和唯一修订符合预期。
- 平台按需页面和轻量索引不引入 SDK。编辑器实际没有 UserMenu，使用独立页头的新标签页入口保留编辑现场；部署关闭不隐藏既有草稿。
- 存储的持久授权、使用量与配额如实显示，未知不补 0；两项查询独立完成。320px、长列表、键盘取消/确认、行移除后的可见焦点和未知副本离开提示均覆盖。

## 3. 发现、修复及原失败

1. 固定许可初次绑定若暂时 blocked，缓存失败 Promise 会让同页永远不能重试。两条反例先失败；每次重查同一固定许可后通过，不允许改绑后来会话。
2. 副本成功后的旧按钮原可复制后来记录；未知副本后确定不可读也不应继续保留旧正文。补充反例并修复为先重新检查，以及释放旧内容、保留旧副本结果未知的元数据说明。
3. 会话失效原未清空已完成副本的标题/链接，初始失效还会一直显示检查中。两条单元先失败，修复后相关 15 文件/280 项通过，三浏览器补充另一页换人的真实反例。
4. 存储界面用 Promise.allSettled 等待两项查询，任一未返回会扣住另一项已知事实。两条反例先失败，改为各自更新后 6 项存储 UI 测试通过，迟到的初始状态仍不能覆盖随后申请成功的事实。
5. 初轮镜像用例在建立放弃观察前持有另一 Worker 的同步句柄，导致读镜像阶段即无法完成，未到要验证的清理失败。改在清理阶段注入 removeEntry 失败，保留真实镜像、主库与恢复流程；原报告保留。
6. WebKit 鼠标点击没有使放弃按钮获得焦点，关闭确认后实际聚焦本行标题。诊断记录证实回退正确；鼠标断言核对本行可见稳定元素，键盘断言仍严格核对原按钮，未修改产品焦点实现。
7. 新入口令旧编辑器测试的“唯一链接”定位和旧预算夹具失效。分别定位明确返回链接、补上平台按需 Worker 图及缺失检查，原焦点/字节/预算断言保持。新增平台 Worker 登记沿用同一 15 KiB 产物上限；编辑器 8 文件只是基线观测，原门禁仅限制其字节数，平台 2 文件上限不变。
8. 首轮完整 lint 扫入了 SDD 内保存的生产清单 JSON。原件按 SHA-256 验证后移至外部 handoff，保留原失败；没有修改 lint 排除规则或格式化原始证据。
