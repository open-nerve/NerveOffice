## 核对结果

- `formula-fallback` 只接受结构化 Worker 错误，以同一快照、权限和视图最多重试一次主线程，后续替换沿用本页偏好。普通渲染错误与主线程失败没有重试；首次故障锁存，不修改 SDK 版本或 URL 行为。
- `formula-recovery` 先订阅再读首错，宏任务内才开始捕获和替换。等待组字期间不拦 compositionend；准备开始后才挂完整屏障。旧保存已发起的输入准备先结束，再提交当前输入；不等待 HTTP。
- 单元格提交与面板准备各自 await 后都复核资格。捕获失败保留旧实例并允许完成输入后明确重试；冻结之后的失败和重试只读稳定正文，旧模型被销毁后不会再捕获它。
- 页面代次、本人会话、恢复资格，以及编辑时的原协调器、调度、租约和本机锁一起决定接纳。会话离开又回来也不能复用旧续行；旧创建先经槽位准确丢弃，之后才重新尝试。打开自检失败的实例没有绑定、捕获或上传。
- 阅读恢复不申请编辑权、不上传；可编辑权限后来撤销不会被恢复改回。编辑恢复保持同一保存资源，逻辑序号连续，旧 ACK 不清掉新恢复的待更新标记，原请求正文逐字节不变。
- 零修改序号也会补存。沿原调度规则，没有输入静默期时可以先上传带待更新标记的冻结稿，公式收齐后再上传无标记版本；不能为了少一次请求改变原保存策略。
- 保存按钮、快捷键、退出、交出、接管、刷新与异步确认后的续行受同一恢复状态控制。实际标签页交接在恢复期间回既有 busy 消息；已在途的退出/刷新继续唯一地负责替换。失权从稳定捕获入口保留正文，并沿原副本流程收尾；pagehide、换人和销毁使迟到结果作废。
