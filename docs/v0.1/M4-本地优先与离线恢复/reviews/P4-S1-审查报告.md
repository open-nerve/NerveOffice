## 2. 已核对的边界

- 输入先限制原始项数再规范化、去重；101 个相同 UUID 也拒绝。静态路由先于 `:id`，响应顺序固定。
- 文档和调用者授权一起读取；缺失项仍走批量权限查询。全部无权、缺失、回收站及混排的真实 SQL 序列与业务结构一致。不可读项没有标题、修订或占用信息。
- 只读快照开场仍复核登录；文档、权限、修订及持有者/预留人的补充事实均在同一连接串行读取。撤权后改名及保存的确定性交错未带出新标题或修订。
- 当前修订来源只给实际保存者本人。占用复用原租约七条有效条件、R2 旧代次续上规则及交出预留；没有复制另一套授权逻辑。100 份文档的修订、租约各一次批量读取，不读正文。
- 会话原因取实际行，数据库失败原样传播；未知令牌不猜用户，账户缺失不猜停用。退出与改密竞争的详情在原事务取得；replaced 不清新 Cookie，原有审计、回滚和最终状态断言保留。
- 所有仓储跨模块调用仍经公开入口；新读服务在 documents 模块内注册，MISSING_DOCUMENT 只在模块内部共享。
