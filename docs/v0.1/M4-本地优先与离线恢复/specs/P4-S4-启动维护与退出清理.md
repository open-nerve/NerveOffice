# P4-S4 启动维护与退出清理规格

> 日期：2026-10-14｜基线：1fb1effc｜状态：Step 自审与验收通过｜唯一工作区：codex/m4-p4-drafts-cleanup

## 1. 意图和范围

兑现 Phase §3.3、3.5：本人明确退出、已确认账户停用、文档不可读和超过保留期时清理本机草稿，同时防止旧请求、冻结页面和旧清理误伤新登录的数据。平台和编辑器均接入。密码重置、改密、登录替换、普通过期、网络未知不当作账户停用，草稿保留。

沿用用户“按照既定规划一步步自主推进”的授权与每 Phase 一个分支、每 Step 一次提交。S2 已实现低层资格/条件清理，S3 已提供逐份恢复与目录；本 Step 接入触发、生命周期和真实用户流程。S5 再处理 SDK 及旧记号，本 Step 的成功文字只称“本机草稿”，不提前称全部本机存储已清空。

## 2. 代码事实和方案

现有 LocalCleanup 有 beginUser/removeUser/purgeExpired，用户清理全程核对持久 clearing；但尚无启动触发、退出预览或账户失效副作用。session-activation 已在真实会话请求前记录 ticket，成功后关联原响应；普通 API 错误尚未绑定发出时的本机许可。旧 logout 会在同一人换登录后自动重发退出，这不符合新清理流程的确认边界。旧保留期按读得出的更新时间删除任何格式，镜像只看文件时间，与 Phase 对较新格式的保守规则需要统一。

选择共享生命周期协调、固定操作来源和按需 UI。API 层只记录/传递请求开始时的来源，实际存储动作留在 shared/local-drafts；页面显示事实，不自己判定删除。各按钮各自清理会重复失败分类与竞态处理；只依靠广播无法阻止冻结后的旧写入，因此仍以 S2 的事务栅栏为准。

## 3. 保留期与到期提示

仍以严格超过 14 天为到期（等于边界保留），不论账户归属；未来时间、无效时钟、无法判定更新时间与较新格式保留。当前格式中形状损坏但可判定的旧时间沿既有规则到期清理。主库清理返回已清记录和保留键，保留记录的镜像不得由另一条时间判断独自删除。

OPFS 非空目录清理前读取并解析真实槽位，较新格式、读取失败、无法判断到期的非空内容保留。可识别的两槽记录都到期且目录不再被主库保留时才删；旧空目录仍按原文件时间回收。整个判断、删除和主库提示在同源锁内串行，不能留下“主库新格式保留、备份却删掉”的分叉。只读元数据和密文结构，不取他人的密钥或解密正文。

主库删除与 expired 提示在同一 strict 事务，镜像独有的到期清理也留下 expired 提示；只有完成删除才说已清理。提示不含标题/正文/密钥，仍按 userId/documentId 隔离。当前账户可从共享恢复视图读到提示；后台替别的账户清理后，后者下次登录也能得知。权限重新确认后才显示标题，无权/未知只显示通用说明。提示的确认继续使用原 at 条件，不能删掉更新提示。

## 4. 认证失败必须绑定请求来源

页面采纳真实 SessionResponse 时，把它关联的本机许可与 CSRF 一起作为本页请求上下文。普通 API 在实际发出前固定这个许可；后来的重新登录或换人不改变旧请求的来源。原 API 错误及完整请求时限保持，本机步骤失败不重发网络请求、不吞掉原错误。

已通过契约校验的 SESSION_EXPIRED/account_disabled，只有 details.userId 匹配该请求的固定许可才能 beginUser；随后存储还须核对原代次。其他认证/CSRF 失败只暂停对应原许可。网络/5xx/超时不启动删除。

初次查询可能尚无本页许可，使用 session-activation 已在网络前取得的 ticket：失败转移必须比较原 ticket.generation 与持久行，并核对服务端 userId 与原 source.userId。不能在错误返回后读取最新代次替旧请求补资格。会话变更未决、未知持久格式或代次不符均拒绝；停用可从仍属于这张票据的已知来源进入 clearing，其他失败保留。更早的失败不清理、不暂停新激活代次。

先持久化停写/清理资格，再广播“会话变了”并使本页宿主停止本机写入、释放恢复读者和密钥。广播只促使其他页核对；清理、晚到写入与新登录的最终顺序仍由 S2 控制。失效后的原页内存编辑内容仍按既有页面说明处理，不赋予重新写本机的许可。

确证停用的登录入口和留在编辑器内的失效提示必须说明账户已停用；编辑器另说明修改仍在内存、关闭会丢失及重新启用后才能继续保存，不把停用事实表述为已清理成功。普通请求仍先确认当前会话，新登录存在时不能沿用旧响应的停用说明。后台目录和取钥同样可能首先收到停用：平台通过既有按需维护入口订阅本页持久协调的停用事件，只在当前真实API响应仍关联原userId/generation时保留原因再复核。普通停止、旧代次和换人不推断停用；该界面通知不授予清理或写入许可。重置、改密、过期保持既有失效说明；结果未知的自行停用与已经确证的停用分别表达。

## 5. 明确退出及独立结果

采用按需公开 `/logout` 页面承载预览和未完成结果。入口仍叫“退出”；页面先实际确认当前账户，再固定原 SessionResponse/许可。列出本人的待处理草稿、标题可确认性和本机时间，提供草稿页及取消入口。读取不完整要明确说可能还有未列出的草稿；确认文案说明本会话其它页在确认前写下的草稿也会被清理。

“清理本机草稿并退出”才开始：核对固定许可→beginUser→本页停写/释放资源→按同一清理许可 removeUser→服务端退出。清理 pending/失败也尝试结束服务端会话，结果分别保存。网络不持同源锁或 IDB 事务；退出请求使用确认时的 CSRF，不隐式换用新登录重发。

服务端成功或确认原会话已结束后清除平台旧查询缓存；本机同时完成则整页到登录页。还有清理未完成时留在只显示结果的退出页，提供原资格重试和登录入口，不把旧工作区数据继续展示。服务端结果未知时如实说尚未确认退出，保留原操作；重试沿原来源核对，不显示已经退出。

同用户重新登录、换人或新激活代次出现后，旧退出/重试结束；不得从新会话借资格继续删除或自动重发退出。再次退出必须重新预览、确认。本机存储连 beginUser 都未能完成时说明资格尚未建立，仍可结束服务端会话；仅在原来源仍有资格时重试，不能把未建立资格的失败包装为成功。持久 clearing 支持后续页面安全补清；来源失效则停止。

## 6. 启动维护与界面

平台入口和编辑器入口按需建立同一共享维护运行时；启动、重新联网、可见性恢复与聚焦合并为串行任务。公开一次性链接页不额外请求会话，不影响其内存令牌。维护不阻塞普通阅读。

先补未完成 clearing，再执行全站保留期；只有真实采纳的当前用户许可可检查其文档权限/吊销/损坏/确认状态，复用 S3 catalog/DocumentRecovery 逐份处理和释放正文。未知副本仍由原页面拥有，不由维护发起副本或恢复；维护不会申请编辑权。

同一页面只保留一个恢复操作所有者：编辑器当前文档交给前台 DocumentRecovery，本机草稿页交给前台目录；后台只检查其余文档，避免重复取钥、重放和清理打断前台。过滤发生在目录发起文档事实/恢复操作之前；扫描绑定启动时路径，导航后迟到结果失效。全局保留期和持久 clearing 不因前台所有权跳过，到期删除仍由持久提示告知前台。后台实际完成不可读、吊销或损坏清理时显示对应原因。完成原因独立于最新扫描的目录，以当前原许可下的有限枚举集合保存在本页共享运行时；后续空扫描不抹掉原因，不保留旧文档身份或正文。同人新代次、换人、资格失效或未知均清空，运行时释放后不跨页持久化。列表观察维护结束后重读本人轻量索引，使已清理原件的旧标记消失；读索引不取钥、不查询文档事实。

按需状态组件在平台与编辑器显示本人到期/不可读等清理结果、未完成原因和重试。登录前仅能显示不含账户/文档身份的清理提示。换人或原许可失效即清空旧标题与通知，不接纳迟到扫描结果。普通阅读可继续使用，进行中按钮保留且防重入，320px 与键盘焦点沿现有组件约定。

## 7. 验收

1. 保留期：真实主库/镜像，14 天严格边界、未来/未知时间、较新格式、其他用户、镜像独有及读取失败；到期提示持久且只属于本人，原件比对与墓碑规则不退化。
2. 认证来源：普通请求与初次会话 ticket，两类旧回包遇新登录都被拒绝；停用才删，重置/改密/过期/替换/网络均保留；DB blocked、错误结构和不匹配 userId 保守处理。
3. 退出：预览/取消、明确确认、主库与 OPFS 清理、多标签页晚到捕获、镜像占用、退出响应丢失、同用户新登录和换人使旧操作失效；服务器结束与本机结果各自诚实。
4. 平台/编辑器启动、部署关闭仍维护、公开一次性链接无额外认证、登录前通用提示、当前用户标题隔离、320px 与焦点。
5. 三浏览器串行核心及反例，生产自动保存节奏；相关旧账户/恢复回归、全项目单元/类型/lint、生产构建及原预算。整 Phase 全量 verify/容器/独立审查/CI 仍归 S6。

自审：既定 Phase 的清理触发与界面，没有新增权限或恢复身份；退出不会误借新登录，未知不删除；跨入口能力共享，首屏与 Worker 原预算不提高。S5 清理层接入边界保留，未提前宣称其工作已完成。
