# P6-S3 真实 Safari 暂停与请求恢复

> 状态：S3 实机验收及 Step 最终回归通过；Phase 审查与完整门禁在 S6｜日期：2026-10-17｜依据：M4 总设计 §2.1 第 6 条、P6 §3.3、DEF-069

## 1. 目标

证明专用 Safari 编辑页的实际执行停止、服务端真实租约到期和恢复后的旧写入隔离，并补齐请求方的保留期与后台取消场景。沿用已批准的进程暂停实验、r23 明确恢复和现有代次/服务端裁决，不新增产品身份继承或自动挂起识别机制。

页面暂停、隐藏、崩溃是不同的条件。人工 SIGSTOP 只证明该 WebContent 停止执行；它不执行 WebKit 自身的暂停通知协议，不能声称完全模拟 Safari 自主挂起。自然隐藏观察和受控暂停分别记结果。

## 2. 进程归属与恢复保障

复用 P3 的专用场景、页面 URL、单窗口单标签、创建前 PID 基线、UID、微秒级出生身份、Apple 动态签名及 LaunchServices 身份。新窗口必须有本次实际证明，旧窗口/旧 PID 的历史报告不充当当前归属。主 Safari 进程、其他窗口或无法唯一认定的目标一律拒绝。

SIGSTOP 前须满足宿主解锁、连续空闲至少 120 秒、完整映射不超过 2 秒、运行尚未超时。目标本来已停止也要拒绝，避免把他方暂停认作本次操作。暂停过程只允许一个已验证 PID，不按名称或进程组发信号。

独立的原生恢复守护者必须先就绪，再允许本次停止。它不依赖 Node 驱动、Apple Events 或页面 JavaScript 在停止后继续响应。成功发送 SIGSTOP 后须从内核确认停止状态；仅本次成功暂停且出生身份仍相同的进程可以收到 SIGCONT。正常请求恢复、主驱动 EOF/退出、用户活动、锁屏、超时、监测不可用和时钟异常都必须走恢复与收尾。期限按单调时间执行，墙上时间只用于跨组件证据；守护者自身被不可恢复地终止或宿主断电的限制如实记录。

回执包含守护者/目标身份、授权与实际信号时刻、停止状态、恢复原因、恢复信号及最终状态。未经 SIGSTOP 的目标不发送 SIGCONT；退出或 PID 重用时记录拒绝，不能向替代进程补发。Node 失败后独立恢复须用专用自有子进程做真实内核校准，不能只靠 mock 宣称成立。校准不能接受任意外部 PID。

## 3. 持有者的真实暂停

复用现有 `paused-holder` 的三格、接口协作者、数据库时间线与后端请求证据。前两格依原流程上传；第三格必须经真实本机保存完成并独立核对后才暂停。现有共享前奏把捕获期限调为一小时，因此不能只看到“第三格已写入内存”就停止；该变体应恢复本机捕获的正常节奏，保持初始定时云端上传暂停，其他场景原样保留。

宿主取得本机完成事实后暂停唯一目标。对照最后一次持有者续租、暂停区间、另一账户请求/续期及实际申请时刻，证明：

- 内核确认目标停止，暂停区间页面计时与持有者 HTTP 心跳没有继续；
- 服务端依真实时间经过原有 90 秒租约，没有缩短 TTL、修改系统时钟或种造租约；
- 协作者正常取得下一代并保持心跳，然后恢复旧页；
- 旧页走 `lost-after-pause`，给出失去编辑权说明，旧写入被原服务端规则拒绝，不能覆盖协作者持有的原文档；
- 原文档仍是已确认的两格与正确修订，另存副本包含第三格；本机原件及成功副本后的清理符合现有写入者栅栏。

旧盖屏测试的 `handed-over` 仍是有效的自然观察结果，但不能算作本项受控暂停通过。页面的长计时器间隔只能佐证执行停顿，不能单独替代内核状态和服务端事实。

## 4. 请求方与自然隐藏观察

三个请求方场景分开计时、分别保留服务器与页面证据：

1. 现有路 1 回归：后台得知保留给自己，保持零申请，前台才以普通方式进入。
2. 保留期过期：后台实际跨过服务端给出的两分钟保留期限；回到前台时无其他持有者，仍经普通申请进入。确认后台没有提前申请、没有继续延长已获准的请求，成功编辑与正文修订正确。
3. 后台取消：协作者持续持有，请求方在后台等待真实十分钟；核对取消/到期的实际 HTTP 与服务端请求状态、页面说明及零编辑申请。此变体使用独立明示的长预算，不能把旧场景时限一概放宽，不能用缩短常量或虚拟时钟充当实机结果。

分别观察最小化、隐藏应用和切换桌面的编辑器页，记录实际可见性、页面计时、心跳、后台保存和观察时长。仅操作本次测试窗口；外部操作或锁屏令本轮作废并保留原件。没观察到自行暂停就记未复现，不推断暂停一定不会发生，也不为了强行复现而移除产品需要的 Worker/Web Lock。

解释 Safari 行为时区分实际构建、上游源码线索与已经证实的因果。上游主干的后台 activity、标题变更等线索尚未证明本机编辑器的具体调度原因；不能把相关性写成根因。详见本机 `s3-webkit-source/source.json` 的固定源码版本与 `s3-exploration-notes.md`。

## 5. 校准、验收与停止边界

- 纯状态/协议负例先验证：未就绪、旧身份、目标本来停止、过期映射、重复控制、主驱动退出、用户活动、锁屏、期限、未知回执与恢复失败。
- 原生自有子进程校准：实际停止状态、实际恢复、主驱动异常后的独立恢复、正常期限与失败清理；所有过程记录身份和退出，不用名字批量清进程。
- 三浏览器校准新增页面/编排，保留现有两条请求路径与崩溃套件；模拟心跳拦截和受控时钟只算校准。
- 真正 Safari 的暂停链、三条请求路径和三个自然隐藏条件分别有原件。保留无效和失败轮次；缺证据不关闭 DEF-069。
- Step 全部相关回归、lint/typecheck/unit/stories 通过后提交；Phase 的独立审查与完整门禁仍在 S6。

当前没有新增产品协议、数据库迁移或保存机制。实施方案自审后按既有自主推进授权执行；若真实结果暴露架构回归、跨模块调整或意外高风险，先提交证据和当前工作，再按 CLAUDE.md 请求决策。
