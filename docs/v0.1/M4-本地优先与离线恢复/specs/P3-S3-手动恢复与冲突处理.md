# P3-S3 手动恢复与冲突处理

基线：`4aa77f92`。按 M4 总设计与 P3 Phase 设计自主实施；本 Step 不实现 S4 的自动重载身份证明，也不关闭 DEF-064。

## 1. 用户意图与验收

用户联网重开文档后能看到本机未同步修改，明确选择恢复、另存为副本或放弃。恢复不会重复提交已经保存过的请求，不用旧内容覆盖新修订，不绕过当前权限、租约、本机锁、打开自检及公式计算。部署关闭新本机保存时，仍能处理已有记录，后续编辑如实显示只在内存。

无新依赖、服务端业务端点或数据库迁移。沿用原平台与 Worker 预算。全部工作在唯一 P3 worktree 内；当前用户独占开发，主目录 main 不切换。

## 2. 代码事实与接入位置

- S1 的 `decideDraftRecovery` 是唯一内容判定表；`replayContent` 明确不带租约令牌。旧在途正文与请求描述必须一同固定到核对结束。
- S2 的观察凭证属于创建它的宿主，登记会改变写入者，不能拿登记之前的凭证清理登记之后的记录。编辑会话内必须重新 observeRecovery。
- `startEditing` 已按租约→本机锁→内容→prepareDraft→新实例→打开自检→保存→解除屏障排列。恢复插在这个边界；SDK 仍由 EditMode 操作，存储适配层只接收回调和捕获结果。
- `EditingDraft` 目前在 existing-draft 时转内存并关闭宿主。只有显式恢复回调才保留 S2 恢复资格，原普通调用的保护不变。
- `SaveCoordinator.savedSeq` 和 Autosave 初始计时都以 0 为已保存基线。恢复初值的 editorSeq=0 必须显式标记为未同步并启动调度，不伪造 SDK 修改事件。
- 阅读的 editStatus 没有修订来源；申请编辑权的响应已有 source。阅读时缺少来源不能直接判成冲突或自动写入，手动进入时以新租约响应重新核对严格“自己追自己”。
- 已核实的 source（含明确 null）仅按同一用户/文档的同一修订保留元数据，后续阅读检查只补 undefined；新明确来源优先。修订变化、身份暂停/销毁使该记忆失效，权限与占用每次仍实时读取。

## 3. 边界与所有权

`recovery/recovery-reader.ts` 负责独立只读发现宿主与密钥：observe、刷新密钥、条件清理、P1 提示读取/条件清除和销毁。它不 register/adopt，不因部署关闭而禁用。没有既有记录时不请求本机密钥；有记录且需要解密才取钥。缺钥、宿主超时和未知镜像保留原件。密钥换版最多主动刷新一次，持续不一致给出重试。

`recovery/document-recovery.ts` 负责一次文档恢复的事实、动作和状态；依赖 Reader、S1 判定、旧请求 API、WorkingDraft/副本端口。视图只含元数据、决定、动作状态与成功事实，不含 gzip/正文/密钥。所有异步结果受用户、文档和本轮代次约束；暂停/换人立即作废观察与宿主资格并清掉内存钥匙。

Reader 没有候选或待重试清理时，在本次动作读完通知后释放；提示仅保留元数据，明确确认时以原 at 重建 Reader 条件清除。空阅读不长期持有恢复 Worker。持久编辑来源因失锁等原因暂停时，同步停写，先由唯一 WorkingDraft 接住最后正文，再关闭暂停开始时绑定的旧宿主，让新页能够核对镜像。普通暂停保留失败留下读回退路；不得照搬清钥的无条件关机规则，迟到收尾也不得关闭新代宿主。

原 gzip 在重放核对期间由一次发现持有。确认结束后，正文只交给一个 WorkingDraft 来源；副本使用 `createLostCopyFlow` 的固定请求/上传引用，结果未知时沿用原请求，不新建第二份副本请求。用于 SDK 创建的字符串仅短期借用，不放入长期配置、视图或缓存的 ready 结果。

编辑恢复使用 `EditingDraftRecovery` 回调。适配层准备 OutboxSession 后把本次恢复端口交给 EditMode；回调可以观察、判定、构建尚未接上的编辑器和进行打开自检/公式收齐，然后返回初值。适配层只在此后创建 WorkingDraft 并采用初值，不自行操作 SDK。后续保存、副本和离开沿用同一个来源。

## 4. 发现与旧请求核对

已确认本页用户后，异步发现当前文档记录，不阻塞通常的云端阅读。状态必须区分尚未检查、正在检查、没有记录、保留/重试、可恢复、占用、冲突、正在操作、操作成功及清理待完成。

逐项采用 S1 判定顺序：身份未知、离线、存储/钥匙失败不清理；读不到原文档、过期、已吊销、同版本认证失败或形状损坏按原观察条件清理；旧钥先刷新；较新格式保留并要求更新页面。认证后的 gzip 解压或 UTF-8 失败按损坏处理，不能交给 SDK 或副本；SDK 打开自检失败保留可解码原件，不声称存储损坏。

旧请求仅在 S1 返回 replay 时发出，使用原 requestId、clientInstanceId、localSeq、baseRevision、writeEpoch、格式、pending 标记及原 gzip；没有当前租约令牌。网络失败/超时/非确定拒绝保留未知结果；只有明确租约未接受才按 unconfirmed 重判。已确认则条件清理原观察，并重新 fetchContent 当前修订；回执对应的旧快照不安装。

发现后到动作开始期间可能已有新保存/新写入者。每个手动动作重新核对事实，不能把第一次提示当永久授权。changed/fenced 返回“本机修改已变化，正在重新检查”，保留新记录；不得改成无条件清理。

## 5. 手动恢复与交互/上传屏障

1. 点击恢复经 EditorPage 的会话确认，进入原申请编辑权流程；取得本机锁后按本次租约响应的 revision/source 重新判定。
2. 部署启用且存在记录：OutboxSession 显式恢复，重新观察后核对原请求。部署关闭或合法内存退路：用独立 Reader 观察，不 register/adopt。
3. 决定为 restore 后解码，使用恢复快照构建未接上的可编辑实例，执行原打开自检。失败则释放编辑权，回到阅读并保留原记录与重试说明。
4. formulasPending 为真时强制全量重算，并在解除屏障前等待收齐。等待最多 10 秒；未收齐不上传、不采用，回到阅读保留原记录并允许重试。成功后从该实例捕获完整快照（含重算结果），创建恢复初值。
5. 恢复序号高于本次观察的高水位；首份采用后无旧 inFlight。采用 changed/fenced 时取消本轮安装；quota/缺钥/宿主失败保留内存初值，不偷偷 force 或重新登记。正文可用不等于原凭证仍有效：只有同一有效宿主/代次的暂时失败保留清理回调；Worker 超时终止、钥匙或代次作废后不再有原条件清理资格。

existing 准备因冲突或打开/公式失败退出时，先通过初始化端口 retire 关闭原 OutboxSession 并释放镜像句柄，再以独立 Reader 重新核对，给阅读操作建立新候选。原来源整体由 blocked 收尾正常销毁。只有新判定仍可恢复且正文相同才保留该次 SDK/公式失败说明；新内容或新判定按 changed 处理。确认框仍绑定打开时的原观察，不在确认动作中换成新观察删除。
6. 来源就绪后建立保存与调度，显式 initialUnsaved，接上编辑器，解除屏障。没有额外输入也会上传恢复初值；上传前公式已收齐，后续普通编辑沿现有策略。

普通“编辑”、请求获准、本人接管最终都经过同一个准备入口，不允许发现既有记录却绕过判定直接以云端内容覆盖它。S4 再给该入口增加自动进入的身份证明。

保留 M4 总设计 §6.1 与 US-M4-11 的存储退路：只有 Reader 明确返回浏览器禁止或缺少能力（unavailable 的 denied/unsupported）、本轮编辑权事实有效且从未发现未处理原件时，普通入口可固定使用内存编辑云端内容。此结果不等于恢复成功，不调用旧正文安装、不标记恢复初值、不携带条件清理资格；之后捕获、暂停/继续及钥匙恢复均不自动重新登记持久来源。镜像忙、一般失败、配额失败、blocked/newer-version 不授予此许可。既有端口和非 absent 的有效观察均记住“原件存在”，不随 Reader 关闭或读取失败消失；仅明确 absent/empty，或当前候选同一观察代次的 removed/absent 清除。新原件已读出但核对尚未结束时，旧删除回包也不得清掉这一事实。未知副本请求仍先于该退路阻止新编辑。

观察尚未完成也不能遗忘中途已见的记录：无钥读取后的取钥/再次读取失败，以及非空镜像与主库核对失败，均由失败结果携带 `recordKnown: true` 贯穿 Worker 协议、Reader 和协调器。它只表示存在事实，不携带旧 observation、正文或删除资格；迟到删除也不能覆盖更新的存在事实。完整新观察明确 absent 后才按不存在处理。

同一事实也经过登记准备链路：主库为空而镜像为新版时，登记结果中的 `recordKnown` 独立于镜像写入能力（主线程退路为 off），显式恢复仍归入 existing 端口，不能把 ready 当成空记录。登记中途失败已见的记录同样传入内存恢复上下文。Worker 与主线程读完非空第一槽后，第二槽读取失败都保留这项事实；尚未读到原件的纯未知错误不虚构存在事实。

有效准备轮次累计每次登记返回的存在事实，包括 superseded 裁决：核对租约后重登失败、回包时已经换钥，均不能抹去此前已见原件。内存退路只携带这项事实，不复活旧宿主或旧钥；第二次登记没有 existing 也须经恢复观察确认不存在。暂停、销毁、身份或租约代次作废时，仍优先交回原取消结果，不让迟到回包影响新一轮。

只有主库存着原件时也遵守同一规则。Store 的 read/observe/register 在收到非 undefined 的原始记录回调时即记住事实，早于后续分类或其他请求取值；事务中止、配额失败、连接重开失败、观察关闭和分类异常均保留。该布尔事实跨同一操作的连接重试，失败不返回未提交的观察凭证；纯写入者记录或从未读到原件的失败不虚构存在事实。

已采用的持久来源沿原确认规则清理。采用失败/部署关闭的内存来源在原文档的真实云端确认之后，且原清理资格仍有效时才条件清理原观察；确认较旧捕获不得把仍未同步的新输入标为已保存。清理暂时失败保留可重试凭证；宿主已死亡等凭证失效时保留记录并提示需重新检查，不能新建宿主/观察后套用旧回执自动删除。已删除而镜像失败分别呈现实际事实，镜像残留由后续具备完整事实的清理流程处理。源被销毁/用户变化后迟到确认不发起清理。

## 6. 冲突、副本与放弃

只能阅读、真冲突或被别人占用时，原件留在本机；当前仍可读且格式可理解才给另存为副本。副本沿现有标题、请求标识、确定拒绝和未知结果重试规则。成功创建副本后仅条件删除原观察；绝不把副本 revision 传给原文档来源 confirm。清理失败仍展示副本成功链接，不重复创建。

放弃复用现有 ConfirmDialog，说明会移除这份文档的本机未同步修改。确认后仅删除本次观察；结果 unknown/changed 保留清楚的下一步。未登录、身份未知或换人时，所有写/清理按钮不可用。

副本流程与候选草稿按认证后的元数据及 gzip 摘要关联，摘要只用于区分内容归属，不授予条件删除资格。重查同一原件不会创建第二个副本请求；未知结果即使看到新草稿也仍沿原请求核对。明确放弃对应原件且条件清理已返回 removed/absent/changed 时，才结束该未决副本并允许后续编辑；清理未知时保留原流程。确定成功/拒绝之后发现真正的新草稿，可处理新候选；此前成功的副本链接独立保留，不遮住新候选的操作。

EditorPage 尚未创建 EditMode 就收到 document/content 的已认证 403/404 时，仍以该用户/文档的独立 Reader 条件清理；401、会话失败和另一个用户的页面不得进入此路。

P1 的 restored/lost 提示按事实显示，明确点击“知道了”后以原 at 条件清除；新提示不能被旧 UI 清掉。离线说明“联网之后可以恢复”，不承诺离线冷启动。

## 7. 视图与无障碍

在页头现有通知区域添加恢复提示，沿用按钮、状态区和确认框样式。可恢复时显示“发现 HH:mm 未同步的修改”和“恢复并编辑”；冲突说明云端已有新内容；已恢复显示对应时刻。保留/失败状态提供重试或需要新页面的说明。请求编辑/在此编辑仍沿现有入口。

操作进行中的按钮保留但禁用，文字表示正在核对/恢复/保存副本/清理；成功事实与后续清理失败并存。常驻读屏状态区不重复播报轮询，操作面板消失时焦点回到仍存在的页头元素。正文和技术凭证不出现在视图或日志中。

## 8. 测试与交接

单元覆盖 S1 每种决定到动作的映射、精确旧请求字节、迟到/换人/换钥、关闭开关、未知副本复用、清理失败重试、初始脏状态及公式屏障。真实页面 E2E 同时读取本机/服务器正文与修订，三浏览器包含快进、确认丢失、更新捕获追自己、真冲突/只读副本、占用、损坏/过期/新格式/钥匙变化、403/404 早期路径、开关关闭与迟到结果。

质量流程沿 S2：红灯→实现→复验；检查运行期间不编辑源码/测试/文档；独立审查后修复复验；所有初次失败保留。原预算不提高。全 Phase 门禁、容器和 CI 属于 S6，崩溃进程证据属于 S5，本 Step 不把它们标为完成。
