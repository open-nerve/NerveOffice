# P2-S3 工作草稿与宿主准备：需求规格

> 状态：已自审，按已批准的 M4/P2 范围自主实施｜日期：2026-10-10｜所属：M4-P2｜代码基线：`b2b0f161`

## 背景与目标

S1 已拆分编辑会话，S2 已完成完整请求时限与接管位置。S3 建立 S4 所需的工作草稿接口、部署能力、密钥与宿主生命周期；S4 再替换自动保存、上传与副本的内容来源。用户授权按既定规划自主逐步推进，本规格不改变总设计范围。

验收对象是同一编辑会话中的两种来源：正常时内容在发件箱，关闭或不可用时内容只在内存。上层使用捕获引用与固定的一份上传数据；本机成功不能冒充云端确认，旧的异步完成不能改变新的会话。

## 选择与边界

采用独立的工作草稿来源及宿主准备器，复用 P1 DraftWriter。在 autosave/save-coordinator 中各接一套存储会重新产生多份内容；让 DraftWriter 管租约/页面会把产品状态带进 Worker，这两种方案均不采用。

S3 不改变捕获节奏、页面保存接线和页头；S4 接入来源，S5 展示本机/联网事实。部署字段先贯穿服务端及客户端会话，准备器据此决定是否启动。P3 的恢复、接手、adoptSeq 及 P4 全局清理不自动提前执行。

## 1. 部署能力

- `NERVE_LOCAL_DRAFTS_ENABLED` 默认 `true`，只接受字符串 `true`/`false`，空字符串沿用项目的未设置规则，其余值启动失败；进入冻结的 `AppConfig.clients.localDraftsEnabled`，不进入主密钥配置。
- SessionResponses 为登录、当前会话、修改密码、接受邀请、完成密码重置统一加 `features: { localDraftsEnabled: boolean }`；新会话仍在原事务内构造响应，不新增数据库访问。
- 响应契约保持宽松。旧后端没有 features 时，新客户端归一化为关闭；字段存在但形状不对仍报格式错误，不默认为开启。未知 feature 字段丢弃，旧客户端照常忽略新增字段。
- 关闭后不启动用于新写入的宿主，不取钥、不申请 persist、不登记/写入/重封/确认删除本机记录；内存上传继续。已有草稿保留，恢复入口留 P3/P4。
- Compose、配置说明与配置门禁同步，明确重启生效、不会自动清除旧草稿。

## 2. 模块与公共契约

新模块在 `apps/web/src/features/sheet-editor/`；keeper 仍在 `shared/outbox/local-key.ts`。

| 模块 | 职责 |
|---|---|
| `working-draft.ts` | 捕获引用、完成结果及上传数据类型，单会话唯一内容来源接口 |
| `memory-working-draft.ts` | 最新内存内容及至多一份固定上传，不打开存储 |
| `working-draft-source.ts` | 两来源共用的内容所有权、引用身份、合并队列和串行读写 |
| `outbox/outbox-host.ts` | Worker 握手、初始失败时的进程内退路、宿主销毁，不判断租约 |
| `outbox/outbox-session.ts` | 能力、取钥、登记、暂停、换钥与重建；服务端裁决由注入 confirm 提供 |
| `outbox/persistent-working-draft.ts` | 适配 DraftWriter，处理引用、去重、读回及内存退路 |

- `DraftCaptureRef` 仅含会话标识、捕获顺序 serial、同步分配的 draftSeq、editorSeq、UTF-8 大小及公式标记，不含内容、密钥或令牌。
- `WorkingDraft.capture({ editorSeq, snapshot, formulasPending, dedupe })` 同步分配并编码，交回引用；`ready(ref)` 只交回该次的摘要和本机结果，不能把较新内容冒充旧引用。
- `prepare(ref)` 在同步调用部分保留该次内容，交回 gzip 与真实内容的元数据，或明确的 superseded/failed/disposed。同时只保留一份上传；第二个不同引用不能替换第一份，处理完经 `release(prepared)` 放开。
- `release` 结束该上传，清除来源持有的固定上传及其 Promise/正文；结果未知时继续保留，不调用 release。匹配的在途标记随下一次真实落盘清除，同文去重不能跳过清理；更早写入的晚到成功不能消掉这个要求。调用方自己仍持有的 PreparedDraft 或已兑现 Promise 须自行放开，不承诺外部对象立即被回收。
- `markInFlight(prepared, inFlight)` 与 `confirm(prepared, revision)` 只作用于已保留内容。写入失败不能声称留下重放信息；旧确认不能丢掉新内容。
- `readLatest()` 为只读重建/副本临时解压，用完释放；`view()/subscribe()` 只发布元数据与本机事实；`dispose()` 停新工作及发布、释放宿主，不清除持久记录。
- `prepareOutboxSession(options)` 同步交回对象，`ready()` 等初次准备结果；准备中也可暂停/销毁。对外只有经资格检查的 write/markInFlight/confirm/read/setKey 等方法，不暴露原始 DraftWriter。`suspend()` 同步封住新写入/确认/换钥；`resume()` 得到注入的服务端 confirm=current 后才重新登记，调用方不能自行 force。暂停时仍可 read，resume 关闭旧宿主前，来源须先取回仍需要的当前内容。
- 持久来源另外提供 `suspend/resume/setKey`，上层通过它协调内容与资格。内核的 retainLatest 只交给持久适配层：保留承诺跨过已经开始的 write，接住 gzip 后才允许恢复关闭旧宿主；unchanged 没有 gzip 时用该引用仍持有的临时文本准备内存内容。新捕获和新生命周期代次使旧保留/换钥结果失效，不能覆盖新内容。

接口不要求上传者理解存储与写入者；S3 完成接口实现及契约验证，编辑器接线留 S4。

## 3. 序号、唯一来源与去重

1. 持久来源从 register.lastDraftSeq 分配，内存从指定高水位或 0 分配；与 editorSeq/序列化内容在同一同步段。失败、被新捕获取代也不回收序号；超过安全整数明确失败。
2. 持久写成后主线程只保留元数据，上传按需读发件箱；write 已交回的 gzip 可直接交给已保留的上传。内存来源只留最新工作内容，另允许一份在途/结果未知的 gzip，不让三个调用方各留 JSON。
3. 字节转移期间允许保留当前捕获的临时文本作失败退路，写成或得到 gzip 后释放。Worker 崩溃且没有 gzip 时，用仍属于当前或已保留捕获的临时文本准备内存内容。正常路径只编码一次，故障退路允许重新编码，不能取最新编辑器内容冒充原请求。
4. 慢宿主的普通捕获至多保留一个执行中、一个未发送的最新项；另有至多一个由 prepare 同步固定的上传槽位（包含尚在准备的上传）。例如 A 执行、B 被固定、C 最新时，B 不能被 C 合并掉，B 的读取/准备完成前 C 不能覆盖单行存储。普通中间项明确 superseded，序号有空隙且队列有界。
5. P1 unchanged 没有写下新分配的序号。来源记录本次捕获对应的已存在内容序号，prepare 使用真实序号；省略的分配号永久跳过，不把它写入 InFlightSave。显式保存不去重。
6. 云端确认后，只要当前真实 contentSeq 仍与上传相同，就把固定 gzip 交回来源作为当前内存内容；本机可能已删除却丢了回包，失败不能使当前正文消失。当前真实 contentSeq 仍与上传相同时，deleted 或后续幂等确认的 absent 都可发布 local=confirmed/revision，证明本机已无该记录；不得把旧 A 的结果套到较新 B。确认失败时独立发布同步元数据限制：正文的 persisted 与覆盖范围不一律清空；同一正文已被云端确认但删除结果未知时，页头说明本机状态未核实，不再声称仍有本机记录。后续 mark 成功不能掩盖确认失败留下的旧基准，完整新写入或对应确认成功后解除限制。清掉 P1 的去重种子，下次捕获相同内容也真正落盘；上层仍可据摘要、公式标记和确认修订去重云端上传。存在未知请求时不得据此去重。
7. 哈希、写入、读回、确认的晚到结果只完成原引用，view 仅在引用仍当前时更新。确认按对应序号保留较新内容并更新基准；不能只按会重置的 editorSeq 判断。
8. P1 压缩后的失败结果没有摘要时给 digest=undefined，不做上传去重，不在主线程另编码正常路径。内存实现用同一次编码算摘要并压缩。

## 4. 宿主、登记与失败状态

- 默认 P1 Worker；握手/请求看门狗 15,000 ms，长于同源锁等待 10,000 ms 和 IDB 升级等待 3,000 ms。保留现有 100 ms Worker 空定时器。
- 进程内退路同样有 15 秒等待上限；超时停用管道并结束调用方等待，底层已开始的操作仍持有 P1 锁直到实际结束。dispose 立即关闭当前资源，操作实际结束后在锁内再次收尾，关闭晚到的连接；DraftStore.close 之后可被新操作重新打开的契约不变。
- 仅初始创建/握手失败回退 createDraftWriter + createDraftStore，保留默认只读镜像恢复，不注入空 recovery，不在主线程写 OPFS。运行中崩溃先有界结束操作并保留内容；后续最多一次新宿主准备，先核对写入者，失败后等新捕获/显式恢复，不循环重启。
- Web Locks/必要加密能力不可用直接内存。IndexedDB 不可用、新版库、登记失败、已有未处理草稿均给具体原因。
- register 的任何 existing（含 no-key/unreadable/newer-format/malformed）均保留，不 adopt/覆盖；释放句柄，用内存。准备结果只存分类与元数据，不在 state/已完成的 ready Promise 里保留 gzip。宿主恢复时已有本会话内容也须验证身份和序号，不能仅凭数值猜测。
- 失效宿主需要读回时，readRecovered 临时准备只读宿主，设置当前密钥、沿用 P1 默认镜像恢复后读取，最后关闭；不登记/force、不申请 persist，也不恢复写入资格。来源核对文档、原 writer 身份与真实 contentSeq；读到不同内容明确失败。这里的只读指不发新捕获及登记，P1 的镜像比对语义保持。
- superseded/not-writer 先 confirm，仅 current 可 force；ended/superseded 交回租约失效，unknown 停持久化、保留内存。每次新登记用新 writerId，不存租约 token。
- 运行中的 write/markInFlight/confirm 被栅栏拒绝时立即暂停这一代资格；之后的新持久操作被拒，旧代晚到的拒绝不影响新代。显式 resume 仍走服务端核对。
- suspend 同步阻止新 write/markInFlight/confirm/setKey；已发出的由 P1 互斥与栅栏裁决。暂停仍保留工作内容，恢复须重新确认、登记并重写当前内容。
- 本机状态区分 preparing、writing、persisted（含镜像事实）、memory（disabled/unsupported/existing-draft/no-key/quota/unavailable/fenced/worker-failed）、disposed。旧捕获的成功不能用来描述当前修改。
- 首次符合条件的编辑会话申请一次 storage.persist；拒绝/失败/缺失不阻止编辑，捕获及换钥不重复申请。
- dispose/suspend 与握手、取钥、register、confirm、setKey 交错时，晚到结果不能重新启用或触发新登记；已创建宿主最终关闭。

## 5. 密钥版本与换钥

- 无当前密钥时也记录取用期间观察到的版本；observeVersion 本身不从阅读状态启动取钥。并发 ensure 共用一次取用。
- 新数字版本立即停旧钥并通知订阅者；低于已知版本的取用响应不 publish。一次 ensure 至多紧接再取一次，仍过旧则按原退避返回 unavailable，避免旧响应导致风暴。更高版本可接受，旧数字心跳不回退已知版本。
- null 保留 P1 保守停用语义；取用期间新观察到 null，旧取用不发布、重新取用。discard 清版本观察、退避和计数，作废在途结果，新登录独立开始。
- 第一回会话类失败确认后立即重试、第二回起退避、Retry-After 上限及 10 秒取钥时限沿用。
- 来源先停旧钥，再 setKey；notResealed 包含当前文档时对当前内容不去重重写。重写及晚到 setKey/取钥均检查会话与版本，旧钥不能装回。
- 仅密钥暂缺而原资格、宿主仍有效时，refreshKey 在原宿主 ensure/setKey，保留其重封缓存；取钥失败不关闭它。没有可续用宿主才走有界 resume。来源先保留当前内容，换钥成功后不去重重写当前引用对应的最新编辑；此处允许一次临时解压/编码，正常捕获仍只编码一次。
- 引用与产品状态不暴露密钥；仅在 keeper/宿主受控参数间传不可导出的 CryptoKey。

## 验收标准

- 配置默认/true/false/非法、五类真实会话入口、旧响应关闭退路有确定测试。
- 两种来源共用契约：序号、旧完成、新捕获、固定上传、未知结果、旧确认、显式保存、dispose；持久模式证明写成后无长期主线程正文。
- 真 Worker/IDB 浏览器覆盖登记、读回、密钥/存储退路、初始与运行中失败，复用 P1 能力探测，不操作用户真实浏览器配置。
- 可控 promise 覆盖暂停与服务端裁决、各准备步骤结束会话、新版本先于旧取用回包、持续旧版本的有界退避；修复做撤回/变异。
- 独立审查及相关单元/集成/类型/lint 通过后进入 S4，完整门禁和预算留 S6。

## 自审

明确了 unchanged 与新分配号的区别、转移后失败的临时内容所有权、暂停不发新持久操作、关闭保留旧记录及旧密钥的有界重取。未改变恢复与清理边界，无待用户决策事项。
