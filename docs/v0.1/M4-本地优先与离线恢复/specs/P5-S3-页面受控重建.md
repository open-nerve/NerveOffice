# P5-S3 页面受控重建：需求规格

> 状态：已实现并通过 Step 验证｜日期：2026-10-16｜所属：M4-P5｜依据：Phase §3.2–§3.5｜代码基线：`230f3907`

## 目标与边界

把 S1 的 Worker 故障与 S2 的稳定保存入口接到阅读/编辑页面。实例仍由 editor-slot 串行创建和销毁，保存资源仍由 EditingSession 拥有。S3 提供实际恢复、页面状态和重试入口；文案与有限诊断契约在 S4 完成，真实浏览器与生产镜像链路在 S5 验收。

## R1. 本页执行模式与创建失败

新增 `formula-fallback.ts`，保存本页首次 Worker 故障和主线程偏好，并包装原 CreateModeEditor。没有故障时不给生产额外模式参数，保留默认 Worker 和既有测试构建的模式入口。

遇到 `FormulaWorkerError` 时，在适配层完成失败清理后，以相同快照/access/viewState、`formulaMode: main-thread`、`recalculate: true` 再创建一次；后续本页的进入/退出/刷新也沿用该模式。普通加载/渲染错误、主线程错误不重复创建，不把它们报成 Worker 故障。重试主线程也失败时交回原失败处理，没有循环。

运行期故障同样设置偏好。创建/退出已经在途时，正在进行的槽位替换继续负责自己的结果；恢复不能并行创建第二个 SDK。新主线程实例仍须经过每条原路径的打开自检，进入编辑后的公式补存不依赖额外用户输入。

## R2. 重建前只等待已有输入准备

既有自动保存的 `prepareNow` 会先提交单元格，await 后才等待面板。换实例时必须等完已经发起的这些输入准备，否则旧操作可能在 await 后读取新实例的面板。

新增 `Autosave.settleInputPreparations(): Promise<void>`：等待调用时已经登记、尚未结束的输入准备，不提交新输入，不等待公式、网络保存或重放。每个准备在调用的同步段登记，成功/失败后都释放；错误原样交回，已有保存的原错误处理不变。重建时先禁止新保存动作，再调用此方法；随后按当前具体实例完成输入，最后才冻结。恢复路径保留 settleInputs 的提交→面板顺序，但分别等待并复核资格，避免提交等待期间失权后仍调用旧实例的面板。

这一步不改 snapshot-capture 的原有提交顺序、显式保存合并、HTTP 或退避规则。

## R3. 运行期恢复的所有权

新增 `formula-recovery.ts`，消费本页模式偏好、EditorSlot、EditingSession、LeaseClock，以及页面当前代次/阅读或编辑/本人会话/恢复资格。它只组织恢复，不自行申请编辑权或创建草稿。

- 先订阅当前实例的 Worker 故障，再读 getter，覆盖接线前的首错；监听跟随实例切换，旧实例的回调不能操作当前页。
- 故障处理排到下一宏任务，不能在 SDK 命令或组合输入事件的栈中捕获/销毁。
- 同时只有一轮恢复；同一个错误、重复同步、重试点击不能启动第二次重建。
- 正在进入/退出/刷新/失权时不另起替换；页面再次停在阅读或编辑时重新检查当前实例是否仍需恢复。
- 每次 await 后核对原页面代次、本人会话和恢复资格。编辑时还核对原协调器、调度、租约与本机锁；迟到结果不能恢复被撤销的编辑权。
- 会话离开再回来也使旧恢复代次作废；冻结正文保留，重新允许恢复后由新一轮接续。

恢复状态只保留有限事实：首次 Worker 故障，等待输入/准备/重建/暂停/失败/已切换，是否拦输入，失败阶段。原始异常只走现有本地 reportError，不成为诊断请求。

## R4. 输入与正文保全

编辑时先挂起自动保存。正在组字时仅进入“等待输入”状态，不挂会拦 compositionend 的完整交互屏障；组字结束后经调度再开始准备。禁止新保存、退出、交出和替换动作。

准备时挂完整屏障，等待 R2，再按当前具体实例执行 settleInputs。提交不了或捕获抛错时保留旧实例，解除这次完整屏障，让人完成输入后重试，不重复提交后来开始的输入；公式失效事实仍在。

输入完成后调用 EditingSession.freezeEditor，读取同一个稳定入口的完整快照，再经槽位以主线程、原 access、强制重算重建。阅读时保留当前只读快照，无保存或租约动作。

新实例打开自检通过且原代次/权限仍有效时，编辑模式先 replaceEditor，再 attach，最后恢复本轮挂起的调度和撤屏障。逻辑序号、草稿 sessionId、在途请求及修订号沿 S2 连续；旧 ACK 只能确认自己那次捕获。

打开自检失败、新建失败或接纳资格失效时，不把新模型交给保存层。冻结正文供重试与失权流程使用；重试从同一份完整正文重新建立实例。主线程反复销毁仍经过原 30 秒 stop-before-dispose 规避。

## R5. 槽位只丢弃自己的待接纳实例

新增 `EditorSlot.discard(created): void`，仅当参数恰是当前 handedOut 时退役它、清空待接纳对象并转为 none。不得销毁已经 attach 的实例或后来创建的另一个实例，不改变后来任务的 ticket。下一次 replace 仍等待它的异步销毁。

这使打开自检失败或权限变化后的迟到结果可以被准确清理，不使用 clear 去取消别的替换任务。视图仍由槽位的 carried 状态保留。

## R6. 页面与已有流程

EditModeView / EditorPageView 暴露公式恢复状态及重试入口；EditorPage 在准备、重建和冻结后失败时保持屏障，等待组字时保留原输入通道。UI 文案在 S4 接上，同一个入口供按钮和快捷键。

保存、退出、交出、进入、刷新/接管以及异步确认后的续行都检查恢复状态。已发出的保存照原协议收尾；仅新的动作受控。自动交出和空闲释放等到恢复结束再评估。标签页交接在恢复期间回应已有 busy 消息，不能先 ACK 再悄悄不交出；只新增内部 recovering phase，不改跨页消息格式。

失权、权限撤销、会话变化、pagehide 和 dispose 优先，使旧恢复作废。失权捕获改用 EditingSession.captureEditor，以便槽位为空时仍保住冻结正文；进入丢弃/副本流程后保留原所有权转交规则。读取不到或保存终态不被恢复路径改回可编辑。

## 验收

1. 输入准备等待与槽位丢弃有失败先行测试：等待只涉及已有准备；网络在途不阻塞；迟到/错误实例不能删掉新实例；异步销毁有正向控制。
2. 创建退路测试覆盖结构化错误、普通错误负对照、最多一次、保持参数、后续偏好和强制重算。
3. 恢复控制测试覆盖 IME、输入/捕获失败、失败重试、旧事件、已在途替换、同步信号与所有 await 边界。
4. 使用真实 EditMode/EditingSession/SaveCoordinator/WorkingDraft 与可控 SDK/网络替身，观察内容、对象身份、请求原字节、权限及未保存状态；覆盖零修改序号与原 ACK。
5. EditorPage 测试实际派发组合输入和交互事件，证明等待时未截断 compositionend、准备后拦输入、新实例自检成功后才放开。
6. 相关回归、全仓单元、lint、类型、生产构建和原产物预算通过；关键失败保护有实际变异证据。本 Step 不宣称真实浏览器链路或整个 Phase 完成。

## 自审与后续

上述接线位于已批准 Phase 的页面/保存/槽位职责内，不增加新的协议或 SDK 内部 API。运行期恢复的打开自检失败在 S3 阻止接纳，S4 再给诊断增加准确起因，不能暂时伪装成 refresh。旧保存输入准备的等待由 Autosave 自己登记，避免恢复模块探查其私有排队状态。
