# P2-S5 离线状态与联网复核

> 日期：2026-10-10。基线：`5005ad2a`。依据：P2 §3.6、§3.8 与已批准 M4 总设计 §2.2、§6.7。沿当前 P2 分支自审后实施。

## 1. 目标与边界

已经进入编辑的页面断网后继续输入、捕获、加密和落盘。网络恢复只是允许尝试；当前编辑会话取得新的服务端编辑权确认后，才可同步。页头同时表达本机与云端事实，并让需要服务端的操作在离线/连接异常时不可用。恢复新开页面、接手旧草稿、冲突自动恢复与集中草稿管理仍属于 P3/P4。

无新依赖、数据库迁移或服务端协议变更。沿用既有 React 页头、提示、表单和无障碍约定，不改版。平台首屏仍 ≤180 KiB/2 文件，发件箱 Worker ≤15 KiB；联网状态不得进入 Worker。

## 2. 页面共用的连接事实

在 `shared/lib/connection-state.ts` 保存元数据。放在 shared 是因为编辑器与平台文档操作都消费它；请求层不反向依赖 feature。这是 Phase 模块位置的明确细化。

- 浏览器明确 offline 时立即不可用。online 事件只恢复尝试资格，不能直接宣布连接已恢复。
- `apiFetch` 在完整请求时限（含正文读取、校验）结束后发布结果。NetworkError/RequestTimeoutError 进入连接异常；调用方取消不计网络故障；HTTP 业务拒绝/格式错误保留自己的语义，不伪装成功。
- 请求票据包含开始代次与顺序。离线/新故障后，旧请求的迟到成功不能恢复；较新请求成功后，较旧请求的失败不能倒退事实。元数据不含路径、正文、凭据或密钥。
- 实际成功可恢复连接事实，但不能直接恢复编辑会话的上传资格。连续故障保持首次异常时刻，供 90 秒提示使用。
- 浏览器连接适配器最多一只探测请求、一只退避计时器。复核复用 `requestSession(signal)`，不改 CSRF/用户身份，不自动重放平台写操作。初始退避 2 秒、翻倍至 30 秒；offline 不探测，online 可以立即复核；成功请求合并触发，不递归探测。销毁取消请求、清计时器与监听。
- 平台/编辑器每页只安装一份适配器；单元可注入时钟、事件源与复核函数。

## 3. 重连后的编辑权与真实发送边界

连接丢失同步停止云端上传，但不调用 suspendDraft、discardKey 或 autosave.dispose。持续捕获的生产链路保持 S4 行为。

EditingSession 拥有重连代次和单飞核对，复用 `confirmDraft`：先实际续租确认；已过期时沿既有 lose/续上，至多一轮，再实际确认。只有同一编辑会话、租约、锁、用户、保存协调和当前重连代次的 current 能开上传。unknown 维持关闭，按 2–30 秒退避复核；重复 online、请求成功与有效心跳合并，不因旧心跳/旧确认打开。再次断网、失锁、会话切换、停止或销毁使旧结果无效。不能把 `lease.resume():Promise<void>` 当成确认成功。

`setSavingActive` 的页面许可、S4 本机栅栏许可与本步连接许可共同约束上传。恢复资格只让原调度继续；不能伪造浏览器 online 事件或清掉既有 Retry-After。

SaveCoordinator 与会话发送函数区分两种意图：普通保存（包括先核对旧 unknown），以及结束编辑/终态时对已发出固定请求的核对。每一次实际 HTTP 之前，包括 mark/排队/续上后的第二次尝试，都重新检查许可。终态核对仅可沿原字节、原标识，在网络可尝试时核对一次，不能借它重获编辑权或发送新正文。

未发出不是网络失败：发送接口明确返回 `not-sent`。新请求未发出时清掉本次 unconfirmed 并释放 pin；原本 unknown 的请求未发出时保留原标识、pin 与未知事实，不误判确定未提交，也不制造网络错误或退避。此前已发送后才失去许可的结果仍按原幂等规则处理。

## 4. 本机事实与用户操作

EditingDraft 暴露不含正文/密钥的存储事实与变化订阅。复用 OutboxSession 的宿主、镜像、持久保存申请结果；初始退化为内存并关闭宿主后仍保留原因。P1 的 `storage-status.ts` 是持久保存事实的唯一来源，不另申请一轮 persist。

本机状态依据当前 WorkingDraft、editorSeq 与未提交输入联合判断：未捕获、写入中、当前修改已落盘、仅旧修改落盘、内存退路、云端已确认且本机记录已删除。A 晚到写入完成不能把更晚的 B 或单元格输入说成已保存在本机；confirmed 也不能冒充磁盘仍有记录。直接监听编辑修改/输入与来源，不能只等 save.unsaved 的布尔值变化。

页头保留 `data-save-state` 云端状态，另呈现本机摘要及详情：

- 有完整落盘证据且尚未云端确认：“已保存在本机（等待同步）”。
- 明确离线且当前修改完整落盘：“已离线，修改已保存在本机”；否则说明还有修改只在本页。
- 配额失败：“本机存储空间不足”。部署关闭：“本部署关闭了本机草稿（浏览器崩溃会丢掉没保存的修改）”。
- 浏览器联网但实际请求无回应：“网络没有回应，正在重试”；不能无证据追加已保存本机。
- 无密钥、存储不可用、不支持、已有受保护草稿、镜像降级、进程内宿主分别说明原因和限制；拒绝持久保存申请不阻止编辑，也不能说浏览器承诺永久保留。
- 异常超过 90 秒说明编辑权可能已过期，恢复后如果他人保存过，需要另存为副本。提示按真实异常起点计算，重连事件不重置仍未恢复的时长。

离开提示继续依据未云端确认/未提交输入。读屏只播有意义的故障、降级、恢复变化，不逐次捕获朗读；不抢焦点。

平台的分享、移动、改名、复制、删除、新建，以及编辑器的进入/请求/接管/交出/退出/另存副本等服务端操作，统一说明需要联网。沿用 aria-disabled 以保持焦点可达；点击和表单实际提交均读当前事实阻断，包括断网前已打开的对话框/确认框。取消、复制文本、已有编辑输入仍可操作。认证/退出安全流程和显式重新读取不被通用写操作守卫误伤。

## 5. 验收

- 单元确定证明完整请求结束后的观测、旧响应隔离、单飞/退避/销毁、重连租约核对、mark/排队/续上交错、not-sent 与 unknown 的区别；本机覆盖范围与各降级文案；已打开表单的离线阻断。
- 三浏览器真页面离线连续编辑 10 分钟，读实际密文验证；90 秒提示；在线后暂停真实续租/续上回包，证明确认前零正文上传，放行后原内容同步。浏览器时钟与数据库时钟分开，过期场景用既有测试数据库 helper 明确使租约过期。
- navigator 仍 online 的实际网络失败/超时、恢复无新编辑、换人/丢锁/再次离线、存储配额/不可用/关闭开关、离开提示、平台已打开对话框、原 M3 保存/会话/交接故事继续覆盖。
- 所有检查退出后才修改源码；有意义的守卫做撤回/变异验证，独立复核后提交。S6 做整 Phase `pnpm verify`、测量、收尾和合并，不提前宣称 P2 完成。
