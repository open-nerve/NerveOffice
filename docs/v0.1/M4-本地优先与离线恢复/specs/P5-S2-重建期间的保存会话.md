# P5-S2 重建期间的保存会话：需求规格

> 状态：已自审｜日期：2026-10-16｜所属：M4-P5｜依据：Phase §3.3–§3.4｜代码基线：`5553892b`

## 背景与目标

公式 Worker 退路需要替换具体编辑器。现有保存协调器、自动保存与本机状态直接引用创建时的编辑器；重新创建它们会打断在途请求与草稿身份，继续引用旧实例则会捕获已销毁的模型。

本 Step 提供稳定的保存入口及明确的公式失效确认边界。页面如何等待输入、加屏障、通过槽位重建和处理权限并发由 S3 实施；S2 不自行申请、释放编辑权或创建 SDK 实例。

## 需求

### R1. 同一编辑会话的稳定入口

新增 `saving-editor.ts`，消费 `AutosaveEditor & SaveEditor`，只拥有订阅，不拥有 SDK 生命周期。`createSavingEditor(source, reportError)` 返回 `SavingEditorBinding`：

- `editor: SavingEditorSource`：保存层始终使用的对象。
- `freeze(): FrozenSavingEditor`：同步固定 `{ snapshot, editorSeq }`；重复调用交回同一份。
- `bind(source): void`：只在冻结之后绑定新实例；没有冻结、已经销毁时拒绝。
- `dispose(): void`：释放订阅和冻结正文，可以重复调用，不销毁具体编辑器。

首次绑定保留原始修改序号。重建时逻辑序号不变，新实例的初始序号作为偏移基点，之后新增模型修改继续递增；例：旧实例到 7，新实例载入时为 3，接上仍为 7，新实例到 4 时逻辑序号为 8。公式重算不能伪造成用户修改。

四类订阅（模型、未提交输入、公式进度、组合输入）通过稳定入口转交。换实例后旧订阅释放，已经排队的旧回调由代次挡住；一个观察者抛错不会阻止其余观察者，交给注入的报告器。取消订阅和销毁真实有效。

### R2. 冻结必须保全输入

冻结前要求没有组字、没有打开的单元格编辑器、`uncommittedInput() === 'none'`。不满足时抛出 `SavingEditorInputError`，保持原实例和订阅；由 S3 完成输入后再调用。不会在这里偷偷提交单元格或清掉面板状态。

同一个同步段读取逻辑序号与 `capture()`；捕获抛错时不退订、不进入冻结。成功后才固定快照、退订具体实例，并通知公式进度变成未收齐。冻结期间：

- `capture()` 交回固定完整快照，`changeSeq()` 不变；
- `formulasSettled()` 为 false，`settleFormulas()` 返回 timeout；
- 不再读取旧模型，不重复提交输入，不等待旧面板；未提交输入和组字均为 none/false（冻结前已验证）；
- 同一保存协调器排队中的捕获仍可以读取这份正文，不会访问被槽位销毁的实例。

冻结前已发起的异步操作不能替新实例作保证：旧 `settleFormulas` 结束之后重看当前代次/当前状态，只有当前模型已收齐才能返回 settled。旧输入的提交与面板等待保持调用时语义，不能因此提交新实例上后来开始的输入。

### R3. 公式失效与旧 ACK

现状：`SaveCoordinator.noteCapture` 只更新快照体积；`confirm` 直接采用被确认捕获的 `formulasPending`。因此相同编辑序号下，恢复前的旧 ACK 会把恢复中的公式结果错误地说成已保存。

新增 `SaveCoordinator.noteFormulaRecovery(ref: DraftCaptureRef): void`，登记原工作草稿给出的恢复捕获身份 `{ sessionId, serial }`。它立即让 `view().formulasPending`、`hasUnsavedWork()` 为真，不改 `unsavedEdits`、编辑序号、baseRevision 或请求字段。

`CaptureRecord` 同步保留捕获的 sessionId/serial。恢复标记只在**同一草稿会话、serial 晚于恢复捕获、且 formulasPending 为 false**的捕获获确认时清掉；本地摘要去重确认同样适用。旧 ACK、旧结果未知请求的重放/认领、带 pending 的新 ACK 都不能清掉它。重复登记同一标记或更早的标记不能倒退边界。这里使用来源已经分配的 serial，不创建第二套持久序号。

不改 HTTP 请求、幂等键、内容摘要、服务端/数据库结构。原在途请求的 requestId、localSeq 与正文逐字节不变；不同的捕获仍由现有来源分配内容序号，保存协调器照原规则串行。

### R4. 自动保存接纳恢复捕获

新增 `Autosave.captureForFormulaRecovery(): DraftCaptureRef | undefined`。未结束且未销毁时，经既有 `captureNow` 路径同步捕获，使用 `formula-recovery` 原因与 `formulasPending: true`，更新 latest、capturePending、耗时与体积，并调用协调器的 `noteFormulaRecovery`。

该方法不立刻发起 HTTP，不调整退避、联网、会话和上传间隔；允许调度已 suspend 时调用。S3 负责 suspend/resume。已结束/已销毁返回 undefined，不捕获。捕获失败原样抛出，由页面保留旧实例并说明；不把旧草稿当成成功。

即使逻辑序号仍为 0、没有新的模型修改，也必须留下恢复捕获并显示公式待更新。接上强制重算实例后，收齐的进度信号触发原 capturePending 补捕获路径；没有用户新输入也能补存不带标记的结果。上传仍服从原权限、离线、定时暂停与退避规则。

### R5. 编辑会话接线

`EditingSession.startSaving` 创建一个稳定绑定，协调器、自动保存、本机状态与失权捕获使用相同入口；它们的对象身份和订阅在具体编辑器替换时不变。新增：

- `captureEditor(): EditingSessionEditor | undefined`：给需要捕获的页面流程读同一稳定入口；停自动捕获之后仍可用。
- `freezeEditor(): DraftCaptureRef | undefined`：若绑定/协调器/调度已不存在则返回 undefined；否则冻结后经 R4 登记恢复捕获，重复调用不再分配新的捕获。R4 同步失败时恢复原实例绑定并抛出，不丢未保存内容。
- `replaceEditor(editor): boolean`：存在待接纳的冻结绑定时同步接上，清掉本次冻结引用，返回 true；已经结束或没有冻结则 false。不会重建保存资源、不会自行撤屏障/恢复调度；页面在调用前负责权限与 generation 检查。

freezeEditor/replaceEditor 还核对保存资源仍属于原租约、本机锁仍持有、会话仍是本人。租约已 detach、锁被取代或本人会话已结束时不开始/接纳恢复；已冻结的 captureEditor 仍供失权流程保留正文。这里仅核对既有所有权，不发新的权限或租约请求。

`stopCapturing` 只销毁自动保存，保留稳定入口与原协调器，以便失权流程捕获/核对旧请求。`stopSaving` 先按原顺序结束协调与调度，再释放绑定。`takeDraft` 的来源转交语义不变，旧会话停止不能销毁新所有者的来源。冻结后的正文保持在原来源内；稳定入口只在替换间隙持有同一份重建输入，不成为新的草稿来源。

## 验收标准

1. 假编辑器可以确定推进修改、输入、公式、组字以及迟到回调，证明 R1/R2 的每个边界；没有依赖真实时钟竞速。
2. 单独的保存协调器测试证明相同编辑序号下旧 ACK 不清标记、新 pending ACK 不清、新完成捕获 ACK/摘要去重才清；旧未知结果重放保留原请求。
3. 调度测试证明序号 0 的恢复捕获、挂起时不上传、重算后无输入补存、失败不伪造捕获、结束后无副作用。
4. 编辑会话测试观察真实协调器、自动保存、工作草稿和假租约：替换前后对象同一、无额外 acquire/release、逻辑序号连续、新内容能落盘/上传，失效后不能再次接纳实例。
5. 原保存、离线、锁交接及编辑器页单元回归通过；全仓单元、lint、类型与产物原预算通过。页面的真实浏览器故事在 S3/S5 接线后验证。

## 不做什么

不在保存层决定 UI 权限，不做实际 SDK 重建，不把重建失败视为放弃草稿，不改协议或补丁 SDK，不新开分支。

## 未决问题

无阻断问题。S3 接线时必须使用稳定入口执行恢复期间的失权捕获，并保证新实例通过打开自检之后才调用 replaceEditor。
