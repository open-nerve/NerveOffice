# P3-S2 原子观察、接手与条件清理

日期：2026-10-11；基线：`03f32de1`。上层：P3 设计 §3.3–3.5。只增加恢复所需的存储与内容来源能力，不接页面，不改变服务端协议或数据库格式。

## 1. 需要守住的交错

序号相同不能证明记录未变：标记在途、换钥或改基准会重封；另一个页面也能先登记、随后才写草稿。旧观察者的确认、放弃或副本完成不能删除这时的新状态。损坏记录没有合法序号，同样不能无条件删除。

采用宿主内保存的观察凭证：调用方只拿到用户/文档键和随机 id，不携带或拼接 expectedSeq。存储实例在一次只读事务里同时读取草稿、写入者和提示，保存它们的原始结构化克隆。每份文档只保留最近一次观察，后续观察令旧凭证失效；关闭实例清空观察。凭证不能跨存储实例或宿主续用。

比较与修改在同一个包含草稿、写入者（删除另含提示）的 strict 事务里执行。比较的是完整原始记录，包括密文、IV、元数据、写入者身份、登记时间及高水位。调用方拿到的解密结果、元数据和密文字节与内部观察副本互不共享；转移缓冲或修改返回值不能改变凭证。

原始值比较覆盖本库可能写出的普通数据对象、数组、基本值、ArrayBuffer 与各类字节视图，并识别循环/共享引用，区分缺字段、undefined、数组空洞与字节变化。异常外部值（例如 Blob、未知对象）、超出防御性遍历上限时无法证明相同，保留并返回 changed；不按长度、JSON 摘要或“仍然损坏”猜测相等。不增加通用序列化框架，不在事务里 await 加密/解压。

## 2. 存储契约

- `observeDraft(key)`：返回观察凭证、形状核对后的当前记录（含 absent）及当前写入者。失败保留 StoreProblem；不登记、不立墓碑、不改变草稿或提示。
- `adoptObserved(observation, draft)`：新记录形状合法且键相同；凭证仍有效；当前原始写入者与草稿均未变；新记录属于当前非墓碑写入者，序号严格高于高水位；被接手的原记录必须是可识别的草稿。全部成立才写入新密文并抬高水位。不能以 duplicate 绕开观察，也不以 adoptSeq 代替观察。结果 written / fenced（changed、not-writer、stale-seq、foreign-draft）/ StoreProblem。
- `removeObserved(observation, now)`：凭证、原记录和写入者均未变才删草稿。删除与写入者换为墓碑在同一事务提交，高水位保留；阻止旧宿主补写及镜像复活。只清除同时观察到且未变化的提示，新提示保留。原本就没有草稿仍须比较凭证，确认没有新写入者/新记录才返回 absent；不借 absent 去删除镜像。发生变化返回 changed，不能自动重读后继续删。
- 成功接手/删除后消费凭证。失败不伪装成功；事务中止、配额和连接错误保持原存储状态。原有普通保存/确认/放弃接口暂不改义，恢复只用新接口。

## 3. 写入管道、Worker 与清理

`DraftWriter.observe` 在现有同源互斥中先完成镜像比对，再获得库里的原子观察并解开该记录。读不全/镜像无法比对时不给可操作凭证；不把“只能从镜像临时读到”当作已经可原子修改的库记录。

`DraftWriter.adopt` 沿用 SHA-256、gzip、AES-GCM、strict 提交及镜像流程；必须显式给观察凭证，不能去重，不接受旧 inFlight 或 adoptSeq。新捕获可以包含恢复后重算的公式结果。旧请求原样核对和修订判定仍由 S1/S3 完成，接手前原字节、序号与 inFlight 保持不动。

`DraftWriter.removeObserved` 在同源互斥内提交条件删除和墓碑，再释放自己的镜像句柄并尝试删除该文档镜像目录。目录失败/被占用时返回“库已删除、镜像待清理”的事实，墓碑继续阻止复活；不把目录失败折成“原件还完整保留”，也不报告完全清理。进程内退路同样能异步删除目录。成功后仍保留墓碑高水位，后续合法登记继承；账户级/保留期清理由 P4 统一回收。

Worker 请求/响应增加 observe、adopt、remove-observed，逐项核对凭证、捕获及结果。gzip 只转移交给调用方的副本；内部观察只留密文，不长期多持有正文。宿主超时/关闭后旧凭证失效，旧响应不复活已停会话。接口失败值与进程内放置保持一致。

## 4. 编辑会话与恢复初值

普通 OutboxSession 的 existing-draft 保护不变。显式 `recoverExisting` 模式才允许在已取得租约、本机锁并完成登记之后，为既有草稿暂时保留宿主；此时仍是 memory(existing-draft)，普通 write/mark/confirm 均不可用。

恢复会话可以 observeRecovery，之后把该会话刚观察的凭证与首份恢复捕获交给 adopt。调用前后都核对会话代次、租约代次、宿主、当前密钥和仍存活条件；只有实际 written 才进入 ready。changed/fenced 要重新发现，不能退成普通写入或自动 force。暂停、换钥、续上新代次和销毁使旧资格失效。removeRecovery 使用同一个会话凭证进行条件清理；暂时的采用失败保留该凭证，供 S3 在内存内容获云端确认后清理原件。已提交的删除事实不因响应回来时会话过期而改写，页面仍须核对自己的流程代次。

WorkingDraft 可以接收显式恢复初值，仍由同一来源创建自己的合法引用和队列项；调用方不能伪造 DraftCaptureRef。初值以 editorSeq=0 也属于未确认的内容，草稿序号从当前持久高水位继续分配，不使用 SDK 的修改计数代替。持久实现的首份恢复写入走 adopt，后续恢复普通 write；内存实现同样保持初值与副本/上传所有权。恢复初值不携带旧请求身份。采用尚未成功时后续捕获只留在内存，resume 不自动重新登记；下一次采用必须重新发现并创建来源。配置中的初值在来源接收后不由长期闭包额外持有。

部署关闭新写时，独立的只读宿主仍可 observe/条件清理既有记录；编辑走内存来源，不进行 register/adopt，也不自动删除原件。云端确认、成功副本或用户放弃才由 S3 使用原观察凭证条件清理。公式重算屏障、保存调度的初始脏状态与页面安装属于 S3；S2 不以存储成功代替它们。

## 5. 验收与自审

确定交错必须包含：观察后仅登记、同序号重封/换密文、抬高水位、malformed→合法/新格式/另一份 malformed、迟到确认、跨键/宿主/关闭后的凭证、返回值被修改、配额/事务中止、镜像清理失败。接手检查新正文/基准/格式/公式标记、水位和旧请求不复用；删除检查新提示与墓碑及恢复不会复活。

以纯函数和管道单元验证反向路径，再以真实三浏览器 IndexedDB 排队事务、Worker 协议和进程内宿主证明生产接线。核对现有栅栏、密钥与镜像回归；平台及 Worker 预算沿用原值，不增依赖。原子机制完成后独立复核，再提交 S2。

自审：凭证不等于编辑权限；登记前的观察不能借登记后的新身份删除。只保留最近观察会让过期 UI 返回 changed，这是有意的保守结果。墓碑与删除必须原子提交，不能等镜像失败后再补墓碑；否则中间崩溃会复活旧镜像。关闭新写不等于禁止处理已存在的数据。对不认识的外部结构只报告无法核对，不声称已清理。
