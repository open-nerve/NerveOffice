# P6-S2 虚拟机突停与持久证据

> 状态：自审通过，环境资格验证先行｜日期：2026-10-17｜基线：`17fe99a5`

## 1. 目的与边界

落实已批准 M4 总设计 §2.1 第 5 条及 P6 §3.2：Linux 官方 Chrome/Edge、macOS 真正 Safari 在客体 OS 突停后，能否读回宿主已经记录完成的写入。宿主不关机，因此不覆盖宿主/硬盘缓存、物理断电或损坏；默认组不要求出现丢失，零丢失也不构成永久保证。缺失轮次或停止证明只能记未验证。

只在唯一 P6 worktree 实现。工具、镜像、磁盘与实验原件放主目录 `.codex/handoffs/m4-p6-20261017/`，不进 Git。宿主不共享用户目录、工作区、GitHub 凭据或钥匙串给客体。结果中不记录应用密钥、Cookie、令牌和密码。

## 3. 两层实验

### 3.1 IndexedDB strict/default 对照

每浏览器先做一个不停止的完整控制轮，再做 strict/default 交替的 20 个独立突停轮次（各 10）。每轮有不同 `runId`，同一轮重启前后使用同一来源、浏览器资料和虚拟磁盘，不恢复快照。

页面在自己的专用 IndexedDB 中连续写入 1 MiB 确定性字节、递增 `seq` 及 SHA-256。正文从本轮身份和序号生成，摘要在事务之前算好；只在 `transaction.oncomplete` 后报告。记录请求的 durability 与浏览器实际返回值。默认组不传 transaction options，strict 组明确传 `durability: 'strict'`。页面只读取/写入本轮数据。

宿主固定在序号 10 的完成报告后触发突停。收集器验证本轮身份、初页 boot ID、模式、精确字段、序号及独立计算的摘要；把接收时间、报告和冻结点写入专用 journal 并 fsync，成功后才让控制器发 SIGKILL。写 journal 失败不能发信号、不能算已确认。冻结之后的旧页报告一律拒绝，不能补写原冻结点。冻结资格最多有效 5 秒，临发核对再次检查年龄；超时或时钟倒退即作废，不能再次尝试。宿主 journal 记录的接收/冻结/信号时刻可直接比较；客体完成时刻另附 SSH 时钟采样的偏移区间，跨时钟耗时只作为有不确定性的估计，不能冒充精确端到端时间。

重启资格由控制器证明：原 VM 子进程因 SIGKILL 退出，新 VM 进程、客体 boot ID 均改变，原磁盘路径与文件身份保持；确认后收集器才接受新的页面 boot。读回使用只读事务，库不存在时中止升级，不创建空库冒充原件。

若读回缺失、序号小于冻结序号、存储身份不符或正文摘要不符，记录数据丢失/损坏并保留失败；更高序号允许，但必须独立核对其确定性正文。读取阶段原生异常单独记为 `unreadable`，保留读取阶段及白名单错误名，不把它等同于空记录或协议格式错误；默认组保留该结果继续对照，strict/控制轮仍停止。拒绝旧页面、重放、跨轮和额外字段。完整保留无效轮次，不以重跑覆盖。

### 3.2 产品恢复

每浏览器至少 3 个独立突停轮次，使用真实编辑器、正式 strict Worker 与 OPFS 路径，实际读取并独立解密本机草稿。复用已有 Safari 崩溃自检的公开恢复按钮和服务器正文核对；测试构建只负责观测/编排，不修改身份或种草稿。初页云端定时上传暂停的既有测试前提须明确记录，不把它称为生产容器验收；生产部署正常自动保存已由 S5 单独覆盖。

Worker 完成与独立解密证据先写宿主 journal，然后突停。OPFS 必须有真实镜像完成或只读槽位证据，不能仅凭“代码启用 OPFS”宣称落盘。重启后 Cookie 若丢失，通过测试登录重新取得密钥，不把它当作数据丢失；新 Document 先阅读、零编辑申请/保存。宿主核对原件与云端 revision 1 后，才给测试驱动一次点击真实恢复入口的许可，随后核对新页面身份、正文、revision 2、唯一上传和旧草稿清理。

给已有恢复会话增加明确的 `vm-power-cut` 模式及专用 VM 停止证明入口，不能拿普通刷新或浏览器进程信号充当 VM 实验。不得放宽原有 Safari 页面崩溃模式的资格。

## 4. 资源控制

VM 控制器只能操作自己本次 spawn 的 QEMU/Tart 子进程。记录并在信号前重查 PID、UID、启动时间、可执行文件/参数和资源登记；进程已退出、身份变化或路径不在本次资源目录则拒绝。不使用名称匹配批量 kill，不操作 Parallels 或其他现有 VM。

Tart `stop` 在 SIGKILL 前先发 SIGINT，不能用于本实验；直接对登记且复核过的运行子进程发 SIGKILL。QEMU 同样不发 ACPI shutdown、monitor quit 或保存状态。工具的正常关闭只用于未计入实验的环境准备/最终清理，报告须区分。

收集器与 SSH 转发只绑定 loopback。不同运行的控制入口、一次性身份与原件目录互相隔离，请求体有大小限制，Origin 精确匹配；VM 页面不能调用系统信号或指定代理目标。控制器接收事实，再经受测状态机与宿主落档顺序决定是否停止。

## 5. 验收与自审

- 单元覆盖：完成报告 fsync 前不发信号、失败 journal、冻结后迟到、跨轮/跨 boot、重放、序号回退/正文损坏、读回不存在，以及退出/身份变化的 VM 拒绝信号。
- 浏览器校准：三个既有浏览器实际验证 control/strict/default 页面的事务、报告和读取路径；校准标识与真正突停分开。
- 实机矩阵：三浏览器各 1 控制、20 存储突停、3 产品突停，原始状态、journal、停止/重启、读回/解密/云端证据齐全。没有运行的单元格不写通过。
- Step 静态/单元/相关浏览器回归及故事门禁通过，报告写清范围；全 Phase 审查、完整 verify/容器和 CI 留 S6。

自审：本方案落实既有 M4 决策，不改变产品协议。选择完整 x86_64 模拟以覆盖实际发布的 Linux Edge；使用 macOS 27 镜像避免把旧 Safari 结果代入当前版本。环境准备本身不算实验通过，普通 Safari 持久资料与 automation 临时会话必须区分；产品层延用已有自检并明示上传暂停前提，避免重复建设一套恢复逻辑。
