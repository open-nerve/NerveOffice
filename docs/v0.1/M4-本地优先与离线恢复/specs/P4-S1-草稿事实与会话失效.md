# P4-S1 草稿事实与会话失效：规格

> 日期：2026-10-14｜状态：已实现，Step 验收通过｜基线：f600f7b5｜上层：04-P4-本机草稿页与本机清理.md §3.2–3.3

## 1. 目标与非目标

给后续本机草稿页提供一批文档的当前事实，并让已经持有会话的页面区分账户停用与其他登录失效。这里只实现契约和服务端查询，不删除浏览器数据、不接界面、不改变登录失败或原有编辑权裁决。

## 2. 批量文档事实

`GET /api/documents/draft-facts?ids=<uuid>,<uuid>`，要求登录。静态路由在 `:id` 之前。

- `ids` 必填且只能出现一次；原始字符串最长 3,699 字符，逗号分隔的原始项数为 1–100（重复项也计数）。不接受空项、空格、非法 UUID、数组/嵌套参数或额外字段。
- 校验后 UUID 转为小写，按首次出现去重；响应顺序与此顺序相同，每个规范化 id 恰好一项。前端对超过 100 份的目录串行分批。
- 成功响应为 `{ items: DocumentDraftFact[] }`，每项是以下二者之一；响应契约兼容丢弃将来的额外字段，未知状态或缺少必需事实仍拒绝。

| status | 字段 |
|---|---|
| accessible | id、title、type（既有 DOCUMENT_TYPES，当前只有 sheet；doc 属于 M6）、canEdit、revision（正安全整数）、revisionSource（既有结构或 null）、occupied |
| unavailable | id、status；没有标题、权限、位置、修订或占用信息 |

服务器只返回当前用户能读取的正常文档。不存在、回收站、无权读取、取消分享与未加入空间的系统管理员，均为 unavailable。归档空间仍可读取但 canEdit=false；单独授权依照现有访问策略与归档规则。不得把网络、数据库、认证或契约失败转为 unavailable。

revisionSource 通过现有 `revisionSourceFor`：只有保存该修订的本人能看到，其他人一律 null。新建修订无来源。接口不返回内容、快照、租约令牌、摘要、持有者/预留人身份、内部写入代次。

occupied 复用 `occupancyOf` 与 `reservationOf`，包括本人在另一页持有、有效预留，以及 M3 的 R2：跨空间移动后仍有登录和编辑权的其他持有者可以先续上。过期、空闲超时、已结束、登录失效、撤权及无效预留不占用；代次过时的本人按现有规则可重新申请。所有时间使用同一数据库快照的 now()，不另造“只看 expiresAt”的判断。

## 3. 查询与隔离

最外层专用 `DocumentDraftFactsService.get(userId, ids)` 只开一次 readSnapshot。该快照开场复核会话、账户和系统角色，后续文档、授权、空间、修订及租约均使用同一个事务并逐条 await。

文档与调用者的单独授权一次查询；调用 `accessOfMany` 批量判权，缺失项以访问策略已有的不存在对象占位，全部不存在也执行同样的权限查询。不可读与不存在在同等输入形状下返回相同业务结构并经过相同 SQL 语句序列。混合结果中只为可读项取修订和租约，不查正文。

当前修订与租约各批量一次；id 数组用 inIdArray。涉及持有者/预留人的登录和编辑权时，复用现有按需事实回调，串行、有界（最多 100 份），不复制另一套授权 SQL。读请求不顺便修改租约、清除预留或修订记录。

查询结果只是当时的事实，不能作为后续恢复或清理的永久授权；操作的重新核对归 S2–S4。

## 4. SESSION_EXPIRED 的详情

保持原 HTTP 401 与错误码，在 details 中增加：

| 数据库/请求事实 | reason | userId |
|---|---|---|
| revoked_reason=disabled | account_disabled | 被该会话识别的用户 |
| password_reset | password_reset | 同上 |
| password_changed | password_changed | 同上 |
| replaced | replaced | 同上 |
| logout | logout | 同上 |
| 已识别会话自然到期 | expired | 同上 |
| 格式错误、无法解码、不认识或已清理的令牌/会话 | expired | 不带 |

契约允许 expired 不带 userId，其余原因必须带有效 UUID；未知原因或畸形详情不能被前端解释成停用。既有后端缺少 details 时，后续页面按未知认证处理并保留草稿。

同一行只保留最初的撤销原因，后来的账户变化不改写历史原因。服务端数据库失败照原机制传播，不假定为 expired。没有 Cookie 仍为 UNAUTHENTICATED；登录名/密码失败仍为 INVALID_CREDENTIALS，不能因为本次新增原因泄露账户停用。

共享分类适用于 SessionGuard、SnapshotIdentityCheck、SessionService.requireActive，以及退出和修改密码已经产生 SESSION_EXPIRED 的竞争路径。只读/写事务内的分类在原事务里完成，事务提交后不再为拼错误追加数据库访问。

守卫发现已认证会话对应账户不可用时，沿用撤销该会话的防御；原因读取仍以实际记录为准。快照已通过会话但发现账户明确 disabled 时，以 account_disabled 与已经认证的 userId 拒绝；账户缺失只作 expired，不能猜成停用。

replaced 的守卫或退出竞争响应不清除可能已经更新的 Cookie；其他守卫失效沿用原来的清除行为。快照和写事务的失效不改 Cookie。正常退出仍 204、正常修改密码仍创建新会话；只改变原有 SESSION_EXPIRED 的细节，不改密码凭据失效等其他错误码。

## 5. 验收与反例

- 契约：1/100/101 项、原始重复项计数、大小写 UUID、顺序、空项、重复参数、非法输入、额外字段、未来响应字段、非法来源/修订；失效详情的原因与 userId 组合。
- 真实 HTTP：静态路由、登录要求、可读/不可读混排、各权限途径、归档/移走/删除、他人来源隐藏；100 项成功、101 项拒绝；错误不能变成空目录。
- 真实存储事实：有效与过期/空闲/已结束/会话失效/降权的租约、本人和他人、有效/过期/撤权的预留、R2；状态与既有编辑状态一致，不触碰内容。
- 只读快照：加入全部 GET 路由核对；加入确定性撤权交错，快照只能返回一个完整时刻的事实；隐藏与缺失的 SQL 及业务结构一致。
- 会话：所有原因在真实数据库与 Cookie 下可区分；守卫之后到快照、写事务或退出/改密之间撤销，仍返回同一分类；轮换旧响应不清新 Cookie；数据库失败不能被吞掉；登录失败不新增原因。
- 全项目单元、相关集成、完整类型/lint 通过。S1 没有浏览器行为变更，累计浏览器与生产容器门禁留在 Phase 的适当步骤，S6 全跑。

## 6. 自审

设计只补 M4 已批准的接口事实与会话原因。沿用访问策略、修订来源保护、租约规则及事务边界，没有新增服务端表、依赖或授权入口。检查未知/失败状态与 unavailable 的区别，记录大小写与查询上限，给后续清理提供事实但不在本 Step 引入删除副作用。
