# P4-S3 本机草稿页规格

> 状态：实现、自审及 Step 验收通过｜日期：2026-10-14｜基线：4ea34f0c｜唯一工作区：codex/m4-p4-drafts-cleanup

## 1. 范围与依据

兑现 Phase §3.4、M4 总设计 §6.4/6.7 的本人本机草稿目录、存储状态、逐条恢复/副本/放弃和空间、与我共享、搜索标记。沿用 S2 的完整原件观察、持久会话许可和共享 DocumentRecovery。S4 的启动维护、退出/停用及保留期自动协调，S5 的 SDK 存储和旧记号，S6 的全量验收不提前宣称完成。

这是已批准 Phase 的第二个恢复使用方，属于既定架构实施，不新增自动恢复、批量修改、跨设备同步或服务端授权。用户已授权自主推进，按 Step 完整验证后一次中文提交。

## 2. 方案与职责

选择按需加载的 features/local-drafts 页面，shared/local-drafts 提供目录读取、串行协调和传输，编辑器继续负责租约、重建、公式和最终保存。与平台直接引用 sheet-editor、页面另写判定两种方案相比，此方案保持入口隔离和单一判定。

- draft-facts-api：每批最多 100 个不同 UUID，串行分批。校验运行时结构及响应 ID 的完整集合，缺失、额外或重复不成为权限事实。只读取元数据，不取文档正文。
- content-api：提取现有副本、原请求重放与内容上传传输，编辑器保持原函数入口兼容；60 秒完整请求时限、格式参数、幂等请求和租约头规则不变。
- draft-inventory：固定当前会话许可的 store；先 reconcileAll，再列主库元数据。比对未完成、非空或无法读取的镜像单独保留；空目录不冒充草稿。失败不能变成空列表，失去会话资格不能交出旧用户的条目。
- draft-catalog：无 React/SDK 的串行协调。目录视图只有标题、时间、共享 RecoveryView 和检查/操作状态；每份发现后释放其 reader。操作时只保留当前一份 DocumentRecovery，副本未知时仅它持有待重试内容。
- features/local-drafts：页面、行、状态文字和存储状态；使用共享能力，不写另一套恢复或删除规则。

## 3. 目录事实与生命周期

当前真实 SessionResponse 的关联许可是唯一资格来源；不从全局最新代次借用。页面切换用户、许可变化或卸载后销毁目录及 reader，迟到异步结果不再进入视图。所有具体存储动作仍由 S2 事务核对许可。元数据请求前后也在同源锁下核对固定许可，防止换人期间把新会话的标题展示到旧页面；暂时读盘失败仍按未知保留。

先列当前用户的主库和镜像，然后批量获取文档事实，逐份调用共享 discover。可访问项的标题来自批量响应；不可访问或请求失败不沿用旧标题，显示“无法确认文档”。批量 unavailable 在执行发现前再单条核对，避免把排队很久的无权事实直接用于自动清理；显式副本、放弃、重试均重新查询当前事实。请求失败对应 access unknown，保留已知条目且说明尚不能检查，不能当作 unavailable。

记录较新、密钥暂时拿不到、会话未知、镜像/主库故障保持待处理。移除、已确认、过期、吊销、损坏由共享判定和原件条件清理完成；页面留下具体处理结果。镜像单独存在或未知时不能声称“没有草稿”或“已全部清理”；已移除主记录而镜像 busy/failed 时说明仍有镜像待处理，墓碑保留，后续由既有比对/维护处理，不以旧 expectedSeq 再删。

焦点回到页面、重新联网、可见性恢复或用户按“重新检查”时刷新。操作、确认和未知副本期间不替换当前恢复实例或观察；通知仅标记有待重新检查。完成后允许继续刷新。没有事件能绕过服务端事实或会话栅栏。

## 4. 逐条动作

- **打开文档恢复**：普通 documentPagePath 链接，不带恢复授权参数。进入编辑器后仍须 P3 的明确恢复/接手点击，目录不申请租约。
- **另存为副本**：调用共享 copy，开始前重查权限与原件。未知结果沿用同一实例的 requestId、标题和 gzip，不启动另一条记录的解密/副本；显示先处理当前副本的说明。成功链接独立保留，清理只使用原观察，changed 保留更新的草稿。副本修订不确认原文档。成功后旧按钮不能直接复制随后出现的新原件，须重新检查；成功链接独立保留。未知请求之后若确认文档已不可读，释放旧内容、停止重发，经共享发现再次核对并条件清理，另保留“此前副本结果仍未知”的元数据说明。
- **放弃**：点击行按钮先重新检查这一条，获得 beginDiscard 的不透明意图后才打开 ConfirmDialog；确认文字含文档名和已观察的本机时间。确认按钮直接提交该意图，不重新观察、不换绑。取消释放；changed 说明其他页已修改，重新选择后才可再确认。当前未知副本的放弃说明其副本结果仍未知。
- **重试**：发现/读取失败重新检查；副本失败重试原流程；条件清理失败只重试当前绑定的目标。较新格式保留并引导更新页面，不能用放弃绕过未知格式保护。
- 进行中按钮留在原位、用 aria-disabled 防重入。未知副本及在途副本离开时明确提示；内部路由和关闭/刷新都覆盖，用户仍可选择离开，原本机草稿不因离开而删除。

## 5. 界面与存储状态

平台账户菜单始终提供“本机草稿”；编辑器没有账户菜单，在原页头提供新标签页入口以保留当前编辑现场；不受 localDrafts 部署开关隐藏。路由 `/local-drafts` 经 RequireSession、AppShell 和 loadChunk 按需加载，入口不引入 SDK 或完整草稿能力。

沿用现有中性主题、列表、按钮、ConfirmDialog、RetryButton、StatusRegion 和页面标题。顶部说明“只包含这台设备、当前账户的修改”，提供重新检查；接着展示存储状态、目录及处理结果。320px 宽下操作换行，长标题省略且可取得全文。空状态仅在目录完整且确无待处理项时显示；失败有独立说明与重试。

持久保存授权、站点已用空间、配额分别显示；缺失/失败为“无法取得”，不是 0。用量是整个站点在浏览器中的用量，不声称是本人草稿大小。申请持久保存调用已有 requestPersistence，显示获准/未获准/不可用，不保证永不丢失。结果变化用常驻 StatusRegion；不抢焦点，行消失或确认关闭后回到稳定的本行结果/列表元素，避免长列表跳回顶部或焦点落到 body。

## 6. 三处标记与边界

空间文档行、与我共享行、搜索结果读取当前用户的 draftDocumentIds；只按需 import 轻量索引，不取密钥、不读取正文、不另发服务端标题/权限请求。用户变化立即丢弃旧集合，旧查询回包不得给新人显示标记。焦点/可见性恢复时重读。索引失败只影响提示，不阻塞正常文档列表。

新增模块没有依赖；完整目录只由路由动态载入。保持平台 180 KiB/2 文件、编辑器 2350 KiB、公式 Worker 800 KiB、草稿 Worker 15 KiB 的原预算。扩展 lint 仅放行按需草稿页及其确认框，其他平台模块仍不许静态引用完整 outbox/local-drafts。

## 7. 验收与自审

1. 契约客户端：101 个 ID 分两批，空列表无请求，缺失/额外/重复结果拒绝；网络失败不撤权，单条动作刷新事实；原上传/重放/副本请求回归。
2. 目录：先比对再列库，镜像独有/失败/空目录、主库失败、不同用户、许可中途失效；串行检查与释放，无正文累积。
3. 动作：确认期间同 seq 不同原件及不同 writer 保留；未知副本同请求同内容，成功后只删原件；取消不删；暂停和晚到回包隔离；mirror pending 真实；较新格式保留。
4. UI：空/加载/失败/状态、独立存储三值、部署关闭入口、行和确认键盘焦点、长列表与 320px、离开未知副本提示；三列表本人标记及异步换人隔离。
5. 三浏览器真实链路：目录打开编辑器明确恢复并唯一保存、副本未知重试与原件变化、放弃/取消/变化、镜像与存储失败、权限/密钥/格式分支、关闭部署既有记录；生产自动保存节奏核心对照。
6. 全部相关单元、类型、lint、生产构建/原预算与故事登记通过。实际运行与原始失败/通过留档；全量 verify、容器、独立 Phase 审查和同 SHA CI 仍归 S6。

自审：需求均落在既定 Phase；没有新增身份继承或批量删除；未知/未完成不误报成功；明文只在当前检查或当前未知副本中借用；外部设计工具未登录，因此直接依据既有组件完成设计，不引入外部服务依赖。
