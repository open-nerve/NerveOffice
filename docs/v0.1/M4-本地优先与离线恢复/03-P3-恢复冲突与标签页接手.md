# M4-P3 恢复、冲突与标签页接手：架构设计与实施规划

> 状态：S1–S4 完成，S5 进行中｜日期：2026-10-11｜基于代码：main `9a6bc3c2`｜唯一分支：`codex/m4-p3-recovery`

## 1. 目标与范围

实现 M4 总设计 §5 的 P3、§6.4 的恢复判定和 §6.3 的本浏览器接手：联网重开后找回最后一次已写本机的修改；确认丢失不重复提交；真冲突不覆盖；同一标签页意外重载在可证明安全时自动恢复；本人接管在 20 秒后接上原标签页未同步的草稿。

覆盖 US-M4-03、04、05、06、14，承接 US-M4-15 的“部署关闭新写后仍可处理既有草稿”，以及 US-M4-10 的打开文档时损坏/吊销/新格式处理。文档列表的标记、本机草稿页、账户级及全站启动清理留在 P4；公式 Worker 的退路留在 P5；虚拟机断电和 Safari 暂停后继续留在 P6。P3 包含真实 Safari 测试页进程崩溃后的恢复验证。

## 2. 现状与 P2 交接

P2 已关闭：`be4a40b9` 经 `--no-ff` 合入 main `9a6bc3c2`；[CI 38101559020](https://github.com/open-nerve/NerveOffice/actions/runs/38101559020) 的六项 job 全部通过，原始报告零失败、重试、flaky、依赖未运行和全局错误。原 P2 分支/worktree 已在证据归档后清理。本 Phase 从该 main 新建，主目录始终保持 main。

- `editing-session.ts` 已拥有租约、本机锁、草稿准备和保存会话。`edit-mode.ts:startEditing` 在申请、拿锁、取服务端内容和 `prepareDraft` 之后才建可编辑实例、启动保存并解除屏障；恢复在这个边界接入。
- `OutboxSession` 当前遇到既有记录返回 `memory(existing-draft)`，保留元数据并关闭宿主。它故意不暴露 `adoptSeq`。P3 增加有明确身份的恢复资格，不能删掉这层保护后直接开始捕获。
- P1 登记交回 `lastDraftSeq` 和既有记录；存储事务以 writeEpoch/writerId 核对资格，写入显式 `adoptSeq` 才能替代外来草稿。序号沿文档的持久高水位继续。
- `WorkingDraft` 是正文唯一来源；引用与 `PreparedDraft` 按对象身份认所有权。保存、副本均固定同一来源中的正文，不长期另存 JSON/gzip。
- 服务端保存的重放先于格式、租约和基准检查，只要求原用户仍可访问、请求与负载相同。租约头允许缺失；未提交的保存仍经过租约校验。申请返回当前修订来源，GET 编辑状态没有来源或租约的 clientInstanceId。
- P1 的持久浏览器目录、精确识别进程与崩溃工具可复用；P2 的生产自动保存模式、连接确认、密钥生命周期和原始报告留证继续保留。

## 3. 设计

### 3.1 模块与依赖方向

| 单元 | 职责与边界 |
|---|---|
| 编辑器功能层 `recovery/` | 恢复判定纯函数、只读发现、一次恢复的编排、旧保存核对、页面提示和动作；不直接操作 SDK 或 IndexedDB 事务 |
| `shared/outbox` | 观察记录身份、原子核对/接手/条件清理；继续统一加密、严格事务、写入者栅栏及 OPFS 镜像；不知道页面文案和服务器业务 |
| `outbox/OutboxSession`、`editing-draft` | 在当前编辑会话内授予一次显式接手，持有及释放宿主/密钥；旧代次不能重新生效 |
| `WorkingDraft` 实现 | 接收被确认的恢复内容所有权，为恢复初值建立合法引用，后续捕获/保存/副本沿现有接口工作 |
| `editor-page`、`edit-mode`、现有页头组件 | 注入用户、文档、网络和会话事实；调用恢复编排，展示状态；控制可编辑实例的屏障，不内嵌判定表 |
| 自动重载身份单元 | 用户/文档隔离的 sessionStorage 记号及不可抢夺的页面实例存活锁；不持久化租约令牌、密钥或正文 |

不新增服务端业务接口或数据库迁移。HTTP 保存的只核对旧请求模式复用原端点；通过真实集成测试固定它的“有回执才成功、不能新增提交”边界。底层仅增加恢复所需的原子能力，不把页面编排塞进 Worker。平台首屏与 Worker 预算不调整。

### 3.2 恢复判定与许可

判定使用类型化事实和表驱动纯函数，不发请求、不读存储、不持有正文。输入包含当前用户的访问结论、连接事实、记录的可读性/格式/保留期、服务端当前修订及来源、旧请求的核对结果。输出明确区分保留等待、重新取钥、需要新页面、核对旧请求、可恢复、已确认、真冲突、副本及条件清理。

| 事实 | 决定 |
|---|---|
| 会话身份未确认、网络未知/离线、取钥或服务端事实未取得 | 保留原件并说明/重试；不能把失败当成不存在、撤权或可以恢复 |
| 当前用户已确认读不到原文档 | 条件清理所观察到的原记录与镜像，说明原因，不给副本；401/会话未知不属于此行 |
| 没有记录 | 使用通常的阅读/进入编辑流程 |
| 超过 14 天 | 当前文档入口不恢复过期记录，条件清理并说明；不扩展成 P4 的全站扫描 |
| 较新记录结构或本页不能理解的数据格式 | 保留，提示需要更新的页面；不解压后试着改写 |
| 本页密钥比记录旧 | 取新密钥重读，绝不当作损坏删除 |
| 密钥已吊销、认证失败且密钥版本相等、记录形状损坏 | 条件清理所观察到的那份，分别说明原因；并发变化时重新发现 |
| 记录就是未满 14 天的在途正文 | 先以原字节和原请求元数据核对；结果未知则保留原件，不能先改序号覆盖重放证据 |
| 原请求已经提交 | 条件确认原记录；重新读取服务器当前内容，不能将较旧回执对应的快照盖到之后的新修订上 |
| 只能阅读且旧请求未确认 | 另存为副本、放弃或保留；不申请写入资格 |
| 当前修订等于基准 | 取得租约、本机锁并登记之后，接手该内容；后续保存以此基准快进 |
| 当前修订恰为基准加 1，来源的 clientInstanceId/localSeq 与记录的在途请求严格一致 | 自己追自己：以当前修订接续最新本机内容；不得只凭同用户、同实例或序号相近认定 |
| 别人在编辑但尚未保存 | 保留提示，允许请求编辑、另存为副本或稍后处理；获准后重新取事实再判定 |
| 其他修订差异或无法证明自己的来源 | 真冲突，只给副本、放弃或保留，不自动上传 |

“可恢复”只是内容判定。真正安装内容还须当前会话、同用户/文档、当前租约、本机锁及存储写入资格均有效。发现与阅读不授予这些许可；所有异步返回和释放/清理动作均受同一次恢复的身份约束。进入过程中失去任一条件立即停写，旧完成事件不能打开新编辑器。

### 3.3 旧请求与正文所有权

1. 只有 `draftSeq === inFlight.localSeq` 且发出未满 14 天才原样重放；沿用原 `requestId`、`clientInstanceId`、`localSeq`、`baseRevision`、gzip、格式与 `formulasPending`。P1 的 `canReplayAsSent` 保持为唯一保留期判定来源。
2. 增加仅核对旧保存的客户端调用，传原 writeEpoch，**不带租约令牌**。因此已提交可重放，未提交不可能借新租约变成新的提交。网络失败/超时仍未知；明确的租约拒绝之后才继续按当前事实判定，不能将任意 4xx 都归成“没提交”。
3. 新捕获已覆盖旧在途正文时绝不套用旧 requestId，只用严格的来源证据判“自己追自己”。拿不准保留并提供副本。
4. 核对阶段保留原压缩字节和元数据，不能先用 `adoptSeq` 将 seq=5 改成 seq=6，破坏原请求身份。旧请求明确结束后才允许显式接手并分配高于持久水位的新序号。
5. 恢复初值交给同一个 WorkingDraft 来源；打开自检通过前保持交互和上传屏障。副本接收该来源的合法引用，使用已有未知结果重试规则。副本成功后只条件删除原观察记录，不能把副本的 revision 确认给原文档。

### 3.4 原子接手与条件清理

S2 在现有存储事务和同源互斥内补齐观察/比较契约：一次观察绑定 userId/documentId、记录身份及当时写入者的身份/高水位；接手要核对当前登记仍属于本恢复会话、原记录仍是已观察的那一份。写入继续要求序号严格大于高水位，保持原加密/AAD和镜像规则。

自动确认、损坏/撤权清理及副本完成后的删除不能只比 `expectedSeq`：另一个页面可能已登记却还没重写同一个 seq，或者同 seq 已经重封。比较必须在事务里与动作一起完成；读不出 seq 的损坏记录也不能退成无条件删除。观察后变为合法新草稿、较新格式、新写入者、不同密文/元数据时，返回 changed/fenced，保留并重新发现。清理不能借“新宿主登记”覆盖这一变化。

Worker 协议同步携带最小的可校验身份；主线程不得伪造已接手的 DraftCaptureRef。宿主失败、清理镜像失败、关闭开关等结果保留实际事实：内容还在则不报已删除，只有内存则不报已保存在本机。部署关闭时仍可按需读出/处理既有记录，后续编辑走内存、不再新写；既有记录仅在云端确认、成功副本或用户明确放弃后条件清除。

### 3.5 页面流程、公式与失败状态

- 打开文档且当前用户身份已确认后按需发现本机记录；阅读模式提示“发现 14:32 未同步的修改”。不在平台首屏预加载恢复实现。
- 手动恢复：取当前编辑权 → 本机锁 → 登记/重新观察 → 核对旧请求和当前内容 → 判定 → 以恢复内容构建尚未接上的编辑器并打开自检/收齐公式 → 通过唯一来源显式接手 → 接上保存 → 解除屏障。每一步都可被会话变化、失锁、退出取消。S3 细化时将采用放在打开自检之后，避免失败的安装改变原件。
- “公式待更新”的恢复强制全量重算，收齐后才做新捕获/上传；旧请求核对仍使用原 pending 标记和原字节。不得把加载后的归零 editorSeq 当成草稿序号，恢复初值本身也要被保存调度识别为未同步。
- 放弃复用现有确认框；失败保留提示和再试入口。副本使用当前权限和原内容，不在无读取权、未知会话、格式不兼容时绕过限制。
- document/content 的 404 可能发生在 EditMode 创建之前：在已确认当前用户的载入失败路径也要处理相应本机记录；换人或身份未知时不处理前一用户的记录。
- P1 的 restored/lost 提示按原事实显示；消费后按提示身份条件清除，旧 UI 不清除新的提示。离线提示“联网之后可以恢复”，不承诺离线冷启动。
- 失败日志只记阶段、错误类别和必要的文档标识；正文、密钥、租约、Cookie 不进入日志。

### 3.6 自动重载与同浏览器接手

自动重载的 sessionStorage 记号按用户/文档隔离，只记原 clientInstanceId、writeEpoch、writerId 等非敏感身份。它本身不构成授权：同时证明是重载/页面回收、原实例存活锁已经释放、记录确由记号中的实例及代次写下，再用原 clientInstanceId 做**普通申请**。服务端在锁下只允许原页自己的租约重试或空闲租约；不能用 fresh clientInstanceId + takeover:self 自动抢走另一个活页。

实例存活锁与可被抢走的文档编辑锁分开，不使用 steal。普通导航、复制标签页、用户/文档不符、格式/身份不明时失效旧记号并改为提示；这样复制标签页后再刷新也不能借继承记号冒充原页。Safari 崩溃重载的导航事实由 S5 真实实验确认，不将 Playwright WebKit 等同 Safari。

申请成功后仍按 §3.2 重判，只有直接快进或严格“自己追自己”才自动恢复，说明“已恢复 14:32 未同步的修改”；其他情况保持阅读与明确操作。主动退出编辑、放弃和切换账户清除对应记号，崩溃/刷新保留用于核对的记号，不改变 M3 pending-save/edit-request 的 P4 归属。

本人接管沿用 M3 的 20 秒总时限和服务端优先裁决。正常交出先同步；到期由新标签页申请、抢锁、登记后重新读回原草稿，走同一恢复编排。旧标签页先停发件箱写入，确认被取代后只读；在途写入由代次与写入者栅栏拦下。P3 关闭 DEF-064 的条件是此路径真正接上未同步正文，而非只展示副本按钮。

## 5. 约束符合性自审

- [x] 00 号计划书 §7.5–7.8：先获许可，待决定只读；保持原请求与正文；读不到不给副本；联网取钥、14 天、加密与丢失边界不变。

- [x] 工程规范：功能层编排、适配层封装 SDK、无跨服务私有依赖/新依赖，维持平台 180 KiB/2 文件和 Worker 15 KiB；门槛不延期。
- [x] 自审发现并在正文补齐：原样重放前改序号会丢证据；复制标签页后再刷新；无租约重放的真实 HTTP 反例；副本 revision 误确认原件；同 seq/新登记者清理竞态；部署关闭仍须处理原记录；过期/撤权/格式判断优先级。
