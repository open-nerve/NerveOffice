## 与设计的偏差

- 没有新增数据库迁移，不改服务端保存和租约协议。会话响应加 `features.localDraftsEnabled`，配置 `NERVE_LOCAL_DRAFTS_ENABLED` 默认 true，只接受 true/false；关闭新写仍保留已有记录。
- 持久去重可能复用较早正文，因此除了 `editorSeq` 与 `draftSeq`，还明确 `contentSeq`；上传与确认按实际正文的序号处理，不能拿编辑器重建后归零的计数删草稿。
- 审查发现“正文已落盘”不能代表“同步元数据可靠”。WorkingDraftView 的 `metadataIssue` 独立说明 mark/confirm 限制，不抹掉正文事实；确认 A 的未知删除与较新 B 的保护分开。已回写 S3 spec、ADR-011 和页头契约。
- 受控连接复核与真正上传的许可分开：普通探测/旧心跳成功不能发新正文；会话恢复先等旧单飞结束，再取得当前代次的新许可。发送前仍核对本机锁、会话、浏览器信号与保存归属。
- 旧 M3 浏览器用例按已批准的 P2 文案与换钥语义更新。失锁后以真实续租裁决作同步点，换钥故事按生产节奏自动同步；没有降低质量阈值、增加重试或跳过失败故事。

## 下一个 Phase 须知

1. **恢复边界**：P2 遇已有别页草稿或更新格式记录会保留它、走内存退路，不自动 adoptSeq。重新打开恢复、真冲突判定、本人接管接续、自动恢复属于 P3；草稿列表和全局清理属于 P4；公式 Worker 退路属于 P5。US-M4-01/02/11 已登记 active，跨 Phase 的 10/15 仍 planned。
2. **内容归属**：`working-draft.ts` 的引用依赖创建它的来源和对象身份，复制字段不构成合法引用。`prepare` 固定这一份 gzip、格式、基准和实际 contentSeq；unknown 必须保留它，不能用新捕获套旧 requestId。结束这次请求才 release。`lost-copy-flow.ts` 接收同一来源，不能再建另一份长期 JSON 缓存。
3. **恢复与写入栅栏**：沿用 P1 的登记、高水位、writerId、短期互斥、AAD 与镜像保护。先恢复/核对，再登记；不能仅凭 writeEpoch 数值大就抢写。真实心跳恢复本机锁后才恢复草稿资格；旧会话的异步结果不能复活新会话的资源。恢复入口应沿 `editing-session.ts` 的生命周期接线。
4. **密钥和关闭开关**：阅读/关闭新写时不为新保存主动取钥；恢复既有记录仍需要按用户与版本按需取钥。高版本记录对应 stale-key，不能当损坏删除。退出/换人同步停用旧钥与写入资格，不删除旧内容。Worker 创建失败可退进程内，但没有同步 OPFS 冗余，必须如实展示。
5. **本机事实**：已写本机也保留尚未云端确认的离开提示。捕获覆盖只到对应 editorSeq；未提交输入与较新的修改不能借用旧 saved。mark/confirm 的元数据故障另报，不把仍在盘上的正文说成纯内存；云端已确认但本机删除未知也不能声称记录已清除。
6. **验证与归档**：完整门禁使用独立 `codex-nerve-m4-p1` 测试 PostgreSQL，`pnpm verify --ci` 默认全量 scope、不设置 CI 环境变量；不操作用户数据库或真实 Safari。浏览器用例默认暂停定时上传，要求生产自动同步的故事显式 `autosave: running`。崩溃工具仍沿 P1；最终 16 项既有跳过为 3 项 WebKit CDP 能力限制、13 项崩溃用例的平台限定，逐项见审查报告。真实 WebKit OPFS 写满尚未实测。平台入口 177.3/180 KiB、发件箱 Worker 13.3/15 KiB，P3 增量须继续守住预算。
