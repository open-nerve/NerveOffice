## 与设计的偏差

都已回写 P1 设计（§1 的偏差 1–9、各节与 §9 变更记录）、ADR-020、M4 总设计（§6.1 等就地改，§9）与计划书 r22：

- **崩溃工具从 P3 提前到 P1**（偏差 1）：P1 的验收要"写入中途结束进程时的原子性"，P3 沿用这套工具。
- **写入者不存租约令牌、在途请求只记四项、高水位在写入者记录里、存储层不覆盖别的写入者的草稿**（偏差 2–5）。
- **M0 的写入耗时、`strict` 的开销与写满是在不落盘的上下文里测的**（偏差 7）：在持久上下文与真实 Safari 上重测，磁盘上同一量级（Safari 约 5 MiB 的写入 p95 8 ms，strict 多约 1 ms），计划书 §7.5、§7.6、§12.2 已订正。
- **加了 OPFS 的冗余**（偏差 9，需求方 2026-10-09 决定）：S7 查出 Chromium（含 Google Chrome）崩溃重开时可能删掉整个来源的 IndexedDB（UR-034）。三个浏览器都用 Worker 放置（DEF-011 的定论），进程内放置没有镜像。
- **审查之后**：清理删不掉镜像目录时立墓碑；写回按库里写入者的高水位与代次判（不按代次比先后）；解不开多一种 `stale-key`；槽位核对是这份文档的；保留期只回收超过 14 天没动过的镜像目录；比对一份一份地来、拆成 `draft-recovery.ts`；本机草稿页列出之前先比对；Worker 一侧由 lint 界定（`OUTBOX_WORKER_SIDE`、`OUTBOX_MAIN_THREAD_ONLY`，不许用页面里才有的全局）。
- **接手续修**：登记前的恢复失败就不登记；新版槽位保护整个镜像；恢复候选自己的旧草稿时保持当前写入者与高水位，unseen 保留双方并留一次 lost，平台只读恢复不留 lost。按用户清理先在同一 strict 事务中为三个仓库的文档键并集立墓碑，之后才动镜像。
- **并发边界**：所有完整文档任务、平台单份恢复与清理共用短期 Web Lock `nerve-office-outbox-operation`，避免恢复与登记、主库提交与镜像写入被清理穿插。长期 OPFS 句柄不持锁；无锁或等待 10 秒仍未开始时明确失败，已经开始的操作直到真实结束才释放。进程内退路不写镜像，但默认先做只读恢复。

## 下一个 Phase 须知

**P2（接入保存管道）**：

- **接口**：编辑器页只依赖 `DraftWriter`（`shared/outbox/draft-writer.ts`）；生产的放置是发件箱 Worker（`createOutboxWorker()`，`features/sheet-editor/outbox/`）。审查之后的接口：`mirroredDocuments(userId)` + `reconcile(key)`（一份一份地比对，原来的 `reconcile(userId)` 拆开了）；存储的 `removeUserData(userId, { retire, now })`、`retireUser(userId, { now })`、`retireWriter`、`listTombstones`、`dropTombstones`。
- **序号与登记**：序号在 `save()` 的同步段里从登记交回的高水位往上分配；同一个写入者不对不同的内容重用序号（重试只重发同一次捕获，存储认"同一写入者、同一序号"为 `duplicate`，看不出内容，审查 A16）。取得编辑权并拿到本机锁之后登记写入者；`superseded`（含同一代的另一次登记、墓碑）与 `not-writer` 经服务端核对处理：确实是当前的一代就 `force` 重新登记，否则转只读。墓碑出现在：本机草稿页放弃了这份、退出登录或账户停用时清理删不掉镜像目录、保留期里登记超过 14 天又没有草稿的写入者——前两种情况下那一页之后的写入都是 `not-writer`，要经服务端核对（会话已失效时不再登记）。
- **恢复与短期锁**：不要直接调用 store/mirror 绕过 `DraftWriter`、`pageReconciliation` 与 `createLocalCleanup` 的互斥。M3 编辑权锁的退化策略不意味着发件箱可以无锁运行；Web Locks 不可用时转内存保存模式并如实提示，不能声称已保存在本机。Worker 起不来时沿用默认工厂的只读恢复，不注入空恢复替代它。`newer-format` 镜像状态表示旧页面读不懂，不能删除。
- **上传与在途**：上传发出之前先等 `markInFlight` 落盘；重封、改基准、换密钥的结果里没有镜像的状态（审查 A14），页头的"已保存在本机"以写入的结果为准，镜像没写成时下一次写入或登记的补写会追上。
- **写满**：存储层如实交回 `quota`，Chromium 写满之后用量要过一阵才降下来；页头一直说"本机存储空间不足"，每次捕获照常再试，节奏由 P2 定（不重试成风暴）。
- **本机密钥**：编辑器页的生产代码引用 `local-key.ts` 时，再核对一次两份入口的静态闭包（测试构建与生产构建）；取用途中收到心跳的新版本时不记下（审查 A15），可以接心跳时顺手处理（之后的 `setKey` 会重封，影响小）。解不开的 `stale-key`：本页的密钥过时，去取新密钥再试，绝不删草稿。
- **体积**：本轮最终测试构建的发件箱 Worker 为 45,710 字节，按体积门禁同口径的 Node 默认 gzip 为 13,591 字节（13.27 KiB）；P2 接入生产构建时登记约 15 KiB 预算，并复测其静态闭包。独立报告的 gzip -9 数字压缩参数不同，不混用。
- **放置的退路**：Worker 起不来时退到进程内就没有 OPFS 镜像（同步访问句柄只在专用 Worker 里有），Chromium 系上少了防 UR-034 删库的那一层，要在页头或上报里如实体现。
- **lint**：`shared/outbox` 里新加的文件默认算 Worker 一侧（只许引用 Worker 一侧与不带 zod 的契约常量、不许用页面里才有的全局）；只在主线程用的模块要列进 `eslint.config.ts` 的 `OUTBOX_MAIN_THREAD_ONLY`。

**P3（恢复）**：

- 判定读 `ReadDraft`、`DraftRead` 与 `canReplayAsSent`；读草稿只交回最新的那一个版本（解不开如实交回原因，不退回更旧的）；接手别的写入者留下的草稿用 `adoptSeq`；原样重放成功之后用 `removeDraft(key, expectedSeq)` 删；判定表同样核对"在途的序号不大于草稿序号"。
- 写回的规则（ADR-020"读与恢复"）里 `keep` 的那一种会把镜像里的草稿写回成"别人留下的草稿"、不动写入者——P3 的判定按"别的写入者的草稿"处理（给副本）。
- 打开文档时读出恢复的提示（`restored`、`lost`），如实告诉用户，看过之后清除（清除带上读出的时刻）。
- 崩溃用例沿用 `tests/e2e/support/browser-crash.ts`：持久上下文的资料目录一律经 `persistent-profile.ts` 的 `profileDirFor`（只有 ASCII，Linux 上 WebKit 遇到非 ASCII 的路径起不来）；macOS 上 `crash-webkit` 要求机器上只有一个 Playwright WebKit。

**P4（本机草稿页与清理）**：

- 本机草稿页列出与清理之前先比对：`reconcileAll(pageReconciliation({ store, directory, now }), userId)` → `listDrafts` → 合一的清理 `createLocalCleanup`（平台页面里只读镜像、只写回，不截断、不补写、不留 `lost`）。
- 退出登录、账户停用、放弃与保留期都经合一的清理；按用户清理交回 `pending` 之后的重试只在这个人仍是退出的时候做；放弃的 `pending` 不必重试（墓碑挡住复活）；保留期的结果带 `mirror: done | failed`，库那一段删了的照样说明。
- 保留期清理每次读出所有草稿的完整值（几 MiB 的密文，只为看 `updatedAt`，审查 A12）：平台的任何页面启动时都跑的话要节流（例如一台设备一天一次），或者以后加 `updatedAt` 的索引（只做加法的升级）。
- 保留期按墙上时间：设备时钟曾慢、校正之后刚写下的草稿可能被删（固有的限制，ADR-020）。
- 列表的标记只引用 `draft-index.ts`，并且按需加载（平台首屏的余量约 4 KiB）。

**CI 与测试**：

- CI 的 Linux Google Chrome 与 Edge 从没在本机跑过崩溃项目（arm64 没有这两个）：合并之后第一次 CI 重点看 chrome、msedge 两片的 `crash-*` 附件 `crash-tool.json`（认出的角色、via、late、notes）。
- 崩溃用例依赖 UR-034 的前提（Chromium 的 IndexedDB 是复用日志的 LevelDB）：CI 装的是当时最新的稳定版，前提哪天不在了，失败说明以"UR-034 的前提不在了"开头，到时的处理写在 `specs/crash/indexeddb-*.spec.ts` 的文件开头（换了后端：先在新后端上重查崩溃之后会不会丢库；缺陷修好了：用最小复现确认版本，改用删库的接口造出"库没了"，OPFS 的冗余留不留由需求方定）。
- 测量：`measure:probe` 每个浏览器约 9 分钟，`-g 冷热` 约 3 分钟；Playwright 一给页面装路由就关掉 HTTP 缓存，量冷热不要用 `page.route` 收结果（`support/selftest-collector.ts`）。
- 旧格式测试库只有在能证明属于本项目、本主机且已无使用者时才能清理；本轮验证使用独立 PostgreSQL 容器，没有操作共用开发库。新命名按主机标识，不凭名称猜测旧库归属。
