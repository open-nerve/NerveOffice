## 与设计的偏差

原 S4 使用 reload/sessionStorage/实例锁组合自动继承身份。真实 Safari 原页崩溃可报 navigate，延迟副本也可形成相同身份输入，原假设被否定。用户批准方案 1，计划书 r23 已调整：保持纯网页，新 Document 使用新身份，自动发现后先阅读，由用户明确恢复或接手。崩溃后的正文质量、权限与租约、冲突、唯一修订及真实 Safari 质量门槛保留；旧失败和副本反例不改写为自动身份通过。

其他细化：恢复动作须比较完整原件和写入者，不能只比 expectedSeq；一次点击在异步等待前绑定来源，不能因磁盘已有另一份记录便采纳它；旧保存未知时保留原件并明确重查，不增加隐式重试。已同步 ADR-011/018/020 和 Phase 设计，没有新增后端接口、数据迁移、依赖或资源预算。

## 下一个 Phase 须知

1. **恢复接口与边界**：`DraftWriter.observe/adopt/removeObserved` 和存储 `observeDraft/adoptObserved/removeObserved` 是共享原子能力。观察凭证绑定存储实例、完整原件和写入者；后续平台功能不能只认 seq 或跳过墓碑/镜像清理，也不能跨功能层直接引用 sheet-editor。
2. **未知与缺失分开**：见过记录而读盘/镜像/密钥失败仍保留 recordKnown；不能按空草稿继续编辑。新密钥版本先重新取钥，较新格式保留；读不到原文档清理且不给副本，会话/网络未知不当成撤权。
3. **旧保存**：只有记录仍是原在途正文且未过保留期才原样、无租约核对。成功重读当前云端，未知保持原件；新正文不能套旧 requestId。副本成功只条件清理原观察，不用副本 revision 确认原文档。
4. **页面身份**：新 Document 一律新实例，旧 reload/edit-request 存储不再授权；pending-save 仍保留原职责。活页内存请求意图、已有明确 20 秒接手和 `?edit=new` 新建例外继续有效。不要重新引入可复制页面信号的自动授权。
5. **部署关闭**：关闭新的本机写入后仍须允许处理既有记录；可使用内存来源恢复并上传。新列表/清理入口必须按当前用户、权限与联网事实处理，不能以开关关闭为由隐藏旧草稿。
