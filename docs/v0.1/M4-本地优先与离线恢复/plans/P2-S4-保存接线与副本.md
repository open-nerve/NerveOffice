# P2-S4 保存接线与副本：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans 在当前会话逐任务实施；步骤用复选框追踪。

**Goal:** 自动捕获、云端保存与失效副本共用一个 WorkingDraft，完成真实本地优先保存。

**Architecture:** 调度只管时机和引用；保存协调拥有单份上传及云端事实；编辑会话准备并管理来源、密钥与写入资格；副本在原保存结束后接收来源。复用 S3/P1，不在这些调用方复制存储或压缩逻辑。

**Tech Stack:** TypeScript、Vitest、Playwright、实际 Worker/IndexedDB/PostgreSQL；无新依赖。

**Spec:** `../specs/P2-S4-保存接线与未知请求.md`、`../specs/P2-S3-工作草稿与宿主准备.md`、Phase §3.2–3.5。

## Global Constraints

- 主目录 main 不动，使用当前 worktree；中文提交，无 AI 署名，Phase 合并后才推 main。
- 正常捕获只编码一次；调度/协调/副本不长期留 JSON；最多一份固定上传。unknown 先原样核对，不能用新正文配旧 requestId。
- editorSeq 只用于本页云端确认；上传 localSeq 用实际 contentSeq。捕获失败不回收 draftSeq；显式保存不去重。
- Worker 看门狗 15 秒，保存/副本 HTTP 60 秒、租约/取钥 10 秒；不增加无限重试。现有捕获、公式与输入提交常量不变。
- 栅栏不能绕过；锁被抢同步停持久动作，force 之前服务端 current；租约代次变化使旧宿主失效。
- 部署关闭不取钥/持久写入，已有草稿不覆盖、不自动 adopt。P3/P4 恢复/清理和 S5 文案不提前混入。
- 无源代码修改与门禁并跑；每任务先红后绿，独立审查问题修复复验，整步三浏览器与生产预算。

## Review Focus

- 重放旧 unknown 时新捕获不断到来：重放原字节，随后取最新引用，不把旧成功说成新编辑已保存（任务 1）。
- 本机确认回包失败或晚于租约续上的 ownRevision：云端事实不能回退，下一次准备等本机收尾，正文仍归来源（任务 1）。
- 准备/取钥期间租约 writeEpoch 改变或退出登录：旧宿主不再写，旧钥不能发布回新代次（任务 2）。
- 锁被抢、核对 unknown、后台继续编辑：本机资格同步暂停，内存内容保留，旧续租的晚到成功不能恢复（任务 2）。
- 失效后原重放仍在途、副本被点或只读重建失败：单份上传只有一个所有者，副本成功链接不丢、晚到原结果不污染副本（任务 3）。

## 任务 1：捕获与云端保存改用引用

**Files:** 修改 `snapshot-capture.ts`、`autosave.ts`、`save-coordinator.ts`、`editor-api.ts`、`client-format.ts`；`editing-session.ts` 先用单一内存来源接入。相应测试及 `snapshot-capture.test-support.ts` 更新；新增 `working-draft.test-support.ts`（只模拟异步边界）和 `save-working-draft.test.ts`（真实两种来源整合）。目录均为 `apps/web/src/features/sheet-editor/`。

**Interfaces:** `takeSnapshot(editor, draft, { formulasPending, dedupe }): DraftCaptureRef`；`captureSettled<T>` 去掉旧 SnapshotCapture 限制。`PreparedCapture = DraftCaptureRef | 'cell-editing' | 'session'`，CaptureSource 仍可同步/异步。AutosaveOptions 的 digest 改为 draft；SlotCapture 只存 ref，事件 seq 仍为 editorSeq。SaveCoordinatorOptions 的 compress 改为 draft，增加可选 now（默认 Date.now）和 onDraftResult（只含 DraftMutation）。SaveRequest 去掉 snapshot，增加 ContentFormat；clientFormatParams 可接冻结格式，默认仍为 PAGE_CLIENT_FORMAT。SaveView 原云端字段保留；本机修改结果经 onDraftResult 交给会话。

## 任务 2：进入编辑时准备持久来源与生命周期

**Files:** 新建 `editing-draft.ts`、`editing-draft.test.ts`；修改 `editing-session.ts`、`edit-mode.ts`、`editor-page.ts`、`start.tsx`、`edit-lease.ts`、`local-lock.ts`、`outbox/outbox-session.ts` 及各自测试。复用 S3 工厂和 LocalKeyKeeper。

**Interfaces:** `EditingDraft extends WorkingDraft`，增加 `suspend():void`、`resume():Promise<void>`、`observeVersion(version:number|null):void`、`discardKey():void`。`prepareEditingDraft(options)` 同步给出可销毁的准备句柄，ready 交 EditingDraft 或 lost/disposed；参数包括 enabled、user/document、sessionId、format、baseRevision、writeEpoch getter、keeper/host 可注入测试接缝、confirm、still、reportError。EditingSession 增加 `prepareDraft(initial):Promise<...>`、只读 draft、`takeDraft():EditingDraft|undefined`；唯一转交后会话不再 dispose 它。OutboxSession 的 writeEpoch 支持 getter，并在每次准备/写入检查当前代次。LocalLock 增加可选 `onHeldChange(held:boolean)`，丢锁先通知；EditLease 新增有效心跳版本回调，不改变旧 onRenewed 的时刻语义。

- [ ] 失败测试：服务端/锁/来源/编辑器的准备顺序；能力关闭零取钥；ready 前 dispose、退出或换人不建保存；打开自检失败释放来源。
- [ ] 失败测试：准备中 epoch 3→4 丢弃旧登记；已有宿主 epoch 不符停写，恢复用新代次并保持高水位；锁被抢先 suspend 再 confirm，unknown 不恢复，旧续租回包无效。

## 任务 3：失效副本接收原内容来源

**Files:** `lost-copy.ts`、`lost-copy-flow.ts`、`edit-mode.ts`、`editing-session.ts`、`editor-api.ts` 与对应测试；清理 start/page 中剩余主线程 compress/digest 注入（若其他用途仍需要则只删保存路径）。

**Interfaces:** LostContent 改为 `{ ref:DraftCaptureRef|undefined, formulasPending, inputLeft }`，captureLostContent 接收 draft。LostCopyOptions 用 draft/ref 取代 snapshot/compress；副本请求类型包含冻结的 format。LostCopy/Flow 增加 dispose，释放其 pin 和拥有的来源。协调器 dispose 终结原重试并释放 pin，仍可读取已完成的云端元数据；不得在其 HTTP 未完成时把来源转交。

- [ ] 写失败测试：原来源捕获后转只读，副本 gzip 与最新捕获相同；等待原 HTTP 与一次 unknown 核对结束才转交；unknown 副本重试原 requestId/标题/format/gzip；明确拒绝后换标识。
- [ ] 写失败测试：原旧确认到来不能覆盖新失效捕获；输入未提交继续提示；只读重建失败仍能复制/另存，副本成功而页面重载失败保留成功链接；放弃/重载/卸载只 dispose 一次。
- [ ] 运行红灯后实现所有权转交。readLatest 文本仅作为重建调用的临时变量，不在 lostCopy、mode 或事件长期保存。新文档修订不得 confirm 原文档。
- [ ] 原副本/失效/会话回归、来源整合、完整前端、类型/lint；撤所有权等待或字节固定应失败。独立审查并提交。
