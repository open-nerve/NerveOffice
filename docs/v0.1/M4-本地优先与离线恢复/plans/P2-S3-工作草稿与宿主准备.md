# P2-S3 工作草稿与宿主准备：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans 在当前会话逐任务实施；步骤用复选框追踪。

**Goal:** 交付部署能力与两种内容来源契约，使 S4 能以同一接口接入本地优先保存。

**Architecture:** 服务端统一返回会话能力；keeper 管密钥时序，宿主管 Worker 放置，会话准备器管写入资格，工作草稿管内容所有权。继续使用 P1 的 DraftWriter 与互斥，页面和保存调度接线留 S4。

**Tech Stack:** TypeScript、Zod、NestJS、Vitest、真实 PostgreSQL、Playwright Worker/IDB；不新增依赖。

**Spec:** `../specs/P2-S3-工作草稿与宿主准备.md`，以及 Phase 设计 §3.2–3.5、3.8。

## Global Constraints

- 主目录 main 不动，使用现有 `codex/m4-p2-local-first` worktree；中文提交，只在 Phase 合并后推 main。
- `NERVE_LOCAL_DRAFTS_ENABLED` 默认 true，只认 true/false；旧会话响应缺 features 时关闭，坏字段不容错开启。
- 宿主看门狗 15,000 ms；沿用锁等待 10,000 ms、IDB 升级等待 3,000 ms、Worker 空定时器 100 ms、取钥 10,000 ms。
- 正常捕获只编码一次，持久写成后主线程不长期留正文；内存只留最新内容和至多一份固定上传。
- 高水位同步分配，失败不回收；unchanged 使用原内容序号，不伪造新记录；旧确认不删除新内容。
- 不自动 adopt/恢复/删已有草稿；Web Locks 不可用不持久化；进程内退路使用 P1 默认恢复。
- suspend/dispose 同步停止新持久操作；force 必须先确认服务端仍 current；未知结果保留。

## Review Focus

- 老后端未返回 capability、字段类型错误及新会话入口漏字段，不能误开启持久化（任务 1）。
- 新版本先于旧密钥响应、连续旧响应、discard 后旧 ensure 的清理，不能发布旧钥或解除新 pending（任务 2）。
- 初始化失败与运行中崩溃不能混为一谈；暂停/销毁期间晚到登记不能启用写入（任务 3）。
- 高水位分配后 unchanged 与上传序号、已确认记录已删除，不能标记不存在的序号或读错内容（任务 4）。
- 本机写慢时排队、保留上传后继续捕获、确认/换钥交错，不能无限积累正文或丢当前内容（任务 4、5）。
