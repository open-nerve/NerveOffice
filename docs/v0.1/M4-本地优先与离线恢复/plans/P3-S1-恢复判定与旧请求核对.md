# P3-S1 恢复判定与旧请求核对：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans，在唯一 P3 worktree 内逐任务实施，不另开分支。

**Goal:** 固定恢复判定表和只能取旧回执的原样请求契约，为后续接手提供可测试的事实，尚不接页面。

**Architecture:** 功能层纯函数接收元数据、访问/网络/服务器和重放事实；正文不进入判定。客户端保存传输复用现有序列化，以独立方法明确省略租约头。服务端行为保持现有协议，以真实 HTTP/数据库核对不会产生新提交。

**Tech Stack:** TypeScript、Vitest、真实 PostgreSQL 与现有 API 测试应用；不新增依赖。

**Spec:** `../03-P3-恢复冲突与标签页接手.md` §3.2、3.3；M4 总设计 §6.4；代码基线 `1dced65a`。

## 全局约束

- 主目录停在 main；本 Step 在 `.codex/worktress/codex/m4-p3-recovery`，开发分支不推远端。
- `canReplayAsSent` 复用 P1：记录序号必须等于在途 localSeq，发出未满 14 天。原 requestId、clientInstanceId、localSeq、baseRevision、gzip、格式和 formulasPending 不改。
- 只能在许可齐全后安装恢复内容；本 Step 的 `restore` 是内容判定，不授予租约、锁或存储写入资格。
- 原记录已由存储形状守卫读取；当前 key 是已确认的用户/文档。外来 key、未知会话/网络、未知服务器来源不自动恢复或删除。
- 当前用户仍可访问时，数据格式/旧钥不明保留；本 Step 仅对成功解开的兼容草稿判断过期，绝不将 stale-key/新格式借过期分支删除。已确认读不到原文档则按总设计条件清理；外来用户/文档身份始终先拦下。P4 全站保留期另行实现。

- 任一本地检查运行期间不编辑源码/测试/文档或提交；按红灯 → 实现 → 绿灯推进，完成 Step 后中文详细提交。

## 审查重点

1. 旧回执迟到后草稿已换成另一请求：重放结论必须匹配当前 inFlight.requestId，较新正文不能借旧确认删除（Task 1）。
2. 当前修订恰好加 1 但只匹配实例或只匹配序号：均是真冲突；来源未知须先取完整事实（Task 1）。
3. 外来用户/文档的元数据不能借撤权分支删除；当前用户/文档仍可访问时，新格式和旧钥不能借保留期分支删除；已确认读不到原文档则优先条件清理（Task 1）。
4. 无租约核对发生在自己仍持有或已经新申请的租约期间：仍不可创建新修订/回执/审计，不能悄悄套用新令牌（Task 2）。
5. 回执属于旧修订但服务器已经有更新内容，或用户已经只能读/读不到：分别重放原结果、按现权限拒绝；新内容不变，副本或编辑留后续流程（Task 2）。

## Task 1：元数据判定表与原请求描述

**Files:** 新增 `apps/web/src/features/sheet-editor/recovery/recovery-decision.ts` 及相邻测试；复用 `shared/outbox/writer-fence.ts`、`draft-record.ts`、`draft-writer.ts` 和 contracts 的版本比较，不修改它们。

**Interfaces:**

- `RecoveryRecord`：`DraftRead` 的所有非正文结果，以及 `{ kind: 'draft', meta: DraftMeta }`；不带 gzip。
- `RecoveryServer`：`{ revision: number, source: RevisionSource | null | undefined, occupied: boolean }`。undefined 表示尚未取得来源，null 是服务端明确没有可归属给本人的来源。
- `ReplayFact`：`{ kind: 'unchecked' }`，或带 `requestId` 的 `unconfirmed` / `unknown` / `confirmed`（后者含 `revision`）。unconfirmed 只允许调用方在本次无租约核对得到明确租约拒绝后提供，不能把网络错误或任意 4xx 放进去。
- `RecoveryFacts`：`key`、`record`、`access: 'unknown' | 'unreadable' | 'read-only' | 'editable'`、`online: boolean`、`current: RecoveryServer | undefined`、`pageFormat: ContentFormat`、`replay: ReplayFact`、`now: number`。
- `DraftReplayRequest`：`{ request: SaveRequest, writeEpoch: number }`；`draftReplayRequest(meta: DraftMeta, now: number): DraftReplayRequest | undefined` 只按原元数据生成。
- `decideDraftRecovery(facts: RecoveryFacts): RecoveryDecision`：none；preserve（session/offline/storage/key/identity/newer-format/replay/server）；refresh-key；remove（unreadable/expired/revoked/corrupted/malformed）；replay（请求描述）；confirmed（revision）；copy（read-only/conflict）；held；restore（baseRevision、formulasPending、fast-forward/own-revision）。每个决定保留区别，不能布尔化。
