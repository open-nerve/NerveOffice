# P3-S2 草稿接手与条件清理：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans，在唯一 P3 worktree 内逐任务实施，不另开分支。

**Goal:** 以完整观察凭证原子接手/清理记录，守住旧页面迟到动作与新写入者之间的边界，为 S3 提供带会话资格的恢复初值。

**Architecture:** shared/outbox 负责观察、事务比较与密文写入；DraftWriter 串行化并维护镜像，Worker 只传最小凭证；OutboxSession 守编辑资格；WorkingDraft 独占初值正文。页面编排留 S3。

**Tech Stack:** TypeScript、Vitest、现有 Playwright 三浏览器/真实 IndexedDB 与 Worker；不增加依赖或数据库版本。

**Spec:** `../specs/P3-S2-原子观察接手与条件清理.md`，基线 `03f32de1`。

## 约束与审查重点

- 一 Phase 一分支/worktree；主目录 main 不动。只使用独立测试库 53522，不设置 CI，不碰用户数据库与 Safari。
- 每项先写失败断言，再实现和复验；检查运行期间不编辑源码/测试/文档，不提交。失败原日志保留。
- 重点：同序号重封与仅登记的交错；损坏结构没有 seq 也不能无条件删；删除/墓碑必须同事务；凭证不能跨宿主/代次/密钥使用；关闭开关仍可处理旧记录；恢复初值的唯一所有权和序号不归零。

## 自审

本计划没有提前安装页面内容、重放请求或变更保存调度。存储凭证解决“观察后变了没有”，会话资格解决“这次恢复还能不能写”，两层均不可省。镜像清理失败与主库已删除是并存事实；高水位/墓碑保留，不能把旧镜像重新装回去。测试覆盖真实事务接线及反向交错，不只复述函数实现。
