# P4-S2 共享恢复与清理资格实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans 在唯一 P4 worktree 内联执行；沿用用户自主推进授权，Step 完整验证后一次中文提交。

**Goal:** 草稿页与编辑器共用 P3 恢复能力，并以持久会话代次阻止清理后的旧写入和新登录后的旧清理。

**Architecture:** 提取无 SDK 的恢复/副本/来源与宿主；纯状态规则 + IDB v2 单条会话状态 + 同源互斥；真实会话请求用前置票据绑定本机资格，宿主固定资格，存储事务再次核对。清理仍复用完整原件观察及原有墓碑/镜像顺序。

**Tech Stack:** TypeScript、Web Crypto、IndexedDB、Web Locks、Worker、Vitest、Playwright；不新增依赖。

**Spec:** `../specs/P4-S2-共享恢复与清理资格.md`

## Global Constraints

- 主目录 main 不动；仅在 codex/m4-p4-drafts-cleanup 工作区；不拆 Task 分支，不提前合并/推送。
- 原恢复判定、原样重放、固定副本 requestId、未知结果保留及完整原件条件删除不变。
- 无资格不得自动借用最新会话；旧检查不得重新取票据包装旧响应；清理状态不得被旧来源重新激活。
- 状态比较和数据操作同一 IDB strict 事务；主库/镜像/状态转移共用既有锁；网络和摘要计算不持锁，不重入锁。
- 会话状态只存来源摘要和必要元数据；不落盘 Cookie、CSRF 原值、密钥、正文。
- S2 绑定资格，S3/S4 才增加页面、退出/停用删除触发。数据库失败不能假称已清空或已退出。
- 浏览器测试串行；测试期间不改源码；仅使用 53522 专用数据库，原预算/门禁不变。原件保存至外部冻结。

## Review Focus

1. 同一人不同会话、旧 GET 与旧登录回包：票据是否在网络前固定，是否会借最新代次复活旧来源。
2. 清理之后才创建宿主/才 force 登记的旧页面：不能只阻止已有写入者，所有宿主和事务入口均要有来源资格。
3. 新登录与 pending 清理的两种顺序：库和 OPFS 不得出现“资格已过时但仍删了新数据”的空隙。
4. 原件被同序号不同内容/写入者替换，以及未知副本结果：不能删替换后的记录、换 requestId 或丢掉成功副本事实。
5. 存储不可用、旧连接、升级和删库后的 ABA：不能默认 active，不能让网络认证和退出依赖本机清理成功。
6. 提取后的模块图和产物：共享层不得依赖 SDK/feature，Worker 不带页面 API/Zod；不靠抬预算或削弱 lint 放行。
