# P5-S3 页面受控重建：实施计划

> 状态：已完成｜日期：2026-10-16｜所属：M4-P5
> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `superpowers:executing-plans`，在当前唯一 Phase 工作区逐任务实施。

**Goal:** Worker 故障后保留输入和保存会话，经原槽位切换主线程；新模型通过自检、代次与权限检查才接纳。

**Architecture:** formula-fallback 保存本页执行偏好并包装创建；formula-recovery 组织运行期重建；editor-slot 仍唯一拥有实例；EditingSession/S2 仍唯一拥有保存与草稿。页面传当前资格并统一屏障/动作入口。

**Tech Stack:** TypeScript、Vitest、现有编辑器/保存/时钟/页面模块，零新依赖。

**Spec:** `../specs/P5-S3-页面受控重建.md`，R1–R6。

## Global Constraints

- 基线 `230f3907`；唯一 `codex/m4-p5-formula-fallback`，主目录 main 不动。
- 不改变 HTTP、跨页消息、快照格式、草稿来源、编辑权规则或 SDK 版本。
- 组合输入结束之后再加完整屏障；输入准备结束和完整快照在旧实例销毁之前。
- 不等待网络保存来启动恢复；旧请求按原字节收尾。
- 新实例自检与原代次/权限都通过才绑定；旧回调和迟到结果不能复活编辑权。
- 保留 stop-before-dispose、原超时、预算、浏览器矩阵；S3 全部任务/检查后中文提交一次。
- 原始日志在 skill 工作区，机器 JSON/变异备份在外部 P5 handoff。

## Review Focus

- 旧保存跨 await 的面板调用：Task 1 的输入准备集合 + Task 4 的真实会话交错。
- IME 被屏障截断：Task 3 控制调度，Task 4 实际 DOM 事件正反对照。
- 失败后重试读取已销毁模型：Task 3 固定正文、Task 4 令旧 capture 抛错验证不再访问。
- 恢复期间原 ACK 与失权：S2 状态继续有效，Task 4 核对原请求、稳定入口与副本正文。
- 迟到实例的销毁误伤新任务：Task 1 discard 的身份边界和异步 retire 测试。
