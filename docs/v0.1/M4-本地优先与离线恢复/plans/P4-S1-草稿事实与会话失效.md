# P4-S1 草稿事实与会话失效实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans 在当前唯一 P4 工作区逐任务内联执行；Step 完整验证后一次中文提交。沿用用户自主推进授权。

**Goal:** 提供不泄露隐藏文档的批量恢复事实，并可靠表达既有会话的失效原因。

**Architecture:** contracts 定义严格请求与兼容响应；auth 统一把实际会话行映射为错误详情。documents 的专用读服务在一个只读快照中批量取事实，复用权限、修订来源和占用规则，不读取内容、不引入浏览器清理副作用。

**Tech Stack:** TypeScript、Zod 4、NestJS、Drizzle/PostgreSQL、Vitest；不新增依赖。

**Spec:** `../specs/P4-S1-草稿事实与会话失效.md`

## Global Constraints

- 唯一分支 codex/m4-p4-drafts-cleanup；主目录保持 main，路径为 .codex/worktress/codex/m4-p4-drafts-cleanup。
- 输入原始项数 1–100、字符串最长 3,699；UUID 小写后按首次出现去重；空项/空格/额外或重复参数拒绝。
- unavailable 只含 id/status；revisionSource 只给保存该修订的本人；occupied 复用 occupancyOf/reservationOf。
- 一个 readSnapshot；同连接顺序 await；数组参数不展开；不读正文、不写数据库、不改原编辑裁决。
- account_disabled/password_reset/password_changed/replaced/logout 必须带 userId；expired 只有识别到会话时带 userId；未知/失败不等于停用。
- 测试仅使用 codex-nerve-m4-p1 的 53522 专用数据库，明确设置 NERVE_TEST_DATABASE_URL；不访问 54318 开发库。
- Node 24.21.0、pnpm 12.6.0；原门禁保持，原始日志保存在本计划 SDD 目录，Phase 删除前外部冻结。

## Review Focus

1. 大小写重复 UUID 与原始超额输入：不能把存在的记录判缺失或用去重逃过上限；Task 1/3 固定反例。
2. 全部缺失、全部无权和混合批次：不得漏查权限、泄露标题或产生不同 SQL 序列；Task 3 实际语句与响应比较。
3. 同一文档他人的修订来源与仍有续上机会的旧租约：必须隐藏他人来源且保留 M3 R2；Task 3 数据库反例。
4. 守卫之后的停用、重置、轮换、退出：详情来自当前事务、旧响应不得删除新 Cookie；Task 2 确定性交错。
5. 失效分类查库失败、未知会话与缺失账户：不能误报停用；Task 2 单元及真实 HTTP 反向验证。
