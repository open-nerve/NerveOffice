# P2-S2 请求时限与接管位置：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans 在当前会话逐任务实施；步骤用复选框追踪。

**Goal:** 请求从发送到正文读取、校验都有应用时限；被本人接管的位置优先使用服务端 `sameSession`，同时保留未知结果与迟到响应保护。

**Architecture:** 请求层统一管理取消、计时和最终结果，正文在请求作用域内消费。编辑器接口只选择时限，不自行创建计时器。接管位置由独立的无资源模块合并服务端事实与本机后备证据，页面继续管理作废代次和资源。

**Tech Stack:** TypeScript、Fetch/AbortController、Vitest 可控时钟与暂停的响应流、既有 Playwright 三浏览器回归；不新增依赖。

**Spec:** `../02-P2-本地优先保存.md` §3.6、§3.7、§4；M4 总设计 §6.2；DEF-041、DEF-071。

## Global Constraints

- S1 已通过独立审查及 849 项三浏览器回归；在此行为保持基线上实施本 Step。
- 主目录保持 main；在 `codex/m4-p2-local-first` worktree 实施，只在 Phase 合并后推 main。
- 通用请求默认 30,000 ms；保存与副本 60,000 ms；租约申请、核对、续租/续上及本机取钥 10,000 ms。释放/交出类租约操作也使用 10,000 ms，页面既有退出等待 5,000 ms 不变。
- 超时不代表服务端没有提交；不回收请求标识，不清空待原样重试的内容，不把超时归为确定拒绝。
- 计时覆盖成功、失败响应的正文与契约校验；收到 HTTP 头不能结束计时。取消要中止 fetch，同时保证不响应取消的替身或迟到响应不能再兑现成功。
- 不接发件箱、不改捕获节奏、不增加自动重试次数；联网事实和统一页头在 S5 接入。
- 服务端持有者为本人时 sameSession=true/false 分别表示这个浏览器的登录/别处；持有者消失、变为他人或查询失败才退到现有本机证据。强制接管不套用本人接管规则。

## Review Focus

- 头已到、成功或错误正文不结束：到总时限结束，错误正文不能把超时吞成确定 4xx（任务 1、2）。
- 请求超时后才成功或失败：调用方只收到一次超时；未处理拒绝、计时器和取消监听器不能泄漏（任务 1）。
- 保存已经提交但回包超时：原 requestId、gzip、序号与基准不变；重试得到原成功（任务 2）。
- 同一失效中本机证据与 sameSession 矛盾：采用服务端事实；查询失败仍保留原本机判定（任务 3）。
- 位置查询晚于卸载、重新进入或新一次失效：不修改新页面，不释放新会话的锁（任务 3）。

**Interfaces:**
- `RequestTimeoutError extends NetworkError`，构造器接收并保留 `readonly timeoutMs: number`；超时仍属于可自动重试、结果未知的网络失败；调用方取消保留自己的 signal.reason。
- `withinRequestDeadline<T>(options: { timeoutMs: number; signal?: AbortSignal }, run: (signal: AbortSignal) => Promise<T>): Promise<T>` 管理一次完整请求；所有结束路径清理 timer 和上游 signal 监听器。
- `RequestOptions<T>`、`RawRequestOptions` 增加 `timeoutMs?: number`，默认 `30_000`。
- `apiFetch<T>(path: string, options: RawRequestOptions, read: (response: Response) => T | Promise<T>): Promise<T>` 在同一作用域内执行 fetch、错误正文读取和成功响应消费；不再把待消费的 Response 交出作用域。无正文接口用返回 undefined 的 reader，304 在 reader 中识别。
- `apiRequest` 在上述 reader 中调用 `readJson`；`readJson` 仍负责格式校验。ApiError、NetworkError、ResponseFormatError 的原公开导出保持兼容。
- 有网络正文的所有 editor-api 调用同步迁移；gzipText 的内存 Response 不纳入网络计时。
