# P4-S4 启动维护与退出清理实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans，在唯一 P4 worktree 内联执行；沿用自主推进授权，完整 Step 全绿后一次中文提交。

**Goal:** 明确退出、停用、不可读和到期时如实清理本机草稿；旧操作不伤及新登录。

**Architecture:** 请求来源绑定→共享失效/退出/维护协调→现有持久资格与合一清理；按需公开退出页和状态组件消费结果，编辑器只承担自身停写与资源释放。

**Tech Stack:** 既有 TypeScript、React、TanStack Query、IndexedDB/OPFS、Vitest/Playwright；不新增依赖。

**Spec:** `../specs/P4-S4-启动维护与退出清理.md`

## Global Constraints

- main 主目录不动；复用 codex/m4-p4-drafts-cleanup，Step 一次提交，不推 Phase 分支。
- 实际请求开始时固定来源，网络不持存储锁；清理阶段每次核对原代次，广播不授予资格。
- 只用隔离数据库 53522；浏览器 workers=1 串行，运行期间不改源码或跑其他门禁。
- 保留平台180 KiB/2文件、编辑器2350 KiB、公式800 KiB、草稿Worker15 KiB原预算；完整能力与文字按需加载。
- Task 使用 task-start/task-done 留证；单元先RED，原失败和最终报告分开；JSON/源码/覆盖率归档放外部 handoff，避免混入完整lint。

## Review Focus

- 错误返回时已经新登录：Task2用请求原许可和查询前ticket反例；禁止读取最新代次补授权。
- 主库新格式留下但镜像被文件时间删除：Task1同时核对保留键、槽位格式、时间与原始字节。
- 退出未知后新会话被自动再次退出：Task3/6验证固定CSRF与新代次结束旧操作，不能调用旧adoptRenewedSession重发流程。
- 本机失败但服务器已退出：Task3/5分别呈现结果，清缓存和原资格重试；不能只看pending数组是否为空。
- 迟到后台扫描泄露前一人的标题或复活旧草稿：Task4/6在切换、冻结/漏广播及正在捕获的交错中核对来源与原件。

规格复核补充：Phase §3.3 要求确证停用时说明原因；先前将全部失效故事都改为通用过期提示的判断不完整。重置/改密/过期仍沿既有说明，确证停用则传递独立原因，覆盖平台初始查询、普通请求、编辑器初始查询及开着的离线编辑页。8 项单元反例 RED 后修复，540 项相关单元通过；浏览器先定向验证，再完成受影响故事的三浏览器及 running 对照。说明不提供清理资格、不声称清理成功，旧响应遇到新登录仍需重新确认。
