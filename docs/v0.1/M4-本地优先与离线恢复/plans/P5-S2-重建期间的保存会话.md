# P5-S2 重建期间的保存会话：实施计划

> 状态：已完成｜日期：2026-10-16｜所属：M4-P5
> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `superpowers:executing-plans` 在当前会话逐任务实施，沿用唯一 Phase 工作区。

**Goal:** 换具体编辑器时保留原保存会话、连续序号和待确认公式结果。

**Architecture:** 一个稳定绑定转交保存层需要的编辑器能力；冻结时提供完整快照，重新绑定后延续序号。公式恢复用原草稿 sessionId/serial 标记确认边界，原请求与协议不变。页面在 S3 控制实际重建及输入/权限状态。

**Tech Stack:** TypeScript、Vitest、现有 WorkingDraft/SaveCoordinator/Autosave，零新依赖。

**Spec:** `../specs/P5-S2-重建期间的保存会话.md`，R1–R5；Phase §3.3–§3.4。

## Global Constraints

- 当前分支 `codex/m4-p5-formula-fallback`；主目录始终 main；以 `5553892b` 为本 Step 基线。
- 只有 WorkingDraft 一个草稿来源；不改 HTTP、幂等键、数据格式、锁和租约协议。
- 不伪造用户编辑；逻辑序号跨实例连续；真实强制重算的 onlyLocal 写回不算编辑。
- 冻结前 composing=false、isCellEditing=false、uncommittedInput=none；失败保留原实例。
- 公式恢复仅在同 sessionId、晚于恢复 serial、formulasPending=false 的确认之后清标记。
- 保留所有质量门槛、预算、超时与浏览器矩阵；S2 单元验证完成后中文提交一次。
- 机器 JSON 回执存外部 `.codex/handoffs/m4-p5-20261016/`；skill 工作区只留不会被源码 lint 当成程序的日志/Markdown。

## Review Focus

- 新编辑器初始序号非零：不能让序号倒退或跳增，Task 1 用 7→新 3→新 4 的字面结果 7→8 验证。
- 旧编辑器已经排队的事件或公式等待晚到：不能变更新实例状态，Task 1 保存并手动派发旧回调/释放旧 Promise。
- 公式失败时没有任何新输入：seq=0 仍须待保存并自动补存，Task 2/3 以零修改序号覆盖。
- 恢复前 ACK 或未知结果的认领晚到：不能抹掉新公式待更新，Task 2 覆盖旧 ACK、replay/adopt 和新结果确认。
- 冻结后失权/来源转交/停止捕获：不能重新接纳编辑器、也不能毁掉新所有者草稿，Task 3 验证资源身份与真实来源内容。
