# P5-S4 页头说明与有限诊断：实施计划

> 状态：已完成｜日期：2026-10-17｜所属：M4-P5
> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `superpowers:executing-plans`，在当前唯一 Phase 工作区逐任务实施。

**Goal:** 把 S3 的恢复状态变成可读、可操作的页头说明，并以有限字段上报真实 Worker 故障。

**Architecture:** 同一个诊断端点接收兼容旧结构的新变体，共用权限、去重和账户限量。页面在知道实际创建修订和权限的入口报告一次；恢复自检保留独立报告。页头把公式、服务端保存、本机保存作为三条独立事实。

**Tech Stack:** TypeScript、React、Zod、NestJS、Vitest 与现有 PostgreSQL 集成夹具；零新依赖。

**Spec:** `../05-P5-公式Worker的退路.md` §3.5、§4；S3 页面恢复接口。

## Global Constraints

- 基线 `417ac0b5`；同一个 `codex/m4-p5-formula-fallback`，根 main 不切换。
- 旧 OpenCheckReport 的结构兼容；新报告不含快照、公式、资源内容、异常 message/stack 或 Worker URL。
- 七种故障保持 S1 名称；共用原 10 分钟去重、每账户 20 条限量、10,000 键上限。权限检查先于配额。
- 不新增端点、数据库迁移、SDK 参数、存储来源、生产故障注入或新依赖。
- 上报是后台诊断，不影响恢复与会话，不重试、不改变保存状态；本页 Worker 首错最多报一次。
- 保留 stop-before-dispose、原超时/预算/浏览器矩阵；S4 全部任务与检查后中文提交一次。
- 原始日志保存于 skill 工作区；机器 JSON 和变异备份放外部 P5 handoff。

## Review Focus

- 阅读刷新失败时 shown 尚是旧修订：Task 2 用创建入口的上下文，验证新修订和 refresh，而非猜测全局状态。
- 两种报告各用一套配额会翻倍：Task 1 交替发送，验证合计第 21 条被限量；拒绝权限不能占配额。
- 原异常字段夹带内容：Task 1 验证严格拒绝及日志无内容，Task 2 构建器只挑白名单。
- 可见按钮与 S3 动作保护不一致：Task 3 验证鼠标/键盘、旧确认框继续、取消仍可用与重试后焦点。
- 公式提示掩盖保存失败或重复播报：Task 3 验证三条事实独立、例行保存不重复播旧公式状态。
