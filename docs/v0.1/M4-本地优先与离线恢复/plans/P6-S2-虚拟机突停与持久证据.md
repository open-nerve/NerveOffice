# P6-S2 虚拟机突停与持久证据：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为三个正式浏览器的客体 OS 突停、存储完成与产品恢复提供可复核的独立证据。

**Architecture:** loopback 收集器保存完成事实并冻结；拥有 VM 子进程的控制器在 journal fsync 后停止客体，再用同一磁盘重启。原生 IndexedDB 页面做 strict/default 对照，产品层复用既有恢复自检和独立云端核对。

**Tech Stack:** Node 24.21.0、TypeScript、Vitest、现有 Playwright 校准、QEMU 11.1.2、Tart 2.41.1。

**Spec:** `docs/v0.1/M4-本地优先与离线恢复/specs/P6-S2-虚拟机突停与持久证据.md`。

## Global Constraints

- P6 唯一 worktree，主目录 main 不动；Step 完成提交一次，Phase 末审查/合并。
- VM 与报告是专用自建资源，禁止全局清理、共享用户目录及输出凭据。
- 1 MiB 确定性字节、序号 10 触发；strict/default 各 10，产品各 3；每浏览器先做 1 控制轮。
- journal fsync 成功后才能发 SIGKILL，冻结后不补填；实际客体 boot ID 改变、原磁盘保留。
- 原有 Safari 崩溃恢复及 r23 不弱化；测试构建的上传暂停不称为生产部署证明。
- 真正 VM 实验不进 CI；自动单元与浏览器校准进入既有门禁。失败原件保留。

## Review Focus

- 收集器已收到但 journal 尚未落盘就停止 VM：Task 2 用阻塞/失败 journal 证明发信号顺序。
- 旧 VM/页面的迟到消息覆盖冻结点：Task 2 覆盖旧 boot、冻结后报告及重复报告。
- 只重开浏览器或换了磁盘却被称为 OS 突停：Task 1/2 以客体 boot ID、子进程信号及磁盘身份独立判断。
- Safari automation 新会话不保留原存储：Task 1/3 使用客体普通 Safari 自检页面，先做不停止的持久回读控制。
- 产品只检查 IDB 却漏了 OPFS，或 Cookie 丢失误判正文丢失：Task 3 要求镜像实际完成/槽位证据，并覆盖重新登录后明确恢复。
