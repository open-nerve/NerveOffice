# P2-S6 测量与整体验收：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans，在当前 Phase worktree 逐任务推进。

**Goal:** 对真实本地优先管道给出可复核性能证据，完成整 Phase 质量门禁、独立审查、文档交接和 main 的 CI 验收。

**Architecture:** 复用既有持久浏览器目录、样本生成器、只读落盘观察、自动保存日志与统计函数；测量走实际编辑器、生产保存节奏和 Worker，不另建保存实现。生产代码仅在证据显示缺陷时修正。

**Tech Stack:** TypeScript、Playwright、Vitest、现有独立 PostgreSQL 测试容器；不新增依赖。

**依据:** 计划书 §12.2、P2 Phase §4/6/8、DEF-012/041/071；S5 基线 `463881ff`。

## 约束与测量口径

- P2 唯一分支 `codex/m4-p2-local-first`，主目录保持 main；Phase 验收后 `--no-ff` 合并，只推 main。
- 检查期间不改源文件、测试、文档，不运行 lint --fix 或提交；所有会话退出后再改。
- 只使用 `codex-nerve-m4-p1` 的独立测试 PostgreSQL，各套件自行建删隔离库；不操作用户开发库，不启动真实 Safari。
- 正式测量每组至少 20 次，Chromium、Chrome、Playwright WebKit 串行、单 worker、零重试；三个样本为约 1 MiB、约 5 MiB、perf-50k（约 5 万格、1,000 个公式），分别在线/离线。
- 真实计时，不快进时钟、不改捕获/上传节奏、不主动 flush。每组使用全新持久资料目录；第一轮单列，后续轮完整保留。
- 起点为浏览器内最后一次同步修改命令开始（包含命令本身成本，保守于“修改停止”）；终点为当前修改对应的 `data-local-save-state=saved` DOM 更新。必须先观察离开旧 saved 状态，不能把旧记录当新完成。
- 终点之后读真实 IDB 密文并独立解密，核对本轮修改、单调 draftSeq 与公式标志；读盘和统计放在计时窗口外。记录捕获同步成本及本轮公式完成时间。
- 最近秩 p50/p95/max；同时报告全部样本和满足公式 ≤900ms 的样本，不删除慢轮。后者本机保存 p95 ≤2s，约 1 MiB 的同步捕获 p95 ≤100ms；超出条件的公式首轮单列并关联 DEF-072，不冒充真实 Safari 或 M7 部署压测。

## 自审

测量范围直接来自已经批准的 P2 S6；工具仅观察实际页面，原始结果包含冷启动与慢轮。`verify --ci` 与默认完整门禁只有数据库启动及额外 audit 的差别，数据库已由明确隔离环境提供；clean 仅删除 apps/packages 的构建产物。无范围变更、无用户数据操作，无须暂停等待批准。
