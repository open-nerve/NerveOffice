# P1 本机发件箱：实施计划

> 状态：S1–S9 实现、复核与本机完整门禁通过，S8 合并及 CI 待完成｜日期：2026-10-09，2026-10-10 接续更新｜所属：M4-P1｜依据：`01-P1-本机发件箱.md`

勾选依据为已落档代码与 `reviews/P1-真实浏览器复核.md`、原 Claude A/B/C 报告；历史运行与 Codex 本轮验证在 `reviews/P1-审查报告.md` 分开记录。原计划的未勾选不代表全部未实施：接手断点在 S8 独立复验之后的修复与收尾。

## 目标

按 P1 设计的 §6 逐个完成 S1–S8。

- **每个 Step 收尾**：lint、类型检查、单元测试全绿；有浏览器层或崩溃用例改动的 Step，在本机三个浏览器上跑通。提交一次。
- **变异验证**：每条承重的判断都做（规范 §10.5）——写入者的判定、序号、只删到已确认的序号、AAD 的字段表、解不开的归类、看门狗、密钥的清零。加密另有已知答案测试，钉住字节。
- **持久上下文**：落盘、耗时、配额、原子性的用例用持久上下文，逻辑类的照常。
- **不进存储与日志的东西**：租约令牌与原始密钥不进浏览器的存储；日志与探针的结果里没有内容与密钥。
- **真实 Safari**：只在用户空闲时跑，跑之前核对 `safari:selftest` 的空闲判定照常工作。
- **Linux 镜像**：拉 Docker 里 Playwright 的 Linux 镜像之前，主会话先告诉需求方。

## 任务

### S1 真实浏览器的前置复核（第一轮）
- [x] 1. 页面自检的报告加 `facts` 字段与运行次数的地址参数；判定的纯函数放在驱动脚本一侧（单元测试）。
- [x] 2. `editor/testing/` 下的探针与它的 Worker：
  - 存储的事实（persist、estimate、durability、两个仓库、升级、versionchange、`databases()`、5 MiB 的字节）；
  - 事务 abort 的回滚；
  - `CryptoKey` 交给 Worker、Worker 里的 AES-GCM 带 AAD、CompressionStream、digest；
  - Web Locks。
- [x] 3. `worker-stall` 场景（探针 Worker 有无空定时器 × 空闲 0.2、1–1.5、3、10 秒）；`capture-cost` 场景（1 MiB、约 5 MiB，分段计时、异步段的最长阻塞、主线程 gzip）；`perf-baseline` 场景（首屏的冷与热、两种公式模式下的收齐与帧间隔）。
- [x] 4. Playwright 的校准（小样本、少次数，进 CI）；三个浏览器的持久上下文里跑足次数（不进 CI，`playwright.measure.config.ts` 一类）。
- [x] 5. 真实 Safari 跑一轮（用户空闲时），写复核报告的初稿：放置、`durability`、密钥交给 Worker 的结论。

### S2 契约与保留期

### S3 记录、AAD、编解码与写入者的判定

### S9 OPFS 的冗余（设计 §3.8）
- [x] 1. `shared/outbox/` 下的镜像：槽位文件的格式（头：魔数与版本、写入者、序号、代号、内容的长度与 SHA-256、头的校验）与读写的纯逻辑（两个槽位中取校验通过、代号最大的；写一半落选，新版格式保护整个镜像）；单元测试。
- [x] 2. Worker 里的镜像：同步访问句柄、建好两个槽位、轮流原地改写（截断 → 内容 → 头 → flush）、截断、句柄的独占与退避、写满与出错；IndexedDB 提交之后才写；写入的结果带上"镜像没写成"。
- [x] 3. 读与恢复：读时在 IndexedDB 与两个槽位里取最新的；打开、登记之前比对，OPFS 更新时写回 IndexedDB（连同写入者的记录），留下"已从备份恢复""因浏览器存储损坏丢失"两种事件；按用户清理与保留期删目录。
- [x] 4. 浏览器层：写读、两个标签页的句柄独占、写满、IndexedDB 被删之后恢复与事件（三个浏览器）。
- [x] 5. 崩溃用例（崩溃工具的实现者）：原子性的口径不变、从 OPFS 恢复也算；写镜像途中结束；"日志结尾补一个只有头的记录"确定地造出删库之后恢复；Chromium 删库的前兆记成附件。
