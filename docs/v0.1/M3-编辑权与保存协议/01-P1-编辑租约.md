# M3-P1 编辑租约：架构设计与实施规划

> 状态：进行中｜日期：2026-10-04｜所属：M3-P1｜依据：M3 总设计 §2.1、§5（P1 一行）、§6.1、§6.3、§6.4、§6.7–§6.9；00 号计划书 §6.2–§6.4（r13）、§7.4、§8.4｜基于代码版本：`bf95b23`（main，M3 总设计已合并）

## 1. 目标与范围

同一时刻只有一个标签页能写一份文档；失效的会话、失去编辑权的人写不进来。全部在服务端由数据库保证，编辑器页只做最小的接入，阅读模式与原地切换在 P2。

- **编辑租约**：申请、心跳续租、释放、读编辑状态；租约绑定"这个标签页、这次登录"；每次申请产生新的一代（`writeEpoch` 加一）；时间以数据库为准；有效期 90 秒、心跳 10 秒；服务端按最后活动时间兜底回收（12 分钟）；记下异常结束，供 P5 的提示。
- **保存要求租约**：令牌、代次、登录会话、标签页都对得上才写入；同一次保存的重放仍然只要求能访问（ADR-011，M3 总设计 §6.3 的原则）。
- **收回写入权接上租约**：M2 留下的五种范围里，失去编辑权的持有者的租约在同一个事务里结束，文档的代次加一；收口"进行中的保存与撤权不互斥"（M2-P2 设计 §7、ADR-014）。
- **登录失效，租约随之失效**：退出、被撤销、换令牌之后，绑定在那次登录上的租约不再有效（系统管理员的"强制结束编辑"由撤销登录承担，M3 总设计 §2.1）。
- **编辑器页的最小接入**：能编辑时打开就申请；拿不到时只能阅读，说明谁在编辑；心跳；保存带上令牌与代次；编辑权失效时停止保存并说明；关闭页面时尽力释放。

用户故事（服务端部分，集成测试）：US-M3-04（编辑唯一）、US-M3-11（过期的会话不能覆盖）、US-M3-12（撤权时停止写入）、US-M3-13（确认丢失时安全重试）。它们的 E2E 在 P2，与阅读模式的界面一起做；本 Phase 改写 US-M1-07 的 E2E（两个标签页）以适应租约。

**不在本 Phase**：打开即阅读、"编辑"与"退出编辑"、原地切换、阅读者的更新提示、续上与另存为副本（P2）；完整的快照校验与内容哈希、拦截旧客户端（P3）；自动保存（P4）；请求编辑、本人接管、强制接管、空闲释放的界面、异常中断的提示（P5）。

## 2. 现状（`bf95b23`，按代码核对）

- **保存**（`documents/document-content.service.ts`，ADR-011）：与文档无关的基本校验在事务之前；事务里先不加锁判断能否访问 → 能编辑时锁文档行（`FOR UPDATE`）、锁下再判断 → 按 `requestId` 查重放（只要求能访问）→ 不是重放才要求能编辑 → 核对 `unitId` → 基准修订号 → 写内容、修订记录与审计（`documents.content_saved`）。查询参数 `baseRevision`、`requestId`、`clientInstanceId`、`localSeq`（`saveContentQuerySchema`，严格结构）。
- **代次**：`documents.write_epoch`（M2-P2，迁移 0019 的触发器保证只增不减）；删除（`trash`）、跨空间移动与转移（`moveToSpace`）在仓储里加一。`DocumentRow` 里**没有**代次。
- **收回写入权**（`documents/write-access.ts`）：抽象类 `WriteAccessRevocation` 与 `coversWriter`（五种范围的语义），实现 `LeaselessWriteAccessRevocation` 为空。调用方：成员的调整与移出（workspace）、归档（admin）、停用（admin）、转移、跨空间移动、删除（文档与文件夹）、取消与降低单独授权（documents），都在改动权限的事务里调用。
- **会话**（auth）：`Principal` 带 `sessionId`；`SessionService.isActive(sessionId, transaction)`（未撤销、未过期）；退出、停用、重置、修改密码（换令牌）都会撤销会话；会话守卫每个请求按需顺延空闲过期。
- **模块**：documents ──► database、spaces、audit（类型上已引用 auth 的 `Principal`）；workspace ──► database、audit、users、spaces、documents，分享等需要人名的接口在这里编排；接口只经模块的 `index.ts`。
- **锁的顺序**（ADR-007、ADR-014）：…… → 空间树锁 → 空间行 → 成员行 → 文件夹行、文档行、回收站行 → 审计。
- **自动核对**：路由表（未登录一律 401）、"看不到 / 不存在"的探测或豁免、读快照的请求表（ADR-017）、权限矩阵；`held-lock.ts` 构造确定的交错。
- **测试**：16 个集成测试文件与 2 个 E2E 直接发保存的请求；`editor/conflict.spec.ts`（US-M1-07）让同一个人的两个标签页同时编辑；`tests/stories.json` 只登记了 M1、M2 的设计与故事。
- **编辑器页**（`features/sheet-editor/editor-page.ts`）：按 `permissions.canEdit` 创建编辑器（`access`），保存的状态机（`save-coordinator.ts`）不依赖接口的细节（`send(request, body)`）。

## 3. 设计

### 3.1 模块划分与依赖方向

```
workspace ──► documents、users、auth …    编辑权的接口：申请、心跳、释放、编辑状态（补持有者的人名）
documents ──► auth（新：SessionService）、spaces、audit、database
              租约的表、仓储、规则与服务；保存时核对租约；收回写入权的实现（接入租约）
```

**租约放在 documents 模块，不另建 editing 模块**（M3 总设计 §6.7 写的是新建 editing 模块，并说明"模块的名字与边界在 P1 的设计里锁定"；这里改为放进 documents，理由如下，记进总设计的变更记录）：
1. 保存核对租约是保存事务里、文档行锁下的一个条件；代次就在文档行上。分到别的模块，就要由 documents 定义入口、由那个模块在运行时登记：漏了登记时只能在运行时发现，处理不好就是保存绕过租约（失败时放行）。
2. 收回写入权要按范围找到租约：按空间的范围（归档、移出）要把租约与文档按空间连起来查，并锁住文档行。跨模块不能引用别人的表（ADR-003），分开之后就得在租约上冗余空间 id，或者让 documents 再开一个口子。
3. 租约的有效条件要用到的东西——文档行、代次、有效权限、保存事务——都在 documents 里。

documents 的文件以 `edit-lease` 开头，集中在一处：`edit-lease-rules.ts`（纯函数）、`edit-lease-token.ts`、`edit-leases.repository.ts`、`edit-lease.service.ts`、`lease-write-access.ts`（收回写入权的实现，取代 `LeaselessWriteAccessRevocation`）。documents 引入 AuthModule 只为了 `SessionService.isActive`（判断别人的租约绑定的登录还在不在）；auth 不依赖 documents，依赖图仍然无环。

编辑权的 HTTP 接口放在 workspace（`DocumentEditingController`、`DocumentEditingService`）：编辑状态与"别人正在编辑"的响应要带持有者的人名，人名由 workspace 经 users 补上，与分享的做法相同。

### 3.2 接口契约

契约写进 `packages/contracts/src/documents/editing.ts`，从 contracts 的入口转出。

| 接口 | 说明 |
|---|---|
| `GET /api/documents/{id}/edit-lease` | 编辑状态（能读就能看）：`{ revision, editor: { holder: UserSummary, lastActiveAt, sameUser } \| null }`。在读快照里（ADR-017） |
| `POST /api/documents/{id}/edit-lease` | 申请（要能编辑）。请求 `{ clientInstanceId }`；成功 201：`{ token, writeEpoch, revision, expiresAt, interruption }`。有效的租约在别人手里时 409 `EDIT_LEASE_HELD` |
| `PUT /api/documents/{id}/edit-lease` | 心跳续租（要能编辑，带令牌）。请求 `{ idleSeconds }`；成功 200：`{ expiresAt }`。租约不再有效时 409 `EDIT_LEASE_LOST` |
| `DELETE /api/documents/{id}/edit-lease` | 释放（能读就行，带令牌）：令牌是当前租约的才结束它；否则什么也不做。一律 204（页面关闭时的 `keepalive` 请求不看结果） |
| `PUT /api/documents/{id}/content?…&writeEpoch=` | 保存：查询参数加 `writeEpoch`（必填，契约是严格结构；v0.1 还没有部署，没有旧页面）；请求头带令牌 |

- **令牌**：32 字节的安全随机数，base64url（43 个字符），只在申请的响应里出现一次；服务端存 SHA-256 摘要，比较用恒定时间。经请求头 `X-Edit-Lease` 传递，不进地址与日志（日志本来就不记请求头）。控制器用一个读请求头并按 schema 校验的参数装饰器 `@EditLeaseToken()` 取得（规范不允许 `@Headers()`；自己写的参数装饰器由审查保证），documents 转出，保存与 workspace 的接口共用。格式不对是 400 `REQUEST_INVALID`；没带时按"没有租约"处理。
- **`clientInstanceId`**：编辑器页每次加载生成的标识（M1 起保存就带着），租约绑定它。
- **`idleSeconds`**：距离本页最后一次键盘、鼠标操作的秒数（0–86400 的整数）。只报相对时长，不用浏览器的时钟。
- **`interruption`**：上一个租约异常结束（见 §3.4.5），并且在 30 分钟以内时给出 `{ holder: UserSummary, endedAt }`，否则为 null。本 Phase 只给出，提示的界面在 P5。
- **新错误码**（ADR-006）：
  - `EDIT_LEASE_HELD`（409，"别人正在编辑这份文档"）：`details` 为 `{ holder: UserSummary, lastActiveAt, sameUser }`。`sameUser` 是"持有者就是自己"（在别的标签页或设备上），P5 据此给出"在此编辑"。
  - `EDIT_LEASE_LOST`（409，"编辑权已失效，本次操作没有生效"）：`details` 为 `{ reason }`，原因见 §3.4.1。客户端对不认识的原因按通用的"编辑权已失效"处理（契约的响应结构是宽松的，以后的 Phase 可以加原因）。
- **常量**（contracts，前后端共用）：`EDIT_LEASE_TTL_SECONDS = 90`、`EDIT_LEASE_HEARTBEAT_SECONDS = 10`、`EDIT_LEASE_IDLE_RECLAIM_SECONDS = 720`、`EDIT_INTERRUPTION_NOTICE_SECONDS = 1800`。
- 失去访问与失去编辑权**先于**租约判断：读不到是 404，能读不能编辑是 403（`PERMISSION_DENIED`），之后才看租约。P2 的页面据此区分"还读得到就给副本"与"读不到就丢弃"（M3 总设计 §2.1 第 4 条），不必另设原因。

### 3.3 数据模型与迁移

迁移 `0022`（`db:generate --name m3_p1_document_edit_leases`，只做加法）。表定义放 `db/schema/documents/`，仓储 `edit-leases.repository.ts`（一表一仓储）。

`document_edit_leases`：每份文档至多一行，新的申请改写这一行。

| 列 | 说明 |
|---|---|
| `document_id` | 主键；外键到 `documents`，级联删除（永久删除时随文档删掉） |
| `holder_id` | 持有者；外键到 `users` |
| `session_id` | 绑定的登录会话；不做外键：会话行会被清理，有效与否经 auth 判断 |
| `client_instance_id` | 绑定的标签页 |
| `token_digest` | 令牌的 SHA-256（CHECK 32 字节） |
| `write_epoch` | 这一代的代次（申请时文档的代次加一之后的值） |
| `acquired_at` | 申请的时间 |
| `renewed_at` | 最近一次续租的时间（申请时等于 `acquired_at`） |
| `expires_at` | 到期时间：续租时为 `now() + 90 秒`（CHECK 晚于 `renewed_at`） |
| `last_active_at` | 最后活动时间：续租时为 `now() - idleSeconds`，不早于 `acquired_at`、不晚于 `now()` |
| `ended_at`、`end_reason` | 明确结束的时间与原因：`released`（释放）、`revoked`（收回写入权）；两列同时为空或同时有值（CHECK）。到期、空闲、登录失效、代次过时不写这两列，按 §3.4.1 算出来 |

- 按 `holder_id` 建索引（停用、移出、取消授权按人找租约）；按文档找的是主键。
- `documents` 不加列：`DocumentRow` 补上已有的 `write_epoch`（`COLUMNS` 加一项），仓储加 `advanceWriteEpoch(id)`（`write_epoch + 1 RETURNING`，**不动** `updated_at`：申请编辑权不算修改文档，列表的排序不变）。
- 时间一律取数据库的 `now()`（事务开始的时刻）。测试改写租约行的时间来模拟到期与空闲，不等真实的时间。

### 3.4 关键流程

#### 3.4.1 租约的有效条件（纯函数 `edit-lease-rules.ts`）

输入：租约行（可能没有）、数据库的 `now`、文档当前的代次，以及按需取得的两项事实——持有者的登录还在不在、持有者还能不能编辑。按下面的顺序判断，第一条不满足的就是失效的原因：

| 顺序 | 条件 | 不满足时的原因 |
|---|---|---|
| 1 | 有这一行 | `none` |
| 2 | 没有明确结束 | `end_reason`（`released`、`revoked`） |
| 3 | 代次等于文档当前的代次 | `stale`（删除、跨空间移动、转移、收回写入权之后，或者有了新的一代） |
| 4 | 没有到期（`expires_at > now`） | `expired` |
| 5 | 没有空闲超时（`now - last_active_at < 12 分钟`） | `idle` |
| 6 | 绑定的登录仍然有效 | `session` |
| 7 | 持有者对文档仍有编辑权 | `revoked` |

第 6、7 条要查数据库（各一两条语句），只在前五条都满足时才查。持有者自己的请求（心跳、保存、释放），第 6 条换成"请求的登录就是租约绑定的那一个、请求的标签页就是租约绑定的那一个"，不另查（会话守卫刚认证过这次登录；换过令牌的页面拿的是新的登录，按 `session` 失效，P2 的页面自动续上）。令牌对不上而这一行是有效的别人的租约时，原因是 `replaced`。

#### 3.4.2 申请

一个事务：
1. 不加锁判断能否编辑（`requireDocumentContent(…, ['edit'])`：读不到 404，只能读 403）；
2. 锁文档行（`FOR UPDATE`），锁下再判断一次；
3. 锁租约行（`FOR UPDATE`，没有行就是没有），按 §3.4.1 判断当前的租约；
4. 当前的租约有效：
   - 持有者是同一个登录、同一个标签页：这是同一个页面的重试（例如上次申请的回包丢了），往下发一个新的；
   - 否则 409 `EDIT_LEASE_HELD`（持有者、最后活动时间、是不是自己）；
5. 文档的代次加一，生成令牌，改写（或插入）租约行：持有者、登录、标签页、令牌摘要、新的代次、`acquired_at = renewed_at = last_active_at = now()`、`expires_at = now() + 90 秒`，清掉结束的两列；
6. 上一个租约异常结束（原因是 `expired`、`idle`、`session`，即没有明确结束、也不是被新的一代取代）而且结束在 30 分钟以内时，给出 `interruption`（持有者、`endedAt` = 它最近一次续租的时间）；
7. 返回令牌、新的代次、文档当前的修订号、到期时间。页面拿修订号与自己打开时的比较（P2：落后就先重新加载）。

#### 3.4.3 心跳、释放与编辑状态

- **心跳**：一个事务：不加锁判断能否编辑（404 / 403）→ 锁租约行 → 按 §3.4.1 判断（持有者自己的请求）→ 有效就续租（`renewed_at`、`expires_at`、`last_active_at`），否则 409 `EDIT_LEASE_LOST`。不锁文档行：收回写入权、新的申请都先锁文档行、再锁租约行，并改写这一行；心跳只锁租约行，与它们按租约行串行，不成环。
- **释放**：一个事务：不加锁判断能否访问（404，看不到与不存在一致）→ 锁租约行 → 令牌是当前这一行的、而且没有明确结束，就记 `released`；其余情况什么也不做。一律 204。
- **编辑状态**：只读快照里：能否访问（404）→ 读租约行 → 判断是否有效（第 6、7 条查持有者的登录与编辑权）→ 返回修订号，以及有效时的持有者、最后活动时间、是不是自己。workspace 在同一个快照里补持有者的人名。

#### 3.4.4 保存

在 ADR-011 的顺序里插入租约这一步，其余不变：

能访问 → 能编辑时锁文档行、锁下再判断 → 按 `requestId` 查重放（只要求能访问：**重放先于租约**，租约失效之后重发已经提交的保存，照样拿到原来的结果，A07）→ 不是重放才要求能编辑 → **租约**：令牌是当前这一行的、按 §3.4.1 有效、代次等于查询参数的 `writeEpoch`、登录与标签页对得上，否则 409 `EDIT_LEASE_LOST` → 核对 `unitId` → 基准修订号 → 写入。

保存不续租（续租靠心跳），也不加锁读租约行：能改写租约行的申请、收回写入权都先锁文档行，而保存在租约这一步之前已经锁住了文档行。

`DocumentContentService.save` 的参数由 `userId` 改为"谁在保存"（`userId`、`sessionId`、令牌），控制器从 `@CurrentPrincipal()` 与 `@EditLeaseToken()` 取得。

#### 3.4.5 异常结束

上一个租约没有明确结束（不是 `released`、`revoked`），而是因为到期、空闲超时或登录失效而失效，就是异常结束：持有者的页面可能还有没保存的修改。新的申请改写这一行之前算出来，在申请的响应里给出（§3.4.2 第 6 步）。被新的一代取代（`stale`）不算：那是删除、移动、撤权或者新的申请造成的，各有各的说法。

#### 3.4.6 收回写入权（`lease-write-access.ts`）

`LeaseWriteAccessRevocation` 取代 `LeaselessWriteAccessRevocation`，调用方不改。在调用方的事务里：
1. 按范围找出没有明确结束的租约所在的文档（与文档表按空间连查：`user` 按持有者；`membership` 按持有者与空间；`space` 按空间；`documents` 按文档；`userDocuments` 按持有者与文档——与 `coversWriter` 的语义一致，单元测试逐种核对），**按文档 id 的顺序锁文档行**，再锁这些租约行；
2. 锁下逐个按变化之后的权限判断持有者还能不能编辑（访问策略在同一个事务里查，看得到调用方刚做的改动）；
3. 不能编辑了：租约记 `revoked`，文档的代次加一。还能编辑的不动（`documents` 范围里跨空间移动之后仍能编辑的持有者：调用方已经给代次加了一，这个租约按 `stale` 失效，P2 的页面自动续上）。

**收口"进行中的保存与撤权不互斥"**：保存在租约这一步之前锁住了文档行；撤权要给持有者的文档加代次，必须先拿到同一把锁。所以两者必有先后：保存先提交，撤权在它之后生效；撤权先提交，保存在锁下看到新的代次与新的权限，被拒绝。"撤权提交之后的保存必定被拒绝"由数据库保证（计划书 §6.4）。申请与撤权交错时（申请在撤权提交之前判断了权限、在它之后才提交），租约行是有了，但第 7 条让它在每次使用时失效。

**锁的顺序**：撤权的调用方已经持有账户行、空间行、成员行或这些文档行，之后才锁文档行、租约行；申请先锁文档行、再锁租约行；心跳与释放只锁租约行。在锁顺序表里"文档行"之后加"租约行"（ADR-014 与架构总览同步）。

#### 3.4.7 编辑器页的最小接入

P2 会把这一段改成"打开即阅读、点'编辑'才申请"，这里做的租约管理（申请、心跳、释放、失效）在 P2 原样复用：
- `editor-api.ts`：申请、心跳、释放（`fetch` 的 `keepalive`，带 CSRF 与令牌两个请求头）、读编辑状态；保存带上令牌与 `writeEpoch`。
- `edit-lease.ts`（新，不依赖 Univer 与界面，用假的接口与假的时钟做单元测试）：持有令牌与代次；每 10 秒一次心跳，带上距离最后一次键盘、鼠标操作的秒数（在页面的捕获阶段记）；心跳得到 `EDIT_LEASE_LOST` 或 403、404 就转为"失效"，通知页面；网络错误时照常重试，到期由服务端判断；页面隐藏、关闭时尽力释放。
- `editor-page.ts`：能编辑时，载入内容之后申请：成功就按可编辑创建编辑器，并核对申请得到的修订号与载入内容的一致（不一致就重新载入一次）；`EDIT_LEASE_HELD` 就按只读创建，页头说明"××正在编辑"（是自己时说"你在另一个标签页或设备上正在编辑"）。编辑权失效时停止保存（保存的状态机 `stop`），页头说明编辑权已失效、本页的修改没有保存，提供重新加载；保存得到 `EDIT_LEASE_LOST` 同样处理。
- 失效时的"另存为副本""续上"在 P2。

### 3.5 错误处理、安全与可观测性

- 令牌只存摘要，比较用恒定时间；不进地址、日志与审计；申请的响应带 `Cache-Control: no-store`。
- 看不到与不存在一致：四个新接口都先判断能否访问，探测进"看不到 / 不存在"的核对。
- 申请、心跳、释放不写审计（太频繁；结束原因留在租约行上）。强制接管的审计在 P5。
- 日志：申请成功、被拒（持有中）、心跳失效各记一条 debug 级的结构化日志（文档 id、原因），不记令牌。
- 数据库繁忙按 ADR-006：还没提交 503，已提交 500。
