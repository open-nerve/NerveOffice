# M3 编辑权与保存协议：交接单

> 日期：2026-10-09｜所属：v0.1-M3｜对应合并：P1–P5 各自以 `--no-ff` 合并到 main（P1 `31feef2`、P2 `b0f7527`、P3 `7f4bd48`、P4 `1c71ad2`、P5 `d0567b5`）；P6 `71534a80`（合并之后的 CI 六项全绿，见 `reviews/M3-收尾汇报.md` §3）；标签 `v0.1-m3`

M3 让多人场景下的在线编辑正确、不覆盖：编辑租约与交接规则、保存协议的加固、自动保存与打开自检、打开即阅读的阅读模式，以及本机密钥的服务端管理。执行顺序 P1 → P6（总设计 2026-10-04 审批通过，计划书 r13）。本交接单是 M4 总设计的输入；各 Phase 的交接单里有更细的"已知的坑"，这里不重复。M3 总设计 §8 退出条件的逐条证据在 `reviews/M3-收尾汇报.md`。

合并之前另做了 M3 的合并前评审（Codex，另一家的模型，`reviews/M3-合并前评审-Codex.md`）："不通过"，4 条（阻断 1、重要 2、一般 1），核实都属实，按根因修复（P6 设计 §3.13，计划书 r20）：

- **CX1（阻断）**：明确结束（释放、交出）只锁租约行，在途的保存跨过它们，撤权又不锁明确结束了的租约，"撤权提交之后的保存必定被拒绝"出现缺口（A06）。释放与交出改为先锁文档行、再锁租约行，明确结束在类型上凭锁下的租约行（`LockedEditLease`）。
- **CX2（重要）**：迟到的旧申请回包抢走更新一代的本机锁，把合法的持有者挤成失去编辑权。本机锁的争用改为以服务端的事实裁决（`local-lock.ts`、租约的 `confirm`）。

## 与设计的偏差

都已回写到各 Phase 的设计、ADR 与 00 号计划书（r13–r20）：

- **P1**：租约放进 documents，编辑权的接口在 workspace，不新建 editing 模块；"续上"从 P2 提前到 P1（租约绑定登录，否则 US-M1-05 倒退）；系统管理员的"强制结束编辑"= 签发重置链接或停用账户（r14）。
- **P2**：阅读与编辑之间的切换一律重建编辑器（需求方决定，r15），DEF-036 随之关闭。
- **P3**：快照检查改用子进程池（需求方决定：工作线程的内存上限挡不住 V8 内置函数里的超限，r16）；"格式不兼容"落为 `DOCUMENT_TOO_NEW`；拦截旧客户端扩到申请编辑权与心跳；"内容相同不递增"留回执。
- **P4**：自动保存两级（M3 没有发件箱，捕获进内存里的最近一次捕获，r17）；`pagehide` 有在途的保存不释放编辑权。
- **P5**：请求单槽、交出之后保留 2 分钟（强制接管同样被挡）；撤权只收回按时间还活着的租约，刚死不久的仍锁文档行，保存的事务由数据库限时至多 70 秒（r18）。
- **P6**：本机密钥第一次取用时生成、取用是 `POST`；吊销不顺带退出登录、停用不顺带吊销；主密钥对不上时记 error、照常启动（r19）。真实 Safari：被别的应用挡住两分多钟的编辑中的编辑器页没有被暂停，P5 设计里"Safari 会暂停后台页面"的前提改写。
- **合并前评审（Codex）之后**：明确结束先锁文档行、本机锁的争用以服务端的事实裁决、吊销的响应分成结果与现状、还没写进模型的输入算未保存（r20）。

## M4 须知

- **写入栅栏建在本机锁之上**："先服务端、后本机锁"，锁的争用以服务端的事实裁决（合并前评审 CX2）——拿锁时被占着先核对本页这一代仍是当前的才抢；被抢的一方先核对，确实被别的一代取代才失去编辑权，这一代自己失效的交给租约已有的失效处理，核对不了时不判自己失效、由之后发出的心跳给出结论（只认被抢之后发出的续租）。写入栅栏要与之协调：被抢的那一刻先停写发件箱，核对得知仍是当前的再恢复；`steal` 之后从发件箱接手未同步的修改同样以服务端的裁决为准；复核 DEF-064 的 20 秒总预算。
- **本机密钥**：`POST /api/local-key`（第一把在第一次取时生成；200 `{ version, key }`，`no-store`；解不开回 500，页面按"暂时取不到"处理，不要重试成风暴）；导入为不可导出的 `CryptoKey` 只放在内存；心跳的 200 带 `localKeyVersion`，与内存里的不同 → 停用旧密钥、重新取、用新密钥重写当前内容；阅读时的编辑状态不带版本，进入编辑、恢复与另存为副本之前先取一次。US-M3-17 的 E2E 里"页面上没有可见的反应"的几句（`expectNoVisibleReaction`）要随 M4 的反应一起改。
- **发件箱替换内存里的最近一次捕获**：捕获、去重、立即上传、退避与 `Retry-After` 的规则在 P4 的 `autosave.ts`、`capture-*`；"还没写进模型的输入"（`uncommittedInput`：单元格编辑器里的、面板防抖中的）算未保存，写进发件箱之前先等面板（`settlePanels`）。DEF-059（规范化去掉没人引用的样式）与客户端的哈希一起定。主线程公式模式的规避在把它变成生产的退路之前必须保留。
- **浏览器里留下的记号**：`localStorage` 的 `nerve-office:pending-save:<documentId>`（`{ v: 1, at, revision }`）与 `sessionStorage` 的 `nerve-office:edit-request:<documentId>`（`{ v: 1, requestedAt? }`）不含内容与凭证；本机清理（退出登录、撤权）要把它们与 Univer 自己的存储一起列进去。
- **会话类失败的口径**：保存、续租、请求续期、本机密钥的取用遇到未登录、令牌失效时，只有连着的第一次在页面确认会话之后立即重试，之后按自己的节奏或退避；发件箱的上传照此。
- **请求的时限**：写请求、申请编辑权与本机锁争用时的核对都没有应用层的时限（DEF-041），要与"结果未知"的说明、离线时的行为一起设计。
- **服务端的事务限时**：`TransactionRunner.run` 的 `limit`（到点由数据库结束会话、开始得太晚不执行，都按数据库繁忙回 503）；别的写路径要依赖"事务短于某个时长"时照此用。让租约失效的写在类型上凭持锁的凭据（`LockedDocumentRow`、`LockedEditLease`，规范 §5）。
- **测试**：E2E 默认暂停定时的自动保存，容器 E2E 与 `E2E_AUTOSAVE=running` 按生产的节奏跑；时刻按数据库算的地方要有一条非 UTC 会话时区的用例（`startTestAppInTimeZone`）；真实 Safari 的页面自检 19 步、约 10 分钟，要用户空闲时跑，结果在 `tests/e2e/safari-results/`。
