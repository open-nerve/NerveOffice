## 与设计的偏差

都已回写 P3 设计（§9 变更记录）、M3 总设计、00 号计划书（r16）或 ADR：

- **快照检查改用子进程**（需求方 2026-10-05 决定）：S3 实测工作线程的 `resourceLimits` 不是可靠的隔离边界。设计原写工作线程；子进程的堆超限只结束子进程，服务照常。
- **审查之后的收紧**：
  - 链接判定只信任各引擎必然一致的部分：主机只收 LDH 与 IPv4、不收 IPv6；规范写法里空白、双引号、尖括号、反引号与 `|` 一律编码。
  - 规范化的空值等价只在资源 `data` 的第一层。
  - 一个 `requestId` 在修订记录与回执之间同样唯一（`RequestLedger`）。
  - 快照检查每个账户至多 2 份。
  - 执行期间被外部 SIGKILL 的子进程按"过于复杂"拒绝。
  - 内容相同时"公式待更新"只清不设。
  - 另存为副本的信封取页面的值。
- **E2E 的后端**把空闲连接的超时调到 10 分钟（测试进程复用连接的竞态，不影响生产配置）。

## 下一个 Phase 须知

- **P4（自动保存与打开自检）**：
  - **"公式待更新"**：页面在捕获没等到公式收齐时带上标记；服务端写入新内容时照请求记，内容相同时只清不设。带标记的文档进入编辑时先全量重算、收齐之后保存清掉（P4 做），阅读页的说明也在 P4。负载摘要计入标记：同一个 `requestId` 而标记不同就是另一个请求，重发结果未知的保存时连标记一起原样重发。
  - **`HYPERLINK()` 的格子没有 `v`**：按 `WHEN_EMPTY` 每次打开都重算；改写器让结果确定（`rangeId`、`paragraphId` 按位置），重算不改变内容。P4 的强制重算与"打开之后不改就不保存"的判断要把它算进去。
  - **自动保存的节奏与检查池**：同一个账户在快照检查里至多 2 份（执行与排队合计），多出来的回 503 带 `Retry-After`；一个页面的保存是串行的，同一个人同时开着多份文档时，自动保存要按 `Retry-After` 退避、原样重发（同一个 `requestId`），不要立即重试。
  - **`requestId`**：每次新的保存用新的 `requestId`；只有结果未知的重发用原来的（负载摘要要一致）。回执用过的 `requestId` 不能再拿去新建一类的请求，反之亦然。
  - **不兼容的终态**：转入 `CLIENT_OUTDATED`、`DOCUMENT_TOO_NEW` 时先核对结果没有着落的保存再定说法——结果未知的原样重发一次，续租得知时在途的先等它的结果（审查 B5、复验 C1）；另存为副本被拒、再试也一样时转入终态（审查 B3）。自动保存要接上这两处，不能在终态之后继续上传。
  - **副本与内存**：另存为副本期间子进程因瞬时的内存不足被外部 SIGKILL 时按"过于复杂"拒绝，这一页随之不再给副本（审查 A4 与 B3 叠加，复验 C6）；按部署说明的内存规则配好时几乎不会发生。
  - Safari 暂停看不见的页面（P2 S1 复核 F1）：自动保存在 `visibilitychange` 变成 hidden 时立即上传；开工前的真实 Safari 复核用 `safari:selftest --front`。
  - 自动保存是编辑行为的结果，不能标 `@BackgroundRequest()`（P2 交接单）。
- **M5**：图片在 M5 之前一律存不进去（服务端只接受相对的平台地址 `/api/assets/{uuid}`）：只读样本与测量用"去掉图片的样本"（`sampleWithoutImagesFor`），页面自检的进入与退出跳过带图片的入口；M5 开放图片时一并恢复。`SNAPSHOT_INVALID` 给出位置（DEF-052）。链接判定由命令守卫与粘贴清洗共用（同一个 `link-address.ts`），IPv6 的地址不收。
- **M6**：快照检查用的档案写死为表格（`INSPECTED_PROFILE`），M6 按文档类型选；页面上报的档案与文档类型目前不交叉核对（保存与另存为副本都一样，DEF-055），M6 加上。文字文档的 `settings.zoomRatio` 加进规范化的视图字段。
- **接口与约定**：
  - 新的写入路径凡是带 `requestId`，经 `RequestLedger`：事务的第一把锁是 requestId 的锁，锁下查修订记录与回执两张表（新建一类用 `lockForCreated`）。
  - 用快照检查的地方经 `requirePassingSnapshot` 传发起人（按账户的份数）。
  - 规范化的口径（contracts 的 `content-canonical.ts`）是格式：改动它就是数据格式的变更，测试向量与 `editor/testing/content-compare.ts` 要一起改；E2E 的"内容不变"按同一口径比较，更深层的空值变化会让 E2E 先失败。
  - 链接判定改动之后，跨引擎的用例表、逐字符扫描与性质检验（E2E）三个浏览器都要过。
- **已知的坑**：
  - 存量内容（P3 之前写下的）的第一次保存在锁下解析上一版，被拒的保存每次重新解析（审查 A8；v0.1 没有上线数据）。
  - `pnpm --filter @nerve-office/e2e run test -- <spec>` 不按 spec 过滤；只跑指定的 spec 时在 `tests/e2e` 下带 `NODE_OPTIONS=--conditions=@nerve-office/source` 直接 `npx playwright test`。
  - 测量与容器探针都要在机器空闲时跑。计时类的用例按 CPU 时间比较（`artifacts.test.ts` 的"不是平方级"改用 `process.threadCpuUsage`，`3e83d7f`；登录耗时的集成测试按进程的 CPU 时间），不要按墙上时间定比值的上限。
  - 链接判定"Node 收、浏览器不收"的两类（IDN 的 Unicode 版本、浏览器把 Bidi 核对到同一个域名里其余的标签）只影响收不收；E2E 的性质检验里"每个地址的结果与 Node 相同"成立是因为扫描里没有 RTL 字符，以后加进去时这条要放宽（复验 C5）。
