## 与设计的偏差

都已回写 P6 设计（各节的"实施"与 §9 变更记录）、ADR-019 或 00 号计划书 r19：

- **吊销的时刻**（审查 A1）：设计用数据库的 `now()`（事务开始的时刻），吊销在锁上等着时别的事务生成并提交了当前的那一把，`CHECK (revoked_at >= created_at)` 让合法的吊销 500；改为执行时的 `clock_timestamp()`，下一版生成于这一刻（不变量 I21），（复验 C2 之后）下一版的生成时刻在 SQL 里取上一版的 `revoked_at`，不经 JS 传时刻。审计的时刻仍是事务开始的时刻（全仓约定）：罕见的交错里审计页上两次吊销的先后可能与实际相反，按明细里的版本看。
- **应用全局关掉 Express 按响应体自动算的 ETag**（审查 A8）：取用的响应体就是原始密钥，ETag 是它的稳定指纹；接口的响应本来都是 `no-store`。读取内容的修订号 ETag 由那个接口自己写、静态文件由 `express.static` 管，不受影响。
- **账户页的状态列显示本机密钥的版本**（审查 B2，设计原来不推荐本期做）：在列表靠下的一行吊销时状态区不在可视区域里；吊销成功按响应换上这一行、接着刷新列表（复验 C1）。
- **焦点上方的内容变高之后把焦点滚回可视区域**（复验时发现的 N1，再复核 D1、D5）：页面顶部的状态区空着时不占位置，写进说明之后整页下移、三个浏览器都不补偿滚动，在可视区域底部附近做完操作时焦点交还的按钮被挤出屏幕（M2 起就有）。做成共用的 `useKeepFocusInView`（`ResizeObserver`，只在容器变高时滚、只滚排在它后面的焦点），`StatusRegion` 的 `keepFocusInView` 用它；账户页、成员页、转移页的状态区与转移页"有文档已经不在了"的说明接上，规范 §2.4 补一句。
- **确认框三版**（审查 B1）：停用的账户另一版——他的登录都已退出、重新启用之后旧密码照旧可用、启用之后立即生成重置链接；启用的确认框也提醒。
- **DEF-049 扩到同一类的四处**（S4）；**DEF-062 的做法**改为"Safari 一方加接口一方"（S5，两个账户都在 Safari 时盖屏会把两方一起暂停）。
- **真实 Safari 的前提改写**（S5）：P5 设计里"Safari 会暂停后台页面"对编辑中的编辑器页不成立（被别的应用挡住两分多钟照常心跳），请求方"只在看得见时自动进入"作为保守的做法保留。
- **合并前评审（Codex）之后**（P6 设计 §3.13，计划书 r20）：释放与交出先锁文档行、明确结束在类型上凭锁下的租约行（CX1）；本机锁的争用以服务端的事实裁决（`local-lock.ts`、租约的 `confirm`，CX2；复验之后另合上 E1–E3、E8、E9、E11）；吊销的响应分成本次的结果与账户的现状（CX3）；还没写进模型的输入合成一个状态算未保存与离开提示（`uncommitted-input.ts`，CX4）。

## 下一个 Phase 须知

P6 是 M3 的最后一个 Phase，下一步是 M4（本地优先与离线恢复）；M4 的须知见 `handoffs/M3-交接单.md`，这里只列本机密钥与 P6 特有的：

- **本机密钥的取用**：`POST /api/local-key`（不是 GET：第一把在第一次取时生成，要写；登录之后的 GET 一律在只读快照里，ADR-017），200 `{ version, key }`（`key` 是 32 字节的 base64），`no-store`；解不开回 500（主密钥对不上），页面按"暂时取不到"处理、不要重试成风暴。取用的会话类失败按 P5 交接单的口径（只有连着的第一次在确认会话之后立即重试）。
- **吊销的得知**：心跳的 200 带 `localKeyVersion`（从没取过为 null）；与内存里的版本不同 → 停用旧密钥、重新取、用新密钥重写当前内容（ADR-019"影响"）。阅读时的编辑状态不带版本，进入编辑、恢复与"另存为副本"之前先取一次。US-M3-17 的 E2E 里"页面上没有可见的反应"那几句（`specs/admin/local-keys.spec.ts` 的 `expectNoVisibleReaction`）要随 M4 的反应一起改。
- **主密钥**：只有应用进程要求它；命令行的配置里没有它（在应用容器里执行时进程环境里仍有）；容器 E2E 每次随机生成。找出要逐个吊销的人用部署说明里的 SQL。
- **焦点与插入的内容**：在长列表上方写进说明、插进提示的地方接共用的 `useKeepFocusInView`（或 `StatusRegion` 的 `keepFocusInView`），容器要一直在（空的时候可以不显示）；编辑器页不接（有焦点的可能是 Univer 的隐藏输入元素）。
- **测试**：时刻按数据库算的地方要有一条非 UTC 会话时区的用例（共用的 `startTestAppInTimeZone`）（照 `jobs/trash-purge.test.ts`、`local-keys.test.ts`、`documents.test.ts`、`login-throttle.test.ts` 的写法）；跨事务比较时刻的约束要想清楚"事务开始"与"执行时"的区别（A1）。真实 Safari 的页面自检共 19 步、约 10 分钟，要用户空闲时跑，结果在 `tests/e2e/safari-results/`。
