# M3-P5 交接规则：架构设计与实施规划

> 状态：进行中｜日期：2026-10-06｜所属：M3-P5｜依据：M3 总设计 §2.1 第 2 条（请求编辑没有回应时的做法）、§5（P5 一行）、§6.1、§6.2、US-M3-06 至 10，A20、A14；00 号计划书 §6.3、§6.4、§7.5（r17）；P1–P4 交接单的"P5 须知"；延期登记 DEF-042、DEF-044｜基于代码版本：`1c71ad2`（main：M3-P4 合并）

## 1. 目标与范围

编辑权按计划书 §6.3 交接：

- **空闲释放**（US-M3-07）：10 分钟没有键盘、鼠标操作，页面先保存再释放，回到阅读并说明；服务端 12 分钟兜底（已有）。
- **请求编辑与交出**（US-M3-06）：阅读者"请求编辑"；持有者已空闲满 2 分钟就先保存再自动交出，否则页头出现不打断输入的提示"交出 / 继续编辑"，不理会时一旦空闲满 2 分钟就交出；请求方可以取消；交出之后编辑权在一小段时间里只留给请求方，请求方的页面自动进入编辑；持有者的页面没有响应时按到期处理。
- **本人接管**（US-M3-08、DEF-042）：同一浏览器里用 Web Locks 判断正在编辑的标签页还在不在——在就让它先保存再交出，几秒没有回应就接手；不在（关了、刷新过、载入途中离开留下的孤儿租约）就立即接手。跨设备立即接手，旧页面失去编辑权、给副本。
- **强制接管**（US-M3-09）：空间管理员、个人空间的所有者，记审计；被接管的人给副本。系统管理员撤销登录之后编辑权随之结束（已有，补 E2E）。
- **异常中断提示**（US-M3-10、DEF-044）：编辑权因到期、空闲回收或登录失效而结束之后的 30 分钟内，申请编辑的人得到说明；审查 P1-A6 的三处坑一并收掉。

用户故事：US-M3-06 至 10；P5 结束时改为 active。

**不在本 Phase**：本机发件箱与 `steal` 之后的接手（M4，计划书 §7.5）；DEF-048、DEF-049（登记为"M3-P5 或 P6"的前端细节，放进 P6）；账户级的写频率限制（DEF-054，M7）。

## 2. 现状（`1c71ad2`）

两路设计前的探索（2026-10-06，`scratchpad` 的 `p5-explore-a.md`、`p5-explore-b.md`）给出的事实：

- **服务端的租约是完整的，P5 全部是加法**：一份文档一行（迁移 0022），七条有效条件按顺序取第一条不满足的作为原因（`edit-lease-rules.ts`），申请、心跳、释放、编辑状态四个接口，保存在文档行锁下不加锁读租约行，收回写入权接上租约，锁的顺序"文档行 → 租约行 → 审计"。
- **`interruption` 只算出来、没人用**：申请的响应里有，页面一处没用，编辑状态里没有；审查 P1-A6 的三处坑都在——"先到期、后被移动"不提醒被单元测试钉成了预期（`edit-lease-rules.test.ts:219-221`），收回写入权把已经到期的租约也记 `revoked`、加代次（`lockInScope` 只筛"没有明确结束"，DEF-044 的根），自己续上会得到关于自己的提醒。
- **被接管的旧页面只能得到 `replaced`**：新的申请整行改写，旧的一代没有记录；页面把 `replaced` 当作能续上的原因，被接管之后会先去续上，说法是带"90 秒"建议的那一句。
- **页面能直接复用的**：`exit()` 的"挂起调度 → 等面板 → flush → 等在途 → 捕获 → 释放（≤5 秒）→ 以只读重建"正是空闲释放与交出要的骨架；交互屏障随 `switching()` 的模式挂上；`flush('handover' | 'idle-release')` 与 `saved()` 已就位（P4）；失去编辑权之后的副本与放弃（`lost-copy.ts`）照用。
- **页面要改的**：心跳的响应没有请求信息；阅读时的检查间隔是常量 30 秒；`exit()` 要求公式收齐（交出与空闲释放按 P4 可以带标记）；别人在编辑时页头仍显示"编辑"；文案与 E2E 里写死的"最多 90 秒后自动结束"；`trackActivity` 不看 `isTrusted`、不滤零位移的 `pointermove`。
- **浏览器能力**（Playwright 1.63 的 Chromium、Chrome 154、WebKit 实测）：同一个浏览器上下文的两个页面共用 Web Locks 与 BroadcastChannel，不同上下文完全隔离（可以模拟跨设备）；持锁的页面关闭、刷新、导航离开之后 1–13 ms 锁就放开，它在 `pagehide` 里发的广播先到；`steal` 立即生效，被抢的一方以 `AbortError` 结束；页面主线程卡住时抢锁照样成功，恢复之后排着的广播与 `AbortError` 一起到；`page.clock` 是上下文级的；**Playwright 模拟不了真正的隐藏与冻结**（"旧标签页不响应"改用只给那一页装 `addInitScript` 吞掉频道消息）；WebKit 在鼠标不动、页面被程序滚动时派发零位移的可信 `pointermove`。
- **真实 Safari**：看不见的页面约 6 秒之后整页暂停（P2-S1 F1）；暂停期间也不处理消息是推测——同一浏览器的"先保存再交出"在 Safari 上多半走到"没有回应就接手"，数据靠 P4 的"切到后台立即上传"兜住。

## 3. 设计

### 3.1 总规则

1. **服务端是唯一的权威**：谁有编辑权只看租约；Web Locks 与 BroadcastChannel 只用来在同一个浏览器里判断"那个标签页还在不在"、让它先保存再交出、并让被抢的一方立即得知。
2. **先服务端、后本机锁**：正在编辑（服务端批准之后直到离开编辑）的标签页持有 `nerve-doc:<documentId>`（计划书 §7.5 的锁名）。拿锁一律在服务端批准之后：锁空着用 `ifAvailable`；被本浏览器的别的标签页占着就 `steal`——服务端既然批给了这一页，那一页的租约必然已经失效。被抢（`AbortError`）的一方不再问服务端、不续上，直接转为失去编辑权。这是对计划书 §7.5"以 `ifAvailable` 申请"的细化（M3 没有发件箱，锁不挡写入；M4 的写入栅栏在它之上），00 号计划书 r18 写明。
3. **离开编辑一律先挡住输入再保存**：空闲释放、交出、本人接管时的交出与退出编辑同一个流程（`leaveEditing(cause)`），先挂交互屏障、挂起定时的捕获与上传，再 `flush`（P4 的约定：提交哪一次单元格编辑在调用的那一刻定）。
4. **新的写请求遇到会话类失败**照 P4 的口径（交给页面确认会话；只有连着的第一次在确认之后立即重试）。

### 3.2 数据模型与迁移 0025

`document_edit_leases` 加列（都可空，存量都是空的；只做加法，不回填）：

| 列 | 说明 |
|---|---|
| `request_id` uuid | 待回应或已谢绝的请求的标识 |
| `requested_by` uuid（FK users restrict） | 请求方 |
| `request_session_id` uuid | 请求方的登录（不做外键，同 `session_id`） |
| `requested_at`、`request_expires_at` timestamptz | 发出的时刻；有效期（请求方每次续期往后推） |
| `request_declined_at` timestamptz | 持有者选了"继续编辑" |
| `reserved_for` uuid（FK users restrict）、`reserved_until` timestamptz | 交出之后留给谁、留到何时 |
| `taken_over_token_digest` bytea、`takeover` text | 这一代接管的那一代的令牌摘要与方式（`self`、`forced`） |

CHECK：请求的五列（不含谢绝）同空同有，谢绝只在有请求时有值，`request_expires_at > requested_at`，`requested_by <> holder_id`；保留的两列同空同有，有保留时 `end_reason = 'handed_over'`；接管的两列同空同有，摘要 32 字节，`takeover IN ('self','forced')`；`end_reason` 加 `handed_over`。审计的 `audit_events_action_check` 按 0023 的写法全量重列，加 `documents.edit_taken_over`。不加索引（都按主键找）。

### 3.3 契约（`packages/contracts`）

- **常量**（与计划书 §6.3 的起始参数对应）：`EDIT_IDLE_RELEASE_SECONDS = 600`（页面的空闲释放）、`EDIT_HANDOVER_IDLE_SECONDS = 120`（有请求时空闲满 2 分钟自动交出）、`EDIT_HANDOVER_RESERVE_SECONDS = 120`（交出之后的保留）、`EDIT_REQUEST_TTL_SECONDS = 600`（请求方停止续期 10 分钟后请求失效）、`EDIT_REQUEST_RENEW_SECONDS = 5`（等待中的续期间隔）、`EDIT_TAB_HANDOVER_ACK_MS = 3000`、`EDIT_TAB_HANDOVER_DONE_MS = 20_000`（同一浏览器的交接：回应与完成的时限）、`EDIT_PENDING_SAVE_WAIT_MS = 30_000`（§3.7 的 R1）。
- **失效原因**加 `handed_over`、`taken_over`（详情另带 `forced: boolean`）；页面把它们排除在续上之外。
- **申请**加 `takeover?: 'self' | 'force'`、`idleSeconds?`（只给续上用，最后活动写成 `now() - idleSeconds`）。
- **编辑状态**加 `canTakeOver`、`request`（待回应的请求：请求方、时刻、`mine`）、`reservation`（留给谁、到何时、`mine`）、`interruption`（`{ holder, endedAt, sameUser } | null`）；`editor` 加 `sameSession`（持有者的租约绑定的就是调用者这次登录 ⇔ 同一个浏览器）。`EDIT_LEASE_HELD` 的详情与 `editor` 同一个结构，另带 `canTakeOver`、`request`。
- **心跳的响应**加 `request: { id, requester, requestedAt } | null`（只给待回应的）。
- **请求的结果**（`EditRequestOutcome`，按 `kind` 区分）：`pending`（等待；带有效期与持有者）、`declined`、`reserved`（交给你了：立即申请）、`free`（没人在编辑：立即申请）、`self`（是你自己在编辑：改用本人接管）、`occupied`（别人先请求了）、`reservedForOther`、`gone`（只出现在续期：我的请求已不在，例如换了一代）。
- **错误码**：`EDIT_LEASE_RESERVED`（409，详情 `{ reservedFor, reservedUntil }`）、`EDIT_REQUEST_GONE`（409，交出时请求已不在，租约不动）。
- **审计**：`documents.edit_taken_over`，明细 `{ holderId }`；admin 的动作文案。
- **权限**：`DocumentPermissions` 加 `canTakeOver`（空间管理员；个人空间是所有者；归档时没有），`DOCUMENT_CONTENT` 加操作 `takeOver`——与分享、跨空间移动同一个机制，不借用 `canShare`。

### 3.4 接口

都挂在 `DocumentEditingController`（`documents/:id/edit-lease`）；workspace 开事务、补人名，documents 的 `EditLeaseService` 管规则与数据。都先判断访问（404 在 403 之前），看不到的不读租约行、不取锁，语句序列与不存在的文档相同。

| 方法与路径 | 谁 | 请求 | 成功 | 主要错误 | 后台请求 |
|---|---|---|---|---|---|
| `GET …/edit-lease` | 能读 | — | 200 编辑状态（加字段） | 404 | 是（不变） |
| `POST …/edit-lease` | 能编辑；`force` 另要 `takeOver` | `{ clientInstanceId, takeover?, idleSeconds?, …格式 }` | 201（不变） | 403、409 `EDIT_LEASE_HELD`（详情加字段）、409 `EDIT_LEASE_RESERVED`、409 `CLIENT_OUTDATED`/`DOCUMENT_TOO_NEW`、401 | 否 |
| `PUT …/edit-lease` | 能编辑，令牌 | 不变 | 200 `{ expiresAt, request }` | 409 `EDIT_LEASE_LOST`（新原因） | 是（不变） |
| `DELETE …/edit-lease` | 能读，令牌 | — | 204 | — | 否（不变） |
| `POST …/edit-lease/handover` | 能编辑，令牌 | `{ requestId }` | 200 `{ reservedFor, reservedUntil }` | 409 `EDIT_REQUEST_GONE`（租约不动）、409 `EDIT_LEASE_LOST`、401 | 否 |
| `POST …/edit-lease/request` | 能编辑 | `{ …格式 }` | 200 请求的结果（除 `gone`） | 403、409 `CLIENT_OUTDATED`、401 | 否 |
| `PUT …/edit-lease/request` | 能编辑 | — | 200 请求的结果（没有就是 `gone`） | 403、401 | **是** |
| `DELETE …/edit-lease/request` | 能读 | — | 204（清我的请求与留给我的保留） | — | 否 |
| `POST …/edit-lease/request/decline` | 能编辑，令牌 | `{ requestId }` | 204（对不上也 204） | 409 `EDIT_LEASE_LOST`、401 | 否 |

各操作按"同一个人的同一件事"天然幂等，不需要 `requestId` 的账本：请求已有就续期；谢绝、取消对不上就什么也不做；交出的重试得到 `handed_over`；接管时同一个页面的重试走"同一个页面"那条路，不再写审计。写的一侧在事务里按主键核对登录（P1 的约定）。

### 3.5 有效条件、异常中断与 DEF-044

- **异常结束按事实判断**：没有明确结束，并且已到期、空闲满 12 分钟或绑定的登录失效——代次过时不再遮住它（P1-A6 第 1 处；`edit-lease-rules.test.ts:219-221` 的预期有意改掉）。代次过时但按时间、登录都还活着的（刚被移走、持有者的页面正在续上）不算。
- **收回写入权只锁"按时间还活着"的租约**（`lockInScope` 加 `expires_at > now()` 与空闲不满 12 分钟，边界与有效条件逐一相同）。按时间已死的租约不可能再被续租或用来保存（心跳与保存都先判到期），不必记 `revoked`、不必加代次——提醒因此保留，撤权也不再锁一批历史文档行（DEF-044 的两半；关闭）。仍会被记 `revoked` 的只剩"登录已失效但还没到期"的，最长 90 秒。`lease-revocation-locks.test.ts` 里靠"已到期的租约"构造交错的那一条改用"登录失效但未到期"。
- **提醒带 `sameUser`**（P1-A6 第 3 处）：页面按它分别说"上一位编辑者 [人名] 的会话异常中断……"与"你上一次的编辑异常中断……"；只在用户发起的申请（"编辑""在此编辑""强制接管"、请求被批准之后的自动进入）里显示，续上不显示。编辑状态里也给出（没人在编辑时），阅读页不必等点"编辑"。
- **交出、接管、释放、空闲释放都是明确结束**，不给提醒。
- **跨空间移动之后的窗口**（探索 R2，P1 起就有）：代次过时、而按时间、登录、编辑权都还活着、持有者不是申请人时，对别人按"被占用"回答，只让持有者本人续上——P5 的等待中的请求方会自动申请，命中这个窗口的概率变大。
- **空闲的兜底计时准确**（复验 P1-C5）：申请可带 `idleSeconds`（续上时带本页的空闲），心跳的最后活动只前进不后退。

### 3.6 请求编辑与交出（US-M3-06）

**服务端**：

- 请求记在租约行上，**单槽、先到先得**：后来的人得到 `occupied`（详情给先请求的人与时刻），已谢绝或已失效的请求不占槽。同一个人再发：有待回应的就续期；已被谢绝时显式再点一次会换成新的请求。
- 请求是一份"小租约"：`POST` 发出（用户操作，顺延登录；按页面上报的格式先拦旧页面）；等待中的页面每 5 秒 `PUT` 续期（后台请求，响应就是请求的现状）；`DELETE` 取消（`pagehide` 时 `keepalive` 尽力发）。**请求方停止续期 10 分钟后请求失效**——请求方的页面崩溃、合盖、被 Safari 暂停时 `pagehide` 不一定触发；持有者不理会时请求照样一直有效（计划书 §6.3），只是请求方的页面不在了才失效，免得持有者空闲 2 分钟之后把编辑权交给一个没人的页面。
- 请求绑定请求方那次登录，用到时判断登录还在、仍能编辑；收回写入权不需要另外处理请求方。
- 换了一代时：新的持有者还是同一个人（重试、续上、本人接管）就沿用请求（含已谢绝的状态）；换了别人就清掉（请求方续期得到 `gone`）；新的持有者就是请求方，请求已经实现，清掉。
- **交出**：持有者 `flush('handover')` 存上之后 `POST …/handover { requestId }`。只锁租约行（与释放同一类），锁下核对登录、令牌、请求仍有效且 `id` 对得上：结束原因记 `handed_over`，写下保留（留给请求方 2 分钟），请求转成保留。请求已经不在：409 `EDIT_REQUEST_GONE`，租约不动，持有者留在编辑。普通的释放不隐式变成交出。
- **保留期内**除被保留的人之外一律 409 `EDIT_LEASE_RESERVED`（强制接管也挡，最多 2 分钟）；被保留的人用哪个标签页、哪次登录都行（按人，不按页面）。保留有效 = 没过期，且被保留的人仍能编辑。
- **谢绝**：`POST …/request/decline { requestId }` 记谢绝的时刻；请求方下一次续期得到 `declined`。

**页面（请求方）**：

- 持有者是别人、自己能编辑时，"编辑"换成"请求编辑"；能强制接管时并列"强制接管"（§3.8）。持有者的信息来自阅读时的检查或 409，可能过时：仍点得到"编辑"时照旧处理 409。
- 发出之后按钮换成"取消请求"；读屏的状态区说"已请求编辑，等待 [人名] 回应。[人名] 停下操作 2 分钟后会自动保存并交给你；你也可以取消请求"（不倒计时）。等待中每 5 秒续期；页面隐藏时浏览器自己会降频，回到前台立即续期一次。
- 结果：`reserved` 或 `free` → **只在页面看得见时**自动进入编辑（Safari 会暂停后台页面，抢到的编辑权会因心跳停了而到期）；后台时回到前台再进，保留期过了而编辑权空着时照样进入（请求的意图还在）；`declined` → "[人名] 选择继续编辑，你的请求已取消"（不能强制接管的人另说"着急时可以请空间管理员强制接管"）；`occupied` → "[人名] 已在请求编辑"；`self` → 改为"在此编辑"。
- 等待中的页面空闲满 10 分钟就取消请求（人走了，免得编辑权交给他之后空占）。

**页面（持有者）**：

- 心跳的响应带来请求 → 编辑模式记下；本页空闲满 2 分钟（起点 = 最后一次操作与进入编辑中较晚的那个）就自动交出；否则在页头下面显示提示，提示在的时候一旦空闲满 2 分钟同样自动交出。
- 提示是带标题的分组（`role="group"`，`aria-labelledby` 指向"[人名] 请求编辑这份文档"），两个按钮"交出""继续编辑"，一行静态说明"你停下操作 2 分钟后会自动保存并交给对方"；不是对话框、不是 `alert`、不新插入 `role="status"`；**出现时不移动焦点、不挂屏障**，单元格编辑与输入法照常；读屏在一直在的状态区里礼貌地播一次。
- 交出：`leaveEditing('handover-request')`（§3.10）→ 存上（公式没收齐也可以，带"公式待更新"）→ 交出 → 以只读重建 → 阅读，"已保存并把编辑权交给了 [人名]"。没存上就留在编辑，说明原因，请求照旧在。`EDIT_REQUEST_GONE` → 留在编辑，"[人名] 已取消请求"。
- 继续编辑：谢绝 → 提示消失。
- **退出编辑与关页时有待回应的请求**：用交出代替释放（关页时 `keepalive` 的交出；保存在途时照 P4 不释放、也不交出）。

### 3.7 本人接管（US-M3-08、DEF-042）

**服务端**：申请加 `takeover: 'self'`，只在当前有效的租约的持有者就是调用者时生效——同一个事务里（文档行 → 租约行）代次加一、整行改写成新的一代，并记下接管标记（被接管那一代的令牌摘要、`self`）。旧令牌的心跳、保存、交出、谢绝因此得到 `taken_over`（`forced: false`），不再是笼统的 `replaced`。持有者是别人时不起作用（照常 `EDIT_LEASE_HELD`）；当前的租约本来就无效时按普通申请处理。同一个页面的重试沿用上一代的接管标记。不写审计。

**页面**：编辑状态说持有者是自己时，`navigator.locks.query()` 看锁在本浏览器里有没有人持有：有 → "你在本浏览器的另一个标签页里正在编辑这份文档"；没有 → "你在另一台设备或浏览器上正在编辑这份文档（也可能是刚关闭、刷新过的页面）"。按钮一律是"在此编辑"（换掉"编辑"）。

"在此编辑"的流程（新标签页 B）：

1. **锁在本浏览器里没人持有**（跨设备、另一个浏览器或配置文件、刚关闭或刷新过的页面、DEF-042 的孤儿租约）：以 `takeover: 'self'` 申请 → 拿锁（`ifAvailable`）→ 以可编辑重建。说明里写清那边会失去编辑权。
2. **锁被本浏览器的标签页 A 持有**：经交接频道 `nerve-office:doc:<documentId>` 发 `handover-request`，按钮说"正在接手…"：
   - 3 秒内收到 A 的 `ack`：等 A 做完（以等锁为信号，`AbortSignal.timeout`，另收 `done`、`failed`），完成的时限 20 秒；拿到锁之后申请（A 的释放没送到、得到 `sameUser` 的 409 时改用 `takeover: 'self'`）→ 重建。
   - 收到 `failed`（A 保存失败、冲突、会话不对）：说明原因，给"仍在此编辑"（那边没保存的修改可以在那边另存为副本）与"取消"。
   - 3 秒内没有 `ack`（冻结、Safari 暂停、页面卡住）：以 `takeover: 'self'` 申请 → 成功之后 `steal` 锁 → 重建。
3. **A 收到 `handover-request`**：只理会同一个人的，而且自己确实还持有锁（被抢之后迟到的请求一律不理）；`editing` 时在消息处理里同步回 `ack`，然后 `leaveEditing('handover-tab')` → 存上就释放 → 放锁 → 发 `done` → 阅读，"已在本浏览器的另一个标签页接着编辑"；没存上就发 `failed`、留在编辑。`exiting` 时回 `ack`、照常退出；`entering` 时回 `busy`，B 稍后再试。
4. **A 的锁被抢**（`AbortError`）：立即转为失去编辑权（"你在本浏览器的另一个标签页接手了编辑"），有没保存的修改照旧给副本与放弃。
5. **跨设备的旧页面**：下一次心跳（≤10 秒）或保存得到 `taken_over` → 不续上 → 失去编辑权（"你在另一台设备或浏览器上接手了编辑"），给副本。

**刷新时在途的保存（探索 R1）**：P4 让"`pagehide` 时有在途的保存不释放"，那次保存要能提交；P5 的立即接手会结束旧的一代，那次保存如果还在服务端检查快照或等锁，会被 `taken_over` 挡掉——旧页面已经没了，修改无声丢失。做法：旧标签页在 `pagehide` 时保存忙，就在 `localStorage` 记下 `nerve-office:pending-save:<documentId>` 与时刻（同步写；不可用时跳过）；新标签页在"锁空着、本人接管"之前看到 30 秒内的记号，就先等——每 2 秒读一次编辑状态，修订号前进了（那次保存提交了）或者到 30 秒就接手，期间说"上一个页面的保存还在进行，稍后接手…"；接手之后清掉记号。记号只在同一个浏览器里起作用，正好覆盖这个情形（跨设备的旧页面还在，被接管之后自己给副本）。

### 3.8 强制接管（US-M3-09）

- **谁**：`canTakeOver`（空间管理员；个人空间是所有者；归档的空间里没有；只凭授权的人没有）。申请按 `['edit', 'takeOver']` 判断，不加锁一次、锁下一次。
- **怎样**：`takeover: 'force'`。当前有效的租约在别人手里：代次加一、改写成管理员的新的一代，接管标记记 `forced`，在同一个事务里写审计 `documents.edit_taken_over`（操作者、文档、`{ holderId }`、来源），排在租约行之后。持有者就是自己：当作本人接管，不写审计；没有有效的租约：普通申请，不写审计；保留期内被挡。有请求在等的一并清掉。
- **页面**：阅读时、别人持有编辑权时，"请求编辑"旁边的"强制接管"（`variant="outline"`）；`ConfirmDialog` 确认（destructive）："[人名] 正在编辑（最后活动 x 分钟前）。强制接管会立即结束他的编辑权：他还没保存的修改不会写进这份文档，他可以在自己的页面上另存为副本。这次操作会记入审计。"；结果的说明等确认框关掉、焦点交还之后再写（规范 §2.4）。
- **被接管方**：心跳或保存得到 `taken_over`、`forced: true` → 不续上 → "编辑权已失效：空间管理员强制接管了编辑"（接管人由转为阅读之后读一次编辑状态得到）；副本与放弃照旧。
- **系统管理员**：签发重置链接或停用账户 → 持有者的租约因登录失效而无效 → 下一个申请的人看到异常中断的提示（`session` 属于异常结束）。补 E2E。

### 3.9 空闲释放（US-M3-07）

- **计时**：一个截止时刻的计时器（`max(最后一次操作, 进入编辑的时刻) + 10 分钟`），到点重算；只在 `editing` 时排。"有操作"沿用 `trackActivity`，加两条过滤：只认可信事件（`isTrusted`）；零位移的 `pointermove` 不算（WebKit 在页面被程序滚动时派发它，不滤的话"10 分钟没有操作"永远到不了）。
- **后台**：Chrome 隐藏的页面计时器降频，空闲释放最多晚约一分钟；Safari 隐藏约 6 秒后计时器停止——**回到前台时**（`visibilitychange` 变成 visible 的处理里同步判断）按隐藏之前的最后一次操作算空闲，满 10 分钟就走空闲释放，并且不再续上（释放开始的那一刻就让租约停止续上，免得 `dormant` 被回来时的操作叫醒）。
- **流程**：`leaveEditing('idle')`：屏障 → 挂起 → 等面板 → `flush('idle-release', { ready: confirmedForWrite })`（不主动向服务端确认会话；会话不对时这一轮不释放，交给服务端 12 分钟兜底）→ 等在途 → 存上（公式没收齐照样释放，带"公式待更新"）→ 释放 → 放锁 → 以只读重建 → 阅读，说明"10 分钟没有操作，已保存并释放编辑权"。**没存上就留在编辑**（保存的状态本来就在说失败的原因），过一个心跳周期再判断；一直存不上时由服务端 12 分钟兜底，人回来时按 P1 的续上处理。
- 自动进入编辑的人（请求被批准）另有完整的 10 分钟（起点取进入编辑的时刻）。

### 3.10 页面：模块与状态

新模块（都不依赖 Univer，时钟与浏览器 API 注入，用假的做单元测试；浏览器的实现只在组装处给出，与 `browserLeaseClock`、`openSessionChannel` 同一个做法）：

| 模块 | 职责 |
|---|---|
| `same-browser.ts` | Web Locks 与交接频道的薄适配：`tryHold()`（`ifAvailable`）、`steal()`、`heldHere()`（`query()`）、持有的句柄（`release()`、被抢时兑现的 `stolen`）；频道的收发与消息解析（版本化、按 `requestId` 配对、解析失败一律忽略；用 `addEventListener('message')`） |
| `idle-watch.ts` | 截止时刻的计时器；回到前台按隐藏之前的操作算 |
| `edit-request.ts` | 请求方一侧的状态（发出、等待、取消、被谢绝、留给我）与续期节奏 |
| `pending-save-marker.ts` | §3.7 的记号：写、读、清（`localStorage` 不可用时什么也不做） |
| `edit-mode.ts`（改） | `exit()` 重构为 `leaveEditing(cause)`，`cause` 是 `exit`、`idle`、`handover-request`、`handover-tab`（退出要求公式收齐，其余可以带标记）；新的失效与说明；把上面几个接起来 |

状态的扩展：`exiting` 带 `cause`（页头按它说）；`editing` 带 `request?`（持有者一侧）与 `interruption?`；`reading` 带 `request`（请求方一侧）、`selfHolder?: 'this-browser' | 'elsewhere'`、`takeover`（"在此编辑"的进展）、`canTakeOver`；`LeaseLoss` 加 `taken-over`（`this-browser` 或 `elsewhere`）与 `forced`；阅读的说明加 `idle-released`、`handed-over`、`request-declined`、`takeover-failed`。

阅读时的检查（`reading-checks.ts`）照旧 30 秒；等待请求时由 `edit-request.ts` 的 5 秒续期接手，不另起读编辑状态的轮询。

### 3.11 页头、文案与读屏

- 进行中的按钮不卸载、`aria-disabled`、`aria-busy`；随状态消失的按钮由 `useFocusRescue` 接住（规范 §2.4）。
- 说明一律放进一直在的 `StatusRegion` 或保存状态的播报区，不新插入 `role="status"`；不用 `assertive`。
- 去掉"最多 90 秒后自动结束，到时再点'编辑'"一类的建议（`SELF_ELSEWHERE_HINT`）——有了"在此编辑"之后它不再成立；E2E 里写死它的断言随之改。
- 异常中断的说明：进入编辑之后页头下面一条不打断的说明，带"知道了"，退出编辑时消失；时刻按页面的时区写成"HH:mm"（不是今天时加日期），只格式化服务端的时刻，不与浏览器的时钟比较。

### 3.12 锁的顺序与确定交错

- 不新增锁的种类，锁顺序表不变（…文档行 → 租约行 → 审计）。申请（含本人接管、强制接管）：文档行 → 租约行 → 审计。请求的发出、续期、取消、谢绝、交出：**只锁租约行**，锁住之后再读文档的代次（与心跳、释放同一个做法）。
- 保存在文档行锁下不加锁读租约行，仓储的注释要求"在不锁文档行的路上改别的列之前先重新论证"：新的不锁文档行的写路径只改"结束"两列与保留两列（交出，性质同释放）、请求列（请求、谢绝、取消），都不改持有者、令牌、代次；保存也不读请求与保留——原来的线性化论证照样成立（写进 ADR-018 的补充与仓储注释）。
- 每个新写路径的确定交错（`raceAgainstHeldLock`）：接管 vs 旧持有者的保存（两种先后）、接管 vs 旧持有者的心跳、接管 vs 交出、两个管理员同时强制接管、强制接管 vs 管理员被降级、交出 vs 请求方取消、交出 vs 第三人申请、两个请求方同时发出、请求的续期 vs 持有者自己的新一代、请求的续期 vs 第三人在到期之后申请、谢绝 vs 取消、收回写入权的时间条件。

### 3.13 错误处理、安全与可观测性

- 看不到与不存在一致：每个新路由进"看不到 / 不存在"的核对（外人、回收站里的、只凭授权的人），`takeover` 的两种取值也加。
- 强制接管记审计；交出、本人接管不记（总设计只要求强制接管记审计）。
- 后台请求清单只加 `PUT …/request`；请求、取消、谢绝、交出、接管是用户的操作，顺延登录。
- 令牌只在请求头；接管标记只存摘要；交接频道的消息不带令牌，只带 `documentId`、`requestId`、标签页标识与用户 id（同一个浏览器里本来就同一个人）。
- 页面记 debug 级的诊断（交接的各步与时刻），不上报。

### 3.14 真实 Safari 的复核

页面自检加一个两个标签页的场景（驱动脚本已有"另开标签页让编辑器页隐藏"的做法）：A 编辑、键入 → 另开 B（同一会话）→ 等 8 秒后 B 点"在此编辑"——记下有没有 `ack`、多久进入编辑、服务器上的内容与代次；能做到时切回 A 核对它的失效说明。与 Playwright 不同时按真实 Safari 调整回应时限与说法。报告 `reviews/P5-真实Safari复核.md`。

## 7. 风险与未决问题

| 风险 | 应对 |
|---|---|
| Safari 暂停后台页面：同一浏览器的"先保存再交出"多半走到"没有回应就接手"，请求编辑的"自动交出"多半走到到期 | 正确性靠代次、抢锁与 P4 的"切到后台立即上传"；真实 Safari 复核（§3.14）；说法如实 |
| Playwright 模拟不了真正的隐藏与冻结 | 这些分支用单元测试（假频道永远不回、恢复之后广播与 `AbortError` 两种先后）；E2E 用只给那一页装的"吞消息"注入（生产构建也能用） |
| 刷新时有保存在途、很快"在此编辑"，那次保存被新的一代挡掉（探索 R1） | `pending-save` 记号与最多 30 秒的等待（§3.7）；`localStorage` 不可用时退回立即接手（写进已知限制） |
| 跨空间移动之后的窗口里别人抢先申请（探索 R2，P1 起就有；等待中的请求方会自动申请） | 代次过时但其余都还活着时对别人按"被占用"回答（§3.5） |
| 收回写入权的语义变了（死租约不再记 `revoked`、不加代次） | 有安全论证（§3.5）；现有交错用例改构造；写进 ADR-018 与 ADR-014 的补充 |
| 请求方的页面不在了（崩溃、合盖、Safari 暂停）而请求还在，持有者把编辑权交给没人的页面 | 请求方停止续期 10 分钟后请求失效；`pagehide` 尽力取消；保留期 2 分钟之后谁都能编辑 |
| 后台节流让请求方错过 2 分钟的保留 | 回到前台时编辑权空着照样自动进入（请求的意图还在） |
| WebKit 的零位移 `pointermove` 让空闲永远到不了 | 过滤（§3.9） |
| 系统休眠时 `performance.now()` 可能不走，空闲少算 | 影响小（用户刚回来）；写进已知限制 |
| 交出、空闲释放之后还有输入随销毁丢失 | 一律先挂屏障再 `flush`（§3.1 第 3 条） |
| 恢复之后迟到的交接请求让已被抢的旧页面误操作 | 处理交接请求之前确认自己仍持有锁；消息按 `requestId` 配对、只认本人 |
| 现有 E2E 的说法与流程要改；E2E 变多（两个、三个上下文，三个浏览器） | 在 S6 里集中改，审查时核对没改掉原意；用时钟不真等；看 CI 分片的时长 |
| 租约行变宽（10 个新列） | CHECK 兜住组合；仓储的改写集中在按用途命名的方法里；单元测试逐列核对改写与沿用 |
