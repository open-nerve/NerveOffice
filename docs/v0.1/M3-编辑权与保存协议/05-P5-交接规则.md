# M3-P5 交接规则：架构设计与实施规划

> 状态：已完成｜日期：2026-10-06｜所属：M3-P5｜依据：M3 总设计 §2.1 第 2 条（请求编辑没有回应时的做法）、§5（P5 一行）、§6.1、§6.2、US-M3-06 至 10，A20、A14；00 号计划书 §6.3、§6.4、§7.5（r17）；P1–P4 交接单的"P5 须知"；延期登记 DEF-042、DEF-044｜基于代码版本：`1c71ad2`（main：M3-P4 合并）

## 1. 目标与范围

编辑权按计划书 §6.3 交接：

- **空闲释放**（US-M3-07）：10 分钟没有键盘、鼠标操作，页面先保存再释放，回到阅读并说明；服务端 12 分钟兜底（已有）。
- **请求编辑与交出**（US-M3-06）：阅读者"请求编辑"；持有者已空闲满 2 分钟就先保存再自动交出，否则页头出现不打断输入的提示"交出 / 继续编辑"，不理会时一旦空闲满 2 分钟就交出；请求方可以取消；交出之后编辑权在一小段时间里只留给请求方，请求方的页面自动进入编辑；持有者的页面没有响应时按到期处理。
- **本人接管**（US-M3-08、DEF-042）：同一浏览器里用 Web Locks 判断正在编辑的标签页还在不在——在就让它先保存再交出，几秒没有回应就接手；不在（关了、刷新过、载入途中离开留下的孤儿租约）就立即接手。跨设备立即接手，旧页面失去编辑权、给副本。
- **强制接管**（US-M3-09）：空间管理员、个人空间的所有者，记审计；被接管的人给副本。系统管理员撤销登录之后编辑权随之结束（已有，补 E2E）。
- **异常中断提示**（US-M3-10、DEF-044）：编辑权因到期、空闲回收或登录失效而结束之后的 30 分钟内，申请编辑的人得到说明；审查 P1-A6 的三处坑一并收掉。

用户故事：US-M3-06 至 10；P5 结束时改为 active。

**不在本 Phase**：本机发件箱与 `steal` 之后的接手（M4，计划书 §7.5）；DEF-048、DEF-049（登记为"M3-P5 或 P6"的前端细节，放进 P6）；账户级的写频率限制（DEF-054，M7）。

## 2. 现状（`1c71ad2`）

两路设计前的探索（2026-10-06，`scratchpad` 的 `p5-explore-a.md`、`p5-explore-b.md`）给出的事实：

- **服务端的租约是完整的，P5 全部是加法**：一份文档一行（迁移 0022），七条有效条件按顺序取第一条不满足的作为原因（`edit-lease-rules.ts`），申请、心跳、释放、编辑状态四个接口，保存在文档行锁下不加锁读租约行，收回写入权接上租约，锁的顺序"文档行 → 租约行 → 审计"。
- **`interruption` 只算出来、没人用**：申请的响应里有，页面一处没用，编辑状态里没有；审查 P1-A6 的三处坑都在——"先到期、后被移动"不提醒被单元测试钉成了预期（`edit-lease-rules.test.ts:219-221`），收回写入权把已经到期的租约也记 `revoked`、加代次（`lockInScope` 只筛"没有明确结束"，DEF-044 的根），自己续上会得到关于自己的提醒。
- **被接管的旧页面只能得到 `replaced`**：新的申请整行改写，旧的一代没有记录；页面把 `replaced` 当作能续上的原因，被接管之后会先去续上，说法是带"90 秒"建议的那一句。
- **页面能直接复用的**：`exit()` 的"挂起调度 → 等面板 → flush → 等在途 → 捕获 → 释放（≤5 秒）→ 以只读重建"正是空闲释放与交出要的骨架；交互屏障随 `switching()` 的模式挂上；`flush('handover' | 'idle-release')` 与 `saved()` 已就位（P4）；失去编辑权之后的副本与放弃（`lost-copy.ts`）照用。
- **页面要改的**：心跳的响应没有请求信息；阅读时的检查间隔是常量 30 秒；`exit()` 要求公式收齐（交出与空闲释放按 P4 可以带标记）；别人在编辑时页头仍显示"编辑"；文案与 E2E 里写死的"最多 90 秒后自动结束"；`trackActivity` 不看 `isTrusted`、不滤零位移的 `pointermove`。
- **浏览器能力**（Playwright 1.63 的 Chromium、Chrome 154、WebKit 实测）：同一个浏览器上下文的两个页面共用 Web Locks 与 BroadcastChannel，不同上下文完全隔离（可以模拟跨设备）；持锁的页面关闭、刷新、导航离开之后 1–13 ms 锁就放开，它在 `pagehide` 里发的广播先到；`steal` 立即生效，被抢的一方以 `AbortError` 结束；页面主线程卡住时抢锁照样成功，恢复之后排着的广播与 `AbortError` 一起到；`page.clock` 是上下文级的；**Playwright 模拟不了真正的隐藏与冻结**（"旧标签页不响应"改用只给那一页装 `addInitScript` 吞掉频道消息）；WebKit 在鼠标不动、页面被程序滚动时派发零位移的可信 `pointermove`。
- **真实 Safari**：一开始就在后台打开（窗口被挡、不在前台）的页面约 6 秒之后计时器停止（P2-S1 F1）；**被同一个窗口里的新标签页遮住的页面没有被暂停**（S8 复核：隐藏 8 秒照常回应交接、抢锁即时得知、心跳照常，只是计时器被压低），同一浏览器的"先保存再交出"在 Safari 上照常走。页面真的冻结、卡住时才走"没有回应就接手"，数据靠 P4 的"切到后台立即上传"兜住。（初稿推测"多半走到没有回应就接手"，被 S8 的复核推翻。）**被别的应用的窗口挡住两分多钟的编辑中的编辑器页同样没有被暂停**（P6-S5 复核：心跳照常、照常带来请求，持有者空闲满 2 分钟照常先保存再自动交出；同样盖屏，空白页约 50 秒就暂停）——请求编辑的"持有者被暂停、走到到期"只在真正的暂停（合盖、休眠、卡死）时出现，真实 Safari 上没有复核（DEF-069）。

## 3. 设计

### 3.1 总规则

1. **服务端是唯一的权威**：谁有编辑权只看租约；Web Locks 与 BroadcastChannel 只用来在同一个浏览器里判断"那个标签页还在不在"、让它先保存再交出、并让被抢的一方立即得知。
2. **先服务端、后本机锁**：正在编辑（服务端批准之后直到离开编辑）的标签页持有 `nerve-doc:<documentId>`（计划书 §7.5 的锁名）。拿锁一律在服务端批准之后：锁空着用 `ifAvailable`；被本浏览器的别的标签页占着就 `steal`——服务端既然批给了这一页，那一页的租约必然已经失效。被抢（`AbortError`）的一方不再问服务端、不续上，直接转为失去编辑权。这是对计划书 §7.5"以 `ifAvailable` 申请"的细化（M3 没有发件箱，锁不挡写入；M4 的写入栅栏在它之上），00 号计划书 r18 写明。
   **实施**（S5）：服务端批准之后在 `startEditing` 一开始就拿锁（早于取内容与重建，那边越早得知越好）；退出编辑与空闲释放时等服务端的释放有了结果（≤5 秒）之后再放（S6 据此把"等锁"当作对方完成的信号）；失去编辑权、没能进入、卸载、`pagehide` 一律放锁（`pagehide` 时保存在途也照样放）。被抢的一方：租约 `abandon`（停心跳与续上、不发释放）→ 失去编辑权 `taken-over`（`this-browser`）；进入途中被抢就放弃进入；已经放下的锁后来才说被抢不算（适配层与编辑模式各挡一层）。
3. **离开编辑一律先挡住输入再保存**：空闲释放、交出、本人接管时的交出与退出编辑同一个流程（`leaveEditing(cause)`），先挂交互屏障、挂起定时的捕获与上传，再 `flush`（P4 的约定：提交哪一次单元格编辑在调用的那一刻定）。
4. **新的写请求遇到会话类失败**照 P4 的口径（交给页面确认会话；只有连着的第一次在确认之后立即重试）。

### 3.2 数据模型与迁移 0025

`document_edit_leases` 加列（都可空，存量都是空的；只做加法，不回填）：

| 列 | 说明 |
|---|---|
| `request_id` uuid | 待回应或已谢绝的请求的标识 |
| `requested_by` uuid（FK users restrict） | 请求方 |
| `request_session_id` uuid | 请求方的登录（不做外键，同 `session_id`） |
| `requested_at`、`request_expires_at` timestamptz | 发出的时刻；有效期（请求方每次续期往后推） |
| `request_declined_at` timestamptz | 持有者选了"继续编辑" |
| `reserved_for` uuid（FK users restrict）、`reserved_until` timestamptz | 交出之后留给谁、留到何时 |
| `taken_over_token_digest` bytea、`takeover` text | 这一代接管的那一代的令牌摘要与方式（`self`、`forced`） |

CHECK：请求的五列（不含谢绝）同空同有，谢绝只在有请求时有值，`request_expires_at > requested_at`，`requested_by <> holder_id`；保留的两列同空同有，有保留时 `end_reason IS NOT DISTINCT FROM 'handed_over'`（写成 `=` 时没有结束原因的行因 NULL 比较被放过，S1 发现）；接管的两列同空同有，摘要 32 字节，`takeover IN ('self','forced')`；`end_reason` 加 `handed_over`。审计的 `audit_events_action_check` 按 0023 的写法全量重列，加 `documents.edit_taken_over`。不加索引（都按主键找）。`request_expires_at > requested_at` 在续期时比较的是两个事务的 `now()`，中间隔着 10 分钟的有效期，只有数据库时钟回拨超过 10 分钟才会违反（表定义的注释写明）。

### 3.3 契约（`packages/contracts`）

- **常量**（与计划书 §6.3 的起始参数对应）：`EDIT_IDLE_RELEASE_SECONDS = 600`（页面的空闲释放）、`EDIT_HANDOVER_IDLE_SECONDS = 120`（有请求时空闲满 2 分钟自动交出）、`EDIT_HANDOVER_RESERVE_SECONDS = 120`（交出之后的保留）、`EDIT_REQUEST_TTL_SECONDS = 600`（请求方停止续期 10 分钟后请求失效）、`EDIT_REQUEST_RENEW_SECONDS = 5`（等待中的续期间隔）、`EDIT_TAB_HANDOVER_ACK_MS = 3000`、`EDIT_TAB_HANDOVER_DONE_MS = 20_000`（同一浏览器的交接：回应与完成的时限）、`EDIT_PENDING_SAVE_WAIT_MS = 30_000`（§3.7 的 R1）。
- **失效原因**加 `handed_over`、`taken_over`（按有效条件的顺序插入：`taken_over` 在 `replaced` 之后，`handed_over` 在 `revoked` 之后；详情另带 `forced`，宽松解析，不是布尔值时当作没有）；页面把它们排除在续上之外。接管方式在 API 上写 `self`/`force`，库里记 `self`/`forced`。
- **申请**加 `takeover?: 'self' | 'force'`、`idleSeconds?`（只给续上用，最后活动写成 `now() - idleSeconds`）。
- **编辑状态**加 `canTakeOver`、`request`（待回应的请求：请求方、时刻、`mine`）、`reservation`（留给谁、到何时、`mine`）、`interruption`（`{ holder, endedAt, sameUser } | null`）；`editor` 加 `sameSession`（持有者的租约绑定的就是调用者这次登录 ⇔ 同一个浏览器）。`EDIT_LEASE_HELD` 的详情与 `editor` 同一个结构，另带 `canTakeOver`、`request`。
- **心跳的响应**加 `request: { id, requester, requestedAt } | null`（只给待回应的）。
- **请求的结果**（`EditRequestOutcome`，按 `kind` 区分）：`pending`（等待；带有效期与持有者）、`declined`、`reserved`（交给你了：立即申请）、`free`（没人在编辑：立即申请）、`self`（是你自己在编辑：改用本人接管）、`occupied`（别人先请求了）、`reservedForOther`、`gone`（只出现在续期：我的请求已不在，例如换了一代）。
- **错误码**：`EDIT_LEASE_RESERVED`（409，详情 `{ reservedFor, reservedUntil }`）、`EDIT_REQUEST_GONE`（409，交出时请求已不在，租约不动）。
- **审计**：`documents.edit_taken_over`，明细 `{ holderId }`；admin 的动作文案。
- **权限**：`DocumentPermissions` 加 `canTakeOver`（空间管理员；个人空间是所有者；归档时没有），`DOCUMENT_CONTENT` 加操作 `takeOver`——与分享、跨空间移动同一个机制，不借用 `canShare`。

### 3.4 接口

都挂在 `DocumentEditingController`（`documents/:id/edit-lease`）；workspace 开事务、补人名，documents 的 `EditLeaseService` 管规则与数据。都先判断访问（404 在 403 之前），看不到的不读租约行、不取锁，语句序列与不存在的文档相同。

| 方法与路径 | 谁 | 请求 | 成功 | 主要错误 | 后台请求 |
|---|---|---|---|---|---|
| `GET …/edit-lease` | 能读 | — | 200 编辑状态（加字段） | 404 | 是（不变） |
| `POST …/edit-lease` | 能编辑；`force` 另要 `takeOver` | `{ clientInstanceId, takeover?, idleSeconds?, …格式 }` | 201（不变） | 403、409 `EDIT_LEASE_HELD`（详情加字段）、409 `EDIT_LEASE_RESERVED`、409 `CLIENT_OUTDATED`/`DOCUMENT_TOO_NEW`、401 | 否 |
| `PUT …/edit-lease` | 能编辑，令牌 | 不变 | 200 `{ expiresAt, request }` | 409 `EDIT_LEASE_LOST`（新原因） | 是（不变） |
| `DELETE …/edit-lease` | 能读，令牌 | — | 204 | — | 否（不变） |
| `POST …/edit-lease/handover` | 能编辑，令牌 | `{ requestId }` | 200 `{ reservedFor, reservedUntil }` | 409 `EDIT_REQUEST_GONE`（租约不动）、409 `EDIT_LEASE_LOST`、401 | 否 |
| `POST …/edit-lease/request` | 能编辑 | `{ …格式 }` | 200 请求的结果（除 `gone`） | 403、409 `CLIENT_OUTDATED`、401 | 否 |
| `PUT …/edit-lease/request` | 能编辑 | — | 200 请求的结果（没有就是 `gone`） | 403、401 | **是** |
| `DELETE …/edit-lease/request` | 能读 | — | 204（清我的请求与留给我的保留） | — | 否 |
| `POST …/edit-lease/request/decline` | 能编辑，令牌 | `{ requestId }` | 204（对不上也 204） | 409 `EDIT_LEASE_LOST`、401 | 否 |

**实施**（S4）：请求编辑的五个操作在 `EditRequestService`（`documents/edit-request.service.ts`），两个服务共用的事实（持有者、请求方、被保留的人的登录与编辑权）在 `edit-lease-facts.ts`。状态码：发出 200、续期 200（后台请求）、取消 204、谢绝 204、交出 200。续期没有请求体、不拦旧页面（旧页面之后申请时得到 `CLIENT_OUTDATED`）；只有发出在任何查询之前拦旧页面。发出、续期、谢绝、交出在锁住租约行之后核对登录；取消不核对（同释放：常由关页时的 `keepalive` 发出，只清调用者自己的请求与保留）。这几个接口不判断 `DOCUMENT_TOO_NEW`（太新的文档本来谁也拿不到租约）。请求的标识由数据库的 `uuidv7()` 生成，不是凭证。

各操作按"同一个人的同一件事"天然幂等，不需要 `requestId` 的账本：请求已有就续期；谢绝、取消对不上就什么也不做；交出的重试得到 `handed_over`；接管时同一个页面的重试走"同一个页面"那条路，不再写审计。写的一侧在事务里按主键核对登录（P1 的约定）。

### 3.5 有效条件、异常中断与 DEF-044

- **异常结束按事实判断**：没有明确结束，并且已到期、空闲满 12 分钟或绑定的登录失效——代次过时不再遮住它（P1-A6 第 1 处；`edit-lease-rules.test.ts:219-221` 的预期有意改掉）。代次过时但按时间、登录都还活着的（刚被移走、持有者的页面正在续上）不算。
- **收回写入权只收回"按时间还活着"的租约，刚死不久的仍锁文档行（审查 A1 之后）**：`lockInScope` 的第一条语句锁"一个有效期之前那一刻按时间还活着"的租约所在的文档行（`aliveByTimeAt(now() - 90 秒)`，到期与空闲两个条件都按那一刻算）——等在途的保存提交；第二条语句（锁下复核）只把按时间还活着的交给收回写入权，记 `revoked`、加代次。保存用的是事务开始时的 `now()`，所以要的是保存的事务从开始到提交短于一个有效期——**由数据库与事务运行器保证**（复验 C1、再复核 D1、D2）：保存的事务从 BEGIN 到提交至多 70 秒。事务运行器的限时事务（`run` 的 `limit`）在第一条语句里做三步，同一条语句、按数据依赖强制先后（内层的 `set_config` 是外层的参数，外层 `CASE` 的条件成立之后才读时长）：先把 `transaction_timeout` 设成 0（停掉会话默认值在 BEGIN 时启动的计时器——已有计时器时事务里设更短的不起作用），再设成 60 秒（`SAVE_TRANSACTION_TIMEOUT_MS`，从这一刻计时，到点由数据库结束会话、整体回滚），然后读 BEGIN 至今的时长，超过 10 秒（`SAVE_TRANSACTION_START_WITHIN_MS`）就不开始（work 不执行、回滚、什么也没写）。两种都按数据库繁忙回 503。推导：撤权的 `now()` 为 T0，保存开始于 S、设下时限于 S′、提交于 C；撤权执行时保存还在途，C > T0；S′ − S ≤ 10 秒（读时长不早于设下时限）、C − S′ ≤ 60 秒 ⇒ C − S ≤ 70 < 90 秒 ⇒ S > T0 − 90，保存在 S 时判断租约有效，第一条语句一定锁住它（余 20 秒）。这与会话默认值（库上、角色上）、连接串的 `options`、`PGOPTIONS` 与各超时的配置都无关；运维设的默认值比它短时，只有保存的事务改用自己的时限，别的事务照旧；BEGIN 到第一条语句之间仍按库上的默认值——默认值比那段停顿还短时在第一条语句之前就到点，回 500、什么也没写（再复核 D7，接受）。原来写的"受 `lock_timeout` 5 秒、`statement_timeout` 15 秒、`idle_in_transaction_session_timeout` 10 秒约束"不成立：它们只管一次等锁、一条语句、一次空闲，而且都能经环境变量调到 600 秒。窗口的大小另有集成用例按行为钉住（到期约 70 秒、空闲满 12 分钟之后又约 70 秒仍等在途的保存——正是保存的事务的上界，复验 C5、再复核 D8）。所以"撤权提交之后的保存必定被拒绝"照样成立（撤权要么等它提交，要么它在锁下看到新的权限与代次）。死了超过一个有效期的不锁、不记 `revoked`、不加代次——提醒因此保留，撤权也不锁历史文档行（DEF-044 的两半；关闭）。仍会被记 `revoked` 的只剩"登录已失效但还没到期"的，最长 90 秒。心跳的窄交错只剩"事务开始在到期之前、又在第二条读过租约行之后才锁住它"的那一次，由有效条件第 7 条（停用时另有第 6 条）在每次使用时让它失效。`lease-revocation-locks.test.ts` 里靠"已到期的租约"构造交错的那一条改用"登录失效但未到期"。
- **提醒带 `sameUser`**（P1-A6 第 3 处）：页面按它分别说"上一位编辑者 [人名] 的会话异常中断……"与"你上一次的编辑异常中断……"；只在用户发起的申请（"编辑""在此编辑""强制接管"、请求被批准之后的自动进入）里显示，续上不显示。编辑状态里也给出（没人在编辑时），阅读页不必等点"编辑"。
- **实施**（S8）：申请的结果带 `interruption`，只有用户发起的申请（"编辑""在此编辑""强制接管"、请求被批准之后的自动进入；`?edit=new` 也走这条路，新建的文档本来没有提醒）才显示；续上走租约内部的 `recover()`，结构上拿不到它。编辑时页头下面一条不打断的说明，带"知道了"，同一句进一直在的读屏状态区；离开编辑的过程中留着，回到阅读、失去编辑权时消失；点"编辑"被占用时清掉之前读到的提醒。阅读时只说别人那一代的提醒，自己那一代的只在进入编辑之后说——本页退出时释放没送到，那一代约 90 秒后到期，服务端照样算异常中断，而本页的修改其实都已存上，阅读时说就是误报。时刻用 `formatRecentClockTime(endedAt, 30 分钟)`：服务端只在结束之后 30 分钟内给提醒，"现在"一定落在这段时间里，这段跨过午夜（页面的时区）就加日期（"10月6日 23:50"），否则只写 HH:mm——不读浏览器的时钟，代价是 23:30 之后结束、现在还是同一天时也带日期；日期手写成"X月X日"（Node 与浏览器的 ICU 写法不同）。
- **交出、接管、释放、空闲释放都是明确结束**，不给提醒。
- **本页自己那一代**（审查之后）：申请响应的提醒另带 `samePage`（被中断的那一代绑定的标签页就是这次申请带的 `clientInstanceId`，同一个人），页面在 `samePage` 时不说——本页退出时释放没送到、那一代到期之后本页再进入编辑，修改其实都已存上；编辑状态（没有 `clientInstanceId`）的提醒照旧只给别人看。
- **跨空间移动之后的窗口**（探索 R2，P1 起就有）：代次过时、而按时间、登录、编辑权都还活着、持有者不是申请人时，对别人按"被占用"回答，只让持有者本人续上——P5 的等待中的请求方会自动申请，命中这个窗口的概率变大。
- **实施**（S2）：申请与编辑状态共用一个占用判断（`occupancyOf`）：占着＝有效的租约，或上一条的"过时而活着"（编辑状态里别人看到有人在编辑、持有者本人看到空着，与申请的回答一致）；空着时带失效原因与 30 分钟以内的提醒。持有者的登录与编辑权在一次请求里至多各查一次。异常结束按事实（`endedAbnormally`），只有按时间还活着时才查登录。收回写入权加时间条件之后有一个极窄的交错：心跳在撤权事务开始之前判断有效、在它的第一条语句之后才提交——续上的那一代不被记 `revoked`，与"申请和撤权交错"同一个性质，由有效条件第 7 条（停用时另有第 6 条）在每次使用时让它失效，保存仍在文档行锁下判断权限（仓储注释写明）。改写时的沿用：请求只在新旧持有者是同一个人时沿用（含已谢绝）；保留一律清空；接管标记只在同一个登录、同一个标签页（同一个页面）时沿用，不论旧的一代是否有效。
- **空闲的兜底计时准确**（复验 P1-C5）：申请可带 `idleSeconds`（续上时带本页的空闲，上限 719 秒＝回收阈值减一秒，超出 400——免得新的一代一出生就按空闲失效，审查 A4），心跳的最后活动只前进不后退。
- **持有者页面的续上不先释放**（审查 A3）：续上原来对一切可续上的原因都先放掉本页那一代再申请，`stale` 时这一放就让等待中的请求方抢进"先释放、再申请"之间。现在只有 `session`（换过登录、原来的登录还在时那一代仍有效）先释放；`stale`（服务端把本人的过时租约看作空着的）、`expired`/`idle`（谁看都是空着的，先放只会消掉别人的提醒）、`none`/`replaced`/`released`（释放什么也不改）都直接申请。人不在时记下失效原因，人回来续上时照它处理。

### 3.6 请求编辑与交出（US-M3-06）

**服务端**：

- 请求记在租约行上，**单槽、先到先得**：后来的人得到 `occupied`（详情给先请求的人与时刻），已谢绝或已失效的请求不占槽。同一个人再发：有待回应的就续期；已被谢绝时显式再点一次会换成新的请求。
- 请求是一份"小租约"：`POST` 发出（用户操作，顺延登录；按页面上报的格式先拦旧页面）；等待中的页面每 5 秒 `PUT` 续期（后台请求，响应就是请求的现状）；`DELETE` 取消（`pagehide` 时 `keepalive` 尽力发）。**请求方停止续期 10 分钟后请求失效**——请求方的页面崩溃、合盖、被 Safari 暂停时 `pagehide` 不一定触发；持有者不理会时请求照样一直有效（计划书 §6.3），只是请求方的页面不在了才失效，免得持有者空闲 2 分钟之后把编辑权交给一个没人的页面。
- 请求绑定请求方那次登录，用到时判断登录还在、仍能编辑；收回写入权不需要另外处理请求方。
- 换了一代时：新的持有者还是同一个人（重试、续上、本人接管）就沿用请求（含已谢绝的状态）；换了别人就清掉（请求方续期得到 `gone`）；新的持有者就是请求方，请求已经实现，清掉。
- **交出**：持有者 `flush('handover')` 存上之后 `POST …/handover { requestId }`。只锁租约行（与释放同一类），锁下核对登录、令牌、请求仍有效且 `id` 对得上：结束原因记 `handed_over`，写下保留（留给请求方 2 分钟），请求转成保留。请求已经不在：409 `EDIT_REQUEST_GONE`，租约不动，持有者留在编辑。普通的释放不隐式变成交出。
- **保留期内**除被保留的人之外一律 409 `EDIT_LEASE_RESERVED`（强制接管也挡，最多 2 分钟）；被保留的人用哪个标签页、哪次登录都行（按人，不按页面）。保留有效 = 没过期，且被保留的人仍能编辑。
- **谢绝**：`POST …/request/decline { requestId }` 记谢绝的时刻；请求方下一次续期得到 `declined`。
- **实施**（S4）：编辑状态里的请求只要还在等就给出，不论这时有没有人在编辑（请求方刷新之后可以据此恢复等待）；保留只给算数的（没过期、被保留的人仍能编辑），只在没人占着时出现。同一个人再发一次只续期，请求仍绑定第一次发出时的那次登录（那次登录失效后请求作废，别的页面续期得到 `gone`，可以重新发出）。谢绝只记第一次的时刻；请求已过期时同样记成谢绝。交出先比对标识、再要求请求仍待回应；回包丢了再交出得到 `handed_over`，请求方已经接手时得到 `replaced`——页面都当作交出完成。取消清掉调用者自己的任何请求（待回应、已谢绝、已过期）与留给他的保留，交出的记录留着。保留只在普通申请（`claimOf` 为 `fresh`）、加代次之前判断，本人接管、强制接管与交出的人自己因此一样被挡；被保留的人用哪次登录、哪个标签页都行。
- **实施**（S8）：`handed_over` 单独成失效 `handed-over`（交出的结果未知、其实已经交出、下一次心跳才得知时），说"编辑权已失效：已交给请求编辑的 [人名]"（人名取自还在等的那个请求）；谢绝之后"着急时可以请空间管理员强制接管"在个人空间里说"文档的所有者"。

**页面（请求方）**：

- 持有者是别人、自己能编辑时，"编辑"换成"请求编辑"；能强制接管时并列"强制接管"（§3.8）。持有者的信息来自阅读时的检查或 409，可能过时：仍点得到"编辑"时照旧处理 409。
- 发出之后按钮换成"取消请求"；读屏的状态区说"已请求编辑，等待 [人名] 回应。[人名] 停下操作 2 分钟后会自动保存并交给你；你也可以取消请求"（不倒计时）。等待中每 5 秒续期；页面隐藏时浏览器自己会降频，回到前台立即续期一次。
- 结果：`reserved` 或 `free` → **只在页面看得见时**自动进入编辑（后台的页面可能被浏览器暂停——Safari 一开始就在后台打开的页约 6 秒停计时器、极简页被挡住约 50 秒暂停——抢到的编辑权会因心跳停了而到期；人回来之前也不该占编辑权。P6-S5 复核：被挡住两分多钟的编辑中的编辑器页没有被暂停，这条理由不是必然发生，规则作为保守的做法保留）；后台时回到前台再进，保留期过了而编辑权空着时照样进入（请求的意图还在）；`declined` → "[人名] 选择继续编辑，你的请求已取消"（不能强制接管的人另说"着急时可以请空间管理员强制接管"）；`occupied` → "[人名] 已在请求编辑"；`self` → 改为"在此编辑"。
- 等待中的页面空闲满 10 分钟就取消请求（人走了，免得编辑权交给他之后空占）。

**页面（持有者）**：

- 心跳的响应带来请求 → 编辑模式记下；本页空闲满 2 分钟（起点 = 最后一次操作与进入编辑中较晚的那个）就自动交出；否则在页头下面显示提示，提示在的时候一旦空闲满 2 分钟同样自动交出。
- 提示是带标题的分组（`role="group"`，`aria-labelledby` 指向"[人名] 请求编辑这份文档"），两个按钮"交出""继续编辑"，一行静态说明"你停下操作 2 分钟后会自动保存并交给对方"；不是对话框、不是 `alert`、不新插入 `role="status"`；**出现时不移动焦点、不挂屏障**，单元格编辑与输入法照常；读屏在一直在的状态区里礼貌地播一次。
- 交出：`leaveEditing('handover-request')`（§3.10）→ 存上（公式没收齐也可以，带"公式待更新"）→ 交出 → 以只读重建 → 阅读，"已保存并把编辑权交给了 [人名]"。没存上就留在编辑，说明原因，请求照旧在。`EDIT_REQUEST_GONE` → 留在编辑，"[人名] 已取消请求"。
- 继续编辑：谢绝 → 提示消失。
- **退出编辑与关页时有待回应的请求**：用交出代替释放（关页时 `keepalive` 的交出；保存在途时照 P4 不释放、也不交出）。
- **实施**（S7，请求方）：`edit-request.ts` 的进展是 `sending`、`waiting`、`cancelling`、`granted`，结束有取消、空闲、谢绝、被占、留给别人、请求不在、自己在编辑、失败八种；进入编辑不算结束，交回调用方用普通申请进入。续期按"轮次"作废（取消、结束、恢复都开始新的一轮，同一轮只有一个在途，旧一轮在途的不挡新一轮）；空闲不另起计时器，每次续期之前与回到前台时（可见性的通知里同步）判断。`reserved`/`free` 时页面看得见、会话是本人才进入，否则停在 `granted`、不再续期，回到前台再进；这一刻进不了（正在"有更新"重建）就留在 `granted`，重建完了再试；`granted` 而这一页已经不能进入编辑时请求作罢并尽力撤回（清掉保留）。续期得到 `reservedForOther` 时本人的请求还在槽里，顺手撤回（不等结果）、结束并说明——这一支在现有的写路径下到不了（保留只由交出写下，交出在同一条语句里清掉请求），留作防御（审查 A6）；空闲取消与关页撤回的 `DELETE` 不等结果（没送到的 10 分钟后失效）。刷新之后按编辑状态里的 `request.mine` 或 `reservation.mine` 恢复等待，检查发出时记下进展的版本，变过了就不按它恢复（审查 B2 之后只在发出过请求的那一页恢复，见下）。
- **实施**（S7，持有者）：心跳带来的请求经编辑租约的 `onRequest` 交给编辑模式；`editing` 与 `exiting` 都带着请求（离开的过程中提示留着、按钮不可用，焦点不丢）。请求到达时本页已空闲满 2 分钟就在同一步里开始离开、不显示提示；否则显示提示并用空闲计时（起点取进入编辑与最后一次操作中较晚的那个，回到前台按隐藏之前算）。交出与释放共用 5 秒的时限；交出的结果：200 → 阅读、租约 `abandon`（不发释放）；`EDIT_REQUEST_GONE` → 留在编辑；`handed_over`、`replaced` → 算交出；别的失效 → 失去编辑权（本页的修改都已存上）；没有结果、超时、会话类失败 → 留在编辑、提示里说明，自动交出的过一个心跳周期再试、终态不再试。谢绝进行中两个按钮都不可用，记下刚谢绝的那个、迟到的心跳不再显示它，失效后续上了用新的编辑权再谢绝一次。退出与空闲释放时有请求在等就交出代替释放（交不出照常释放；交给本浏览器的另一个标签页时不交给请求方——同一个人，请求随新的一代沿用；审查 B4 之后这时也不释放，见 §3.7；正在谢绝时不交出）。
- **审查之后**（请求方，B1、B2、B11）：只有**发出过请求的那一页**恢复等待（`issued-request.ts`）。发出之后在 `sessionStorage`（按标签页，刷新之后还在）记下 `nerve-office:edit-request:<documentId>` → `{ v: 1, requestedAt? }`（服务端给的发出时刻；发出时编辑权就交给了本页的不带），请求结束、进入编辑时清掉，撤回时不清（刷新时撤回没送到的话照记号恢复）；编辑状态里本人待回应的请求要发出时刻对得上才算这一页的，留给本人的保留有记号就算；对不上、读不到本人的请求时清掉记号；存储读写失败按"不是这一页发出的"处理（宁可不恢复，也不撤掉别处的请求）。别的页面（同一个人另开的标签页、别的设备）不续期、不撤回、不空闲取消、不自动进入，阅读时说"你已在别处请求编辑这份文档"（`requestedElsewhere`）；在那一页再点"请求编辑"照常发出（服务端只续期），那一页随之成为发出过的页面。原来任何页面读到本人的请求都恢复等待，它关页（撤回）或空闲满 10 分钟（空闲取消）就会撤掉用户在别的页面正在等的请求（服务端的取消按人清）。请求不在了的说法改为"你的编辑请求已经失效（可能在别的页面取消了，或者正在编辑的人换了），可以重新请求编辑"。续期与取消的会话类失败与续租同一个口径（M3-P4 复验 C1、复核 D1）：只有连着的第一次在会话回到本人时立即续期，之后按 5 秒的节奏；发出、续期、取消成功与页面确认会话不是本人时清零；编辑模式只在会话真的从不是本人变成本人时让请求方立即续期——原来续期一直被拒为 CSRF 失效、确认会话照常是本人时，两者按网络往返的速度连着发（审查 B1）。`granted` 带上在等什么（`until`）：页面在后台说"可以进入编辑了：回到这一页时自动进入编辑"，看得见、这一刻进不了（会话在确认、正在载入新版本）说"可以进入编辑了：稍后自动进入编辑"。
- **审查之后**（持有者，B3、B6）：持有者一侧的请求拆到 `holder-requests.ts`（在等的请求、刚谢绝的、说明、2 分钟计时、谢绝与交出的结果映射；离开编辑仍由状态机做）。离开编辑的过程中到来的请求只记下、没有计时，离开没成、留在编辑之后按请求刚到处理：空闲已满 2 分钟、可写、联网时立即交出，否则显示提示、开始计时（原来留在编辑之后提示照样在，人走开 2 分钟却不会自动交出）。
- **复验之后**（请求方，C2）：复制标签页会连同 `sessionStorage` 的记号一起复制，副本也会恢复等待、关掉时撤回原页的请求。发出过请求的页面在等待（含 `granted`）期间以**共享方式**持有本机锁 `nerve-office:edit-request:<documentId>`（`same-browser.ts` 的 `holdIssuedRequest`、`issuedRequestHeld`）：记下记号、恢复等待时拿，请求结束、进入编辑、撤回、停下时放，拿锁回来时请求已经结束的随即放开。恢复等待要记号对得上、**而且**这把锁在本浏览器里没人持有（原来那页已经刷新或关掉）；有人持有说明自己是副本，按"别处发出的"处理并清掉复制来的记号。共享模式让同一个人两页都显式发出时两页都能等（这时刷新其中一页不恢复，另一页照旧在等）；刷新时旧页面的锁在新页面最早的脚本里就已放开（三个浏览器各 5 次实测），万一还看得到就按别处处理、宁可不恢复；没有 Web Locks 的环境退回只看记号。
- **复验之后**（持有者，C3、C4）：离开途中到来的请求换了一个（标识变了）时停掉并丢弃原来的计时——它属于前一个请求，留在编辑之后新的请求按"请求刚到"处理（空闲已满 2 分钟就同一步交出，不再多等一个心跳周期）；换了一代（`reset`）时计时一并停下，卸载之后各入口直接返回；"过一个心跳周期再看"共用 `edit-lease.ts` 的 `HEARTBEAT_MS`。
- **合并之后**（CI，msedge）：交出在途时续租先得知"已经交出"（两者几乎同时发出、服务端先提交了交出——空闲满 2 分钟的计时与心跳一起到点时），原来随即转入失去编辑权（"编辑权已失效：已交给请求编辑的……"），之后到的交出回答作废；现在离开编辑里交出在途时记下它、等交出的回答把离开走完（说"已保存并把编辑权交给了……"），交出的回答到了时限也没回来时照样当作交出完成。原来持有者有没存上的修改、交出要先上传，心跳总是先到，没碰上。

### 3.7 本人接管（US-M3-08、DEF-042）

**服务端**：申请加 `takeover: 'self'`，只在当前有效的租约的持有者就是调用者时生效——同一个事务里（文档行 → 租约行）代次加一、整行改写成新的一代，并记下接管标记（被接管那一代的令牌摘要、`self`）。旧令牌的心跳、保存、交出、谢绝因此得到 `taken_over`（`forced: false`），不再是笼统的 `replaced`。持有者是别人时不起作用（照常 `EDIT_LEASE_HELD`）；当前的租约本来就无效时按普通申请处理。同一个页面的重试沿用上一代的接管标记。不写审计。

**实施**（S3）：申请怎样对待占着的那一代写成纯函数 `claimOf`，四种结果：没人占着 → 普通申请（带不带接管方式都一样）；占着的就是这个页面 → 重试（先于接管判断，标记由仓储沿用、不再写审计）；占着的是自己在别的标签页或设备上的租约 → `self` 与 `force` 都按本人接管；占着的是别人（有效的或 R2 的）→ 只有 `force` 起作用，`self` 与普通申请一样被占用。本人接管只要求能编辑。自己的租约代次过时（R2 只对别人）时"在此编辑"是普通申请、不写接管标记——旧页面得到 `replaced`、去续上、被占用（`sameUser`），说法是"你在别处正在编辑"而不是"接手了"，数据不受影响（S3 提出，接受）。接管成功的响应里没有提醒（被接管的那一代是有效的）。心跳与保存的失效详情经共用的 `editLeaseLost(loss)` 给出，被接管时带 `forced`；交出、谢绝（S4）照同样的写法。

**页面**：编辑状态说持有者是自己时，`navigator.locks.query()` 看锁在本浏览器里有没有人持有：有 → "你在本浏览器的另一个标签页里正在编辑这份文档"；没有 → "你在另一台设备或浏览器上正在编辑这份文档（也可能是刚关闭、刷新过的页面）"；没有、而本浏览器里有刷新时在途的保存的记号（30 秒以内、修订号还没前进）→ "你刚关闭或刷新的页面还有一次保存在进行。点"在此编辑"会先等它存完（至多 30 秒）再接着编辑"（`just-closed`，审查之后，见下文 R1）。按钮一律是"在此编辑"（换掉"编辑"）。

"在此编辑"的流程（新标签页 B）：

1. **锁在本浏览器里没人持有**（跨设备、另一个浏览器或配置文件、刚关闭或刷新过的页面、DEF-042 的孤儿租约）：以 `takeover: 'self'` 申请 → 拿锁（`ifAvailable`）→ 以可编辑重建。说明里写清那边会失去编辑权。
2. **锁被本浏览器的标签页 A 持有**：经交接频道 `nerve-office:doc:<documentId>` 发 `handover-request`，按钮说"正在接手…"：
   - 3 秒内收到 A 的 `ack`：等 A 做完（以等锁为信号，`AbortSignal.timeout`，另收 `done`、`failed`），完成的时限 20 秒（按总时长，DEF-064）；拿到锁之后以 `takeover: 'self'` 申请（A 存上之后不释放，本人接管在同一个事务里结束它那一代，审查 B4）→ 重建。
   - 收到 `failed`（A 保存失败、冲突、会话不对）：说明原因，给"仍在此编辑"（那边没保存的修改可以在那边另存为副本）与"取消"。
   - 3 秒内没有 `ack`（冻结、Safari 暂停、页面卡住）：以 `takeover: 'self'` 申请 → 成功之后 `steal` 锁 → 重建。
3. **A 收到 `handover-request`**：只理会同一个人的，而且自己确实还持有锁（被抢之后迟到的请求一律不理）；`editing` 时在消息处理里同步回 `ack`，然后 `leaveEditing('handover-tab')` → 存上之后不释放、只放弃这一代（停心跳）→ 放锁 → 发 `done` → 阅读，"已交给本浏览器的另一个标签页"（不断言那边一定接着编辑了）；没存上就发 `failed`、留在编辑。**审查 B4 之后不释放**：原来"存上就释放、B 再普通申请"，释放与申请之间等待中的请求方续期得到 `free` 会抢进来（B 被占用，A 却说那边接着编辑了）；现在槽从来不空，请求随 B 的新一代沿用。代价：B 没跟上（例如随即被关）时 A 那一代至多 90 秒后到期，这期间别人进不来，到期之后别人看到异常中断的提醒。`exiting` 时回 `ack`、照常退出；`entering` 时回 `busy`，B 稍后再试。
4. **A 的锁被抢**（`AbortError`）：立即转为失去编辑权（"你在本浏览器的另一个标签页接手了编辑"），有没保存的修改照旧给副本与放弃。

**实施**（S6）：请求方一侧的协议（`askTabToHandOver`）与记号的等待（`awaitPendingSave`）在新模块 `self-takeover.ts`（锁、频道、时钟注入）；回应的一侧离不开编辑模式，留在 `edit-mode.ts`（审查 B6 之后与"在此编辑"的编排一起拆到 `tab-handover.ts`，离开编辑、开始一件事与它的作废、申请并进入仍在状态机里，经回调调用）。"等锁直到空着"（`same-browser.ts` 的 `untilFree`）只当信号——排队请求、轮到就立即放开，拿锁仍在服务端批准之后；"锁空了"与"收到 `done`"都算那边做完，两种先后只算一次。3 秒与 20 秒的时限用注入的时钟排，到点撤销等锁（不用 `AbortSignal.timeout`：它走真实时间，`page.clock` 拨不动）。三条路的细节：锁空着 → 先等记号、再本人接管；那边做完 → 同样先等记号（关掉的页面可能留下记号）、再申请（S6 是普通申请、仍被自己占着就立即改用本人接管；审查 B4 之后一律以本人接管申请一次）；3 秒没有回应或选了"仍在此编辑" → 直接本人接管并抢锁（那边还活着，不看记号）；对方回 `busy` → 隔 1 秒换一个请求再问，最多 20 秒。旧标签页：`opening`（`?edit=new` 正在进入）与 `entering` 一样回 `busy`；`exiting` 时先回 `ack`、记下这个请求，离开结束时发 `done`，没离开成就发 `failed`。`failed` 的原因按先后：版本冲突 → 会话不对 → 其余都是没存上（审查 B11 之后另有 `not-handed-over`：正在把编辑权交给请求编辑的人、没交出去而修改都已存上，还在编辑）。交出走 `leaveEditing('handover-tab')`，与空闲释放同一套"不是人按的离开"的规则（不主动确认会话、公式没收齐也离开、离开期间停止续上）；交给标签页时释放没确认也不标 `releaseUnconfirmed`（这边随即接手；审查 B4 之后交给标签页本来就不释放）。接手的进展记在阅读状态里（`takeover`：`preparing`、`asking`、`waiting-save`、`failed`），真正申请时才转为进入、挂屏障；接手进行中"编辑"与"有更新"不做事。接手之后清掉记号。跨设备被接管：`forced` 为假 → `taken-over`（`elsewhere`）；为真 → 新的失效 `forced`（说法 S8 细化）；认不出 → 只说编辑权已失效；三种都不续上。
5. **跨设备的旧页面**：下一次心跳（≤10 秒）或保存得到 `taken_over` → 不续上 → 失去编辑权（"你在另一台设备或浏览器上接手了编辑"），给副本。

**刷新时在途的保存（探索 R1）**：P4 让"`pagehide` 时有在途的保存不释放"，那次保存要能提交；P5 的立即接手会结束旧的一代，那次保存如果还在服务端检查快照或等锁，会被 `taken_over` 挡掉——旧页面已经没了，修改无声丢失。做法：旧标签页在 `pagehide` 时保存忙，就在 `localStorage` 记下 `nerve-office:pending-save:<documentId>` 与时刻（同步写；不可用时跳过）；新标签页在"锁空着、本人接管"之前看到 30 秒内的记号，就先等——每 2 秒读一次编辑状态，修订号前进了（那次保存提交了）或者到 30 秒就接手，期间说"上一个页面的保存还在进行，稍后接手…"；接手之后清掉记号。记号只在同一个浏览器里起作用，正好覆盖这个情形（跨设备的旧页面还在，被接管之后自己给副本）。**实施**（S5）：记号写成 `{ v: 1, at, revision }`（`at` 是墙上时间——要在另一个页面里比较；`revision` 是本页确认过的最新修订号），新标签页按"编辑状态的修订号大于它"判断那次保存已提交。**审查之后**：阅读页有这样的记号（30 秒以内、编辑状态的修订号不大于记号里的基准）时用第三种说法 `just-closed`（不再说"那边会失去编辑权、另存为副本"——刚关闭、刷新过的页面已经不在了）；修订号前进就清掉记号、回到一般的说法；记号到 30 秒时排一次检查（之前的作废、卸载时取消）；申请被自己占用、续上时不知道修订号，只看记号的时刻。失去编辑权（`losing`、`lost`）之后关页不写记号——那一代服务端已经不认，那次保存不可能再提交，新页面白等（审查 B12）。

### 3.8 强制接管（US-M3-09）

- **谁**：`canTakeOver`（空间管理员；个人空间是所有者；归档的空间里没有；只凭授权的人没有）。申请按 `['edit', 'takeOver']` 判断，不加锁一次、锁下一次。
- **怎样**：`takeover: 'force'`。当前有效的租约在别人手里：代次加一、改写成管理员的新的一代，接管标记记 `forced`，在同一个事务里写审计 `documents.edit_taken_over`（操作者、文档、`{ holderId }`、来源），排在租约行之后。持有者就是自己：当作本人接管，不写审计；没有有效的租约：普通申请，不写审计；保留期内被挡。有请求在等的一并清掉。
- **页面**：阅读时、别人持有编辑权时，"请求编辑"旁边的"强制接管"（`variant="outline"`）；`ConfirmDialog` 确认（destructive）："[人名] 正在编辑（最后活动 x 分钟前）。强制接管会立即结束他的编辑权：他还没保存的修改不会写进这份文档，他可以在自己的页面上另存为副本。这次操作会记入审计。"；结果的说明等确认框关掉、焦点交还之后再写（规范 §2.4）。
- **实施**（S3）：`force` 的 403 按先后：先判断 `edit`（查看者"只能查看…"、归档"空间已归档，只能查看"），再判断 `takeOver`（编辑者"只有空间管理员能强制接管这份文档的编辑"、只凭编辑授权的人"这份文档是单独分享给你的，不能强制接管编辑"）。R2 里"过时而活着"的那一代同样可以被强制接管，审计里的被接管者就是那位持有者。权限矩阵另核对"强制接管成功的格子恰好是编辑状态 `canTakeOver` 为真的格子"。
- **实施**（S8，页面）："强制接管"在能强制接管、能编辑、还读得到、没有不兼容、数据完整、正在编辑的是别人时出现，沿用请求编辑与"在此编辑"的两个互斥条件；正在载入最新版本、正在确认会话、会话不是本人时不可用。确认之后的接管交回给确认框关掉、焦点交还之后再做（`AfterConfirmed`），`returnFocus` 交给"强制接管"（按钮已经不在时交给返回链接——WebKit 里点按钮不会把焦点放到按钮上）；进入编辑的过程中同一个按钮说"正在接管…"。失败：403 → "没能强制接管：[原因]"，只撤 `canTakeOver`（能不能编辑交给随后的检查）；`EDIT_LEASE_RESERVED` → "编辑权刚交给了 [人名]，留到 HH:mm，这期间不能强制接管"；`EDIT_LEASE_HELD` → 回到阅读说明谁在编辑；其余 → "没能强制接管：…"。被接管方说"编辑权已失效：空间管理员 [人名] 强制接管了编辑"（个人空间说"文档的所有者"——被接管的可能是被授权的编辑者）；接管人在失去编辑权的那一刻与捕获、重建同时读一次编辑状态，晚到的就地补上，读不到时不带人名。
- **被接管方**：心跳或保存得到 `taken_over`、`forced: true` → 不续上 → "编辑权已失效：空间管理员强制接管了编辑"（接管人由转为阅读之后读一次编辑状态得到）；副本与放弃照旧。
- **系统管理员**：签发重置链接 → 持有者的全部登录失效、租约因此无效 → 下一个申请的人看到异常中断的提示（`session` 属于异常结束）；补 E2E。停用账户走收回写入权（`user` 范围），还活着的租约记 `revoked`，是明确结束、没有提醒（P1 起的行为，集成测试钉着；S2 核实）。

### 3.9 空闲释放（US-M3-07）

- **计时**：一个截止时刻的计时器（`max(最后一次操作, 进入编辑的时刻) + 10 分钟`），到点重算；只在 `editing` 时排。"有操作"沿用 `trackActivity`，加两条过滤：只认可信事件（`isTrusted`）；零位移的 `pointermove` 不算（WebKit 在页面被程序滚动时派发它，不滤的话"10 分钟没有操作"永远到不了）。
- **后台**：Chrome 隐藏的页面计时器降频，空闲释放最多晚约一分钟；Safari 一开始就在后台打开的页面约 6 秒后计时器停止（被同一个窗口的新标签页遮住时只是压低，S8 复核）——**回到前台时**（`visibilitychange` 变成 visible 的处理里同步判断）按隐藏之前的最后一次操作算空闲，满 10 分钟就走空闲释放，并且不再续上（释放开始的那一刻就让租约停止续上，免得 `dormant` 被回来时的操作叫醒）。
- **流程**：`leaveEditing('idle')`：屏障 → 挂起 → 等面板 → `flush('idle-release', { ready: confirmedForWrite })`（不主动向服务端确认会话；会话不对时这一轮不释放，交给服务端 12 分钟兜底）→ 等在途 → 存上（公式没收齐照样释放，带"公式待更新"）→ 释放 → 放锁 → 以只读重建 → 阅读，说明"10 分钟没有操作，已保存并释放编辑权"。**没存上就留在编辑**（保存的状态本来就在说失败的原因），过一个心跳周期再判断；一直存不上时由服务端 12 分钟兜底，人回来时按 P1 的续上处理。
- 自动进入编辑的人（请求被批准）另有完整的 10 分钟（起点取进入编辑的时刻）。
- **实施**（S5）：开始之前先看"会话可写且联网"（与 `confirmedForWrite` 同一个口径，另加联网），不满足就不开始这一轮（不挂屏障、不上传），10 秒后再看——没联网时既存不上也放不掉，每轮闪一次屏障没有意义；`flush` 的 `ready` 用同一个门槛；`skipped(session)` 算没存上；保存进入终态（冲突、过旧、文档太新）之后不再重试，交给服务端 12 分钟兜底；释放期间得知的、本可续上的失效先交回"说不准"、心跳照常，恢复时 `dormant` 而人已回来就立即续上。公式没收齐也释放，阅读时"公式待更新"取保存状态机最后存上的那一版。编辑器页的操作改由组装处注入（`PageActivity`；jsdom 造不出可信事件）。

### 3.11 页头、文案与读屏

- 进行中的按钮不卸载、`aria-disabled`、`aria-busy`；随状态消失的按钮由 `useFocusRescue` 接住（规范 §2.4）。

- **实施**（S8，焦点通查）：每次重建时新建的 Univer 把焦点放进自己的输入框，P5 的各条路径都没有落到 body——空闲释放、交出、本人接管的两边、被强制接管：新的编辑器；"请求编辑"：同一个按钮（"取消请求"）；强制接管没成功：还在"强制接管"上；它随权限或保留消失、"继续编辑""知道了"：返回链接（`useFocusRescue`）。修正两处：确认框的 `returnFocus`；强制接管进入编辑的过程中按钮留着不卸载。`handover-focus.spec.ts` 钉着这些去处。
- **实施**（S7）："编辑""请求编辑""正在请求…""取消请求""正在取消…"同一个按钮元素（等待中"有更新"重建期间仍能取消）；持有者的提示放在页头下面，带标题的分组；读屏的那一句进一直在的 `StatusRegion`，只有这一句时视觉隐藏（分组里已经写着）；交出之后分组消失，焦点随重建落进新的编辑器（S8 的焦点通查）。"请求编辑""取消请求"与"编辑"走同一个会话确认，"交出""继续编辑"与"退出编辑"走同一个；交出与取消请求都用 `keepalive`。"留到 HH:mm"用新的 `formatClockTime`（只格式化服务端的时刻）。
- **实施**（S6）："编辑""在此编辑""正在接手…""仍在此编辑""正在进入编辑…"是同一个按钮元素，只换文字，进行中 `aria-disabled` 与 `aria-busy`；那边没能交出时另加"取消"，点了随之消失，焦点由 `useFocusRescue` 交给返回链接。`elsewhereThisPage` 保留"最多 90 秒"——那是本页自己那一代的事实，不是让人去等的建议，末尾改成"可以直接点'在此编辑'"。

### 3.12 锁的顺序与确定交错

- 不新增锁的种类，锁顺序表不变（…文档行 → 租约行 → 审计）。申请（含本人接管、强制接管）：文档行 → 租约行 → 审计。请求的发出、续期、取消、谢绝、交出：**只锁租约行**，锁住之后再读文档的代次（与心跳、释放同一个做法）。
- 保存在文档行锁下不加锁读租约行，仓储的注释要求"在不锁文档行的路上改别的列之前先重新论证"：新的不锁文档行的写路径只改"结束"两列与保留两列（交出，性质同释放）、请求列（请求、谢绝、取消），都不改持有者、令牌、代次；保存也不读请求与保留——原来的线性化论证照样成立（写进 ADR-018 的补充与仓储注释）。
- **实施**（S4）：交出 vs 请求方取消、交出 vs 第三人申请、两个请求方同时发出、请求续期 vs 持有者自己的新一代、请求续期 vs 第三人在到期之后申请、谢绝 vs 取消、接管 vs 交出（两种先后）（`lease-request-locks.test.ts`）。照搬的 `inOrder` 在等第二个请求停在锁上时与 `raceAgainstHeldLock` 自己的等待同时轮询，外层先看到就提交，里层误报"前提不成立"——改成里层只等第一个（S3 的文件一并改）。
- **实施**（S3）：接管与旧持有者的保存、接管与心跳各两种先后（`self`、`force` 各一遍）、两个管理员同时强制接管、强制接管与管理员被降级两种先后（`lease-takeover-locks.test.ts`，装了审计的闸门）；"接管与交出"留给 S4。看不到与不存在加 10 个接管的探测。
- 每个新写路径的确定交错（`raceAgainstHeldLock`）：接管 vs 旧持有者的保存（两种先后）、接管 vs 旧持有者的心跳、接管 vs 交出、两个管理员同时强制接管、强制接管 vs 管理员被降级、交出 vs 请求方取消、交出 vs 第三人申请、两个请求方同时发出、请求的续期 vs 持有者自己的新一代、请求的续期 vs 第三人在到期之后申请、谢绝 vs 取消、收回写入权的时间条件。

### 3.13 错误处理、安全与可观测性

- 看不到与不存在一致：每个新路由进"看不到 / 不存在"的核对（外人、回收站里的、只凭授权的人），`takeover` 的两种取值也加。
- 强制接管记审计；交出、本人接管不记（总设计只要求强制接管记审计）。
- 后台请求清单只加 `PUT …/request`；请求、取消、谢绝、交出、接管是用户的操作，顺延登录。
- 令牌只在请求头；接管标记只存摘要；交接频道的消息不带令牌，只带 `documentId`、`requestId`、标签页标识与用户 id（同一个浏览器里本来就同一个人）。
- 页面不记诊断日志（页面没有 logger，生产代码不用 `console`；S6 核实）。**测试构建的交接日志**（S8）：事件类型在 `features/sheet-editor/handover-trace.ts`（17 种：交接请求与回应、锁空了、没有回应、"在此编辑"的开始与锁在不在本浏览器、申请与结果、进入编辑、锁被抢、请求方的发出、续期、交给了我、进入，离开编辑的开始与结果），编辑模式、`self-takeover.ts`、`edit-request.ts` 报出，观察者出错由编辑模式接住；记录器 `editor/testing/handover-log.ts` 挂在 `window.__nerveHandoverLog`（`log()` 交回拷贝，每条另记墙上时间，至多 2000 条），组装处在测试构建里与自动保存的控制各自动态引入；门禁按来源、分块名与禁用关键字三重认出（生产构建里没有）。
- **收尾时**（E1）：整页跳转会取消还在路上的加载，WebKit 还常在 `pagehide` 之前就让它们失败（`pagehide` 也不一定派发）——动态引入的分块报"Importing a module script failed."，公式 Worker 的脚本让编辑器以 `worker-failed` 失败；页面把它们当意外错误上报，E2E 的页面错误夹具算成页面错误（`page-errors.spec.ts` 在 WebKit 上本机十次失败两次，P4 起就有、P5 多引入一个分块之后更常见）。做法：**编辑器的加载失败在页面开始离开之后不上报**——"开始离开"认可信的 `beforeunload`（三个浏览器在整页跳转、含 Playwright 的 `page.goto` 时都先派发它、之后才取消加载，探针核对；页面自己派发的不可信、不算），之后 10 秒内的加载失败不报，别的时候照常立即上报；编辑器里测试构建的模块（档案故障、公式模式、探针）没引入成按编辑器建不起来处理（`SheetEditorLoadError` 的 `testing-module-failed`）；页面一开始就引入的测试钩子（自动保存的控制、交接日志）没引入成不上报——跳转可能在入口的脚本执行之前就已开始，听不到它的 `beforeunload`，分不清；用到它们的 E2E 自己会失败。别的意外错误照常立即上报。

### 3.14 真实 Safari 的复核

页面自检加一个两个标签页的场景（驱动脚本已有"另开标签页让编辑器页隐藏"的做法）：A 编辑、键入 → 另开 B（同一会话）→ 等 8 秒后 B 点"在此编辑"——记下有没有 `ack`、多久进入编辑、服务器上的内容与代次；能做到时切回 A 核对它的失效说明。与 Playwright 不同时按真实 Safari 调整回应时限与说法。报告 `reviews/P5-真实Safari复核.md`。

- **实施**（S8 后半）：页面自检加交接的场景（`editor/testing/selftest-handover.ts`）——两个标签页的本人接管（A 编辑、隐藏时上传、隐藏之后再写一格；B 用同一个会话直接打开编辑器页，8 秒后点"在此编辑"）、它的变体"A 收不到交接频道的消息"（挂接给 A 装一个吞消息的频道 `deafenHandoverChannel`，模拟冻结的页面）、刷新时在途的保存（让保存停在服务端时刷新）。驱动脚本另开标签页编排，B 交回结果之后关掉自己、回到 A，按库里的时间线与后端日志判定（编排与判定在 `tests/e2e/support/selftest-handover.ts`）；交接日志另记页面关闭时的处理（`page-hide`：走了哪一支、那一刻保存在途还是结果未知——自检自己的 `pagehide` 监听在 Chromium 系排在编辑器页之后，看不准）；`--steps` 只跑其中几步。Playwright 三个浏览器校准，两种打开状态（暂停与 `E2E_AUTOSAVE=running`）都通过；变异 8 条全部认出。
- **结论**（真实 Safari 27，8 次运行，最终代码上完整的 17 步全部通过）：A 照常回应——ack 在请求之后 3–92 ms 到、done 39–226 ms，点击之后 0.50–0.72 秒进入编辑，A 的修改都在服务器上；A 收不到消息时 B 在 3 秒时本人接管、约 3.5 秒进入编辑，A 在抢锁的那一刻得知，失效说法与另存为副本如实；刷新时 Safari 先取消在途的保存、再派发 `pagehide`，编辑器页看到结果未知、不释放并记下记号，服务端照常提交那次保存，"在此编辑"先等、之后本人接管。回应 3 秒、完成 20 秒、刷新之后等 30 秒三个时限都不改，说法都如实。没测到的（用户自己按刷新、关标签页或窗口、长时间隐藏与休眠、那次保存没有送到时等满 30 秒、请求编辑的两个账户）见报告 §六 与 DEF-062。
- **审查之后**（B4、B8、刷新之后的说法）：answered 那一对的判定改为"A 不释放、B 恰好一次本人接管"，refresh 一步要求 `just-closed` 并逐字核对说法；测试构建、地址带 `selftest` 时先挂好自检的挂接再载入（"A 收不到消息"不再依赖分块的先后）。修复之后的代码上真实 Safari 第 9 次运行（只跑交接的 5 步）26 项全部通过：A 不释放、第 2 代的接管方式是 `self`；ack 3 ms、done 62 ms、569 ms 进入编辑；收不到消息时 3001 ms 判定、3507 ms 进入；刷新之后显示 `just-closed` 的说法，"在此编辑"等了约 6.1 秒、那次保存提交之后本人接管。
