# M3-P2 阅读模式与编辑权的界面：架构设计与实施规划

> 状态：进行中｜日期：2026-10-04｜所属：M3-P2｜依据：M3 总设计 §2.1、§5（P2 一行）、§6.2、§6.5；00 号计划书 §6.1、§6.5、§7.5、§10.2（r14）；P1 交接单的"P2 须知"｜基于代码版本：`31feef2`（main，P1 已合并）

## 1. 目标与范围

打开文档先阅读，点"编辑"进入编辑，"退出编辑"回到阅读；编辑权的每一种变化在页面上如实呈现，失去编辑权时本页的修改按"还读得到就给副本"处理。

- **打开即阅读**：编辑器一律以只读创建；刚由自己新建的表格直接进入编辑。
- **进入与退出编辑一律重建编辑器**（需求方 2026-10-04 决定，§3.1）：新建一个编辑器实例，"能不能编辑"仍在创建时决定（ADR-015），切换前后保留当前工作表与滚动位置。
- **阅读者的更新提示**：阅读时每 30 秒读一次编辑状态，有新版本时提示"有更新，点击刷新"，点了就按新内容重建；"××正在编辑（最后活动 x 分钟前）"随之更新。读取内容支持 `If-None-Match`，修订号没变时 304（DEF-017）。
- **失去编辑权时**：捕获本页的内容，重建为只读、显示本页的内容；还读得到（403）就提供"另存为副本"与"放弃"，读不到了（404）就说明并丢弃（M3 总设计 §2.1 第 4 条）。另存为副本由服务端按快照新建（计划书 §7.5）。续上（P1）照旧。
- **后台请求不顺延登录**（DEF-043）：阅读页的定时检查与心跳不让登录一直不过期。
- **真实 Safari 的页面自检**（DEF-003 的阅读模式部分）：测试构建里的自检页与驱动脚本，在真实 Safari 上复核只读的入口与进入、退出编辑；P4 复核捕获时机时复用。
- 延期项：DEF-017、DEF-027、DEF-028、DEF-035、DEF-036（随"一律重建"关闭）、DEF-040、DEF-043。

用户故事：US-M3-01（阅读与进入编辑）、US-M3-05（阅读者的更新提示）；US-M3-04、11、12、13 的 E2E（服务端部分在 P1）。P2 结束时这 6 个故事改为 active。

**不在本 Phase**：完整的快照校验与内容哈希（P3）；自动保存与打开自检（P4）；请求编辑、本人接管、强制接管、空闲释放、异常中断的提示（P5）。

## 2. 现状（`31feef2`）

- **P1 的合并之后的 CI**：run 37164189575，六项全绿（含 Edge 与容器 E2E）。
- **编辑器**（`apps/web/src/editor/`，ADR-010、ADR-015）：`createSheetEditor({ container, snapshot, access })`，能不能编辑在创建时决定——授权服务的回答在实例里固定，只读守卫分三步装上（创建工作簿之前、之后、就绪时），界面按 `access` 静态配置（工具栏、右键菜单、底栏菜单、新增工作表按钮、工作表标签的 5 项菜单）。现成能撤的只有守卫的 `dispose`。
- **原地切换的探索结论**（2026-10-04，主会话派的探索）：
  - M0 只验证过"以编辑创建 → 原地进只读 → 原地退出"，P2 的主路径"以只读创建 → 原地进编辑"从没验证过；
  - 以只读创建、原地切到编辑，列标题悬停时的菜单按钮一直缺失（`HeaderMenuRenderController` 只在 Rendered 时按当时的配置注册，类不导出，之后补不上）；
  - 原地切换要在运行时让 SDK 重设 22 个工作簿权限点（`SheetPermissionInitController.initWorkbookPermissionChange`，DEF-036）、处理撤销拦截的先后、命令执行栈的残留（UR-005）；
  - **同一个 Univer 实例里 `disposeUnit` 之后再 `createWorkbook`，新单元不再按授权服务设权限点（默认可编辑），也不再有 Rendered**：计划书 §10.2 与 M3 总设计 §6.5 写的"先 disposeUnit 再重新创建"走这条路时，只读会不完整。
- **编辑器页**（`features/sheet-editor/`，681 行）：能编辑就在载入时申请编辑权，取得了以可编辑创建，被占用或 403 以只读创建，之后 `readOnly` 不变；失效时只停止保存（编辑器仍能键入，P1 审查 R6）。租约管理在 `edit-lease.ts`（申请、心跳、续上、失效、释放），保存的状态机在 `save-coordinator.ts`。
- **服务端**：`GET /api/documents/{id}/edit-lease`（编辑状态，读快照）已有；内容的读取以修订号作 ETag，不支持 `If-None-Match`；没有"按快照新建"的接口；会话守卫对每个请求按需顺延登录的空闲过期。
- **E2E**：`support/sheet.ts` 的 `openEditor` 在 15 个文件里被调用 62 次，都默认"打开即可编辑"。
- **M0 的真实 Safari 页面自检**（`spikes/m0/scripts/safari-selftest.ts`）：`open -g -a Safari` 在后台打开带 `selftest` 参数的页面，页面用 Facade 做检查、把结果 POST 到同源的收集端，脚本轮询收集端。本机 Safari 是 27.0。

## 3. 设计

### 3.1 模式切换一律重建（需求方 2026-10-04 决定）

**决定**：进入编辑、退出编辑、失去编辑权、"有更新，点击刷新"，都销毁当前的编辑器（Univer 实例与公式 Worker），以目标的 `access` 新建一个；不做原地切换，也不在同一个实例里 `disposeUnit` 再创建。

**理由**：
1. "能不能编辑在创建时决定"已经由 M2-P3 的 E2E 全面验证（M0 的 28 个编辑入口、全部已注册的快捷键、撤销与重做、图片、批注、编辑栏、冻结线）；重建直接复用，不新增任何运行时的只读机制。
2. 原地切换的主路径有补不上的界面缺口（列标题的菜单按钮），还要新登记内部 API 让 SDK 在运行时重设权限点、处理撤销拦截的先后与执行栈的残留——每一处都是新的、没有验证过的只读机制。
3. 同一个实例里 `disposeUnit` 再创建会让只读不完整（§2），只能整个实例重建。
4. 代价是每次切换一次重新渲染（M0 的单次样本：到 Rendered 约 0.33–0.35 秒，不含 Worker）。S5 用平台的实际路径（公式 Worker、`IMAGE()` 的安装）实测，明显超过 1 秒再与需求方商量（需求方的决定）。

**切换的过程**（编辑器页编排，§3.4）：
1. 取出当前的视图状态（当前工作表、左上角可见的行列、选区；§3.3）；
2. 决定用哪一份快照：进入编辑、退出编辑与失去编辑权时用本页手里的内容（进入时修订号没变：载入的那一份；退出时保存之后：捕获的那一份；失效时：捕获的本页内容），修订号变了或"有更新"时按 `If-None-Match` 取服务端的；
3. 销毁旧的编辑器（交互屏障挡住期间的输入，与载入时相同）；
4. 以目标的 `access` 与那一份快照新建，就绪之后恢复视图状态；
5. 页头与保存的状态机随之换上（只读时没有保存的状态机）。

DEF-036（运行时改变授权的回答）与执行栈的残留（UR-005）随之不再相关：DEF-036 关闭，ADR-015 的"影响"一节改写。DEF-035（渲染时不经 mutation 改单元格图片的尺寸）不作为"阅读时被改过"的依据：它在阅读、编辑、重建之后都会原样发生（探索结论），重建消除不了它。

### 3.2 服务端

**另存为副本**：`POST /api/documents/{id}/conflict-copies?requestId&title`，正文是 gzip 压缩的快照（与保存同一个读取方式：压缩前后都限 5 MiB、单个完整的 gzip 成员）。
- 只要求能读原文档（读不到 404，看不到与不存在一致）：失去编辑权、还读得到的人正是要用它的人；
- 放在哪里（计划书 §7.5）：本人在原文档所在的空间有新建权限时，放进原文档所在的文件夹（文件夹不在了放空间的根目录）；否则放进本人的个人空间的根目录；
- 标题由页面给出（`documentTitleSchema` 校验）：原标题加"（冲突副本 时间）"，时间按页面所在的时区写到分钟；contracts 提供 `conflictCopyTitle(sourceTitle, label)`，加完超过上限时按码点截断原标题（与 `copiedDocumentTitle` 同一个写法）；
- 快照做 M1 的基本校验（P3 的完整校验同样适用于它），快照的 `id` 要等于原文档的 `unit_id`（`unitId` 不改写，§8.3），副本的 `unit_id` 与原文档相同；
- 新文档：类型、档案、平台格式版本照原文档，SDK 版本是服务端内置的；修订号 1；不继承原文档的单独授权；修订记录的种类是 `created`；
- `requestId` 幂等（与新建、复制同一个做法：同一个人同一次请求返回原来的结果，带 `replayed`）；
- 审计：新动作 `documents.conflict_copied`（明细：原文档 id、新文档所在的空间；不记标题）；
- 响应与复制相同：新文档的 `DocumentDetail`。

**读取内容的条件请求**（DEF-017）：`GET /api/documents/{id}/content` 带 `If-None-Match` 而修订号等于它时回 304（仍先判断权限，看不到与不存在一致；304 不带内容）；读快照里判断。

**编辑状态带上能否编辑**：`editStatusSchema` 加 `canEdit`（调用者现在能不能编辑这份文档，与详情的 `permissions.canEdit` 同一个规则）。阅读页据此显示或隐藏"编辑"（权限在阅读期间可能变化）。

**后台请求不顺延登录**（DEF-043）：会话守卫按接口上的标记（`@BackgroundRequest()`，`shared/`）跳过空闲过期的顺延；标在编辑状态（阅读页每 30 秒一次）与心跳（续租）上。用户的操作（保存、打开、整理）照常顺延。P4 有了自动保存之后，编辑中的保存会让登录保持有效。

### 3.3 适配层

- **视图状态**：`SheetEditor` 加 `viewState()`，`createSheetEditor` 加可选的 `viewState`，就绪之后恢复：当前工作表（按 id；不在了就用默认）、左上角可见的行列（滚动位置）、主选区。优先用 Facade（`FWorkbook`、`FWorksheet` 的公开方法）；没有公开方法的项登记为内部 API（ADR-010）。恢复失败不影响编辑器可用（记一条警告，回到默认视图）。
- **DEF-027**（只读时冻结区域的分隔线显示调整光标）：探索的结论是根因很可能不是"冻结区域"，而是 SDK 判断行高、列宽的权限时把第 1 行、A 列（索引 0）当作"没有给出"一律放行。先用 E2E 核实（没有冻结的表上拖第 1 行的下沿），属实则只读时在 `HEADER_RESIZE_PERMISSION_CHECK` 上注册一个优先级高于 SDK 的、总是不允许的拦截器（写法同冻结线的拦截，登记内部 API），DEF-027 完成。
- **DEF-028**（只读时"高级查找"的链接）：只读的编辑器容器带一个标记，样式按 SDK 的 DOM 标记（查找面板 `data-u-comp="find-replace-dialog"`）隐藏那个链接；DOM 标记登记（ADR-010），E2E 核对只读时看不到、编辑时照常。
- **DEF-035 的旁支**：探索推断"在单元格编辑器或编辑栏里粘贴带图片的内容"可能不经被拦的命令写入单元格图片。用 E2E 核实；能写入的话入口守卫补上带 drawings 的 `InnerPasteCommand`（否则 P3 的完整校验上线之后这类保存会被拒）。核实的结论与处理写进交接单。

### 3.4 编辑器页

页面现在 681 行，P2 的状态再放进去会难以维护。拆出 **`edit-mode.ts`**（不依赖 Univer 与界面，用假的编辑器工厂、假的接口与假的时钟做单元测试）：阅读与编辑的状态机，持有当前的编辑器、租约（`edit-lease.ts`）与保存的状态机（`save-coordinator.ts`）；`editor-page.ts` 留下载入、会话与页头的编排。

**状态**：

| 状态 | 编辑器 | 页头 |
|---|---|---|
| 阅读（不能编辑） | 只读 | 只能查看；没有"编辑" |
| 阅读（能编辑） | 只读 | "编辑"；有人在编辑时说明是谁（是自己时说在另一个标签页或设备上） |
| 进入编辑中 | 只读，交互屏障 | "正在进入编辑…" |
| 编辑 | 可编辑；保存的状态机 | 保存状态、"保存"、"退出编辑" |
| 退出编辑中 | 可编辑，交互屏障 | "正在退出编辑…" |
| 失去编辑权（有修改、还读得到） | 只读，显示本页的内容 | 原因；"另存为副本""放弃本页的修改" |
| 失去编辑权（读不到了，或没有修改） | 只读（读不到时显示本页的内容并说明） | 原因；读得到时"重新加载"（403），读不到时只说明（404，P1 审查 B2） |

**转移**：
- **打开**：以只读创建；能编辑时页头给"编辑"。地址带 `?edit=new`（新建表格之后的跳转）时、而且能编辑，直接进入编辑，进入之后把这个参数从地址里去掉（刷新不再自动进入）。
- **进入编辑**：申请编辑权（`acquireEditLease`）→ 被占用：留在阅读，页头说明谁在编辑；403：留在阅读，"编辑"消失；404：按读不到处理；取得了：申请得到的修订号等于本页的修订号就用本页的内容，否则按 `If-None-Match` 取服务端的内容 → 重建为可编辑（§3.1）→ 建保存的状态机（基准是这一份内容的修订号）。重建失败时释放刚取得的编辑权、回到阅读并说明。
- **退出编辑**：有未保存的修改先保存（提交正在编辑的单元格；保存失败就留在编辑、说明原因，不释放）→ 捕获 → 释放编辑权（等它的结果；结果未知也照样退出，租约 90 秒内自行到期）→ 重建为只读（用捕获的内容）。
- **失去编辑权**（续租或保存得到失效、403、404，且续上没有成功；P1 的续上规则不变）：停止保存 → 提交正在编辑的单元格、捕获本页的内容 → 重建为只读、显示本页的内容 → 页头按上表说明。
  - **另存为副本**：上传捕获的快照（§3.2）→ 成功：页头说明"已另存为副本《…》"并给链接（在新标签页打开），本页按服务端的最新内容重建为阅读；失败：说明原因，内容留着，可以再试。
  - **放弃本页的修改**：按服务端的最新内容重建为阅读（读不到时显示"内容不存在"）。
  - 结果未知的保存：给副本之前，先原样重发那一次结果未知的保存请求（重放先于登录与租约，P1）——拿到原来的结果就说明它其实已经提交，按"已保存"处理、不再说"没有保存"（P1 交接单"P2 须知"的偏保守说法）。
- **阅读者的定时检查**：阅读时每 30 秒读一次编辑状态（页面隐藏时暂停、回到前台立即读一次）：
  - 修订号比本页新：页头提示"有更新，点击刷新"；点了按 `If-None-Match` 取内容、重建为阅读（保留视图状态）；
  - 持有者与最后活动时间、能否编辑随之更新；
  - 请求失败照常下一次再试；读不到了（404）说明文档已不可访问。
- **页头详情刷新失败**（DEF-040）：`refreshDetail` 失败时页头用与列表相同的"没能刷新"说明（规范 §2.4 的 `RefreshProblem` 一类做法），能重试；不清掉已有的信息。
- 离开提示、保存的快捷键、会话的处理（signed-out、other-user）照旧，只在编辑状态有效。

### 3.5 真实 Safari 的页面自检（DEF-003 的阅读模式部分）

探索给出的做法（§2；约束：页面的 CSP 不允许执行字符串代码、结果只能同源提交或经顶层跳转带出、编辑器页不能嵌进 iframe）：
1. **自检页**：测试构建专用的入口 `selftest.html`（仿照 csp 探针的入口，门禁 `artifacts` 同步：生产构建里没有它），从地址的 `#` 片段读测试账户、同源登录，再跳到编辑器页并带 `selftest=<场景>`。
2. **自检模块**：编辑器页在测试构建、带 `selftest` 参数时，就绪之后动态引入 `editor/testing/selftest.ts`：用探针执行**编译进测试构建**的检查（M2-P3 只读入口清单里能用 Facade 与合成事件执行的部分、撤销与重做、界面检查；P2 的场景另点页头的"编辑""退出编辑"），以命令日志为同步点比较快照；`window.onerror` 与 `console.error` 收集页面错误；结果经同源接口回报。
3. **驱动脚本**（`tests/e2e/safari/`，Node）：起 E2E 的后端（测试构建）、写库造场景、`open -g -a Safari` 在后台打开、轮询结果、写 `tests/e2e/test-results/safari/*.json`，记下 Safari 的版本。不进 CI（CI 上没有 Safari），在本机按需运行；`package.json` 加一条命令。
4. 盲区（与 M0 相同）：可信的键盘输入与输入法由 Playwright 的 WebKit 覆盖，Worker 作用域看不到。

S1 先做只读的入口；S5 加上进入、退出编辑的场景。结论写进 `reviews/P2-S1-真实Safari复核.md`。

### 3.6 错误处理、安全与可观测性

- 另存为副本只要求能读，放在本人有新建权限的地方；不继承授权；看不到与不存在一致（新接口进"看不到 / 不存在"的探测、路由表与权限矩阵）。
- 304 之前照常判断权限；条件请求不改变"读快照"的规则。
- 后台请求的标记只影响登录的空闲过期，不影响认证与 CSRF。
- 重建期间交互屏障挡住输入；重建失败按"编辑器加载失败"说明，能重新加载。

## 7. 风险与未决问题

| 风险 | 应对 |
|---|---|
| 重建的耗时让进入、退出编辑显得慢（大文档、公式 Worker） | S5 实测（多次取样，三个浏览器）；交互屏障与"正在进入编辑…"的说明；明显超过 1 秒时停下来与需求方商量（需求方的决定） |
