## 任务

### S1 镜像

- [x] 1. `.dockerignore`：排除 `node_modules`、各 `dist`、`.git`、`.claude/`、`refer/`、`spikes/`、测试输出、`.env*`。
- [x] 2. `deploy/Dockerfile`：`base`、`manifests`、`build`、`prod-deps`、`runtime` 五个阶段；非 root、exec 形式的命令、Node 的健康检查、OCI 标签。pnpm 的全局安装要执行它自己的安装脚本（放好原生二进制；否则开了 shellEmulator 的脚本里启动 pnpm 得到 Exec format error）。
- [x] 3. 服务端许可清单：`tools/src/deploy/server-licenses.ts` 与单元测试；镜像构建时生成；缺正文的 5 个包补进 `apps/api/third-party-licenses/`；`licenses` 门禁提前核对。
- [x] 4. `pins` 门禁：Dockerfile 的 Node 标签等于 `.node-version`、pnpm 版本等于 `packageManager`、镜像带摘要、同一个镜像各处一样；单元测试。
- [x] 5. 本机构建（linux/arm64）；容器连开发库迁移、启动、就绪；只读根文件系统、去掉全部 capabilities、`init` 下正常，SIGTERM 优雅退出（退出码 0）；体积在 S4 的编排脚本里记录。

### S2 应用侧的部署前提

- [x] 1. `deploy/sql/bootstrap-roles.sql`；集成测试：按它建角色与库，执行迁移，以应用角色读写，关不掉审计表的触发器。（集成测试环境不一定有 psql：测试按 psql 的规则执行脚本，只支持脚本用到的写法；真正的 psql 由测试环境的数据库初始化执行）
- [x] 2. 启动时的数据库角色自检（超级用户、审计表的所有者）与单元测试。（放在 audit 模块：只追加的保护是它的）
- [x] 3. 代理未被信任的告警（HTTPS 公开地址、`request.secure` 为假，每个进程一次）与测试。（只看带转发头的请求：健康检查直接访问应用）
- [x] 4. 哈希排队的上限与等待时限（配置、信号量、503 与 `Retry-After`、登录页的说明）与单元、集成测试；容器里的 Argon2 基准测试，定默认值。

### S3 测试环境编排

- [x] 1. `deploy/test/compose.yaml`、`Caddyfile`、`db-init/10-roles.sh`、`.env.example`。（`pins` 门禁不再检查整个是变量的 `image:`：那是本仓库构建、运行时指定的镜像；Caddy 另去掉 `Via`，不宣告 HTTP/3）

- [x] 3. 按部署说明手工起环境：迁移、初始化管理员、经 HTTPS 登录、新建、保存、重开；核对响应头、gzip 的内容响应、6 MB 以内的上传、就绪探针对外 404。（真正的 psql 执行了初始化脚本；应用以 `nerve_app` 运行，自检不告警；审计里的客户端地址是本机经发布端口的来源地址，不是 Caddy 的；5.9 MB 的上传到达应用、6.5 MB 由 Caddy 拒绝；`docker compose stop` 时应用优雅退出，退出码 0。浏览器的核对由 S4 的容器 E2E 完成）

### S4 E2E 与 US-M1-10
