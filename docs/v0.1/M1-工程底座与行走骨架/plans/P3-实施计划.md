### S2 会话、登录与防护

- [x] 1. contracts：`auth/`（登录请求、会话信息、`X-CSRF-Token`）；错误码 `UNAUTHENTICATED`、`SESSION_EXPIRED`、`INVALID_CREDENTIALS`、`TOO_MANY_ATTEMPTS`、`CSRF_TOKEN_INVALID`、`ORIGIN_NOT_ALLOWED`。
- [x] 2. 配置：`NERVE_PUBLIC_ORIGIN`（本机调试之外必须是 HTTPS）、会话的两个时长（交叉检查空闲不大于绝对）、登录限流的四个参数；集成测试的辅助与 `.env.development` 同步。
- [x] 3. 表定义 `auth_sessions`、`auth_login_throttles` 与迁移 `0003_auth_sessions`。
- [x] 4. auth 模块，纯逻辑测试先行：
  - 会话令牌与摘要、CSRF 令牌的派生与常数时间比较；
  - Cookie 的属性（HTTPS 与本机调试）；
  - 限流的判断。
- [x] 5. auth 模块，实现：
  - 会话仓储与 `SessionService`（新建、校验、活动顺延、撤销、清理）；
  - 限流仓储与 `LoginThrottle`；
  - `AuthService.login()`（先查限流、假哈希、需要时重新哈希、撤销浏览器原来的会话、审计）与 `logout()`；
  - 控制器：登录、退出、会话。
- [x] 6. `shared/public.ts` 的 `@Public()`；health 的探针标为公开。
- [x] 7. 全局守卫：会话守卫（`@CurrentUser()`、请求上下文的用户）、CSRF 与 Origin 守卫；在 app 层按顺序注册。
- [x] 8. 日志：请求结束的日志与请求内的日志带 `userId`；脱敏清单核对（会话令牌、CSRF 令牌）。
- [x] 9. 集成测试（每个接口四类）：
  - 登录：成功（Cookie 的属性、审计）；密码错误与用户不存在的响应相同；限流（按用户名、按地址、锁定后正确的密码也被拒绝、窗口过后恢复）；Origin 不对；
  - 会话：空闲过期、绝对过期、撤销、活动顺延只在超过 1 分钟时写库；
  - 退出：CSRF 令牌缺少或错误、Origin 不对；
  - 已有接口（探针）仍然公开；其他接口默认要求登录。
