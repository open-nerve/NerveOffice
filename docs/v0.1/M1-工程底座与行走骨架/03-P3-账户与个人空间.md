> 状态：进行中｜日期：2026-09-26｜基于代码版本：`caf715c`

## 1. 目标与范围

对应 M1 总设计 §5 的 P3 一行：能登录并进入个人空间。本 Phase 交付以下用户故事：

## 3. 设计

### 3.1 模块划分与依赖方向

**后端**新增五个模块：

| 模块 | 职责 | 依赖 |
|---|---|---|
| users | 账户（用户名、显示名、密码哈希、系统角色、状态）；密码哈希；初始化首个管理员 | spaces、audit、database |
| spaces | 个人空间（M2 扩展为团队空间与成员）；"某人的个人空间""是否为空间的所有者" | database |
| auth | 登录、退出、会话；登录限流；认证与 CSRF、Origin 的全局守卫；当前用户的参数装饰器 | users、spaces、audit、database、config |
| documents | 文档元数据（P4 加上内容与修订）；列表与读取；访问策略 | auth（当前用户）、spaces、database |
| web-hosting | 托管前端产物：静态资源、页面路由的回退、缓存头 | config |

- 依赖是单向的：auth → users → spaces；documents → auth、spaces。没有循环。
- **"不需要登录"的标记放在 `shared/`**：`@Public()` 只是一条元数据，health 等模块用它时不必依赖 auth；读它的是 auth 的全局守卫。
- **全局守卫由 app 层注册**（`APP_GUARD`），顺序固定：先认证（会话守卫），再 CSRF 与 Origin 检查。
- **命令行经 app 层的程序接口**：`cli/init-admin.ts` 调用 `app/index.ts` 的 `initializeAdmin()`，后者建一个不带 HTTP 的 Nest 应用上下文。边界策略加上"api-cli 可以引用 api-app 的入口"；这正是 `app/index.ts` 的定位（"命令行与集成测试共用的程序接口"）。
- 模块之间的数据只经对方的服务取得，不跨模块联表：documents 先从 spaces 取得个人空间的 id，再按空间查自己的表。

**前端**按 ADR-003 的分层：

```text
apps/web/src/
  entries/platform/     入口：挂载应用
  app/                  路由表、Provider（请求缓存）、布局、错误边界
  features/
    auth/               登录页、会话状态（useSession）、退出、未登录与过期的跳转
    documents/          个人空间的文档列表
  shared/
    api/                请求层：同源请求、CSRF 请求头、错误解析、响应校验
    ui/                 界面组件（改写后的 shadcn/ui）
    i18n/               界面文字（简体中文，集中管理）
    lib/                cn() 等小工具
```

编辑器（`src/editor/`）在 P4 建立。

### 3.2 数据模型与迁移

枚举的取值放在 contracts，表定义用 `text` 加 CHECK 约束（与 P2 的审计表一致）。三个迁移分别随 S1、S2、S3 生成：`0002_users_and_spaces`、`0003_auth_sessions`、`0004_documents`。

### 3.3 接口契约

请求与响应的结构写在 contracts（`auth/`、`users/`、`spaces/`、`documents/`），前后端共用。

| 接口 | 需要登录 | 成功 | 错误 |
|---|---|---|---|
| `POST /api/auth/login`，请求体 `{ username, password }` | 否（只查 Origin） | 200，会话信息（见下）；`Set-Cookie` | `REQUEST_INVALID`；`INVALID_CREDENTIALS`（401）；`TOO_MANY_ATTEMPTS`（429，带 `Retry-After`）；`ORIGIN_NOT_ALLOWED`（403） |
| `POST /api/auth/logout` | 是 | 204；清除 Cookie | `UNAUTHENTICATED`、`SESSION_EXPIRED`（401）；`CSRF_TOKEN_INVALID`、`ORIGIN_NOT_ALLOWED`（403） |
| `GET /api/auth/session` | 是 | 200，会话信息 | `UNAUTHENTICATED`、`SESSION_EXPIRED`（401） |
| `GET /api/documents?limit=&cursor=` | 是 | 200，`{ items, nextCursor }` | `REQUEST_INVALID`（limit 不在 1–100、游标不合法）；401 |
| `GET /api/documents/{id}` | 是 | 200，文档元数据与调用者的权限 | `NOT_FOUND`（不存在与无权访问相同）；`REQUEST_INVALID`（id 不是 UUID）；401 |

- **会话信息**：`{ user: { id, username, displayName, systemRole }, personalSpace: { id, name }, csrfToken }`。
- **文档摘要**：`{ id, title, type, createdAt, updatedAt }`；列表按 `updatedAt` 从新到旧，同一时间按 `id`。游标是"最后一条的更新时间与 id"的不透明编码（keyset 分页），默认每页 50 条。
- **文档元数据**：摘要加上 `spaceId` 与 `permissions: { canEdit }`。
- **新增错误码**（contracts 的登记表）：

| 错误码 | HTTP | 用途 |
|---|---|---|
| `UNAUTHENTICATED` | 401 | 没有登录 |
| `SESSION_EXPIRED` | 401 | 带着会话 Cookie，但会话已过期或被撤销：界面提示"登录已过期"，而不是当作从未登录 |
| `INVALID_CREDENTIALS` | 401 | 用户名或密码错误，两种情况不区分 |
| `TOO_MANY_ATTEMPTS` | 429 | 登录失败次数过多，暂时锁定 |
| `CSRF_TOKEN_INVALID` | 403 | 状态变更请求缺少或带错了 CSRF 令牌 |
| `ORIGIN_NOT_ALLOWED` | 403 | 状态变更请求的 `Origin` 不是本站 |
| `ADMIN_ALREADY_INITIALIZED` | 409 | 已有系统管理员，拒绝再次初始化 |

- **请求头**：`X-CSRF-Token`（contracts 的常量）。

### 3.4 账户与初始化管理员

- **用户名**：登录时不区分大小写，存小写的规范写法；写法见 §3.2 的 CHECK。显示名 1–64 个字符，去掉首尾空白。
- **密码**：
  - 设置密码（本 Phase 只有初始化管理员；M2 的改密、重置沿用）时要求 12–256 个字符，不设字符种类的要求（NIST SP 800-63B）；
  - 登录时只限制长度 1–1024，不向外透露密码规则；
  - 哈希：Argon2id，参数取自配置，默认内存 19 MiB、迭代 2 次、并行度 1（OWASP 的最低推荐；00 号计划书 §11.1 要求按部署机器的基准测试设置，P5 部署时复核）。参数变了之后，下次登录成功时用新参数重新哈希；
  - `PasswordHasher` 是接口，单元测试用假实现；实现类包装 @node-rs/argon2。
- **初始化首个管理员**（`AdminInitializationService`，users 模块）：
  1. 在事务之外先算好密码哈希：它是计算密集的操作，事务要尽量短（规范 §5）；
  2. 在一个事务里：
     - 取事务级 advisory lock，两个并发的初始化不会都成功；
     - 已有系统管理员时抛出 `ADMIN_ALREADY_INITIALIZED`，数据不变；
     - 创建账户（`admin`）与个人空间；
     - 写审计 `users.admin_initialized`（来源 `cli`，操作者 `system`，对象是新账户）。
- **命令行**：`node dist/cli/init-admin.js --username <用户名> [--display-name <显示名>] [--password-stdin]`，开发环境用 `pnpm admin:init --username <用户名>`。
  - 密码不出现在命令行参数与日志里：
    - 终端里交互输入，输入两次，不回显；
    - 非交互环境（脚本、容器的一次性任务）用 `--password-stdin` 从标准输入读取，去掉末尾的一个换行；
    - 非交互环境又没有 `--password-stdin` 时报错退出。
  - 退出码：0 成功；1 已初始化、输入不合法或数据库错误（说明写到标准错误）；2 用法错误。
  - 应用上下文按配置连接数据库，与 HTTP 服务同一套配置与日志；执行完关闭连接池。

### 3.5 会话、登录与防护

- **会话令牌**：32 字节随机数，base64url 编码后放进 Cookie；数据库只存它的 SHA-256 摘要，按摘要查找。
- **Cookie**：
  - `HttpOnly`；`SameSite=Lax`；`Path=/`；不设 `Domain`；
  - `Max-Age` 取绝对过期时长：关掉浏览器再打开仍然登录，过期由服务端判断；
  - 公开地址（`NERVE_PUBLIC_ORIGIN`）是 HTTPS 时带 `Secure`，名称用 `__Host-nerve_session`（浏览器强制 `Secure`、`Path=/`、不带 `Domain`）；
  - 公开地址只有在本机调试（`127.0.0.1`、`localhost`、`::1`）时才允许是 HTTP，这时名称是 `nerve_session`，不带 `Secure`。
- **会话的生命周期**：
  - **登录**：新建会话，每次登录都换新的令牌，防会话固定；浏览器原来带着的会话一并撤销（原因 `replaced`）。
  - **每个请求**：按摘要查会话，要求没有撤销、没有超过空闲过期与绝对过期（都用数据库时间），账户仍是 `active`。
  - **活动顺延**：距上次记录超过 1 分钟时，才更新 `last_seen_at` 与空闲过期（不超过绝对过期），免得每个请求都写一次库。
  - **退出**：撤销会话（原因 `logout`），清除 Cookie。
  - **清理**：登录时顺带删除一小批过期或撤销已超过 30 天的会话（每次最多 100 条），表不会无限增长。
  - 默认时长：空闲 12 小时，绝对 7 天，都可以配置。
- **认证（默认拒绝）**：全局的会话守卫对每个接口生效，标了 `@Public()` 的除外（登录、存活与就绪探针）。
  - 没有 Cookie 时返回 `UNAUTHENTICATED`；
  - 有 Cookie 但会话无效时返回 `SESSION_EXPIRED`，并清除 Cookie；
  - 认证通过后，当前用户挂在请求上，控制器用参数装饰器 `@CurrentUser()` 取得；它也写进请求上下文，请求日志随之带上 `userId`（规范 §7）。
- **CSRF 与 Origin**（全局守卫，只对 `POST`、`PUT`、`PATCH`、`DELETE`）：
  - **Origin**：必须等于配置的公开地址，缺少也拒绝，登录接口同样检查（防登录 CSRF）。浏览器对非 GET 请求（包括同源）都会带 `Origin`。
  - **CSRF 令牌**（需要登录的接口）：请求头 `X-CSRF-Token` 必须等于 `base64url(HMAC-SHA256(会话令牌, "nerve-office:csrf:v1"))`，按常数时间比较。
    - 令牌由会话令牌派生，不用另外存储；
    - 前端从登录与会话接口的响应里拿到它；
    - 攻击者的页面读不到这些响应（同源策略，不开 CORS），也读不到 HttpOnly 的 Cookie。
  - 与 `SameSite=Lax` 一起，是三层防护。
- **登录限流**（计数存在数据库里，重启不丢；将来多实例也共用）：
  - **两个维度**：
    - 按用户名：窗口 15 分钟内失败 5 次，锁定 15 分钟；
    - 按客户端地址：窗口 15 分钟内失败 50 次，锁定 15 分钟。
    - 都可以配置；键只存摘要。
  - **验证之前先查**：任一维度锁定中，直接返回 `TOO_MANY_ATTEMPTS` 与 `Retry-After`，不验证密码。
  - **失败时**：两个维度各加一次，达到上限就锁定，计数用一条 `INSERT … ON CONFLICT` 原子地更新。
  - **成功时**：只清除这个用户名的计数。地址的计数不清，免得攻击者夹着自己账户的成功登录继续尝试别的账户。
  - **不存在的用户名**：同样计数；验证时拿一份固定的假哈希算一次，响应时间与"密码错误"相近，不暴露账户是否存在。
  - **清理**：失败时顺带删除一小批窗口与锁定都已过期的计数。
  - **客户端地址**：来自 Express 的 `request.ip`，经 `trust proxy` 识别反向代理（P2）；P5 部署时按反向代理配置。
- **审计**：
  - `auth.login_succeeded`：操作者与对象都是这个账户；
  - `auth.login_failed`：操作者匿名；用户名对应的账户存在时，对象是这个账户；`details.reason` 为 `invalid_credentials`，因这次失败被锁定时另记 `lockedUntil`；
  - 锁定期间被拒绝的请求只记日志（warn），不写审计，免得攻击时写爆审计表；
  - `auth.logout`：操作者是这个账户。
  - 以上都带请求标识与客户端地址。

### 3.6 个人空间、文档列表与访问策略

- **spaces**：
  - `createPersonalSpace(userId, name, { transaction })`：由 users 在创建账户的同一个事务里调用；
  - `personalSpaceOf(userId)`；
  - `isOwner(userId, spaceId)`。
- **documents**：
  - **列表**：`GET /api/documents` 只列当前用户个人空间里的文档，按更新时间分页（§3.3）。M2 加上团队空间与"与我共享"时，改为按参数指定空间，调用方不变。
  - **读取**：`GET /api/documents/{id}` 先按 id 查文档，再经访问策略判断；没有读取权限与不存在返回同一个 `NOT_FOUND`（规范 §4，US-M1-08）。
  - **访问策略**：`DocumentAccessPolicy` 接口，`accessOf(user, document)` 返回 `owner`、`editor`、`viewer` 或"无权"。
    - M1 的实现只有一条规则：文档所在空间是这个人的个人空间，结果为 `owner`；
    - M2 在同一个接口后面扩展为 00 号计划书 §5.2 的有效权限，控制器与服务不改。
  - 本 Phase 没有新建文档的接口（P4）：测试数据由集成测试与 E2E 直接写库。

### 3.7 前端骨架

- **基础**（ADR-008）：
  - React Router 8：数据路由（`createBrowserRouter`），只用库模式，不用框架模式与服务端渲染；
  - TanStack Query 5：管理服务端数据的加载、失败、重试与缓存；
  - Tailwind CSS 4：构建时生成样式文件，没有内联脚本；
  - 界面组件取自 shadcn/ui 的 Radix 版本（`radix-nova` 风格），代码放进 `shared/ui` 并按项目的规范改写（§2 的探针）；
  - 系统字体，不加载字体文件。
  - 路由表只写组件（`Component`、`ErrorBoundary`），测试用同一张表建内存路由；跨功能的流程在 app 层测试，功能模块的测试只渲染自己的组件。
- **路由**：
  - `/login`：登录页。已登录时直接转到首页；
  - `/`：我的空间，即文档列表。未登录时转到 `/login`，登录后回到原来要去的地址（只接受站内的相对路径）；
  - 其他地址：404 页面；
  - 路由的错误边界：通用的错误页，带请求标识，可以重试。
- **请求层**（`shared/api`，规范 §2.4"服务端数据经统一的请求层获取"）：
  - 同源请求，`credentials: 'same-origin'`；非 GET 请求带 `X-CSRF-Token`；
  - 错误响应按 contracts 的结构解析成带错误码的 `ApiError`；
  - 成功的响应也用 contracts 的结构校验：接口与前端不一致时立即暴露，而不是渲染出错的数据。
- **会话状态**（`features/auth`）：
  - `useSession()` 查询 `GET /api/auth/session`，把 CSRF 令牌交给请求层；
  - 任何请求得到 `UNAUTHENTICATED`、`SESSION_EXPIRED` 时（由请求缓存的全局错误处理统一接住），清空缓存，转到登录页；过期时提示"登录已过期，请重新登录"；
  - **退出**：成功后清空全部缓存，以替换历史记录的方式转到登录页。按后退键回到列表地址时，数据要重新请求，得到 401 后回到登录页，看不到内容（US-M1-02）。
- **登录页**：
  - 用户名与密码都有标签；提交中按钮不可用，防重复提交；
  - 错误分别提示：用户名或密码错误（两种情况同一句话）、尝试次数过多（带等待时间）、网络或服务错误。
- **文档列表页**：
  - 加载中显示骨架屏；空列表显示"还没有文档"；
  - 加载失败显示说明与"重试"；
  - 分页用"加载更多"，它自己的加载中与失败状态单独显示。
  - 本 Phase 的条目只显示标题、类型与更新时间，打开与新建随 P4 的编辑器页加入。
- **界面文字**：集中在 `shared/i18n/zh-cn.ts`；错误码到提示文字的对应也在这里。
- **开发**：Vite 开发服务器把 `/api` 代理到 `pnpm dev:api`（`127.0.0.1:3000`）。`.env.development` 的公开地址是开发服务器的地址，浏览器的 `Origin` 与之相同，CSRF 与 Cookie 在开发时照常生效。
- **首屏体积预算**（规范 §11）：
  - 新增门禁 `budgets`：按构建清单计算每个入口的首屏 JS（入口块加上它静态引用的块，不含动态加载的块），用 gzip（默认压缩级别）统计；
  - 平台页面入口的预算定为 180 KiB。S4 实测约 147–152 KiB，主要是 react-dom 65、React Router 31、contracts 与 zod 26、TanStack Query 11、tailwind-merge 9、应用代码 7，留约 15% 的余量（ADR-008）；
  - P4 加上表格编辑器入口的预算。
- **zod 与 CSP**：zod 4 默认用 `new Function` 探测能否做 JIT，在定稿的 CSP 下会报一条违规。前端入口在渲染之前设置 `jitless`，运行时不再探测；产物里的探测代码由门禁 `artifacts` 登记为已知探测（函数体是空字符串，不执行任何代码）。

### 3.8 托管前端产物

- 配置 `NERVE_WEB_ROOT` 指向前端的构建目录：
  - 设置时，应用同时托管前端（P5 的镜像这样部署，E2E 也这样测）；
  - 不设置时只提供接口（开发时前端由 Vite 开发服务器提供）。
- **管线**：挂在安全响应头之后、JSON 请求体之前，只处理 `GET` 与 `HEAD`，从不处理 `/api` 下的地址。
  - **静态文件**：Express 自带的 `express.static`（不列目录，不提供点开头的文件）。
    - 带哈希的资源（`/assets/`）：`Cache-Control: public, max-age=31536000, immutable`；
    - 其他文件：沿用默认的 `no-store`。
  - **页面路由的回退**：路径没有扩展名的请求返回入口页 `index.html`（`no-store`）；有扩展名但找不到的文件交给后面，得到统一的 404 错误响应。
  - **入口的映射**：路径到入口页的映射是一张表，本 Phase 只有平台页面；P4 把编辑器的路径映射到编辑器页。
- **安全头**：静态文件与入口页同样经过安全响应头的中间件，HTML、脚本与 Worker 脚本都带定稿的 CSP（US-M1-09）。
- **请求日志**：成功的静态文件请求记为 `debug`，默认级别下不输出，免得刷屏；出错照常记录。

### 3.9 CSP 阳性对照（只在测试构建里）

- **测试构建**：`vite build --mode e2e`，输出到 `dist-e2e/`。它在生产构建的基础上多一个入口 `csp-probe.html` 与一个探针 Worker。
- **生产构建**（`dist/`）不包含探针，由门禁 `artifacts` 检查。
- **探针的动作**：页面与 Worker 各自执行三件事，把结果（放行或被拦截）写到页面上：
  - 向另一个源发请求（地址由查询参数给出）；
  - `eval`；
  - `new Function`。
- **E2E**：
  - 在应用上打开探针：页面与 Worker 的三个动作都被拦截；
  - **对照**：用一个不带安全头的静态服务提供同一份探针，三个动作都放行，证明探针本身有效、目标可达；
  - 目标由测试自己起一个本机服务。

### 3.10 E2E 基础设施

- **服务的启动**：Playwright 的 `webServer` 执行 `tests/e2e/support/serve.ts`，依次：
  1. 新建一个本次运行专用的数据库（名称带进程号；遗留的库在下次启动时按进程是否还在清理，与集成测试一致）；
  2. 执行迁移命令；
  3. 用初始化命令创建管理员，密码经标准输入传入（US-M1-01 的 E2E 用这个账户登录）；
  4. 启动构建好的后端，托管测试构建 `dist-e2e/`；
  5. 退出时删除这个数据库。
- **配置**：
  - 地址 `http://127.0.0.1:4174`，与 `NERVE_PUBLIC_ORIGIN` 相同；
  - 按地址的登录限流调高：所有测试都来自本机，按用户名的限流照常测；
  - 数据库地址经环境变量交给测试进程。
- **测试数据**：每个测试建自己的账户（用户名带随机后缀），测试之间互不影响；账户、个人空间与文档直接写库（`pg`，密码哈希用 @node-rs/argon2）。
- **门禁**：

  - `pnpm test:e2e` 同样先构建后端与测试构建；
  - CI 用已有的 PostgreSQL 服务容器。
- 原来的框架冒烟改为"登录页的标题正确，没有控制台错误"。

## 7. 风险与未决问题

| 风险 | 应对 |
|---|---|
| React Router 8 是第一次在本项目使用的大版本 | S4 开头在真实骨架上验证数据路由、错误边界与构建体积；有问题退回 7.18（仍在维护，与 8 同时发布补丁） |
| E2E 的服务要先准备数据库，而 Playwright 的 `webServer` 与全局准备的先后不便控制 | 数据库的准备放在 `webServer` 自己执行的脚本里，服务可用即代表数据库已就绪 |
| WebKit 对本机 HTTP 上的 `Secure` Cookie 的处理与 Chromium 不同 | 本机调试时公开地址是 HTTP，Cookie 不带 `Secure`（§3.5）；生产必须是 HTTPS，由配置校验保证 |
| 所有 E2E 都来自 `127.0.0.1`，按地址的限流会互相影响 | E2E 调高按地址的上限；按地址的限流由集成测试覆盖 |
| Argon2id 的默认参数在较慢的服务器上可能偏慢，或者需要更强的参数 | 参数可配置，哈希里带参数，改了之后登录时自动重新哈希；P5 在部署机器上做基准测试并记录 |
| 会话校验要查会话与账户两次，每个请求多两次查询 | 都按主键或唯一索引；活动顺延最多每分钟写一次。M7 压测时复核 |
| 前端的首屏体积 | S4 实测后定预算；超出时按路由拆分 |
