> 日期：2026-09-28｜所属：v0.1-M1｜对应合并：P1–P5 各自以 `--no-ff` 合并到 main；标签 `v0.1-m1`

## M2 须知

- **先读**：架构总览 v1（`docs/architecture/overview.md`）与 ADR-001 至 012；00 号计划书 r6。
- **访问控制**：服务只经 `DocumentAccessPolicy` 判断权限（M1 只有"个人空间的所有者"一条规则），M2 在同一个接口后面扩展为团队空间、成员与分享的有效权限；没有任何权限与不存在都是 `NOT_FOUND`，能访问却不能编辑时保存得到 `PERMISSION_DENIED`（编辑器页按 `permissions.canEdit` 只读）；`requestId` 的重放按"同一个人"判断。A03（越权访问）的首次验证在 M2。
- **账户**：创建账户时沿用 `USERNAME_TAKEN`；停用账户、修改或重置密码时撤销这个人的全部会话（ADR-007，撤销原因加进 CHECK 约束）。
- **数据**：新表由迁移以所有者建，默认权限自动授权给应用角色；新的对象类型（视图、函数、新的 schema）要先确认应用角色的权限并补进初始化脚本与部署说明（ADR-012）。
- **复制文档**：`documents.unit_id` 不唯一（迁移 0007，Codex 评审 CX5）：按计划书 §8.3 原样复制快照，不改写 unitId；平台的身份是文档 id。
- **密码参数**：调整 Argon2 参数之后，失败的验证按实测的耗时补到"当前参数与现存哈希里最慢的一组"（留 1.2 倍余量，ADR-007，Codex 评审 CX4）。调低参数时，失败的登录都补到旧参数的耗时，直到重启之后库里不再有旧参数的哈希。
- **编辑器页与只读**：载入期间页头之外的输入一律拦下（交互屏障，Codex 评审 CX1）。只读现在靠就绪之后的 `setEditable(false)`，而 SDK 在用户变化时会按授权服务重新初始化权限点、把它改回可编辑；M1 只有个人空间、不会只读，**M2 做只读分享时要让编辑器身份的授权服务（ADR-009）按文档的权限回答**，不能只靠 `setEditable`（独立复验 N1）。
- **工程**：新的用户故事登记进 `tests/stories.json`；E2E 的新用例两种运行方式都要能执行，只在测试构建里成立的打 `@test-build`；强制结束后端的用例放进重启项目；新的 `NERVE_*` 配置同步部署说明与变量模板。
- **测试资源的归属**：集成测试、E2E 与容器 E2E 清理中断的运行留下的库、编排项目与镜像时，按名字里的进程号判断那次运行还在不在，这只在"数据库与 Docker 只供本机使用"时成立。要让几台机器共用一个数据库或 Docker 时，先改成服务端的归属校验（租约），或者只清理本次运行自己的资源（Codex 评审的覆盖说明）。
- **上游报告**：21 条草稿等需求方确认之后提交（`docs/upstream/README.md`）；安全类的两条草稿不在公开仓库里（主目录的 `docs/upstream/private/`）。
