## 与设计的偏差

都已回写到 P4 设计（§3.3–§3.10 的"实现"与"实测"段落）或 ADR。

- **Univer 用 1.0.1**：1.0.0 的部分包没有来源证明，过不了 `trustPolicy: no-downgrade`；1.0.1 的产物与 1.0.0 相同。冷却期内临时豁免，期满之后、合并之前已经去掉。
- **新建的重放同样 201**：Nest 按方法给出默认状态码，拦截器改不了；与 Idempotency-Key 草案一致。
- **不是 gzip 的正文是 400**（`REQUEST_INVALID`），只接受单个完整的 gzip 成员；带 `Content-Encoding` 的上传 415。
- **新错误码 `PERMISSION_DENIED`**（403）：访问策略的"查看者"不能保存（M1 只有所有者，由单元测试覆盖）。
- **核对快照 `id` 放在事务里判断权限之后**：否则别人的文档与不存在的文档结果不同。
- **访问策略接受事务**：权限查询走事务的连接，不在事务里再从连接池取连接。
- **"自己追自己"按全部结果未知的保存识别**，不只最近一次。
- **模板在 S1 直接用 S2 探针的收敛结果**，S4 的更新脚本重新生成，逐字节相同。
- **共用部分移进 `shared/`**：登录页的地址、确认会话的请求、整页跳转；登录后要回到编辑器页时整页打开。
- **contracts 声明 `"sideEffects": false`**：编辑器专用的结构不进平台页面的包。
- **上传的快照在内存的字节上压缩**（E2E 在 WebKit 上发现：读取 Blob 要经它的网络进程，离线时失败）。
- **不开启 `strictExecutionOrder`**：两个入口共用的块里关掉 JIT 在前；E2E 没有违规。
- 审查之后的修改（详见审查报告）：
  - **gzip 用 `DecompressionStream` 解压**：Node 的 zlib 会解开全部成员，"空成员加合法的成员"服务端判为合法、浏览器解出空串；
  - **保存先判断权限再加锁**：无权的请求不取锁，也不能按等锁的时间区分别人的与不存在的文档；
  - **编辑器页的会话**：载入之后一律不整页跳转；登录过期或在别处退出时暂停保存、提示在新标签页中登录，本人回来之后恢复；别的标签页换了人时不能保存，原来的人回来之后恢复（原设计是"换了人或退出了就停止保存、提示刷新"，刷新会丢掉修改）。保存得到未登录或令牌失效时先向服务端确认会话，确认期间页头说明正在确认、失败的说明等确认有了结果再显示；确认失败时说明原因，再按保存先确认；令牌已知失效时，确认成功之前不再发保存；
  - **键入网址时 SDK 自动识别为链接**：不是入口，M1 保留，登记 DEF-021；
  - **产物扫描**：按浏览器的解析规则识别地址（HTML 用 parse5 截取分词器给出的每个开始标签，SVG 按 XML 解析，样式按 CSS 的分词规则，JSON 按顺序取出每个字符串字面量），比较、去重与核对允许清单都用解析出的规范写法；门禁无法确定浏览器会怎样解析的标记写法直接报违规（`artifacts/markup`）；前缀放行只对编辑器页的产物；入口引用了没有预算的 Worker、一个预算匹配到多个同名的 Worker、产物里有没有归属的脚本时报违规；
  - **lint**：包名一律小写；不用 `import.meta.glob`；`@univerjs/*` 的包名不带查询串与片段；三斜杠引用与 `import x = require()` 一律报错；
  - **新依赖**：仓库工具加 parse5、saxes（与 jsdom 用的同一个版本），后端的开发依赖加 yaml（核对 SDK 版本的测试按 YAML 解析目录）。

## 下一个 Phase 须知

- **P5（部署）**：
  - 反向代理不得对 `/api/documents/*/content` 的响应再压缩或解压（正文已经是 gzip，`Content-Encoding: gzip`）；万一改动了编码、把 ETag 标成弱校验器，客户端也认得（`W/"<修订号>"`）；上传的 `application/gzip` 正文不做处理，请求体上限不小于 5 MiB 加上查询串；
  - 托管：`editor.html` 与 `index.html` 都要在 `NERVE_WEB_ROOT` 里，缺一个启动失败；
  - 模板随 SDK：升级 Univer 或调整档案之后执行 `pnpm --filter @nerve-office/e2e run update:sheet-template`，再跑编辑器的 E2E。
- **M2**：访问策略在 `DocumentAccessPolicy` 后面扩展；查看者保存得到 `PERMISSION_DENIED`，编辑器页按 `permissions.canEdit` 只读；`requestId` 的重放按"同一个人"判断。
- **M3**：完整的快照校验与内容哈希、`If-None-Match`（DEF-017）、拦截旧客户端（`sdk_version` 目前写平台内置的版本）、租约与阅读模式、自动保存与捕获时机（DEF-020）；链接地址的规范写法要覆盖键入网址的自动识别（DEF-021）。
- **M7**：独立安全审查时评估产物扫描是否解开 JS 字符串里嵌的样式与 HTML、`data:` 地址里的文档（DEF-022）。
- **已知的坑**：
  - Univer 的单元格画在画布上：E2E 按默认行高列宽点击画布，按接口取回的快照核对内容（`tests/e2e/support/sheet.ts`）；
  - 查找替换要到 steady（渲染完成后约 3 秒）才注册；
  - 数据验证拒绝输入时，提交编辑也算成功（SDK 先写入再回滚），保存的是回滚之后的内容；
  - 在 WebKit 上不要用 Blob 作为上传的正文；
  - 块注释里不要写"斜杠加星号"（例如 `@univerjs/` 后面跟星号）：lint 的自动修正（`style/indent`）会把它当作注释的开头，截掉前面的文字；
  - 表格的界面：筛选按钮没有可访问的名称（E2E 按 `data-u-command` 定位）；选中区域时查找只在区域里进行；"替换全部"要先点"查找"才可用，还有一个确认对话框；工作表标签的右键菜单一直在页面里（按钮可见），右键点过单元格之后单元格菜单的"删除"也在，按名称找"删除"时注意范围；
  - E2E 的"计算进行中再改一处"依赖较重的公式：第二处修改要落在第一轮计算里（SDK 触发计算有 10 ms 的去抖，两处挨得太近会并成一轮），按保存之后等的又要在公式收齐的 3 秒上限之内。CI 的 WebKit 比本机慢几倍：现在第一轮重（300 个公式依赖 D1）、第二轮轻（一个公式依赖 D2）；改动公式时先在 CI 上实测；
  - E2E 里拖住某个请求：`page.route` 的处理函数里等一个手动放行的 Promise，先用 `expect.poll` 确认请求已经被拦住，再做下一步（`session.spec.ts`）；
  - 门禁截取 HTML 的开始标签用的是 parse5 标着 `@internal` 的 `Parser`：升级 parse5 时先跑 `tools/src/gates/html-values.test.ts`，它锁住截取与"开始标签被丢掉"的检测。parse5 仍按旧的规则解析 `<select>`，等它跟上浏览器，这部分检测可以收窄；
  - 门禁报 `artifacts/markup`：HTML 或 SVG 里有门禁无法按浏览器的规则确定会请求什么的写法（被丢掉的原始文本元素、SVG 的 DOCTYPE 与处理指令、格式错误的 SVG），改写法，不要放宽规则；
  - 压缩器把普通字符串也写成模板字符串：产物扫描对两者用同一个规则，门禁的用例两种都要测；
  - parse5 在 HTML 里每层都查一遍打开的元素，几万层的 `<div>` 嵌套是平方级的：测深层嵌套用 SVG 的 `<g>`。
