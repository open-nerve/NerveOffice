## 合并后的 CI

- 第一次运行（run 36235085323）失败，只有 lint 自测的第一个用例超过 Vitest 默认的 5 秒。原因：类型感知的 lint 第一次运行要加载整份配置，并为每个 tsconfig 工程建立类型程序，这部分冷启动算进了第一个用例（本机 2.7 秒，CI 的 4 核机器上还要和并行的测试抢 CPU）。修复（分支 `m1-p1-fix-ci-timeout`）：冷启动移到 `beforeAll`，对本组用到的每个工程各检查一个真实文件做预热，给出单独的时限；整份文件的用例统一时限（原来只有最后一组写了）。预热后本机每个用例都在 0.1 秒以内。
- 同一分支让 CI 的结果不登录也能看到：完整日志与报告要登录才能下载，排查这次失败时只能读公开的注解。`pnpm verify` 在 GitHub Actions 里把失败的步骤与全部步骤的汇总写成注解，Playwright 在 CI 上加 `github` 报告器。
- 修复推送后的第二次运行（run 36235749514）全部通过，四个浏览器（含 Edge）的框架冒烟都通过。

## 下一个 Phase 须知

**P2 开头先验证 NestJS 12（纯 ESM）的工具链**，不通过就退回 11.2 并修订 ADR-002（M1 总设计 §7）：
- 构建：`nest build`（NestJS 12 的 CLI 依赖 TypeScript 6.0）或 tsc；相对导入写 `.ts`、由 `rewriteRelativeImportExtensions` 改写，这一点是否被 CLI 与 SWC 支持（审查的建议项，未证实）；
- 监听模式；
- Vitest 与装饰器元数据：Vite 8 用 Oxc 转译，确认能否输出 `emitDecoratorMetadata`，不能就按 NestJS 官方的做法接入 SWC，或者全部使用显式的注入标记；
- 集成测试与优雅退出。

**api 消费 contracts**：Vitest、ESLint 与类型检查经 `@nerve-office/source` 读源码；Node 运行时读 `dist/`，所以 api 的构建与启动要先构建 contracts（`pnpm build` 已按拓扑顺序执行）。工作区的包经符号链接解析到仓库目录，不在 `node_modules` 里，P2 可以顺带确认 Node 能否直接对它做类型剥离。

**模块边界**：在 `eslint.config.ts` 里为 api 声明元素与策略（模块只经 `index.ts` 对外、只有仓储访问数据库、一个模块的仓储只被这个模块使用），并在 lint 自测里加违规样例。

**集成测试**：P2 设计每个测试文件独立的数据库（例如从已迁移的模板库复制）；连通检查已在 `beforeAll` 里。

**给 P3 的备注**：产物扫描判断不了运行时拼出来的代码与地址，由 CSP 兜底（P1 设计 §3.3）。前提是 P3 让 CSP 同时随 HTML 与 Worker 脚本的响应下发（US-M1-09），策略里不出现 `'unsafe-eval'`、`script-src` 的 `'unsafe-inline'`，也不允许 blob: Worker。

**给引入原生模块的 Phase 的备注**：平台专属的可选依赖（例如 `@node-rs/argon2`、sharp 的各平台二进制）在本机只装了本平台的那一份，许可检查跳过本机没装的，以 CI（Linux x64）为准。

**给 P5 的备注**："以 CI 为准"的前提是 CI 与生产镜像是同一个平台。镜像只构建 linux/amd64；如果以后要构建多架构镜像，在镜像构建里再执行一次 licenses 门禁，否则 arm64 的平台专属包不会被检查。

**已知的坑**：
- pnpm 的 `shellEmulator` 不展开未加引号的通配符：脚本里的目录过滤要写成 `'./apps/*'`。
- 提交钩子装在共用的 `.git/hooks` 里，脚本里写的是安装它的那个 worktree 的路径。合并后在主目录执行一次 `pnpm install`（`prepare` 会重装钩子），再删除 worktree。
- lint-staged 在一次提交中偶发 0.1 秒内失败、重试即通过，原因未查明；再出现时查看它的备份暂存（它会用 `git stash`）。
- 本机跑 WebKit 与 Chrome 需要登录的桌面会话；长时间运行前起 `caffeinate`。
- E2E 不复用已在运行的预览服务，端口 4173 被占用时直接失败。
