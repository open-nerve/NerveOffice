## 与设计的偏差

都已回写到 P5 设计、M1 总设计的变更记录或 ADR。

- **E2E 的管理员由外部模式的全局准备初始化**（`support/external-setup.ts`），不在编排脚本里：账户只在 E2E 包里定义一次；已经有了就不再执行，同一套环境可以反复跑。
- **浏览器项目可以用 `E2E_BROWSERS` 选**：重启项目依赖"全部浏览器项目"，容器 E2E 在 CI 上只跑 Chromium，靠它把依赖收窄到 Chromium。
- **代理未被信任的告警只看带转发头的请求**：容器的健康检查直接访问应用，本来就是 HTTP。
- **启动自检放在 audit 模块**：只追加的保护是它的；最多等 2 秒，超过时照常启动，有了结果再记。
- **镜像五个阶段**：多了 `manifests`；pnpm 全局安装要执行它自己的安装脚本（S1 实测，原生二进制要放到位）。
- **容器 E2E 的镜像标签与临时目录带进程号**；跑 E2E 期间每 2 秒取样应用容器的内存（重启用例会重启应用，跑完之后的数字不作为指标）。
- **编排脚本直接用 Node 起 Playwright**（不经 pnpm：它不转信号），放进单独的进程组：收到信号时先给它 SIGINT（Playwright 只把 SIGINT 当作正常停止），再收到时给整个进程组 SIGKILL，整个进程组退出之后才清理；编排脚本被强制结束时，Playwright 的全局准备按 `E2E_RUNNER_PID` 发现它不在了，自己停下（复验 RB1、SB1、SB2）。M1 对抗评审之后（Codex 评审 CX12、CX13），docker 的长命令（构建、`compose up`、`compose run`）同样异步执行、各在自己的进程组里，第一次的 SIGINT 发给整个进程组（docker 的命令行在输出是终端时不把信号转给 buildx、compose 插件）；清理的每一步都执行，有一步失败就以非零退出；部署配置的核对另量随镜像分发的许可文件。
- **Caddy 以 nobody 运行**（审查 A7），证书放在 tmpfs 里；只把 443 发布到本机回环。
- **`@test-build` 只有 2 条**（CSP 的阳性对照与对照）：安全头的用例改用生产构建里的公式 Worker，两种运行方式都执行（审查 B2）。
- **上游报告的安全类草稿不进公开仓库**（UR-013、UR-014）：放在 `.gitignore` 排除的 `docs/upstream/private/`，合并后移到主目录的同一位置；另外，M0-P5 的验证报告（已公开）里有这两条的利用写法，要不要改写由需求方决定（M1 收尾汇报）。
- **00 号计划书 r6**：补记 M1-P4 起 Univer 基线为 1.0.1。

## 下一个 Phase 须知

- **部署**（ADR-012，`deploy/README.md`）：
  - 新的表、序列由迁移以所有者建，默认权限自动授权给应用角色；**新的对象类型**（视图、函数、schema 以外的东西）应用要用时，先确认默认权限覆盖到，并在初始化脚本与部署说明里补上；
  - 应用启动时的自检：超级用户或审计表的所有者会告警，本机开发与测试照常出现这条告警；
  - 新的 `NERVE_*` 配置要进 `.env.example`（需要时）与部署说明；未知的 `NERVE_*` 变量会让应用拒绝启动；
  - 镜像引用一律按摘要锁定（`pins` 门禁）；compose 里整个引用是变量的（`${NERVE_IMAGE}`）才不算。
- **E2E**：
  - 新用例默认两种运行方式都要能执行；只在测试构建里成立的，打 `@test-build` 标签（外部模式按标签排除，不是跳过）；
  - 强制结束后端的用例放进重启项目（`specs/deploy/`），只跑它：`pnpm --filter @nerve-office/e2e run test --project restart --no-deps`；命令行的 `--grep` 不作用于依赖的浏览器项目；
  - 容器 E2E：`pnpm test:e2e:container`（需要 Docker；默认只跑 Chromium，`--browsers` 可多选，`--` 之后的参数交给 Playwright）。
- **上游报告**：21 条草稿在 `docs/upstream/`，提交前要需求方确认（跟踪表列了要确认的事）；提交之后把链接写回跟踪表，上游修复发布之后评估升级与去掉平台的规避。
- **已知的坑**：
  - `docker compose wait` 只认运行中的容器：容器已经停下时报错；等停下用 `docker compose ps --status running` 为空；
  - `docker compose start` 会先把依赖的一次性服务（`migrate`）再跑一遍：只重启应用用 `up -d --no-deps --wait app`；
  - `docker compose port app 3000` 在没有发布时输出 `:0`；
  - containerd 的镜像存储里 `docker image inspect` 的 `Size` 是压缩之后的，解压之后的体积看 `docker image ls`；
  - 官方 caddy 镜像的可执行文件带 `cap_net_bind_service` 文件 capability：去掉全部 capabilities 时连执行都会被拒绝，要留着 `NET_BIND_SERVICE`；
  - `pg_isready` 对不存在的库与角色也返回成功；官方 PostgreSQL 镜像第一次初始化失败之后，再启动不会重新执行初始化脚本；
  - 应用的路由不区分末尾斜杠与大小写：代理上屏蔽某个接口要按前缀、不区分大小写；
  - Playwright 的 `--project` 会吞掉后面的参数：只跑某个文件时写成 `test <文件> --project=chromium`；
  - zsh 里 `echo ======` 这类以等号开头的参数会被当作路径展开而报错。
