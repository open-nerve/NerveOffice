# M6-P1 文字文档底座：架构设计与实施规划

> 状态：进行中｜日期：2026-11-18｜基于代码版本：`b3302447`（main，M6 总设计审批合入之后）｜分支：`m6-p1-doc-foundation`（worktree `.claude/worktrees/m6-p1-doc-foundation`）

## 1. 目标与范围

对应 M6 总设计 §5 的 P1 一行：契约、数据与服务端规则就绪；编辑会话层与类型解耦，表格的行为不变。

- **契约与数据**：`doc` 类型、`doc@1` 档案、文字文档的默认标题；documents 与检查点表三条 CHECK 约束的迁移；响应里的类型字段对没见过的取值宽容（总设计 §2.2 第 5 条）。
- **服务端规则**：资源规则模型的扩展；doc@1 的结构、链接、图片位置规则；按档案的规范化；错误位置加上文字文档的形状（总设计 §6.1、§6.2）。
- **DEF-055**：按页面上报的档案检查，在事务里交叉核对（总设计 §2.2 第 8 条）。
- **共用编辑会话层**：从 `features/sheet-editor` 抽出与类型无关的编辑会话与页面编排，表格迁到编辑器接口，表格的行为与既有测试不变（总设计 §6.3）。
- **main 定时 CI #106 的 WebKit 自检前提**：按 M5-P9 调查的方案 A 只改测试（总设计 §2.1 第 11 条）。
- **用户故事**：US-M6-13 的服务端部分（拒收不合 doc@1 规则的快照、指出原因）。其余故事在后面的 Phase。
- **不在 P1**：
  - 新建文字文档：新建模板要经编辑器页生成（总设计 §6.2），P2 编辑器就绪时一起放开。P1 的新建接口仍只收表格。
  - 文字文档的编辑器、加载时规范、页面上的图标与“请刷新”提示：分别在 P2、P5。

## 2. 现状（`b3302447`）

两个只读调研（同模型子 Agent）抽查属实，要点如下。路径缩写：C = `packages/contracts/src/documents`，A = `apps/api/src/modules/documents`，W = `apps/web/src`，FS = `W/features/sheet-editor`，ED = `W/editor`。

### 2.1 契约与服务端

- **常量**：C/documents.ts 的 `DOCUMENT_TYPES = ['sheet']`、`DOCUMENT_PROFILES = ['sheet@1']`、`DOCUMENT_PROFILE_OF`、`DEFAULT_DOCUMENT_TITLES`。加取值后，类型检查会强制四张穷举表补项：
  - C/profile-resources.ts 的 `PROFILE_RESOURCES`；
  - A/snapshot-checks.ts 的档案规则表；
  - A/document-creation.service.ts 的模板表；
  - W/shared/i18n/zh-cn/messages.ts 的类型名称。
- **写入接口是严格的**：新建请求 C/document-requests.ts；上报的档案由 A/client-format-gate.ts 核对；数据库 CHECK 约束。
- **读取响应现在也是严格的**：文档摘要（详情、新建与副本、搜索、分享都继承它）、历史、草稿事实、管理端的类型字段都是严格枚举。前端解析不合契约时，`readJson` 抛出 ResponseFormatError，整个响应作废（W/shared/api/client.ts）。已有宽容写法的先例：C/snapshot-rules.ts 的 `snapshotInvalidDetailsSchema`。
- **数据库**：三条约束在 apps/api/src/db/schema/documents/index.ts（`documents_type_check`、`documents_profile_check`、`document_checkpoints_type_check`），最新迁移 0039，下一个是 0040。
- **快照检查**：子进程池按“结构 → 资源 → 图片 → 链接 → 哈希”检查。
  - 检查用的档案写死为表格：A/upload-inspection.ts 的 `INSPECTED_PROFILE`；“不缩水”也用它（A/document-content.service.ts）。
  - 档案规则表只有“结构、链接”两项，没有交叉核对的位置。
  - 图片位置与链接只认表格的路径（sheets、cellData、`SHEET_DRAWING_PLUGIN`）。`checkCellLinks` 读 `p.body.customRanges`，可以直接用于文字文档的正文。
- **资源规则模型**：C/profile-resources.ts 的 `ResourceRule` 只有 `entries`（顶层每个键下的值都是数组或都是对象）与 `mustBeEmpty`，结构检查要求顶层是对象。页面的打开自检用同一套。
- **规范化**：C/content-canonical.ts 只去掉工作表上的视图状态，ADR-011 写明文字文档留给 M6。“客户端能逐字节复现”由固定的 SHA-256 向量与测试工具里的第二份实现对照保证。
- **写入路径的档案校验（DEF-055）**：
  - 申请编辑权、心跳、请求编辑与保存，都只核对“上报的是现有档案之一”。
  - 保存在事务里先回 DOCUMENT_TOO_NEW，再核对 unitId，两者之间没有核对上报的档案。
  - 另存为副本按审查 A7 不判断“文档太新”，信封记页面上报的档案。
- **新建**：模板 C/sheet-template.ts 由工具经编辑器页生成；默认标题计入新建的幂等摘要。

## 3. 设计

### 3.1 模块划分与依赖方向

- **contracts**：documents（常量、可新建的类型、宽容的响应解析）、snapshot-rules（规则与位置）、profile-resources（资源规则模型）、content-canonical（按档案规范化）。前后端共用，不依赖 Univer。
- **api**：documents 模块里的档案规则表（加 doc@1）、图片位置与链接检查（按档案取路径）、上传检查（DEF-055）、保存与另存为副本的核对。
- **web**：
  - `W/features/document-editor/`（新目录，本设计定名）：与类型无关的编辑会话与页面编排，含租约与交接、本机锁、编辑模式、保存协调、自动保存、捕获、本机发件箱、恢复、冲突副本、阅读模式、离开提示，以及页头的通用部分。
  - `W/features/sheet-editor/`：表格的扩展，含 CSV、公式恢复与“公式待更新”、强制重算、表格的页头部分、表格编辑器的装配。
  - P2 的文字文档放在 `W/features/doc-editor/`。
  - **依赖方向**：sheet-editor → document-editor。document-editor 不得引用 sheet-editor，也不得引用 ED 里表格专有的模块，用 eslint 规则约束。

### 3.2 接口契约

- **常量**：
  - `DOCUMENT_TYPES = ['sheet', 'doc']`、`DOCUMENT_PROFILES = ['sheet@1', 'doc@1']`、`DOCUMENT_PROFILE_OF.doc = 'doc@1'`；
  - `DEFAULT_DOCUMENT_TITLES.doc = '未命名文字文档'`。
- **可新建的类型**：新增 `CREATABLE_DOCUMENT_TYPES`，P1 只有 `sheet`。新建请求按它校验，模板表的键也按它，P2 加上 `doc`。
- **响应宽容**：
  - 页面解析列表、详情、搜索、与我共享、历史、草稿事实、管理端的响应时，类型字段没见过的取值解析为 `'unknown'`，不让整个响应作废。
  - 只宽容没见过的非空字符串。缺少、空串与非字符串仍是格式错误，不猜测，沿用 M4-P4 草稿事实“缺失不能猜测为默认事实”的原则。
  - 契约推断出的类型因此包含 `'unknown'`，页面上按类型分支的地方都要处理它，类型检查会强制。服务端由数据库的行产出类型，受 CHECK 约束，不会产出 `'unknown'`，也不按它分支，所以不另立一套产出类型。
  - 写入接口（新建）仍按已知的取值严格校验。
  - 页面对 `'unknown'` 只做最小处理：类型名称显示“未知类型”，历史预览、编辑器页不尝试打开。“请刷新”的提示在 P5。
- **规则与位置**（C/snapshot-rules.ts）：
  - 加上文字文档的规则标识（结构、版式、页眉页脚、分节符、目录区间、资源与正文不一致等）与位置形状（段落、文字文档的图片）。确切的标识在 S3 的 spec 里定。
  - 响应解析照旧宽容：旧页面遇到新规则按“格式不正确”说，遇到新的位置形状就忽略位置。
  - 服务端与页面的说法按文档类型给出，不再写死“表格”。
- **资源规则模型**：`ResourceRule` 改为按资源声明的判别联合，在 S3 的 spec 里定：
  - **现有形状**：顶层每个键同一种类，可以要求必须为空。sheet@1 的十项逐项等价迁移，结果不变。
  - **结构校验器**：纯函数，可以带“与正文一致”的交叉核对，例如 `DOC_DRAWING_PLUGIN` 的 `{data, order}`、`DOC_HYPER_LINK_PLUGIN` 的 `{links}`。
  - **必须为空**：只按“深层为空”判断，不要求顶层是对象。M0 的文字文档样本里，`DOC_OBJECT_PERMISSION_PLUGIN` 的 data 是 `[]`，按现有规则会被判为 resource-data，SDK 存下的每一份文字文档都会被拒。
- **规范化**：`canonicalize(content, profile)`。
  - sheet@1 的输出逐字节不变，现有向量照旧通过。
  - doc@1 去掉 `settings.zoomRatio` 这类视图状态，另加文字文档的哈希向量与第二份实现的对照。

### 3.3 数据模型与迁移

- **迁移 0040**：按契约常量重建 `documents_type_check`、`documents_profile_check`、`document_checkpoints_type_check`，加上 `doc` 与 `doc@1`。
  - 用 `pnpm db:generate --name` 生成，人工审阅，照 0023 加中文头注。
  - 只做加法；合并后不再改。
- 检查点表的 profile 是自由文本，不涉及。

### 3.4 关键流程

**保存**：顺序沿用计划书 §7.4。
1. 重放预检。
2. 页面上报的数据格式：档案是现有的之一，否则 CLIENT_OUTDATED。
3. 快照检查：按上报的档案选规则，不读文档，“看不到”与“不存在”得到同样的回答。
4. 事务：访问判断；文档的档案比服务端新时回 DOCUMENT_TOO_NEW；**新增：上报的档案与文档的档案不同时回 CLIENT_OUTDATED**；核对 unitId；不缩水按文档的档案。

新增的核对排在访问判断与 DOCUMENT_TOO_NEW 之后，不泄露文档的类型；回答与“客户端太旧”同类（总设计 §2.2 第 8 条），页面刷新之后会按类型载入正确的编辑器。

**另存为副本**：
- 上报的档案必须等于这类文档在服务端的档案（`DOCUMENT_PROFILE_OF[文档类型]`），不比文档行里存的档案。这样仍保住审查 A7：回滚之后文档比服务端新，失去编辑权的人照样能存副本。
- 信封记服务端的档案。表格的取值与原来相同，行为不变。

**上传检查**：按上报、且已通过格式核对的档案选择检查规则（DEF-055 第 4 处）。

**不扩到的地方**：申请编辑权、心跳与请求编辑，仍只核对“是现有档案之一”。这三处不写入内容，错配的页面在保存时被拦下。DEF-055 也没有列这几处。

**编辑器页按类型装配**：
- 页面取到文档详情后，按类型取编辑器的装配。没有装配的类型（P1 的 `doc`，以及 `'unknown'`）进入“格式不支持”的现有状态，不创建编辑器。
- 页面上报的档案改由装配处按类型注入。表格的取值逐字节不变，包括协议、发件箱附加认证数据与草稿目录的可读判定。

### 3.5 共用编辑会话层

- **编辑器接口**：取现有窄接口的并集，作为 SheetEditor 的结构子集。P1 保留现有的方法名，例如 `settleFormulas`、`formulasSettled`、`commitCellEditing`，因为改名会牵动上万行测试里的假件。文字文档的适配在 P2 实现这些方法：没有派生内容，恒为已收齐。改名留到 P2 有了两个实现之后，由 ADR-027 决定。
- **表格的扩展点**：CSV、公式恢复与上报、“公式待更新”与进入编辑时的重算、位置描述（工作表名）、页头的表格部分。由表格的装配挂接，会话层只看到扩展点的接口。
- **不变量**：
  - 旧编辑器真正销毁之后才新建；换编辑器是单飞的（主线程模式先停正在算的公式）。
  - 保存协议与发件箱里的字段不改名、不改取值。
  - `#sheet-editor` 与 `data-editor-*` 选择器不改名。改名会牵动 30 个文件，留给 P2 按需要另定。
- **迁移顺序**：一次迁一个职责，每一步不改表格行为、跑全量单元与相关 E2E。
  1. 按类型装配，加接口类型（与契约改动同在 S2）。
  2. 搬迁没有表格引用的模块，按租约与交接、本机锁、草稿与发件箱、恢复、页头小件分批，同步改按路径写的规则。
  3. 保存层的公式钩子改为扩展点；editor-slot 泛型化，公式回退挂到表格装配上。
  4. 拆 edit-mode：csvTarget → 工作表名 → “公式待更新”与重算 → 公式恢复与上报。
  5. editor-page：CSV 与 formulaBusy 移入扩展，页面上报的档案按类型注入。
  6. editor-chrome 改成插槽；start 与 mount 按类型装配；selftest-hook 最后动。
- **风险最高的两处**：
  - 第 4 步的公式恢复：嵌在通知的顺序里，门控着交接、请求编辑与 CSV，对应约 8,400 行测试，而且对计时敏感。
  - 第 5 步的档案注入：出错就是 CLIENT_OUTDATED，或者本机草稿读不回。
  - 这两步先写 spec。迁移中发现必须改变表格的行为，按跨模块的协同调整停下请示。

### 3.6 #106 的自检前提（方案 A）

  - 改完立即 `forceRound`，并当场核对“上限到点时还在算”，不成立就写明原因失败。

### 3.7 错误处理、安全与可观测性

- 新规则只回规则标识与有限的位置，不回显快照内容（M3-P3 §3.12）。
- 交叉核对的拒绝，日志记文档 id、上报的档案与文档的档案。
- 宽容解析把未知取值映射成 `'unknown'` 时，不记录原值，避免把服务端的新取值当成异常刷屏。
