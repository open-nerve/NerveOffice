## 与设计的偏差

- **S8 分三步**：P1 设计里 S8 是一个 Step。S8 spec 按风险拆成 S8a、S8b、S8c 三步，各自审查、验证、提交；S8c 原拟再分两步，因第一步要临时转出页头，改为一步做完（`a3184bcd`）。
- **页头插槽的写法**：S8c 起初插槽是模块级常量、几个插槽收页面。独立审查 B 查出 P2 把两类文档放进同一张装配表时编译不过，S10 改为插槽不收页面、由装配为每页建一次（S8 spec §3.2 的 S10 修订，ADR-027）。
- **会话层的公开入口**：S6 spec 要求只放生产代码用到的名字。S7、S8 搬迁之后没有跟着删，S10 按引用方重新整理（S6 spec §2 的 S10 修订）。
- **doc-section-break 认表格**：S3 spec 原只看 `tables` 的区间，审查 A 查出能伪造。S10 改为以 `dataStream` 的表格控制符为准（S3 spec 已改）。
- **分支 CI 的时点**：设计写 S5 之后跑一轮原六项、S8 之后跑原六项与托管 Mac。S5 与 S9 之后都推送了本分支，但 Chrome 没有登录 GitHub，手动触发不了原六项。两轮合并为 S10 的最终一轮：原六项与托管 Mac 都在最终的代码提交上跑，门槛不变。
- **picomatch 例外**：不在原设计里。main CI #109 的 audit 因外部通告失败，P1 加了一条有到期日的例外；通告 11-18 就撤回了，原六项 CI #110 的 audit 报例外用不上，S10 删除（`36394cbd`）。#109 与 #110 都不重跑。
- **S9 的位置**：设计允许 S9 插在任何 Step 之间，实际在 S6 与 S7 之间。
- **PostgreSQL 基线由 18.6 升到 18.7**：不在原设计里。托管 Mac #9 因托管镜像的 Homebrew 已是 18.7 停在起数据库一步，需求方 11-22 批准升级。开发库、测试环境、CI 的服务容器与 Linux 浏览器运行器按摘要钉住 `postgres:18.7-alpine`，托管 Mac 的 `POSTGRES_VERSION` 改为 18.7，“版本不同就失败”的核对不变（ADR-002 的附录、ADR-005）。本机开发库重建为 18.7，数据卷保留。以后出补丁版本照此升级。

## 下一个 Phase 须知

**P2 第一步：测试加固**（需求方 11-23 的决定）
- DEF-091、DEF-092、DEF-093 三项只改测试或测试夹具：断言、阈值与单例时限都不变。每项先在本机构造出失败（负载、浏览器离线模拟、导航不回应），看改前失败、改后通过，再做独立审查。
- main 定时 CI #112 的 WebKit flaky（`crash/write-atomicity.spec.ts:212`）的只读分析结果与方案，如果需求方审过并排进 P2，一并在这一步做。

**文字文档接入会话层（P2）**
- 文字文档编辑器提供：
  - 装配：档案 doc@1、页面扩展与编辑模式的扩展；
  - 页头的插槽：照表格的 `sheetChromeOf`，装配建好页面扩展之后按扩展对象建一次，插槽不收页面；
  - 自己的 kit，或者与表格的 kit 合成一份，组合处怎样合并在 P2 定；
  - `OPENABLE_DOCUMENT_TYPES` 加 `doc`。组装处的装配表写成 `satisfies Record<OpenableDocumentType, …>`，少一项编译不过。
- 两类文档的成员放进同一张装配表、同一个页面与 kit 不用 `as`，会话层与表格各有一条类型回归用例核对。页面的 `Extra` 取两类的并集时，视图里只剩共有的键，P2 定页面的 Extra。
- **图片操作的状态**在页头插槽的参数里，对它是逆变的：文字文档的图片状态与表格相同时没有问题；P4 定文字文档的图片时如果不同，要另定写法（ADR-027）。
- 新的类型相关行为经编辑模式的扩展、页面扩展的挂点、页头的插槽或 kit 加进来，不在会话层里按类型分支。确实需要新挂点时，挂点放在原来调用的位置，先后写进 spec。
- 会话层的新模块不能引用表格编辑器与编辑器适配层，需要编辑器能力就在会话层定义窄接口。公开入口只放生产代码用到的名字，逐个加；只有测试用到的放测试入口。
- 公开入口转出什么没有自动守卫，只靠约定与审查（复验的提醒）。P2 有了第二个使用方之后，考虑写成 tools 的用例：按引用方核对公开入口的每个名字都有生产代码在用、测试入口的都有测试在用，生产代码不引用测试入口。S10 核对用的脚本只在会话的临时目录，做法见实施记录 S10 一节。
- 以下几处 P1 没改，P2 定：
  - 编辑器接口的方法名（`settleFormulas` 等），有了两个实现之后在 ADR-027 补一节；文字文档先按原名实现：派生内容恒为已收齐，没有未提交的输入；
  - 骨架里写死“表格”“单元格”的 9 条文案，其中载入中、格式不受支持、载入失败三条出现时还不知道类型；
  - `#sheet-editor` 与 `data-editor-*` 选择器，改名会牵动约 30 个文件；
  - 通用页面按编辑模式视图的五个通用键拆出扩展的部分：视图以后加了通用的键而这里没跟着改，那一项会混进扩展的部分，类型检查查不出（S8b 已登记的 Minor）。

**doc@1 的定稿**（总设计 §2.2 第 9 条：P2 合入 main 之前定稿插件清单与影响数据的配置）
- 需要时随定稿调整资源规则与 doc@1 的快照规则。
- **DEF-089**（P2 合入 main 之前完成）：`doc-section-break` 按 SDK 结构校验器（core 的 `structure-validator.ts`）的口径扫控制符，表格、行、单元格成对，再数单元格之外的分节符，包括 `dataStream` 里没有记录的 `\n`；登记表里的三类反例（不成对的两端、自造的一对控制符、没有记录的分节符）各写成拒收的用例，用 M0 的 30 份样本复核不误拒。
- **DEF-090**：`noteSettings` 里的分隔符等几段是正文，可以带链接区间，规则不看。定稿时用一份带此字段的快照打开，核实会不会显示、能不能点开；会的话要求它们深层为空或跑同一条链接检查（M0 样本里这一项都是 `{}`，不会误拒）。
