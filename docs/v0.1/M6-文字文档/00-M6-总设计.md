> 文档编号：00｜所属版本：v0.1｜状态：草稿（待需求方审批）｜日期：2026-11-16

M5 已完整收官：`v0.1-m5` 打在 main `8cbe1ab5`，main 同 SHA 原六项 CI（run `43722214552`）全部成功。2026-11-16，需求方批准开始 M6 总设计的讨论。同时进行的 Codex 合并后评审（P7、P8）确认的问题，已由 M5-P9 修复：2026-11-17 合入 main `717ac3ca`，main 同 SHA 原六项 CI（run `43944527139`）全部成功。本稿记下启动讨论中的各项决定（§2.1）和本设计的细化（§2.2）。DEF-013 的真实输入法核对已于 2026-11-17 完成，结果与据此定下的处理见 §2.3。

## 1. 目标与范围

- **目标**：文字文档达到计划书 §4.3 的范围。团队成员能新建、编辑、阅读文字文档，中文输入与粘贴可靠，内容保存重开一致。编辑权、保存、本机草稿、历史版本、复制和权限这些平台机制，在文字文档上与表格同样成立。对应计划书 §13.2 的 M6 一行，按 r31 调整，见 §6.10。
- **范围内**：
  1. **doc@1 档案**（插件档案 v1 §2）。
     - 插件分四组：
       - core：Docs、RenderEngine、UI、DocsUI，DocsUI 配置 `toc: true`；
       - drawing：Drawing、DrawingUI、DocsDrawing、DocsDrawingUI；
       - hyperlink：DocsHyperLink、DocsHyperLinkUI；
       - find-replace：FindReplace、DocsFindReplace。
     - 不注册公式引擎和目录块。
     - 排版 Worker 是否启用，按 DEF-007 的评估决定，在 doc@1 定稿之前定下来。
  2. **能力**（计划书 §4.3）：
     - 正文与标题样式、字符格式、段落对齐与设置、三种列表；
     - 基础表格（带守卫）；
     - 图片：内联，以及五种浮动环绕；
     - 超链接（规范写法）、`/` 快捷插入（不吞字）、查找替换、大纲侧栏；
     - 附加能力：分割线、符号、表情、格式刷、清除格式、段落把手、“仅保留文本”。
  3. **版式与规范**：
     - 固定使用 MODERN 版式；
     - 加载时规范：改版式、去掉页眉页脚数据和多余分节符；
     - 隐藏 30 个菜单项，守卫 15 个命令；
     - 服务端按 doc@1 的规则拒收不合规的快照（计划书 §11.2）。
  4. **中文输入**：输入法事件归一；捕获时机感知组合输入（已有通用实现，按文字文档复核）；候选框位置按 DEF-013 的结论处理：核对中没有明显偏离，不列已知限制，P3 用更长的拼音复核（§2.3）。
  5. **复制粘贴**：
     - 粘贴清洗：危险内容、单元格里的图片、表格之外的分节符；
     - 链接规范；
     - 会改变含义的转换偏差，在平台侧修正（§2.1 第 8 条）；
     - “仅保留文本”。
  6. **图片资源**：
     - 在线时插入、粘贴、拖放上传；读取失败时显示占位；
     - 资源引用随保存、复制、历史与恢复保留；
     - 单元格里不放图片；向前删除键能删除选中的图片。
  7. **阅读模式与只读**：打开即阅读；进入与退出编辑时重建编辑器；查看者的只读加固（M0 的 8 个入口）。
  8. **共用编辑会话层**：从表格编辑器页抽出与类型无关的编辑会话（§2.1 第 4 条），表格的行为不变。会话层另加不下载图片字节的图片权限复核（DEF-088，§6.3），表格页、历史预览与文字文档一并覆盖。
  9. **平台功能覆盖文字文档**：
     - 新建、列表、搜索、分享、回收站；
     - 复制与另存为副本、历史版本的预览与恢复为副本；
     - 本机草稿页、断网与崩溃恢复、退出与撤权时的本机清理。
  10. **契约与服务端**：
      - `doc` 类型与 doc@1 档案；
      - 结构规则和资源规则；按档案规范化；
      - DEF-055 的交叉核对；
      - 升级兼容：契约对没见过的类型宽容处理。
  11. **真实环境的复核**：
      - DEF-013：macOS 真实输入法，2026-11-17 已完成（§2.3）；
      - DEF-008：真实 Safari，做成自动页面自检；
      - DEF-006：真实来源粘贴，用 WPS 与网页；
      - DEF-007：排版 Worker；
      - DEF-004 的文字文档部分，用能提供的来源。
- **范围外**：
  - Windows 输入法的真机核对（DEF-005，§2.1 第 2 条）；Word（Windows、macOS）、Google Docs、飞书来源的真实粘贴（DEF-087，§2.1 第 7 条）。两项都记账到 M7 上线总验收前裁决。
  - 不提供的功能：正文里插入的目录块（计划书 §4.4）、页面模式、页眉页脚、分节与分栏、形状、线程评论、内嵌公式。
  - Office 文件的导入导出、打印与 PDF（计划书 §4.5）。
  - 离线插入图片：照 M5 的规则，离线时禁用。
  - 多人实时协同：单写者，见计划书 §4.5。
  - 放宽“单元格里不放图片”，这要走范围变更（计划书 §4.3）。
  - 压测、备份恢复演练、独立安全审查，都在 M7。

### 2.2 本设计的细化（随本总设计一起审批）

1. **平台功能全面覆盖文字文档**：
   - 新建、列表、搜索、与我共享、分享、回收站；
   - 复制与另存为副本、历史版本的预览与恢复为副本；
   - 本机草稿页、管理端。

   CSV 只适用于表格。
2. **断网与崩溃恢复**：文字文档走同一条本机发件箱与恢复链路，断网编辑、崩溃恢复、冲突另存为副本、退出与撤权清理都补上核心 E2E。
3. **补装四个包**：`@univerjs/docs-drawing-ui`、`docs-hyper-link`、`docs-hyper-link-ui`、`docs-find-replace`，与其余 `@univerjs/*` 同为 1.0.1。按依赖门禁登记版本、许可、来源与产物里的地址；供应链规则（发布满 3 天、可信度不降）不满足时停下请示。
4. **排版 Worker**（DEF-007）：
   - 默认不启用；
   - 先修 Worker 模式下单元格里 Tab 被吞的问题，再评估是否启用；
   - 评估在 doc@1 定稿之前完成，因为启用就是增加插件，属于档案变更。
5. **升级兼容**：列表、历史、草稿事实、管理端这些响应里的类型字段，对没见过的取值宽容处理，页面提示“请刷新”，不整页出错。写入接口仍然严格。
6. **上游草稿**：照 2026-09-29 的决定暂不提交。M6 的新发现照样只写草稿。
7. **计划书修订**：见 §6.10。
8. **DEF-055 的做法**：
   - 保持快照检查在事务之前、且不读文档的设计，让“看不到”与“不存在”得到同样的回答；
   - 按页面上报的档案选择检查规则；
   - 事务里核对上报的档案与文档的档案是否一致，不一致按格式门槛拒绝，与“文档太新、客户端太旧”同类回答；
   - 另存为副本的信封记服务端的档案。
9. **档案定稿**：
   - doc@1 的插件清单、注册顺序和影响数据的配置，在合入 main 之前定稿，之后不改；要变更就发 doc@2（插件档案 v1 §4）。
   - 保存重开的回归样本随 doc@1 一起建立。
10. **加载时规范与写回**：
    - 加载时以命令执行规范：改为 MODERN，去掉页眉页脚数据和表格之外多余的分节符；
    - 阅读模式下只显示、不保存；进入编辑后，随第一次捕获保存；
    - 规范之后的内容必须能通过服务端规则。正常流程里，这类数据只可能来自缺陷或绕过客户端的请求（插件档案 v1 §2）。
11. **`/` 菜单的目标行为**：
    - 只在表格之外的空段落弹出，只列已启用的能力；
    - 菜单打开后，接着键入的可见字符照常进入正文，或作为菜单的筛选词，一个字也不丢；
    - Esc、点击别处、继续输入都能关闭菜单；
    - 其他位置按 `/` 原样插入，表格单元格里也一样（UR-011）；
    - 一次按键只处理一次：`keydown` 的 keyCode 为 229 或 `isComposing` 为真，表示输入法已经处理了这个键，不再当普通按键处理。Safari 在中文标点状态下先发 `beforeinput`（`insertText`，`/`），随后才有 keyCode 229 的 `keydown`，以 `beforeinput` 为准；Chrome 与英文标点状态只有 keyCode 191 的 `keydown`（DEF-013，§2.3）；
    - 菜单出现在光标旁边。只在空段落弹出时，光标在行首，菜单就在段落左侧；需求方 2026-11-17 看到的“字在行尾、菜单在段落左侧”，是 SDK 在非空段落也弹菜单造成的，目标行为下不再出现；
    - 做法优先在平台侧的捕获阶段接管按键，不得已才打补丁，补丁集中登记（ADR-010）；
    - 三个浏览器和真实 Safari 都通过之后，从计划书 §4.5 删去吞字一条。
12. **粘贴偏差的修正范围**：
    - 平台侧规范 HTML，修正以下偏差：
      - Google Docs 外层 `<b>` 使全文变粗；
      - `<em>` 变成粗体；
      - `<br>`、`<del>`、`<h6>` 丢失；
      - 嵌套列表的父项并进子项；
      - Word 的项目符号字符残留在正文里；
      - 纯文本自动识别出的链接地址是整段文字（UR-015）。
    - 字号、颜色、行距这类细节偏差，列为已知限制。
    - 单元格里粘贴含表格的内容（UR-017）现在会静默失败，改为拆成文字或拒绝并提示，具体做法在 P4 设计里定；不得静默失败。
13. **真实 Safari 自检的内容**：
    - 各入口、撤销重做、保存重开；
    - `/` 键的两条路径、粘贴清洗与“仅保留文本”、阅读模式；
    - 组合输入下的捕获时机（合成事件只能覆盖页面侧的一部分，真实输入法另列人工清单，含更长拼音下候选框的位置，§2.3）。
14. **测试组织**：
    - 文字文档的 E2E 另建目录（例如 `tests/e2e/specs/doc-editor/`）。
    - 页面助手、探针、只读入口清单单独为文字文档建立，不改动表格的那一套。
    - 造数据助手支持 `doc`。
15. **性能**：
    - 样本：约 2 万汉字，含标题、列表、表格和图片（计划书 §12.1、§12.2）；
    - 目标：
      - 1 MiB 文档保存，服务端 p95 ≤ 1 秒；
      - 从捕获到“已保存到云端”，p95 ≤ 3 秒；
      - 从停止修改到“已保存在本机”，p95 ≤ 2 秒；
      - 1 MiB 文档捕获时的主线程阻塞，p95 ≤ 100 ms。
    - 与 M0 的文字文档基线对照：首屏、键入到画出、组合更新。

| 中文标点状态按 `/` | 经过输入法：先 `beforeinput`（`insertText`，`/`），后 `keydown`（key 为 `/`，keyCode 229，`isComposing` 为假）。SDK 默认页：`/` 进了正文。平台策略页：按一次得到 `//`；在空段落里菜单打开，也多出 `/`（需求方观察） | 不经过输入法：只有 `keydown`（keyCode 191）。SDK 默认页：被吞，菜单打开（已知缺陷）。平台策略页：插入一个 `/` |
| 英文标点状态按 `/` | 只有 `keydown`（keyCode 191）。SDK 默认页被吞、菜单打开；平台策略页插入一个 `/` | 同左 |
| 组合中按 Esc | 取消组合，正文不变：先 `compositionend`（文字为空），之后才有 Esc 的 `keydown`（keyCode 229，`isComposing` 为假） | 取消组合，正文不变：Esc 的 `keydown`（keyCode 229，`isComposing` 为真）在 `compositionend` 之前 |
| 组合中按 Shift | 已打的字母 `ceshi` 原样上屏，切到英文 | 同左 |
| 组合中焦点切走（点工具栏） | 组合的文字上屏 | 同左（只在平台策略页做了） |
| 候选框 | 紧挨着正在打的拼音 | 同左 |

另外，本机简体拼音在中文标点状态下按 `/`，输出的也是 `/`，不是清单设想的顿号。

**归类**（P5 交接单“结果不符时的处理”的五种）
1. Safari 与 Chrome 的顺序相同：不是。
2. **Safari 是 WebKit 顺序，平台策略页撤销正确：是。** M0 的结论成立，事件归一必须做。
3. 平台策略页仍错，或出现第三种顺序：输入法事件方面没有。`/` 在 Safari 平台策略页上插两次是另一回事：M0 原型只在 `isComposing` 为假时处理 `keydown`，而 Safari 在输入法处理完之后补发的 `keydown`（keyCode 229）`isComposing` 也是假，于是 `beforeinput` 与 `keydown` 各插了一次。这在平台侧可以解决，不需要停下请示。M0 原型不改，由 P3 的生产实现处理（下面第 3 条）。
4. 英文标点状态下 `/` 不经过 `keydown` 与 `beforeinput`：不是，两个浏览器都有 key 为 `/`、keyCode 191 的 `keydown`。
5. 候选框明显偏离输入位置：不是。

**据此定下的处理**
1. **候选框**：
   - 不写进已知限制：计划书 §4.5 不加这一条，M0 结束评审 SC-4 第 3 条就此了结；§4.3 的那句改成核对结论（§6.10）。
   - M6 不默认改动隐藏输入元素，那要动 SDK 内部的元素。M0 测得的偏移仍在：组合文字变长、隐藏输入元素换行时向下偏 18～54 px；这次最长的拼音是 `zhongwenshuru`。
   - P3 在产品页面上用更长的整句拼音、在行尾换行处复核，列入真实输入法的人工清单（§2.2 第 13 条）。明显偏离时，按 M0 提出的缓解做：隐藏输入元素放到组合开始处，字号随缩放，不换行。
2. **事件归一**（P3）：
   - 按 WebKit 的提交顺序实现，用这次 Safari 的记录回放验证。附录 A 第 6 步的回放并入 P3：这几份记录直接做成生产实现的回放用例。
   - 平台自己补发的事件，用平台自己的登记识别（例如 `WeakSet`），不靠 `isTrusted`。这次 Chrome 两页的 11 个 `compositionend` 全部 `isTrusted` 为假；SDK 默认页上没有页面代码派发这个事件，最可能是浏览器扩展拦下原事件再补发，用户的浏览器同样可能装着这类扩展。
   - 记录脚本的汇总只统计 `isTrusted` 为真的事件，在这种环境里会漏掉 Chrome 的提交。上面 Chrome 的结论，按全部事件与检查点得出。
3. **按键是否已由输入法处理**（P3，§2.2 第 11 条）：`keydown` 的 keyCode 为 229 或 `isComposing` 为真，就不再当普通按键处理。由此，Safari 中文标点状态下的 `/` 以 `beforeinput` 为准、只插一次；组合中按 Esc 只取消组合，不连带关闭 `/` 菜单。两个浏览器都用这次的记录回放。
4. **SDK 版本**：核对用的是 M0 的验证页面，Univer 1.0.0。浏览器的事件顺序与 SDK 版本无关；SDK 默认行为那部分（撤销重做的缺陷、`/` 被吞、菜单的位置），P3 用产品的 1.0.1（含补丁）再确认。
5. **其他文档**：结果另补进 M0 的 P5 报告 §3.4 与能力矩阵；DEF-013 登记为已完成。

## 6. 架构影响

### 6.1 契约与数据模型

- **类型与档案**：
  - `DOCUMENT_TYPES` 加上 `doc`，`DOCUMENT_PROFILES` 加上 `doc@1`；
  - `DOCUMENT_PROFILE_OF.doc = 'doc@1'`，并给出文字文档的默认标题；
  - 迁移更新 `documents.type`、`documents.profile` 和检查点表上的三条 CHECK 约束。数据模型只做加法。
- **宽容的响应**：见 §2.2 第 5 条。涉及文档摘要、历史、草稿事实、管理端，它们现在都用严格枚举。
- **错误位置**：现在只有“工作表、单元格”这种表格形状，要为文字文档加上段落位置，文案按类型给出。

### 6.2 服务端：快照检查

- **doc@1 的结构规则**（计划书 §11.2、插件档案 v1 §2）：
  - 只收 MODERN；不收页眉页脚；
  - 表格之外只允许文末一个分节符（单元格里各有一个分节符，是正常结构）；
  - 不收目录块的区间；
  - 链接必须是规范写法；
  - 图片地址的提取覆盖正文的 `drawings` 和资源；页眉、页脚、脚注这类位置出现即拒。
- **资源规则模型**：现在只能表达“顶层每个键同一种类”，要扩展成按档案声明结构校验器，并加上“与正文一致”的交叉核对：
  - `DOC_DRAWING_PLUGIN` 的 `{data, order}`，对照正文的 `drawings`；
  - `DOC_HYPER_LINK_PLUGIN` 的 `{links: [...]}`，对照正文的 `customRanges`；
  - 其余文字文档资源必须为空。
- **按档案的规范化**：
  - 规范化增加档案参数，文字文档的视图状态（如 `settings.zoomRatio`）在规范化时去掉（ADR-011 写明“留给 M6”）；
  - “客户端能逐字节复现”的要求不变，配跨端一致的用例。
- **DEF-055**：见 §2.2 第 8 条。
- **新建模板**：照表格的做法，由工具经编辑器页“打开→保存”生成，在 P2 编辑器就绪之后建立。

### 6.3 共用编辑会话层

- **现状**：`features/sheet-editor` 顶层的非测试源文件约 1.5 万行，把两类东西写在一起：
  - 与类型无关的编辑会话：租约、编辑模式、保存协调、自动保存、捕获、组合输入、本机发件箱、恢复、冲突副本、阅读模式、离开提示、页头状态；
  - 表格专有的部分：SheetEditor、CSV、公式恢复与“公式待更新”、表格的只读入口。

  保存层已经只依赖窄接口。
- **做法**：
  - 抽出与类型无关的编辑会话与页面编排，目录名在 P1 设计里定；
  - 定义编辑器接口：创建与销毁、捕获快照、变更通知、只读切换、焦点与选区的恢复、打开自检、资源守卫；
  - 表格与文字文档各实现一个编辑器适配；CSV 与公式恢复这类表格专有的部分以扩展点挂接。
- **顺序**：
  - 先在不改行为的前提下迁移表格，一次迁一个职责，每一步跑全量单元与相关 E2E；
  - 再接文字文档；
  - 表格侧的既有测试全部保持通过：单元与集成 18,006 项；E2E 每个浏览器 837～848 条（M5-P9 之后的基线，取自分支 CI #107；main CI #108 的各浏览器片与之相同）。
- **边界**：
  - “公式待更新”、强制重算、主线程的退路只属于表格，文字文档的档案不含公式引擎。
  - 迁移中如果需要改变表格的行为，按跨模块的协同调整停下请示。
- **图片权限复核（DEF-088，P5）**：
  - 现状：读取授权按文档求并集。图片的读权只来自另一份文档时，那份文档撤权、本文档权限不变，服务端拒绝新的读取，但已解码的像素保留到下一次重读图片或重新打开（ADR-023 的 M5-P9 附录）。
  - 做法：会话层对正在显示的图片复核读权，不下载图片字节；读权已失去的，清除对应像素、换成占位。复核的时机与接口在 P5 设计里定。
  - 范围：表格页、历史预览与文字文档一并覆盖。
  - 放在 P5 的理由：P1 迁移会话层时不改表格的行为；文字文档的图片在 P4 才有，P5 可以一次覆盖三处。这一项会改变表格页的行为，属于需求方 2026-11-16 已批准的范围。

### 6.4 文字文档编辑器与 doc@1 档案

- **依赖**：见 §2.2 第 3 条。
- **档案**：插件与注册顺序按插件档案 v1 §2，配置 `toc: true`；不注册公式引擎、目录块、线程评论；排版 Worker 按 §2.2 第 4 条处理。
- **隐藏与守卫**：
  - 隐藏 30 个菜单项，含子项，功能搜索也找不到（UR-019）；守卫 15 个命令。
  - 入口守卫按档案分开：表格档案里拦下的 `doc.command.insert-doc-image` 和带图片的 `doc.command.inner-paste`，在文字文档里是正文命令，不能沿用。
- **加载时规范**：见 §2.2 第 10 条。
- **只读**：文字文档的只读守卫和权限点（ADR-015 补充）；不配置 `objectPermissionTypes`。
- **内部 API**：新增的都在 internal-api 登记，并配回归用例（ADR-010）。资源守卫取文字文档的资源 hook，不再只认表格的。

### 6.5 页面入口与加载

- **地址与加载**：`/documents/:id` 不变。页面先取文档信息，再按类型加载编辑器：两种档案共用的 Univer 部分预先加载，各自专属的部分按类型加载。
- **预算**：
  - 两种编辑器分别设首屏预算和可达预算（M0 测得 doc@1 首屏 gzip 约 0.99 MiB）；
  - 表格的首屏体积与打开耗时，与 M5 对照不退步，由 P2 实测。
- **历史预览**：只读预览页同样按类型渲染。

### 6.6 平台策略

- **输入法**：
  - 事件归一：真实 Safari 是 WebKit 的提交顺序（DEF-013），按此实现，用 DEF-013 的记录回放；平台自己补发的事件用平台自己的登记识别，不靠 `isTrusted`（§2.3）；
  - 捕获时机仍按整页 DOM 事件判断组合输入（计划书 §7.3，r17、r20），按文字文档复核。
- **`/` 菜单**：见 §2.2 第 11 条。
- **表格守卫**：
  - 单元格里不放图片，覆盖插入、移动、拖动、改为内联、粘贴；
  - 禁用单元格里的“表格”按钮；
  - 拒绝嵌套表格。
- **图片**：
  - 文字文档注册平台的图片服务：鉴权读取、占位、实例登记（ADR-022）；
  - 插入、粘贴、拖放都经上传；向前删除键能删除选中的图片；
  - 离线时插入入口禁用。
- **链接**：
  - 前后端共用的地址判定扩到文字文档的位置（正文的 `customRanges` 和链接资源），保存规范写法；
  - 复制出的 HTML 里样式与 id 的转义（UR-014 的 M6 部分）。
- **粘贴**：见 §2.2 第 12 条。

### 6.7 平台功能接入

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 抽出编辑会话层引起表格回归 | 先迁表格、不改行为；按职责小步迁移，每步跑全量单元与相关 E2E；分支 CI 原六项与托管 Mac 兜底。需要改变表格行为时，停下请示 |
| 1.0.1 的补丁改变了 M0 的结论 | docs-ui 的焦点与链接悬停、ui 的右键菜单焦点、图片渲染这几处补丁可能有影响。P2 的真实 Safari 首跑与三浏览器 E2E 先确认，不符的按根因修 |
| `/` 菜单不吞字需要深入 SDK | 优先在平台侧的捕获阶段接管按键；需要补丁时集中登记（ADR-010）。做不到可靠时停下请示；可能的退路是去掉菜单，属于范围变更 |
| 真实输入法下的行为与记录不符 | DEF-013 属于 P5 交接单的第 2 种，结论成立（§2.3）。SDK 默认行为在 P3 用产品的 1.0.1 再确认；回放用例覆盖两种提交顺序与 `/`、Esc 的按键。平台侧解决不了的，按意料之外的高风险停下请示 |
| 粘贴规范的范围膨胀 | 只修会改变含义的偏差，每项有真实样本（WPS、网页）的回归，其余列为已知限制 |
| 托管 Mac 跑不了真实 Safari | 探测失败就改在本机跑，需求方批准后经 `run.py` 按 native 登记，Mac 空闲约 20 分钟 |
| 本机浏览器长测仍暂停 | 完整门禁走分支 CI 与托管 Mac（§2.1 第 6 条） |
| 首屏体积与打开耗时 | 两种编辑器分别设预算；表格侧与 M5 对照不退步 |
| 排版 Worker 的 Tab 缺陷 | 默认不启用；评估在档案定稿之前；要启用，必须先修好 Tab 并有回归 |
| 新包的供应链门槛 | 1.0.1 早已发布，按依赖门禁登记；不满足时停下请示 |
