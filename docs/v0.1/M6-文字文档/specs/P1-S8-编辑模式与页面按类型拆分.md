# M6-P1 S8：编辑模式、页面与页头按类型拆分

> 日期：2026-11-21｜对应 [P1 设计](../01-P1-文字文档底座.md) §3.5 第 4～6 步与 S8｜状态：S8a 已定；S8b、S8c 在各自开始之前补上

S8 把编辑器页里剩下的三块拆成“共用会话层的通用部分 + 表格的扩展”：编辑模式（edit-mode）、页面（editor-page）、页头（editor-chrome）。页面上报的档案改为按类型注入，start 与 mount 按类型装配。之后 P2 的文字文档只需提供自己的编辑器与扩展。

**不变的**：
- 表格的行为不变；
- 协议、日志、存储里的字符串不变；
- `#sheet-editor`、`data-editor-*` 选择器不变；
- 第 1.6 节列的通知顺序不变。

拆分中如果发现必须改变表格的行为，按设计 §3.5 停下请示。

现状由一个只读的同模型子 Agent 调研。主审抽查了构造顺序、通知函数、打开自检的类型与 CSV 目标，属实。

## 1. S8a：编辑模式拆成通用核心与表格扩展

### 1.1 表格专有的部分

edit-mode.ts 约 2,400 行。表格专有的部分分五类：

| 类 | 内容 | 在通用流程里的位置 |
|---|---|---|
| CSV | `csvTarget(newDocument)`；会话或本机代次一变就作废的 `csvSessionGeneration` | 不在流程里，由页面的 CSV 控制器拉取。它读编辑模式的大量私有状态：代次、模式、租约与写入代次、保存的状态机、本机锁、待处理的失权与阻断、显示的快照、会话、是否隐藏 |
| 工作表名 | `sheetName(id)` | 不在流程里，只读当前接上的实例 |
| “公式待更新”与重算 | 服务端的标记 `latestFlag`，阅读模式的 `formulasPending`；进入编辑与本机恢复时 `recalculate`；保存状态机的初值 | 打开、阅读检查、进入、离开、进入失败、重载、刷新 |
| 公式的回退与恢复 | `formulaFallback` 包住工厂；`formulaRecovery`；`recoveryBusy()` 挡约 14 个入口；交接回应 `'recovering'` | 通知函数的开头；会话变化、页面隐藏、卸载时撤销 |
| 故障上报 | 公式 Worker 故障的上报 `reportFormulaFault` | 通知函数里的稳定状态；每次创建之后 |

另有**打开自检**（`openCheckOf`、阅读模式的 `damaged`）。它不是表格专有的：
- 失败的种类、资源名与上报的格式都在 contracts；
- 资源名的写法本来就包括 `DOC_`。

所以它随核心进会话层，`OpenCheck` 的类型由会话层按 contracts 定义，做法同 S7 的 `UncommittedInput`。

### 1.2 切法：装配时注入一个扩展对象

调研列出三种切法：

| 切法 | 结论 |
|---|---|
| 外层包装：表格包住通用的编辑模式，在入口先判断再转发 | 不采用。包不住核心内部自己触发的路径（自动交出、空闲释放、交接回应、请求获准后的自动进入、保存的二次判断）；恢复的同步只能接在通知之后，改变第 1.6 节的 D1、D2、D10 |
| 生命周期钩子散在约 25 处 | 与扩展对象的挂点相同，只是接口分散 |
| **扩展对象**：核心在构造时调用表格给的工厂，得到一个扩展，在原来的位置调用它 | **采用**。挂点与今天的调用点一一对应，顺序不变；接口集中在一处，文字文档给一个空实现 |

### 1.3 通用核心（`document-editor/edit-mode.ts`）

用 `git mv` 把 `sheet-editor/edit-mode.ts` 搬进会话层，保留历史，再把表格专有的部分抽到表格一侧。核心保留：

- 阅读、进入、退出、交接、请求编辑、本人接管、失去编辑权、刷新、重载、卸载的全部流程。
- **打开自检**：`openCheckOf`、阅读模式与打开结果里的 `damaged`、上报。上报的请求体 `open-check-report.ts` 一起搬进会话层。页面上报的档案在 S8b 注入，S8a 里仍取 `PAGE_CLIENT_FORMAT`。
- **服务端的“公式待更新”标记**：`latestFlag`、阅读模式的 `formulasPending`。这是协议里的字段，按 S7 spec §5.2 第二类照旧，文字文档恒为假。
- **本机恢复安装前等派生内容收齐**：`settleFormulas(10_000)`，不收齐就以 `'formulas'` 阻断。方法名与取值照旧，文字文档在 P2 恒为已收齐。

**编辑器的类型**是核心的类型参数，要求的是会话层的窄接口并集：
- 保存（`EditingSessionEditor`）；
- 槽位（`SlotEditor`）；
- `openCheck`。

视图状态、生命周期的阶段与创建的选项随之成为类型参数。

**视图**：`EditModeView<Extra>` 是通用的六项去掉 `formulaRecovery` 之后，再并上扩展的视图。
- 核心记下扩展上一次交出的视图对象，按引用比较是否变化，与今天比较 `formulaRecovery` 的写法相同。
- 扩展要保证没有变化时交出同一个对象。
- 表格的扩展交出 `{ formulaRecovery }`，所以 `view().formulaRecovery` 对页面与测试不变。

**动作目标**：CSV 目标里与类型无关的部分由核心给出，即 `actionTarget()`。它交回：
- 当前编辑器；
- 一个 `current()` 谓词：代次、会话代次、会话、隐藏、实例、模式、租约与写入代次、本机锁、待处理的失权与阻断、保存的状态机，任何一项变了就为假；阅读时另要求没读不到、没有自检失败与不兼容、没有在刷新与接手；
- 新文档判断要用的几项事实：模式、修订号、保存状态机的“未保存”、显示的快照。

`csvSessionGeneration` 改为核心的会话代次。setSession 里加一的位置不变，仍在撤销扩展之前。

### 1.4 扩展的接口

**扩展从核心拿到的（`EditModeHost`）**，即今天 `createFormulaRecovery` 与 CSV 用到的：
- `editing`、`slot`、`clock`、`reportError`；
- `context()`：代次、访问方式、会话是否本人、是否允许、修订号。取法与今天 `formulaRecovery` 的 context 逐字相同；
- `openCheck(created, context)`：核心的打开自检；
- `notify()`、`retryRequests()`；
- `still(token)`、`generation()`、`session()`、`hidden()`、`disposed()`，供上报判断；
- `actionTarget()`。

**核心调用扩展的地方（`EditModeExtension`）**：

| 成员 | 今天的调用点 | 表格的实现 |
|---|---|---|
| `onNotify(stable)` | 通知函数的开头：先 sync，再按稳定状态上报 | `formulaRecovery.sync()`，然后 `reportFormulaFault(stable)` |
| `afterCreate(context)` | `replaceEditor` 里 `slot.replace` 之后，`still(token)` 时 | `reportFormulaFault(context)` |
| `blocksActions()` | `recoveryBusy()` 的后半 | `formulaRecovery.view()?.blocksActions === true` |
| `view()` | `computeView()` | 引用稳定的 `{ formulaRecovery }` |
| `cancel()` | setSession 里会话变了、releaseOnHide | `formulaRecovery.cancel()` |
| `dispose()` | dispose | `formulaRecovery.dispose()` |
| `enterOptions(pending)` | 进入编辑、本机恢复两处创建的选项 | `pending ? { recalculate: true } : {}` |
| `savingPending(flag)` | `startSaving` 的“公式待更新”初值（非恢复时） | `flag \|\| fallback.failure() !== undefined` |

**表格扩展的构造**沿用今天的位置：
- 回退包住工厂，在核心之前建；
- 核心建好 tabs 之后、`current = computeView()` 之前，调用扩展的工厂。

扩展的 onChange 与今天相同：先 `host.notify()`，阶段到 ready 再 `host.retryRequests()`。

**`busy()`**：核心保留今天的判断，即编辑中，或阅读且不在刷新，再加上 `extension.blocksActions()`。约 14 个入口照旧在第一句判断，交接回应照旧回 `'recovering'`。

**文字文档的空实现**留到 P2。核心的测试用一个空扩展。

### 1.5 表格的扩展与门面（`sheet-editor/sheet-edit-mode.ts`）

`createSheetEditMode(options)` 依次做三件事：
1. 建回退；
2. 以表格的扩展工厂建通用核心；
3. 交回 `SheetEditMode`：核心的 EditMode，加上 `csvTarget`、`sheetName`、`retryFormulaRecovery`。

- **选项与今天的 `EditModeOptions` 相同**，`createEditor` 仍是 `CreateModeEditor`。页面与测试只改引用。
- **`csvTarget`** 由动作目标加上表格的条件组成：
  - 自检通过；
  - 没有 Worker 故障；
  - 不在恢复；
  - 新文档时是表格的空白模板、而且没改过。

  阅读时的 `formulasPending` 取核心的阅读模式。
- **`sheetName`**：取核心当前接上的实例。

### 1.6 通知顺序的对照

| 依赖 | 拆分之后 |
|---|---|
| D1 先 sync 再上报，再比较视图、通知监听者 | 核心的通知函数先调 `onNotify`（表格在里面先 sync 再上报），再算视图、比较扩展视图的引用 |
| D2 重入：sync 里经 onChange 嵌套 notify，嵌套的 sync 直接返回 | 不变。嵌套的 notify 再调 `onNotify`，表格恢复里的 `syncing` 守卫照旧 |
| D3 begin 先加代次、setMode 先设模式再 notify | 不变，都在核心 |
| D4 推迟一拍执行，同步挂起 | 不变，在表格的恢复里 |
| D5 门控在函数第一句 | 不变，`busy()` 在核心 |
| D6 保存的二次判断 | 不变，在核心 |
| D7 setSession：先设会话，再会话代次加一与撤销，再 syncSaving 与 notify；隐藏：先 hidden 再撤销；卸载：先 disposed，再扩展的 dispose，最后清空槽位 | 逐项照搬，扩展的 `cancel`、`dispose` 放在原来的位置 |
| D8 创建路径的上报取创建前的代次 | 不变，`afterCreate` 在 `replaceEditor` 里原来的位置 |
| D9 恢复就绪：先 notify 再 retry | 不变，在表格扩展的 onChange 里 |
| D10 页面在同一个栈里反应 | 不变，订阅关系不动 |
| D11 构造顺序：回退 → 槽位 → 会话 → …… → 恢复 → 视图 | 回退在核心之前；扩展的工厂在核心里原来建恢复的位置调用 |
| D12 阶段的含义 | 不变，在表格的恢复里 |

## 2. S8b：页面（S8b 开始之前补上）

已知要做的：
- editor-page 拆成通用页面与表格扩展：CSV 控制器、`formulaBusy`、`sheetName`、`retryFormulaRecovery`、视图里的 `imageOperation` 与 `formulaRecovery`。
- 页面上报的档案按类型注入。用到它的地方：
  - 编辑权的三个请求体（申请、续租、请求编辑）；
  - 草稿的 format，也就是保存与副本的查询参数与附加认证数据；
  - 恢复的可读判定，包括编辑器页与草稿页两处；
  - 两种上报。

  表格的取值逐字节不变。
- 页面载入详情之后，按详情里的类型取装配；没有装配的类型进入“格式不受支持”。今天的判断是 `isKnownFormat`。
- 详情没取到就要恢复草稿时（404 之后），不知道类型，可读判定怎么定在这一步写清楚。P1 只有表格的草稿。

## 3. S8c：页头、start 与 mount（S8c 开始之前补上）

已知要做的：
- editor-chrome 改成通用骨架加插槽。表格的插槽：
  - CSV 入口；
  - 公式恢复的说明与重试；
  - 按工作表名的说明；
  - 图片输入的提示。
- start 与 mount 按类型装配。start 在测试构建里动态引入 `editor/testing/` 的自动保存控制与交接日志，会话层不能引用适配层，所以要么由装配注入，要么把这两个与类型无关的测试工具搬进会话层的 testing/。到时定。
- selftest-hook 依赖适配层的页面自检，留在表格编辑器，由表格的装配接上。
- 按路径写的规则：
  - 确认弹窗、`dialog.tsx`、同事选择的豁免只列了 sheet-editor；
  - 分享入口、本机数据提示的放行；
  - 门禁 artifacts 的 `TEST_ONLY_SOURCES`；
  - lint 自测里写到这些文件的十来处。
