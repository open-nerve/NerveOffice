# M6-P1 S6、S7：共用编辑会话层（第 1、2 批）

> 日期：2026-11-18（S7 一节 2026-11-21）｜对应 [P1 设计](../01-P1-文字文档底座.md) §3.1、§3.5 与 S6、S7｜状态：S6 已完成；S7 已定，实施中

S6 把表格编辑器（`W/features/sheet-editor`）里与表格无关、也不引用留下的模块的部分，原样搬进共用编辑会话层 `W/features/document-editor`，同步改按路径写的规则，加上依赖方向的规则。不改任何行为。

## 1. 搬迁的范围

- 只引用这一批要搬的模块，以及 shared、contracts、`editor/testing/` 里零依赖的诊断格式；
- 不碰公式、CSV、工作表这类表格的概念。

脚本按每个文件的相对引用（含 `import type`、动态 `import()` 与 `vi.mock`）核对过：搬的文件不引用留下的文件，集合是闭合的。

## 2. 公开入口与测试入口

**公开入口 `document-editor/index.ts`**：只放 sheet-editor 的生产代码用到的名字，逐个列出，不用 `export *`。

请求层 editor-api 整体以命名空间 `editorApi` 转出，原因是同名：
- editor-api 的 `acquireEditLease` 是申请编辑权的请求；
- edit-lease 的 `acquireEditLease` 是带重试的申请流程。

两者原来各在自己的文件里，并到一个入口就同名了。命名空间让组装处读作 `editorApi.acquireEditLease`，两个模块都不改名。editor-api 里别处也用到的类型（`LoadedContent`、`FetchedEditStatus`、`LeaseCredentials`）与 `CONTENT_UNCHANGED` 另外直接转出，引用它们的文件只改路径。

**测试入口 `document-editor/index.test-support.ts`**：sheet-editor 的测试经它取两类东西：
- 假件：`fakeBrowser`、`memoryIssuedRequest`、持久工作草稿的测试辅助；
- 只有测试用到的内部常量与函数：重试与轮询的间隔、锁与频道的名字、`onReply`、`keyOf`、`createPersistentWorkingDraft` 等。

这样公开入口不为测试加名字。写法照 api 的 `app/integration.test-support.ts`（只给集成测试的入口）。

**sheet-editor 一侧只改引用路径**：
- 生产代码改经 `../document-editor/index.ts`；
- 测试改经公开入口或测试入口；
- `start.test.tsx` 原来 `vi.mock('./page-guards.ts')`，改为对公开入口 `vi.mock(import('../document-editor/index.ts'), …)`，其余名字取原实现。不能写成 mock 内部文件：路径字符串不经模块边界检查，等于绕过了它。

## 5. S7：保存层的公式钩子改为扩展点；editor-slot 泛型化

现状由一个只读的同模型子 Agent 调研，主审抽查了引用、测试辅助的依赖与跨目录引用的名字，属实。

### 5.2 公式的钩子：哪些是扩展点，哪些照旧

保存层里与公式有关的东西分四类：

| 类 | 内容 | S7 的处理 |
|---|---|---|
| 编辑器接口里的“派生内容收齐” | `settleFormulas`、`formulasSettled`、`onFormulaProgress`；同类的 `isCellEditing`、`commitCellEditing`、`settlePanels`、`uncommittedInput` | 这就是扩展点。保存层只依赖会话层自己的窄接口（CaptureEditor、SaveEditor、AutosaveEditor 等），表格编辑器照旧实现；文字文档在 P2 实现成恒为已收齐、没有未提交的输入。名字不改，见设计 §3.5 与 ADR-027 |
| 协议与草稿里的“公式待更新” | 保存请求的 `formulasPending`；草稿捕获与附加认证数据里的 `formulasPending`；申请编辑权响应里的标记，进入编辑时成为 `initialFormulasPending` | 不改名、不改取值。会话层照旧按它算“未保存”与补捕获。文字文档的服务端不会给出这个标记 |
| 日志与界面的取值 | 捕获原因 `'quiet'`、`'cap'`、`'formulas'`、`'formula-recovery'`；交接回应的 `'recovering'`；页头文案的键 `'formulas-pending'` | 不改。前两类进自动保存的控制日志、交接日志与页面自检 |
| 同一会话里换编辑器（只有表格的公式恢复在用） | editing-session 的 `freezeEditor`、`captureEditor`、`replaceEditor`；autosave 的 `captureForFormulaRecovery`、`settleInputPreparations`；save-coordinator 的 `noteFormulaRecovery`；saving-editor 的冻结与重新接上 | 原样搬进会话层，作为会话层提供给扩展的端口：冻结当前的编辑器、带标记捕获并记下边界、接上新的实例、序号接得上。机制与文档类型无关，调用方 formula-recovery 留在表格编辑器 |

最后一类里带公式字样的两个方法名，与日志值 `'formula-recovery'`，随会话层里其余的公式字样一并交给 ADR-027，在 P2 有了两个实现之后定。这几个端口要不要合成一个，在 S8 拆 edit-mode 的公式恢复时，写进 S8 的 spec。S7 只搬，不改名：改名的这一次与 ADR-027 的那一次会重复。

**进入编辑时的重算**（`recalculate`）与 **Worker 失败的回退**（`formulaMode`）是创建编辑器的选项，见 5.3。

### 5.3 editor-slot 泛型化

**会话层不再引用编辑器适配层**：

- `UncommittedInput`（`'none' | 'open' | 'pending'`）与 `EditorAccess`（`'edit' | 'read'`）由会话层自己定义，分别放在 save-coordinator 与 editor-slot。两者语义与文档类型无关。
- 适配层的同名类型照旧，它们同形。sheet-editor 把 `SheetEditor` 交给会话层时由类型检查核对：适配层多出一种取值，或者会话层的访问方式多出一种，组装处就编译不过。
- 这是依赖倒置：接口归使用它的会话层，适配层按结构满足它，两边互不引用。S6 spec §3 预留的“只开类型”的口子不开，会话层到适配层保持默认的禁止。
- `SheetEditor`、`SheetViewState`、`SheetEditorLifecycle`、`FormulaMode` 随槽位泛型化去掉。

**槽位按编辑器的类型泛型化**：

- 对编辑器只要求四样：取出视图状态、销毁（交回 Promise，可能要等一会儿）、生命周期的阶段与订阅。视图状态与阶段的类型跟着编辑器的类型走。
- 进展是 `'none' | 'creating' |` 编辑器的阶段。sheet-editor 的页面仍按 `'steady'` 判断。
- 另一个类型参数是创建的选项。工厂收到快照、访问方式、视图状态，加上 `replace` 给的选项。槽位原样交出选项；`replace` 不给选项时，交出建槽位时给的 `defaultOptions`。表格给的是空对象，不多任何一项。
- 为什么要 `defaultOptions`：选项的类型是泛型，类型检查无法确认“空对象”是一份合法的选项。由建槽位的一方给出，就不用类型断言。
- 不变量不变：单飞；旧的销毁完才新建；取代之后销毁结果；没接上就被取代或新建失败时，视图状态留给下一个；`discard` 只丢弃交出未接上的那一个。

**表格的部分挂在表格一侧**：

- 新建 `sheet-editor/sheet-editor-slot.ts`，是表格对槽位的实例：
  - 表格的创建选项 `ReplaceOptions = { recalculate?: true, formulaMode?: FormulaMode }`；
  - `CreateModeEditor`，即槽位的工厂按 `SheetEditor` 与这组选项实例化；
  - `SheetEditorSlot`、`SheetEditorSurface`；
  - `createSheetEditorSlot`：写明四个类型参数，`defaultOptions` 给空对象。edit-mode 与公式恢复的测试辅助都经它建槽位。
- 原来由槽位做的规整（`recalculate` 只在为 true 时交给工厂）改由类型保证：`recalculate` 只能是 `true`。edit-mode 有两处按布尔值传，改为为真时才带上。“不带标记进入编辑时，创建参数里没有 `recalculate`”仍由 edit-mode 的现有用例核对，用例不改。
- formula-fallback 照旧包住表格的工厂：记下故障之后改成主线程模式并强制重算。它仍由 edit-mode 构造，S8 之前 edit-mode 就是表格的装配。
- editor-page、formula-fallback、formula-recovery、edit-mode 的类型改从这个文件取。

**槽位的测试随它搬**：
- 假件改成只实现上面四样的最小编辑器，不再带 CSV、工作表名与公式。原来的假件借用 sheet-editor 的 `csv.test-support.ts`，会话层不能引用它。
- 两条“选项交给工厂”的用例改用中性的选项，核对的内容照旧：给了就原样交出，不给就没有这一项。第二条另核对工厂收到的只有快照、访问方式与视图状态三项，比原来只看“没有 recalculate”更严。

- 其余用例的断言不变。
