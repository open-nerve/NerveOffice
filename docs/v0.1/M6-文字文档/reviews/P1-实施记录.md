## main CI #109 的依赖漏洞（2026-11-18）

- **现象**：M6 总设计合入之后的 main CI #109（run `44269592484`，`b3302447`）只有 verify 一项失败，其余五项成功。失败在最后一步 audit（0.9 秒）；lint、typecheck、门禁、单元与集成覆盖率、构建都通过。
- **原因**：picomatch 新公布了高危通告 [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)：单分支重复的 extglob 会引起 ReDoS。受影响的版本是 4.0.7 及以下，上游还没有修复版本。依赖链是 tools → vite → tinyglobby → fdir → picomatch@4.0.7。tools 把 vite 写在 dependencies 里，所以算作生产依赖。这次合并没有改动依赖。
- **影响**：
  - 运行时镜像只装 api 的生产依赖（`deploy/Dockerfile` 的 prod-deps 阶段），不含 vite 与 picomatch。
  - vite 只在构建阶段运行，交给 picomatch 的匹配模式都来自本仓库的配置，不接收外部输入。
- **处理**：按《工程规范与完成定义》的规定（生产依赖出现高危漏洞，在当前 Phase 内升级、替换，或者登记例外并写明缓解措施），在 `tools/src/gates/policy.ts` 登记第一条漏洞例外，到期日 2026-12-18。
  - 修复版本发布满 3 天（供应链冷却期）就升级，并删掉这条例外。
  - 例外到期，或者对应的漏洞不再出现，门禁都会失败，迫使重新评审。
- **验证**：本机 audit 门禁，登记前失败（1 处违规），登记后通过。
- main 的 CI #109 不重跑。这条例外随 P1 合入 main 之后，由 main 同 SHA 的 CI 验证。

**实现中的调整**：

- **补上 `doc-notes`。** 写规则前与计划书 §11.2、总设计 §6.2 逐条对照，发现 S3 的 spec 把脚注写成了“不判”，与“本期不支持的结构（页眉页脚、脚注尾注等）要求为空”不符。改为新规则 `doc-notes`：`notes`、`footnotes`、`endnotes` 不在或深层为空。`noteSettings` 只是编号的设置，不判。spec 已改。
- **交叉核对只比 SDK 加载时读的字段。** 核对了 Univer 1.0 的源码：链接资源加载时只读每一项的 `id` 与 `payload`，按 id 覆盖正文的地址；图片资源加载时只读 `data` 与 `order`（`resetDrawing(data, order)`）。所以逐项比这几个字段，多出的键不看。
- **分节符的判断不随规模的乘积增长。** 表格的区间排序合并之后二分查找；单元测试用十万个表格与十万个分节符核对。
- **段落位置。** 段落的 `startIndex` 是段落结尾的 `\r`，区间起点所在的段落是第一个 `startIndex` 不小于起点的段落。段落数组按文档里的先后排序之后二分；写法不对的段落不算。
- **M0 样本。** 30 份（9 份原文、21 份浏览器保存的结果）在图片换成平台地址之后都通过。原样的 doc-all 按 image-source 拒绝，位置是顶层的两张图片与图片资源。样本文件带缩进，换地址前先写成紧凑的 JSON。
- **文字文档的哈希向量另行核对。** 按 ADR-011 与 spec 的文字另写了一份 Python 实现（只放在会话的临时目录，不入库），对 M0 的 doc-all 算出的 SHA-256 与 TS 的结果相同（`727f21cc…7347`），之后才钉进测试。
- **规范化的档案参数必填。** 现有调用（服务端检查、api 与集成测试、测量脚本、E2E）都显式传 `sheet@1`，表格的规范文字逐字节不变，原有向量照旧通过。测试工具里的第二份实现默认按表格，理由见 spec §5。
- **上传检查仍按 sheet@1。** doc@1 的规则在 S4 只经单元测试与整条检查的测试走到；上传检查按上报的档案是 S5（DEF-055）的事。

## S5 DEF-055：上报的档案与文档的档案（2026-11-18）

1. **上传检查按上报的档案。** `requirePassingSnapshot` 增加档案参数，保存与另存为副本都传页面上报、已通过格式核对的档案；`INSPECTED_PROFILE` 删去。检查不读文档，看不到与不存在的文档得到同样的回答。

4. **副本的信封记服务端的档案**（与核对过的上报相同，表格的取值不变）。
