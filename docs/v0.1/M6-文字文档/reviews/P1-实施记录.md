## main CI #109 的依赖漏洞（2026-11-18）

- **现象**：M6 总设计合入之后的 main CI #109（run `44269592484`，`b3302447`）只有 verify 一项失败，其余五项成功。失败在最后一步 audit（0.9 秒）；lint、typecheck、门禁、单元与集成覆盖率、构建都通过。
- **原因**：picomatch 新公布了高危通告 [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)：单分支重复的 extglob 会引起 ReDoS。受影响的版本是 4.0.7 及以下，上游还没有修复版本。依赖链是 tools → vite → tinyglobby → fdir → picomatch@4.0.7。tools 把 vite 写在 dependencies 里，所以算作生产依赖。这次合并没有改动依赖。
- **影响**：
  - 运行时镜像只装 api 的生产依赖（`deploy/Dockerfile` 的 prod-deps 阶段），不含 vite 与 picomatch。
  - vite 只在构建阶段运行，交给 picomatch 的匹配模式都来自本仓库的配置，不接收外部输入。
- **处理**：按《工程规范与完成定义》的规定（生产依赖出现高危漏洞，在当前 Phase 内升级、替换，或者登记例外并写明缓解措施），在 `tools/src/gates/policy.ts` 登记第一条漏洞例外，到期日 2026-12-18。
  - 修复版本发布满 3 天（供应链冷却期）就升级，并删掉这条例外。
  - 例外到期，或者对应的漏洞不再出现，门禁都会失败，迫使重新评审。
- **验证**：本机 audit 门禁，登记前失败（1 处违规），登记后通过。
- main 的 CI #109 不重跑。这条例外随 P1 合入 main 之后，由 main 同 SHA 的 CI 验证。
- **后续**：这条通告 2026-11-18 15:38（UTC）就撤回了，原六项 CI #110 的 audit 因此报例外用不上。S10 删除了这条例外，见 S10 一节。

**实现中的调整**：

- **段落位置。** 段落的 `startIndex` 是段落结尾的 `\r`，区间起点所在的段落是第一个 `startIndex` 不小于起点的段落。段落数组按文档里的先后排序之后二分；写法不对的段落不算。

## S10 独立审查的修复（2026-11-22）

S8c 之后，两个同模型子 Agent 对 P1 全分支各做一份独立审查：A 看服务端与契约（S2～S5），B 看前端的会话层（S6～S8c）。逐条的核实、处置与复验写进 [P1 审查报告](P1-审查报告.md)，这里记修复的过程。

**审查 A 的 M-1：`doc-section-break` 认表格只看 `tables`**
- 现象：规则把 `tables` 里声明的区间当作表格，区间里的分节符不计。伪造一个盖住正文的区间，就能藏住多出的分节符。
- 修法：表格以 `dataStream` 里的控制符为准。起点是表格开始 `\x1A`，终点的前一位是表格结束 `\x0F`，这是 SDK 写表格的写法（docs-ui 的 `buildDocTableInsertBody`），M0 的 8 个表格都是。不是的区间不算表格。
- 测试：
  - 新增 1 条，核对三种不算表格的区间：正文里没有表格、`tables` 却声称有；只有起点是控制符；只有终点的前一位是控制符。两端都对的照常是表格。
  - 原有 4 条的输入改为真实的表格写法，期望不变：表格里每个单元格的分节符、区间的先后与重叠、写法不对的表格、十万个表格的规模。原来的 `dataStream` 里没有表格控制符，按新的规则不再是表格。规模用例里每个表格占 4 个字符。
  - 先失败：新增那条报 `expected 'ok' to be 'doc-section-break'`，同文件其余 64 条通过。修法之后，相关的 4 个文件 181 条通过，其中 M0 的 30 份文字文档样本照常通过。

**审查 B 的 I-1：页头插槽对页面扩展的类型逆变**
- 现象：S8c 的插槽是模块级常量，`toolbar`、`notice`、`snapshotProblem` 收 `page: EditorPage<Extension, …>`，经 `page.extension()` 读成员；骨架与启动要求 `Extension extends EditorChromeMembers<Extension, …>`。插槽是属性函数，参数在 strictFunctionTypes 下按逆变检查，而页面对 Extension 协变。P2 把两类文档的成员合成并集时，表格的插槽不满足约束，不用 `as` 就编译不过，与 S8 spec 说的“通用页面不用改”相反。P1 的运行时不受影响。
