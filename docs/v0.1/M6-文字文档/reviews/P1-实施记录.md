## main CI #109 的依赖漏洞（2026-11-18）

- **现象**：M6 总设计合入之后的 main CI #109（run `44269592484`，`b3302447`）只有 verify 一项失败，其余五项成功。失败在最后一步 audit（0.9 秒）；lint、typecheck、门禁、单元与集成覆盖率、构建都通过。
- **原因**：picomatch 新公布了高危通告 [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)：单分支重复的 extglob 会引起 ReDoS。受影响的版本是 4.0.7 及以下，上游还没有修复版本。依赖链是 tools → vite → tinyglobby → fdir → picomatch@4.0.7。tools 把 vite 写在 dependencies 里，所以算作生产依赖。这次合并没有改动依赖。
- **影响**：
  - 运行时镜像只装 api 的生产依赖（`deploy/Dockerfile` 的 prod-deps 阶段），不含 vite 与 picomatch。
  - vite 只在构建阶段运行，交给 picomatch 的匹配模式都来自本仓库的配置，不接收外部输入。
- **处理**：按《工程规范与完成定义》的规定（生产依赖出现高危漏洞，在当前 Phase 内升级、替换，或者登记例外并写明缓解措施），在 `tools/src/gates/policy.ts` 登记第一条漏洞例外，到期日 2026-12-18。
  - 修复版本发布满 3 天（供应链冷却期）就升级，并删掉这条例外。
  - 例外到期，或者对应的漏洞不再出现，门禁都会失败，迫使重新评审。
- **验证**：本机 audit 门禁，登记前失败（1 处违规），登记后通过。
- main 的 CI #109 不重跑。这条例外随 P1 合入 main 之后，由 main 同 SHA 的 CI 验证。

## S3 资源规则模型、规则标识、位置与说法（2026-11-18）

规则与证据见 [S3、S4 spec](../specs/P1-S3-文字文档的快照规则.md)。

**先失败的测试**：

| 测试 | 旧代码上的结果 |
|---|---|
| contracts `profile-resources-doc.test.ts` 9 条：doc@1 的资源白名单、三种 kind、M0 样本的资源 | 8 条失败（还没有 doc@1 的资源规则）；“两种档案的资源互不认识”一条本来就通过 |
| contracts `snapshot-rules.test.ts` 新增 4 条：新规则的顺序、详情、两类新位置 | 4 条失败 |
| api `snapshot-inspector.test.ts`：文字文档的说法 | 3 条失败：文字文档的说法一条，另两条是改为显式传档案的旧用例（签名变了） |
| web `snapshot-problem.test.ts`：文字文档的说法与位置 | 写测试时没有单独跑失败。事后把 `editor.ts`、`snapshot-problem.ts` 临时换回 HEAD 补看：7 条失败，其中两条新用例因为功能缺失，另 5 条旧用例因为签名多了文档类型；随后原样恢复，两个文件的 SHA-256 前后一致 |

**实现中的调整**：

- **资源 `[]` 的误拒。** M0 样本里 `DOC_OBJECT_PERMISSION_PLUGIN` 是 `[]`，按 sheet@1 的资源结构（顶层必须是对象）会判 resource-data。规则模型改为判别联合：`entries`（sheet@1 十项，语义不变）、`empty`（任何 JSON，深层为空）、`shaped`（图片与链接各自的结构）。sheet@1 的旧用例不改即通过。
- **说法按档案给出。** 服务端 `snapshotInvalid` 与页面 `snapshotInvalid` 都改为按档案或类型取名词与例子；表格的说法有逐字不变的用例。
- **拒收日志加档案。** `快照不合格，拒绝写入` 的日志多记 `profile`（不是敏感信息，便于区分两种文档），两条日志断言跟着补上，用例名改为“只记规则、档案、文档 id 和字节数”。
- **漏洞门禁的装配用例（`5dc3788e` 的疏漏）。** 登记例外之后只跑了 audit 门禁，没跑 tools 的单元测试。门禁直接读仓库的例外清单，两条用固定真实输出的装配用例因此多出“用不上的例外”。改为由门禁表把 `AUDIT_EXCEPTIONS` 传给 `auditGate`，装配用例传空清单；另加一条用例核对仓库清单的写法（GHSA 编号、原因、到期日，编号不重复），门禁表接的仍是仓库清单（原有的 runGate 对照用例）。
- **lint。** `describeLocation` 的 switch 显式列出表格的三种位置，不用 default；正则改用字符范围。
