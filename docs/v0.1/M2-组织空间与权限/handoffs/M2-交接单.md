# M2 组织、空间与权限：交接单

> 日期：2026-10-03｜所属：v0.1-M2｜对应合并：P1–P4、P6 各片、P5 各自以 `--no-ff` 合并到 main（P5 的合并提交与合并之后的 CI 记在 `reviews/M2-收尾汇报.md` §3）；标签 `v0.1-m2`

M2 把 M1 的单人骨架变成团队用的平台：账户与系统管理（邀请、重置、停用、系统管理员）、团队空间与成员角色、有效权限与"可访问文档"、查看者的只读加固、文件夹与回收站、改名移动复制、按标题搜索、单独分享与"与我共享"，以及越权访问的全面验证。执行顺序是 P1 → P4 → P6（2026-09-30 插入的复核）→ P5。本交接单是 M3 总设计的输入；各 Phase 的交接单里有更细的"已知的坑"，这里不重复。M2 总设计 §8 退出条件的逐条证据在 `reviews/M2-收尾汇报.md`。

## 与设计的偏差

都已回写 M2 总设计的变更记录（§9）、00 号计划书（r7–r12）或 ADR：

- 运维命令 `pnpm admin:reset-link`（唯一的管理员忘记密码时）；新增 workspace 模块（避免 spaces 循环依赖）；工作簿级的 `setEditable(false)` 由授权服务的回答取代。
- 插入 P6「M2 复核」，执行顺序改为 P1–P4 → P6 → P5。
- 需求方在复核与 P5 中的决定：全员可见对系统管理员同样生效；只凭授权的人不能移动、删除；US-M2-14 的耗时一致按"响应与 SQL 语句序列相同"验证；归档空间里分享冻结；显示名里不禁止括号、只靠界面区分，人名里登录名与显示名同样醒目；个人空间按所有者的人名呈现，不显示存的名称；系统管理员可以像别的同事一样被单独分享文档（00 号计划书 r12）。
- 登录限流改为三个维度（"用户名 + 来源"锁定、宽的只按用户名的上限、只按来源），管理员可以解除锁定（ADR-007）；失败登录对各组参数各算一次，耗时与账户是否存在无关。

## M3 须知

- **有效权限只有一个入口**：`access-rules.ts` 的纯函数（`documentAccessOf` 先取空间角色与单独授权的较高者、再按归档降级）加 `DocumentAccessPolicy`。`DocumentAccess` 分开带 `spaceRole`（结构性操作：移动、删除、分享）与 `contentRole`（读、保存、改名、复制），`accessVia` 说明凭什么访问。M3 的编辑权（租约）按 `contentRole` 判断；服务不自己拼权限条件。
- **读请求的一致快照**（ADR-017）：登录之后的 GET 在一个只读快照里判断权限、读数据（`TransactionRunner.readSnapshot`）；快照在最外层的服务里开、内层方法传事务、不嵌套，快照进行中连接池上的查询一律报错；新的 GET 接口要在 `tests/integration/src/api/read-snapshots.test.ts` 的请求表里登记。M3 的编辑器读接口同样照办；写接口仍是"先判断、再加锁、锁下复核"。
- **"可访问文档"只在 `documents.repository.ts` 的 `accessible({ spaceIds, grantsOf })`**：按空间列出、转移、回收站不并授权；"与我共享"只要授权那一半（按 `document_grants(user_id)` 驱动，EXPLAIN 用例守着）；搜索两半都要，"凭授权命中"与行出自同一条语句。
- **收回写入权**：改动权限的事务里调用 `WriteAccessRevocation.revoke(scope, transaction)`，范围有五种：某人（停用）、某人在某个空间（移出、调整角色）、空间（归档）、这些文档（转移、删除、跨空间移动）、某人在这些文档上（取消分享、降级）。M2 的实现为空，**M3 接入租约**，并收口"进行中的保存与撤权不互斥"（P2 设计 §7）；`coversWriter` 是给 M3 的语义规格。`writeEpoch` 在转移、删除、跨空间移动时加一。
- **锁的顺序**（ADR-007、ADR-014）：system-admins → 按登录名 → 账户行 → 重置或邀请行 → 限流计数 → 会话行 → 空间树的 advisory lock → 空间行 → 成员行 → 文件夹行、文档行、回收站行 → 审计。分享的写入：账户行 `FOR SHARE` → 空间行 `FOR SHARE` → 文档行 `FOR UPDATE`，锁下复核；保存、改名、复制在文档行锁下重新判断授权。新的写路径先放进这张表，并写确定交错的用例（`tests/integration/src/support/held-lock.ts`）。
- **写接口的约定**：数据库繁忙时 503 = 确定没有生效；提交之后的繁忙回 500（结果未知），响应在业务事务里拼好（请求级的提交记录 `CommitLedger`）；带 `requestId` 的重放带 `replayed`。
- **编辑器的只读在创建时决定**（`createSheetEditor({ access })`）；只读守卫的四个出口留给 M3 的原地切换复用（DEF-036）。
- **前端的共用做法**（规范 §2.4）：写操作结果未知时先按 `refresh` 刷新再说明（`shared/api/write-outcome.ts`）；带 `requestId` 的新建按页面一份的请求标识记账；人名一律经 `PersonName`（登录名在前），个人空间经 `SpaceLabel`；内容会变化的说明与进展用 `StatusRegion`；确认框里成功之后要说的由 `run` 交回、确认框关掉之后再写；模态弹窗开着时也可能变化的常驻状态显式写 `aria-live`；写操作成功之后的刷新有时限（`refreshAfterSuccess`），界面依赖刷新结果的先按确定的写入结果改缓存；列表刷新失败用 `RefreshProblem` 明说并能重试。
- **防泄漏的自动核对**：新接口要进路由表的核对（未登录、"看不到 / 不存在"的探测或写明豁免），新操作要在权限矩阵里加行；矩阵的预期按规则独立推出。
- **测试与审查的做法**：每条修复做变异验证，包括"测试的前提失效"一类；复验者的复现用例移进仓库；修复里的新机制另请复验；计时类的判定比较 CPU 时间或墙上耗时的下四分位；子 Agent 一律显式指定与主会话相同的模型，并在汇报的第一行写出模型标识（规范 §10）。
- **CI**：`verify`（no-e2e）加按浏览器分片的 E2E 与容器 job；出现重试即失败。M2 加了不少 E2E（本机三个浏览器 582 条），CI 上按浏览器分片；再加 E2E 之前先看各片的时长。
- **已知的坑**：WebKit 点按钮时不聚焦按钮（焦点给最近的可聚焦祖先，分享对话框里的取消分享因此回到对话框本身）；Radix 的模态弹窗只把焦点还给 `DialogTrigger`，并把弹窗之外的内容标为 aria-hidden（打开那一刻已经在、显式带 `aria-live` 的元素除外）；TanStack Query 的 `isPending` 要等通知之后重新渲染才变（确认框用同步的标记）；摆世界共用的连接上回调里不能再调 `query`。
