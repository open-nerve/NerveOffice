## 与设计的偏差

都已回写 P5 设计（§9 变更记录）、ADR-014 与规范：

- **编辑器页静态引用分享对话框**：两处都按需加载时，平台首屏会多拆出第 3 个文件；编辑器页因此多约 9 KiB（S3）。
- **个人空间存的名称不对别人给出**：搜索、"与我共享"、文档详情里都只给所有者或 id 与类型（`spaceIdentitySchema`），只给本人看的地方保留；界面一律按所有者的人名呈现（S2、S3）。
- **繁忙的用例按能构造的写法**：用"排队构造证明提交之后不再读账户表"加"最后一步（审计）繁忙回 503"代替原来的"补人名时繁忙"（S2）。
- **需求方 2026-10-02 的决定**：系统管理员可以像别的同事一样被单独分享文档，个人空间里的也可以（00 号计划书 r12、ADR-014）。
- **说明的口径**（审查之后）：归档时"恢复之后才能调整分享"只给恢复之后能分享的人；不是编辑者的人删除被拒时说"没有删除这份文档的权限"；几处说明不再假定被授权人在那个空间里没有角色。
- **读屏的反馈**（审查与复验之后，规范 §2.4）：共用的状态区 `StatusRegion`（lint 近似拦下藏起来的写法）；确认框里成功之后的说明由 `run` 交回、确认框关掉之后再写（`ConfirmDialog` 的 `AfterConfirmed`、`DialogContent` 的 `onClosed`）；后台会变化的常驻状态显式写 `aria-live`（编辑器页头的保存状态）。

## 下一个 Phase 须知

M2 的最后一个 Phase，下一步是 M3（编辑权与保存协议）。跨 Phase 的约定写在 M2 交接单里，这里只记 P5 新增的：

- **有效权限**：`documentAccessOf` 先取空间角色与单独授权的较高者、再按归档降级；`DocumentAccess` 带 `spaceRole`（移动、删除、分享只看它）、`contentRole`（读、保存、改名、复制）与 `accessVia`。新的操作先想清楚是结构性的还是内容的，在 `access-rules.ts` 里加权限位，矩阵加行。
- **可访问文档的两半**：`accessible({ spaceIds, grantsOf })`。按空间列出、转移、回收站只要空间那一半；"与我共享"只要授权那一半（按 `document_grants(user_id)` 驱动）；搜索两半都要，"凭授权命中"与行出自同一条语句，凭授权命中的结果不给文件夹。
- **分享的写入只经 workspace 的 `DocumentSharingService`**：锁顺序与锁下复核见 ADR-014；每把锁在 `documents/sharing-locks.test.ts` 有确定交错的用例。保存、改名、复制在文档行锁下重新判断授权，依赖分享写入对文档行取 `FOR UPDATE`。
- **收回写入权的"某人在这些文档上"**（`userDocuments`）：取消分享与降级调用；M3 接入租约时按 `coversWriter` 的语义收口。
- **前端**：分享对话框经同事选择与人名组件；"与我共享"与分享对话框的文案在各自的范围文件；确认框里成功之后的说明由 `run` 交回（`run` 的两条约定见 `confirm-dialog.tsx`）；内容会变化的说明用 `StatusRegion`。
- **测试的工具**：矩阵的世界（`permissions/matrix-world.ts`）摆世界共用一个连接，回调还没做完时不能再调 `query`（立即报错）；`tests/e2e/support/status-writes.ts` 记下状态区每一次写进去那一刻的样子（在不在无障碍树里、焦点交还了没有）。
- **已知的坑**：
  - WebKit 点按钮时不聚焦按钮：在分享对话框里用鼠标点"取消分享"，确认框关掉之后焦点回到分享对话框本身（不丢），用键盘时落在"已分享给"标题；
  - 模态弹窗打开时 Radix 只跳过那一刻已经在的、显式写了 `aria-live` 的元素，其余都在 aria-hidden 之下；
  - TanStack Query 的 `isPending` 要等通知（setTimeout）之后重新渲染才变，"进行中"的判断要同步时自己记（确认框的做法）；
  - 只在 Playwright 的 WebKit 上观察到重新加载之后不再请求失败过的分块（DEF-038），E2E 改在新开的页面里核对恢复。
