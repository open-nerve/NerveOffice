## 与设计的偏差

都已回写到 P2 设计、M2 总设计或 ADR。

- **新增 workspace 模块**（需求方确认，M2 总设计 §6.2 补充）：面向成员的空间接口与编排；spaces 只管数据与不变量，没有控制器。
- **实现中的细化**：改名的响应与成员页的页头用 `TeamSpace`；名称唯一由唯一索引兜住，创建与改名放进保存点；转移页的页头另加 `GET /api/admin/users/{id}`；确认的弹窗挪到 `features/confirmation`。
- **审查之后的修正**（`reviews/P2-审查报告.md`）：
  - 请求里的 UUID 统一转成小写（契约的 `uuidSchema`，审查 A1）：原来用大写的自己的 id 加入空间，审计会记成普通的添加成员；
  - 转移的目标不能是操作者自己的个人空间（403，审查 A7）；转移的响应是 `{transferred}`（审查 A5）；
  - 看不到的目标一律不取锁：管理接口先判断是团队空间再锁空间行，转移只锁来源空间里的文档（审查 A4）；
  - 三项已接受的取舍登记在 P2 设计 §7：进行中的保存与撤权不互斥（M3 收口）、名称唯一透露看不到的同名空间存在、转到自己是成员的团队空间之后看得到内容。
- **前端**：
  - 窄屏的导航用展开按钮（`aria-expanded`、`aria-controls`，CSS 显隐），不是设计原来写的 `details`；
  - 成员的接口函数与空间的放在一起（`features/spaces`），成员页与管理界面共用，随首屏加载（几百字节）；首屏 161.6 KiB；
  - 审查之后：先看错误再看数据（空间看不到了刷新导航、去掉缓存）；成员的角色每一行各自保存；按关键词选一项的通用组件（`KeywordPicker`），同事选择与团队空间选择共用；同事选择的标签是名词（"要添加的同事""接收文档的同事""目标团队空间"），怎么找写在输入框的提示里。

## 下一个 Phase 须知

- **有效权限只经 `DocumentAccessPolicy`**（documents 导出，ADR-014）：目标是文档或空间；规则在 `access-rules.ts`（纯函数），同一套规则给界面（`SpaceView.permissions`、`DocumentDetail.permissions`）与服务端（`requireSpaceContent`、`requireSpaceManagement`、`requireAccess`、`canEdit`）。服务不自己拼权限条件。
  - P3 的编辑器身份按 `DocumentDetail.permissions.canEdit` 回答（已按有效角色给出）。
  - P5 在 `EffectiveAccessPolicy` 里并上单独授权；矩阵加授权的行与列。
- **"可访问文档"的条件**只在 `documents.repository.ts` 的 `accessible(scope)`：列表、标题列表与转移都经它。P4 排除回收站、P5 并上授权只改这里；P5 扩展范围时，转移与标题列表仍传只含来源空间、不含授权的范围。
- **看不到与不存在一致**：执行同样的查询；需要锁的操作"先判断（不加锁）→ 加锁 → 锁下再判断"，看不到的目标不取锁。
- **锁的顺序**（ADR-007 的补充）：system-admins → 按登录名 → 账户行 → 重置或邀请行 → 限流计数 → 会话行 → 空间行（按 id）→ 成员行 → 文档行（按 id）→ 审计；新建文档的 `requestId` 锁在最前。空间的改动取 `FOR NO KEY UPDATE`，在空间里新建、转移的来源与目标取 `FOR SHARE`；文档行 `FOR UPDATE`。
- **收回写入权**：改动权限的事务里调用 `WriteAccessRevocation.revoke(scope, transaction)`（停用、移出、调整角色、归档已接上；P5 加"某人在某份文档"）。M2 的实现为空；M3 接入租约，并收口"进行中的保存与撤权不互斥"（P2 设计 §7，审查 A3）。
- **`writeEpoch`**：转移已递增；P4 的删除与跨空间移动在同一个事务里加一，空间内移动不加。
- **请求里的 id**：新的请求结构里的 UUID 一律用 contracts 的 `uuidSchema`（统一成小写）；响应里照旧 `z.uuid()`。
- **预期会失败的语句**：仓储放进 `inSavepoint`，返回业务结果、事务仍可继续（团队空间的名称，ADR-014）；集成测试可以经 `additionalModules` 挂测试探针，在一个事务里直接调用服务（`space-names.test.ts`）。
- **权限矩阵**：`tests/integration/src/permissions/matrix-world.ts`（`cellsOf`、`expectCell`、`freshDocument`、`freshSubject`、`freshSpace`）；每个 404 格子与"不存在"比较响应；409 目前只表示"目标空间已归档"。
- **前端**：
  - 页面先看错误、再看数据：`isMissingResource`（404 与地址里不合法的 id）显示"不存在或无权访问"，不管缓存里有没有旧数据；空间看不到了用 `useForgetMissingSpace` 刷新导航、去掉这个空间的缓存。页内的操作按访问权限被拒绝（`isAccessDenied`：403、404）时，让空间的查询失效重新请求（新建表格的 `onDenied`）。
  - 失败之后，确认的弹窗里要执行的内容已经过时（例如转移冲突、已被别人移出）：刷新之后关闭弹窗，在页面上说明，不让用户原样重发。
  - 状态提示（`role="status"`）的容器一直渲染，内容变化时往里填文字：与内容一起插入的状态部分读屏不播报。
  - 请求缓存：导航、空间页头、成员列表都在 `SPACES_QUERY_KEY`（`['spaces']`）之下，改动空间或成员之后让这个前缀失效；一个空间的文档列表用 `spaceDocumentsQueryKey(spaceId)`。
  - 按需加载的边界（lint 强制）：`features/admin`、`features/members` 只由 `app/routes.ts` 动态引用；`features/confirmation`、`features/colleagues` 只由这两个功能引用；弹窗文件 `shared/ui/dialog.tsx` 只由这两个功能与 `features/confirmation` 引用。P5 的分享页如果按需加载，照此加进 lint 的边界。
  - 按关键词选一项：`KeywordPicker`（`features/colleagues`），P5 选分享对象可以直接用 `ColleaguePicker`。
  - 确认的弹窗关闭之后，打开它的元素可能随操作消失：用 `returnFocus` 给出稳定的去处（例如带 `tabIndex={-1}` 的页标题）。
- **E2E**：团队空间与账户的名称带随机后缀；断言导航里"没有"某个空间之前，先等导航的团队空间一节加载完；按名称找链接加 `exact: true`（并行的用例会造出名字相近的空间）。
- **已知的坑**：
  - `z.uuid()` 接受大写并原样返回：请求里的 id 用 `uuidSchema`；
  - `FOR UPDATE` 带条件时，等到锁之后按新的行版本重新判断（转移"只锁来源空间里的文档"依赖它：被别人转走的行不再返回）；
  - 唯一索引的检查在对方事务没有提交时等待：两个连接的交错可以用"持有未提交的改名"构造；两个空间同时互换名称会在唯一索引上死锁（500），极罕见，接受；
  - TanStack Query 在重新请求失败时保留旧数据：先看错误、再看数据（审查 B1）；
  - lint 自测（`tools/src/lint/lint-rules.test.ts`）在 CI 上比本机慢十倍左右：新用例一条检查的代码段控制在十几段以内，本机超过 1 秒的要想想能不能拆开（M2-P2 合并之后 CI 上超时过一次，时限按实测放宽到 60 秒）。
