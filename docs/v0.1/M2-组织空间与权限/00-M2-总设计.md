# M2 组织、空间与权限：总设计

> 文档编号：00｜所属版本：v0.1｜状态：已评审（2026-09-28 审批通过），进行中｜日期：2026-09-28

## 1. 目标与范围

- **目标**：完整实现 00 号计划书 §5 的组织与权限模型。同事受邀加入，在个人空间与团队空间里整理文档，按空间角色与单独分享协作；越权访问一律被拒绝，而且不暴露对象是否存在。对应 00 号计划书 §13.2 的 M2 一行（按 r7 调整，见 §6.10）。
- **范围内**：
  1. 账户：邀请注册、修改密码、由管理员发起的重置密码、停用与启用、系统管理员的授予与取消。停用账户、重置密码时，撤销这个人的全部会话。
  2. 空间：团队空间的创建、改名、归档与恢复、全员可见；成员与空间角色；系统管理员把自己加入空间才能看内容。
  3. 文档管理：多级文件夹、重命名、移动（空间内与跨空间）、复制、回收站与恢复（30 天后自动清除）；新建文档到任意有新建权限的空间。
  4. 分享：单独分享给同事（查看者或编辑者）、"与我共享"、按名字搜索同事。
  5. 按标题搜索我能访问的文档。
  6. 系统管理：管理界面（账户、邀请、团队空间、审计查询）；本 M 的全部管理与授权操作都记审计。
  7. 查看者的只读加固（§6.5 的做法，从 M3 提前，见 §6.6）。
  8. 文档行上的 `writeEpoch` 与"收回写入权"的入口（§6.4；租约在 M3）。
- **范围外**（归属以 00 号计划书 §13.2 为准）：
  - 编辑租约与交接、阅读模式的进入与退出编辑、自动保存、完整的快照校验（M3）；
  - 本机发件箱与离线恢复（M4）；
  - 图片资源与复制时带上资源、历史版本、CSV（M5）；文字文档（M6）；
  - 监控告警、备份与恢复、压测（M7）；
  - v0.1 不做：匿名链接与公开发布、邮件通知、全文检索、文件夹的独立权限、编辑者分享（首发）、删除账户（只停用）。

### 2.1 启动讨论中已确认的决定（2026-09-28）

| # | 事项 | 决定 |
|---|---|---|
| 1 | 查看者的只读 | §6.5 的只读加固提前到 M2：编辑器身份的授权服务按文档权限回答，关掉本地权限点，拦截对本文档的改动与撤销重做，隐藏编辑入口。M3 复用这套机制，只加阅读模式与编辑之间的切换 |
| 2 | 邀请注册 | 管理员发邀请时填好登录名和显示名，生成一次性链接（7 天有效，可作废、可重发）；受邀人打开链接只设密码，可以改显示名 |
| 3 | 回收站 | 30 天后自动永久删除；空间管理员（个人空间是本人）可以提前永久删除；永久删除记审计 |
| 4 | 文件夹 | 多级，最多 10 层；删除文件夹时，里面的文档与子文件夹一起进回收站、一起恢复；编辑者只能删除"里面只有本人创建的文档"的文件夹，其余由空间管理员删除 |
| 5 | 审计查询 | M2 做系统管理员的审计查询页（按时间、操作者、动作、对象筛选，分页，只读）。审计不记文档正文，也不记文档标题 |
| 6 | 系统管理员 | 在管理界面授予与取消，始终至少保留一个有效的系统管理员；命令行只用于初始化首个管理员，以及运维为指定账户签发重置链接（唯一的系统管理员忘记密码时恢复，不授予任何角色） |
| 7 | 同事目录 | 分享与添加成员时按名字搜索同事：所有有效账户的显示名与登录名对彼此可见，停用的账户不出现 |
| 8 | `writeEpoch` | M2 在文档行上加这一列。删除与跨空间移动在同一个事务里递增；撤权、移出空间、停用账户都经同一个"收回写入权"的入口，M3 在这个入口里终止租约，并递增此人持有租约的文档的代次 |
| 9 | 补上的账户与文档功能 | §4.1 里 M1 没做的修改密码（要输入旧密码，改完退出其他登录）与重命名 |
| 10 | 会话 | 停用账户、重置密码时，撤销这个人的全部会话 |
| 11 | 按标题搜索 | 范围是我能访问的全部文档，标题包含关键词即可，不区分大小写；约 100 人的规模不做全文索引，也不加数据库扩展，M7 压测时复核 |
| 12 | 权限测试 | 一张权限矩阵表驱动集成测试，逐格覆盖 §5.3，作为 A03 的首次验证 |

本设计在此基础上的细化，随本总设计一起审批：
- **复制的权限**：能读源文档、在目标空间有新建权限即可复制。查看者也能把文档复制到自己的个人空间，因为内容本来就能复制粘贴。
- **移动的权限**：
  - 空间内移动需要编辑者及以上的空间角色。只有单独授权的人看不到空间的目录结构（§5.5），所以不能移动。
  - 跨空间移动对文档与文件夹都开放，需要源空间的空间管理员角色，以及在目标空间的新建权限。
  - 空间内移动不改变任何人的权限，不递增 `writeEpoch`。
- **归档空间**：所有人至多是查看者，包括被单独授权为编辑者的人。归档空间里的分享冻结：不能新增、调整或取消，要改先由系统管理员恢复空间（需求方 2026-10-01 确认，M2-P6 S2 复核）。
- **删除的权限**：只凭单独授权的人不能删除文档。删除与移动一样是空间里的结构性操作；回收站按空间划分，他看不到，删了也恢复不了（需求方 2026-10-01 确认，M2-P6 S2 复核）。
- **令牌放在链接的 `#` 之后**：邀请与重置链接的令牌不出现在请求行里，因而不进访问日志，也不随 Referer 外泄；页面读出令牌，放进请求体提交。重置链接 24 小时有效。
- **新增两个后端模块**：`admin` 负责系统管理的接口与跨模块编排，避免 users 与 auth 互相依赖；`jobs` 执行应用内的定时任务（§6.2）。

## 3. 用户故事

E2E 用例的标题以故事编号开头。浏览器 E2E 在本机的 Chromium、Chrome、WebKit 上通过，在 CI 上另加 Edge。US-M2-14 以集成测试的权限矩阵为主，E2E 覆盖关键路径。

| 编号 | 角色 | 故事 | 验收 |
|---|---|---|---|
| US-M2-01 | 系统管理员 | 邀请同事：填好登录名与显示名，生成一次性链接，经受控渠道发给本人；对方打开链接设置密码后可以登录 | 链接 7 天内有效、只能用一次，作废或过期之后打不开，提示明确；登录名已被占用或已有待接受的邀请时拒绝；接受时在同一个事务里建账户与个人空间，并记审计；令牌只存摘要，尝试有限流；未登录也能打开邀请页，页面只显示登录名与显示名 |
| US-M2-02 | 成员 | 修改自己的密码 | 必须输入旧密码；新密码符合强度规则；改完之后，本人在其他地方的登录全部失效，当前页面保持登录；记审计 |
| US-M2-03 | 系统管理员 | 为忘记密码的同事生成重置链接 | 生成时撤销这个人的全部会话；链接 24 小时内有效、只能用一次；设置新密码后可以登录；记审计 |
| US-M2-04 | 系统管理员 | 停用与启用账户；设置或取消系统管理员 | 停用后，此人不能登录，已打开的页面下一次请求就被要求重新登录；启用后恢复；始终至少保留一个有效的系统管理员；停用者个人空间里的文档，由系统管理员转移到其他人的个人空间或某个团队空间，转移时只看得到标题；都记审计 |
| US-M2-05 | 系统管理员 | 创建团队空间并指定空间管理员；设为全员可见；归档与恢复 | 只有系统管理员能做；全员可见时，所有有效账户都能以查看者的身份看到这个空间；归档后只读，可以恢复；系统管理员要看某个团队空间的内容，必须先把自己加入这个空间（记审计），个人空间的内容对他始终不可见。例外：全员可见的空间所有有效账户都是查看者，系统管理员也在其中；打开全员可见本身记审计、对全员可见，确认框写明"包括你自己"（需求方 2026-10-01 确认，M2-P6 S2 复核） |
| US-M2-06 | 空间管理员 | 管理成员与空间角色 | 按名字搜索同事并添加，调整角色，移出；被移出的人立即失去空间角色带来的权限，单独授权保留；记审计 |
| US-M2-07 | 成员 | 在有权的空间里整理文档：新建表格与文件夹、重命名、移动 | 左侧导航列出我的空间、我所在的团队空间与全员可见空间、与我共享；文件夹最多 10 层；空间内移动与跨空间移动按 §2.1 的权限；没有权限的操作在界面上不出现，直接调接口被拒绝 |
| US-M2-08 | 成员 | 复制文档 | 能读源文档、在目标空间有新建权限即可复制；副本是一份新文档，快照原样复制（值、公式、格式、批注、条件格式、数据验证等），打开后与源文档一致；两份各自编辑、保存，互不影响；单独授权不随副本复制 |
| US-M2-09 | 成员 | 删除与恢复 | 删除的文档或文件夹（连同里面的内容）进入所在空间的回收站；删除者与空间管理员可以恢复到原位置；编辑者只能删除本人创建的文档，以及里面只有本人创建的文档的文件夹；空间管理员可以永久删除；30 天后自动永久删除；回收站里的文档打不开，也不出现在列表、搜索与"与我共享"里 |
| US-M2-10 | 空间管理员或个人空间的所有者 | 把文档单独分享给同事（查看者或编辑者），调整或取消 | 分享对话框里按名字搜索同事；对方在"与我共享"里看到这份文档，能看到所属空间的名称，看不到空间的目录结构；取消之后对方立即不能访问；编辑者不能分享；记审计 |
| US-M2-11 | 查看者 | 打开有阅读权限的表格，只能看不能改 | 界面上没有编辑入口；M0 列出的表格编辑入口全部无效，撤销与重做无效；可以选中与复制内容；服务端拒绝保存；归档空间里的文档同样只读 |
| US-M2-12 | 成员 | 按标题搜索我能访问的文档 | 结果只含我能访问的文档（个人空间、我所在的团队空间、全员可见空间、与我共享），不含回收站里的文档；标题包含关键词即可，不区分大小写 |
| US-M2-13 | 系统管理员 | 查询审计事件 | 按时间、操作者、动作、对象筛选，分页；只有系统管理员能看；审计里没有文档正文与标题 |
| US-M2-14 | 安全负责人 | 越权访问一律被拒绝，而且不暴露对象是否存在 | §5.3 权限矩阵的每一格都有测试；无权访问与访问不存在的对象，接口响应、页面与耗时一致（耗时一致按"响应相同、执行的 SQL 语句序列相同"验证，这是耗时一致的充分条件，结果确定、不受机器快慢影响；M7 压测时抽查耗时。需求方 2026-10-01 确认）；列表、搜索、计数、"与我共享"与回收站里不出现无权的文档；停用、移出空间、取消分享之后，下一次请求即生效 |

## 4. 负责的上线门槛

| 门槛 | 本 M 的验证方式 |

## 5. Phase 规划

## 6. 架构影响

### 6.1 有效权限与授权

**有效权限**：取下面两项中较高的一个（§5.2），角色从低到高为查看者、编辑者、空间管理员（个人空间的所有者相当于空间管理员）：
1. 用户在文档所在空间的空间角色。全员可见的空间，所有有效账户至少是查看者。
2. 用户在这份文档上的单独授权。

另有三条限制：
- 空间归档：所有人至多是查看者，包括被单独授权为编辑者的人。
- 文档在回收站：只允许回收站的操作（恢复、永久删除），其余一律当作不存在。
- 账户停用：一切失效。会话已经撤销，守卫对每个请求检查账户状态。

**系统管理员**：系统角色本身不带来任何内容权限（§5.2）。要看团队空间的内容，先把自己加入这个空间，这个操作记审计。个人空间的内容对他始终不可见；转移停用者的文档时只看得到标题。

**操作权限**：按 §5.3，加上 §2.1 的细化：

| 操作 | 条件 |
|---|---|
| 阅读 | 有效权限至少是查看者 |
| 保存、重命名 | 有效权限至少是编辑者 |
| 在空间里新建文档与文件夹 | 空间角色至少是编辑者（单独授权不算） |
| 空间内移动 | 空间角色至少是编辑者 |
| 跨空间移动（文档或文件夹） | 源空间的空间管理员，并且在目标空间有新建权限 |
| 复制 | 能读源文档，并且在目标空间有新建权限 |
| 删除 | 空间管理员可以删除任何文档与文件夹；编辑者只能删除本人创建的文档，以及里面只有本人创建的文档的文件夹 |
| 恢复 | 删除者与空间管理员 |
| 永久删除 | 空间管理员 |
| 分享、调整单独授权 | 空间管理员（首发编辑者不能分享） |
| 管理成员与空间角色 | 空间管理员、系统管理员 |
| 创建团队空间、改名、归档与恢复、设置全员可见 | 系统管理员（改名另允许空间管理员） |
| 账户、邀请、重置密码、系统管理员的授予、审计查询 | 系统管理员 |

**实现约束**：
- 权限只经一个入口计算：`DocumentAccessPolicy` 扩展为有效权限，目标可以是文档（空间加文档）或空间；服务不自己拼权限条件。
- "我能访问的文档"由一个查询给出：列表、搜索、"与我共享"与计数都用它，不各写各的过滤条件。
- 无权与不存在一律 `NOT_FOUND`，并且耗时对齐（沿用 M1 的做法，扩展到新的目标类型）。
- 系统管理的接口要求系统管理员，逐请求在服务端检查；前端的隐藏只是体验。

### 6.2 后端模块

| 模块 | M2 的职责 |
|---|---|
| users | 账户的停用、启用与系统角色；同事目录 |
| auth | 按人撤销会话（撤销原因扩充）；修改密码；邀请与重置密码的一次性令牌：签发、接受邀请（建账户与个人空间）、用重置链接设置新密码、尝试限流（与登录限流同一套机制）。这些流程既要读写账户又要撤销会话，放在已经依赖 users 的 auth 里，不产生循环依赖 |
| spaces | 团队空间（创建、改名、归档与恢复、全员可见）；成员与空间角色。只管数据与不变量，没有控制器：users、auth、documents 都依赖它，它不能反过来依赖它们（P2 设计 §3.1） |
| documents | 文档、文件夹、回收站、复制、单独授权、按标题搜索；有效权限与"可访问文档"的查询；`writeEpoch` 与"收回写入权"的入口 |
| workspace（新，P2 补充） | 面向成员的空间接口与编排：我能看到的空间、空间页头、成员的查看与管理、改名。成员的变更要在一个事务里经有效权限授权、改 spaces 的数据、收回写入权、记审计，所以放在 documents 之上 |
| admin（新） | 系统管理的接口与跨模块的编排：账户管理、邀请与重置链接的签发（调用 auth）、团队空间管理、停用者文档的转移、审计查询。停用账户要同时改账户状态、撤销会话、收回写入权，由它在一个事务里编排 |
| jobs（新） | 应用内定时任务：注册、按间隔执行、用 PG 的 advisory lock 防止重复执行（§9.3）、失败记日志。M2 只有回收站的清理 |
| audit | 新的动作与对象类型；按条件查询（只给 admin 模块用） |

其余模块（config、logging、security、database、health、web-hosting）不变。模块之间只经公开入口依赖，依赖图无环，由 lint 强制（ADR-003）。

### 6.3 数据模型

只做加法（ADR-005）。M1 的存量数据：文档都在个人空间的根目录，`writeEpoch` 为 0。

| 表 | M2 的加法 |
|---|---|
| users | 状态加"停用" |
| invitations（新） | 登录名、显示名、令牌摘要、签发人、到期时间（7 天）、接受时间与建成的账户、作废时间；同一登录名最多一条待接受的邀请 |
| password_resets（新） | 账户、令牌摘要、签发人、到期时间（24 小时）、使用时间、作废时间 |
| auth_sessions | 撤销原因加：停用、修改密码、重置密码 |
| spaces | 类型加"团队"；状态加"归档"；创建人 |
| space_members（新） | 空间、用户、空间角色（管理员、编辑者、查看者）；（空间，用户）唯一 |
| folders（新） | 所属空间、父文件夹、名称、创建者、状态（正常、回收站）；最多 10 层 |
| documents | 所属文件夹（空表示空间的根目录）、`writeEpoch`、状态加"回收站"、所属的删除单元 |
| trash_entries（新） | 删除单元：一份文档，或一个文件夹连同里面的内容；所属空间、删除者、删除时间、原位置、到期时间 |
| document_grants（新） | 文档、用户、角色（查看者、编辑者）、授权人；（文档，用户）唯一；移动文档、移出空间都不删除 |
| audit_events | 新的动作与对象类型：邀请、重置密码、账户、团队空间、成员、文件夹、文档（重命名、移动、复制、删除、恢复、永久删除）、单独授权、系统管理员加入空间 |

### 6.5 前端

- **平台页面**（单页应用，沿用 React Router、TanStack Query 与 shadcn/ui）：
  - 左侧导航：我的空间、我所在的团队空间与全员可见空间、与我共享；顶栏：按标题搜索、账户菜单（修改密码、退出），系统管理员另有"管理"入口。
  - 空间页：面包屑，文件夹与文档的列表，操作（新建表格、新建文件夹、重命名、移动、复制、删除、分享），回收站与成员的入口。
  - 与我共享、搜索结果、回收站。
  - 管理界面：账户（邀请、停用与启用、重置密码、系统管理员）、邀请、团队空间、审计查询。
  - 公开页面：接受邀请、重置密码。令牌在链接的 `#` 之后，页面读出后放进请求体。
- **编辑器页**：查看者与归档空间里的文档只读（§6.6）；页头返回到文档所在的空间，或"与我共享"；文档被删除、移走或失去权限之后，下一次请求时给出明确提示。
- 新页面都有加载、空、失败、无权限的状态；没有权限的操作在界面上不出现。

### 6.6 编辑器：查看者的只读加固

按 00 号计划书 §6.5 与 M0 的实测，在编辑器适配层实现：
- **授权服务**：编辑器身份的 `IAuthzIoService`（ADR-009）改为按文档权限回答，不再全部允许。SDK 在用户变化时按它重新初始化权限点，所以只读不会被改回可编辑（M1 独立复验 N1）。
- **本地权限点**：工作簿级 `setEditable(false)`（P3 实现时由授权服务的回答取代，见上一条与 ADR-015），再用 `IPermissionService` 在本地关掉工作表的权限点，保留"查看"与"复制"；不创建保护规则，不写入保护类资源。
- **mutation 防火墙**：在 `BeforeCommandExecute` 里取消作用于本文档（或没有 `unitId`）的非本地 mutation。只拦本文档：单元格编辑器往内部文档单元写的内容不拦（§6.5）。
- **撤销与重做**：在命令执行前拦截，并清空撤销栈（`IUndoRedoService.clearUndoRedo` 经注入器获取，登记为内部 API）。
- **界面**：M2 的查看者一开始就以只读创建编辑器，用静态配置关掉工具栏、右键菜单与底栏菜单，隐藏新增工作表按钮（插件档案 v1 §5.2）。原地切换在 M3 随阅读模式实现。
- **测试**：M0 的表格编辑入口清单逐项写成 E2E（本机三个浏览器，CI 另加 Edge），并覆盖公式 Worker 模式；复制仍然可用；进入只读不产生 mutation。
- 服务端照旧拒绝查看者的保存（`PERMISSION_DENIED`），前端的只读只是体验层（§6.5）。

### 6.7 一次性令牌（邀请与重置密码）

- 令牌由安全随机数生成，服务端只存摘要；链接只在签发时显示一次。
- 令牌放在链接的 `#` 之后：不出现在请求行、访问日志与 Referer 里。
- 单次有效：接受或使用时，在同一个事务里原子地标记，并完成建账户或改密码。
- 有时限：邀请 7 天，重置 24 小时；可以作废，重发即作废旧的、签发新的。
- 尝试限流：按客户端地址，机制同登录限流；失败的尝试记审计。
- 日志与审计不记令牌与密码（§11.5）。

### 6.8 回收站与定时任务

- **删除单元**：删除一份文档或一个文件夹时，生成一个删除单元，文件夹里的全部内容随它一起进回收站、一起恢复。回收站按空间划分。
- **恢复**：回到原位置；原来的父文件夹已经不在（被永久删除，或者另外进了回收站）时，回到空间的根目录。同一文件夹里允许同名。
- **永久删除**：删除文档行及其内容、修订记录与单独授权，以及文件夹行；记审计。自动清除时，审计的操作者记为系统。
- **定时清理**：`jobs` 模块定期扫描到期的删除单元，逐个在短事务里永久删除；用 advisory lock 防止将来多实例时重复执行（§9.3）。测试用可控的时钟。
- **与 `writeEpoch` 的关系**：删除与跨空间移动在同一个事务里递增受影响文档的代次。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 越权：权限计算有遗漏，或者列表、搜索、计数泄漏无权的文档 | 权限只经一个入口计算，"可访问文档"只有一个查询；矩阵驱动的集成测试逐格覆盖；"无权与不存在一致"的对照；合并前的对抗评审 |
| 只读加固依赖内部 API（`IPermissionService`、`IUndoRedoService`、命令拦截），SDK 升级可能改变行为 | 集中在编辑器适配层并登记（ADR-010）；M0 的编辑入口清单逐项写成 E2E，升级时回归 |
| 文件夹与回收站的级联复杂：恢复时原位置不在、跨空间移动文件夹、删除单元里混着别人的文档 | 以删除单元为粒度；恢复与移动的规则在 P4 设计里写全，并逐条测试；编辑者删除文件夹的条件在删除时的事务里检查 |
| 一次性链接泄漏 | 单次、时限、只存摘要、限流；令牌在 `#` 之后，不进日志与 Referer；可以作废；签发与使用都记审计 |
| 审计泄漏文档标题 | 审计的 `details` 按严格的结构校验，不含标题与正文；查询页只给系统管理员 |
| 系统管理员被全部取消或停用，没人能管理 | 授予、取消与停用在同一把锁下检查"至少保留一个有效的系统管理员"；命令行的初始化只在没有管理员时可用 |
| 定时清理在单实例内执行，将来多实例会重复执行 | advisory lock；每个删除单元一个短事务，中途失败不影响其他单元；失败记日志，M7 接入告警 |
| 管理与权限界面的工作量大 | 复用 shadcn/ui 的组件；按故事拆 E2E；界面在各 Phase 的设计里画线框 |
| 按权限过滤的列表与搜索的性能 | 按空间、成员、授权建索引；约 100 人的规模下足够，M7 压测时复核 |
