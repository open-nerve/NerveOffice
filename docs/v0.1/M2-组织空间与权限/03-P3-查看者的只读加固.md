# M2-P3 查看者的只读加固：架构设计与实施规划

> 状态：进行中｜日期：2026-09-29｜基于代码版本：`9a10a62`

## 1. 目标与范围

对应 M2 总设计 §5 的 P3 一行与 §6.6：查看者与归档空间里的文档真正只读（00 号计划书 §6.5，从 M3 提前）。用户故事 US-M2-11：打开有阅读权限的表格，只能看不能改——界面上没有编辑入口；M0 列出的表格编辑入口全部无效，撤销与重做无效；可以选中与复制内容；服务端拒绝保存；归档空间里的文档同样只读。

本 Phase 交付：
1. 编辑器身份的授权服务按文档权限回答（ADR-009 的延伸）。
2. 只读的加固：工作表的本地权限点、mutation 防火墙、撤销与重做的拦截与清空撤销栈。
3. 只读时的界面：一开始就以只读创建，用静态配置关掉工具栏、右键菜单与底栏菜单，隐藏新增工作表按钮（插件档案 v1 §5.2）。
4. 编辑器页按文档权限以只读或可编辑创建编辑器。
5. 内部 API 登记与 lint 的受限符号。
6. E2E：M0 的 28 个表格编辑入口逐项（本机三个浏览器，CI 另加 Edge；公式一直在 Worker 里），界面的隐藏，复制，进入只读不产生 mutation、不写保护类资源，归档空间；US-M2-11 改为 `active`。

不在本 Phase：
- 阅读模式与编辑之间的原地切换、编辑租约（M3）。本 Phase 的机制按 M3 能复用的方式实现（§3.3），但不做运行时切换。
- 文字文档：v0.1 目前只有表格的编辑器，文字文档的只读随文字文档一起做（`setReadOnly()`，计划书 §6.5）。
- 服务端没有改动：`DocumentDetail.permissions.canEdit` 已按有效角色给出（P2），查看者的保存一律 `PERMISSION_DENIED`（ADR-011）。

## 2. 现状

- **编辑器页**（`features/sheet-editor/editor-page.ts`）：先确认会话，再并行取元数据（带 `permissions.canEdit`）与内容，最后创建编辑器。`canEdit` 为假时：
  - 就绪之后调 `setEditable(false)`；不建保存状态机（没有保存按钮，Ctrl/Cmd+S 不做事，离开不提示）；页头显示"只能查看"。
  - 没有防火墙，没有撤销拦截，界面照常（工具栏、右键菜单、底栏菜单、新增工作表按钮都在）。
  - `setEditable(false)` 只是暂时的：SDK 在 Ready 与用户变化时按授权服务重设工作簿的权限点（M1 独立复验 N1），编辑器身份一律允许。
- **适配层**（`editor/`）：
  - `createSheetEditor({ container, snapshot })` 是唯一入口，没有只读参数；创建顺序见 `sheet-editor.ts` 的文件开头。
  - 身份：`AllowAllAuthzIoService` 对每个动作都允许，权限数据的写入一律拒绝，不调用 `setCurrentUser`（ADR-009）。
  - 入口守卫（M5 之前不开放的图片与超链接命令）与变更检测，都在创建工作簿之前挂在 Facade 的 `BeforeCommandExecute`、`CommandExecuted` 上。
  - 变更检测的判定是纯函数（`change-classifier.ts`）：本文档（或没有 `unitId`）的 mutation，不带 `onlyLocal`、`fromCollab`、`fromChangeset`、`fromFormula`，不在排除名单里。
  - 内部 API 登记 10 项；`IPermissionService`、`IUndoRedoService`、工作表的权限点都还没有登记。
- **E2E**：跑测试构建（生产构建加 CSP 探针页）；没有页面钩子，画布上的内容读不出来；与只读相关的用例只断言"只能查看"。
- **M0 的结论**（M0-P3 报告 §5，插件档案 v1 §5.2）：本地权限点加 mutation 防火墙，表格 28 个入口在三个浏览器、含公式 Worker 模式全部被拦住；只靠权限点漏掉 9 个；`FWorksheetPermission.setReadOnly()` 不可用；单元格编辑器会往内部文档单元写内容，防火墙只拦本文档。

## 3. 设计

### 3.1 模块划分与依赖方向

改动都在前端，集中在编辑器适配层（ADR-010），编辑器页只传入"能不能编辑"：

```text
features/sheet-editor（编辑器页）── createSheetEditor({ container, snapshot, access }) ──► editor（适配层）
                                                                                         ├─ identity/     授权服务按 access 回答
                                                                                         ├─ read-only/    只读守卫：工作表权限点、防火墙、撤销与重做
                                                                                         ├─ profile/      按 access 的界面配置
                                                                                         ├─ internal-api/ 新登记的内部符号
                                                                                         └─ testing/      E2E 的探针（只在测试构建里）
```

- `access` 是 `'edit' | 'read'`，由编辑器页按 `DocumentDetail.permissions.canEdit` 决定。适配层不知道"查看者""归档"这些业务概念，只知道这份文档这次以什么方式打开。
- 去掉 `SheetEditor.setEditable`：只读在创建时决定，不再有"就绪之后再设"的第二条路。M3 的原地切换另加运行时的接口（§3.3 的机制可以复用）。

### 3.2 编辑器身份：授权服务按文档权限回答

`AllowAllAuthzIoService` 改为按创建时给定的 `access` 回答（改名为 `EditorAuthzIoService`，经 `useFactory` 或 `useValue` 注入）：
- `access = 'edit'`：每个动作都允许（与现在相同）。
- `access = 'read'`：只允许"查看"与"复制"，其余动作一律不允许。这两个动作取自 SDK 自己的权限点类（`WorkbookViewPermission`、`WorkbookCopyPermission` 的 `subType`），与只读守卫保留的工作表权限点是同一组定义；动作的枚举 `UnitAction` 在 `@univerjs/protocol` 里，不为它新增依赖。
  - 查看是打开的前提；复制是 US-M2-11 的"可以选中与复制内容"（复制要求工作簿与工作表的复制权限点都为真，M0-P3 审查 R6）。
  - 其余动作都会改动文档或权限（编辑、增删改工作表、排序、筛选、插入超链接、浮动图片……），或者本平台没有（打印、导出、历史记录）。
- SDK 在 Ready 与用户变化时按 `allowed()` 的结果设置工作簿的 22 个权限点：只读的文档设出来就是只读的，不会被改回可编辑（M1 独立复验 N1 的根因）。每个动作都给出明确的布尔值（SDK 不处理 undefined）。
- 不变的：当前用户保持匿名，不调用 `setCurrentUser`；权限数据的写入一律拒绝（保护规则、协作者）；本地授权服务不构造，`SHEET_AuthzIoMockService_PLUGIN` 不出现。
- 这是 ADR-009 的延伸：原来写的"只读由平台决定：`setEditable(false)`"改为"平台在创建编辑器时给出这份文档能不能编辑，授权服务按它回答"。仍然由平台决定，身份仍不是真实用户（ADR-015 记录）。

### 3.3 只读守卫

`installReadOnlyGuard(univer, univerAPI, classifierConfig)`，只在 `access = 'read'` 时装上；`classifierConfig`（本文档的 unitId 与排除名单）与变更检测用同一份。返回的句柄有 `applyWorksheetPoints()`、`applyRenderedGuards()`、`clearUndoStack()` 与 `dispose()`（M3 的原地切换复用这几个入口）。调用的顺序是：创建工作簿之前装上（防火墙与撤销拦截在打开的过程中也生效）→ 工作簿创建之后 `applyWorksheetPoints` → 就绪时 `applyRenderedGuards`、`clearUndoStack`。`applyRenderedGuards` 这一步是渲染模块到位之后才能做的两件事（冻结线的拦截、编辑栏的放开，见第 7、8 条）：渲染控制器到 Rendered 才注册，装守卫时取不到；就绪之前的输入本来由交互屏障拦住。设计时是前三件事，S3 的 E2E 与审查之后补上后面五件：

1. **mutation 防火墙**：在创建工作簿之前挂在 `BeforeCommandExecute` 上（与入口守卫一样，打开文档的过程中也生效）。
   - 取消的条件与变更检测的判定相同：`classifyCommand(record) === 'change'`，即本文档（或没有 `unitId`）的 mutation，不带 `onlyLocal` 等标记，不在排除名单里。
   - 这样有一条不变量："只读时，变更检测会认作修改的一律取消"；公式的结果（Worker 同步回来，带 `onlyLocal`）照常显示；单元格编辑器写内部文档单元（其他单元）不拦（M0-P3 审查 R2）；排除名单里的 `sheet.operation.clear-drawing-transformer`（类型是 MUTATION，只清除界面上的图片变换框）不拦。
   - 比 M0 的条件（只看 `onlyLocal`）多放过 `fromCollab`、`fromChangeset`、`fromFormula` 与排除名单：前两个在本平台不出现（没有协同），排除名单只清除界面状态；`fromFormula` 的嵌套 mutation 会改单元格的公式（M2-P6 第 4 片复核订正：原来写"都不改文档"），放行它安全靠的是先后：Facade 的执行前监听在 `createWorkbook` 之前注册（由入口守卫占住），排在 SDK 的 `UpdateFormulaController` 之前，订阅者不能减到零（ADR-015 决策第 1 条）。
   - 被取消的命令不执行、不进撤销栈：Facade 抛出的 `CanceledError` 由命令服务接住，调用方拿到 false（core 的 `command.service.ts:467-474`），不是页面错误。少数 Facade 方法在取消之后仍去取结果，会在调用方抛错（M0 见过的 `insertSheet` 抛 TypeError），同样不是页面错误。
   - SDK 的一个问题（UR-005）：命令被取消、或者被 SDK 的权限检查拦下时，命令执行栈里的那一项不弹出，之后不在命令里执行的 mutation 会带上它的 id 作为触发来源（`trigger`）。SDK 里读 `trigger` 的地方有好几处（例如公式的脏区判断遇到 `set-style` 一类的触发来源就不标脏，`sheets-formula` 的 active-dirty.controller.ts:82-84），只读时被权限检查拦下的命令（例如加粗）会留下这样的记录；只读时本来不改文档，没有可见的影响，M3 的原地切换在只读之后回到编辑时要评估（审查 A5）。
2. **撤销与重做**：订阅 Facade 的 `BeforeUndo`、`BeforeRedo` 并取消（重做直接重放 mutation，绕过权限检查）；就绪时经注入器取 `IUndoRedoService`，`clearUndoRedo(unitId)` 清空撤销栈。本 Phase 以只读创建，撤销栈本来就空；清空是给 M3 的原地切换用的同一个入口。
3. **工作表的本地权限点**：工作簿创建之后（SDK 在创建工作簿时为每张表加入权限点，初值允许），对每张工作表（含隐藏的）把"查看"与"复制"以外的权限点设为不允许（`getAllWorksheetPermissionPoint()` 与 `getAllWorksheetPermissionPointByPointPanel()` 去重，共 16 个；权限点不存在就先加上）。
   - 工作表的权限点只有存在保护规则时才经授权服务设置，没有规则的表不会被 SDK 改回去；用户变化时 SDK 重新加入权限点，沿用原来的值。
   - 不创建保护规则，不写保护类资源；不用 `FWorksheetPermission.setReadOnly()`（M0-P3 报告 §5.3）。
   - 只读时新表建不出来（防火墙取消 `insert-sheet`），所以只在创建时设一次。

4. **图片不可编辑**：设完工作表权限点之后，把图片设为不可编辑（`@univerjs/drawing` 的 `IDrawingManagerService.setDrawingEditable(false)`）。drawing-ui 画图片时按这个服务的标志决定挂不挂变换框，它默认为真，SDK 不改它；sheets-drawing-ui 的权限控制器设的是表格图片服务上的同名标志，渲染不读（S3 的 E2E 发现：拖动图片被拦下之后，图片停在拖到的位置；修复时实测）。
5. **替换、"搜索功能"面板与快速求和不开放**（后两个是 M2-P6 第 4 片复核补上的）：执行前取消打开替换面板的操作（`ui.operation.open-replace-dialog`，查找面板的"高级查找"与替换的快捷键都走它）、打开"搜索功能"面板（`ui.operation.open-feature-search`，列出的都是编辑功能）与快速求和（`formula-ui.operation.insert-function`，否则编辑栏会显示文档里没有的公式）。查找照常；代价是只读时没有高级查找的选项（查找顺序、查找范围、匹配方式），而且查找面板上"高级查找"的链接仍显示着、点了没有反应（隐藏它要改 SDK 的界面元素，得不偿失）。
6. **批注浮层只读**：SDK 的批注浮层总是可编辑的文本框（没有只读的开关，打开时还会被程序聚焦），写回虽然被防火墙取消，界面上却能输入。只读时给它的文本框加上 `readOnly`，并且不能拖动改大小（观察 `document.body` 里出现的 `textarea[data-u-comp="note-textarea"]`）：文字照常显示、可以选中复制。
7. **编辑栏点不进去**：工作簿不可编辑、又没有保护规则时，点编辑栏只聚焦编辑栏的内部编辑器，并把"正在编辑栏里""编辑器已激活"的上下文设为真；能复位它们的只有单元格编辑器关闭那一条路径，只读时走不到，之后查找等表格快捷键失效（SDK 在这条路径上的缺陷，S3 的 E2E 发现）。只读时在页面上（捕获阶段）拦下落在编辑框与取消、确认、插入函数按钮上的指针事件，编辑栏照常显示当前单元格的内容；名称框与展开的箭头不拦。只拦按下还不够：在别处按下、在编辑框上松开，编辑框自己的松开处理照样会聚焦它（审查 A1）；所以另外订阅编辑器服务的聚焦，焦点落到编辑栏的编辑器时放开它并复位那几个上下文，不管从哪条路径进来都复位。放开要排一个微任务再做，不能同步做：SDK 聚焦之后还会把 DOM 的焦点移进编辑框、设光标，React 提交之后又把"编辑器已激活"置一次真，同步放开会被这些操作覆盖（实测：同步放开的构建里，E2E 仍然看到编辑框有焦点）。守卫装上时若已经聚焦在编辑栏（M3 的原地切换），立即放开。
8. **冻结线拖不动**：sheets-ui 1.0.1 没有注册冻结线的权限拦截（它定义了却没有调用），只读时冻结线照样能拖，拖完界面停在拖到的位置（审查 B2）。只读时补上：在冻结线的权限检查上注册返回不允许的拦截器。冻结区域里的行列分隔线仍能拖出"不能调整"的提示（SDK 在冻结区域与非冻结区域的处理不一致），数据不变，由 E2E 断言。

不采用 sheets-ui 的 `disableEdit`（设计初稿的结论不变，修复时实测）：它让单元格编辑器不渲染，点单元格之后键盘的焦点没有着落，复制与方向键都失效（US-M2-11 要求可以复制）；编辑框的外层还写死了 `pointer-events: auto`，编辑栏照样点得进去，修不好上面第 7 条。

### 3.4 只读时的界面

按 `access` 组合插件的配置（插件档案 v1 §5.2 的"销毁重建"一栏）：
- `UniverUIPlugin`：`toolbar: false`、`contextMenu: false`。编辑栏（`header`）保留：它显示当前单元格的内容，点不进去（§3.3 第 7 条）。
- `UniverSheetsUIPlugin`：`footer.menus: false`（底栏的网格线开关会写进快照）、`footer.addSheetButtonConfig.show: false`。
- 菜单再隐藏工作表标签的 5 项（删除、复制、改名、标签颜色、隐藏）：右键菜单已经关掉，这 5 项隐藏是档案的约定，防止以后打开右键菜单时漏掉。
- 两种模式都隐藏的保护类与背景图片菜单不变。
- 权限的提示改写成只读的说法：平台不用 SDK 的保护（入口隐藏、写入被拒绝），"该范围已被保护……请联系创建者"这类提示只会在只读时出现，语言包里统一改成"这份文档只能查看，不能……"（S3 的 E2E 发现原来的措辞会误导查看者）。SDK 的 `mergeLocales` 只合并第一层，覆盖用深合并，键名写错直接报错。

### 3.5 编辑器页

- `createEditor({ container, snapshot, access: detail.permissions.canEdit ? 'edit' : 'read' })`，去掉就绪之后的 `setEditable(false)`。
- 其余不变：只读时不建保存状态机、页头显示"只能查看"、交互屏障在就绪之前照常拦住输入。

### 3.6 内部 API 与 lint

新登记（`internal-api/`，每项带用途、证据与回归用例）：
- `IPermissionService`（core）：设工作表的本地权限点；
- `IUndoRedoService`（core）：`clearUndoRedo`；
- 权限点的清单与类（sheets）：`getAllWorksheetPermissionPoint`、`getAllWorksheetPermissionPointByPointPanel`、`WorksheetViewPermission`、`WorksheetCopyPermission`（只读守卫保留的工作表权限点），`WorkbookViewPermission`、`WorkbookCopyPermission`（授权服务允许的动作）；
- `IDrawingManagerService`（drawing）：图片设为不可编辑；
- SDK 的 DOM 标记（`internal-api/dom-markers.ts`）：批注浮层的文本框、编辑栏的编辑框与按钮。它们不是公开 API，版本之间可能改名，由 E2E 回归。
- 审查之后又加 6 项：`IEditorService`（docs-ui，认出焦点落在编辑栏的编辑器上、放开它）、`IContextService`、`FOCUSING_FX_BAR_EDITOR` 与 `DOCS_FORMULA_BAR_EDITOR_UNIT_ID_KEY`（都在 core：上下文服务、"编辑栏正被聚焦"这个键、编辑栏内部编辑器的单元 id）、`IRenderManagerService`（engine-render）与 `HeaderFreezeRenderController`（sheets-ui，注册冻结线的权限拦截）。M2-P3 共 17 项。
- 哪些算"界面的包"以登记表的 `origin` 为准（docs-ui、engine-render、sheets-ui、ui、design 这些）：只有它们进 `ui.ts`，core、sheets、drawing 仍进 `index.ts`。

出口分两个：界面的包（docs-ui、engine-render、sheets-ui）放在 `internal-api/ui.ts`，只由主线程引用；`index.ts` 不从界面的包再导出。原因是公式 Worker 也引用 `index.ts`，而 Univer 的包没有声明 `sideEffects`，再导出会把整个界面包打进 Worker（实测 1502.7 KiB，门禁 `budgets` 的预算是 800 KiB；拆开之后 677.4 KiB）。登记表的自测核对两个出口与登记一一对应，并核对 `index.ts` 不从界面的包再导出。

lint 的受限符号同步补上，自测补正反例。

### 3.7 E2E 的探针（只在测试构建里）

M0 的 28 个入口里，21 个是直接调 Facade 的（筛选、排序、增删改工作表、图片、合并、条件格式……）；只读时它们在界面上没有入口，但防火墙必须拦住它们（SDK 升级可能带来新的入口）。另外画布上的内容读不出来，"改动被拦住"要比较内存里的快照。所以测试构建里放一个探针：
- `editor/testing/e2e-probe.ts`：`window.__nerveEditorProbe = { univerAPI, snapshot(), 命令日志 }`。命令日志记下每条命令的执行前（含是否被取消）与执行后，E2E 以它作确定的同步点；探针在就绪之后才订阅，只看得到在它之前订阅的监听者设下的取消（M3 的原地切换若在就绪之后装只读守卫，要注意这个前提，审查 B12）。
- `editor/testing/probe-facades.ts`：补上编辑器没有引用的插件 Facade（筛选、排序、图片、条件格式、数据验证、超链接、批注、查找替换），往 Facade 的类上加方法，另有一个 FWorkbook 的初始化钩子（数据验证的 Facade，惰性的 getter；M2-P6 第 4 片复核订正），就绪之后才加载，不改变编辑器的行为。
- 探针（M2-P6 第 4 片复核之后）另有 `shortcuts()`（SDK 当前注册的快捷键，经登记的 `IShortcutService`）与 `formulaBarText()`（编辑栏的内容），给全部快捷键的回归用例用；探针模块只能经动态 `import()` 引入（lint），补上的 Facade 单独成块时门禁按分块名认出。
- 只在 `import.meta.env.MODE === 'e2e'` 时由 `createSheetEditor` 动态引入并装上；生产构建里这个分支与分块都被去掉。
- 产物门禁核对：生产构建里没有探针的分块（`TEST_ONLY_ARTIFACTS`），也没有 `__nerveEditorProbe` 这个名字（禁用关键字只查生产产物）。
- 探针只读取与调用 Facade，不改变编辑器的行为；E2E 的其他用例不用它。依赖它的用例带 `@test-build` 标签，容器 E2E（生产镜像）按标签排除；生产镜像上另有一条不用探针的只读冒烟用例（审查 B4）。
- 测试构建的编辑器入口因此与生产构建不再逐字节相同：多一个探针的分支，补上的插件 Facade 也让共用模块的分块不同（M1-P3 审查 B19 核对过的"两次构建的入口块相同"不再成立）。产品代码的模块相同，E2E 覆盖的是同样的实现（审查 A2）。

### 3.8 错误处理、安全与可观测性

- 前端的只读只是体验层；写入的边界在服务端：查看者的保存 `PERMISSION_DENIED`，M3 的租约与代次条件写入。
- 被防火墙取消的命令不产生页面错误；E2E 核对只读的全过程没有页面错误与 CSP 违规。
- 探针不进生产构建（门禁）。
