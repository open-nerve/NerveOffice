# P6-S6 工程与过程决定：复核报告

> 审查者：一位独立的 Opus 5.5 子 Agent（报告第一行核对了模型标识 `claude-opus-5-5`，会话记录里每条消息都是 5.5；它分出的一个逐条对照规范的分支同样是 5.5）｜日期：2026-10-02｜复核范围：M2 期间放宽过的超时、CI 的分片与时长、延期项 DEF-026 到 034、ADR-014/015/016 的取舍、ADR-001 的内存归因、前五片留下的过程问题、规范里标【自动】的条目｜被复核的版本：`6dcd43a`（main，第 1–5 片已合并）
>
> **状态：主会话已在 Opus 5.5 上逐条核实（2026-10-02）**；文档一侧的修复由主会话完成，工具与测试一侧由一位 Opus 5.5 实现者完成（第五节）。

审查者的一句话结论是**修复后通过**：没有架构层面的问题——CI 的分片没有漏跑检查，M2 期间集成测试的时限一处都没有放宽，编辑器 E2E 的时限只是挂起时的兜底，延期项都没碰上线门槛，ADR 的"影响"与代码一致。要修的是四件"过程上的欠账"：两处放宽是在躲问题、ADR-001 的内存归因不成立、前几片的"做法补充"只写在 P6 计划里、CI 上有一次不稳定跨了三片没人记。

实测的环境：本机 Apple M4 Pro 12 核（常驻约 1.1 核的远程桌面）；CI 的数字取自 GitHub 的 check-run 与注释（未登录、只读）。CI 与本机的倍数：`pnpm lint` 2.3 倍，测试一步 3.2 倍，静态门禁一步 6.1 倍，E2E 单条 1.3–1.8 倍。

## 一、必须修

| 编号 | 问题 | 证据 |
|---|---|---|
| M1 | **lint 规则自测（60 秒）与门禁自测里 stories（300 秒）的放宽是在躲问题**。lint 自测慢的根因是一条用例塞了几十段要做类型感知检查的代码（每段 120–180 毫秒），例如第 4 片的 F4 一条 41 段、本机 5.1 秒，违反 P2 交接单"一条十几段以内，本机超过 1 秒要考虑拆"的约定；整个文件是 `pnpm test` 的关键路径（覆盖率那一轮里其他文件 61.6 秒跑完，它跑到 138.2 秒），按 P2 那次的倍数估算 CI 上余量只有 1.2–1.9 倍。门禁自测又把 `stories` 跑了一遍（`pnpm verify` 与 `--fast` 的静态门禁一步本来就跑它），而且慢在 `vitest list`（17.0 秒）、不在注释说的 playwright（0.5 秒）；按注释自己的定法（本机 × 20）已经超过 300 秒 | 本机实测与 CI 的 check-run；P2、P3 两次 CI 超时都出在这两处 |
| M2 | **ADR-001 的内存归因不成立**："M2-P4 之后空闲多出约 23 MiB"是噪声（CI 上 P4 只多 2.4 MiB；本机同一份代码背靠背跑，空闲就有约 210 与约 244 两档）；"峰值来自编辑器那批用例并发保存"不成立（只跑编辑器的 48 条是 268.5 MiB）；峰值本身分两档（约 240–270 与约 380–490），第 3–5 片报告拿一次低档的数说"在区间之内"算不上证据；P3 报告"CI 的机器在跑别的 job"也不对（GitHub 托管的每个 job 各用一台虚拟机） | 本机同一份代码 6 次容器 E2E；CI 每次合并打印的数字（从来没人对照过） |
| M3 | **前五片的"做法补充"只写在 P6 计划里**：01 号规范、审查报告的模板、`CLAUDE.md` 都没收；只有第 5 片的"首屏文件数"进了门禁。只写在计划或交接单里的约定没人执行（第 4 片就违反了 P2 交接单的约定） | P6 计划的变更记录与规范、模板的对照 |
| M4 | **CI 上的一次不稳定跨了三片没人记**：第 2 片合并时 Chrome 那一片的 `admin/audit.spec.ts` 首跑失败、重试通过，job 的结论仍是成功，任何文档都没有记（违反规范 §8.4），到第 5 片第四批才查清根因；同一次合并 WebKit 的 ResizeObserver 修复也没进任何报告 | check-run 的注释 |

## 三、主会话的决定

## 四、核实过、没有问题的要点

- CI 的分片完整：不含 E2E 的一片加各浏览器的 E2E 等于整套（`plan.test.ts` 守着）；Edge、`audit`、容器只在 CI 上跑是设计如此。
- M2 期间集成测试的 `testTimeout`、`hookTimeout` 一处都没有放宽；新增的几处等待都是新代码。
- 编辑器 E2E 的 4 分钟与快捷键回归的 8 分钟是挂起时的兜底（余量 18.8 与 22.5 倍，单步仍有更短的等待管着）。
- DEF-026 到 034 都没碰 A01–A20，也没碰 00 号计划书的范围；目标里程碑合理。
- ADR-014/015/016 的"影响"逐项对过代码，都一致。
- ResizeObserver 的排除写得恰当（只排除那一条，严格匹配）。
