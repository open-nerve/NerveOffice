初审的共同点：
- **边界上没有统一的写法**：UUID 的大小写由各处自己处理（零散的 `toLowerCase`），漏掉的地方让"系统管理员加入空间"的审计可以被归成普通的添加成员（A1）。修法是在契约的边界上统一成小写，服务端只见到一种写法。
- **看不到的目标也取了锁**：管理接口先锁空间行再判断类型，转移锁住请求里的全部文档（A4）。响应一致，但锁会让别人的保存排队、耗时能分辨"存在且正被编辑"。修法与 ADR-011 相同：先判断、再加锁、锁下再判断；锁的条件带上"可访问文档"。
- **测试证明不了它声称的东西**：保存点、转移的文档锁的强度、撞名的并发都没有能检出回归的用例（A6）；前端的 E2E 用整页加载绕过了缓存的问题（B1）。新测试都做了变异核对。
- **前端的"看起来对"**：TanStack Query 在重新请求失败时保留旧数据，页面按 `data === undefined` 判断失败，被移出的人在已打开的页面里仍看到旧的页头与管理控件（B1）；选择框立即弹回旧值、没有进行中（B3）。
