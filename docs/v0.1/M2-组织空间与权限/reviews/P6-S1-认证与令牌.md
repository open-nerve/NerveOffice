| 一般-5 | 一般（误伤） | 蒙古文元音分隔符 U+180E 是传统蒙古文正字法的一部分（例如名字"娜拉"），现在被拒绝 | 已处理（第四批）：蒙古文元音分隔符只在蒙古文字母之后、紧跟 a 或 e 时放行 |
| 一般-6 | 一般（残留） | 放行的那几类字符夹在用不上它们的地方时与原名等宽，不换行空格与普通空格等宽 | 按第九节，放进第 2 片（按规范化写法判重）与第 5 片，浏览器实测的数据一并带过去 |
| 一般-7 | 一般（文档） | ADR-008 的元数据一行缺 `renews` 与 `expiredReason` | 已订正 |

疑点（没有复现）：标签页 A 修改密码已提交、响应还没到浏览器时，标签页 B 的请求得到"登录已过期"、确认也在这个窗口里发出，B 会转到登录页，随即被送回原地址。前端无法区分这种情况，窗口很短，不处理。

## 十一、第四批的连带发现与第五批

第四批的实现者在修的过程中又找出几条窄窗口的交错，主会话逐条定了处理（第五批由主会话自己实现，每条都有持锁构造的确定交错用例，5 个变异全部检出）：

| 编号 | 问题 | 处理 |
|---|---|---|
| 连带-1 | 退出的认证在换令牌提交之前通过、撤销在之后执行，影响 0 行，于是回 204 并清除 Cookie；这个响应早于修改密码的响应到达时，浏览器随后又被写回新 Cookie，登录页把人送回应用 | 已处理：退出发现会话已经结束时不记审计、回"登录已过期"；因换令牌而结束时不清除 Cookie，交给前端确认之后带新令牌再退出一次 |
| 连带-2 | 完成重置先撤销全部会话、再作废浏览器原来的会话：原来的会话属于同一个账户时按 `password_reset` 撤销 | 不处理：签发重置时已经撤销了这个人的全部会话、旧密码随即失效，完成时同一个账户不可能还有有效的会话，晚到的旧令牌请求早在签发之后就结束了 |
| 连带-3 | 修改密码与另一个标签页的退出同时发生、退出先提交：修改密码照样新建会话、写回 Cookie，浏览器又变成登录状态 | 已处理：当前这条会话在认证之后已经结束时，修改密码整个回滚（不改密码、不新建会话、不记审计），回"登录已过期"，占的名额退回 |
| 连带-4 | 本页的变更开始之前就发出、之后才处理的那一轮确认，仍可能在"没有会话"时整页重新加载，或者用旧令牌覆盖新令牌 | 不处理：窗口极窄，结果通常会自愈（旧令牌的下一个状态变更得到 CSRF 令牌不对，随即重新确认；整页重新加载之后通常用的是新 Cookie，例外见第十二节的疑点）；ADR-008 的确认规则已写明只有之后开始的一轮能下结论 |
| 连带-5 | 标题仍然接受只由行间注释字符组成的内容 | 已处理：行间注释字符并入"看不见的字符"，只由它们组成的标题按"只有看不见的字符"拒绝，夹在字中间照常保存 |
| 连带-6 | 复验者的来源键属性测试（4 万多组 IPv6 写法）没有移植 | 不处理：第三批的单元测试与集成用例已覆盖 /48 与 /64 的各种写法，属性测试是复验者核对用的 |

## 十二、第三轮复验（只看第四、五批）

又一位 Opus 5.5 的子 Agent 只复验第四、五批（`e41c828`、`c0c41c7`）。结论**通过**：第十、十一节的处理都成立，没有"必须修"或"建议"级的问题。
它写了 45 条自己的用例（前端 12、契约 24、用持锁的第二个连接构造交错的集成 9），做了 19 个变异，17 个被交付的用例检出，存活的 2 个都是测试缺口。
另核实：前端在任何先后组合下都不会卡住、不会重复跳转或循环、不会把另一个人的令牌交给页面；服务端锁的顺序仍是"账户行 → 计数行 → 会话行"；
名称与标题没有误伤（中、日、韩、阿拉伯、希伯来、波斯、天城、泰、藏文，带窄不换行空格的蒙古文，表情组合、旗帜、键帽、组合重音）。

| 编号 | 问题 | 处理 |
|---|---|---|
| 一般-A | 修改密码因会话中途结束而回滚时，事务里抛的不是 AppError，事务运行器按约定把这个连接丢弃（每次多建一个连接） | 已处理：回滚用的错误改成 AppError 的子类，连接照常放回池里；集成用例记下被挡住的连接、回应之后核对它还在，变异（换回普通的 Error）检出 |
| 一般-B | 存活变异：轮数在等待之前就加一，会在"确认等修改密码时又得到登录已过期、修改密码失败"时多发一次确认 | 已处理：补这条用例，变异检出 |
| 一般-C | 存活变异：元音分隔符后面放行全部蒙古文元音 | 已处理：补 a、e 之外六个元音的边界用例，变异检出 |
| 一般-D | 退出时确认那一步断网、别的标签页的消息也没能换上新令牌时，第一次重试先得到"页面已失效"，第二次才成功；交付的用例的假接口不核对 CSRF 令牌 | 不改代码：两处同时断网才会出现，结果看得见、能自己恢复；ADR-008 写明 |
| 一般-E | 退出正在确认时另一个请求开始了全局确认，它的回应比退出的 204 先到时，登录页的说明是"已过期"而不是"已退出" | 不处理：只是文字，窗口极窄，页面只跳转一次 |
| 一般-F | 40 秒上限的注释说"略大于最长耗时"，但语句与等锁的时限按每条语句计，严格的最坏会更长 | 已订正：注释与 ADR-008 改成"通常的最坏情形"，写明严格的最坏会更长、到上限照常确认 |

疑点（没有复现）：第十一节连带-4 的理由说"整页重新加载之后用的是新 Cookie"。重新加载时修改密码的响应头还没到浏览器的话，这个请求会被中止，浏览器拿不到新 Cookie，停在登录页，而新密码已经生效；窗口不到 1 毫秒，本人知道新密码。这句理由因此改为"通常"成立，结论（不处理）不变。

**至此第 1 片的修复收敛**：三轮复验依次通过，后两轮只剩窄窗口的一般项。之后进入收尾：从干净状态跑完整门禁、容器 E2E，合并。
