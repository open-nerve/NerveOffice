## 修复带来的结构性改动

- **守卫多一个阶段 `applyRenderedGuards()`**（就绪时）：冻结线的控制器与编辑栏的放开都要等渲染模块注册之后才能装。编排是：装上 → `applyWorksheetPoints` → 就绪时 `applyRenderedGuards`、`clearUndoStack`。
- **`internal-api/` 拆出第二个出口 `ui.ts`**：界面的包只能从它导出。公式 Worker 也引用 `index.ts`，而 Univer 的包没有声明 `sideEffects`，界面包从那里再导出会整包打进 Worker（1502.7 KiB，门禁 `budgets` 的预算 800 KiB；拆开后 677.4 KiB）。登记表的自测核对两个出口，并核对 `index.ts` 不从界面包再导出。
- **内部 API 17 项**（原 11 项加 6 项：`IEditorService`、`IContextService`、`FOCUSING_FX_BAR_EDITOR`、`DOCS_FORMULA_BAR_EDITOR_UNIT_ID_KEY`、`IRenderManagerService`、`HeaderFreezeRenderController`）。

## 复验

第三位子 Agent（同一模型，从工作区克隆到自己的目录，主工作区未改动）逐条核实 17 项修复，结论是**修复后通过**：没有功能性回归，必须修的三条都在文档。

**它做的独立验证**（不只是读代码）：

- **A1 的微任务是必要的，找到了 SDK 侧的硬证据**：`sheets-formula-ui` 的 `focusFormulaEditor` 在 `editorService.focus()` 之后**同步**移 DOM 焦点、设光标，组件的 `useRefactorEffect` 用的是 `useLayoutEffect`（React 提交阶段同步再置一次"编辑器已激活"）。同步放开必被这两步盖掉。它还把 SDK 里 `editorService.focus(...)` 的全部调用点（docs-ui 4 处、sheets-ui 5 处、sheets-formula-ui 3 处）过了一遍，确认进入编辑栏编辑器的路径都经过它订阅的那个事件；键盘 Tab 进不来（编辑器的隐藏输入框聚焦过一次之后 `tabIndex = -1`，Tab 又被 Univer 的快捷键接走）。
- **复位的上下文正好是需要的一组**：`blur(true)` 复位"编辑器已激活""独立编辑器""批注编辑器"，守卫另复位"编辑栏正被聚焦"——这正是 SDK 判断"表格的快捷键可用"所看的那几个。
- **B2 不会静默失效**：取渲染单元与控制器时取不到会抛错（`RenderUnit` 的依赖解析在没登记时直接抛），由编辑器的加载失败暴露，不会悄悄放过；只在本文档的渲染单元上注册，`dispose` 注销。
- **`applyRenderedGuards` 的时机安全**：冻结线的控制器由 `UniverSheetsUIPlugin.onRendered()` 注册，而守卫这一步排在 `Rendered` 的 `await` 之后（还要等 Worker 的一次消息往返）；`sheet-editor.test.ts` 有顺序断言兜住。Rendered 到就绪之间的空窗由交互屏障覆盖。
- **界面包拆分的体积结论属实**：它自己干净构建，公式 Worker 677.4 KiB / 预算 800 KiB；把三项界面包搬回 `index.ts` 重新构建是 1503.3 KiB，门禁 `budgets` 报错。守护有两道：登记表自测（按包名）与 budgets 门禁（真实产物）。
- **B1 与 Univer 的判断逐字相同**：`/Mac/.test(navigator.appVersion)`；`tests/e2e/` 下 `process.platform` 零命中。
- **B9 确实不再恒为真**：新断言筛的是"执行前"的记录，而探针记得到被取消的命令（Facade 先遍历完全部监听者再判断取消，守卫先订阅、探针后订阅）。
- **UR-022 的核心结论"SDK 定义了却没调用"经它亲自核对属实**（产物里那个初始化方法全文件只出现在定义处）。
