## 五、之前说已修复或已验证、实际不成立的地方

1. P4 交接单说搜索"防泄漏两层"：第二层不是独立的防护，反而掩盖第一层的回归，分页仍会外泄（S2）。
2. ADR-014 与 P2 设计说"单元测试核对查询序列"，P4 审查勾选了"看不到与不存在一致（每个 404 格子与'不存在'比响应）"：文件夹与删除单元的路径没有任何核对（S1），404 格只比 code 与 message（S4）。实现现在是对的，但这条声称没有证据支撑。
3. P2 审查 A9"绕过内容权限的服务用 lint 限定调用方"：P4 照搬时只拦了外壳（S7）。
4. P4 审查 G2 说 `deniedCodes` 的两个具体格子由回收站的集成用例钉住：查看者那几格没有钉住（S4）。
5. ADR-014"调用方都已接上，M3 不用改调用方"：转移没接上（S6）。
6. P2 设计"名称唯一，导航里才能区分"：达不到（M3）。
7. `trash-matrix` 文件头说"查看者那一列与外人那一列就是删完之后被降级或被移出的人"：删除单元一律由编辑者或所有者删除，这种情形只由 `trash.test.ts` 覆盖。
8. 没有发现"判为误报、其实是真问题"的条目；P2 审查 A3（已接受的窗口）复现属实（G3），接受的理由仍然成立，但同一类问题在复制的源文档上（M2）当时没有识别出来。
