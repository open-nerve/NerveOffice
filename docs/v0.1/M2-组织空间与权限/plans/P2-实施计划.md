  - 文档：列表的查询与新建的请求加可选的 `spaceId`；详情加 `space`。
  - 管理：团队空间的列表、创建、全员可见；停用者文档的标题列表与转移（一次最多 100 份）。
  - 错误码：`SPACE_NAME_TAKEN`、`ALREADY_MEMBER`、`LAST_SPACE_ADMIN`、`ACCOUNT_UNAVAILABLE`、`ACCOUNT_NOT_DISABLED`、`SPACE_ARCHIVED`、`TRANSFER_CONFLICT`。
  - 审计：9 个新动作。
  - 单元测试。
- [x] 2. 表定义：
  - spaces：`created_by`；重建个人空间的 CHECK，新增团队空间的 CHECK；团队空间名称的部分唯一索引。

  - `documents.write_epoch`。

- [x] 3. 前端：审计动作的名称（`AUDIT_ACTION_NAMES`）。

### S2 有效权限与文档

- [x] 1. spaces：
  - 空间事实（一条语句：空间行左连接这个人的成员行）；
  - 我能看到的空间的候选；
  - 查个人空间（可以带事务）；
  - 空间行的 `FOR SHARE`。
- [x] 2. documents 的访问策略：（规则是纯函数 access-rules.ts；访问策略只取事实、调用规则；单元测试的假对象用真实的策略，底层是内存里的空间与成员）
  - 文档、空间两种目标，加上"我能看到的空间"；
  - 操作规则；角色统一为空间角色（M1 的 `owner` 并入空间管理员）；
  - 单元测试：全部组合，以及"不存在"与"看不到"两条路径的查询序列相同。
- [x] 3. "可访问文档"的条件（仓储只拼一处）；按空间列出（M1 兼容）；详情带所在的空间。
- [x] 4. 新建到指定空间：
  - 事务里判断，空间行 `FOR SHARE`，锁下再判断；
  - 负载摘要带 `spaceId`（不带时同 M1）；
  - 返回按有效角色计算的权限。
- [x] 5. 收回写入权的入口（抽象与 M2 的实现）；documents 导出访问策略与这个入口。
- [x] 6. 测试辅助：集成与 E2E 的负载摘要；建团队空间与成员的 SQL 辅助。（直接写库的文档等同于不带空间的新建，摘要与 M1 相同，不用改）
- [x] 7. 集成测试：（矩阵 150 格；8 个变异全部检出）
  - 按空间列出、在空间里新建（权限、兼容、重放）、详情的空间；
  - 无权与不存在一致；
  - 权限矩阵的框架与文档部分；
  - 并发：归档与新建、移出与新建（用两个连接构造的交错）。

### S3 空间与成员

- [x] 1. spaces：（名称唯一由唯一索引兜住，创建与改名放进保存点；database 模块加 inSavepoint、isUniqueViolation）

- [x] 3. workspace 模块（新）：（管理操作的共同步骤放在 ManagedSpaces：复核系统角色、先判断、锁空间行、锁下再判断；改名的响应是 TeamSpace）

- [x] 5. 集成测试：（管理矩阵 270 格；单元测试核对编排的顺序；14 个变异全部检出）

  - 每个接口的"未登录"与"无权限"；
