## 任务

### S1 数据模型与有效权限

- [ ] 1. 契约：授权的角色与类型、分享的请求与响应、"与我共享"的响应；文档详情里"经授权访问"的说明字段；三个审计动作的明细结构（`audit-details.ts`）。
- [ ] 2. 表定义与迁移（`document_id` 级联删除、`(user_id)` 索引、审计三个动作）；`gate schema migrations`。
- [ ] 3. `DocumentGrantsRepository`（一表一仓储）。
- [ ] 4. `DocumentAccess` 分开带空间角色与内容权限（纯函数，归档一律降到查看者）；内容与结构两组权限位，结构的只看空间角色；单元测试覆盖全部组合。
- [ ] 5. `EffectiveAccessPolicy.accessOf` 两条语句（空间事实、授权），不存在的文档同样执行两条；`spaceAccessOf` 不看授权；只凭授权时详情不带文件夹。
- [ ] 6. `accessible` 按"要哪几半"接受参数；各调用方写明（按空间列出与回收站只要空间那一半，搜索两半，"与我共享"只要授权那一半，转移只要空间那一半）。
- [ ] 7. `WriteAccessRevocation` 加"某人在这些文档上"的范围（ADR-014 的补充）。
- [ ] 8. 永久删除连带删授权（级联）；集成测试。

### S2 分享的接口与"与我共享"

- [ ] 1. `DocumentSharingService`：列表、设置、取消；被授权人的账户行 → 空间行（`FOR SHARE`）→ 文档行（`FOR UPDATE`）并在锁下复核；审计；取消与降级时收回"这个人在这份文档上"的写入权。
- [ ] 2. 校验：不能给自己（400）、被授权人不存在或停用（409 `ACCOUNT_UNAVAILABLE`）；归档里查看、设置、调整、取消一律 403；回收站 404。
- [ ] 3. `workspace` 的控制器：`/api/documents/{id}/grants`（GET、PUT、DELETE）与 `GET /api/shared`；分享列表把用户换成显示名。
- [ ] 4. 搜索并上授权：只凭授权的结果只给空间名称与类型；"凭授权命中"由搜索的同一条语句给出；搜索的不变量检查相应改成"在我能看到的空间里，或者我有授权"。
- [ ] 5. 集成测试：幂等、取较高者、只凭授权的人不能移动与删除、按空间列出与回收站不受授权影响、搜索受授权影响、跨空间移动 / 移出空间 / 停用 / 转移都保留授权、复制不带授权；分享与归档、移出的确定交错。

### S3 前端

- [ ] 1. 分享对话框（按需加载，复用同事目录的选人组件）：搜人、选角色、调整、取消；进行中与失败的处理按既有约定；归档的空间里不出现分享入口。
- [ ] 2. "与我共享"页与左侧导航入口（按需加载）；显示所属空间的名称，不显示目录结构。
- [ ] 3. 按权限隐藏分享入口（只有空间管理员 / 个人空间所有者看得到）；只凭授权时不显示所在位置、没有移动与删除的入口。
- [ ] 4. 前端单测与 E2E。

### S4 越权访问的全面验证（US-M2-14、A03）

- [ ] 1. 权限矩阵加两个角色（只有查看授权、只有编辑授权），六张表全部扩一列；补结构性操作的格子（空间内移动、`PATCH {folderId}`、跨空间移动、删除都是 403；详情不带文件夹）。
- [ ] 2. 生效时机：取消分享、移出空间、停用之后下一次请求即生效。
- [ ] 3. 无权与不存在一致：响应逐字节相同，语句序列相同（需求方 2026-10-01 确认以此验证"耗时一致"），新路径全部接入 P6-S2 的核对。
- [ ] 4. 列表、搜索、"与我共享"、回收站都不出现无权的文档（列表类格子断言"恰好是这几条"）。
- [ ] 5. E2E 的关键路径：猜文档地址、取消分享后访问、移出空间后访问、停用后访问。
