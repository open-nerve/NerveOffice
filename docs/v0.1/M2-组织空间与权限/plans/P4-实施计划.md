## 任务

### S1 数据模型与文件夹

- [ ] 1. 契约：`folders` 的类型与 schema；`documents` 的列表查询加 `folderId`；错误码复用。
- [ ] 2. 表定义与迁移 `0010_m2_folders_trash`：`folders`、`trash_entries`、`documents` 的两列与索引、审计的 CHECK 全量重列；`pnpm gate schema migrations`。
- [ ] 3. `FoldersRepository`（一表一仓储）与 `FoldersService`：新建、改名、移动、按父列出；深度存列、10 层上限在事务里校验。
- [ ] 4. 空间树的 advisory lock：取锁的辅助函数与锁顺序注释；结构性改动一律先取它。
- [ ] 5. 权限规则扩展（`access-rules.ts` 的纯函数）与 `SpacePermissions` 的新位；单元测试。
- [ ] 6. `workspace` 的文件夹控制器；集成测试（含 10 层、同名、跨空间的父、看不到的空间）。

### S2 文档的整理

- [ ] 1. 重命名与空间内移动（`PATCH /api/documents/{id}`）：权限、审计、不动 `write_epoch`。
- [ ] 2. 跨空间移动（`POST /api/documents/{id}/move`）：源空间管理员 + 目标新建权限；`write_epoch + 1`；同事务调 `WriteAccessRevocation.revoke`。
- [ ] 3. 复制（`POST /api/documents/{id}/copy`）：`INSERT … SELECT` 直接复制压缩字节，`unitId` 不变，新文档 `revision=1`；幂等按 `requestId`。
- [ ] 4. 集成测试：复制的逐字节一致与两份互不影响；跨空间移动之后的权限变化。

### S3 回收站

- [ ] 1. spec：恢复与永久删除的规则细则（原位置不在、深度超限、同名、跨空间移动过的文档）。
- [ ] 2. 删除：文档与文件夹子树；删除单元；`write_epoch + 1`；审计。
- [ ] 3. 列表、恢复、永久删除；回收站里的文档打不开、不出现在列表与搜索里。
- [ ] 4. 集成测试：级联、恢复的回落、并发（展开子树与移入新文档、两个方向的跨空间移动）。

### S4 `jobs` 模块与 30 天清理

- [ ] 1. lint 边界登记与 `TrashPurgeService` 的引用限定；模块骨架与 `Clock` 抽象。
- [ ] 2. 定时器、advisory lock、批量与逐条短事务、失败只记日志。
- [ ] 3. 配置项与默认值；`.env` 模板、`deploy/README.md`、架构总览的部署一节。
- [ ] 4. 单元与集成测试（假时钟推进 30 天）。

### S5 搜索

- [ ] 1. 接口与关键词转义；结果里的空间名与文件夹路径。
- [ ] 2. 顶栏搜索框（结果页或下拉，按 P5 的"与我共享"预留位置）。
- [ ] 3. 单元与集成测试；E2E 一条。
