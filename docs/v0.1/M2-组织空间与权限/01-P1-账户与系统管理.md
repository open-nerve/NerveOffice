# M2-P1 账户与系统管理：架构设计与实施规划

> 状态：已完成（2026-09-29 合并到 main）｜日期：2026-09-28｜基于代码版本：`78f856a`
>
> **M2-P6 复核（2026-09-30）改动了本设计的几处**：登录限流的维度、修改密码时当前会话的令牌、一次性链接的尝试计数、签发人离任时的链接、审计的动作与明细、名称的字符规则。受影响的段落已就地加注，细节以 ADR-007、ADR-013 与 `reviews/P6-S1-认证与令牌.md` 为准。

## 1. 目标与范围

对应 M2 总设计 §5 的 P1 一行：同事能受邀加入；系统管理员能管理账户、查审计。

- **用户故事**：US-M2-01（邀请注册）、US-M2-02（修改密码）、US-M2-03（重置密码）、US-M2-13（审计查询）全部完成；US-M2-04 完成停用、启用与系统管理员的授予和取消，停用者文档的转移随 P2（团队空间）完成。
- **范围内**：
  1. 一次性令牌：邀请与重置密码的签发、查看、接受或完成、作废、重发；尝试限流；公开页面。
  2. 修改密码：输入旧密码，改完退出其他登录。
  3. 账户的状态与角色：停用与启用；系统管理员的授予与取消，始终至少保留一个有效的系统管理员；按人撤销会话。
  4. 同事目录：按名字搜索有效账户（P2 添加成员、P5 分享都用它）。
  5. `admin` 模块与管理界面：账户、邀请、审计查询；系统管理员才能访问。
  6. 审计：新的动作与对象类型；按条件查询。
  7. 运维命令：签发重置链接（§3.9）。
  8. 门禁：`stories` 支持累计多个 M 的总设计，M2 的故事登记进来。
- **范围外**：团队空间与停用者文档的转移（P2）；"收回写入权"的入口（P2，随 `writeEpoch`）；左侧导航（P2）。

## 2. 现状

基于 `78f856a`（M2 总设计合并之后）：

- **users 模块**：
  - 账户表已有系统角色（`admin`、`member`），状态只有 `active`（CHECK 约束）。
  - `UsersService.verifyCredentials` 对不存在的账户同样算一次哈希，失败的耗时补齐（ADR-007）；停用的账户按真实哈希验证，密码对时不补齐（P1 审查 A8 改为对假哈希验证，§3.5）。`findActiveById` 由会话守卫对每个请求调用，账户一停用，下一次请求就被拒绝。
  - 初始化管理员在同一个事务里建账户、个人空间并记审计，用 advisory lock 串行；已有管理员时拒绝。
- **auth 模块**：
  - 会话只能按 id 或令牌摘要撤销单条，撤销原因只有 `logout`、`replaced`（CHECK 约束）；`user_id` 上已有索引，就是为 M2 按人撤销准备的。
  - 登录限流按用户名与客户端地址两个维度，先占名额再验证，计数存在 `auth_login_throttles`（键只存摘要）。（M2-P6 复核 A1 起改为三个维度：用户名 + 地址、只按用户名的宽上限、只按地址；管理员可以解除锁定，ADR-007。）
  - 全局守卫：先认证（`@Public()` 的接口跳过），再查 CSRF 与 Origin。公开的状态变更接口只查 Origin。
- **audit 模块**：只追加（触发器）；动作与对象类型由 contracts 的常量生成 CHECK 约束，新增要写迁移；`details` 按严格的结构校验，不超过 4 KiB；没有查询接口。M1 的文档事件只记修订号，不记标题。
- **前端**：平台页面是单页应用，路由只有登录页、文档列表与 404；页头有产品名称、当前用户与退出。界面组件在 `shared/ui`（shadcn/ui 的改写），`radix-ui` 统一包已经包含弹窗、下拉菜单、选择框等原语，不需要新依赖。
- **测试**：E2E 用 SQL 直接建账户（`support/database.ts`），三个浏览器并行、共用一个库；集成测试每个文件一个独立的库。
- **门禁 `stories`**：只核对 `tests/stories.json` 的 `design` 指向的那一份总设计；测试标题引用了没有登记的故事编号就报错。M1 的回归测试以 `US-M1-` 开头，所以不能直接换成 M2 的故事。

## 3. 设计

### 3.1 模块划分与依赖方向

```text
admin（新）──► users、auth、audit          系统管理的接口与跨模块编排
auth ─────────► users、spaces、audit       会话、登录、修改密码、一次性令牌（邀请与重置）
users ────────► spaces、audit              账户、状态与角色、同事目录
```

- **users**：账户的停用与启用、系统角色的授予与取消（"至少保留一个"的规则在这里，§3.5）；同事目录与账户列表；接受邀请时建账户与个人空间（复用初始化管理员的做法）。
- **auth**：
  - 按人撤销会话（M2-P6 复核 B1 起不再保留当前会话：修改密码时连当前这一条一起撤销，再为当前页面新建一个）；
  - 修改密码；
  - 一次性令牌：表 `auth_invitations`、`auth_password_resets` 归它；签发、查看、接受邀请、用重置链接设置新密码、作废；尝试限流。这些流程既要读写账户又要撤销会话、建会话，放在已经依赖 users 的 auth 里，不产生循环依赖；
  - 系统管理员的访问检查：`@SystemAdminOnly()`（放在 `shared`，与 `@Public()` 一样只是元数据），由会话守卫在认证之后检查，不是系统管理员时 `PERMISSION_DENIED`。
- **admin（新）**：只有控制器与编排服务，没有自己的表。停用账户要同时改状态、撤销会话、作废未用的重置链接，由它在一个事务里编排；P2 在这里接上"收回写入权"。
- **audit**：新增按条件查询的仓储方法，只由 admin 模块使用。

模块之间只经 `index.ts`，依赖图无环（lint 强制）。

### 3.2 数据模型与迁移

一次迁移（`0008`），只做加法：

| 表 | 变化 |
|---|---|
| users | 状态加 `disabled`（CHECK）；凭据的版本 `password_version`（默认 1；修改密码、签发与完成重置时加一，按新参数重新哈希不变，复验 X1、X2） |
| auth_sessions | 撤销原因加 `disabled`、`password_changed`、`password_reset`（CHECK）。M2-P6 起修改密码时当前这条按 `replaced`（换成了新的）、别的设备上的按 `password_changed` 撤销，只有 `replaced` 的旧令牌晚到时不清除 Cookie |
| auth_invitations（新） | `id`；`username`（规范写法，CHECK 同账户表）；`display_name`；`token_hash`（32 字节，唯一）；`created_by`（账户，外键）；`created_at`；`expires_at`；`accepted_at` 与 `accepted_user_id`（同时有或同时没有）；`revoked_at` 与 `revoked_by`。CHECK：接受与作废最多一个。部分唯一索引：同一个用户名最多一条"未接受、未作废"的邀请 |
| auth_password_resets（新） | `id`；`user_id`（外键）；`token_hash`（唯一）；`created_by`（账户，可空：运维命令签发的没有）；`created_at`；`expires_at`；`used_at`；`revoked_at`。CHECK：使用与作废最多一个。部分唯一索引：同一个账户最多一条"未使用、未作废"的重置 |
| audit_events | 动作与对象类型的 CHECK 扩充（§3.7） |

- 时间一律取数据库时间；"已过期"在查询时按 `expires_at <= now()` 判断，不靠定时任务改状态。
- 两张令牌表的行不清理：约 100 人的规模下增长很慢，它们也是邀请列表与审计的上下文。
- 新表由迁移以所有者建，默认权限自动授权给应用角色（ADR-012），不写 GRANT。

### 3.3 接口契约

请求结构严格，响应结构宽松（沿用 M1 的约定）。路径都在 `/api` 下。

| 接口 | 访问 | 说明 |
|---|---|---|
| `PUT /auth/password` | 登录 | `{currentPassword, newPassword}` → 204；本人其他会话全部撤销（M2-P6 复核 B1 起 → 200，响应与登录相同：本人全部会话撤销，为当前页面新建一个，写回 Cookie 并下发新的 CSRF 令牌） |
| `POST /auth/invitations/inspect` | 公开 | `{token}` → `{username, displayName, expiresAt}` |
| `POST /auth/invitations/accept` | 公开 | `{token, displayName, password}` → 会话（与登录的响应相同），写入会话 Cookie |
| `POST /auth/password-resets/inspect` | 公开 | `{token}` → `{username, displayName, expiresAt}` |
| `POST /auth/password-resets/complete` | 公开 | `{token, password}` → 会话，写入会话 Cookie |
| `GET /users?query=` | 登录 | 同事目录：显示名或登录名包含关键词的有效账户，最多 20 条 → `{items: [{id, username, displayName}]}` |
| `GET /admin/users?query=&status=&cursor=` | 系统管理员 | 账户列表（含停用的），按登录名排序，每页 50 条 |
| `POST /admin/users/{id}/disable`、`POST /admin/users/{id}/enable` | 系统管理员 | 返回账户 |
| `PUT /admin/users/{id}/system-role` | 系统管理员 | `{systemRole}` → 账户 |
| `POST /admin/users/{id}/password-reset` | 系统管理员 | → `{url, expiresAt}`；同时让当前密码失效、撤销这个人的全部会话（§3.4） |
| `GET /admin/invitations?status=&cursor=` | 系统管理员 | 邀请列表（不含令牌）：待接受、已接受、已过期、已作废；按签发时间从新到旧，每页 50 条。每条带 `superseded`：同一个登录名后来又签发过（界面只对最新的一条给出重新生成） |
| `POST /admin/invitations` | 系统管理员 | `{username, displayName}` → `{invitation, url}` |
| `POST /admin/invitations/{id}/revoke` | 系统管理员 | → 邀请 |
| `POST /admin/invitations/{id}/reissue` | 系统管理员 | 作废旧的、按同一个登录名签发新的，一个事务 → `{invitation, url}` |
| `GET /admin/audit-events?from=&to=&actorId=&action=&targetType=&targetId=&cursor=` | 系统管理员 | 按时间倒序，每页 50 条 → `{items, nextCursor}` |

- 链接只在签发的响应里出现一次，形如 `<公开地址>/invite#<令牌>`、`<公开地址>/reset-password#<令牌>`（§3.4）。
- 新增错误码（contracts）：

| 错误码 | 状态 | 用途 |
|---|---|---|
| `LINK_INVALID` | 410 | 邀请或重置链接不能用；`details.reason` 为 `invalid`（没有这个令牌）、`expired`、`used`、`revoked` |
| `CURRENT_PASSWORD_INCORRECT` | 403 | 修改密码时旧密码不对 |
| `LAST_ADMIN` | 409 | 这个操作会让有效的系统管理员一个都不剩 |
| `ACCOUNT_DISABLED` | 409 | 对停用的账户签发重置链接，或者授予停用的账户系统管理员 |

登录名已被占用或已有待接受的邀请时沿用 `USERNAME_TAKEN`；非系统管理员访问管理接口是 `PERMISSION_DENIED`。

### 3.4 一次性令牌（邀请与重置密码）

**生成与存储**：32 字节安全随机数，base64url 编码；库里只存 SHA-256 摘要，与会话令牌相同。签发的响应里给出完整链接，之后再也取不到（邀请列表只有状态）。

**链接的形态**：令牌放在 `#` 之后。浏览器不把 `#` 之后的部分放进请求行，所以它不进服务端与反向代理的访问日志，也不会出现在 Referer 里。页面读出令牌后，立即用 `history.replaceState` 把它从地址栏与当前的历史记录里去掉，再把它放进请求体提交。

**有效期**：邀请 7 天，重置 24 小时（contracts 的常量）。

**生命周期**：
- 签发邀请：登录名已被账户占用，或者已有未过期、待接受的邀请时，拒绝（`USERNAME_TAKEN`）。已过期、未处理的旧邀请，在同一个事务里自动作废。
- 重发：作废旧的（还没作废时）、按同一个登录名与显示名签发新的，一个事务；新邀请的审计带 `reissuedFrom`（旧邀请的 id）。
- 签发重置：同一个账户未使用的旧重置自动作废；当前密码换成不可用的哈希，旧密码随即失效（审查 A7：账户被盗时，签发即切断旧密码，不用等本人完成重置）；同时撤销这个人的全部会话（原因 `password_reset`）；停用的账户拒绝（`ACCOUNT_DISABLED`）。
- 停用账户：作废这个人未使用的重置。

**查看**：公开页面先用令牌查看，得到登录名与显示名，只显示这两项，不显示签发人等信息。

**锁的顺序**（审查 A2，与 ADR-007 的补充一致）：改动账户的凭据、状态、重置与会话的事务，第一步锁账户行（`FOR NO KEY UPDATE`；登录的复核用 `FOR SHARE`），在锁里复核，再依次动重置行、限流计数、会话行。管理操作在这之前先取 `nerve-office:system-admins` 的 advisory lock、复核操作者（停用与系统角色取排他模式，启用、签发重置、邀请的签发、重发与作废取共享模式，复验 N3）；邀请的签发、重发、接受先取按登录名的 advisory lock，再取邀请的行锁。各处按同一个顺序取锁，互相等待时不成环。

**接受邀请**：先在事务外查一次令牌并计算新密码的哈希（计算密集，事务要短）。然后在一个事务里：
1. 取按登录名的锁、锁住邀请行，复核仍然可用；
2. 建账户（成员）与个人空间，标记已接受；
3. 新建会话（浏览器原来带着的会话作废，同登录）；
4. 记审计。

响应与登录相同，页面进入个人空间（单页内导航，与登录页相同；会话变化照常通知其他标签页）。

事务里复核不通过（查令牌之后被接受或作废）：事务之外按一次失败处理，与查令牌时就不能用的一样，记 `auth.link_rejected`，这次失败使计数达到上限时 429（审查 A10）。

**用重置链接设置新密码**：同样先查令牌、算哈希。然后在一个事务里：
1. 先锁账户行、再锁重置行，复核账户仍然有效、重置仍然可用（复核不通过同接受邀请）；
2. 更新密码哈希，标记已使用；
3. 撤销这个人的全部会话，再新建本次的会话；
4. 记审计。

**不可用的链接**：没有这个令牌、已过期、已使用、已作废，都是 `LINK_INVALID`，`details.reason` 区分原因，页面按原因给出下一步：
- 已接受的邀请、已用过的重置：直接登录；
- 其他情况：请管理员重新发送。

令牌是 256 位随机数，猜不到，按原因区分不会泄漏信息。

**尝试限流**：查看、接受、完成三类请求都先占用名额（与登录限流同一张表、同一套机制），维度是客户端地址，键另起前缀，不与登录的计数混在一起；阈值沿用登录的地址维度。令牌不可用算一次失败，可用就退回名额（M2-P6 复核 B3 起只有"没有这个令牌"计入按地址的失败，"找到了但不能用"另按链接的记录计数，ADR-013）。锁定期间只记日志，不写审计；锁定之外，不可用的尝试记审计（`auth.link_rejected`，找到了记录时带上对象：邀请或账户）。

### 3.5 账户的状态、角色与会话

- **按人撤销会话**：`SessionService.revokeAllOf(userId, reason, { except, transaction })` 撤销这个人全部有效的会话，可以保留当前的一条（M2-P6 复核 B1 删掉了 `except`：没有调用方再保留当前的一条）。
  - 调用方的事务先锁账户行（§3.4 的锁顺序）。登录验证密码在事务之外，进了事务先锁同一行（`FOR SHARE`）复核：账户仍然有效、凭据的版本（`password_version`）还是验证时的那个（审查 A1，复验 X1、X2）。两边一先一后：撤销先提交，登录复核不通过；登录先提交，随后的撤销包括它新建的会话。
  - 账户状态在每个请求里检查（会话守卫），停用即使与撤销之间有先后，也不会漏过请求；守卫发现账户不可用时撤销这条会话、不顺延，启用之后它也不能再用。
- **停用**：在一个事务里完成：
  1. 取 system-admins 的锁，复核操作者仍是有效的系统管理员（审查 A12：守卫检查之后他可能刚被取消）；锁住账户行，状态改为停用；
  2. 作废未用的重置；
  3. 撤销全部会话（原因 `disabled`）；
  4. 记审计。

  停用的人登录时，提示与密码错误相同，不暴露账户状态（沿用 M1）；对假哈希验证，密码对不对耗时都一样（审查 A8）。
- **启用**：状态改回有效。个人空间与文档都没有变过。
- **系统管理员的授予与取消**：只有有效的账户能被授予（`ACCOUNT_DISABLED`）；操作者同样在锁里复核。
- **操作者的复核**（审查 A12、复验 N3）：管理操作都在事务第一步复核操作者仍是有效的系统管理员。停用与系统角色的变更取 `system-admins` 的排他锁；启用、签发重置、邀请的签发、作废与重发取共享锁，彼此不互斥。运维命令签发重置时操作者是系统，不复核。
- **至少保留一个有效的系统管理员**：取消系统管理员、停用系统管理员时，在同一个事务里先取 advisory lock（`nerve-office:system-admins`，与初始化管理员的锁分开），再数除这个人以外的有效系统管理员，为 0 就拒绝（`LAST_ADMIN`）。两个管理员同时互相取消，只有一个成功。可以取消或停用自己，只要还有别的有效管理员；停用自己后本人的会话随之失效。
- **修改密码**：
  1. 先按登录限流占名额（用户名与地址两个维度：猜旧密码与猜登录密码按同一个计数，能锁定登录；M2-P6 起与登录同样的三个维度）；
  2. 按 id 验证旧密码（耗时补齐的做法同登录）；
  3. 在事务里先锁账户行，复核验证旧密码之后凭据的版本没变（没有修改、签发或完成重置）、账户仍然有效，再更新哈希（版本加一），撤销本人除当前会话以外的全部会话（原因 `password_changed`），记审计。M2-P6 复核 B1 起连当前这一条一起撤销（当前这条按 `replaced`、其余按 `password_changed`），同一事务里为当前页面新建一个会话，写回 Cookie 并下发新的 CSRF 令牌：被拷走的旧令牌随即失效。当前这条在认证之后已经结束（同一个浏览器刚退出或重新登录）时整个回滚，回"登录已过期"。
  4. 旧密码不对、复核不通过，都记审计 `users.password_change_failed`（审查 A6：它与登录共用按用户名的计数，能锁定登录，管理员要能查到原因）。

  新密码的规则同初始化（`newPasswordSchema`）；新旧相同也允许（NIST 不要求）。

### 3.6 同事目录与账户列表

- **同事目录**：`GET /api/users?query=`。显示名或登录名包含关键词，不区分大小写，`%` 与 `_` 转义；只返回有效账户，最多 20 条，按显示名排序。返回 id、登录名、显示名，不返回角色与状态。约 100 人的规模不加索引。
- **账户列表**（管理）：含停用的账户，可以按关键词与状态过滤，按登录名分页（游标是登录名，登录名唯一）。

### 3.7 审计

新增动作（已发布的动作不改名、不复用）：

| 动作 | 操作者 | 对象 | details |
|---|---|---|---|
| `users.invited` | 管理员 | 邀请 | 登录名；重发时另有 `reissuedFrom`（旧邀请的 id） |
| `users.invitation_revoked` | 管理员 | 邀请 | 是否因重发（`reissued`）、过期后再签发（`expired`）而作废；M2-P6 起另有签发人离任的原因（复核 A2） |
| `users.invitation_accepted` | 新账户 | 账户 | 邀请的 id |
| `users.password_changed` | 本人 | 账户 | — |
| `users.password_change_failed` | 本人 | 账户 | 原因：旧密码不对（`current_password_incorrect`），或者验证之后凭据变了（`credentials_changed`，复验 N6）；这次失败触发锁定时带锁定秒数（审查 A6） |
| `users.password_reset_issued` | 管理员，或系统（运维命令） | 账户 | —（M2-P6 起带重置的 id） |
| `users.password_reset_completed` | 本人 | 账户 | —（M2-P6 起带重置的 id） |
| `users.password_reset_revoked`（M2-P6） | 管理员，或系统 | 账户 | 重置的 id 与原因：签发新的、账户停用、签发人被停用、签发人不再是系统管理员（复核 C3、A2） |
| `users.login_unlocked`（M2-P6） | 管理员 | 账户 | —（复核 A1） |
| `users.disabled`、`users.enabled` | 管理员 | 账户 | — |
| `users.system_role_changed` | 管理员 | 账户 | 原角色与新角色 |
| `auth.link_rejected` | 未登录的访问者 | 找到了记录时：邀请，或重置对应的账户 | 用途（邀请或重置）、原因 |

- 对象类型加 `invitation`。
- details 不含令牌、密码与文档标题（规范 §6、M2 总设计 §2.1 第 5 条）。M2-P6 复核 M-1 起每个动作的 details 都有严格的结构（contracts 的 `audit-details.ts`），多一个键就拒绝。

**查询**：
- 条件：时间范围（含起点、不含终点；年份至少是 1，PostgreSQL 没有 0 年，审查 A4）、操作者、动作、对象类型与 id。
- 排序与分页：按时间与 id 倒序，游标是最后一条的（时间，id），每页 50 条。
- 显示：审计表只有 id，admin 模块用 users 的批量查询补上账户的登录名与显示名（停用的账户同样显示），邀请补上登录名。
- 管理员能看到客户端地址与请求标识。现有的三个索引（时间、操作者、对象）覆盖这几种条件。

### 3.8 前端

- **公开页面**（在需要登录的外层路由之外）：
  - `/invite`：显示登录名，可以改显示名，设置密码（两次输入），提交后进入个人空间。
  - `/reset-password`：显示登录名，设置新密码（两次输入），提交后进入个人空间。
  - 两个页面按 `LINK_INVALID` 的原因给出下一步；成功时与登录一样通知其他标签页会话变了（ADR-008 的多标签页处理），页内导航与登录页相同。
  - 同一个标签页里只改 `#` 的片段导航（粘贴重发的新链接）时，按新的令牌重新查看；别的标签页登录或退出时，公开页不整页重载，免得已经从地址栏去掉的令牌丢失（审查 B3）。
- **修改密码**：`/settings/password`；用户菜单加入口。成功后提示"其他设备上的登录已退出"。
- **管理界面**：`/admin` 下分账户、邀请、审计三页（P2 加团队空间）。
  - 路由按需加载（`lazy`），不进平台页面的首屏包（规范 §11 的预算）：管理界面只被 `app/routes.ts` 动态引用，lint 禁止静态引用；只有管理界面用的弹窗不经 `shared/ui` 的汇总导出（审查 B2）。直接打开管理页时，加载期间显示会话检查的等待状态（审查 B5）。
  - 非系统管理员打开时显示无权限的页面；服务端另外逐请求检查。
  - 账户页：搜索与状态过滤；停用与启用、设为或取消系统管理员、生成重置链接。停用、取消管理员等操作先在界面上确认；对自己的停用、取消系统管理员、生成重置链接另有确认文案；停用与取消成功之后向服务端确认会话，生成重置链接则在关闭链接的弹窗之后再确认（先把唯一一份链接交到本人手里）；管理接口返回无权限时同样刷新会话，界面切到无权限的状态（审查 B4）。
  - 邀请页：签发（登录名、显示名）、作废、重发（只对同一个登录名最新的一条给出），列表显示状态。
  - 审计页：筛选、表格与"加载更多"。
  - 链接只在签发后的弹窗里显示一次，带复制按钮与"只显示这一次"的提示。
- **页头**：系统管理员显示"管理"入口。
- 新页面都有加载、空、失败、无权限的状态；进行中的按钮用 `aria-disabled`（M1 的做法）；文字集中在 `zh-cn.ts`。
- 新组件（弹窗、表格、标签、选择框）按 shadcn/ui 的写法放进 `shared/ui`；弹窗的底层用已有的 `radix-ui`，选择框用原生的 `select`。行里的操作用按钮，不用下拉菜单。

### 3.9 命令行：运维的重置链接

`pnpm admin:reset-link --username <登录名>` 为指定账户签发重置链接。标准输出只有链接，日志写标准错误；容器里用 `docker compose exec` 执行，输出直接回到终端，不经容器的日志驱动（审查 B13）：
- 走与界面签发相同的服务：作废旧的、撤销会话、记审计；操作者是系统，来源是命令行。
- 用途：唯一的系统管理员忘记密码时恢复。初始化命令在已有管理员时拒绝执行，界面又要先登录，没有这条命令就只能改数据库。
- 它不授予任何角色，与 M2 总设计 §2.1 第 6 条（系统管理员只在界面里授予）的本意不冲突；那一条与 00 号计划书 §5.2 的原文是"命令行只用于初始化首个管理员"，正文同步补上这条运维命令（审查 B12）。
- 部署说明（`deploy/README.md`）写明用法。

## 7. 风险与未决问题

| 风险 | 应对 |
|---|---|
| 令牌泄漏：链接被转发、截图，或者进了日志 | 单次、时限、只存摘要；`#` 之后的令牌不进请求行、日志与 Referer；页面读出后从地址栏去掉；可以作废与重发；签发与使用都记审计 |
| 公开接口被用来刷审计表或拖慢服务 | 尝试限流先占名额；锁定期间只记日志；查看不做哈希，接受与完成先查令牌再算哈希（无效的令牌不触发哈希计算） |
| 并发：同一个令牌同时被接受两次；两个管理员同时互相取消 | 行锁与复核；系统管理员的 advisory lock；集成测试覆盖 |
| 停用与会话撤销之间的窗口 | 会话守卫对每个请求检查账户状态，停用提交之后的请求一律被拒 |
| 验证密码在事务之外：验证与提交之间密码被改、重置被签发、账户被停用 | 事务第一步锁账户行并复核，锁的顺序统一（§3.4、§3.5，审查 A1、A2）；两个连接的集成测试覆盖 |
| 管理界面的代码让平台页面的首屏包超预算 | 管理路由按需加载；预算门禁核对 |
| 审计里的名字随账户改名而变 | 查询时补名字，审计表本身只存 id，记录不被改写；页面显示的是当前的名字，这是有意的 |
