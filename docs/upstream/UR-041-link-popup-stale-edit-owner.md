# UR-041 旧链接菜单覆盖单元格未提交正文

状态：用户批准的本地局部修正已通过真实 SDK 45 项、三浏览器 9 条关键故事、Linux/ARM64 原三故事，以及当前 full05 默认完整门禁和 container03 生产容器；最终合并 SHA 的六项 CI 及阶段关闭仍待完成。未发送上游。固定 `@univerjs/sheets-hyper-link-ui@1.0.1`，发现于 M5-P3-S6。

## 反例与根因

正式宿主先悬停显示已有链接的查看菜单，再双击进入单元格正文编辑，在链接之外输入“新增”。旧菜单仍可点击，其普通取消命令从工作表已提交值重建正文，覆盖刚输入但尚未提交的文字。macOS WebKit 的真实键盘、鼠标及活动 Docs 前后值已证明覆盖；失败发生在保存和撤销之前，不据此宣称持久化或不可恢复丢失。样本、trace 与原始断言见 [调查](../v0.1/M5-表格能力与资源/reviews/P3-S6-链接旧弹层覆盖正文调查.md)。Linux CI 同类命令路由失败是另一条证据，不能替代 Linux 正文丢失复现。

查看与正文事件分别订阅。进入编辑未立即撤掉查看菜单，排队的工作表悬停还可能重新显示旧菜单或关闭新的正文菜单。编辑器保持打开但所属文档、工作表、行或列变化时，旧菜单也未随 owner 退役。菜单的 type 决定普通或 rich 命令，因此这是状态归属问题。

## 局部修正与验证

同一包的 ES/CJS 桌面与移动控制器在进入编辑时立即移除查看菜单；工作表回调执行时检查编辑可见状态；编辑退出、状态清空或 owner 变化时退役旧 Docs 订阅及菜单。异 owner 的正文表单经原 endEditing 结束，仍尊重范围选择器 keepVisible。同 owner 通知、普通表单、只读菜单与实际权限保持。不提前提交文字，不强改命令类型，不新增公开 API 或快照字段。补丁摘要见 `patches/univer-links.json`，语义登记于 ADR-010。

测试使用发布包注册的真实控制器与弹层服务。生命周期初版反例有 9 项有效失败；独立审查追加 owner 和表单反例后仍有 9 项有效失败，修正后生命周期 31 项及既有焦点 14 项全部通过。正式 UI 预先显示旧菜单，再输入未提交前后文，分别实际修改/取消中间链接，核对精确 rich 命令、文字和范围、撤销重做、保存及重开后的客户端整格；三浏览器 9/9 首次通过，无重试和跳过。

移动端目前是实际类的状态回归，未冒称移动 UI 验收。Linux/ARM64 对照使用原 spec/fixtures，API 仍在 Mac；它不替代最终 Linux/amd64 CI。阶段本机 full05/container03 与原件审计已通过，详见 [修复复核](../v0.1/M5-表格能力与资源/reviews/P3-S6-链接修复与CI收尾复核.md)。未打本地其他补丁的上游默认宿主复现尚未补齐，报告未外发。上游修复同一生命周期后，通过上述反例、正式三浏览器及原权限/导航故事，再移除此段补丁；URL normalizer 与焦点去重补丁有各自独立删除条件。
