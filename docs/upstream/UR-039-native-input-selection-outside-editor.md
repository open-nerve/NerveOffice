# UR-039 已聚焦的单元格编辑器遗留外部原生光标，首次输入无效

状态：本地修复，实际 SDK 7 项、S5 最终工程和三浏览器组合通过；P3 阶段验证待完成。未向上游发送。固定版本 `@univerjs/docs-ui@1.0.1`，发现于 M5-P3-S5。

## 反例与根因

正式 UI 新增工作表，先后将两表改名为“汇总”“数据”，经名称框选择 A2，F2 打开编辑器后输入“青”并回车。A2 保存为空，随后 A3 的“山”及数值正常。该失败发生在公式创建之前。

原始证据在 `.codex/handoffs/m5-p3-20261020/s5/`。ui01/02、diagnostic01/03/04/05/06 均失败；diagnostic02 每事件 console 记录改变了时序，虽完整链通过也不计验收。最终 diagnostic06 证明：activeElement 已是 normal editor，DOM Selection 的 anchor 却仍在旧改名控件的父节点。首次“青”触发未取消的 beforeinput，但浏览器未发生 input；后续字符的原生选区在输入框内，全部正常。不是云端保存、公式计算或 SDK 命令丢弃字符。

`DocSelectionRenderService.focus()` 原来只调用 HTMLElement.focus。元素已经聚焦时该调用不重建原生光标，不能恢复被旧 DOM 更新移出的选区。

## 局部修复

在同一 focus 入口完成原调用后，仅当输入框仍实际聚焦、没有进行 IME 组合、且原生选区缺失或任一端点不在输入框内时，使用输入框所属 document 重建收字光标。已经有效的选区及方向保持；焦点回调选择别的控件时不再抢回；不改变 SDK 逻辑选区、正文、公式、保存和权限。

ES/CJS 对称补丁及原始/最终摘要在 `patches/univer-native-focus.json`。不在测试中替换 focus、减慢输入或修改浏览器选区来使页面通过。

## 验证与移除条件

实际 SDK 的 DOM 边界测试先得到 4 个有效失败，修复后 7/7；保留内部选区方向、IME 草稿、焦点回调与不同 document 的负向对照。移除诊断后的六类公式完整链与既有名称框/鼠标焦点历史均已通过 Chromium。

S5 final03 的三浏览器兼容 225、公开 running 21、自检两种模式各 12 项全部通过，单轮独立审查无问题；具体输入与原件见 S5 复核。P3 阶段门禁仍待完成。上游版本通过同一反例和边界后才能移除补丁；真实系统输入法的历史人工验收缺口仍按原账保留。
