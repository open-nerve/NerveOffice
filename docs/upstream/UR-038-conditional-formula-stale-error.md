# UR-038 条件格式公式快速修正后仍被旧错误阻止提交

> 状态：草稿，未发送上游。只核对固定 `@univerjs/sheets-conditional-formatting-ui@1.0.1` 与 `sheets-formula-ui@1.0.1` 发布包；其他版本未核对。M5-P3-S4 最终工程、三浏览器与单轮审查修正完成，见 [S4 复核](../v0.1/M5-表格能力与资源/reviews/P3-S4-表格能力逐项复核.md)。

从数据菜单新建条件格式，切换到自定义公式，输入 `=SUM(` 并确认，界面正确显示“公式错误”。立即全选改为 `=A2>4` 后确认，面板仍显示原错误，规则没有提交。

正式宿主的 `task3-diagnostic01` 记录实际公式文档是 `=A2>4\r\n`、焦点仍在 embedding_formula_editor，排除了误点与错误输入。`FormulaStyleEditor` 的 beforeSubmit 同时检查当前公式和 `formulaError`；后者是展示状态，由 FormulaEditor 的 onVerify 更新。后者的 useVerify 在初始聚焦的 500 ms 内抑制验证通知，快速改正后的旧消息没有清除，于是正确的当前文本仍被拒绝。无需延长测试等待即可复现。

本地修复让 beforeSubmit 使用当前公式的实际判定：长度大于 1、以等号开始、现有词法服务确认括号完整。错误仍显示原消息并拒绝；正确时清除消息并提交。没有删除校验、改变解析器或延长等待。ES/CJS 同步，散列与移除条件见 `patches/univer-conditional-formatting-ui.json` 和 ADR-010。

证据在主项目 `.codex/handoffs/m5-p3-20261020/s4/`：

- `task3-ui04` 与 `task3-diagnostic01`：真实失败、输入文本与命令日志。
- `task3-ui05`：17 条 Chromium 流程通过，包含空条件拒绝、不完整公式拒绝、立即修正提交、实际着色、保存重开与查看者对照。
- 同一文件的另六类条件格式覆盖新增、修改、删除、撤销重做和改值重算；最终三浏览器兼容/公开 running 均通过。实际呈现由浏览器截图取色核对，不依赖规则对象推断。

移除条件：上游实际发布包通过同样的快速修正、非法输入拒绝及条件格式完整回归，并证明提交依据当前文本；不能只因慢速输入不再失败而移除。
