# ADR-015：查看者的只读加固

> 状态：已接受｜日期：2026-09-29｜来源：M2-P3｜修订：2026-10-01，M2-P6 第 4 片复核：防火墙有效的先后前提写明并有 E2E，"搜索功能"面板与快速求和不开放，全部快捷键的回归，探针只能动态引入；2026-10-04，M3-P2：阅读与编辑的切换一律重建（需求方决定，原地切换否决），行列分隔线的拦截（DEF-027）、只读时藏起"高级查找"（DEF-028）、带图片的粘贴（DEF-035 的旁支），视图状态，真实 Safari 的页面自检

## 背景

- 00 号计划书 §6.5：Univer 的权限体系完全在客户端执行，前端只读只是体验层，写入的边界在服务端；做法是本地权限点加 mutation 防火墙，撤销与重做在执行前拦截，界面用静态配置关掉编辑入口；不用表格的 `FWorksheetPermission.setReadOnly()`，不把真实用户身份交给 SDK。
- M0-P3 报告 §5（V09）：本地权限点加防火墙，表格 28 个编辑入口在三个浏览器、含公式 Worker 模式全部被拦住；只靠权限点漏掉 9 个；进入只读不留痕迹、不写保护类资源；复制可用；单元格编辑器会往内部文档单元写内容，防火墙只拦本文档。
- M1 独立复验 N1、ADR-010：编辑器身份一律允许（ADR-009），SDK 在 Ready 与用户变化时按授权服务重设工作簿的权限点，就绪之后的 `setEditable(false)` 会被改回可编辑；M1 的只读只有这一步。
- M2 总设计 §2.1 第 1 条、§6.6：查看者从 M2 起出现（空间的查看者、全员可见、归档空间），只读加固从 M3 提前到 M2；M3 复用这套机制：阅读与编辑之间的切换一律重建编辑器（M3-P2，需求方 2026-10-04 决定），不加运行时的只读机制。

## 决策

**能不能编辑在创建编辑器时决定**：`createSheetEditor({ container, snapshot, access })`，`access` 是 `'edit' | 'read'`，编辑器页按服务端给的 `permissions.canEdit` 传入。适配层不知道"查看者""归档"这些业务概念；没有"就绪之后再设"的第二条路（去掉 `setEditable`）。

**授权服务按文档权限回答**（ADR-009 的延伸）：
- 能编辑：每个动作都允许；只能查看：只允许"查看"与"复制"，其余动作一律不允许（每个动作都给出明确的布尔值）。
- 两个动作取自 SDK 的工作簿权限点类（`WorkbookViewPermission`、`WorkbookCopyPermission` 的 `subType`），与只读守卫保留的工作表权限点是同一组定义。
- SDK 在 Ready 与用户变化时按它设置工作簿的 22 个权限点：只读的文档设出来就是只读的，不会被改回可编辑。
- 身份仍不是真实用户，不调用 `setCurrentUser`；权限数据的写入一律拒绝。

**只读守卫**（`editor/read-only/`，只读时装上）：
1. mutation 防火墙：在创建工作簿之前挂在 `BeforeCommandExecute` 上，判定与变更检测是同一个函数、同一份配置——只读时，变更检测会认作修改的一律取消。因此公式结果（带 `onlyLocal`）照常显示，单元格编辑器写内部文档单元（其他单元）不拦，排除名单里只清除界面状态的 mutation 不拦。**这道防火墙有效的前提**（M2-P6 第 4 片复核 F3）：Facade 的执行前监听要排在 SDK 自己的之前。SDK 的 `UpdateFormulaController` 在 onReady（`createWorkbook` 内部同步发生）挂上执行前监听：每条写单元格的 mutation 执行之前，它先同步执行一条带 `onlyLocal`、`fromFormula` 的嵌套 mutation，把公式写进单元格；Facade 只在第一次订阅 `BeforeCommandExecute` 时注册自己的监听。所以在 `createWorkbook` 之前就要有订阅者（由入口守卫占住，只读守卫先装后装都不影响），直到销毁订阅者不能减到零；M3 的切换一律重建，每个新实例照样在 `createWorkbook` 之前由入口守卫占住。E2E"经 Facade 直接执行写公式的 mutation"守着这条（顺序回退时内容被改，而且带 `onlyLocal`，变更检测看不见）。
2. 撤销与重做：`BeforeUndo`、`BeforeRedo` 取消（重做直接重放 mutation，绕过权限检查）；就绪时经注入器取 `IUndoRedoService` 清空撤销栈。守卫分三步装：创建工作簿之前（防火墙与撤销拦截）、工作簿创建之后（工作表权限点与图片）、就绪时（`applyRenderedGuards`：冻结线与编辑栏，渲染模块到那时才注册）。
3. 工作表的本地权限点：工作簿创建之后，每张工作表（含隐藏的）"查看""复制"之外的 16 个权限点设为不允许。没有保护规则时 SDK 不经授权服务设置它们，不会被改回来。不创建保护规则，不写保护类资源。
4. 图片设为不可编辑（`@univerjs/drawing` 的 `IDrawingManagerService.setDrawingEditable(false)`）：画图片时按它决定挂不挂变换框，默认为真，SDK 不改它。
5. 替换、"搜索功能"面板与快速求和不开放：执行前取消打开替换面板、打开"搜索功能"面板（Cmd/Ctrl+Shift+P：候选项取自功能区与右键菜单的登记，列出的都是编辑功能，关掉工具栏与右键菜单挡不住它，M2-P6 第 4 片复核 F1）与快速求和（它不检查单元格编辑器有没有打开，直接往编辑栏的内部文档写公式，只读时编辑栏会一直显示文档里没有的公式，F2）的操作；查找照常，只读时没有高级查找的选项；"高级查找"的链接只读时藏起（M3-P2，DEF-028：面板没有藏起它的开关，只读守卫在页面的 head 里加一条按 SDK 的 DOM 标记写的样式，随守卫销毁）。快捷键面板（Cmd/Ctrl+\）照常：只列快捷键，不能从那里执行。**全部已注册的快捷键有回归用例**（`read-only-shortcuts.spec.ts`）：经探针取到 SDK 当前注册的快捷键，按页面的平台换算按法，只读时逐个按，核对内容不变、没有改文档的 mutation、不发保存、没有页面错误、编辑栏与单元格的真实内容一致、没有弹出白名单之外的面板与对话框；三种选区（一个空单元格、整行、整列；有快捷键的命令里只有隐藏行、隐藏列按选区类型分支），每按一个组合都核对**确实按到了**：页面收到的按键按 SDK 的规则换算成绑定、必须等于这个组合；含无条件项的组合一定派发到命令；守卫取消的几项（打开替换、"搜索功能"、快速求和、撤销、重做）确实按到、被取消、一条都没有执行；keyCode 没有键名时直接失败（只有非苹果平台上的 `MAC_CTRL` 绑定按不出来、可以跳过，苹果平台上跳过的必须为空）；每次按键的目标在编辑器的容器里、不在组字、不落在工具栏命令或菜单里，扫完之后再按一次含无条件项的组合作哨兵；查找面板里不能有替换；开头先自检编辑栏读得出内容；两帧之后才出现的通知与面板也记进附件。能走到改文档的 mutation、按选区类型分支的只有隐藏行列。SDK 升级新增的入口由它发现。
6. 批注浮层只读：SDK 的批注浮层总是可编辑的文本框，只读时给它加上 `readOnly`、不能拖动改大小（按 SDK 的 DOM 标记 `data-u-comp="note-textarea"` 找到它，登记为内部约定）。
7. 编辑栏点不进去：工作簿不可编辑、又没有保护规则时，点编辑栏会把"正在编辑栏里""编辑器已激活"的上下文设为真，只读时复位它们的路径走不到，查找等快捷键随之失效（SDK 的缺陷）。只读时在页面的捕获阶段拦下落在编辑框与按钮上的指针事件（DOM 标记登记），编辑栏照常显示内容；另外订阅编辑器服务的聚焦，焦点落到编辑栏的编辑器时放开它并复位上下文（在别处按下、在编辑框上松开也会聚焦它，审查 A1）；放开排一个微任务，同步放开会被 SDK 之后的设光标与 React 的提交覆盖。
8. 冻结线拖不动：sheets-ui 1.0.1 定义了冻结线的权限拦截却没有注册，只读时补上（在冻结线的权限检查上注册返回不允许的拦截器，审查 B2）。
9. 行列的分隔线拖不动（M3-P2，DEF-027）：SDK 判断行高、列宽的权限时把索引 0（第 1 行、A 列）当作"没有给出"、一律放行，只读时第 1 行下沿、A 列右沿的分隔线照样显示调整的光标、拖得动（松开时被权限检查拦下、弹出只读的提示）；原来登记的"冻结区域的分隔线"是同一件事（那份样本冻结的正是第 1 行）。就绪时在行列调整控制器的拦截点 `HEADER_RESIZE_PERMISSION_CHECK` 上注册优先级 100、总是不允许的拦截器（SDK 的没有优先级；控制器在 Rendered 时才注册）。

**只读时的界面**（插件档案 v1 §5.2 的"销毁重建"）：`toolbar: false`、`contextMenu: false`；`footer.menus: false`、`footer.addSheetButtonConfig.show: false`；工作表标签的 5 项菜单隐藏。编辑栏保留：它显示当前单元格的内容，点不进去（守卫第 7 条）。权限的提示改写成只读的说法（平台不用 SDK 的保护，这些提示只在只读时出现）。

**内部 API**：`IPermissionService`、`IUndoRedoService`、工作表权限点的两份清单、`WorksheetViewPermission`、`WorksheetCopyPermission`、`WorkbookViewPermission`、`WorkbookCopyPermission`、`IDrawingManagerService`，`IEditorService`、`IContextService`、`FOCUSING_FX_BAR_EDITOR`、`DOCS_FORMULA_BAR_EDITOR_UNIT_ID_KEY`、`IRenderManagerService`、`HeaderFreezeRenderController`，以及 SDK 的两个 DOM 标记（批注浮层的文本框、编辑栏的输入部分）经 `internal-api/` 引用并登记（共 17 项），lint 的受限符号同步。M3-P2 加 2 项：`HeaderResizeRenderController`（DEF-027）、查找面板里"高级查找"那一块的 DOM 标记（DEF-028）。界面的包从第二个出口 `internal-api/ui.ts` 导出，只由主线程引用：公式 Worker 也引用 `index.ts`，而 Univer 的包没有声明 `sideEffects`，界面的包从那里再导出会整包打进 Worker（实测超出门禁 `budgets` 的预算近一倍）。

**写入的边界不变**：查看者的保存由服务端拒绝（`PERMISSION_DENIED`，ADR-011）；M3 的编辑租约与代次条件写入。

**E2E 的探针只在测试构建里**：`window.__nerveEditorProbe = { univerAPI, snapshot(), … }`，由 `createSheetEditor` 在 `import.meta.env.MODE === 'e2e'` 时动态引入。M0 的 28 个入口里 21 个只能经 Facade 触发，画布上的内容也读不出来，E2E 靠它逐项执行并比较内存里的快照。生产构建里这个分支与分块都被去掉，门禁 `artifacts` 核对分块与名字。探针模块只能经动态 `import()` 引入（lint，M2-P6 第 4 片复核 F5：改成静态引入时探针的名字会被摇树去掉，补上的插件 Facade 的副作用却留在生产构建里）；补上的 Facade 单独成块时门禁按分块名认出。补上的 Facade 只加方法，另有一个 FWorkbook 的初始化钩子（数据验证的 Facade，惰性的 getter，F6），不改变行为。探针另经登记的内部服务读快捷键清单（`IShortcutService`，只给测试构建）与编辑栏的内容（读不出来时抛错，不返回空串）。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
|---|---|---|
| A. 创建时决定 + 授权服务按文档权限回答 + 只读守卫 + 静态界面 | 采用 | M0 验证过的做法；授权服务的回答让 SDK 自己的权限初始化与只读一致 |
| B. 只在就绪之后 `setEditable(false)`（M1 的做法） | 否决 | 只管工作簿的"编辑"一项，而且 SDK 在用户变化时会把它改回来；M0 的 28 个入口里大半拦不住 |
| C. 表格的 `FWorksheetPermission.setReadOnly()` | 否决 | 要先 `protect()`，会写保护类资源、关掉复制，而且照样漏掉 9 个入口（M0-P3 报告 §5.3） |
| D. sheets-ui 的 `disableEdit` | 否决 | 初稿的顾虑：M0 没有评估过、静态配置 M3 复用不了。S3 修复编辑栏时实测：它让单元格编辑器不渲染，复制与方向键失效（US-M2-11 要求可以复制）；编辑框的外层写死了 `pointer-events: auto`，编辑栏照样点得进去，修不好编辑栏的问题 |
| D2. 只读时隐藏整个编辑栏（`formulaBar: false`） | 否决 | 查看者看不到公式的原文；拦下编辑框与按钮的指针事件就够了 |
| E. 防火墙按 M0 的条件（只看 `onlyLocal`） | 否决 | 与变更检测是两套判定；共用一个判定才有"只读时检测不到修改"的不变量。多放过的几类里，`fromCollab`、`fromChangeset` 在本平台不出现、排除名单只清除界面状态；`fromFormula` 的嵌套 mutation 会改单元格的公式，放行它安全靠的是决策第 1 条的先后（M2-P6 第 4 片复核 F7 订正） |
| F. 授权服务只关"编辑"一项（M0 的工作簿权限点） | 否决 | 只读时允许的动作越少越稳妥；阅读的功能（切换工作表、选中、复制、查找、看批注）由 E2E 覆盖，失效时按具体的动作放开 |
| G. E2E 只经界面操作，不用探针 | 否决 | 覆盖不了 21 个 Facade 入口，SDK 升级时新的入口失去回归；画布上的内容读不出来，"没有改动"无从判断 |
| H. 探针放进生产构建 | 否决 | 生产构建不能有测试钩子 |
| J. 阅读与编辑之间原地切换（M3 总设计 §6.5 的原方案） | 否决（M3-P2，需求方 2026-10-04 决定） | 以只读创建、原地进入编辑这条主路径从没验证过（M0 只验证过以编辑创建、原地进入只读再退出）；列标题悬停时的菜单按钮补不上（`HeaderMenuRenderController` 只在 Rendered 时按当时的配置注册，类不导出）；还要让 SDK 在运行时重设 22 个工作簿权限点（DEF-036）、处理撤销拦截的先后与执行栈的残留（UR-005）——每一处都是新的、没有验证过的只读机制 |
| K. 同一个实例里 `disposeUnit` 之后再 `createWorkbook`（计划书 §10.2 的原写法） | 否决（M3-P2） | 新单元不再按授权服务设权限点（默认可编辑），也不再有 Rendered，只读不完整 |
| I. 只读时用精简的插件档案（不注册编辑类的插件）（M2-P6 第 6 片复核补列） | 否决 | 插件档案决定文档能不能正确显示（条件格式、数据验证、筛选、图片等即使只读也要渲染），按文档类型固定（ADR-010），只读与编辑用两套会让同一份文档显示不同；同一份文档在阅读与编辑时的显示必须一致（M3 起切换一律重建，换档案不多一次重建，但两套档案会让切换前后的显示不同）；而且编辑类的入口不止来自插件（Facade、快捷键、SDK 内部），只拆插件挡不住，防火墙仍然要有 |

## 影响

- `@univerjs/sheets-drawing-ui` 的 `resizeImageByCell` 在渲染时直接改模型里单元格图片的尺寸、不经 mutation（M2-P6 第 4 片复核）：只读不受影响（不保存）；M3 进入编辑用的是本页载入的那一份快照（不从只读的实例里捕获），阅读时内存里的这种变化不影响编辑（M3-P2，DEF-035 关闭）。它的旁支：编辑栏在编辑时粘贴图片文件或带 `<img>` 的 HTML，会经 `doc.command.inner-paste` 把图片写进单元格，入口守卫按参数取消带图片的这条命令（整次粘贴取消，同时复制来的文字也不贴；单元格编辑器只认纯文本、表格上的粘贴不写图片，不拦；M5 开放图片时重新评估）。
- M3 的阅读与编辑一律重建（M3-P2）：每次切换销毁整个实例（含公式 Worker）、以目标的 `access` 新建，只读守卫随只读的实例装上、随它销毁，能编辑的实例里没有任何只读的残留；切换前后由适配层的视图状态（`SheetEditor.viewState()` 与 `createSheetEditor` 的 `viewState`，只用 Facade）保留当前工作表、滚动位置与主选区。原定的原地切换与它要核实的"运行时改变授权的回答"（DEF-036）不再需要，DEF-036 关闭。编辑器的容器带 `data-editor-access`（`read` 或 `edit`）。
- 编辑栏、批注浮层的处理依赖 SDK 的 DOM 标记，SDK 升级时由 `read-only.spec.ts` 回归；SDK 修好编辑栏的上下文复位之后可以去掉编辑栏的拦截。
- SDK 的一个问题（UR-005）：命令被取消、或者被 SDK 的权限检查拦下时，命令执行栈里的那一项不弹出，之后不在命令里执行的 mutation 会带上它的 id 作为触发来源；SDK 里读它的地方有好几处（例如公式的脏区判断遇到 `set-style` 一类的触发来源就不标脏）。只读时不改文档，没有可见的影响；M3 一律重建之后，只读的实例不会回到编辑，执行栈的残留随实例销毁。
- 测试构建的编辑器入口与生产构建不再逐字节相同（多一个探针的分支，补上的插件 Facade 让共用模块的分块不同，两份构建分块的个数与名字因此不一样。M3 合并之前的评审核对过：平台页面与编辑器页入口的静态引入闭包所含的模块两份构建完全相同（平台 221 个、编辑器 839 个），测试专用的模块只在动态引入的分块里；M2 时测试构建另有一个约 17 KB 的公共分块 `dist-*.js`，现在的构建里已经没有了。M3-P2 的页面自检入口页曾经带来另一处差异（共用的 `api-*.js`），已由入口页自给自足消除；跨两份构建的自动核对没有做，源头由 lint 规则 `nerve/selftest-entry-self-contained` 拦住——静态引入与动态的 `import()` 都拦，审查 B4、复验 C3）；探针不改变行为，生产镜像另有不用探针的只读冒烟用例。探针只看得到在它之前订阅的监听者设下的取消（只读守卫仍在创建时装上，M3 的重建不改变这一点）。
- 适配层从 SDK 引用新符号时，先判断它属于界面的包还是数据的包：界面的包只能进 `internal-api/ui.ts`，否则公式 Worker 会变大（门禁 `budgets` 兜底）。
- 升级 SDK：先跑内部 API 登记表的回归与 `tests/e2e/specs/editor/read-only.spec.ts`（28 个入口、对照组、界面、复制、不产生改动）、`read-only-shortcuts.spec.ts`（全部已注册的快捷键）、`edit-mode.spec.ts`（"进入再退出"之后同一套只读检查，`tests/e2e/support/read-only-checks.ts`）；再在本机真实 Safari 上跑一遍页面自检（`pnpm --filter @nerve-office/e2e run safari:selftest --front`，M3-P2 S1：测试构建的 `selftest.html` 与 `editor/testing/selftest.ts`，与 E2E 共用入口清单 `read-only-entries.ts`、`content-compare.ts`，生产构建里没有）；只读样本的收敛可以用 `pnpm --filter @nerve-office/e2e run update:read-only-sample` 重新生成。
- 文字文档有编辑器之后，只读用公开的 `setReadOnly()`（计划书 §6.5），同样由创建时的 `access` 决定。

## M3-P3 的补充

- 链接的改写器（ADR-010 的 M3-P3 补充）装在入口守卫之后、`createWorkbook` 之前，阅读与编辑都装；决策第 1 条的不变量（入口守卫先订阅、直到销毁才退订）不变——改写器只就地改写参数，不取消命令。
- 页面自检的 enter-exit 场景改用去掉图片的只读样本（M3-P3 起 `data:` 图片存不进去），图片的三个入口在这个场景里跳过：真实 Safari 上"进入再退出"之后的图片入口只由 Playwright 的 `edit-mode.spec.ts` 覆盖。
