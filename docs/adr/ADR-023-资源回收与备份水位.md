# ADR-023：资源回收与备份水位

> 状态：已接受，M5-P4-S5 已实现并通过 Step 验证；本轮 full16/container05 同源双门禁已独立接受，S6 最终来源/同 SHA CI/实际关闭仍须后续完成｜2026-10-29

## 背景与选择

图片上传由持久 reserve、事务外 publish、finalize 三段组成。按 hash 复用同一文件名时，旧回收任务可能删除新上传；只加代次虽然能隔离新文件，却无法阻止长时间暂停的旧发布重新生成已经清账的孤儿文件。

采用不可复用的代次路径、持久退休任务和永久零字节标记。新 claim 用随机 UUID；存活同图仍去重。旧文件的 generation 为空，继续用原 hash 路径，迁移不移动文件或伪造代次。上传三段携带同一 `{ sha256, generation, storageKey }` 回执，旧回执不能借新 claim 转正。

退休在私有卷中写 0600 空文件并 fsync，原子 rename 覆盖精确旧路径，再 fsync 所在目录。迟到 publish 的不覆盖式 hardlink 失败，随后完整性校验也不能把空标记当成图片。完成回执和空标记永久保留；回收图片正文占用，不承诺清空每个 inode 或元数据行。

## 引用与时间

保留判断使用当前文档与全部仍存在的检查点关系，包括归档、回收站、其他空间、删除前和升级前检查点；无读取权限不等于可回收，过期但尚未清除的关系也保守保留。上传者的严格 24 小时窗口仍受保护。

assetId 与物理对象分别从首次观察到无引用时开始完整宽限。最后一个 assetId 删除后，对象另起宽限；失败 claim 同样从首次观察开始。reserve 清除对象或 claim 的候选，finalize 也处理这期间重新出现的对象候选。代价是最后一条资源记录删除后，文件最多再保留一轮完整宽限。

数据库在当前/历史关系 INSERT 或实际更换 assetId 时，按资源和事务号追加引用活动。同一事务重复写入去重，原值 UPDATE 不算活动；不把既有共享资源锁升级为逐资源排他更新，避免多文档捕获形成反向等待。GC 按 quota → 有序资源行锁取一页，在锁下读取 Documents 的有限保留集合并消费活动；两次扫描间出现又消失的引用也会重新开始宽限。

候选时刻在引用与活动查询之后取数据库实时钟，不能用旧调度时刻或事务开始时刻倒推。引用查询不反向获取空间/文档业务锁；并发新增引用由资源锁与 FK 保证互斥。旧 RR 快照、反向多文档捕获与两个先后均须真实库验证。

## 文件与数据库接续

对象/claim 满足条件后，原事务写入身份不可变的 `asset_object_deletions`，再删除原对象/claim，费用保持。已确认提交的任务才交给事务外文件 IO；IO 前重查当前备份政策、代次与没有存活同路径的事实。

文件同步完成后，另开 quota → task 短事务；首次 pending → completed 才释放字节并记录审计。身份及完成时间不能改写，未知提交先重读，失败不盲目补偿。配额不变量为：完整对象 + 持久预留 + 未完成退休任务；记录配额等于 assets 条数。

Jobs 组合 Assets 与 Documents，GC/保留服务不开放给 HTTP 或其他业务入口。整轮会话 advisory lock 防跨实例重复调度，按固定上界和有界页推进；失败停止本轮，下轮从持久状态继续。SIGTERM 完成手上文件及确认后停止，SIGKILL 留下的短事务和私有临时文件由重启接续。资源 GC 单独启用需要至少 2 个池连接，与回收站自动清理同时启用需要至少 3 个；配置在启动时拒绝不足的值。

## 备份与部署边界

GC 默认开启候选整理；备份保留期和恢复水位无默认值。宽限不得短于保留期。删除还要求候选经过完整宽限且严格早于恢复水位；水位相等仍保留。缺声明、未来水位或水位晚于“数据库当前时间减保留期”，均只整理候选，不删除资源记录、不排新任务，也不执行已有待办文件 IO。

水位由运维核实全部保留备份和 WAL 的恢复范围后统一声明。日期格式检查不能证明外部备份，不能用“现在”代替证据，M7 自动备份与恢复演练仍未完成。变更备份策略前暂停所有实例的 GC，核实后统一更新配置并重启；恢复数据库前停止所有旧应用，数据库与资源卷必须配套恢复。

首次上线代次路径前，停止全部旧实例，再迁移、启用新程序。旧二进制不能读取新路径，这次变更不支持新旧实例混跑。所有回收验证只用隔离测试库/私有卷；不得对真实用户目录试运行删除或手工移除回执、标记。

实现和逐项证据见 [S5 规则](../v0.1/M5-表格能力与资源/specs/P4-S5-资源回收与备份水位.md)与 [S5 计划](../v0.1/M5-表格能力与资源/plans/P4-S5-资源回收与备份水位.md)；S6 当前与历史结果统一见[最终验收记录](../v0.1/M5-表格能力与资源/reviews/P4-S6-最终CI与关闭复核.md)。本次结果同步不改变上述 GC、备份与部署决策。

## 附录：M5-P7 审查修复（2026-11-05，S14 修订 2026-11-06）

### 引用只为新出现的图片标识授权（D-01，M5R-I-02）

原规则在每次真实保存时，按保存人的权限重新判断正文里的全部标识。甲在共享文档 D 里写入自己读不到的地址 A，D 不建立关系；之后能读到 A 的乙改了 D 的任意一格并保存，D 就为 A 建立了当前引用，D 的全部读者从此都能读到 A，撤权与历史隐私对图片失效。需求方选择方案 (a)：

- **记下未登记的标识**：每版修订在 `document_revisions.unlinked_asset_ids` 记下这一版正文里存在、却没有登记关系的标识（含未授权与未知的），去重排序，通常为空数组（迁移 0039，可空，带 CHECK）。存量为空表示“未知”，不回填。五个写入点都写：保存与另存为副本取“提取到的标识减去这一次授权的”，新建取模板（为空），普通复制照搬源当前修订，历史恢复取“历史校验时提取到的标识减去检查点的关系”。
- **按基准排除**：基准版本里未登记的标识，任何人这一次写入都不升级；其余标识照上文原规则授权（已登记在本次允许的文档上、有资格查看的历史、本人上传窗口）。删除后再引入的不在基准里，由引入它的人证明来源。资源行仍对全部标识取共享锁。
- **基准的取法**（锁下）：请求所基于的修订，其次当前修订；存量修订缺这一列时在主进程解析当前正文、减去当前已登记的关系；解析不了时当作没有未登记的标识并记警告，这一次等于沿用旧语义。
- **另存为副本**以草稿所基于的修订为基准：契约新增可选 `baseRevision`，只在给出时计入请求摘要，不给时与旧请求逐字节相同；缺省或那一版已不存在时退回源当前版本。修订按创建时间清理（默认 30 天，当前修订不删），草稿所基于的旧修订若已被后来的保存覆盖并过了保留期，只能退回源当前版本，这时的残余与下文已知限制同类。这条跨模块接线（契约、页面、服务端）超出了 P7 设计原写的“副本取源文档当前版本”，S14 停点经需求方追认：冲突副本是系统流程里“不知情”的路径，与 I-02 同性质；客户端改传别的基准，也得不到比“把图片复制进新文档”（见下文已知限制）更多的能力。

**为什么只记未登记的部分**（S14 审查 B1、B3）：S5 最初记的是完整集合，沿用的标识以“此刻登记在基准文档上”判定。副本以较早的修订为基准时，那一版已登记、之后被他人删掉的图片会被直接丢掉，副本的读者看到 404；七万引用的文档每次自动保存还要写约 1.1 MB 的数组，并至少保留 30 天。只记未登记的部分之后，副本里那张图照原规则重新证明（本人上传窗口、可查看的历史等），修订行在常见情况下没有额外开销。

代价：同一用户后来才取得读权、再保存时，旧标识不会自动取得关系，需要删除后重新插入。读取授权与 GC 的保留判断不变；没有登记关系的地址照常留在正文，不取得读取资格。回归见 `asset-save.test.ts` 的 D-01 用例（含 B1 的副本用例）与 `image-policy.spec.ts` 的预埋 E2E。

**已知限制（S14 审查 B2，需求方接受）**：方案 (a) 只在同一份文档的版本链上比较。能看见某张图片的人把含该地址的内容复制进另一份文档，或用含该地址的 CSV 新建文档时，地址在新文档里是新出现的，按他的权限登记。这等于他把自己能看见的图片分享了出去，与“能看见图片的人把它插进别的文档”的正常分享语义一致。报告里的方案 (b)（按文档上下文授权读取）与 (c)（新增共享前确认）才能区分“只有自己看得见”，本版不做。

### 单个文件任务的存储失败不再卡住回收（M5R-M-02）

文件 IO 阶段按任务号推进。某个任务的存储失败原先结束整轮，下一轮又从同一个最小任务号开始，全部物理回收永远卡在它上面。现在只对 `AssetStorageError`（路径类型、权限、属主不符或稳定的 IO 错误）：

- 记任务号与有界原因、保留待办，接着处理后面的任务，本轮结局记为 `partial`；
- 每轮逐条告警最多 5 条，之后只计入本轮结束日志的 `failedTasks`，整卷故障时不会刷出与待办等量的告警；
- 数据库与状态类异常仍结束本轮（`failed`），下轮从持久状态继续。

处置写在 `deploy/README.md`：按告警里的任务号查到存储键，把该路径恢复为应用用户所有的私有普通文件，下一轮自动接续；不手工删除回执或标记。

### 被恢复水位挡住时给出观测（D-05，M5R-M-03）

水位仍由运维静态声明，应用不自动推进。宽限已满、只因候选时刻不早于恢复水位而不能回收的资源记录、对象与文件任务，每轮分别计入 `blockedAssets`、`blockedObjects`、`blockedTasks`，任一非零时告警，提示随备份轮换推进 `NERVE_ASSET_GC_RECOVERY_BEFORE`；文件任务因此暂停时，暂停原因为 `recovery-blocked`。判定与可回收条件互补：宽限已满、且候选时刻不早于水位（相等仍保留，与上文一致）。推进水位的步骤与观测方法见 `deploy/README.md`。
