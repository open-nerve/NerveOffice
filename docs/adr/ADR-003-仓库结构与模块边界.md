# ADR-003：仓库结构与模块边界的强制方式

> 状态：已接受｜日期：2026-09-26｜来源：M1-P1

## 背景

- 00 号计划书 §9.4 给出了目录结构：`apps/web`、`apps/api`、`packages/contracts`、`tests/`、`deploy/`。
- 规范 §1 要求模块边界由工具强制：
  - 只有编辑器适配层能引用 Univer；
  - 平台页面的包里没有编辑器；
  - 模块之间只经公开入口依赖；
  - 没有循环依赖。
- 仓库还需要一个地方存放自己的工具：质量门禁、故事对照、提交钩子与 `verify`。
- contracts 同时供浏览器（Vite 打包）与 Node（NestJS）使用。Node 不对 `node_modules` 里的文件做类型剥离，所以 Node 运行时只能读构建产物。

## 决策

**目录**（在 §9.4 的基础上）：

| 目录 | 包名 | 说明 |
|---|---|---|
| `apps/web` | `@nerve-office/web` | 前端。`src/` 是浏览器代码（`tsconfig.app.json`）；`build/` 是在 Node 里运行的构建插件，与 `vite.config.ts` 一起用 `tsconfig.node.json` |
| `apps/api` | `@nerve-office/api` | 后端（M1-P2 建立） |
| `packages/contracts` | `@nerve-office/contracts` | 前后端共享的结构与错误码 |
| `tools` | `@nerve-office/tools` | 仓库工具：门禁、故事对照、提交钩子、`verify`；Node 24 直接运行 TypeScript，不需要构建 |
| `tests/integration` | `@nerve-office/integration-tests` | 基于真实 PostgreSQL 的集成测试 |
| `tests/e2e` | `@nerve-office/e2e` | Playwright，用例放在 `tests/e2e/specs/<模块>/` |
| `tests/stories.json` | — | 当前 M 的用户故事登记表，由 `gate:stories` 与 M 总设计、测试标题对照 |
| `deploy/dev` | — | 开发用的编排（PostgreSQL） |

`spikes/` 与 `refer/` 不属于 workspace。

**模块系统**：
- 所有包都是 ESM，相对导入写 `.ts`/`.tsx` 扩展名；构建时 TypeScript 改写为 `.js`（`rewriteRelativeImportExtensions`）。
- contracts 的导出带自定义条件 `@nerve-office/source`，指向源码；TypeScript（`customConditions`）、Vite、Vitest 与 ESLint 的解析器都使用这个条件，开发时不需要先构建。
- contracts 的默认条件指向 `dist/`（`tsc -p tsconfig.build.json` 的产物），供 Node 运行时使用。

**边界的强制方式**：

| 规则 | 工具 |
|---|---|
| `@univerjs/*` 只能在 `apps/web/src/editor/` 下引用；任何位置都不能引用 `@univerjs-pro/*` | ESLint `no-restricted-imports`（静态导入与再导出）与 `no-restricted-syntax`（动态导入；动态导入的路径必须是字面量），按路径分别配置 |
| 元素之间的依赖方向：contracts 不依赖内部包；web 按入口、应用、功能、共享、编辑器分层；平台页面的入口不引用编辑器 | eslint-plugin-boundaries 7（`boundaries/dependencies`，默认禁止） |
| 跨元素只经公开入口：contracts、功能模块与编辑器只能引用对方的 `index.ts`；应用层与共享层是被组合的一方，可以直接引用 | 同上，策略里的 `fileInternalPath` |
| 元素目录里没有"无主"文件，引用的目标都属于某个元素（否则可以借中转文件绕过边界） | `boundaries/no-unknown-files`、`boundaries/no-unknown-dependencies` |
| 没有循环依赖 | eslint-plugin-import-x 的 `no-cycle`；要声明 TypeScript 的扩展名与解析器，否则它看不到 `.ts` 之间的引用 |
| 只有编辑器适配层能用 Univer 的内部 API | 受限符号清单，P4 引入 Univer 时建立 |
| 上面这些规则确实生效 | `tools/src/lint/lint-rules.test.ts` 用违规代码与按路径计算出的配置逐条自测；需要"被引用的目标"时临时创建探针文件 |

后端的元素与策略（模块只经 `index.ts` 对外、只有仓储访问数据库、一个模块的仓储只被这个模块使用）在 M1-P2 建立 `apps/api` 时加入同一份配置。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
|---|---|---|
| A. eslint-plugin-boundaries + 受限导入 + import-x 查循环 | 采用 | 与 opennerve 一致；违规在编辑器里立即可见；规则写在同一份 ESLint 配置里 |
| B. dependency-cruiser | 否决 | 多一套配置与一个工具；它的优势是可视化依赖图，目前不需要 |
| C. 仓库工具放在根目录的 `scripts/` | 否决 | 工具需要自己的依赖、类型检查与单元测试（门禁的自测就是 US-M1-11），作为 workspace 的一个包更清楚 |
| D. contracts 只提供构建产物 | 否决 | 开发时每改一次都要先构建，容易读到旧的产物 |

## 影响

- 新增模块时，在 `eslint.config.ts` 里声明元素与允许的依赖，并在 lint 自测里加一条违规样例。
- 元素之外的文件（根目录与各包根目录下的配置文件）不在边界检查的范围里；配置文件只引用构建工具与构建插件。
- 新增的 E2E 用例放在 `tests/e2e/specs/<模块>/`，标题以故事编号开头。
