# ADR-026：M5 阶段接续与集中验收

- 日期：2026-11-02
- 状态：需求方已批准，仅适用于 M5-P5 → P6
- 依据：用户确认“OK，同意，按照你推荐的推进节奏继续”；批准的是 P5 本地工程收尾、P6 统一全量验收与推送。

## 背景与选择

P5 的 CSV 实现、三浏览器专项、生产容器公开故事及源码独审已有结果。full04 的产品测试完成，但报告处理使整个门禁失败；full05 又在 WindowServer 桌面会话中断期间失败。随后修复的报告扫描和会话停测机制已有独立增量审查及小型回归。不能把任一失败轮改写为全量通过。

原流程要求每个 Phase 合并前完整本机门禁，推送后完整 CI。P6 本身紧接 P5 进行 M5 整体收尾，需求方决定将这两次全量验收集中到 P6。

备选方案是 P5 只省本机长测、仍推送并运行远端完整 CI；它保留每次远端 main 完整验收，但仍会与 P6 重复。需求方选择集中验收：P5 在完成下述工程检查后合入本地 main，暂缓推送；P6 从该 main 建唯一分支，最终统一全量验收和推送。CI 工作流与触发条件不改，不使用跳过钩子或跳过 CI 的提交标记。

## P5 工程接续条件

1. 逐项核对既有专项、源码独审与修复结果，绑定实际受测源码和当前源码；旧结果只证明对应输入。产品代码、锁文件、补丁和浏览器测试相对 full04 的一致性须有实际证明，测试基础设施增量单独列出。
2. 在当前输入上运行受管 `pnpm verify --fast --audit`，覆盖 lint、类型、单元、静态门禁及本次未完成的依赖审计；最后测试基础设施增量使用已验证且摘要一致的 393 项资源机制及 10 项外层模拟证明。不为文档落档重复创建浏览器环境。
3. 本次规则、证据边界与接续记录经独立审查；必要问题修复并复验。所有测试资源、敏感原件和唯一证据在工作区退役前明确安置。
4. 正常中文提交，在主目录 main 执行 `--no-ff` 本地合并，核对合并树与受审 Phase tip 一致。主目录不切分支，不推送。
5. 状态仅称“P5 工程完成，M5 整体验收并入 P6”。本地 main 暂为未完成整体发布验收的开发集成状态；远端 main 保持既有 P4 版本。旧完整失败、缺失退出码、环境欠账不改写。

## P6 与最终交付

P6 使用从本地 main 创建的唯一分支/worktree，盘点 US-M5-01–14、插件档案、组合流程、原生环境缺口及已有待办。改动相关回归和代码审查仍逐步执行；权限、保存、迁移或其他公共机制改变时提前扩大影响范围检查，已发现产品缺陷不能移作环境欠账。

最终实际源码仍须完成原完整 Gate、完整生产容器、原浏览器矩阵、原预算和同最终 main SHA CI，并审查和冻结证据。真实 Safari 与既有环境缺口沿原批准范围单列，不以 Linux WebKit 代替原生证据。只有相应退出条件实际满足才可关闭 M5 或打标。

WindowServer 首次崩溃根因仍未知。节奏调整允许继续不依赖长测的工程工作，不证明长测安全，也不自动解除 `needs-attention`。恢复前先确定有界对照或隔离执行方式、重新固定测试输入；不能因会话保护模拟通过直接重跑完整浏览器。

## 适用范围与代价

本决定覆盖工程规范 §9/§10.2、CLAUDE 的 P5 合并推送时序、M5 总设计及 P5-S6 旧计划的冲突条款；主目录 main、每 Phase 一个分支、正常 hooks、资源清理与最终质量要求保持。

本次不全局改变其他里程碑的门禁。代价是 P5 本地合并至 M5 最终验收之间，跨模块回归可能更晚发现，且新提交尚无远端备份；如 P6 不能短期接续，须重新评估该窗口，不能无限期积累未验收改动。过程回执区分工程接续、全量验收、推送与实际关闭，不共用一个“已通过”标记。
