# ADR-008：平台前端的基础与界面组件库

> 状态：已接受｜日期：2026-09-26｜来源：M1-P3｜修订：2026-09-27，P3 审查之后改为会话结束整页跳转、加上多标签页的处理；2026-09-28，M2-P1：管理界面按需加载与首屏、会话复核给组件用、系统管理员接口的元数据、程序打开的弹窗还焦点；2026-09-30，M2-P6 复验 N3：得到 `SESSION_EXPIRED` 先向服务端确认会话，还是同一个人就不离开；2026-10-01，M2-P6 第 5 片复核：带 requestId 的新建共用记账、`PERMISSION_DENIED` 一律显示服务端说明、人名组件（登录名在前）、焦点兜底与页面标题、按需加载失败的边界、成员角色确认才保存、写操作结果未知的共用做法、重放的标记、文案按范围拆分（首屏 169.5 KiB）；2026-10-02，M2-P6 第 5 片第三、四批：人名的登录名与显示名同样醒目（需求方决定）、结果未知之后刷新的时限与成败并覆盖全部写操作、会话复核带原因、门禁限定平台页面首屏的文件数、按钮图标的尺寸规则生效（首屏 170.2 KiB）；第五批：刷新只按列表计成败、后台刷新晚到时改回说法、先取消在路上的请求，修改密码与停用自己的结果未知带原因复核会话（首屏 170.6 KiB）

## 背景

- M1 总设计 §2.1 第 3 条：平台界面用 shadcn/ui（Radix + Tailwind CSS），代码放进仓库。
- 规范 §2.4 的要求：
  - 服务端数据经统一的请求层获取；
  - 每个数据视图处理加载中、空、失败、无权限四种状态，异步操作防止重复提交；
  - 界面文字集中管理；
  - 可访问性（标签、键盘、可读的名称）。
- 定稿的 CSP：`script-src 'self'`（没有 `'unsafe-eval'`），`style-src 'self' 'unsafe-inline'`，`font-src 'self'`，不从第三方加载任何资源（00 号计划书 §11.3、§11.5）。
- 规范 §11：每个前端入口的首屏 JS 有体积预算，在建立入口的 Phase 里定下。
- 平台页面与编辑器页是两个入口，编辑器整页加载（M1 总设计 §6.1）。本 ADR 只管平台页面。

## 决策

**路由**：React Router 8。
- 只用数据路由的库模式（`createBrowserRouter`），不用框架模式与服务端渲染。
- 路由表只写组件（`Component`、`ErrorBoundary`），不含 JSX，测试用同一张表建内存路由。
- 除登录页以外的地址（包括 404）都在需要登录的外层路由之下：未登录时先转到登录页。
- 路由、请求缓存与会话的全局处理组成"运行时"，在入口的 `mount.tsx` 里、React 之外建一次（StrictMode 下不会建两份）。

**服务端数据**：TanStack Query 5。
- 加载、失败、重试与缓存由它管理，页面按它给出的状态显示。
- 重试策略：只有网络失败与 5xx 重试一次（会话查询也一样）；4xx 重试也没用，不重试。
- 查询与变更都是 `networkMode: 'always'`：不按 `navigator.onLine` 挂起，断网时照常失败，由请求层归为网络错误显示出来（P3 审查 B4：默认的挂起让退出一直停在"正在退出"，请求根本没发出去，会话仍然有效）。
- **会话结束**：任何查询或变更得到 `UNAUTHENTICATED`、`SESSION_EXPIRED`，以及退出成功（或退出时会话已经不在了）时，离开前清掉 CSRF 令牌，**整页**转到登录页（`location.replace`，替换历史记录），登录后回到原来的地址（只接受站内地址，拒绝控制字符与空白，按同源解析）。
  - 不在单页里清空缓存再切换路由（P3 审查 B7）：还挂着的组件会在缓存清空后立即重新请求；整页跳转让上一个会话的数据与令牌随页面丢弃。P4 的编辑器页是另一个入口，会话结束时同样整页跳转。
  - `SESSION_EXPIRED` 先确认（2026-09-30，M2-P6 复验 N3）：这个请求带的可能是换令牌之前的旧 Cookie（本页或别的标签页刚修改了密码、刚重新登录，服务端这时不清除 Cookie，ADR-007），浏览器里已经是新的。所以先向服务端确认现在是谁：还是同一个人，换上新的会话与 CSRF 令牌、页面不动（发出请求的组件照常显示它的错误——"登录状态刚刚变化，这次操作没有完成，请重试"——不自动重试）；换了人，整页重新加载；已经没有会话，才按原来的原因（已过期）转到登录页。只有在得到它之后才开始的那一轮确认能下结论（更早的一轮带的可能还是旧 Cookie）；本页的登录、修改密码还在进行时，**每一轮**确认都先等它结束（它的响应带着新的 Cookie；没有进行中的变更时照常同步发出）；等待按变更开始的时间计上限 40 秒（两次哈希排队、语句与取连接的超时合计，是通常的最坏情形：语句与等锁的时限按每条语句计，严格的最坏会更长，复验 一般-1、一般-2 与第三轮 一般-F），到上限照常确认。确认还没结束时又有请求得到"未登录"（过期那次的响应已清除 Cookie），离开时沿用"已过期"的原因（复验 建议-1）。编辑器页载入时仍直接转到登录页（登录页认得出新会话、会送回来），它的保存路径本来就先确认。
  - 退出得到 `SESSION_EXPIRED`（同一个浏览器刚换了令牌，退出带的是旧令牌）：确认一次，还是同一个人就带新令牌再退出一次，不循环；确认或再退出失败时提示"退出失败"、可以重试，不在还可能登录着的时候假装已经退出（复验 一般-4）。确认那一步断网、别的标签页的消息也没能换上新令牌时，页面上的 CSRF 令牌还是旧的：重试先得到"页面已失效"，全局处理随即换上新令牌，再重试才退出成功（第三轮复验 一般-D，两处同时断网才会出现，结果看得见、能自己恢复）。组件经 `AdoptRenewedSessionContext`（`shared/lib/renewed-session.ts`，运行时提供）拿到"确认并换上新会话"这一步。
  - 请求用元数据声明与会话的关系：`handlesAuthentication`（自己处理未登录：会话、登录），`session: 'starts' | 'renews' | 'ends'`（登录；修改密码，M2-P6 复核 B1 起它换掉当前会话的令牌；退出），`expiredReason`（这个请求得到"登录已过期"时登录页的说明，修改密码的结果未知之后再提交时是 `password_changed`，M2-P6 复核 G-1）。"登录已过期"先确认时，本页进行中的 `starts`、`renews` 先等它结束（复验 N3）。
- **多个标签页**（P3 审查 B6）：会话 Cookie 各标签页共用，一个标签页换了人，别的标签页还拿着上一个会话的页面与 CSRF 令牌。
  - 登录与退出经 `BroadcastChannel`（`nerve-office:session`，消息不带内容）通知其他标签页；
  - 收到消息，或者状态变更的请求得到 `CSRF_TOKEN_INVALID` 时（消息可能没送达，这个信号可靠），向服务端确认现在是谁：同一个人，只换上新的会话与令牌，页面不动；换了人或已退出，整页重新加载。
  - M2-P1 起另有两种情形也这样确认：只给系统管理员的请求（元数据 `systemAdminOnly`，对应服务端的 `@SystemAdminOnly()`）得到 `PERMISSION_DENIED`，说明页面显示的系统角色已经过时；组件改了本人的账户（取消自己的系统管理员、停用自己），经 `SessionRecheckContext` 调用同一个确认。不直接让会话查询失效：会话已经不在时它会拿着缓存里的旧会话，与需要登录的外层路由来回跳转；别的标签页换了人时还会悄悄换成那个人。
  - 一次性链接的公开页面（`/invite`、`/reset-password`）不因别的标签页换了人而重新加载：它不显示任何人的数据，令牌读出之后已经从地址里去掉，重新加载只能显示"链接无效"。跳过的复核记下来，路由离开公开页面时补上（接受或完成之后单页进入个人空间时）。
  - 登录页只认没有失败的会话查询：重新请求得到未登录时，缓存里仍留着上一次的会话，不能按它跳回原来的页面。

**请求层**（`shared/api`）：
- 同源请求（`credentials: 'same-origin'`）；状态变更的请求带 `X-CSRF-Token`。令牌由登录与会话接口给出，只放在内存里。
- 错误分三类：
  - `ApiError`：服务端按约定返回的错误，带错误码、请求标识与 `Retry-After`；
  - `NetworkError`：请求没能到达服务端，或者没收到响应；
  - `ResponseFormatError`：成功的响应与契约不一致。
- 成功的响应也用 contracts 的结构校验：接口与前端不一致时立即暴露，不渲染出错的数据。

**样式与组件**：Tailwind CSS 4，加上 shadcn/ui 的 Radix 版本（`radix-nova` 风格）。
- 组件代码取自 shadcn/ui 4.21.0 的生成结果，放进 `shared/ui`，按项目规范改写：单引号、不写分号、`import type`。属性选择器里不写引号（`[class*=size-]`）：Tailwind 扫描源码时会把转义的引号连同反斜杠读进去，生成的规则永远匹配不上（M2-P6 第 5 片发现，按钮里的图标原来都是 24px）；`buttonVariants` 输出经 tailwind-merge 合并之后的类名，直接用它的链接也不会两条尺寸规则同时生效（可见的变化：按钮里的图标回到设计的 16px、小号 14px；小号链接的圆角 10→8px；outline 样式的链接从透明边框变成有边框，与同样式的按钮一致，例如空间页的"成员""打开回收站"）。
- 不采用生成结果带来的三样东西：
  - `cn` 包：刚发布的新包，改用成熟的 `clsx` 加 `tailwind-merge` 自己写 `cn()`；
  - CLI 包自带的 `shadcn/tailwind.css`：只有几条自定义变体，需要时抄进自己的样式；
  - Geist 字体：OFL-1.1 许可不在生产依赖的白名单里，也没有中文字形。改用系统字体，不加载字体文件。
- 只有浅色主题；深色主题等需要时再加。
- `shared/ui` 的桶文件不导出带第三方运行时的重组件（弹窗：Radix Dialog，约 12 KiB gzip），用到的地方直接引用它的文件。web 没有声明 `sideEffects`（zod-jitless 与样式都有副作用，不能笼统声明），经桶文件引用会把它再导出的每个模块都带进首屏（M2-P1 审查 B2）。lint 按解析之后的路径守护：`shared` 里除它自己以外的文件都不能引用 `shared/ui/dialog.tsx`（`import-x/no-restricted-paths`，中转与换写法都拦得住）。
- 程序打开的弹窗关闭之后，焦点不能落到 body（Radix 的模态弹窗只把焦点还给 `DialogTrigger`，M2-P1 审查 B9）：确认的弹窗回到打开之前有焦点的元素，它已经不在了（随操作消失的按钮）时由页面给出去处（`DialogContent` 的 `fallbackFocus`）；签发的链接的弹窗一律交给页面指定的元素（签发表单的登录名、新的那一行）。无权限的说明出现时焦点在 body（取消了自己的系统管理员、管理页连同弹窗一起卸载；成员直接打开管理界面），焦点交给这条说明；焦点在别处（例如页头）时不抢。
- 组件没有内联脚本；内联样式来自 Radix，由 CSP 的 `style-src 'unsafe-inline'` 放行（M0 定稿时已为主题变量保留）。

**zod 与 CSP**：
- zod 4 的 JIT 有两段动态代码：
  - `Function('')` 探测：看能否执行动态代码；
  - 编译器 `Doc.compile`：为对象结构生成解析函数。
- zod 在**创建结构时**就读取 jitless，而 contracts 的结构在模块求值时就建好了。所以设置 jitless 的模块必须是入口**第一个引入**的模块，早于任何结构的创建；在入口的函数体里设置已经晚了（P3 审查 B1：每次整页加载都有一条 CSP 违规，浏览器不写进控制台）。
- 做法：有副作用的模块 `shared/lib/zod-jitless.ts`，作为每个入口的第一个导入；入口文件只写副作用导入（导入排序规则把副作用导入排在普通导入之后、不调整它们之间的先后，写在入口里的顺序就是执行的顺序）。P4 的编辑器入口同样第一个导入它。这两条由 lint 规则保证（`entries/*/main.{ts,tsx}` 只能写副作用导入，第一个必须是 zod-jitless；CSP 阳性对照的入口除外）。
- 这样两段代码都执行不到。门禁 `artifacts` 把它们登记为"已登记的动态代码"，各限 1 次；万一执行，CSP 里没有 `'unsafe-eval'`，浏览器会拦下。
- 打包器的 `strictExecutionOrder` 暂不开启：两个入口共用 contracts 的实验里，只要每个入口都先导入 zod-jitless，默认模式就没有违规；开启要多约 3.5 KiB 与一个运行时块。某个入口忘了导入时，E2E 的违规收集会报出来。P4 加编辑器入口时按实测再定。
- E2E 收集每个页面的 `securitypolicyviolation` 事件，用例结束时断言为空（阳性对照的用例除外）。

**界面文字**：集中在 `shared/i18n/zh-cn/`（M2-P6 起按范围分文件：首屏的 `messages.ts` 含错误码的文案表；管理界面、成员、同事选择、回收站、搜索结果页、编辑器各一个文件，只有对应的功能与测试能引用，lint 限定，不进平台页面的首屏）。
- 界面按错误码显示这里的文字，服务端的说明只是默认值；
- 前端还不认识的错误码（服务端比前端新）用服务端的说明。

**构建**：不注入 modulepreload 的补丁（目标浏览器都原生支持），测试构建与生产构建的平台入口块逐字节相同。

**首屏体积预算**：平台页面入口的首屏 JS（gzip）为 180 KiB，由门禁 `budgets` 检查；M2-P6 起另限定平台页面的首屏文件数不超过 2 个（共用模块经桶文件被编辑器入口一起引用时，打包会多拆出小块，体积还在预算内，门禁原来发现不了）。
- M1-P3 收尾时门禁实测 147.7 KiB，预算比实测多约 22%。主要构成：react-dom 65、React Router 31、contracts 与 zod 26、TanStack Query 11、tailwind-merge 9、应用代码 7。
- 以后需要瘦身时，可以按路由懒加载，或者让 contracts 改用 `zod/mini`。
- M2-P1 起管理界面按路由懒加载：只有 `app/routes.ts` 动态 `import()` 它的公开入口，lint 禁止其他引用（静态、类型、再导出、别处的动态引用）。懒加载的路由在初始匹配里时，需要登录的外层路由用 `HydrateFallback` 显示会话检查的等待状态，页头按路由的导航状态显示进行中。M2-P1 收尾时平台页面首屏 156.4 KiB。
- M2-P2 起成员页（`features/members`）同样只由路由表动态引用；确认的弹窗（带 Radix Dialog）挪到 `features/confirmation`，由管理界面与成员页共用，lint 只允许这两个按需加载的功能引用它；按关键词选一项（`features/colleagues`：按名字选同事、按名称选团队空间）只被它们引用。弹窗文件本身（`shared/ui/dialog.tsx`）也由 lint 限定：只有这两个功能与 `features/confirmation` 能引用，首屏的功能、应用层与入口直接引用会报错（M2-P2 审查 B8：首屏还有余量，预算门禁发现不了）；弹窗类的 Radix 原语只在这个文件里引入，这条对 web 的全部文件生效，命名空间导入与 `export *` 同样拦下（复验）。这几条只管平台页面：编辑器页是另一个包，有自己的预算。左侧导航与空间页进首屏，窄屏时收起、不用弹窗。成员的接口函数与空间的放在一起（`features/spaces`，成员页与管理界面共用），随首屏加载，几百字节。M2-P2 收尾时平台页面首屏 161.6 KiB。
- 请求缓存的约定（M2-P2 审查 B1）：TanStack Query 在重新请求失败时保留上一次的数据，页面先看错误、再看数据；空间看不到了（404）时刷新导航、去掉这个空间的缓存，下次进来不先闪出旧的内容。页内的操作按访问权限被拒绝（403、404）时，页面显示的权限已经过时，让空间的查询失效重新请求（复验）。
- 错误说明的例外（M2-P2 复验）：界面按错误码显示自己的文字，服务端的说明只是默认值；但"看得到却不能做"（`PERMISSION_DENIED`）的原因取决于服务端的状态、界面自己判断不了时（例如成员页：前端只有地址里的空间 id，不知道它是个人空间），页面显示服务端这次给出的说明（ADR-006：服务端的说明只写面向用户的内容），不给重试。M2-P6 第 5 片之后不止成员页：`PERMISSION_DENIED` 一律显示服务端的说明（见下）。

**M2-P6 第 5 片复核之后的约定**：
- **带 `requestId` 的新建**（新建表格、新建文件夹、复制）共用一份请求标识的记账（`shared/api/request-ids.ts`，页面一份，由运行时持有、经上下文给组件），按"这件事"（在哪里建、复制到哪里）记：成功、或者与载荷有关的确定拒绝才换新；结果未知、服务端繁忙（503）、会话类的拒绝（未登录、登录已过期、CSRF）都保留原来的 id；结果未知之后得到 `REQUEST_ID_CONFLICT`，按"上一次可能已经建好"说明并刷新列表。原来各写各的：新建文件夹失败时从不换新（改了名字再提交就死循环在 409），新建表格与复制遇到会话类的 4xx 就换新（可能多建一份）。
- **不带 `requestId` 的写操作**在结果未知时先刷新相关的查询、再说明"可能已经生效"，经共用的 `shared/api/write-outcome.ts` 与确认框必填的 `refresh`：删除、移动、成员的变更、停用与启用、系统角色、解除锁定、归档与恢复、全员可见、作废邀请、永久删除、转移、生成重置链接等；之后的 409、404 给出对应的引导（转移之后的冲突说"多半是你上一次的转移已经完成"）。**重放**：服务端在幂等重放时带 `replayed`（新建文档、复制、新建文件夹），界面据此说"上一次其实已经完成"并结束这一项的记账——否则结果未知的那一项留到页面结束，事后真想再建一份时被当成重试。`request-ids.ts`、`write-outcome.ts` 不经 `shared/api` 的桶文件转出、按路径引用（编辑器页也引用那个桶文件，经它转出时打包会多拆出两个小块，平台页面首屏多约 1.5 KiB；lint 防回退）。给自己生成重置链接的结果未知，登录页另说明"你的密码可能已经失效"。
- **"看得到却不能做"（`PERMISSION_DENIED`）一律显示服务端这次给出的说明**（原来只有成员列表这样做，归档空间里保存时只说"没有权限"）；错误码到文案的表在编译期就要求每个错误码都有文字（服务端说明的那几个单独列出）；`CSRF_TOKEN_INVALID` 说"请再试一次"（全局处理已经换上新令牌，刷新反而丢掉输入）。
- **人名**由 `PersonName` 组件显示，**登录名在前**：登录名在自己的元素里（等宽字体、前面带 `@`；需求方 2026-10-02 决定与显示名同样醒目：颜色、字号、粗细都与显示名相同），后面是用 `<bdi>` 隔离的显示名；纯文字的地方（`aria-label`、确认框的标题）同样是"@登录名 ⁨显示名⁩"（FSI…PDI 隔离）。登录名只含 `[a-z0-9._-]`、全库唯一，显示名的任何内容都只能排在它后面，冒充不了开头（复验发现显示名在前时可以写成"李四 @lisi"冒充）；看到的与读出来的是同一串（WCAG 2.5.3）。从右到左的显示名也不会打乱相邻的文字。审计的对象名改为结构化返回（`target.user`），由前端用同一个组件渲染。需求方 2026-10-01 决定：显示名里不禁止括号，只靠界面区分。
- **结果未知之后的刷新**最多等 10 秒（`refreshWithin`），超时先给说明、刷新在后台继续；刷新改用会抛出失败的 `refreshQueries`，说明区分"已按服务端现在的状态刷新"与"页面没能刷新"。共用的做法覆盖全部写操作（第四批：`refreshIfUnknown` 的 `also` 认出"上一次多半已经生效"的拒绝——已经是成员、已有同名、登录名已被占用、上一次已经建好——同样在时限内刷新；`listRefreshed` 按刷新成败给说法；整理面板与新建、确认框、管理界面的弹窗各有接入点）。会话复核可以带原因（`SessionRecheck` 的 `ifEnded`）：给自己生成重置链接的结果未知时，带 `password_reset` 复核会话，不去刷新需要登录的列表（否则按普通的"登录已过期"离开，丢了"密码可能已经失效"的说明，第 5 片第二批复验的 R-1）。
- 第五批（第三、四批复验的意见）：结果未知之后的刷新只按**列表**计成败（文档的元数据照常重新请求、不计入也不等——删除、移走真的生效时，元数据得到 404/403 正是生效之后的样子）；被拒绝（404）之后的说明同样按列表在时限内刷新的成败来说；到了时限之后后台的刷新成功时，弹窗与表单里的说明改回"已刷新"（`useOutcomeRefresh`、`onLateRefresh`，前一次失败晚到的刷新不改这一次的说法）；刷新先取消在路上的请求、再作废重新请求（`refreshQueries`：TanStack 对正在请求、还没有数据的查询不会取消重来，过滤的请求在路上时创建成功，列表会停在之前的状态），成功之后的刷新不抛出失败；"已经是成员"只在有过结果未知之后才说"可能就是刚才那一次"。修改密码的结果未知时立即带 `password_changed` 复核会话（不在出错的回调里等：那时修改密码还没结束，运行时会先等它，互相等到 40 秒上限）；停用自己的结果未知同样带原因复核（登录页新增原因 `account_disabled`："你的账户可能已经被停用"）。带原因的会话确认因网络失败没有结论时，记下"等连上再确认"，之后任何查询或变更成功就再确认一次（会话还在则清掉原因）；不设固定的有效期——断网久了会丢掉正确的原因，说错一次"可能"的代价更小。页头的人名在窄屏时按余下的宽度（容器查询）判断，不到 3rem 就只留给读屏（可读文字与 `title` 仍是全名）。
- **焦点兜底**：区域里有焦点的元素被移走、焦点落到 body 时，交给页面标题（`useFocusRescue`）；说明条（`Notice`）接住操作之后的焦点；"加载更多"之后焦点移到第一条新内容。**页面标题**：每个平台页面设置浏览器标签页的标题。**输入不合法**时显示文字说明并经 `aria-describedby` 关联（不只是 `aria-invalid` 与按钮不可用）。骨架屏只作装饰，"正在加载"由外层的状态区域读出。对比度：危险样式与灰色说明文字的颜色变量调到 4.5:1 以上。
- **按需加载的失败**：AppShell 之下的内容路由有自己的错误边界，对分块加载失败单独处理——重新取入口页比对模块脚本（10 秒时限），部署了新版本（旧的分块 404）时整页重新加载一次（会话存储防循环）；连不上服务器说"请检查网络后重试"，服务器连得上、版本也没变却下载不了说"代码没能下载下来"；取回的入口页没有模块脚本（代理或认证网关的页面）按连不上处理。可以重试，页头与导航都还在。
- **成员的角色**选了之后点"保存"才提交（Windows、Linux 上收起的原生选择框按方向键会逐个改值，原来每一步都会保存）。


**测试**：Vitest、Testing Library 与 jsdom。
- 接口用假的 `fetch` 按"方法 路径"返回；没有登记的请求让测试失败，免得悄悄走到真实网络。
- 跨功能的流程（登录、跳转、退出、过期、多标签页）在 app 层用与生产相同的路由表与请求缓存测试；整页跳转与标签页消息换成记录调用的假实现；功能模块的测试只渲染自己的组件。
- E2E 的共用夹具收集每个页面的 `securitypolicyviolation`，用例结束时断言为空；CSP 阳性对照显式声明预期有违规，并检查夹具确实收到。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
|---|---|---|
| React Router 8 | 采用 | 数据路由与错误边界完善；大版本已发布三个月以上 |
| TanStack Router | 否决 | 类型化的路由是优点，但体积更大，路由也要按它的方式生成；M1 只有几个页面 |
| wouter 等极简路由 | 否决 | 体积小，但没有数据路由与错误边界，后续的编辑器入口、空间与文件夹的路由要自己补 |
| TanStack Query 5 | 采用 | 请求状态、重试、取消与缓存都现成；全局的错误处理能统一接住未登录 |
| 自己用 useEffect 取数据 | 否决 | 加载、失败、取消、重复请求都要自己处理，规范 §2.4 的四种状态难以统一 |
| shadcn/ui 的 Base UI 或 React Aria 版本 | 否决 | M1 总设计已定 Radix；三者 API 相近，将来要换也只影响 `shared/ui` |
| 直接依赖 shadcn 的 CLI 包与 `cn` 包 | 否决 | CLI 包作为依赖带来大量开发依赖；`cn` 刚发布不久 |
| Geist 等网页字体 | 否决 | 许可不在白名单里；没有中文字形；系统字体的中文显示更好，也不增加首屏体积 |

## 影响

- **新页面**：放在对应的功能模块（`features/*`），对外只经 `index.ts`；路由加进 `app/routes.ts`；界面文字加进 `shared/i18n/zh-cn/` 里对应范围的文件（只在按需加载的页面用到的，放进那个功能自己的文件）。
- **新组件**：优先从 shadcn/ui 的 radix-nova 风格取，改写后放进 `shared/ui`，并在文件头写明来源。
- **新依赖**：进目录（catalog）后检查首屏预算；与 React 上下文有关的包加进单例清单。
- **编辑器入口**（P4）：另起入口，整页加载，自己定体积预算；不引用平台页面的路由与请求缓存。
