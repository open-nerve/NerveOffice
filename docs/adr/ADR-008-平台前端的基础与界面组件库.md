# ADR-008：平台前端的基础与界面组件库

> 状态：已接受｜日期：2026-09-26｜来源：M1-P3

## 背景

- M1 总设计 §2.1 第 3 条：平台界面用 shadcn/ui（Radix + Tailwind CSS），代码放进仓库。
- 规范 §2.4 的要求：
  - 服务端数据经统一的请求层获取；
  - 每个数据视图处理加载中、空、失败、无权限四种状态，异步操作防止重复提交；
  - 界面文字集中管理；
  - 可访问性（标签、键盘、可读的名称）。
- 定稿的 CSP：`script-src 'self'`（没有 `'unsafe-eval'`），`style-src 'self' 'unsafe-inline'`，`font-src 'self'`，不从第三方加载任何资源（00 号计划书 §11.3、§11.5）。
- 规范 §11：每个前端入口的首屏 JS 有体积预算，在建立入口的 Phase 里定下。
- 平台页面与编辑器页是两个入口，编辑器整页加载（M1 总设计 §6.1）。本 ADR 只管平台页面。

## 决策

**路由**：React Router 8。
- 只用数据路由的库模式（`createBrowserRouter`），不用框架模式与服务端渲染。
- 路由表只写组件（`Component`、`ErrorBoundary`），不含 JSX，测试用同一张表建内存路由。

**服务端数据**：TanStack Query 5。
- 加载、失败、重试与缓存由它管理，页面按它给出的状态显示。
- 重试策略：只有网络失败与 5xx 重试一次；4xx 重试也没用，不重试。
- **未登录的统一处理**：任何查询或变更得到 `UNAUTHENTICATED`、`SESSION_EXPIRED` 时，统一清空缓存与 CSRF 令牌，回到登录页，登录后回到原来的地址（只接受站内的相对路径）。自己处理未登录的请求（会话、登录、退出）用 `meta.handlesAuthentication` 标明，统一处理不管它们。

**请求层**（`shared/api`）：
- 同源请求（`credentials: 'same-origin'`）；状态变更的请求带 `X-CSRF-Token`。令牌由登录与会话接口给出，只放在内存里。
- 错误分三类：
  - `ApiError`：服务端按约定返回的错误，带错误码、请求标识与 `Retry-After`；
  - `NetworkError`：请求没能到达服务端，或者没收到响应；
  - `ResponseFormatError`：成功的响应与契约不一致。
- 成功的响应也用 contracts 的结构校验：接口与前端不一致时立即暴露，不渲染出错的数据。

**样式与组件**：Tailwind CSS 4，加上 shadcn/ui 的 Radix 版本（`radix-nova` 风格）。
- 组件代码取自 shadcn/ui 4.21.0 的生成结果，放进 `shared/ui`，按项目规范改写：单引号、不写分号、`import type`。
- 不采用生成结果带来的三样东西：
  - `cn` 包：刚发布的新包，改用成熟的 `clsx` 加 `tailwind-merge` 自己写 `cn()`；
  - CLI 包自带的 `shadcn/tailwind.css`：只有几条自定义变体，需要时抄进自己的样式；
  - Geist 字体：OFL-1.1 许可不在生产依赖的白名单里，也没有中文字形。改用系统字体，不加载字体文件。
- 只有浅色主题；深色主题等需要时再加。
- 组件没有内联脚本；内联样式来自 Radix，由 CSP 的 `style-src 'unsafe-inline'` 放行（M0 定稿时已为主题变量保留）。

**zod 与 CSP**：
- zod 4 默认会用 `new Function` 探测能否做 JIT。探测失败虽被 zod 接住，浏览器仍会报一条 CSP 违规。
- 前端入口在渲染之前设置 `z.config({ jitless: true })`（zod 4.6 在 jitless 时跳过探测）。
- 探测代码仍在产物里：门禁 `artifacts` 把它登记为"已知探测"，限定出现 1 次，因为函数体是空字符串，不执行任何代码。

**界面文字**：集中在 `shared/i18n/zh-cn.ts`。
- 界面按错误码显示这里的文字，服务端的说明只是默认值；
- 前端还不认识的错误码（服务端比前端新）用服务端的说明。

**首屏体积预算**：平台页面入口的首屏 JS（gzip）为 180 KiB，由门禁 `budgets` 检查。
- M1-P3 实测约 147–152 KiB，主要构成：react-dom 65、React Router 31、contracts 与 zod 26、TanStack Query 11、tailwind-merge 9、应用代码 7。
- 以后需要瘦身时，可以按路由懒加载，或者让 contracts 改用 `zod/mini`。

**测试**：Vitest、Testing Library 与 jsdom。
- 接口用假的 `fetch` 按"方法 路径"返回；没有登记的请求让测试失败，免得悄悄走到真实网络。
- 跨功能的流程（登录、跳转、退出、过期）在 app 层用与生产相同的路由表与请求缓存测试；功能模块的测试只渲染自己的组件。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
|---|---|---|
| React Router 8 | 采用 | 数据路由与错误边界完善；大版本已发布三个月以上 |
| TanStack Router | 否决 | 类型化的路由是优点，但体积更大，路由也要按它的方式生成；M1 只有几个页面 |
| wouter 等极简路由 | 否决 | 体积小，但没有数据路由与错误边界，后续的编辑器入口、空间与文件夹的路由要自己补 |
| TanStack Query 5 | 采用 | 请求状态、重试、取消与缓存都现成；全局的错误处理能统一接住未登录 |
| 自己用 useEffect 取数据 | 否决 | 加载、失败、取消、重复请求都要自己处理，规范 §2.4 的四种状态难以统一 |
| shadcn/ui 的 Base UI 或 React Aria 版本 | 否决 | M1 总设计已定 Radix；三者 API 相近，将来要换也只影响 `shared/ui` |
| 直接依赖 shadcn 的 CLI 包与 `cn` 包 | 否决 | CLI 包作为依赖带来大量开发依赖；`cn` 刚发布不久 |
| Geist 等网页字体 | 否决 | 许可不在白名单里；没有中文字形；系统字体的中文显示更好，也不增加首屏体积 |

## 影响

- **新页面**：放在对应的功能模块（`features/*`），对外只经 `index.ts`；路由加进 `app/routes.ts`；界面文字加进 `shared/i18n/zh-cn.ts`。
- **新组件**：优先从 shadcn/ui 的 radix-nova 风格取，改写后放进 `shared/ui`，并在文件头写明来源。
- **新依赖**：进目录（catalog）后检查首屏预算；与 React 上下文有关的包加进单例清单。
- **编辑器入口**（P4）：另起入口，整页加载，自己定体积预算；不引用平台页面的路由与请求缓存。
