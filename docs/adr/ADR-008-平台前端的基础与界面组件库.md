# ADR-008：平台前端的基础与界面组件库

> 状态：已接受｜日期：2026-09-26｜来源：M1-P3｜修订：2026-09-27，P3 审查之后改为会话结束整页跳转、加上多标签页的处理

## 背景

- M1 总设计 §2.1 第 3 条：平台界面用 shadcn/ui（Radix + Tailwind CSS），代码放进仓库。
- 规范 §2.4 的要求：
  - 服务端数据经统一的请求层获取；
  - 每个数据视图处理加载中、空、失败、无权限四种状态，异步操作防止重复提交；
  - 界面文字集中管理；
  - 可访问性（标签、键盘、可读的名称）。
- 定稿的 CSP：`script-src 'self'`（没有 `'unsafe-eval'`），`style-src 'self' 'unsafe-inline'`，`font-src 'self'`，不从第三方加载任何资源（00 号计划书 §11.3、§11.5）。
- 规范 §11：每个前端入口的首屏 JS 有体积预算，在建立入口的 Phase 里定下。
- 平台页面与编辑器页是两个入口，编辑器整页加载（M1 总设计 §6.1）。本 ADR 只管平台页面。

## 决策

**路由**：React Router 8。
- 只用数据路由的库模式（`createBrowserRouter`），不用框架模式与服务端渲染。
- 路由表只写组件（`Component`、`ErrorBoundary`），不含 JSX，测试用同一张表建内存路由。
- 除登录页以外的地址（包括 404）都在需要登录的外层路由之下：未登录时先转到登录页。
- 路由、请求缓存与会话的全局处理组成"运行时"，在入口的 `mount.tsx` 里、React 之外建一次（StrictMode 下不会建两份）。

**服务端数据**：TanStack Query 5。
- 加载、失败、重试与缓存由它管理，页面按它给出的状态显示。
- 重试策略：只有网络失败与 5xx 重试一次（会话查询也一样）；4xx 重试也没用，不重试。
- 查询与变更都是 `networkMode: 'always'`：不按 `navigator.onLine` 挂起，断网时照常失败，由请求层归为网络错误显示出来（P3 审查 B4：默认的挂起让退出一直停在"正在退出"，请求根本没发出去，会话仍然有效）。
- **会话结束**：任何查询或变更得到 `UNAUTHENTICATED`、`SESSION_EXPIRED`，以及退出成功（或退出时会话已经不在了）时，离开前清掉 CSRF 令牌，**整页**转到登录页（`location.replace`，替换历史记录），登录后回到原来的地址（只接受站内地址，拒绝控制字符与空白，按同源解析）。
  - 不在单页里清空缓存再切换路由（P3 审查 B7）：还挂着的组件会在缓存清空后立即重新请求；整页跳转让上一个会话的数据与令牌随页面丢弃。P4 的编辑器页是另一个入口，会话结束时同样整页跳转。
  - 请求用元数据声明与会话的关系：`handlesAuthentication`（自己处理未登录：会话、登录），`session: 'starts' | 'ends'`（登录、退出）。
- **多个标签页**（P3 审查 B6）：会话 Cookie 各标签页共用，一个标签页换了人，别的标签页还拿着上一个会话的页面与 CSRF 令牌。
  - 登录与退出经 `BroadcastChannel`（`nerve-office:session`，消息不带内容）通知其他标签页；
  - 收到消息，或者状态变更的请求得到 `CSRF_TOKEN_INVALID` 时（消息可能没送达，这个信号可靠），向服务端确认现在是谁：同一个人，只换上新的会话与令牌，页面不动；换了人或已退出，整页重新加载。

**请求层**（`shared/api`）：
- 同源请求（`credentials: 'same-origin'`）；状态变更的请求带 `X-CSRF-Token`。令牌由登录与会话接口给出，只放在内存里。
- 错误分三类：
  - `ApiError`：服务端按约定返回的错误，带错误码、请求标识与 `Retry-After`；
  - `NetworkError`：请求没能到达服务端，或者没收到响应；
  - `ResponseFormatError`：成功的响应与契约不一致。
- 成功的响应也用 contracts 的结构校验：接口与前端不一致时立即暴露，不渲染出错的数据。

**样式与组件**：Tailwind CSS 4，加上 shadcn/ui 的 Radix 版本（`radix-nova` 风格）。
- 组件代码取自 shadcn/ui 4.21.0 的生成结果，放进 `shared/ui`，按项目规范改写：单引号、不写分号、`import type`。
- 不采用生成结果带来的三样东西：
  - `cn` 包：刚发布的新包，改用成熟的 `clsx` 加 `tailwind-merge` 自己写 `cn()`；
  - CLI 包自带的 `shadcn/tailwind.css`：只有几条自定义变体，需要时抄进自己的样式；
  - Geist 字体：OFL-1.1 许可不在生产依赖的白名单里，也没有中文字形。改用系统字体，不加载字体文件。
- 只有浅色主题；深色主题等需要时再加。
- 组件没有内联脚本；内联样式来自 Radix，由 CSP 的 `style-src 'unsafe-inline'` 放行（M0 定稿时已为主题变量保留）。

**zod 与 CSP**：
- zod 4 的 JIT 有两段动态代码：
  - `Function('')` 探测：看能否执行动态代码；
  - 编译器 `Doc.compile`：为对象结构生成解析函数。
- zod 在**创建结构时**就读取 jitless，而 contracts 的结构在模块求值时就建好了。所以设置 jitless 的模块必须是入口**第一个引入**的模块，早于任何结构的创建；在入口的函数体里设置已经晚了（P3 审查 B1：每次整页加载都有一条 CSP 违规，浏览器不写进控制台）。
- 做法：有副作用的模块 `shared/lib/zod-jitless.ts`，作为每个入口的第一个导入；入口文件只写副作用导入（导入排序规则把副作用导入排在普通导入之后、不调整它们之间的先后，写在入口里的顺序就是执行的顺序）。P4 的编辑器入口同样第一个导入它。
- 这样两段代码都执行不到。门禁 `artifacts` 把它们登记为"已登记的动态代码"，各限 1 次；万一执行，CSP 里没有 `'unsafe-eval'`，浏览器会拦下。
- 打包器的 `strictExecutionOrder` 暂不开启：两个入口共用 contracts 的实验里，只要每个入口都先导入 zod-jitless，默认模式就没有违规；开启要多约 3.5 KiB 与一个运行时块。某个入口忘了导入时，E2E 的违规收集会报出来。P4 加编辑器入口时按实测再定。
- E2E 收集每个页面的 `securitypolicyviolation` 事件，用例结束时断言为空（阳性对照的用例除外）。

**界面文字**：集中在 `shared/i18n/zh-cn.ts`。
- 界面按错误码显示这里的文字，服务端的说明只是默认值；
- 前端还不认识的错误码（服务端比前端新）用服务端的说明。

**构建**：不注入 modulepreload 的补丁（目标浏览器都原生支持），测试构建与生产构建的平台入口块逐字节相同。

**首屏体积预算**：平台页面入口的首屏 JS（gzip）为 180 KiB，由门禁 `budgets` 检查。
- M1-P3 收尾时门禁实测 146.8 KiB，预算比实测多约 23%。主要构成：react-dom 65、React Router 31、contracts 与 zod 26、TanStack Query 11、tailwind-merge 9、应用代码 7。
- 以后需要瘦身时，可以按路由懒加载，或者让 contracts 改用 `zod/mini`。

**测试**：Vitest、Testing Library 与 jsdom。
- 接口用假的 `fetch` 按"方法 路径"返回；没有登记的请求让测试失败，免得悄悄走到真实网络。
- 跨功能的流程（登录、跳转、退出、过期、多标签页）在 app 层用与生产相同的路由表与请求缓存测试；整页跳转与标签页消息换成记录调用的假实现；功能模块的测试只渲染自己的组件。
- E2E 的共用夹具收集每个页面的 `securitypolicyviolation`，用例结束时断言为空；CSP 阳性对照显式声明预期有违规，并检查夹具确实收到。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
|---|---|---|
| React Router 8 | 采用 | 数据路由与错误边界完善；大版本已发布三个月以上 |
| TanStack Router | 否决 | 类型化的路由是优点，但体积更大，路由也要按它的方式生成；M1 只有几个页面 |
| wouter 等极简路由 | 否决 | 体积小，但没有数据路由与错误边界，后续的编辑器入口、空间与文件夹的路由要自己补 |
| TanStack Query 5 | 采用 | 请求状态、重试、取消与缓存都现成；全局的错误处理能统一接住未登录 |
| 自己用 useEffect 取数据 | 否决 | 加载、失败、取消、重复请求都要自己处理，规范 §2.4 的四种状态难以统一 |
| shadcn/ui 的 Base UI 或 React Aria 版本 | 否决 | M1 总设计已定 Radix；三者 API 相近，将来要换也只影响 `shared/ui` |
| 直接依赖 shadcn 的 CLI 包与 `cn` 包 | 否决 | CLI 包作为依赖带来大量开发依赖；`cn` 刚发布不久 |
| Geist 等网页字体 | 否决 | 许可不在白名单里；没有中文字形；系统字体的中文显示更好，也不增加首屏体积 |

## 影响

- **新页面**：放在对应的功能模块（`features/*`），对外只经 `index.ts`；路由加进 `app/routes.ts`；界面文字加进 `shared/i18n/zh-cn.ts`。
- **新组件**：优先从 shadcn/ui 的 radix-nova 风格取，改写后放进 `shared/ui`，并在文件头写明来源。
- **新依赖**：进目录（catalog）后检查首屏预算；与 React 上下文有关的包加进单例清单。
- **编辑器入口**（P4）：另起入口，整页加载，自己定体积预算；不引用平台页面的路由与请求缓存。
