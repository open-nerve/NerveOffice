# ADR-007：会话、CSRF 与登录限流

> 状态：已接受｜日期：2026-09-26｜来源：M1-P3｜修订：2026-09-27，P3 审查之后改为"先占用名额、再验证"，清理移到事务之外

## 背景

- 00 号计划书的要求：
  - §11.1：服务端 Session；Cookie 设置 HttpOnly、Secure、SameSite；对状态变更接口做 CSRF 防护与 Origin 检查；空闲过期与绝对过期；密码用有人维护的 Argon2id 实现，参数按部署机器的基准测试设置；
  - §5.5：服务端按每个请求授权，默认拒绝；
  - 附录 A：登录会话要限流、审计。
- 规范 §4：令牌不出现在地址、日志与错误里。§6：令牌只存摘要。§7：审计登录成功与失败、退出。
- 部署形态（M1 总设计 §2.1 第 5 条）：同源部署，Caddy 做 HTTPS；开发时经 Vite 开发服务器代理，E2E 走本机的 HTTP。
- 单租户、首发单实例，但迁移已按"将来多实例"加了 advisory lock（ADR-005）。

## 决策

**会话令牌与存储**：
- 令牌是 32 字节的随机数，base64url 编码后放进 Cookie；数据库只存它的 SHA-256 摘要（`auth_sessions.token_hash`），按摘要查找。
- 每次登录都换新的令牌（防会话固定）；同一个浏览器原来的会话一并撤销（原因 `replaced`）。
- 过期：空闲过期（默认 12 小时）随活动顺延，但不超过绝对过期（默认 7 天），都用数据库时间判断。
  - 距上次记录超过 1 分钟才写库顺延，不必每个请求都写；
  - 撤销时空闲过期一并提前到撤销的时间，清理只看这一列；
  - 每次验证过密码之后，在事务之外顺带删除一小批过期或撤销超过 30 天的会话。

**Cookie**：
- 公开地址（`NERVE_PUBLIC_ORIGIN`）是 HTTPS 时，名称用 `__Host-nerve_session`，带 `Secure`。`__Host-` 前缀让浏览器强制 `Secure`、`Path=/`、不带 `Domain`，子域写不了它。
- 公开地址只有在本机调试时才允许是 HTTP（配置校验），这时名称是 `nerve_session`，不带 `Secure`。
- 都带 `HttpOnly`、`SameSite=Lax`、`Path=/`；`Max-Age` 取绝对过期时长（关掉浏览器再打开仍然登录，过期由服务端判断）。

**认证：默认拒绝**：
- 全局的会话守卫对每个接口生效，标了 `@Public()` 的除外（登录、存活与就绪探针）。`@Public()` 放在 `shared`：它只是元数据，用它的模块不必依赖 auth。
- 没有会话 Cookie 返回 `UNAUTHENTICATED`；带着 Cookie 但会话无效（过期、撤销、账户不可用）返回 `SESSION_EXPIRED` 并清除 Cookie。界面据此区分"请先登录"与"登录已过期"。
- 认证通过后，当前用户挂在请求上，控制器用 `@CurrentPrincipal()` 取得；请求日志带上 `userId`。
- 控制器不接触请求与响应对象：会话 Cookie 的读写经窄接口 `@SessionCookieJar()`，只有读取、写入与清除。

**CSRF 与 Origin**（全局守卫，排在会话守卫之后，只管 `POST`、`PUT`、`PATCH`、`DELETE`）：
- **Origin** 必须等于公开地址，缺少也拒绝（`ORIGIN_NOT_ALLOWED`）；登录同样检查，防登录 CSRF。浏览器对非 GET 请求（包括同源）都会带 `Origin`。
- **CSRF 令牌**（需要登录的接口）：请求头 `X-CSRF-Token` 必须等于 `base64url(HMAC-SHA256(会话令牌, "nerve-office:csrf:v1"))`，按常数时间比较，否则返回 `CSRF_TOKEN_INVALID`。
  - 令牌由会话令牌派生，不另外存储；前端从登录与会话接口的响应里拿到它，只放在内存里；
  - 攻击者的页面读不到 HttpOnly 的 Cookie，也读不到会话接口的响应（同源策略，不开 CORS），所以算不出它。
- 加上 `SameSite=Lax`，是三层防护。

**登录限流**（计数存在数据库，`auth_login_throttles`）：
- **两个维度**：按用户名（规范化之后）窗口 15 分钟内失败 5 次，按客户端地址窗口 15 分钟内失败 50 次；达到上限锁定 15 分钟。都可以配置。计数的键只存摘要，不存用户输入的原文。
- **先占用名额，再验证**：
  - 预检：任一维度锁定中，直接返回 `TOO_MANY_ATTEMPTS` 与 `Retry-After`，不验证密码。一次只读的查询，锁定期间的洪水不写库。锁定期间的请求只记日志，不写审计，免得攻击时写爆审计表；
  - 占用：先用户名、再地址，各用一条 `INSERT … ON CONFLICT … WHERE` 原子地把计数加一。窗口已过或上一次锁定已经结束时，从 1 重新计数；加到上限时锁定，这一次仍然验证；锁定中不占用，直接拒绝。地址被拒绝时，退回已经占到的用户名名额；
  - 验证失败：名额保留，计为这次失败；这次占用触发了锁定时就返回 429；
  - 于是同一窗口里真正验证过的失败，不会超过上限，并发的请求也一样。
- **成功时**：清除这个用户名的计数；地址只退回这次占的名额，之前的失败照算，免得攻击者夹着自己账户的成功登录继续尝试别的账户。
  - 退回只在占用时的窗口里生效：窗口已经重新开始时不退，免得减掉新窗口的计数。
  - 计数只在达到上限时才锁定，退回之后低于上限，还在生效的锁定随之解除，即使锁定是别的请求触发的。窗口内验证过的失败仍然不超过上限，只是锁定可能比 15 分钟短。
- **清理**：每次验证过密码之后，在事务之外删除一小批窗口与锁定都已过期的计数，跳过别人正锁着的行（`SKIP LOCKED`）；尽力执行，失败只记日志。
- **不存在的用户名**：同样计数，并用一份假哈希算一次，响应时间与"密码错误"相近，不暴露账户是否存在。
- **客户端地址**：来自 Express 的 `request.ip`，经 `trust proxy` 识别反向代理（P2）；部署时按反向代理配置（P5）。
  - IPv4 按单个地址，IPv4 映射的 IPv6 按其中的 IPv4；IPv6 按 /64：一台主机通常分到整个 /64，按单个地址计数挡不住轮换；
  - 取不到合法地址时归到同一个键：宁可一起限流，也不跳过这个维度。

**密码**：@node-rs/argon2（Rust 实现；按平台发布预编译包，没有安装脚本）。
- 默认参数是 OWASP 的最低推荐：内存 19 MiB、迭代 2 次、并行度 1。参数可以配置，P5 在部署机器上做基准测试。
  - 配置校验：内存（KiB）与迭代次数的乘积不低于 35840，即 OWASP 几组等强度参数里最弱的一组（7168 × 5）。
- 哈希在 libuv 的线程池里计算，线程池也负责读文件与解析域名。同时进行的哈希有上限（默认 2，是默认 4 个线程的一半），超出的排队：登录洪水不能把托管前端产物与连接数据库一起拖住。
- 用户名不存在时拿来算一次的假哈希，在启动时就生成。
- 哈希是 PHC 字符串，带着参数；参数变了之后，下次登录成功时用新参数重新哈希。
- 设置密码要求 12–256 个字符，不要求字符种类（NIST SP 800-63B），不含控制字符；登录时只限制长度，不透露规则。

**审计**：
- 登录成功：操作者与对象是这个账户；
- 登录失败：操作者匿名，账户存在时对象是它，`details.reason` 为 `invalid_credentials`，触发锁定时另记锁定的秒数；
- 退出：操作者是这个账户。
- 都带请求标识与客户端地址。
- 成功时，限流计数、会话与审计在同一个事务里写入；失败时计数已在验证之前占好，只写一条审计。密码验证在事务之外（计算密集的操作）。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
|---|---|---|
| 服务端会话，库里存令牌摘要 | 采用 | 00 号计划书 §11.1 已定；可以随时撤销（退出、M2 的停用与改密） |
| JWT 等自包含令牌 | 否决 | 撤销要另建黑名单，与"服务端会话"的要求相悖；令牌体积大 |
| 同步令牌存在库里 | 否决 | 多一列要维护；由会话令牌派生的令牌同样不可预测，且不需要存储 |
| 只靠 `SameSite` 与自定义请求头 | 否决 | 00 号计划书要求 CSRF 防护与 Origin 检查两层；`SameSite=Lax` 挡不住同站的子域 |
| `SameSite=Strict` | 否决 | 从聊天工具等外部链接点进来时第一次导航不带 Cookie，用户会被要求重新登录 |
| 限流计数放在内存里 | 否决 | 重启就清零；将来多实例时各算各的 |
| 限流时把用户名锁死直到管理员解锁 | 否决 | 攻击者可以借此锁死任何账户；按窗口自动解锁，配合按地址的维度 |
| 先查锁定、验证、失败后再计数 | 否决（P3 初版，审查 A1） | 一波并发的请求都在锁定之前通过检查、全部验证：40 个并发的错误密码全部验证，夹在里面的正确密码登录成功 |
| 验证期间锁住计数的行（事务里 `SELECT … FOR UPDATE`） | 否决 | 验证要几十毫秒，同一个地址的登录全部串行；事务长时间持有连接 |
| 在登录失败的事务里顺带清理 | 否决（P3 初版，审查 A2） | 并发时清理与计数互相等待，出现死锁与锁超时，大量请求返回 500 |
| node-argon2（`argon2` 包） | 否决 | 安装时要执行 `node-gyp-build`，需要加进安装脚本白名单 |

## 影响

- **新接口**：默认要求登录；确实不需要登录的，标 `@Public()` 并在审查时说明原因。状态变更的接口自动受 CSRF 与 Origin 检查。
- **前端**：状态变更的请求带 `X-CSRF-Token`；得到 `UNAUTHENTICATED`、`SESSION_EXPIRED` 时回到登录页（ADR-008）。
- **M2**：停用账户、修改密码、重置密码时，撤销这个人的全部会话（`auth_sessions.user_id` 上有索引），撤销原因加进 CHECK 约束。
- **部署（P5）**：
  - `NERVE_PUBLIC_ORIGIN` 必须是 HTTPS 的公开地址；
  - `NERVE_TRUST_PROXY` 按反向代理配置，否则按地址的限流会把所有人算成同一个地址；
  - Argon2id 的参数按部署机器的基准测试确认；调大 `UV_THREADPOOL_SIZE` 时，`NERVE_PASSWORD_HASH_CONCURRENCY` 一并调大（不超过一半，配置校验会检查）；
  - 反向代理对登录接口再加一层按地址的速率限制：服务端的限流挡的是猜密码，挡不住单纯的请求洪水（DEF-015）；
  - 核对反向代理的信任设置（DEF-014）。
