# ADR-013：一次性令牌（邀请注册与重置密码）

> 状态：已接受｜日期：2026-09-28｜来源：M2-P1

## 背景

- M2 要让同事受邀加入，并由系统管理员为忘记密码的同事重置密码（M2 总设计 §2.1 第 2 条，US-M2-01、03）。
- 00 号计划书 §11.1 的要求：
  - 邀请与重置令牌单次有效、有时限、只存摘要，并做尝试限流与审计；
  - 不依赖外部邮件服务，由管理员通过受控渠道分发链接；
  - 重置密码与停用账户时，相关会话失效。
- §11.5：日志与审计不记录令牌与密码。

## 决策

**令牌与存储**：
- 令牌是 32 字节的安全随机数，base64url 编码（43 个字符），与会话令牌同样的强度。库里只存 SHA-256 摘要（`auth_invitations.token_hash`、`auth_password_resets.token_hash`，唯一索引），按摘要查找。
- 链接只在签发的响应里出现一次，之后再也取不到：邀请列表只有状态，没有令牌。

**链接的形态**：`<公开地址>/invite#<令牌>`、`<公开地址>/reset-password#<令牌>`（页面路径与有效期都是 contracts 的常量）。
- 令牌放在 `#` 之后：浏览器不把这一段放进请求行，所以它不进服务端与反向代理的访问日志，也不随 Referer 外泄。
- 页面读出令牌之后，立即用替换当前历史记录的导航把它从地址栏去掉，再放进请求体提交。四个公开接口（查看、接受邀请；查看、完成重置）都是 POST。

**有效期与状态**：
- 邀请 7 天，重置 24 小时。"已过期"在查询时按 `expires_at <= now()` 判断（数据库时间），不靠定时任务改状态。
- 接受（使用）与作废最多有一个（CHECK）。部分唯一索引保证同一个登录名最多一条未接受、未作废的邀请，同一个账户最多一条未使用、未作废的重置。
- 两张表的行不清理：约 100 人的规模下增长很慢，它们也是邀请列表与审计的上下文。

**签发**（只给系统管理员，§3.3 的管理接口）：
- 邀请：管理员填好登录名与显示名。
  - 登录名已被账户占用，或者已有未过期、待接受的邀请时，拒绝（`USERNAME_TAKEN`）；已过期、未处理的旧邀请在同一个事务里自动作废。
  - 重发：作废旧的（还没作废时）、按同一个登录名与显示名签发新的，一个事务；已接受的不能重发。新邀请的审计带 `reissuedFrom`；列表里旧的一条标为已被替代（`superseded`），界面只对同一个登录名最新的一条给出重新生成。
- 重置：作废这个账户未用的旧重置、签发新的，**同时把密码换成不可用的哈希（旧密码立即失效）**，撤销这个人的全部会话（原因 `password_reset`）；停用的账户拒绝（`ACCOUNT_DISABLED`）。停用账户时作废这个人未用的重置。
  - 不可用的哈希：随机的秘密算出的 Argon2id 哈希，秘密随即丢弃，谁也不知道对应的密码；格式仍满足表上的 CHECK，登录时照常验证、照常失败，耗时与密码错误相同。
  - 账户被盗时直接签发重置：旧密码与全部登录随即失效，本人用链接设置新密码。停用用于离职等"暂时不让用"，启用之后旧密码照旧可用。
- 运维命令 `reset-link --username`：唯一的系统管理员忘记密码时恢复。走与界面签发相同的服务，操作者记为系统、来源记为命令行；它不授予任何角色。
  - 标准输出只有链接，日志写标准错误。
  - 容器里用 `docker compose exec` 执行：exec 的输出直接回到终端，不经容器的日志驱动；`docker compose run` 起的一次性容器的输出会被日志驱动收走，链接就进了集中日志。

**接受与完成**：
- 先查令牌、再算新密码的哈希，都在事务之外：哈希是计算密集的操作，无效的令牌也不触发哈希计算。
- 然后在一个事务里：
  1. 按下面的锁顺序锁住记录，复核仍然可用；完成重置另复核账户仍然有效；
  2. 接受邀请：建成员账户与个人空间（与初始化管理员共用 `AccountCreationService`），标记已接受；完成重置：更新密码哈希，标记已使用，撤销这个人的全部会话；
  3. 新建本次的会话（浏览器原来带着的会话作废，同登录），记审计。
- 复核不通过（查令牌之后被接受、用过、作废，或账户停用）：事务回滚之后按一次失败处理，与查令牌时就不能用的一样，记 `auth.link_rejected`，这次失败使计数达到上限时 429。
- 响应与登录相同：接受或完成之后已经登录，页面进入个人空间，并与登录一样通知其他标签页。

**锁的顺序**：
- 邀请：签发、重发、接受都先取按登录名的 advisory lock（`nerve-office:username:<登录名>`，初始化管理员也取它），再取邀请的行锁。登录名是否可用在锁里检查，不靠唯一约束报错。
- 重置：签发与完成都先锁账户行（`FOR NO KEY UPDATE`），在锁里复核账户有效，再动重置行、限流计数与会话行。这与改动账户的其他事务（登录、修改密码、停用）是同一个顺序（ADR-007 的补充）：互相等待时不成环；并发的签发在账户行上排队，后一个作废前一个。
- 签发时自动作废过期的旧邀请没有锁那一行：作废用带状态条件的更新（未接受、未作废）。与管理员手动作废同时发生时，只有一方更新到行、记审计。

**不能用的链接**：没有这个令牌、格式不对、已过期、已使用、已作废，都是 410 `LINK_INVALID`，`details.reason` 分别为 `invalid`、`expired`、`used`、`revoked`；重置对应的账户已停用时按 `revoked`。
- 页面按原因给出下一步：已接受的邀请、已用过的重置，去登录；其他情况请管理员重新发送。
- 令牌是 256 位的随机数，猜不中；只有持有真实令牌的人才看得到原因，按原因区分不泄漏信息。

**尝试限流**：查看、接受、完成都先占名额，与登录同一张表、同一套"先占用、再尝试"的机制（`AttemptThrottle`，登录与链接共用）。
- 维度只有客户端地址，键另起前缀（`link:`），不与登录的计数混在一起；阈值沿用登录的地址维度（`NERVE_LOGIN_IP_MAX_FAILURES` 等），不另设配置。
- 令牌不可用算一次失败，名额不退回；可用就退回。
- 锁定期间只记日志，不写审计；锁定之外，不可用的尝试记审计 `auth.link_rejected`（操作者是未登录的访问者，details 是用途与原因；找到了记录时带上对象：邀请，或重置对应的账户）。

**审计**：`users.invited`、`users.invitation_revoked`、`users.invitation_accepted`、`users.password_reset_issued`、`users.password_reset_completed`、`auth.link_rejected`。对象类型加 `invitation`。details 不含令牌与密码。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
|---|---|---|
| 平台发邀请与重置的邮件 | 否决 | 00 号计划书 §11.1：不依赖外部邮件服务，由管理员经受控渠道分发 |
| 令牌放在路径或查询参数里 | 否决 | 进访问日志（应用与反向代理），并随 Referer 外泄 |
| 库里存令牌本身（加密） | 否决 | 摘要足以查找；库被读到也拿不到能用的令牌，不必管理加密密钥 |
| 签发之后还能再看到链接 | 否决 | 要存令牌本身；链接丢了就重发（旧的随即作废） |
| 受邀人自己填登录名 | 否决（M2 总设计 §2.1 第 2 条） | 登录名要统一规范；链接被转发时，拿到的人只能注册成管理员定的名字 |
| 接受或完成之后回到登录页、再登录一次 | 否决 | 刚设的密码再输一遍没有安全收益，体验更差 |
| 链接不能用时不区分原因 | 否决 | 持有真实令牌的是本人：说清楚"已接受，请直接登录"还是"请管理员重发"更有用，而 256 位的令牌猜不中，不泄漏信息 |
| 按登录名的唯一约束发现冲突（捕获 23505） | 否决 | 与 M1 相同的做法：先取锁、再检查，错误码明确，不把数据库错误当作业务结果 |
| 链接的尝试另设一组配置 | 否决 | 按地址的阈值与登录相同就够了；配置越少越不容易配错 |
| 签发重置时保留旧密码，直到本人完成重置 | 否决（M2-P1 审查 A7） | 账户被盗时，停用之外没有办法立即切断旧密码；停用的账户又不能签发重置，启用之后旧密码马上又能用，最长 24 小时 |
| 允许对停用的账户签发重置 | 否决 | 停用是可以撤回的状态，签发重置不应顺带改它；签发时让旧密码失效已经覆盖"被盗"的处置 |
| 运维命令用 `docker compose run` 执行 | 否决（审查 B13） | 一次性容器的标准输出归日志驱动收集，配置了集中日志时链接会进日志系统 |

## 影响

- **auth 模块**：两张新表归它；签发、查看、接受、完成都在它里面（它已经依赖 users，建账户、撤销会话、建会话都在同一个模块里完成，不产生循环依赖）。admin 模块调用它签发与作废。
- **users 模块**：`AccountCreationService` 建账户与个人空间（初始化管理员与接受邀请共用）；按登录名的锁。
- **前端**：公开页面 `/invite`、`/reset-password` 在需要登录的外层路由之外；令牌读出后从地址里去掉。
- **部署**：运维命令的用法见 `deploy/README.md`（`docker compose exec`）；反向代理与应用的访问日志里不会有令牌。
- **管理员的权限边界**：管理员能给任何账户（包括别的系统管理员）签发重置，自己打开链接设置密码，从而以对方的身份登录，看到对方的个人空间。这是"不依赖邮件、由管理员分发链接"的固有代价（00 号计划书 §11.1），靠审计追溯：签发与完成都记审计，被重置的人下次登录会发现密码已变。管理员给自己签发时，自己的会话随即撤销、旧密码失效，要用链接设置新密码（界面另有确认）。
- **M7**：独立安全审查复核有效期、限流的阈值、链接的分发流程与管理员的权限边界。
