# ADR-027：共用编辑会话层与编辑器接口

> 状态：已接受｜日期：2026-11-22｜来源：M6-P1

## 背景

M6 加文字文档。到 M5 为止，编辑器页的编排都写在表格编辑器 `features/sheet-editor` 里，约 1.5 万行，与表格编辑器、CSV、公式恢复绑在一起，包括：
- 编辑权、交接与请求编辑；
- 保存与自动保存；
- 本机发件箱与恢复；
- 阅读模式、页头。

文字文档需要的是同一套：同样的编辑权与交接，同样的保存协议、发件箱与恢复。

M6 总设计（§2.2、§6.3）定了做法：抽出与文档类型无关的共用编辑会话层，表格与文字文档各接自己的编辑器；地址仍是 `/documents/:id`，按文档的类型装配。约束是表格的行为与既有测试不变。

P1 的 S6～S8 分步完成了迁移，见 [P1 设计](../v0.1/M6-文字文档/01-P1-文字文档底座.md) §3.5、[S6 spec](../v0.1/M6-文字文档/specs/P1-S6-共用编辑会话层.md)、[S8 spec](../v0.1/M6-文字文档/specs/P1-S8-编辑模式与页面按类型拆分.md)。本 ADR 记下迁移之后的结构与约束。

## 决策

### 1. 模块与依赖方向

- `features/document-editor` 是共用编辑会话层，下称会话层。`features/sheet-editor` 是表格编辑器。依赖方向是 sheet-editor → document-editor。
- 会话层不引用表格编辑器，也不引用编辑器适配层 `apps/web/src/editor`，类型也不行。它需要的编辑器能力，由自己定义的窄接口给出：
  - 例如 `CaptureEditor`、`SaveEditor`、`AutosaveEditor`、`SlotEditor`、`EditorAccess`、`UncommittedInput`；
  - 表格编辑器在结构上满足它们（依赖倒置，不开适配层的类型口子）。
- 表格编辑器的生产代码只经会话层的公开入口 `index.ts` 取值；测试另经 `index.test-support.ts` 取假件与内部常量。会话层内部引用同目录的文件，不经自己的 `index.ts`，免得成环。
- 公开入口只放表格编辑器的生产代码实际用到的名字，逐个列出；只有测试用到的放在测试入口。入口转出什么，类型编辑器的生产代码就能直接用什么：多转出一个 `holdLocalLock` 或 `createEditingSession`，类型编辑器就能绕开编辑模式与页面对租约、本机锁和会话的协调，而 lint 不报（P1 审查 B 的 M-1）。请求层原来以命名空间 `editorApi` 转出，组装处搬进会话层之后没有引用方，不再转出。
- 会话层只由编辑器页引用：编辑器页的入口与表格编辑器，P2 起另有文字文档编辑器。它带着本机发件箱与编辑权的协议，不进平台页面的包。
- 以上都由 eslint 的模块边界强制。lint 自测在真实路径上核对：类型感知的检查只认存在的文件，按路径写的规则写错路径会解析失败，不会悄悄失效。

### 2. 按类型装配：四个层次

每一层都是“会话层给通用的部分，一类文档给扩展”。扩展只在原来调用表格代码的位置被调用，先后不变。

| 层次 | 会话层 | 一类文档给的 | 表格的实现 |
|---|---|---|---|
| 编辑模式 | 通用核心 `createEditMode` | 扩展对象 `EditModeExtension`（`onNotify`、`afterCreate`、`blocksActions`、`view`、`cancel`、`dispose`、`enterOptions`、`savingPending`）；核心交给扩展一面 `EditModeHost` | 门面 `sheet-edit-mode.ts`：公式恢复、“公式待更新”与重算、CSV 的目标、工作表名 |
| 编辑器页 | 通用页面 `createEditorPage`，收一张装配表 | 装配 `EditorPageAssembly`：档案，以及选中时的 `assemble(host)`，它交回页面扩展（5 个挂点加交给使用方的成员）与编辑模式的工厂 | `sheet-editor-page.ts`：CSV、新建表格之后的导入、工作表名、公式恢复的重试、页头的插槽 |
| 页头 | 通用骨架 `EditorChrome` | 7 个插槽 `EditorChromeSlots`，经页面扩展的成员 `chrome` 交出 | `sheet-chrome.tsx` 的 `sheetChromeOf`：装配为每页建一次 |
| 启动 | `startEditorPage(elements, kit)` | kit `EditorPageKit`：装配表、编辑器加载失败的判别、测试构建的两个加载器 | `sheet-editor/start.tsx` 的 `sheetEditorPageKit` |

- **选装配**：载入文档详情之后，按类型选装配。三条都成立才选中，否则照旧显示“格式不受支持”，不创建编辑器：
  - 类型有装配；
  - 详情里的档案等于装配的档案；
  - 格式版本是本构建认得的。
- **编辑器的工厂**在装配的闭包里，页面只给一个 `bindEditor`，包上页面的绑定。编辑器、视图状态与创建选项的类型都不出装配。页面看到的类型参数只有三个：
  - 交给使用方的成员；
  - 编辑模式视图里扩展的部分；
  - 图片操作的状态。
- **页头的插槽**不收页面。装配在选中时为这一页建一次插槽，插槽在用到的那一刻读建它时交给它的成员对象，也就是页面扩展交出的那一份，不在建插槽时取值。骨架每次渲染经 `page.extension()?.chrome` 取插槽；确认框与“放弃本机修改”在调用的那一刻取插槽，按 `page.view()` 的当前值判断；挡住动作按渲染时的视图算。
- **两类文档放进同一张装配表**：交给使用方的成员只在协变的位置；编辑模式视图里扩展的部分在视图里是可选的，取并集之后仍能交给一类文档的插槽。所以 P2 的装配表与页面能同时放表格与文字文档，不用 `as`。会话层与表格各有一条类型上的回归用例核对这一点（P1 审查 B 的 I-1）。
  - 例外是图片操作的状态：页头插槽的参数里有它（`imageOperation`，以及收视图的几个插槽），在 strictFunctionTypes 下是逆变的。文字文档的图片状态与表格相同时没有问题；P4 定文字文档的图片时如果不同，要另定写法，比如骨架只向插槽要文字，图片状态由装配自己收窄。
- **启动**：
  - 会话层的 `start.tsx` 是组合处专用的窄入口：公开入口只转出它的类型，值由 `entries/editor/mount.tsx` 直接引用。
  - kit 的两个加载器各自在函数里按 `import.meta.env.MODE === 'e2e'` 判断，`import()` 写在成立的分支里，生产构建由常量折叠去掉。
  - 测试钩子与自检的挂接要在 `page.load()` 之前装好（M3-P5 审查 B8），所以由 kit 交给启动，不挂在载入之后才选中的装配上。

### 3. 页面档案按类型注入

- 页面上报的档案由 `clientFormatOf(type)` 按类型给出。
- 申请编辑权、续租与请求编辑的请求，页面以选中装配的档案取一次；草稿、打开自检与公式 Worker 的上报，用同一份档案。
- 本机恢复的可读判定按档案的集合，其中任意一个可读即可读：
  - 载入之后只用选中装配的档案；
  - 404 之后用装配表里全部的档案；
  - 草稿页与后台维护用 `READABLE_CLIENT_FORMATS`。
- 本构建能打开的类型是 `OPENABLE_DOCUMENT_TYPES`，P1 只有表格。组装处的装配表写成 `satisfies Record<OpenableDocumentType, …>`，多一项、少一项都编译不过。

### 4. 编辑器接口的方法名：P1 不改

会话层的窄接口沿用表格编辑器原来的方法名：
- 派生内容收齐：`settleFormulas`、`formulasSettled`、`onFormulaProgress`；
- 未提交的输入：`isCellEditing`、`commitCellEditing`、`settlePanels`、`uncommittedInput`；
- 同一会话里换编辑器的端口：`freezeEditor`、`captureForFormulaRecovery`、`noteFormulaRecovery`；
- 日志里的取值 `'formula-recovery'`。

改名会牵动上万行测试里的假件。只有一个实现时，也定不准通用的名字该是什么。

**P2 有了文字文档的实现之后，在本 ADR 里补一节，定下改不改、改成什么。** 文字文档在 P2 先按原名实现：派生内容恒为已收齐，没有未提交的输入。

### 5. 不变的

- 保存协议、发件箱与附加认证数据里的字段，`formulasPending` 等，不改名、不改取值。
- 日志、存储与通道里的字符串不变：Web Lock、BroadcastChannel 的名字，localStorage 与 sessionStorage 的键，挂在 window 上的探针名，Worker 的名字。
- `#sheet-editor` 与 `data-editor-*` 选择器不改名。改名会牵动约 30 个文件，留给 P2 按需要另定。
- 编辑模式的通知顺序（S8 spec §1.6 的 D1～D12）；旧编辑器真正销毁之后才新建，换编辑器是单飞的。
- 只属于测试构建的模块只经 e2e 分支里的动态 `import()` 引入，门禁 artifacts 按来源、按分块名、禁用关键字三道核对：
  - 编辑器适配层的 `testing/`；
  - 会话层的 `outbox/testing/`、`recovery/testing/`；
  - 表格编辑器的 `selftest-hook.ts`。

## 备选方案与取舍

- **在表格的编辑模式外面包一层，不拆核心**：改动小，但包装层拿不到通知的中间时刻，会破坏通知顺序（D1、D2、D10），不采用。
- **装配带着编辑器的工厂字段**：编辑器与它入参的类型落在逆变的位置，P2 的装配表要放两类文档时，不用 `as` 就放不下。改为工厂留在装配的闭包里、页面给 `bindEditor`。
- **页头收一个插槽属性，由启动给出**：P2 要在载入之后按类型换插槽，届时还得改通用骨架。改为插槽经页面扩展的成员交出，通用页面不用暴露选中的类型。
- **插槽收页面、按页面扩展的类型约束**：S8c 起初的写法，插槽是模块级常量，收 `page: EditorPage<Extension, …>`，经 `page.extension()` 读成员；骨架与启动要求 `Extension extends EditorChromeMembers<Extension, …>`。插槽是属性函数，参数在 strictFunctionTypes 下按逆变检查，而页面对 Extension 协变：P2 把两类文档的成员合成并集时，表格的插槽不满足约束，不用 `as` 就编译不过（P1 审查 B 的 I-1）。改为每页建插槽、读成员对象，去掉 F 界。
- **测试钩子与自检的挂接挂在页面装配上**：装配在载入详情之后才选中，来不及在第一次打开交接频道之前换上吞消息的频道（审查 B8）。改由 kit 在启动时给出。
- **会话层的公开入口转出启动**：表格编辑器的生产代码与测试的模块图里，都会多出 React DOM、分享对话框、弹窗等页面外壳。改为组合处专用的窄入口，先例是本机数据的 `notice.ts`。
- **把自动保存控制与交接日志搬进会话层**：适配层与 E2E 要新开引用会话层的口子，前者是反向依赖。改为留在适配层，由表格的 kit 引入。
- **P1 就给编辑器接口改名**：见决策第 4 条。

## 影响

- **P2**：文字文档编辑器提供：
  - 装配：档案、页面扩展与编辑模式的扩展；
  - 页头的插槽；
  - 自己的 kit，或者与表格的 kit 合成一份。
  `OPENABLE_DOCUMENT_TYPES` 加上 `doc`。以下几处届时再定：
  - 组合处怎样合并两份 kit；
  - 骨架里写死“表格”“单元格”的 9 条文案；其中载入中、格式不受支持、载入失败三条出现时还不知道类型；
  - 编辑器接口的方法名，即决策第 4 条。
- **新加的类型相关行为**：经编辑模式的扩展、页面扩展的挂点、页头的插槽或 kit 加进来，不在会话层里按类型分支。确实需要新挂点时，挂点放在原来调用的位置，先后写进 spec。
- **新的会话层模块**：不能引用表格编辑器与编辑器适配层。需要编辑器能力就在会话层定义窄接口，表格在结构上满足它。
- **留意**：
  - 通用页面按编辑模式视图的五个通用键拆出扩展的部分。编辑模式的视图以后加了通用的键而这里没跟着改，那一项会混进扩展的部分，类型检查查不出（S8b 的 Minor）。
  - 全量 lint 的峰值常驻内存约 5.5 GiB，ESLint 的旧生代上限是 6 GiB。P2 加代码之后再量一次。
