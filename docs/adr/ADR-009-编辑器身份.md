# ADR-009：编辑器身份

> 状态：已接受｜日期：2026-09-27｜来源：M1-P4

## 背景

- Univer 的权限点都经 `IAuthzIoService` 判断。默认的实现是本地授权服务（`AuthzIoLocalService`）：它在构造时注册资源 `SHEET_AuthzIoMockService_PLUGIN`，把保护规则写进快照。
- M0-P3 报告 §5.3：给 SDK 设置真实的当前用户之后，本地授权服务连没有保护的单元格也不允许编辑；平台因此不把真实用户交给它。
- 00 号计划书 §6.5：谁能编辑一份文档由平台的服务端决定（访问策略、M3 的编辑租约），编辑器只呈现结果。M1 没有只读与共享，能打开编辑器页的人就能编辑。
- 插件档案 v1（M0 定稿）的资源白名单里有 `SHEET_AuthzIoMockService_PLUGIN`，并规定它"必须为空"（保护类）。

## 决策

- 用"全部允许"的 `IAuthzIoService` 替换本地授权服务（`new Univer({ override: [[IAuthzIoService, …]] })`，`apps/web/src/editor/identity/`）：
  - `allowed` 对每个动作返回允许；`batchAllowed` 按请求的形状返回全部允许；`list` 一类返回空；
  - `create`（创建保护规则）拒绝，保护的界面入口也已隐藏（M5 之前的入口，P4 设计 §3.6.8）；
  - 不调用 `setCurrentUser`：SDK 的当前用户保持匿名（`userID` 为空）。在 `sheet@1` 的范围内只有已隐藏的权限面板读它。
- 本地授权服务不再构造，它的资源随之消失：新的快照里没有 `SHEET_AuthzIoMockService_PLUGIN`；加载含这一项的快照时它被忽略，下一次保存时消失。
- **修订插件档案 v1**：资源白名单与"必须为空"的清单去掉 `SHEET_AuthzIoMockService_PLUGIN`（档案只描述真实存在的数据）。服务端在 M3 做完整的快照校验时按新的白名单处理。v0.1 没有存量文档，不涉及迁移。
- 只读（查看者、阅读模式）由平台决定：编辑器的 `setEditable(false)`，保存的入口不出现（M1 的访问策略只有所有者；阅读模式在 M3）。
- 替换依赖的 `IAuthzIoService` 是内部符号，经 `apps/web/src/editor/internal-api/` 引用并登记（ADR-010）。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
|---|---|---|
| A. 全部允许的 `IAuthzIoService`，不设当前用户 | 采用 | 权限在平台的服务端；S2 的探针在三个浏览器上确认：打开、键入、增删工作表、筛选、排序、条件格式、数据验证、备注、查找替换都照常，40 个权限点都允许，快照里没有这一项资源 |
| B. 保留本地授权服务，当前用户恒为空 | 否决（备选） | 快照里一直带着一项"必须为空"的保护资源；本地授权服务的判断与平台的权限是两套规则，将来容易互相矛盾。A 不通过时才退回这里 |
| C. 保留本地授权服务，设置真实的当前用户 | 否决 | M0-P3 报告 §5.3：连没有保护的单元格也不允许编辑 |
| D. 用 Univer 的权限体系表达平台的权限 | 否决 | 权限要由服务端强制执行（计划书 §6.5），编辑器里的判断只是界面；Pro 的协同权限不在考虑范围内 |

## 影响

- 编辑器里没有权限判断；能不能编辑、能不能保存由页面按服务端给的权限决定（`permissions.canEdit`），服务端对每个保存请求再判断一次（`PERMISSION_DENIED`，ADR-006）。
- M2 的共享、M3 的阅读模式与编辑租约都在平台侧实现，不改编辑器的身份。
- 升级 SDK 时回归 S2 探针的清单：E2E 经界面操作覆盖编辑与保存重开、增删工作表、排序与筛选、条件格式与数据验证、批注与查找替换（`tests/e2e/specs/editor/features.spec.ts`）。新的插件若依赖本地授权服务或非空的当前用户，要在这里重新评估。
